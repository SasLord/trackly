# Contributing

## Гейт приватности

Репозиторий **публичный**. Реальные реквизиты организации, ФИО сотрудников и
инфраструктурные идентификаторы (AD-домен, DC, логины) никогда не должны
попадать в коммиты — ни в код, ни в тесты, ни в `.planning/`-артефакты.
Проект использует единый гейт `scripts/check-privacy.mjs`, который проверяет
это автоматически в двух точках: локально перед коммитом и в CI.

**Локальный хук `.githooks/pre-commit` не включается автоматически** — это
особенность git, а не баг: каталог `.githooks/` присутствует в репозитории,
но `core.hooksPath` нужно указать явно. Сделайте это один раз после клонирования:

```bash
./scripts/setup-hooks.sh
```

После этого каждый `git commit` в этом клоне будет проверять staged-файлы
гейтом приватности перед созданием коммита. Проверить, что хук включён:

```bash
git config core.hooksPath
# ожидаемый вывод: .githooks
```

Если `node` не найден в `PATH`, хук откажет в коммите (fail-closed) — это
намеренное поведение, а не баг: гейт не должен молча пропускать проверку.

Хук — локальный и обходимый (`git commit --no-verify` его пропустит). CI
(`.github/workflows/ci-fast.yml`, шаг «Privacy gate») — backstop, который
не зависит от локальной настройки разработчика.
