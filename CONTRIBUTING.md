# Contributing

## Гейт приватности

Репозиторий **публичный**. Реальные реквизиты организации, ФИО сотрудников и
инфраструктурные идентификаторы (AD-домен, DC, логины) никогда не должны
попадать в коммиты — ни в код, ни в тесты, ни в `.planning/`-артефакты.
Проект использует единый гейт `scripts/check-privacy.mjs`, который проверяет
это автоматически в двух точках: локально перед коммитом и в CI.

**Локальный хук `.githooks/pre-commit` не включается автоматически** — это
особенность git, а не баг: каталог `.githooks/` присутствует в репозитории,
но `core.hooksPath` нужно указать явно. Сделайте это один раз после клонирования:

```bash
./scripts/setup-hooks.sh
```

После этого каждый `git commit` в этом клоне будет проверять staged-файлы
гейтом приватности перед созданием коммита. Проверить, что хук включён:

```bash
git config core.hooksPath
# ожидаемый вывод: .githooks
```

Если `node` не найден в `PATH`, хук откажет в коммите (fail-closed) — это
намеренное поведение, а не баг: гейт не должен молча пропускать проверку.

Хук — локальный и обходимый (`git commit --no-verify` его пропустит). CI
(`.github/workflows/ci-fast.yml`, шаг «Privacy gate») — backstop, который
не зависит от локальной настройки разработчика.

### Добавление нового реального значения в список токенов

Новые категории реальных данных (новый домен AD, новый адрес) добавляются
только через интерактивный режим — значение вводится с подавленным эхом и
никогда не попадает ни в файл, ни в историю оболочки:

```bash
node scripts/check-privacy.mjs --add --hashes scripts/privacy-tokens.sha256
```

Сканер режет строки на слова (последовательности букв и цифр) и строит
n-граммы длиной **не больше трёх слов**, поэтому `--add` принимает значение
той же формы и приводит его к ней сам:

- пунктуация внутри значения отбрасывается (`Иванов-Петров` → два слова) —
  гейт печатает об этом примечание, само значение не показывается;
- значение длиннее трёх слов **отклоняется** (exit 1, файл не меняется):
  такой хэш сканер не получил бы никогда, запись была бы мёртвой. Добавьте
  вместо него отдельные значимые подфразы длиной ≤ 3 слов;
- повторное добавление того же значения с другим классом отклоняется —
  исправьте класс существующей строки вручную.

### Если гейт сообщает «не прочитан»

Цель, содержимое которой прочитать не удалось (нет прав, файл удалён из
рабочего дерева, staged-блоб больше 64 МБ), приводит к отказу гейта, а не к
пропуску этого файла: пропустив цель молча, гейт отчитался бы «PASS», ничего
про неё не проверив. Восстановите файл (`git checkout -- <path>`), поправьте
права или уберите гигантский блоб из индекса и повторите.
