# Requirements: Trackly — Milestone v1.1.1

**Defined:** 2026-07-03
**Milestone:** v1.1.1 — PDF-акт по образцу Word (полное соответствие + мультиустройство)
**Core Value:** Учёт устройств и картриджей с актами приёма-передачи и историей перемещений должен работать надёжно и быстро в режиме «одной кнопкой» — без обращения к Excel-таблицам, ручного присвоения номеров актов или потери истории при возврате на склад.
**Source:** `.planning/PHASE-BRIEF-act-pdf-word-fidelity.md` (разбор образца, гэп-анализ, открытые вопросы для discuss-phase)

## Milestone v1.1.1 Requirements

Требования этого milestone. Каждое маппится на фазу роадмапа. Существующий пайплайн:
MiniJinja-шаблон (в БД) → DocSpec JSON → krilla → PDF-байты.

### PDF-акт: соответствие образцу (PDFA)

- [x] **PDFA-01**: Сгенерированный PDF акта приёма-передачи воспроизводит структуру бумажного образца Word — шапка (логотип + реквизиты), заголовок «Акт приема-передачи», номер/дата, вводная формулировка, блок устройства(-в), «Сроком до», блок подписей «Выдал/Получил».
- [x] **PDFA-02**: Акт с несколькими устройствами печатает все позиции корректно — блок «Устройство» переделан под N позиций (через примитив `ItemsTable`), с корректным переносом длинных ячеек (Комплектация, Технические характеристики).
- [x] **PDFA-03**: Шапка PDF включает расширенные реквизиты организации (телефон, факс, e-mail, ОКПО, ОГРН) из `org_settings`, а не только name/inn/kpp/address.
- [x] **PDFA-04**: Поля «Комплектация», «Технические характеристики» и «Срок до» доступны при формировании акта и попадают в PDF (место хранения — device / позиция акта / свободный ввод — решается в discuss-phase).
- [x] **PDFA-05**: Блок подписей печатает двухстрочные подписи «Подпись / ФИО» для сторон «Выдал» и «Получил», как в образце.
- [x] **PDFA-06**: Дефолтный шаблон акта обновлён под новый вид, редактируем через существующий механизм `document_templates` и корректно сидируется при первом запуске (не хардкод в Rust сверх дефолт-сида).
- [ ] **PDFA-07**: Кириллица во всех полях нового шаблона (включая мультиустройство и реквизиты) рендерится корректно через embedded-шрифт (regression-гарантия существующего пайплайна).
- [ ] **PDFA-08**: Существующие тесты PDF-пайплайна проходят; добавлены автоматические тесты на новый шаблон и мультиустройство (1 vs N позиций).

## Future Requirements

Отложено на будущие milestone. Отслеживается, но не в текущем роадмапе.

### Шаблоны и документы (DOC)

- **DOC-01**: Редактор шаблонов печатных форм в UI (WYSIWYG / расширенное редактирование сверх текущего textarea).
- **DOC-02**: Импорт/экспорт .docx шаблонов.
- **DOC-03**: Прочие виды печатных документов помимо акта приёма-передачи/выдачи.

## Out of Scope

Явно исключено из v1.1.1. Задокументировано, чтобы не расползался скоуп.

| Feature | Reason |
|---------|--------|
| Редактор шаблонов в UI (сверх текущего механизма) | Существующий `document_templates` + textarea покрывает потребность v1.1.1; богатый редактор — отдельная работа (DOC-01) |
| Импорт/экспорт .docx | Образец разобран вручную и сохранён в репозитории; парсинг .docx не нужен для генерации (DOC-02) |
| Прочие виды документов | Milestone фокусируется только на акте приёма-передачи/выдачи (DOC-03) |
| Карта помещений (MAP), внешние уведомления (NTF), Pantum auto-restart (PNT), полный SSO (ADV), i18n (I18N), Windows 7 (WIN7) | v2-бэклог, вне текущего milestone (см. PROJECT.md) |
