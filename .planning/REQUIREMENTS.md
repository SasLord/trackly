# Requirements: Trackly — веха v1.4 «Карта и осмысленное размещение»

**Defined:** 2026-08-22
**Core Value:** Учёт устройств и картриджей с актами приёма-передачи и историей перемещений
должен работать надёжно и быстро в режиме «одной кнопкой» — без обращения к Excel-таблицам,
ручного присвоения номеров актов или потери истории при возврате на склад.

**Milestone Goal:** заменить свободнотекстовое «Размещение» деревом мест, ввести АРМ и историю
перемещений, и дать схематичную карту с расстановкой устройств по этажам и территориям.

> Нумерация REQ-ID продолжает сквозную нумерацию проекта. Категории `PLC`, `HST`, `WKS`, `EDT`,
> `LIV` вводятся впервые; `REQ-07/08` продолжают существующую категорию заявок (макс. был REQ-06).
> `MAP-01..04` из v2-списка вехи v1.1 **переопределены** — тот список был наброском желаний, а не
> требованиями; здесь MAP-01..05 задают проверяемый объём.

## v1 Requirements

### Места — дерево размещения (PLC)

- [x] **PLC-01**: Администратор может построить дерево мест (территория / зона / здание / этаж /
      помещение / уличный объект) с произвольной вложенностью, переименовать и переместить узел
      без потери привязок устройств
- [x] **PLC-02**: Этаж имеет числовой уровень, допускающий 0 и отрицательные значения (подвал);
      этажи сортируются по уровню, а не по имени
- [x] **PLC-03**: Пользователь выбирает размещение устройства и картриджа из дерева мест с
      поиском по полному пути («Здание А / 2 этаж / 214»), а не вводит произвольный текст
- [x] **PLC-04**: Свободнотекстовое поле «Размещение» и таблица `locations` удалены из
      приложения — формы, списки, отчёты, автокомплиты и печатные формы используют место из дерева
- [x] **PLC-05**: Переименование или перемещение узла дерева отражается в полнотекстовом поиске
      и во всех списках без ручной переиндексации
- [x] **PLC-06**: Пользователь может открыть любое место и увидеть всё, что размещено в нём и во
      вложенных местах (устройства, АРМ, принтеры, картриджи), одним списком

### История перемещений (HST)

- [ ] **HST-01**: Каждая смена места устройства или картриджа записывается в историю: откуда,
      куда, когда, кем и по какой причине (вручную / актом / перетаскиванием на карте)
- [ ] **HST-02**: Пользователь видит таймлайн перемещений в карточке устройства и картриджа
- [ ] **HST-03**: Акт приёма-передачи автоматически меняет место переданных устройств и
      фиксирует в истории ссылку на номер акта
- [ ] **HST-04**: Пользователь может получить отчёт о перемещениях за период с фильтром по месту
      и типу устройства

### АРМ — рабочее место (WKS)

- [ ] **WKS-01**: Администратор может собрать АРМ из существующих устройств (системный блок,
      монитор(ы), периферия), указав роль каждого устройства в составе
- [ ] **WKS-02**: Устройство входит не более чем в один АРМ; вывод устройства из состава
      выполняется явным действием
- [ ] **WKS-03**: АРМ имеет собственное место; при смене места АРМ место всех входящих устройств
      меняется вместе с ним, с записью в историю по каждому устройству
- [ ] **WKS-04**: К АРМ привязываются один или несколько пользователей, один из них — основной
- [ ] **WKS-05**: В акте приёма-передачи можно выбрать АРМ целиком — он разворачивается в список
      входящих в него устройств
- [ ] **WKS-06**: При передаче актом устройства из состава АРМ в другое место пользователь
      получает подтверждение, и после подтверждения устройство выводится из состава АРМ
- [ ] **WKS-07**: Пользователь видит карточку АРМ: состав, место, привязанных пользователей и
      подключённые к нему принтеры

### Заявки — умный подбор принтера (REQ)

- [ ] **REQ-07**: В заявке на замену картриджа принтеры ранжируются: USB-принтеры АРМ автора →
      принтеры его помещения → его этажа → его здания → остальные
- [ ] **REQ-08**: Принтер подставляется в форму заявки автоматически, если у автора есть
      единственный очевидный кандидат (принтер его АРМ или единственный принтер его помещения)

### Карта — просмотр (MAP)

- [ ] **MAP-01**: Администратор или менеджер выбирает план этажа или зоны и видит схему
      помещений с размещёнными на ней устройствами и АРМ
- [ ] **MAP-02**: К плану можно приложить готовую подложку в формате JPG и работать поверх неё
- [ ] **MAP-03**: Клик по маркеру открывает карточку устройства или АРМ; клик по помещению —
      список размещённого в нём
- [ ] **MAP-04**: План печатается на лист A4 через существующий механизм печати (десктоп и LAN)
- [ ] **MAP-05**: Роль «Сотрудник» не имеет доступа к разделу «Карта» и к её данным ни на
      Tauri-, ни на HTTP-транспорте

### Карта — редактор планов (EDT)

- [ ] **EDT-01**: Пользователь рисует контур помещений ортогональными стенами по сетке с
      привязкой к её узлам
- [ ] **EDT-02**: Пользователь размещает двери и окна как вырезы на стене, с общепринятыми
      условными обозначениями
- [ ] **EDT-03**: Нарисованное помещение связывается с местом из дерева — после связывания клик
      по нему показывает содержимое этого места
- [ ] **EDT-04**: Устройства и АРМ размещаются на плане перетаскиванием из палитры, с поворотом
      значка
- [ ] **EDT-05**: Действия в редакторе отменяются и повторяются (undo / redo)
- [ ] **EDT-06**: Слои содержимого (подложка / стены / помещения / устройства) переключаются
      независимо друг от друга

### Живые статусы на карте (LIV)

- [ ] **LIV-01**: Маркер принтера на карте окрашен по состоянию: уровень тонера, недоступность
      по SNMP, открытая заявка
- [ ] **LIV-02**: Статусы обновляются на открытой карте без перезагрузки страницы (WebSocket)

## Out of Scope

| Feature | Reason |
|---------|--------|
| CAD-точность: произвольные углы стен, размерные линии, привязки к произвольным объектам | Отдельный продукт по объёму; ортогональные стены по сетке дают ту же наглядность за долю усилий |
| Импорт DXF / SVG / AutoCAD | Готовые планы у пользователя в JPG; парсер CAD-форматов не окупается |
| Рендер PDF-подложек (`pdf.js`) | Подтверждено: планы в JPG. Вернуть только если появятся PDF-исходники |
| Canvas-движки (Konva, Fabric) | На 100–150 объектах на плане SVG выигрывает: hit-testing, a11y и печать через существующий HTML-пайплайн — бесплатно |
| JointJS, tldraw | Лицензионный риск на публичном репозитории |
| react-planner, blueprint-js, SweetHome3D | React / Java / заброшены; починка чужого мёртвого кода дороже собственного узкого редактора |
| 3D-визуализация помещений | Ценность учёта от неё не зависит |
| Доступ сотрудника к карте | Решение пользователя: карта раскрывает IP, модели и серийники — граница Фазы 10 не продавливается |
| Миграция существующих значений размещения | Приложение не в реальной эксплуатации, все акты в БД тестовые — данные обнуляются |
