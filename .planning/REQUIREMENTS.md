# Requirements: Trackly — v1.5 «Trackly Link — клиент и Чат»

**Defined:** 2026-11-26
**Core Value (веха):** сотрудники общаются друг с другом через клиент Link и браузерную версию Trackly; клиенты ставятся и обновляются с сервера Trackly без участия администратора на каждом ПК.

Источники: обсуждение с пользователем 2026-11-25/26, `.planning/PROJECT.md` («Current Milestone: v1.5»),
исследование `.planning/research/SUMMARY.md` (+ STACK, FEATURES, ARCHITECTURE, PITFALLS).

## v1.5 Requirements

### Клиент Link (LNK)

- [ ] **LNK-01**: Link собирается из этого же репозитория отдельным приложением со своей версией; компоненты чата и вложений общие для Trackly и Link
- [ ] **LNK-02**: Link виден только как иконка в системном трее — окна нет на панели задач
- [ ] **LNK-03**: Link запускается автоматически при входе пользователя в систему, свёрнутым в трей
- [ ] **LNK-04**: Закрытие окна прячет Link в трей; полностью выйти можно только пунктом «Закрыть» в меню иконки трея
- [ ] **LNK-05**: У одного пользователя работает один экземпляр Link (повторный запуск показывает окно); на терминальном сервере (RDS) каждый пользователь сеанса получает свой экземпляр
- [ ] **LNK-06**: Сотрудник на доменном ПК входит в Link автоматически (Kerberos/SPNEGO), без ввода пароля
- [ ] **LNK-07**: Сотрудник на ПК вне домена входит логином и паролем; вход запоминается в хранилище ОС и может быть отозван администратором
- [ ] **LNK-08**: Link обменивается данными с сервером только при совпадении закреплённого отпечатка сертификата сервера; при несовпадении — понятная ошибка, данные не отправляются
- [ ] **LNK-09**: При потере связи Link показывает состояние «нет связи» и переподключается сам; после сна ПК догружает пропущенное
- [ ] **LNK-10**: Окно Link: узкий логотип «Link» слева вверху, справа от него вкладки (в v1.5 — «Чат»), сайдбар слева, содержимое справа
- [ ] **LNK-11**: На рабочем столе Linux без системного трея Link остаётся доступен (окно не прячется «в никуда»)

### Распространение (DST)

- [ ] **DST-01**: Администратор устанавливает Link на доменные ПК групповой политикой (скрипт входа тихо ставит, если не установлено) по инструкции в документации; прав администратора на ПК установка не требует
- [ ] **DST-02**: Пользователь ПК вне домена устанавливает Link вручную тем же установщиком
- [ ] **DST-03**: Установщик и исполняемый файл Link подписаны Authenticode внутренним сертификатом организации; инструкция описывает выпуск сертификата и раздачу доверия через GPO
- [ ] **DST-04**: На macOS и Linux Link ставится вручную и запускается вместе с системой
- [ ] **DST-05**: Адрес сервера и отпечаток сертификата задаются при установке (параметр установщика или конфиг), а не вшиваются в публичный релиз
- [ ] **DST-06**: Перед раскаткой выполнен пилот на реальных доменных ПК (AppLocker/SRP, WebView2, тихая установка); итог задокументирован обезличенно

### Автообновление (UPD)

- [ ] **UPD-01**: Link на Windows сам проверяет и устанавливает обновления с сервера Trackly без прав администратора
- [ ] **UPD-02**: Клиент принимает обновление только с действительной подписью ключа проекта; сервер отклоняет загрузку сборки без действительной подписи
- [ ] **UPD-03**: Администратор загружает сборку Link в Trackly и назначает её версией канала «стабильный» или «тестовый»
- [ ] **UPD-04**: Администратор назначает тестовый канал отдельным пользователям и отдельным компьютерам; назначение компьютеру приоритетнее назначения пользователю
- [ ] **UPD-05**: Клиент стабильного канала нигде — в интерфейсе, номерах версий, ответах сервера, логах — не получает упоминаний о других каналах
- [ ] **UPD-06**: Администратор откатывает канал на предыдущую сборку, и клиенты канала переходят на неё
- [ ] **UPD-07**: Сборки Link выпускает CI отдельным процессом, не задевая релизы Trackly; хранение и ротация ключа подписи задокументированы

### Надёжная доставка (DLV)

- [ ] **DLV-01**: После обрыва связи или переполнения очереди событий клиент догружает всё пропущенное по курсору — ни одно сообщение не теряется (закрывает долг «WS Lagged», в т.ч. для экранов Trackly)
- [ ] **DLV-02**: Пользователь получает события только тех бесед, в которых состоит; после исключения из комнаты события перестают приходить сразу
- [ ] **DLV-03**: Повторная отправка после сбоя сети не создаёт дубликат сообщения
- [ ] **DLV-04**: Сервер обнаруживает «мёртвые» соединения, клиенты переподключаются автоматически

### Чат (CHT)

- [ ] **CHT-01**: Пользователь находит любого коллегу поиском и начинает с ним диалог один на один
- [ ] **CHT-02**: Пользователь создаёт комнату с названием и приглашает участников
- [ ] **CHT-03**: Создатель комнаты добавляет и исключает участников; любой участник может покинуть комнату
- [ ] **CHT-04**: Когда Создатель покидает комнату, роль переходит к самому давнему участнику; роль подписана как «Создатель»
- [ ] **CHT-05**: В комнате видны системные сообщения: вошёл, вышел, исключён, сменился Создатель
- [ ] **CHT-06**: Новый или вернувшийся участник видит всю историю комнаты
- [ ] **CHT-07**: Сайдбар: строка поиска, квадратная кнопка «Написать» (новый диалог или комната), список бесед с коротким превью, временем и счётчиком непрочитанного
- [ ] **CHT-08**: Лента: подряд идущие сообщения автора сгруппированы, есть разделители дней, разделитель «Новые сообщения» и переход к первому непрочитанному
- [ ] **CHT-09**: Сообщение отправляется Enter или кнопкой-самолётиком; видно состояние отправки (отправляется / ошибка с повтором)
- [ ] **CHT-10**: Черновик хранится для каждой беседы и переживает перезапуск клиента
- [ ] **CHT-11**: Чат доступен в браузерной версии Trackly всем ролям; в десктопном Trackly раздел чата скрыт
- [ ] **CHT-12**: Диалог с отключённым пользователем становится только для чтения; комната без Создателя не остаётся «бесхозной»
- [ ] **CHT-13**: Пользователь закрепляет беседы вверху списка

### Редактор и содержимое (RTE)

- [ ] **RTE-01**: Редактор: заголовки до 6 уровней, жирный, курсив, подчёркнутый, зачёркнутый, верхний и нижний индекс
- [ ] **RTE-02**: Маркированные и нумерованные списки, цитата, отступы, выравнивание
- [ ] **RTE-03**: Ссылки (только безопасные схемы), код строкой и блоком
- [ ] **RTE-04**: Картинка в тексте — только загруженное вложение, не внешний адрес
- [ ] **RTE-05**: @упоминание участника; @все в комнате (доступно Создателю и администратору)
- [ ] **RTE-06**: Ответ на сообщение с цитатой и переходом к оригиналу
- [ ] **RTE-07**: Эмодзи выглядят одинаково на всех ОС (встроенный лёгкий набор); выбор эмодзи с поиском по-русски
- [ ] **RTE-08**: Вложения файлов (скрепка, перетаскивание, вставка из буфера) с просмотром, как в Заявках; лимит размера — общий из настроек вложений
- [ ] **RTE-09**: Сервер принимает только документ разрешённой схемы; скрипты, HTML и опасные ссылки отклоняются (защита от XSS)

### Операции с сообщениями (MOP)

- [ ] **MOP-01**: Автор редактирует своё сообщение; отредактированное помечено карандашом
- [ ] **MOP-02**: Автор удаляет своё сообщение: у всех вместо него «Сообщение удалено», текст не виден ни в поиске, ни в цитатах, ни в превью, ни в уведомлениях
- [ ] **MOP-03**: Над сообщением всплывает облачко частых реакций плюс полный выбор; до 3 реакций от пользователя на сообщение, при четвёртой снимается самая старая
- [ ] **MOP-04**: Контекстное меню сообщения: ответить, копировать, переслать, закрепить, изменить, удалить, информация
- [ ] **MOP-05**: «Информация о сообщении» показывает всем участникам, кто и когда прочитал и кто какую реакцию поставил; в диалоге 1:1 есть галочки ✓/✓✓
- [ ] **MOP-06**: Сообщение пересылается в другую беседу с указанием исходного автора
- [ ] **MOP-07**: Сообщение закрепляется в беседе и видно плашкой над лентой
- [ ] **MOP-08**: Поиск по сообщениям во всех своих беседах с переходом к найденному

### Уведомления (ALR)

- [ ] **ALR-01**: О новом сообщении сообщает внутренний тост, а когда окно не в фокусе — системное уведомление ОС
- [ ] **ALR-02**: Счётчики непрочитанного на беседах и вкладке; иконка в трее показывает, что есть непрочитанное
- [ ] **ALR-03**: Пользователь заглушает беседу: уведомлений нет, её счётчик серый и не учитывается в трее
- [ ] **ALR-04**: Пользователь отключает уведомления всего приложения
- [ ] **ALR-05**: @упоминание, ответ на моё сообщение и @все пробивают заглушённую беседу, но не отключённые уведомления приложения
- [ ] **ALR-06**: Щелчок по уведомлению открывает нужную беседу; после переподключения приходит одно сводное уведомление вместо шквала

### Администрирование Link (ADM)

- [ ] **ADM-01**: В Trackly есть раздел «Link» с управлением сборками и каналами
- [ ] **ADM-02**: Список клиентов: пользователь, компьютер, версия, канал, последний вход; отзыв устройства
- [ ] **ADM-03**: Администратор видит удалённые сообщения и удаляет их навсегда вместе с вложениями; действия пишутся в журнал аудита
- [ ] **ADM-04**: Администратор явно включает режим расследования, в котором может открыть чужие диалоги и комнаты; чужие беседы помечены, чтобы не войти случайно; каждый просмотр пишется в аудит и не появляется в «Информации о сообщении»
- [ ] **ADM-05**: В режиме расследования администратор видит историю правок сообщения
- [ ] **ADM-06**: Администратор назначает Создателя комнаты или архивирует комнату

## Out of Scope

| Feature | Reason |
|---------|--------|
| Сквозное шифрование (E2E) | Противоречит модерации и режиму расследования; LAN одной организации |
| Превью внешних ссылок | Сервер ходил бы по чужим адресам (SSRF/трекинг) |
| Внешние картинки по URL | Трекинг и утечки; только вложения |
| Служба Windows для Link | Служба в сессии 0 не может показать трей, окна и уведомления |
| Чат в десктопном Trackly | Десктоп действует от системного «Администратора» без личности для переписки |
| Звонки, видео | Не запрошено |
