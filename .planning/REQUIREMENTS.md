# Requirements: Trackly — веха v1.4 «Карта и осмысленное размещение»

**Defined:** 2026-08-22
**Core Value:** Учёт устройств и картриджей с актами приёма-передачи и историей перемещений
должен работать надёжно и быстро в режиме «одной кнопкой» — без обращения к Excel-таблицам,
ручного присвоения номеров актов или потери истории при возврате на склад.

**Milestone Goal:** заменить свободнотекстовое «Размещение» деревом мест, ввести группы
устройств (АРМ, системный блок, разбор) и историю перемещений, и дать схематичную карту с
расстановкой устройств по этажам и территориям.

> Нумерация REQ-ID продолжает сквозную нумерацию проекта. Категории `PLC`, `HST`, `WKS`, `EDT`,
> `LIV` вводятся впервые; `REQ-07/08` продолжают существующую категорию заявок (макс. был REQ-06).
> **2026-10-04:** категория `WKS` (АРМ) переформулирована в `GRP` — АРМ стал одним из типов
> универсальной группы. Соответствие: WKS-01 → GRP-04, WKS-02 → GRP-05, WKS-03 → GRP-06,
> WKS-04 → GRP-02/GRP-08, WKS-05 → GAM-01, WKS-06 → GAM-02, WKS-07 → GRP-08. Тем же решением
> введены категории `GRD` (группы в разделе «Устройства»), `GAM` (группы в актах и местах),
> `ATT` (вложения), `REP` (ремонтные заявки), `MSG` (переписка в заявке), `EMP` (устройства
> сотрудника).
> `MAP-01..04` из v2-списка вехи v1.1 **переопределены** — тот список был наброском желаний, а не
> требованиями; здесь MAP-01..05 задают проверяемый объём.

## v1 Requirements

### Места — дерево размещения (PLC)

- [x] **PLC-01**: Администратор может построить дерево мест (территория / зона / здание / этаж /
      помещение / уличный объект) с произвольной вложенностью, переименовать и переместить узел
      без потери привязок устройств
- [x] **PLC-02**: Этаж имеет числовой уровень, допускающий 0 и отрицательные значения (подвал);
      этажи сортируются по уровню, а не по имени
- [x] **PLC-03**: Пользователь выбирает размещение устройства и картриджа из дерева мест с
      поиском по полному пути («Здание А / 2 этаж / 214»), а не вводит произвольный текст
- [x] **PLC-04**: Свободнотекстовое поле «Размещение» и таблица `locations` удалены из
      приложения — формы, списки, отчёты, автокомплиты и печатные формы используют место из дерева
- [x] **PLC-05**: Переименование или перемещение узла дерева отражается в полнотекстовом поиске
      и во всех списках без ручной переиндексации
- [x] **PLC-06**: Пользователь может открыть любое место и увидеть всё, что размещено в нём и во
      вложенных местах (устройства, АРМ, принтеры, картриджи), одним списком

### Места — формат отображения пути (PLC, добавлено 2026-08-28)

- [x] **PLC-07**: Администратор задаёт умолчание сокращения пути места для всей организации
      («Крайние» / «Два последних» / «Последнее») и разделитель между сегментами прямо в
      «Настройки → Организация», а не в файле конфигурации
- [x] **PLC-08**: Любое место может переопределить вариант сокращения; по умолчанию оно
      наследует выбор родителя, а при отсутствии переопределений у всех предков — умолчание
      организации

### История перемещений (HST)

- [x] **HST-01**: Каждая смена места устройства или картриджа записывается в историю: откуда,
      куда, когда, кем и по какой причине (вручную / актом / перетаскиванием на карте)
- [x] **HST-02**: Пользователь видит таймлайн перемещений в карточке устройства и картриджа
- [x] **HST-03**: Акт приёма-передачи автоматически меняет место переданных устройств и
      фиксирует в истории ссылку на номер акта
- [x] **HST-04**: Пользователь может получить отчёт о перемещениях за период с фильтром по месту
      и типу устройства

### Группы — модель и редактор (GRP)

> Заменяет категорию `WKS` (см. примечание о нумерации выше). Решения приняты в обсуждении
> 2026-10-04: АРМ — не отдельная сущность, а тип группы; поведение типа (`container` /
> `substitute` / `teardown`) хранится как данные.

- [ ] **GRP-01**: Тип группы имеет неизменяемый машинный код и поведение
      (`container` / `substitute` / `teardown`); три встроенных типа (АРМ, Системный блок,
      Разбор) засеваются при запуске идемпотентно по коду, переименовываются и дополняются
      свойствами, но не удаляются
- [ ] **GRP-02**: Администратор ведёт свойства типа (CRUD, порядок, обязательность) с типами
      данных Текст, Число, IP, MAC, Пользователи (с отметкой основного), Ссылки на устройства;
      у каждого свойства есть флаг «На карте»
- [ ] **GRP-03**: Свойство с заполненными значениями скрывается, а не удаляется; тип данных у
      заполненного свойства не меняется; IP и MAC нормализуются и проверяются на сервере
- [ ] **GRP-04**: Раздел «Группы» (дерево типов и групп слева, просмотр и правка справа) даёт
      CRUD групп; имя по умолчанию «{тип} #{seq}» берётся из целочисленного счётчика типа и
      никогда не вычисляется обратным разбором имени; уникальность имён не требуется
- [ ] **GRP-05**: Устройство входит не более чем в одну группу, вывод из состава — явное
      действие; группа может содержать группу с защитой от циклов и правилами допустимых детей
- [ ] **GRP-06**: Место группы протаскивается на все устройства состава, включая вложенные
      группы, с записью в журнал перемещений по каждому устройству; записи одного переноса
      связаны в один пакет
- [ ] **GRP-07**: Отдельное перемещение устройства, входящего в группу, запрещено — место
      задаётся только через группу (единственное исключение — активная ремонтная фаза, REP-07)
- [ ] **GRP-08**: Карточка группы показывает состав, место, привязанных пользователей (один
      отмечен основным) и подключённые принтеры: USB — производные от
      `printers.usb_host_device_id` и не редактируемые вручную, сетевые — по явным ссылкам,
      с дедупликацией при отображении
- [ ] **GRP-09**: Права на обоих транспортах: типы групп и свойства — только администратор;
      группы — администратор и специалист; менеджер — чтение; сотрудник доступа не имеет
- [ ] **GRP-10**: Удаление группы освобождает её устройства, не меняя их места, и требует
      подтверждения с количеством; удаление якорного устройства запрещено, пока группа
      существует

### Группы в разделе «Устройства» (GRD)

- [ ] **GRD-01**: Контекстное меню устройства содержит «Добавить в группу» и быстрые действия
      типов, порождаемые типами с включённым быстрым действием; действие открывает попап
      создания группы с предзаполненными типом и устройством; бессмысленные действия скрыты
      (устройство уже в группе или является якорем, статус «Списано» / «На списание»)
- [ ] **GRD-02**: «Замещение группой» прицепляет группу к устройству как якорь: в списке
      устройств остаётся одна строка с признаком группы и раскрытием состава, инвентарный и
      серийный номера остаются на устройстве и только отображаются группой
- [ ] **GRD-03**: «На разбор» переводит устройство в статус «На списание» и создаёт
      группу-запись разбора; добавленные в неё устройства появляются в общем списке и сохраняют
      неэксклюзивную ссылку «происхождение», не теряемую при включении в другую группу
- [ ] **GRD-04**: Введены статусы устройства «На списание» и «В ремонте»; подписи статусов
      читаются из одного справочника, прежний хардкод `id → подпись` в UI и бэкенде удалён и
      закрыт гейтом
- [ ] **GRD-05**: Правый клик по строке устройства или принтера открывает то же меню, что
      кнопка действий; двойной клик открывает попап просмотра
- [ ] **GRD-06**: Прежняя группировка одинаковых устройств переименована в «Свернуть
      одинаковые» — слово «группа» в интерфейсе означает только новую сущность

### Группы в актах и местах (GAM)

- [ ] **GAM-01**: В акте приёма-передачи можно выбрать группу: контейнерная разворачивается в
      список входящих устройств построчно, якорная идёт одной строкой, её внутренний состав
      печатается в комплектации
- [ ] **GAM-02**: Передача актом устройства из состава группы в другое место требует
      подтверждения; после подтверждения устройство выводится из состава
- [ ] **GAM-03**: Перемещения членов группы, вызванные актом, несут `act_id` и снимаются
      откатом акта
- [ ] **GAM-04**: В «Местах» вместо входящих в группу устройств отображается сама группа;
      чекбокс «Разворачивать группы» (по умолчанию выключен) показывает устройства вместо
      групп; счётчики содержимого считают физические устройства в обоих режимах

### Вложения (ATT)

- [ ] **ATT-01**: Файл хранится в каталоге `./attachments/` рядом с БД под именем от хэша
      содержимого, в БД — исходное имя, MIME, размер и хэш; лимит размера и whitelist MIME
      проверяются на сервере
- [ ] **ATT-02**: В серверном режиме файл отдаётся только под сессией и только при доступе к
      родительской сущности; фото и PDF открываются в попапе просмотра, остальные типы —
      ссылкой на скачивание; потерянный файл деградирует сообщением, а не ошибкой экрана
- [ ] **ATT-03**: Каталог вложений исключён из git и покрыт privacy-гейтом; инструкция по
      переносу portable-сборки и бэкапу называет каталог вложений, а не только файл БД

### Заявки — ремонт (REP)

- [ ] **REP-01**: В создании заявки три раздела: «Замена картриджа» / «Ремонт» / «Свободная
      форма»; в «Ремонте» — дропдаун устройств автора (устройства его АРМ и привязанные
      принтеры) плюс «Другое» и описание; категория «Ремонт техники» скрыта из свободной формы
      (не удалена — старые заявки её показывают)
- [ ] **REP-02**: Принятие в работу заявки с устройством открывает попап «Перемещение
      устройства» (быстрый выбор склада, любое место из дерева, кнопки «Отмена» / «Без
      перемещения» / «Переместить», запоминание последнего выбора); перемещённое устройство
      получает статус «На ремонте»
- [ ] **REP-03**: У заявки в работе в шапке доступны «Забрать на склад», «Отправить в ремонт» и
      «Завершить»; «Забрать на склад» закрывает случай «Без перемещения» при принятии
- [ ] **REP-04**: «Отправить в ремонт» открывает попап с датой, кем выдано, кому выдано и
      местом (последнее место ремонта по умолчанию), переводит устройство в статус «В ремонте»
      и заявку — в статус «В ремонте»
- [ ] **REP-05**: После отправки кнопка сменяется на «Забрать из ремонта»; забор работает как
      забор картриджа с заправки и позволяет приложить файл с результатами работ
- [ ] **REP-06**: «Завершить» предлагает вернуть устройство на место, которое было до ремонта
      (сохранённое на заявке при первом перемещении), с комментарием и вложением
- [ ] **REP-07**: История заявки показывает уход в ремонт и возврат; устройство в активной
      ремонтной фазе может иметь место, отличное от места его группы — единственное исключение
      из GRP-07, членство в группе при этом сохраняется

### Переписка в заявке (MSG)

- [ ] **MSG-01**: У заявки в работе и инициатор, и специалист отправляют сообщения с
      возможностью приложить файл; прежний блок комментария только для администратора убран
- [ ] **MSG-02**: Сообщения показываются в «Истории» вместе с событиями жизненного цикла в одном
      хронологическом порядке (сообщения — своя таблица, события — `audit_log`, слияние на
      чтении)
- [ ] **MSG-03**: Переписка видна только участникам заявки на обоих транспортах; новое сообщение
      доезжает до открытой карточки без перезагрузки (WebSocket)

### Устройства сотрудника (EMP)

- [ ] **EMP-01**: У роли «Сотрудник» в веб-интерфейсе два раздела — «Заявки» и «Устройства»;
      остальные маршруты отдают «Доступ запрещён»
- [ ] **EMP-02**: В «Устройствах» сотрудник видит одним плоским списком все устройства всех
      своих АРМ и привязанные принтеры с полным описанием (наименование, тип, модель, серийный
      и инвентарный номера, место, статус); при отсутствии привязок — пустое состояние с
      подсказкой обратиться к администратору
- [ ] **EMP-03**: Из строки сотрудник создаёт заявку на ремонт (любое устройство) или на замену
      картриджа (если в строке принтер) с подставленным устройством; сервер отдаёт сотруднику
      только его устройства

### Заявки — умный подбор принтера (REQ)

- [ ] **REQ-07**: В заявке на замену картриджа принтеры ранжируются: USB-принтеры АРМ автора →
      принтеры его помещения → его этажа → его здания → остальные
- [ ] **REQ-08**: Принтер подставляется в форму заявки автоматически, если у автора есть
      единственный очевидный кандидат (принтер его АРМ или единственный принтер его помещения)

### Карта — просмотр (MAP)

- [ ] **MAP-01**: Администратор или менеджер выбирает план этажа или зоны и видит схему
      помещений с размещёнными на ней устройствами и АРМ
- [ ] **MAP-02**: К плану можно приложить готовую подложку в формате JPG и работать поверх неё
- [ ] **MAP-03**: Клик по маркеру открывает карточку устройства или АРМ; клик по помещению —
      список размещённого в нём
- [ ] **MAP-04**: План печатается на лист A4 через существующий механизм печати (десктоп и LAN)
- [ ] **MAP-05**: Роль «Сотрудник» не имеет доступа к разделу «Карта» и к её данным ни на
      Tauri-, ни на HTTP-транспорте

### Карта — редактор планов (EDT)

- [ ] **EDT-01**: Пользователь рисует контур помещений ортогональными стенами по сетке с
      привязкой к её узлам
- [ ] **EDT-02**: Пользователь размещает двери и окна как вырезы на стене, с общепринятыми
      условными обозначениями
- [ ] **EDT-03**: Нарисованное помещение связывается с местом из дерева — после связывания клик
      по нему показывает содержимое этого места
- [ ] **EDT-04**: Устройства и АРМ размещаются на плане перетаскиванием из палитры, с поворотом
      значка
- [ ] **EDT-05**: Действия в редакторе отменяются и повторяются (undo / redo)
- [ ] **EDT-06**: Слои содержимого (подложка / стены / помещения / устройства) переключаются
      независимо друг от друга

### Живые статусы на карте (LIV)

- [ ] **LIV-01**: Маркер принтера на карте окрашен по состоянию: уровень тонера, недоступность
      по SNMP, открытая заявка
- [ ] **LIV-02**: Статусы обновляются на открытой карте без перезагрузки страницы (WebSocket)

### Шаблоны инвентарных номеров (NUM, добавлено 2026-09-18 с Фазой 40.2)

> Источник — `.planning/phases/40.2-inventory-number-templates/40.2-SPEC.md`, пункты 1–16 (NUM-NN = пункт NN).

- [x] **NUM-01**: Администратор ведёт в «Настройки / Организация» шаблоны номеров (CRUD) четырёх типов — «Устройства и принтеры», «Акты», «Картриджи», «Фотобарабаны»; маска уникальна в пределах типа, список показывает следующий номер или «переполнен», есть справка по токенам
- [x] **NUM-02**: Маска поддерживает только токены `[YYYY]`, `[YY]`, `[MM]`, `[DD]` и ровно один `[X…]` (`[X]` — без дополнения, `[X…N]` — N разрядов с ведущими нулями); остальной текст буквальный; маска без `[X…]` или с двумя такими токенами не сохраняется
- [x] **NUM-03**: Форма шаблона показывает живой предпросмотр следующего номера с учётом существующих записей этого типа
- [x] **NUM-04**: Сервер вычисляет «первый свободный» и «max+1» по живым записям пространства, подходящим под маску (trim, без учёта регистра, последовательность отдельно на каждый развёрнутый префикс даты); счётчик не хранится, мягко удалённые записи номер не занимают
- [x] **NUM-05**: Переполненный шаблон (нет свободных чисел в разрядности) недоступен в меню «Вставка» и помечен «переполнен» в настройках; при разрыве без места для max+1 подставляется разрыв без переключателя
- [x] **NUM-06**: В попапах «Новое устройство», «Новый принтер», «Новый акт» и «Новый картридж/фотобарабан» поле номера автоподставляет «первый свободный» по запомненному шаблону; кнопка «Вставка» открывает меню шаблонов своего типа и пункт «Без шаблона»
- [x] **NUM-07**: Если «первый свободный» ≠ «max+1», внутри поля есть переключатель ↑/↓ между ними; он виден, только пока значение равно одному из двух предложенных
- [x] **NUM-08**: Сервер хранит последний использованный шаблон (или «без шаблона») для 5 контекстов создания, общий для всех пользователей и режимов; несоответствие, отсутствие выбора или удаление шаблона переводят контекст в «без шаблона»
- [x] **NUM-09**: Сервер запрещает сохранять номер, занятый живой записью того же пространства (устройства+принтеры / акты / картриджи+фотобарабаны; trim, без учёта регистра) при создании и правке, в Tauri и HTTP, атомарно при параллельных запросах; пустой инвентарный № не проверяется
- [x] **NUM-10**: При сохранении занятого номера показывается попап «Номер занят» со сведениями о занявшей записи и кнопкой «Взять следующий свободный» (при активном шаблоне)
- [x] **NUM-11**: При выбранном шаблоне и несоответствующем ему значении сохранение показывает попап «Поправлю / Продолжить» (danger); «Продолжить» сохраняет номер как есть и переводит контекст в «без шаблона»
- [x] **NUM-12**: Номер со смешением кириллицы и латиницы или совпадающий с живым номером после замены похожих букв вызывает неблокирующее предупреждение «Поправлю / Продолжить»
- [x] **NUM-13**: Счётчики `act_number`, `cartridge_seq`, `drum_seq` больше не используются; миграция засевает шаблоны `[X]`, `C-[XXXX]`, `D-[XXXX]` и назначает их контекстам акта/картриджа/фотобарабана; без шаблона № акта и код картриджа обязательны
- [x] **NUM-14**: Номер акта передачи хранится как текст (существующие номера конвертируются без потерь); возврат наследует номер родителя с суффиксом «вN» (N начинается с 1; безцифровой формы «в» не существует — Фаза 40.5) и не участвует в последовательности шаблона
- [x] **NUM-15**: Миграция переименовывает существующие дубли инвентарных номеров живых устройств (кроме самой ранней записи группы) в `ДУБЛЬ-NNNNNN (<исходный>)` со сквозной нумерацией и записью в аудит, не падая
- [x] **NUM-16**: Импорт CSV не импортирует строки с инвентарным номером, занятым в БД или выше в том же файле, и сообщает о них в отчёте как «номер уже занят»

## Out of Scope

| Feature | Reason |
|---------|--------|
| CAD-точность: произвольные углы стен, размерные линии, привязки к произвольным объектам | Отдельный продукт по объёму; ортогональные стены по сетке дают ту же наглядность за долю усилий |
| Импорт DXF / SVG / AutoCAD | Готовые планы у пользователя в JPG; парсер CAD-форматов не окупается |
| Рендер PDF-подложек (`pdf.js`) | Подтверждено: планы в JPG. Вернуть только если появятся PDF-исходники |
| Canvas-движки (Konva, Fabric) | На 100–150 объектах на плане SVG выигрывает: hit-testing, a11y и печать через существующий HTML-пайплайн — бесплатно |
| JointJS, tldraw | Лицензионный риск на публичном репозитории |
| react-planner, blueprint-js, SweetHome3D | React / Java / заброшены; починка чужого мёртвого кода дороже собственного узкого редактора |
| 3D-визуализация помещений | Ценность учёта от неё не зависит |
| Доступ сотрудника к карте | Решение пользователя: карта раскрывает IP, модели и серийники — граница Фазы 10 не продавливается |
| Миграция существующих значений размещения | Приложение не в реальной эксплуатации, все акты в БД тестовые — данные обнуляются |
