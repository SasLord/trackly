# Requirements: Trackly — Milestone v1.1.2

**Defined:** 2026-07-07
**Milestone:** v1.1.2 — Пост-релизные доработки UX и печати
**Core Value:** Учёт устройств и картриджей с актами приёма-передачи и историей перемещений должен работать надёжно и быстро в режиме «одной кнопкой» — без обращения к Excel-таблицам, ручного присвоения номеров актов или потери истории при возврате на склад.
**Source:** Обратная связь после тестирования релиза v1.1.1 (6 пунктов, подтверждённых пользователем 2026-07-07).

## Milestone v1.1.2 Requirements

Требования этого milestone. Каждое маппится на фазу роадмапа.

### Автокомплит и дропдауны (AUTO)

- [x] **AUTO-01**: Дропдаун любого автокомплита в приложении рендерится в `body` (portal/teleport), а не внутри диалогового окна — список не обрезается, не добавляет внутренний скролл и не ломает верстку модалки.
- [x] **AUTO-02**: При фокусировке на поле выбора устройства (Акты → Позиции) дропдаун раскрывается сразу со списком доступных устройств — без необходимости начинать ввод.
- [x] **AUTO-03**: Ввод символов в поле выбора устройства фильтрует список автокомплита по наименованию (сейчас фильтрация не работает).
- [x] **AUTO-04**: Одинаковые по наименованию устройства объединяются в раскрываемую группу в дропдауне; раскрыв группу, пользователь видит и выбирает конкретный экземпляр с его значениями (инвентарный №, серийный №, модель, состояние).
- [x] **AUTO-05**: Если после фильтрации в дропдауне остаётся единственная группа, она не отображается как группа — вместо неё сразу выводятся устройства из этой группы (плоский список).

### Акты (ACT)

- [x] **ACT-01**: При создании акта значение поля даты «Когда отдали» учитывается и сохраняется как дата акта (сейчас всегда подставляется текущая дата).
- [x] **ACT-02**: Пользователь может отредактировать существующий акт — кнопка «Редактировать» активна и открывает рабочую форму редактирования. (gap CR-01 — reconcile archived при edit — закрыт в Plan 19-06)
- [x] **ACT-03**: Пользователь может отредактировать существующий return-акт — «Редактировать» на возврате активна, открывает диалог «Возврат по акту №XXX» с прежними значениями; изменённый возврат сохраняется без ошибок с пересборкой эффектов на устройства по дельте. (Phase 22; отменяет D-07 «return-акты нередактируемы».)

### Печать документов (PRN)

- [ ] **PRN-01**: При печати акта приёма-передачи из раздела Устройства в шапку документа попадает полный контекст организации (логотип, название, ИНН и прочие реквизиты), а не только данные устройства и сторон «сдал/принял».

### Настройки организации (ORG)

- [ ] **ORG-01**: Логотип организации можно загрузить в формате SVG, и он корректно и безопасно встраивается в шаблоны актов/отчётов (SVG санитизируется или вставляется через `<img src="data:...">`, где встроенные скрипты не исполняются).
- [ ] **ORG-02**: В данных организации есть вторая строка адреса, чтобы при необходимости разбить адрес на две строки в печатных формах.

### Картриджи (CRT)

- [ ] **CRT-01**: Автоматически присваиваемый Код нового картриджа имеет формат `C-XXXX` (вместо `C-XXXXXX`), а нового фотобарабана — `D-XXXX`.

## Future Requirements

Отложено на будущие milestone. Отслеживается, но не в текущем роадмапе.

### Шаблоны и документы (DOC)

- **DOC-01**: Редактор шаблонов печатных форм в UI (WYSIWYG / расширенное редактирование сверх текущего textarea).
- **DOC-02**: Импорт/экспорт .docx шаблонов.
- **DOC-03**: Прочие виды печатных документов помимо акта приёма-передачи/выдачи.
