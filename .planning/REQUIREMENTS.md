# Requirements — Milestone v1.3.3 «Печатные формы и приватность данных»

**Defined:** 2026-08-08
**Core Value:** Учёт устройств и картриджей с актами приёма-передачи и историей перемещений
должен работать надёжно и быстро в режиме «одной кнопкой» — без обращения к Excel-таблицам,
ручного присвоения номеров актов или потери истории при возврате на склад.

**Milestone goal:** привести акты приёма-передачи к каноничному виду с единой шапкой и
корректной многостраничностью, и закрыть утечку реальных данных организации и сотрудников
в публичный репозиторий.

**Baseline:** веха v1.3 закрыта 2026-08-08. Печать уже переведена на Paged.js (Phase 33) —
превью и печать совпадают на обоих транспортах, многостраничный рендер подтверждён живым
UAT 2026-08-05. HTML-шаблоны живут файлами в `templates/` рядом с исполняемым файлом
(Phase 16), с вшитыми дефолтами через `include_str!`. Эта веха меняет содержимое и вёрстку
шаблонов, а не механизм печати.

**Жёсткое условие вехи (и всего проекта):** репозиторий публичный; реальные данные
организации и людей не попадают в него никогда — см. `CLAUDE.md` → Constraints.

## v1.3.3 Requirements

### DOC — Печатные формы

- [x] **DOC-04**: Все три печатные формы (акт приёма-передачи, акт приёмки, отчёт) выводят
  одинаковую шапку — лого, название и реквизиты организации — в единой типографике.
- [x] **DOC-05**: Название организации в шапке берётся из настроек (`org.name`); ни в одном
  поставляемом шаблоне нет захардкоженного реального названия организации.
- [ ] **DOC-06**: Пользователь с уже установленным Trackly получает новую шапку после
  обновления, не удаляя свой каталог `templates/` вручную.
- [ ] **DOC-07**: В акте приёма-передачи нет полосок-подчёркиваний под автоматически
  подставляемым текстом; полоски остаются только там, где расписываются от руки.
- [ ] **DOC-08**: Блок подписей — горизонтальный, по строке на каждого подписанта, с
  автоматически подставленными ФИО передающего и принимающего.
- [ ] **DOC-09**: Текст акта составлен в каноничной форме документа приёма-передачи
  (две стороны, предмет, состояние, срок, подписи) и согласован с пользователем до вёрстки.
- [ ] **DOC-10**: Акт на одно устройство умещается на одном листе вместе с полным описанием
  этого устройства.
- [ ] **DOC-11**: Акт на несколько устройств выводит на первом листе только перечень имён с
  отсылкой к «Приложению №1», а со второго листа — «Приложение №1» с таблицей полного
  описания устройств.

### PRIV — Приватность данных

- [ ] **PRIV-01**: В текущем состоянии репозитория нет реальных реквизитов организации и ФИО
  сотрудников — ни в коде, ни в шаблонах, ни в тестах, ни в `.planning/`-артефактах.
- [ ] **PRIV-02**: Попытка закоммитить реальные реквизиты организации или ФИО сотрудников
  ловится автоматической проверкой до попадания в репозиторий.

### QA — Качество

- [ ] **QA-04**: Фаза 32 имеет подтверждённое Nyquist-покрытие (`32-VALIDATION.md`:
  `nyquist_compliant: true`).

## Out of Scope

Явно исключено, чтобы не расползался объём.

| Feature | Reason |
|---------|--------|
| Переписывание истории git | Решение пользователя 2026-08-08: чистим только HEAD, репо остаётся публичным, остаточный риск принят осознанно. Не предлагать повторно без запроса пользователя. |
| Смена пароля `svc-ldap-readonly` | Операционное действие пользователя на его инфраструктуре, не изменение кода. |
| SSO-01 для входа по логин/паролю | Переклассифицировано 2026-08-08 в осознанное ограничение: форма обслуживает локальные учётки, которые выдаёт администратор (недоменные машины по LAN + отдельные учётки специалиста/администратора). ФИО таких учёток ведёт администратор. Ветка `try_ad_login` — запасной выход вне рабочего сценария. |
| Изменение механизма печати (Paged.js, транспорты) | Закрыто в Phase 33 и подтверждено живым UAT. Эта веха меняет содержимое шаблонов, а не движок. |
| Смена ролевой видимости `ad_register` | Решено 2026-08-08: остаётся admin-only, запиннено тестом (quick `260808-np4`). |
