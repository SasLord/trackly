## 4. Межфазная интеграция

Проверялись швы, которые пофазная верификация по построению увидеть не могла.

### BLOCKER-1 — удаление места с историей перемещений падает сырой ошибкой SQLite

**REQ: PLC-01, HST-01. Шов: Фаза 39 (удаление узла) ↔ Фаза 40 (новые FK).**

`V040__place_movements.sql:53,55` добавил:

```sql
from_place_id INTEGER NOT NULL REFERENCES places(id) ON DELETE RESTRICT,
to_place_id   INTEGER NOT NULL REFERENCES places(id) ON DELETE RESTRICT,
```

Предполётная проверка удаления суммирует четыре счётчика и ни одного из новых:

- `place_service.rs:479` — `device_count + nested_places + cartridge_count + referencing_act_count`
- `places_sqlite.rs:555` — тот же набор
- `SubtreeStats` (`trackly-core/src/domain/places.rs:135`) — полей под перемещения нет

`delete_hard` делает настоящий `DELETE FROM places` (`places_sqlite.rs:570`) при
`PRAGMA foreign_keys = ON` (`db/pragmas.rs:58,70`). Пустое место, из которого или в которое
когда-либо что-то перемещали, проходит проверку как «удалять безопасно», `DELETE` ловит
FK-RESTRICT, `map_rusqlite` (`error_conversions.rs:38`) отдаёт `AppError::Conflict` с сырым
английским текстом SQLite — и он попадает в русскоязычный диалог «Удалить место?».

Это буквально тот же дефект, который Фаза 39 закрывала как CR-01 для актов: комментарий об
этом стоит строкой выше проверки. Фаза 40 завела новую входящую ссылку и не дописала
счётчик. Покрытия нет — ни `places_delete_blocked.rs`, ни `places_crud.rs` не упоминают
`place_movements`.

**Починка:** поле в `SubtreeStats` + слагаемое в обе проверки + ветка в
`build_delete_blocked_message` + тест по образцу CR-01-го.

### BLOCKER-2 — фильтр «по типу устройства» в отчёте «Перемещения» недостижим из UI

**REQ: HST-04. Шов: Фаза 40 (бэкенд-фильтр) ↔ UI отчётов.**

Бэкенд готов: `report_service.rs:1449-1455` применяет `filter.type_id` к домену перемещений,
`ReportsPage.svelte:583` даже передаёт `typeId={filter.type_id ?? null}`.

Но `ReportFilters.svelte:85` деструктурирует проп как `typeId: _typeId` — «принято и не
используется», — и контрола нигде не отрисовано. Для домена `movements` в шаблоне
(`ReportFilters.svelte:114-140`) отрисованы ровно два `PlacePicker` — «Откуда» и «Куда».
Та же судьба у `statusId`, `modelId`, `color`, `search`, `deviceTypes`.

Сквозной grep по `ui/src/features/reports/` даёт три вхождения `type_id`/`typeId` — объявление
типа, объявление типа, передача пропа. Ни одного контрола.

**Починка:** отрисовать выбор типа устройства в ветке `movements`, попутно решить судьбу
пяти остальных принятых-и-выброшенных пропов.
