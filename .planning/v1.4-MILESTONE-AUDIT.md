## 4. Межфазная интеграция

**22 из 24 связей прослежены end-to-end. Блокеров нет. Осиротевших экспортов нет.**

### Паритет транспортов — 12/12

Все 12 операций `places_*` доступны и из Tauri-вебвью, и по HTTP
(`POST /api/v1/places_*`), и все проходят через один `PlaceService` — ни один
HTTP-хендлер не обходит сервисный слой. Это ключевой архитектурный инвариант проекта
(транспорты — тонкие адаптеры над сервисом, владеющим единственным писателем SQLite),
и здесь он соблюдён.

### E2E-потоки — 7/7 завершаются

| Поток | Статус |
|-------|--------|
| Устройство с местом → список → поиск по пути → содержимое места (обе кнопки) | ✓ |
| Акт → `place_id` + замороженный `place_path_snapshot` → печать → возврат меняет место | ✓ |

| CSV-импорт устройств по пути → резолв по дереву → текст ошибки | ✓ (W6) |
| Переименование/перемещение → всё пересчитывается без реиндекса | ✓ (W9) |

Две проверки заслуживают отдельного упоминания, потому что закрывают известные
исторические ловушки проекта:

- **Ловушка «шаблон живёт на диске, а не в бандле»** (см. долг вехи v1.1.2) на этот
  раз обработана: коммит `7c819876` зарегистрировал `_legacy_defaults/v26/act_handover.html`,
  и сверка `git show 7c819876^:…act_handover.html` с этим снимком дала байт-в-байт
  совпадение. Значит `upgrade_untouched_defaults_on_startup` распознает дофазовый файл
  как нетронутый дефолт и перезапишет его, а не пометит пользовательским.
- **Парность «запрос ↔ счётчик» в отчётах** соблюдена: рекурсивный CTE подветки есть
  и во всех `query_*`, и во всех `count_*`. Это обычное место, где фильтр и пагинация
  разъезжаются молча.

### Что осыпалось по краям

Полный список — в `tech_debt` во frontmatter. Три подтверждены прямой проверкой
исходников в этой сессии:

**W1 (высокая) — отчёт «Заявки» теряет имя принтера.**
`report_service.rs::combine_printer_and_place` склеивает колонку как
`"<имя принтера>, <полный путь>"`. `ReportTable.svelte::shortPlacePath` применяет
D-26-обрезку к `place_path` безусловно: режет по `' / '` и оставляет два последних
сегмента. Для `"Kyocera-01, Здание А / 2 этаж / 214"` получается `"2 этаж / 214"` —
имя принтера исчезает из ячейки на всех четырёх вкладках «Заявки», как только путь
глубже двух уровней. Данные целы (полная строка в `title`), поэтому не блокер.
**Воспроизведено** прогоном точной shipped-логики:

```
"Kyocera-01, Здание А / 2 этаж / 214"  →  ячейка "2 этаж / 214"   имя принтера ПОТЕРЯНО
"HP-07, Здание Б / 1 этаж"             →  ячейка без изменений    имя принтера цело
```

Ломается ровно при пути в ≥3 сегмента, то есть **на мелком демо-дереве дефект невидим** —
поэтому его и не поймал живой UAT. Это межфазный стык: D-26 из Фазы 39 наехал на
`combine_printer_and_place` из Фазы 12, и тесты каждой фазы по отдельности этого не видят.

**W2 — заголовки экспорта разошлись с экраном.**
`column_labels_for` отдаёт «Локация» / «Расположение» / «Принтер / Локация»;
`ReportsPage.svelte` COLUMNS_MAP везде «Место». Док-комментарий самой `column_labels_for`
объявляет инвариант «labels are sourced from ReportsPage.svelte's COLUMNS_MAP so printed
headers match the on-screen report table» — инвариант нарушен, печатный отчёт несёт
дофазовый словарь.

**W3 — история картриджа показывает сырой FK.**
`CartridgeDetail.svelte:92` выводит `String(p.place_id)` — в строке истории вместо пути
стоит число. Дофазовые записи с ключом `"location"` теперь молча отбрасываются, то есть
деталь размещения из старой истории исчезает совсем. В коде помечено как осознанный
компромисс («потребовало бы сетевого запроса внутри синхронного парсера»), но PLC-04
требует, чтобы списки показывали место из дерева.

**Закрыто с прошлого раза:** отложенный пункт Wave 6 (устаревшие ключи `location*` в
payload'ах `role_endpoint_matrix.rs`) — свип планов 39-21/39-22 отработал, ключи теперь
`place_id`/`bulk_place_id`.

## 5. Риски на будущие фазы

Не пробелы поставленного — предупреждения о том, где форма Фазы 39 будет мешать
Фазам 40–45.

| # | Блокирует | Риск |
|---|-----------|------|
| **F1** | HST-01/02/03 | Перемещение устройства пишется из **четырёх** методов репозитория (`update_in_tx`, `update_status_and_place_in_tx`, `update_status_place_condition_in_tx`, `restore_from_snapshot`), и все вызовы `audit_log` в device/act/cartridge-сервисах хардкодят `user_id: None`. `place_service.rs` в этом смысле образцов — пишет `caller.user_id`. Фазе 40 придётся либо инструментировать все четыре пути, либо поднять хук на уровень сервиса, и отдельно протянуть личность вызывающего — иначе «кто переместил» будет пустым |
| **F2** | WKS-01 | D-23 держится: четвёртый вид в `PlaceContents` аддитивен (union `ContentTab`, ещё один `UNION ALL` в `list_subtree_contents_impl`, у `CONTENT_KIND_LABELS` уже есть fallback). **Но** если АРМ решат моделировать как *вид места*, `V037` содержит `CHECK (kind IN (...))`, а SQLite не умеет `ALTER` для `CHECK` — потребуется миграция с пересборкой таблицы |
| **F3** | REQ-07, REQ-08 | `RequestPrinterOptionDto` несёт `place: Option<String>` — путь строкой, без идентификатора. DTO намеренно минимален по BOLA-соображениям — значит добавление поля это точка повторного security-review, а не механическая правка |
| **F4** | MAP-01, EDT-01/03/04 | В `places` нет геометрии: ни координат, ни размеров, ни ссылки на подложку плана. Нужна аддитивная миграция (колонки или отдельная `place_geometry`) до Фазы 43. Дерево и `place_full_paths` при этом не трогаются — переписывания не будет, риск низкий |
