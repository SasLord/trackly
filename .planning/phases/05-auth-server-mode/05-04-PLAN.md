<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session identity→authorize() | Identity from session is the only input to authorize(); no trust granted to request body |
| Tauri command→desktop_identity | desktop_identity() is the trust source for Tauri; no user input bypasses this |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-16 | Elevation of Privilege | missing authorize() on mutation handler | mitigate | Every mutation handler in devices/acts/cartridges has explicit authorize() call; role_endpoint_matrix CI test enforces this permanently |
| T-05-17 | Elevation of Privilege | Tauri command bypassing RBAC | mitigate | All Tauri mutation build_* functions accept caller Identity + call authorize(); desktop_identity() is the only identity source |
| T-05-18 | Elevation of Privilege | employee reading sensitive data | accept | ReadData action allows all authenticated users to read; this is by design (USR-02: manager/employee can read devices/acts/cartridges) |
| T-05-19 | Tampering | role field forged in session | mitigate | Session data is server-side (rusqlite store); cookie contains only opaque session ID — role cannot be forged in cookie |
</threat_model>
