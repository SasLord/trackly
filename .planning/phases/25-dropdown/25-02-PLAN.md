<!-- Design decision made by this plan (Task 1) for Plan 25-03, 25-06, 25-07 to consume verbatim. -->

**Dropdown.svelte** uses Svelte 5 generics (`<script lang="ts" generics="TGroup, TMember">`) so the
device-specific `DeviceGroup`/`DeviceDto` types stay in the pilot consumer (`ActFormItemsTable.svelte`), per
PATTERNS.md's explicit instruction that the primitive itself must not import `$lib/api/devices` or
`../../bindings`.

Props:
- `variant: 'combobox' | 'select'` (D-03) — this plan implements `'combobox'` fully; `'select'` is
  implemented in Plan 25-03 (this plan should still accept the prop and branch on it, leaving the `'select'`
  branch as a clearly-marked follow-up for 25-03, not a runtime error).
- `flat?: boolean` (default `false`) — when `true`, renders the plain flat-list variant (SC #3: no groups
  concept, `groups` prop IS the flat option list, checkmark `✓` on `isGroupSelected`, no drill-in, panel
  `max-height: 240px`). When `false` (default), renders the grouped/drill-in variant (SC #4: `×N` count +
  `›` chevron on expandable groups, drill-in on click, panel `max-height: 280px`). Reuses the SAME `groups`/
  `TGroup` shape in both modes — `flat` only changes rendering/interaction, not the data contract.
- `value: string` — one-way, NOT `$bindable` (this primitive follows the controlled-component convention:
  caller re-renders `value` via its own `onQueryInput`/pick callbacks, exactly like `PersonAutocomplete.svelte`
  passes `value={row.query}` one-way in `ActFormItemsTable.svelte`'s existing pattern before this
  extraction — do not introduce two-way `$bindable` binding here, it would fight the caller's `onChange`-based
  immutable-array-update architecture).
- `placeholder?: string`, `searchPlaceholder?: string` (default `'Поиск'`, select-variant only, wired in
  25-03), `invalid?: boolean`, `disabled?: boolean`.
- `loading: boolean` — caller-controlled fetch-in-flight flag (drives the "Загрузка…" panel state).
- `groups: TGroup[]` — current, already-filtered group/option list (caller performs the actual search/fetch;
  Dropdown only renders what it's given).
- `getGroupId: (g: TGroup) => string | number`, `getGroupName: (g: TGroup) => string`,
  `getGroupMeta?: (g: TGroup) => string | undefined` (e.g. model), `getGroupSub?: (g: TGroup) => string |
  undefined` (e.g. serial/inventory row, rendered `.tr-mono` in flat mode per UI-SPEC), `getGroupCount: (g:
  TGroup) => number`, `isGroupExpandable: (g: TGroup) => boolean`, `isGroupSelected?: (g: TGroup) => boolean`
  (flat-mode checkmark).
- `onExpandGroup: (g: TGroup) => Promise<TMember[]> | TMember[]` — drill-in fetch callback. Called BOTH on a
  manual click of an expandable group (`showBack = true`) AND internally by Dropdown's own AUTO-05
  auto-flatten logic (`showBack = false`) — this is the mechanism that lets AUTO-05 live inside the
  component while data-fetching stays in the caller.
- `getMemberId: (m: TMember) => string | number`, `getMemberName: (m: TMember) => string`,
  `getMemberMeta?: (m: TMember) => string | undefined`, `getMemberSub?: (m: TMember) => string | undefined`.
- `onSearch: (query: string) => void` — fires after Dropdown's own internal 250ms debounce on typed input,
  and IMMEDIATELY (no debounce) on focus (AUTO-02). Dropdown owns this debounce internally (250ms constant,
  matching the existing UX in `ActFormItemsTable.svelte`'s `handleQueryInput`) so every future consumer
  inherits it for free rather than re-implementing debounce six times across phases 26-28.
- `onQueryInput?: (query: string) => void` — fires SYNCHRONOUSLY on every keystroke (combobox variant only),
  BEFORE the debounced `onSearch` — lets the caller keep its own `value` prop in sync with the DOM input on
  every keystroke (controlled-input pattern; without this the one-way `value` prop would fight the user's
  typing after the first re-render).
- `onPickGroup: (g: TGroup) => void`, `onPickMember: (m: TMember) => void`.

Internal (NOT props) state owned by Dropdown itself, per D-02: `open` ($state, boolean — opens on focus/click,
closes on outside-click/Escape/pick, mirrors `PersonAutocomplete.svelte`'s existing self-contained
`$effect`-based `mousedown`/click-outside pattern — since Dropdown is now a single, non-row-indexed instance
per usage, this per-instance pattern is a direct precedent, NOT `ActFormItemsTable.svelte`'s current
row-indexed `Record<number, T>` pattern, which PATTERNS.md explicitly says collapses away once extracted),
`viewMode: 'groups' | 'members'`, `activeGroup: TGroup | null`, `members: TMember[]`, `showBack: boolean`,
`activeIndex: number` (keyboard nav — wired fully in 25-03, but the state field is declared here since the
view-mode transitions in this plan already need to reset it).

State-machine rule (implemented as a `$effect` watching the `groups` prop, mirroring
`ActFormItemsTable.svelte`'s existing end-of-`fetchGroups` branch at lines 218-229): whenever `groups`
changes, if `groups.length === 1` call `onExpandGroup(groups[0])`, set `viewMode = 'members'`, `members` to
the resolved result, `showBack = false` (AUTO-05); otherwise reset `viewMode = 'groups'`, `activeGroup =
null`, `members = []`, `showBack = false`. Manual drill-in (user clicks an expandable group in `flat=false`
mode) calls `onExpandGroup(g)` with `showBack = true` instead, via a separate `drillInto` function — NOT the
`$effect`.

Drill-in header markup (member-view only): title (`{@render}`-derived from `getGroupName(activeGroup)` +
optional `getGroupMeta`) is ALWAYS rendered; the `← Назад` button is rendered ONLY when `showBack` is true —
these are two independent conditions per the UI-SPEC correction of CONTEXT.md, not a single boolean. Clicking
`← Назад` calls a `backToGroups()` function resetting the same four fields the `$effect`'s "reset" branch
sets.

Panel element: `<ul use:portal use:dropdownAnchor={{ anchorEl: fieldEl, maxHeight: flat ? 240 : 280 }}
role="listbox" class="tr-dropdown-panel">` — reuses `portal`/`dropdownAnchor` VERBATIM (D-02), no
reimplementation. `fieldEl` is a raw `<input>` (combobox variant, this plan) or `<button>` (select variant,
25-03) DOM ref via `bind:this` — `Input.svelte` has no ref-forwarding (see `ActFormItemsTable.svelte`'s
existing comment on this at its own `.device-input`), so the combobox field is a raw `<input>`, matching the
established precedent.

Empty/loading panel rows (D-13, canonical copy): `<li class="tr-dropdown-empty">Ничего не найдено</li>` when
the applicable list (groups or members) is empty and not loading; `<li class="tr-dropdown-loading"><Spinner
size="sm" />Загрузка…</li>` when `loading` is true — both rows are 46px tall, `color: var(--tr-text-tertiary)`,
centered, matching a normal option row's height so the panel doesn't jump size when state changes.
</interfaces>
