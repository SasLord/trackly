## Группы в Dropdown

### Модель групп

| Option | Description | Selected |
|--------|-------------|----------|
| Drill-in как в .dc и в коде | Клик по группе заменяет содержимое панели на экземпляры + шапка «назад». Совпадает и с Dropdown.dc, и с работающим ActFormItemsTable — нулевой риск поведенческой регрессии. Формулировка SC #4 правится под факт | ✓ |

## Граница фазы

### Разделение работы между фазами 25 и 26

| Option | Description | Selected |
|--------|-------------|----------|
| 25 — только строки, 26 — окно целиком | Фаза 25 трогает DeviceListRow/DeviceGroupRow и шапку таблицы. Шапка окна, фильтры, layout, пустые состояния — фаза 26 | ✓ |

**User's choice:** Сначала было выбрано «25 доводит Устройства до макета», затем — после того, как последствия были названы явно — **пересмотрено в пользу «25 только строки»**.
**Notes:** Второй вариант означал перенос требования **WIN-02** из фазы 26 в фазу 25, то есть правку роадмапа, а не решение внутри фазы: фаза 26 схлопывалась до одного окна, фаза 25 забирала её SC #2 и SC #3 (сохранение фильтров, автокомплитов, CRUD, CSV-импорта), и требовалась синхронная правка ROADMAP.md и REQUIREMENTS.md — иначе верификация упала бы на расхождении (та же ловушка, что D-06 фазы 24). После явного подтверждающего вопроса пользователь отклонил перенос. Роадмап остаётся нетронутым.

## Токены и расхождения с референсом

**Notes:** Разведка показала, что `--tr-group` отсутствует в `_tokens.scss`, хотя `TableRows.dc` его требует и задаёт (#e9edf5 / #1a212b). Остальные девять нужных токенов проверены и присутствуют. Ровно на такой дыре фаза 24 уронила сборку через closed-world гейт `ui/scripts/check-tokens.mjs`.

### Правило разрешения конфликтов

| Option | Description | Selected |
|--------|-------------|----------|
| Стили — из .dc, содержание — из приложения | Референс — истина по высотам, цветам, шрифтам, отступам. Тексты, колонки, данные — из реального экрана | ✓ |

**Notes:** Проверка колонок показала, что расхождение минимально: `DeviceList` и `TableRows.dc` совпадают по всем восьми колонкам и их порядку, различается только заголовок последней («Действия» против пустого с «⋯»).

## Состояния и доступность

### Состояние «выбрана» (CMP-06)

| Option | Description | Selected |
|--------|-------------|----------|
| Состояние есть в компоненте, механика — позже | TableRow поддерживает проп selected и показан в витрине; в Устройствах выделение не вводится — это новая функциональность, а не редизайн | ✓ |
| Ввести выделение в Устройствах | Сделать строку кликабельной с подсветкой выбранной | |
| Пилот выделения — Картриджи | Выделение уже работает в CartridgeListRow — перевести его на новый визуал | |

**Notes:** Разведка обнаружила, что в `DeviceList`/`DeviceListRow` выделения строк нет вообще — ни класса, ни `aria-selected`. Оно существует только в `CartridgeListRow` (master-detail). То есть требование CMP-06 «выбрана» не имело дома в Устройствах.

## Claude's Discretion

- Дробление фазы на планы и волны (таблица и dropdown между собой независимы).
- Точная форма API компонентов — пропы против snippets для ячеек, где живёт описание колонок.
- Устройство новых секций витрины — один файл на компонент против подсекций.
- Как `Table`/`TableRow` уживаются с разной разметкой: настоящий `<table>` в `DeviceList` против
  дивов с `role="row"` в `ActFormItemsTable`.
- Конкретная механика фокус-менеджмента при drill-in.

## Deferred Ideas

- Миграция остальных 5 таблиц на `Table`/`TableRow` — фазы 26–28.
- Миграция остальных 6 селекторов на `Dropdown` — фазы 26–28.
- Окно Устройств целиком по макету — фаза 26, WIN-02.
- Механика выделения строк в Устройствах (что делает выбор, массовые операции) — отдельное решение.
- Сортировка колонок и липкая шапка таблицы — ни в референсе, ни в требованиях v1.2.
