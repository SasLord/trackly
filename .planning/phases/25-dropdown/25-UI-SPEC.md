## Color

Фаза **не вводит новых цветов**, кроме одного отсутствующего токена.

| Роль | Токен | Light | Dark | Применение |
|------|-------|-------|------|------------|
| Dominant (60%) | `--tr-surface` | `#ffffff` | `#161b23` | Полотно таблицы, фон обычной строки (`transparent` поверх surface) |
| Secondary (30%) | `--tr-surface-raised` / `--tr-surface-sunken` / `--tr-group` | `#ffffff` / `#e4e8f0` / `#e9edf5` | `#1c222c` / `#0a0d12` / `#1a212b` | Панель dropdown (raised); строка поиска и шапка «Назад» (sunken); фон строки-группы (group) |
| Accent (10%) | `--tr-accent` + `--tr-accent-soft` + `--tr-accent-text` | `#2b5fd9` | `#5b8bff` | см. список ниже |
| Destructive | `--tr-danger-soft` / `--tr-danger-text` | `rgba(207,59,59,.12)` / `#b02f2f` | `rgba(242,101,101,.16)` / `#ff8080` | **Только** бейдж статуса тона danger («Списано», «Неисправно») |

### Accent зарезервирован ровно для:

1. Левый бордюр выбранной строки таблицы — `3px solid var(--tr-accent)`.
2. Фон выбранной строки таблицы и подсвеченной/выбранной опции — `var(--tr-row-selected)`.
3. Счётчик-пилюля группы — фон `--tr-accent-soft`, текст `--tr-accent-text`, бордюр `1px solid var(--tr-accent)`.
4. Счётчик `×N` в строке-группе dropdown — текст `--tr-accent-text`.
5. Бордюр поля dropdown в фокусе — `1px solid var(--tr-accent)` + `box-shadow 0 0 0 3px var(--tr-focus-ring)`.
6. Бейдж статуса тона accent («В работе») — `--tr-accent-soft` / `--tr-accent-text`.
7. Галочка `✓` выбранной опции плоского списка — `--tr-accent`.

Accent **не** применяется к: обычным строкам, hover-состоянию, шевронам, шапке таблицы, тексту опций.

## Component Contracts

### `TableRow` — состояния (CMP-06, SC #1)

| Проп | Тип | Контракт |
|------|-----|----------|
| `selected` | `boolean` | Фон `--tr-row-selected` + `border-left: 3px solid var(--tr-accent)`; при `indent` левый padding 32px → **29px** (компенсация ширины бордюра — строка не должна дёргаться) |
| `indent` | `boolean` | `padding-left: 32px` на первой ячейке — вложенная в группу строка |
| `last` | `boolean` | `border-bottom: none` (последняя строка не рисует разделитель) |

Hover — CSS-состояние `:hover`, не проп. Все три состояния (обычная / наведение / выбрана)
**обязаны быть показаны в витрине** — этим и закрывается CMP-06 (D-11).
Механика выбора строк в Устройствах в этой фазе **не вводится**.

### Строка-группа (CMP-06, SC #2)

| Элемент | Контракт |
|---------|----------|
| Фон / курсор | `var(--tr-group)`, `cursor: pointer` |
| Имя | `font-weight: 600`, ячейка `colspan` по левым колонкам |
| Шеврон | `▸` 18×18px, `--tr-text-secondary`, `margin-right: 4px`; свёрнута — `transform: none`, раскрыта — `transform: rotate(90deg)`; `transition: transform .15s` |
| Счётчик-пилюля | `<Badge variant="accent" appearance="count">{N} шт.</Badge>` — ячейка `text-align: center` |
| Пустые колонки | текст `--tr-text-tertiary` («Разные») |

**Переиспользование вместо дублирования:** пилюля и бейдж статуса **не верстаются заново** —
`Badge` Фазы 24 уже даёт нужную геометрию:
- статус: `appearance="soft" size="md"` → h=22px, radius 11px, 12px/600, тона neutral/accent/warning/danger — **совпадает с `TableRows.dc` побайтово**;
- счётчик: `variant="accent" appearance="count"` → h=20px, padding `0 9px`, 11px/600, `--tr-accent-soft`/`--tr-accent-text`/border `--tr-accent`.

**Единственное расхождение:** `Badge` даёт `border-radius: 11px`, `.dc` — `10px`. При h=20px оба
значения дают полную пилюлю (radius ≥ half-height). **Расхождение принимается, `Badge` не правится.**

### `Dropdown` — две формы (D-03, SC #3/#4)

| Форма | Поле | Поиск | Скролл | Живёт в |
|-------|------|-------|--------|---------|
| **Комбобокс** | `<input>` прямо в поле, placeholder `Устройство со склада` | ввод в самом поле, строки поиска в панели нет | max-height 280px | Пилот `ActFormItemsTable` |
| **Селект** | `<span>` с выбранным значением + `▼` | строка поиска **внутри панели**: h=30px, `--tr-surface-sunken`, radius 5px, иконка `⌕`, в обёртке `padding: 6px 12px` + `border-bottom` | max-height 240px | Витрина (боевые потребители — фазы 26–28) |

**Поле:** h=36px, padding `0 12px`, `--tr-surface`, radius 6px (`--tr-radius-sm`);
бордюр `--tr-border-strong` → `--tr-accent` в фокусе + `box-shadow: 0 0 0 3px var(--tr-focus-ring)`.

**Панель:** `margin-top: 4px`, `--tr-surface-raised`, `border: 1px solid var(--tr-border)`,
radius 8px (`--tr-radius-md`), `box-shadow: var(--tr-elev-2)`, `overflow: hidden`.

**Строка опции:** min-height 46px, padding `8px 12px`, `border-bottom: 1px solid var(--tr-border)`,
hover `--tr-row-hover`, selected `--tr-row-selected`. Двухстрочная:
- ряд 1 (baseline, gap 8px): имя 14px/600 (в плоском — /500) `--tr-text-primary` + `meta` 13px `--tr-text-tertiary`;
- ряд 2: `sub` 12px `--tr-text-tertiary` (в **плоском** списке — моноширинный);
- справа: счётчик `×N` (min-width 34px, right, 13px/600, `--tr-accent-text`, `tabular-nums`) + слот шеврона 12px с `›` только у групп.
- в **плоском** списке вместо счётчика — `✓` `--tr-accent` 14px/700 у выбранной опции.

Имя, `meta` и `sub` — `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`.

### Drill-in по группам (D-01, SC #4)

Модель — **drill-in, а не заголовки секций.** Клик по строке-группе **заменяет** содержимое панели
на экземпляры группы; сверху появляется шапка h=38px, `--tr-surface-sunken`,
`border-bottom: 1px solid var(--tr-border)`, 13px:
`←` + `Назад` (600, `--tr-text-primary`) + `· {название группы}` (`--tr-text-tertiary`, ellipsis).

> **Действие для планировщика/верификатора:** SC #4 в ROADMAP.md сформулирован как «список с группами
> (**заголовки секций**)». Это не соответствует ни референсу, ни коду. Формулировку SC #4 обновить на
> drill-in — иначе верификация упадёт на расхождении, хотя код прав. Тот же приём, что D-06 Фазы 24.

**Нюанс, отсутствующий в CONTEXT.md — обнаружен в коде (`ActFormItemsTable.svelte:568–588`):**
заголовок группы в member-view виден **всегда**, а кнопка «← Назад» — **только при ручном drill-in**
(`showBackByRow`). При авто-схлопывании единственной группы (AUTO-05) заголовок показывается **без**
кнопки возврата, потому что возвращаться некуда. Контракт компонента обязан сохранить это различие:
шапка и кнопка возврата — **два независимых условия**, а не одно.

### Поведенческий контракт Фазы 18 — сохраняется дословно (D-02, SC #5)

Оба правила — **часть компонента, не пропы-опции**:

1. **AUTO-02:** панель раскрывается при получении фокуса, без ввода (`onfocus` → `handleFocus`).
2. **AUTO-05:** если после фильтрации осталась единственная группа — она не показывается как группа,
   сразу плоский список её экземпляров.

**Позиционирование не переписывается.** Новый `Dropdown` **переиспользует** `use:portal`
(`ui/src/lib/utils/portal.ts`) и `use:dropdownAnchor` (`ui/src/lib/utils/dropdownAnchor.ts`) —
отлаженную Фазой 18 механику, на которой висят 7 селекторов и оба контекстных меню.
SC #5 проверяется в самом рискованном месте — пикер внутри модалки формы Акта.

**Ловушка:** дропдаун вынесен `use:portal` в `<body>`, поэтому scoped-стили Svelte до него не
доходят — стилизация идёт через глобальные классы с префиксом (`.dropdown--items`), и это
работающий приём, а не долг. Маркер `data-tr-portal` (паттерн Фазы 24) используется для
обнаружения вынесенных узлов при проверке.

## Keyboard & ARIA Contract (D-12)

**Нижняя граница — не потерять существующее. Проверено grep-ом, CONTEXT.md здесь неточен.**

> **Коррекция CONTEXT D-12.** CONTEXT утверждает, что `ActFormItemsTable` уже несёт `role="combobox"`.
> Grep по файлу показывает: `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`,
> `aria-haspopup` **отсутствуют во всём файле** (и во всех `lib/components/*.svelte`, кроме
> `aria-activedescendant` в `PersonAutocomplete.svelte:211`). Фактическая база — только `role="listbox"`,
> `role="option"`, `aria-autocomplete="list"`, `aria-selected`. Полный combobox-паттерн в этой фазе
> **добавляется**, а не «доводится». Это ровно тот класс ошибки, что описан в 24-LEARNINGS
> («Пометка [VERIFIED] не является проверкой») — планировщик не должен считать роль уже существующей.

### Обязательный минимум (регресс запрещён)

| Механика | Текущее поведение | Статус |
|----------|-------------------|--------|
| `role="listbox"` на панели, `role="option"` на строках | есть | сохранить |
| `aria-autocomplete="list"` на инпуте | есть | сохранить |
| `aria-selected` на активной опции | есть (по `activeIndexByRow`) | сохранить |
| `ArrowDown` при закрытой панели | открывает (через `handleFocus`) | сохранить |
| `ArrowDown`/`ArrowUp` в groups-режиме | циклическая навигация с оборачиванием | сохранить |
| `Enter` в groups-режиме | выбирает активную группу, `preventDefault` + `stopPropagation` | сохранить |
| **`Enter` в member-режиме** | **подавляется** (`preventDefault` + `stopPropagation`) | **критично:** иначе Enter всплывает к native submit формы Акта прямо во время выбора устройства (защита WR-02 Фазы 18) |
| `Tab` | коммитит активную группу и закрывает панель | сохранить |
| `Escape` | закрывает панель, `stopPropagation` (не закрывает модалку) | сохранить |

### Добавляется в этой фазе

| Механика | Требование |
|----------|------------|
| `role="combobox"` на инпуте | + `aria-expanded` (по факту открытия), `aria-controls` → id панели, `aria-haspopup="listbox"` |
| `aria-activedescendant` | id активной опции; каждая опция получает стабильный id |
| **Клавиатура в member-режиме** | Сейчас в drill-in навигация **только мышью** — `ArrowUp/Down/Enter` не выбирают. Довести до паритета с groups-режимом |
| `Home` / `End` | первая / последняя опция активного списка |
| `Escape` в member-режиме | первым нажатием — возврат к списку групп (`backToGroups`), вторым — закрытие панели |
| Фокус-менеджмент при drill-in | фокус остаётся на инпуте (combobox-паттерн), активный элемент переключается через `aria-activedescendant`; при входе в группу активной становится первая опция, при возврате — та группа, из которой вышли |
| Скролл к активной опции | `scrollIntoView({ block: 'nearest' })` при навигации клавиатурой |

   перед UAT через LAN-браузер нужен `pnpm --dir ui build` (`cargo tauri dev` хотрелоадит только
   desktop-webview).
