**TableRow.svelte props** (plain `Props` interface, `$props()` destructure with defaults — mirrors
`DeviceListRow.svelte`'s existing shape, no `$bindable` per D-11 — selection is one-way display state):

- `selected?: boolean` (default `false`) — background `var(--tr-row-selected)` + `border-left: 3px solid
  var(--tr-accent)`.
- `indent?: boolean` (default `false`) — `padding-left: 32px` on the row's first `<td>`; when combined with
  `selected`, compensated to `29px` (32 − 3px border).
- `last?: boolean` (default `false`) — removes `border-bottom` from every `<td>` in the row (literal last row
  of a table, not "last row in an expanded group" — DeviceGroupRow's existing stronger-divider behavior is a
  separate, pre-existing concern untouched by this prop, see Plan 25-05).
- `group?: boolean` (default `false`) — switches to group-row rendering mode (below).
- `groupExpanded?: boolean` (default `false`) — group-row-mode only: controls chevron rotation.
- `groupName?: string` — group-row-mode only: rendered inside the merged name cell.
- `groupColspan?: number` (default `1`) — group-row-mode only: `colspan` of the merged name cell.
- `onToggleGroup?: () => void` — group-row-mode only: fires on click of the row OR the chevron button.
- `class?: string` — appended to the rendered `<tr>`'s class list, so a consumer can layer supplementary
  local CSS (e.g. `DeviceGroupRow`'s pre-existing "strong divider on group-end" rule in Plan 25-05) without
  `TableRow` needing to know about every consumer's extra states.
- `children?: Snippet` — normal mode: the row's `<td>` cells, rendered verbatim. Group mode: the trailing
  `<td>` cells AFTER the merged name cell (e.g. location/condition/status/count-pill — the count-pill itself
  is `<Badge variant="accent" appearance="count">{N} шт.</Badge>`, supplied by the CALLER inside this
  snippet, never hand-rolled by `TableRow`, per PATTERNS.md "Переиспользование вместо дублирования").

Normal mode renders one `<tr class="tr-row" class:selected class:indent class:last>{@render children?.()}
</tr>`. Group mode renders `<tr class="tr-row tr-row-group" onclick={onToggleGroup}><td class="tr-row-group-
name" colspan={groupColspan}><button type="button" class="tr-row-chevron" class:expanded={groupExpanded}
aria-label={groupExpanded ? 'Свернуть группу' : 'Развернуть группу'} onclick={stop-propagation then call
onToggleGroup}>▸</button>{groupName}</td>{@render children?.()}</tr>`.

Because `TableRow` renders the `<tr>` itself, background/cursor/border-left CSS for `.tr-row`/`.tr-row-group`
targets its own scoped selectors directly (no `:global()` needed). Because the `<td>` children come from the
CALLER's snippet (different Svelte scope-hash), EVERY rule that styles those `<td>`s MUST use the
`:global()`-inside-own-`<style>`-block escape hatch (documented working pattern, PATTERNS.md "Shared
Patterns" + 24-LEARNINGS "Пометка [VERIFIED] не является проверкой" — this is the SAME mechanism
`ActFormItemsTable.svelte` already uses for its portaled dropdown, just applied to a direct-child combinator
instead of a portaled subtree).

**`TableRow` owns the base `<td>` values (D-10 — `TableRows.dc`'s `tdBase` is the source of truth).** This is
explicit because the pre-Phase-25 consumer files carry DIFFERENT, older values (`DeviceListRow.svelte:87`
uses `padding: 0 var(--tr-space-xs)` = 8px, and its `.device-row` carries `height: var(--row-height, 40px)`)
— those are superseded here, NOT carried forward (PATTERNS.md: "this file's `--tr-surface` hover and
`--tr-space-xs` (8px) padding are the **old** pre-Phase-25 values and must NOT be copied verbatim"). The rule
set, in cascade order:

| Selector | Declarations |
|----------|--------------|
| `.tr-row :global(> td)` (BASE) | `height: 40px; padding: 0 10px; border-bottom: 1px solid var(--tr-border); vertical-align: middle;` |
| `.tr-row.indent :global(> td:first-child)` | `padding-left: 32px;` |
| `.tr-row.indent.selected :global(> td:first-child)` | `padding-left: 29px;` (32 − 3px border — keeps text from shifting when a row becomes selected) |
| `.tr-row.last :global(> td)` | `border-bottom: none;` |

`padding: 0 10px` and `height: 40px` are UI-SPEC's declared spacing exceptions (hard pixel values from the
reference, deliberately NOT tokenized — see UI-SPEC "Исключения" table). Do not substitute `--tr-space-xs`
(8px) or `--tr-space-sm` (12px) for the 10px — that substitution is exactly the silent-drift failure this
table exists to prevent.

Chevron: `▸` glyph, 18×18px, `color: var(--tr-text-secondary)`, `margin-right: var(--tr-space-2xs)`,
`transform: none` collapsed / `transform: rotate(90deg)` expanded (NOT 180deg — see Plan 25-05's note on the
pre-existing `DeviceGroupRow.svelte` deviation this fixes), `transition: transform .15s` (this ONE transition
stays at `.15s`, not the usual `.12s` micro-transition — UI-SPEC states this value is taken verbatim from
`TableRows.dc` and must not be normalized).

**Table.svelte props**:

- `columns: number` — total `<th>`/`<td>` count; drives skeleton cell count and empty-state `colspan`.
- `loading?: boolean` (default `false`).
- `empty?: boolean` (default `false`).
- `emptyTitle?: string`, `emptyBody?: string` — only rendered when `empty` is true.
- `skeletonRows?: number` (default `5`).
- `head: Snippet` — renders the `<th>` cells of the header row (Table.svelte wraps them in `<thead><tr
  class="tr-thead-row">`).
- `children?: Snippet` — renders `<TableRow>`-based `<tbody>` rows; only rendered when `!loading && !empty`.

Table.svelte owns: `<div class="tr-table-wrapper"><table class="tr-table"><thead>...</thead>{loading ?
skeleton : empty ? empty-row : <tbody>{@render children?.()}</tbody>}</table></div>`. Header row: height
34px, `border-bottom: 2px solid var(--tr-border-strong)`, background `var(--tr-bg)` (mirrors
`DeviceList.svelte`'s existing `.header-row`/`.th` values — these were already token-correct pre-Phase-25,
carry them over unchanged). `<th>` cells rendered by the `head` snippet get their padding/font/color from
Table.svelte's own style via `:global(> th)` under `.tr-thead-row` (same escape-hatch reasoning as TableRow):
padding `0 10px` (UI-SPEC spacing exception, not a token), `font-size: var(--tr-font-size-caption)`,
`font-weight: var(--tr-font-weight-semibold)`, `color: var(--tr-text-secondary)`, `white-space: nowrap`.
`<td>` height 40px, padding `0 10px`, `border-bottom: 1px solid var(--tr-border)` are owned by
**`TableRow.svelte`** (see its base-`<td>` rule table above), NOT by `Table.svelte` and NOT by consumers —
`Table.svelte` owns only the shell/header/skeleton/empty parts. The one exception: `Table.svelte`'s OWN
skeleton and empty-state `<td>`s are rendered by `Table.svelte` itself (not by a `TableRow`), so it styles
those two locally with the same `height: 40px; padding: 0 10px;` base so the skeleton does not jump size
when real rows replace it. Skeleton block styling (pulse animation, `--tr-surface-sunken` background,
`--tr-radius-xs`) mirrors `DeviceList.svelte`'s current `.skeleton-block`/`@keyframes pulse` verbatim — carry
those rules into `Table.svelte`, they were already token-correct.
