<objective>
Rewire the act-rendering service layer from the krilla/DocSpec pipeline to the
new HTML-template path: `ActService::render_pdf` and
`ActService::render_acceptance_pdf` change return type `Vec<u8>` -> `String`,
read template source via `html_templates::load_template` (Plan 16-01's module)
instead of `pipeline.templates.get_active`, render through
`build_safe_html_env` + the existing `render_with_timeout` helper (unchanged),
and build the logo as a base64 `data:` URI from trusted `org_settings` BLOB
bytes instead of injecting `logo_bytes` into a parsed `DocSpec`. Wire
`html_templates::materialize_defaults_on_startup` into `AppCtx::build` startup,
alongside (not replacing) the existing DB-template seed call.

Purpose: This is the single choke point where the "Vec<u8> -> String" change
originates — Plan 16-03 (Tauri/HTTP adapters) and Plan 16-05 (tests) both
consume this plan's new return type; per CLAUDE.md's dual-transport
architectural note, the type change must happen ONCE here, not duplicated in
each adapter.

Decisions implemented here: D-04 (ctx object reused, only the logo key
changes), D-09 (the render path now produces the single artifact — an HTML
string — that both desktop and LAN delivery consume identically in later
plans), D-10 (return type changes from `Vec<u8>` to `String` at the exact
service-method boundary named in D-10), D-11 (logo becomes a base64 `data:`
URI built in Rust from trusted `org_settings`/file bytes — never a filesystem
path or user-supplied value), D-05 (startup materialization wired into
`AppCtx::build`).

Output: `render_pdf`/`render_acceptance_pdf` return HTML strings; krilla/DocSpec
is no longer reachable from either function; templates/ directory is
materialized on first run.
</objective>

pub async fn render_pdf(&self, act_id: i64) -> Result<Vec<u8>, AppError> {
    let pipeline = self.pdf_pipeline()?;
    let act = self.get(act_id).await?;
    let org_legacy = pipeline.organization.read().await?;
    let safe_logo = pipeline.organization.safe_logo_canonical(&org_legacy).await?;
    let (org_dto, logo_bytes, logo_mime) = match pipeline.org_db {
        Some(org_db) => { let (dto, logo_bytes, logo_mime) = org_db.get_for_pdf().await?; (dto, logo_bytes, logo_mime) }
        None => ( /* empty OrgSettingsDto fallback */ None, None ),
    };
    let template_src = pipeline.templates.get_active("act_handover").await?;
    // ... parent_block, suffix, items_json ...
    let ctx = serde_json::json!({ "org": {...}, "act": {...}, "return": {...} });
    let rendered = crate::pdf::minijinja_env::render_with_timeout(&pipeline.pdf.minijinja_env, "act_handover", &template_src, ctx).await?;
    let mut spec: crate::pdf::docspec::DocSpec = serde_json::from_str(&rendered)...?;
    if let Some(bytes) = logo_bytes { spec.header.logo_bytes = Some(bytes); spec.header.logo_mime = logo_mime; }
    pipeline.pdf.render_docspec(&spec)
}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| org_settings BLOB (logo_blob) -> data: URI | Trusted DB bytes (written only via authenticated Settings UI / OrgDbService::save_logo), never user-request-controlled at render time |
| act/device DB rows -> ctx JSON -> HTML template | Free-text fields (specs, kit, condition, names) flow into the same ctx object as before — now rendered through an autoescape-ON environment (Plan 16-01) instead of JSON |
| templates/*.html file content -> render_with_timeout | File is either the materialized embedded default or a user hand-edit; both trusted equally (local file, not network-supplied) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-05 | Tampering | logo `data:` URI construction in render_pdf/render_acceptance_pdf | mitigate | `logo_bytes`/`logo_blob` bytes originate exclusively from `OrgDbService::get_for_pdf` (org_settings table, written only through `OrgDbService::save_logo` behind `ManageSettings` authorization) or from `OrganizationService::read_logo_bytes` (canonicalized local file path, `safe_logo_canonical` already guards path traversal) — no request-supplied bytes ever reach `base64::encode` in this plan's code |
| T-16-06 | Information Disclosure | Accidental leakage of full org_db/device internals into ctx JSON | accept | `ctx` construction is unchanged from the existing (already-reviewed) `serde_json::json!({...})` shape in Plan 3/14/15 — this plan only renames the `logo_path` key to `logo_data_uri` and swaps the render target; no new fields are added |
| T-16-07 | Denial of Service | `read_logo_bytes` reading arbitrarily large logo files into memory for base64 encoding | accept | Logo uploads are already size-gated at `OrgDbService::save_logo` (pre-existing Phase 7 control, unchanged by this plan); acceptance-path logo files come from `organization_service`'s existing canonicalized-path read, same trust level as the pre-Phase-16 krilla path which also read the full file into memory |

</threat_model>
