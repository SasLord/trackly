<objective>
Update the frontend to consume the new HTML-string contract: `acts.ts`'s
`renderPdf`/`renderAcceptancePdf` change from `Promise<number[]>` to
`Promise<string>`; `pdf.ts`'s now-orphaned blob-conversion helpers are removed;
`PdfPreviewModal.svelte` switches from `blob:`-URL `<iframe src>` to `srcdoc`
with the HTML string directly, removes the "open in system viewer" button
(tied to the now-deleted `acts_open_pdf_in_system`), and resolves the
"Сохранить как PDF" action so it never attempts to binary-write a `string` as
`Uint8Array` (which would silently corrupt output).

Purpose: Completes the D-09 UX target (iframe + browser print, same code path
in both desktop and LAN-browser webviews) and prevents the "do NOT silently
keep the old binary-write code" data-corruption trap flagged in PATTERNS.md.
Output: Working HTML print-preview flow wired end-to-end from Rust `String`
return through to `window.print()`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Rust-returned HTML string -> iframe srcdoc | Server-controlled HTML (autoescaped per Plan 16-01/16-02), rendered inside the app's own webview iframe — same origin as the parent app |
| Removed: blob: URL object lifecycle | Eliminated entirely; no longer a surface to reason about (revoke-timing bugs, leaked object URLs) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-11 | Tampering (stored XSS via srcdoc) | `<iframe srcdoc={htmlContent}>` | mitigate (upstream) | The HTML string is produced by `build_safe_html_env` (Plan 16-01/16-02) with `AutoEscape::Html` — all interpolated device/org/act fields are HTML-escaped before this string ever reaches the frontend; the iframe itself receives already-safe markup, no additional client-side sanitization is introduced or needed here |
| T-16-12 | Information Disclosure | Deleted object-URL / blob lifecycle | accept (surface removed) | No blob URLs are created anymore, eliminating any risk of a leaked/lingering `blob:` URL being reachable after the modal closes |

</threat_model>
