<objective>
Create the HTML-template contracts this phase depends on: the two self-contained
HTML templates (act_handover.html, act_acceptance.html) that reproduce the
Word-sample layout already fixed in Phase 15, a new `html_templates.rs` module
that resolves the `templates/` directory (portable + env-override per D-07),
materializes embedded defaults on first run (D-05), and reads-on-render with
graceful fallback to the embedded default (D-06/D-08); and an HTML-safe MiniJinja
environment (autoescape ON) that preserves every other safe-mode invariant.

Purpose: This is the "define contracts" wave — Plan 16-02 (act_service.rs wiring)
consumes `html_templates::{resolve_templates_dir, materialize_defaults_on_startup,
load_template}` and `minijinja_env::build_safe_html_env` directly, without having
to design them mid-wiring.

Decisions implemented here: D-01 (MiniJinja reused as the HTML engine, zero new
template-engine dependency), D-02 (runtime engine chosen over compile-time
askama/maud specifically so Req 4's "edit without rebuild" holds), D-03
(templates are plain author-editable HTML+inline-`<style>` files using the same
`{{ }}`/`{% %}` syntax as the existing `.minijinja` files — no `wrap_text_to_width`
needed, the browser handles wrapping via CSS), D-04 (the `ctx` object is reused
unchanged from `act_service::render_pdf` except the new `logo_data_uri` key),
D-05/D-06/D-07/D-08 (materialize-on-startup, fallback-on-missing, env-override
resolver, read-on-render — see must_haves), D-12 (print CSS `@page` A4 portrait +
`page-break-inside: avoid` on device blocks, authored directly into both new
`.html` files in Task 3).

Output: Two new HTML template files, a new `pdf/html_templates.rs` module, a new
`build_safe_html_env` constructor, and a `Paths::templates_dir()` accessor.

pub fn build_safe_env() -> Environment<'static> {

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| templates/*.html on disk -> HTML render | User-editable file content becomes the template source for MiniJinja |
| act/device/org data -> `{{ var }}` interpolation | Untrusted DB content (device names, free-text specs, org fields) interpolated into HTML output |
| TRACKLY_TEMPLATES_DIR env var -> filesystem read | Dev/test path override could theoretically point elsewhere |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-01 | Tampering / Injection | act_handover.html, act_acceptance.html interpolation of device/org fields | mitigate | `build_safe_html_env` sets `AutoEscape::Html` unconditionally — MiniJinja HTML-escapes all `{{ var }}` output by default; no `| safe` filter is used anywhere in the new templates (verified via acceptance grep in Task 3) |
| T-16-02 | Tampering | `{% include %}`/`{% extends %}` reaching arbitrary filesystem paths | accept (already mitigated structurally) | `build_safe_html_env` never calls `env.set_loader` (same invariant as `build_safe_env`) — MiniJinja has no loader configured, so `{% include %}` cannot resolve any path regardless of template content |
| T-16-03 | Denial of Service | Template render (fuel/recursion/timeout) | accept (already mitigated) | `build_safe_html_env` keeps `set_fuel(Some(100_000))`, `set_recursion_limit(64)`; `render_with_timeout` (unchanged, reused as-is) wraps every render in a 5s wall-clock timeout |
| T-16-04 | Information Disclosure / Path Traversal | `TRACKLY_TEMPLATES_DIR` env override or resolved templates dir | accept | This env var is developer/test-only (mirrors `TRACKLY_AD_MOCK`/`TRACKLY_SNMP_MOCK` precedent), not exposed to end users or over the network; production path is always `exe_dir.join("templates")` computed by `Paths`, never user/network-supplied. `load_template` only ever joins a fixed filename (`act_handover.html`/`act_acceptance.html`) onto the resolved dir — no user-controlled filename component exists in this plan's code, closing path-traversal via filename injection structurally |

</threat_model>
