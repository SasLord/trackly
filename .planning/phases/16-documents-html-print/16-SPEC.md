# Phase 16: Документы через HTML-печать — Specification

**Created:** 2026-07-05
**Ambiguity score:** 0.17 (gate: ≤ 0.20)
**Requirements:** 8 locked

## Goal

Генерация обоих актов (приёма-передачи и приёмки устройства) переходит с активного krilla/DocSpec-пайплайна на HTML-шаблоны: шаблоны лежат в папке `templates/` рядом с исполняемым файлом (редактируются как файлы) с вшитым в бинарь дефолтом-fallback, рендерятся в self-contained HTML по образцу Word и печатаются/сохраняются в PDF через диалог браузера в обоих режимах (desktop + LAN).

## Background

Текущий пайплайн генерации документов (Phase 3 → 15): MiniJinja-шаблон, хранимый в БД-таблице `document_templates`, → `render_with_timeout` → JSON → `serde` в `DocSpec` → `krilla` → PDF-байты.

- `crates/trackly-app/src/pdf/renderer.rs` = 1908 строк ручной вёрстки под krilla (word-wrap `wrap_text_to_width`, per-device `DeviceCard`, page-break из Phase 15).
- Два документа: `templates/act_handover.minijinja` (акт приёма-передачи, образец Word) и `templates/act_acceptance.minijinja` (приёмка устройства).
- Контекст акта (Phase 14): N позиций устройства с полными атрибутами, расширенные реквизиты организации (`org_settings`: телефон/факс/email/ОКПО/ОГРН), «Срок до», двухстрочные подписи «Выдал/Получил» — уже собирается в `context.rs`.
- Доставка: Tauri-команды `acts_render_pdf` / `devices_render_acceptance_pdf` (возвращают `Vec<u8>`) + axum HTTP-эндпоинты (`application/pdf`) + `acts_open_pdf_in_system`; фронт — `PdfPreviewModal.svelte`, `DocumentAcceptanceModal.svelte`.
- Тесты krilla-пайплайна: `pdf_determinism`, `pdf_render_act`, `pdf_column_overflow`, `pdf_text_extract`, `pdf_logo`, `templates_seed`, `template_edit`.

Причина пивота (см. `.planning`-память `pdf_pivot_to_html_print`): ручная вёрстка krilla дорога в поддержке и хрупка по фиделити; HTML + печать браузером даёт word-wrap, кириллицу и вёрстку «из коробки» и одинаково работает в Tauri-webview и в LAN-браузере. Визуальный результат Phase 15 (соответствие образцу Word) должен быть воспроизведён в HTML.

## Requirements

1. **HTML-акт приёма-передачи**: `act_handover` рендерится в self-contained HTML по образцу Word.
   - Current: `act_handover` рендерится через MiniJinja→DocSpec→krilla→PDF (`renderer.rs`)
   - Target: `act_handover` рендерится в самодостаточный HTML-документ, воспроизводящий образец Word — шапка (логотип + расширенные реквизиты), заголовок «Акт приема-передачи», номер/дата, вводная формулировка с ФИО получателя, блок устройства(-в), «Сроком до», подписи «Выдал/Получил»
   - Acceptance: сгенерированный HTML содержит все блоки образца в правильном порядке; печать в PDF через браузер визуально соответствует образцу Word

2. **HTML-акт приёмки устройства**: `act_acceptance` рендерится в HTML.
   - Current: `act_acceptance` рендерится через MiniJinja→DocSpec→krilla
   - Target: путь `devices_render_acceptance_*` выдаёт HTML-документ соответствующей вёрстки вместо PDF-байтов krilla
   - Acceptance: генерация акта приёмки возвращает HTML-документ, который печатается в PDF через браузер без ошибок и содержит обязательные поля приёмки

3. **Мультиустройство без обрезки**: N позиций устройства печатаются полностью.
   - Current: мультиустройство обслуживает krilla-`DeviceCard` + `wrap_text_to_width` + атомарный page-break (Phase 15, WR-05)
   - Target: HTML-шаблон печатает все N позиций; длинные значения «Комплектация» и «Технические характеристики» переносятся (word-wrap) без обрезки и наложения; A4-разрывы страниц не рвут позицию некорректно
   - Acceptance: акт с 2+ устройствами и длинными полями печатается со всеми позициями, без обрезки текста и без наложения, страницы A4 разбиваются корректно

4. **Шаблоны в папке `templates/` + вшитый fallback**: portable-хранение шаблонов файлами.
   - Current: шаблоны сидируются в БД-таблицу `document_templates` через `template_service`, редактируются через textarea
   - Target: HTML-шаблоны обоих актов читаются из папки `templates/` рядом с исполняемым файлом (путь резолвится от `std::env::current_exe()?.parent()?`); при отсутствии папки/файла используется дефолтный шаблон, вшитый в бинарь (`include_str!`); правка файла шаблона любым текстовым редактором применяется к следующей генерации без пересборки
   - Acceptance: (a) при наличии `templates/act_handover.html` рядом с exe генерация использует его; (b) при отсутствии папки генерация использует вшитый дефолт и не падает; (c) изменение содержимого файла шаблона меняет вывод без пересборки

5. **Печать/сохранение в PDF через браузер в обоих режимах**: единый HTML-путь доставки.
   - Current: PDF-байты возвращаются Tauri-командой / HTTP-эндпоинтом и открываются системным просмотрщиком (`acts_open_pdf_in_system`) или в preview-модалке
   - Target: пользователь открывает HTML-версию акта и печатает/сохраняет в PDF через нативный диалог печати браузера; путь одинаково работает в Tauri-webview (desktop) и в LAN-браузере (server mode)
   - Acceptance: в desktop-режиме и в LAN-браузере акт открывается как HTML и вызывается печать; итоговый PDF из диалога печати содержит акт по образцу

6. **Self-contained / offline-safe**: без внешних интернет/CDN-зависимостей.
   - Current: krilla встраивает шрифты в PDF; логотип берётся из БД-BLOB
   - Target: HTML-документ не зависит от внешнего интернета/CDN — кириллица рендерится системными шрифтами (без embed), логотип встроен (data-URI) или отдаётся локальным сервером Trackly; печать работает офлайн
   - Acceptance: при отсутствии интернета печать акта в LAN-браузере показывает логотип и корректную кириллицу; в разметке нет ссылок на внешние CDN/домены

7. **Чистый print-вывод (print CSS, без браузерных колонтитулов)**: A4 + `@page`.
   - Current: n/a — krilla полностью контролировал страницу
   - Target: шаблон задаёт print CSS (`@page` A4-книжная + поля), совпадающие с образцом; вёрстка не полагается на браузерные header/footer
   - Acceptance: при отключённых колонтитулах в диалоге печати итоговый PDF не содержит браузерных URL/даты/номера страницы; формат — A4-книжная с корректными полями

8. **Тесты HTML-генерации**: regression + новые проверки.
   - Current: тесты `pdf_render_act`/`pdf_column_overflow`/`pdf_text_extract`/`templates_seed` покрывают krilla-пайплайн
   - Target: добавлены тесты HTML-генерации обоих актов (наличие обязательных блоков/полей и логотипа в HTML; 1 vs N устройств; чтение шаблона из папки vs вшитый fallback); замороженные krilla-тесты не ломают сборку (оставлены зелёными или помечены `#[ignore]`)
   - Acceptance: `cargo test` зелёный; есть автоматический тест, проверяющий, что HTML обоих актов содержит обязательные блоки при 1 и N устройствах и что fallback-шаблон используется при отсутствии папки

## Boundaries

**In scope:**
- HTML-генерация обоих актов (`act_handover` + `act_acceptance`) по образцу Word
- Мультиустройство (N позиций) с word-wrap и корректными page-break
- Хранение шаблонов в папке `templates/` рядом с exe + вшитый дефолт-fallback; редактирование файлами
- Печать/сохранение в PDF через диалог браузера в обоих режимах (desktop Tauri-webview + LAN-браузер)
- Self-contained HTML (системные шрифты, локальный логотип, без внешних CDN)
- Print CSS (A4-книжная, поля, разрывы страниц)
- Тесты HTML-генерации обоих актов + fallback-шаблона

**Out of scope:**
- Удаление krilla/DocSpec/`renderer.rs`/MiniJinja-шаблонов — остаются в репо **заморожёнными**, активной генерацией не вызываются, fallback на них не делается — возможен возврат позже
- Серверный headless-PDF (генерация канонического PDF-файла на бэкенде) — печать только через браузер
- UI-редактор шаблонов сверх правки файлов (DOC-01) — отдельная будущая работа
- Миграция старых MiniJinja→DocSpec шаблонов из `document_templates` — считаем БД свежей, миграция не нужна
- Любые документы кроме двух актов (отчёты, этикетки и т.п.)
- Embedding шрифтов в документ — достаточно системных (целевые Windows-машины имеют кириллические шрифты)

## Constraints

- **Portable:** путь к шаблонам резолвится от `std::env::current_exe()?.parent()?/templates/`; дефолт вшит через `include_str!`; не писать в `%APPDATA%`/системные пути
- **Офлайн/без CDN:** в HTML нет ссылок на внешний интернет/CDN — ни для шрифтов, ни для логотипа, ни для CSS (portable + LAN-офлайн)
- **Кириллица:** системные шрифты (без embed) — целевая среда Windows с кириллическими шрифтами
- **Формат:** A4-книжная, print CSS `@page`
- **Визуальная цель:** тот же образец Word, что зафиксирован в Phase 15 (не новый дизайн)
- **krilla-путь** остаётся в коде, но активной генерацией документов не используется

## Acceptance Criteria

- [ ] Акт приёма-передачи генерируется как self-contained HTML и печатается в PDF через браузер, визуально по образцу Word (все блоки в правильном порядке)
- [ ] Акт приёмки устройства генерируется как HTML и печатается в PDF через браузер
- [ ] Акт с 2+ устройствами печатает все позиции; длинные «Комплектация»/«Технические характеристики» переносятся без обрезки и наложения; разрывы страниц A4 корректны
- [ ] HTML-шаблоны читаются из папки `templates/` рядом с exe; правка файла меняет вывод без пересборки
- [ ] При отсутствии папки `templates/` используется вшитый дефолт и генерация не падает
- [ ] Печать работает и в Tauri-десктопе, и в LAN-браузере
- [ ] Кириллица рендерится корректно системными шрифтами (без квадратов/пропусков символов)
- [ ] Логотип отображается при печати офлайн (локальный источник, без внешних CDN)
- [ ] При отключённых колонтитулах в диалоге печати итоговый PDF не содержит браузерных URL/даты/номера страницы (print CSS `@page` A4)
- [ ] `cargo test` зелёный; добавлены тесты HTML-генерации обоих актов (1 vs N устройств) и fallback-шаблона
