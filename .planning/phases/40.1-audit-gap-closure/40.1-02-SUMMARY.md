## Gap closure (WR-02, post-verification)

Найдено code review (`40.1-REVIEW.md`, WR-02) и подтверждено `/gsd-verify-phase`-прогоном 40.1
(`40.1-VERIFICATION.md`, отмечено как известный незакрытый риск, не блокирующий статус фазы, но
рекомендованный к закрытию вместе с WR-01): `build_movements_filter_summary` резолвил
`from_place_id`/`to_place_id` через `ctx.places.full_path(caller, id).await?`, пробрасывая
`AppError::NotFound` наружу через `?`, если место, на которое указывает активный фильтр
«Перемещений», было удалено между выбором фильтра и печатью — в отличие от соседнего резолва
`device_type_name` в той же функции, который уже явно деградирует (`Option<String>`, `None` при
отсутствии), а не роняет весь экспорт. Сценарий: менеджер открывает отчёт «Перемещения», задаёт
фильтр «Откуда», другой пользователь удаляет это место (легально — BLOCKER-1's предполётная
проверка блокирует только удаление мест с собственной записью в `place_movements`, не мест,
лишь упомянутых в чьём-то открытом фильтре отчёта) — кнопка «Печать» падает сырым `NotFound`
вместо рендера отчёта.

**Фикс:** новый хелпер `place_full_path_or_none(ctx, caller, place_id)` — то же поведение, что у
`device_type_name`: `Ok(Some(path))` при успехе, `Ok(None)` при `AppError::NotFound` (место
удалено — сегмент сводки просто опускается), любая другая ошибка (авторизация, I/O)
по-прежнему пробрасывается через `?`. `build_movements_filter_summary` использует этот хелпер
вместо прямого `?` для обоих направлений (Откуда/Куда).

**Новый Rust-тест:** `report_movements_export_pdf_omits_deleted_place_from_filter_summary_instead_of_failing`
(`crates/trackly-app/tests/report_movements.rs`) — хард-удаляет строку места напрямую (в обход
`PlaceService::delete_hard`'s предполётных проверок, симулируя место без собственных записей
`place_movements`, легальное к удалению по BLOCKER-1), задаёт его как `from_place_id` фильтра
вместе с валидным `to_place_id`, и утверждает, что экспорт PDF завершается успешно
(`Result::Ok`), сегмент «Откуда:» отсутствует в HTML целиком, а «Куда: …» рендерится как обычно.
Мутационный самотест (временный `git stash` фикса, ре-прогон теста, `git stash pop`) подтвердил:
без фикса тест падает именно с `NotFound { entity: "place", id: … }`, с фиксом — зелёный вместе
с остальными 15 тестами файла.
