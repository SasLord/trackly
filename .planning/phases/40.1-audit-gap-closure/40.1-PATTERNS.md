```rust
/// Subtree counts under a root place, inclusive of the root itself (Pattern 2 —
/// reused by D-14 delete-block, D-21 consequences preview, D-25 tree counters, PLC-06).
```

#### `crates/trackly-app/src/services/place_service.rs` — `build_delete_blocked_message` / `ru_plural`

**Аналог:** ветка `referencing_act_count` в этой же функции (строки 877-929).

```rust
/// Russian noun pluralization by count: `one` (1, 21, 31, …), `few` (2-4, 22-24, …),
/// `many` (0, 5-20, 25-30, …). The 11-14 exception (which would otherwise match
/// `few` via `n % 10 == 1..4`) always resolves to `many`.
fn ru_plural(n: i64, one: &'static str, few: &'static str, many: &'static str) -> &'static str {
    let n_abs = n.unsigned_abs();
    let mod100 = n_abs % 100;
    let mod10 = n_abs % 10;
    if (11..=14).contains(&mod100) {
        many
    } else {
        match mod10 {
            1 => one,
            2..=4 => few,
            _ => many,
        }
    }
}
```

```rust
fn build_delete_blocked_message(stats: &SubtreeStats) -> String {

            "{} {}",
            stats.referencing_act_count,

    format!(
        "Место нельзя удалить: в нём {}. Перенесите содержимое или архивируйте место.",
```

#### `crates/trackly-infra/src/repos/places_sqlite.rs` — `subtree_stats_impl` (SQL)

**Аналог:** CTE-подзапрос `referencing_act_count` в этой же функции (строки 150-193).

```rust
/// Pattern 2 (39-RESEARCH.md): subtree counts under `root_id`, inclusive of the
/// root itself. Shared verbatim by `subtree_stats` (D-25 tree counters / D-21
/// consequences preview) and `delete_hard`'s pre-flight conflict check (D-14) —
/// one source of truth, not two.
fn subtree_stats_impl(conn: &Connection, root_id: i64) -> Result<SubtreeStats, AppError> {
    conn.query_row(
        "WITH RECURSIVE subtree(id) AS (
            SELECT id FROM places WHERE id = ?1 AND deleted_at_utc IS NULL
            UNION ALL
            SELECT p.id FROM places p
            JOIN subtree s ON p.parent_id = s.id
            WHERE p.deleted_at_utc IS NULL
         )
         SELECT
           (SELECT COUNT(*) FROM places WHERE parent_id = ?1 AND deleted_at_utc IS NULL) AS direct_children,
           (SELECT COUNT(*) FROM places WHERE id IN (SELECT id FROM subtree) AND id != ?1 AND deleted_at_utc IS NULL) AS nested_places,
           (SELECT COUNT(*) FROM devices WHERE place_id IN (SELECT id FROM subtree) AND deleted_at_utc IS NULL) AS device_count,
           (SELECT COUNT(*) FROM cartridges WHERE place_id IN (SELECT id FROM subtree) AND deleted_at_utc IS NULL) AS cartridge_count,
           -- CR-01 (phase 39 review): acts referencing this subtree through ANY of
           -- the three D-16 frozen-snapshot columns ...
           (SELECT COUNT(DISTINCT a.id) FROM acts a
              LEFT JOIN act_items ai ON ai.act_id = a.id
            WHERE (a.place_id IN (SELECT id FROM subtree)
                OR a.bulk_place_id IN (SELECT id FROM subtree)
                OR ai.place_id_override IN (SELECT id FROM subtree))
              AND a.deleted_at_utc IS NULL) AS referencing_act_count",
        rusqlite::params![root_id],
        |row| {
            Ok(SubtreeStats {
                direct_children: row.get(0)?,
                nested_places: row.get(1)?,
                device_count: row.get(2)?,
                cartridge_count: row.get(3)?,
                referencing_act_count: row.get(4)?,
            })
        },
    )
    .map_err(map_rusqlite)
}
```

**Что повторить:** добавить ШЕСТОЙ `SELECT COUNT(...)` в тот же список подзапросов —
`from_place_id` и `to_place_id` через оба направления (D-06), БЕЗ двойного учёта строки,
у которой обе стороны лежат внутри поддерева (D-01). Форма (`EXISTS`/`JOIN`/`UNION`) —
на усмотрение исполнителя; естественный шаблон по аналогии с acts-подзапросом —
`SELECT COUNT(*) FROM place_movements WHERE from_place_id IN (SELECT id FROM subtree)
OR to_place_id IN (SELECT id FROM subtree)` (без `DISTINCT a.id`, т.к. в D-01 явно сказано
«число строк», а не число уникальных сущностей — комментарий должен явно фиксировать этот
выбор, как это сделано для acts). Добавить комментарий той же формы («почему», ссылка на
V040, `ON DELETE RESTRICT`). Добавить поле в `Ok(SubtreeStats { ... })` маппинг (следующий
индекс `row.get(5)?`).

```rust
fn delete_hard(&self, conn: &mut Self::Conn, id: i64, version: i64) -> Result<(), AppError> {
    let tx = conn.transaction().map_err(map_rusqlite)?;

    // D-14 (литерал, не обсуждается): без каскада, без авто-репарентинга.
    // Pattern 2 subtree-stats запускается первым; любой ненулевой счётчик
    // блокирует удаление с точными числами (не общим отказом). `ON DELETE
    // RESTRICT` FK (Plan 01) — защита в глубину позади этой проверки (T-39-04-02).
    let stats = subtree_stats_impl(&tx, id)?;

    // прибавлять к нему `direct_children` — значит посчитать их дважды.

    // место с нулевыми остальными счётчиками всё ещё может быть undeletable.

        + stats.device_count
        + stats.cartridge_count
        + stats.referencing_act_count;

        return Err(AppError::Conflict {
            reason: format!(
                "Нельзя удалить место: содержит {} вложенных мест, {} устройств, {} картриджей, {} актов.",
                stats.nested_places, stats.device_count, stats.cartridge_count, stats.referencing_act_count,
            ),
        });
    }
    // ...
}
```

## Shared Patterns

### Русское числительное по счётчику (`ru_plural`)
**Источник:** `crates/trackly-app/src/services/place_service.rs:854-867`
**Применить к:** новой ветке `referencing_movement_count` в `build_delete_blocked_message`
(BLOCKER-1).
```rust
fn ru_plural(n: i64, one: &'static str, few: &'static str, many: &'static str) -> &'static str {
    let n_abs = n.unsigned_abs();
    let mod100 = n_abs % 100;
    let mod10 = n_abs % 10;
    if (11..=14).contains(&mod100) { many } else {
        match mod10 { 1 => one, 2..=4 => few, _ => many }
    }
}
```

### Кастомный `Dropdown` вместо `<select>`/`Select` для справочников «id/name»
**Источник:** `ui/src/features/reports/ReportFilters.svelte:156-181` (внутри файла) и
`ui/src/features/cartridges/CartridgeFilters.svelte:100-126` (тот же класс фильтра «тип»).
**Применить к:** новому фильтру типа устройства в `ReportFilters.svelte`, ветка
`movements` (BLOCKER-2). Форма пропов `Dropdown` (`variant="select"`, `flat={true}`,
`getGroupId`/`getGroupName`/`isGroupSelected`/`onPickGroup`, плоские группы без drill-in,
`noExpand`-заглушка) — повторяется буквально во всех трёх местах, копировать 1:1.

### Комментарий объясняет ПОЧЕМУ, не только ЧТО
Сквозная конвенция репозитория (видна во всех прочитанных файлах: `SubtreeStats`,
`place_service.rs`, `places_sqlite.rs`, миграция V040, гейты `check-*.mjs`) — каждое
неочевидное решение (почему поле здесь, почему дублирование, почему структурная а не
рантайм-проверка) сопровождается комментарием с обоснованием и, где уместно, ссылкой на
ID решения (CR-01, D-XX, номер коммита) или требование. Новый код в этой фазе обязан
следовать тому же стилю — не только `// добавлено перемещение`, а объяснение через FK
V040 / `ON DELETE RESTRICT`, как это сделано для `referencing_act_count`.

### Один общий build_* для обоих транспортов (Tauri + HTTP)
**Источник:** `crates/trackly-app/src/tauri_cmds/reports.rs` (`build_reports_export_csv`,
`build_reports_export_pdf`) + `crates/trackly-app/src/http/reports.rs:262-284`
(`handler_export_csv` вызывает тот же `build_reports_export_csv`).
**Применить к:** WARNING-4 — фикс делается ровно в одной точке (`report_service.rs::export_csv`
+ `tauri_cmds/reports.rs::build_reports_export_csv`), HTTP-хендлер не трогается и
автоматически получает исправление.

## No Analog Found

Файлов без близкого аналога в этой фазе нет — все четыре находки повторяют уже дважды
(BLOCKER-1/CR-01, WARNING-4/export_pdf) или один раз (BLOCKER-2, WARNING-1) закрытый в
этом же репозитории класс дефекта.

Единственная зона с открытым вопросом (не «нет аналога», а «аналог указывает на пробел в
данных») — каскад «картридж едет за принтером» (WARNING-1, write-site 3): клиент
структурно не может получить список затронутых картриджей от текущего API
(`DeviceDto`/`onSaved` не несут этот список), поэтому здесь ожидается не код-паттерн, а
задокументированное ограничение (см. соответствующий раздел Pattern Assignments выше).
