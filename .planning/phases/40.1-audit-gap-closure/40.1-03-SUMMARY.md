## Deviations from Plan

### Round 2 fix (после провала живой проверки Task 4)

**1. [Живой UAT gap-closure] PlaceEntityViewModal инвалидировал только текущий просматриваемый корень, не фактическое старое/новое место записи**
- **Найдено:** живая проверка Task 4, раунд 1 — пользователь сообщил: «счётчики дерева НЕ обновляются, кроме счётчика текущего открытого раздела; нужно переключить раздел и вернуться в Места, чтобы увидеть обновлённые счётчики для других мест»
- **Причина:** исходная реализация (`ab0853c0`) звала `notifyPlaceContentChanged([place.id])` — только id узла, который в данный момент просматривается в `PlaceContents`. `PlaceTree`'s `ancestorsAndSelf()` разворачивает это только ВВЕРХ по `parent_id` — ни узел назначения (другая ветка дерева), ни вложенные подместа под просматриваемым корнем (например, этаж под просматриваемым зданием) не попадали в инвалидацию.
- **Фикс:** `PlaceEntityViewModal`'s `onChanged` расширен до `(changedPlaceIds: number[]) => void`. Компонент уже держит старое место записи в `deviceDto`/`cartridgeDto` (загружены ДО правки, не меняются, пока открыт `editOpen`) и получает новое место из результата сохранения — `DeviceFormModal`'s `onSaved({ typeId, placeId })` (поле `placeId` уже было добавлено в Task 2 этого же плана для другого потребителя) и `CartridgeFormModal`'s `onSuccess(cart: CartridgeDto)` (полная сохранённая сущность). Два раздельных обработчика (`handleDeviceEditSaved`/`handleCartridgeEditSaved`), а не один общий — сигнатуры двух исходных колбэков асимметричны. `PlaceContents.svelte` мержит `place.id` с полученным массивом и дедуплицирует перед вызовом `notifyPlaceContentChanged`.

параметра `cartridgeId`).

(`mutation_test_anchor_must_be_unique`). Гейт `check-place-tree-invalidation.mjs` переработан:
