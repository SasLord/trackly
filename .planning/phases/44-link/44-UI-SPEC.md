# Phase 44 — UI Design Contract

> Визуальный и интеракционный контракт фазы «Link — транспорт, пин сертификата и вход».
> Составлен gsd-ui-researcher, проверяется gsd-ui-checker.
>
> **Макета нет.** Дизайн-система — общие токены `packages/design/src/styles/_tokens.scss`
> (Фаза 23, вынесены в пакет в Фазе 42), примитивы — `packages/kit` (`AuthShell`, `FormField`,
> `Input`, `Button`, `Badge`, `Modal`, `Tabs`, `Dropdown`, `ActionMenu`, `Spinner`, `Toast`,
> `ThemeSwitcher`, `TableRow`), каркас окна Link — `link-ui/src/App.svelte` (Фаза 42, D-14…D-16).

> состояния и тексты. Новых npm-зависимостей — **ноль**. Новых токенов — **ноль**.
>
> **Приватность (жёсткое условие, репозиторий публичный):** все примеры вымышлены:
> «Иванов И.И.», «Петров П.П.», логин `ivanov`, домен `EXAMPLE`, сервер `trackly.example.local`,

> ФИО и отпечатки в код, тесты, скриншоты и UAT-отчёты не попадают.

  UX-слой.

## 3. Spacing Scale

Шкала Фазы 23 не меняется. Задействованные значения:

| Токен | Значение | Использование в Фазе 44 |
|-------|----------|-------------------------|
| `--tr-space-2xs` | 4px | gap «точка связи ↔ текст»; вертикальный padding кнопки-триггера учётной записи; gap лейбла и значения отпечатка |
| `--tr-space-xs` | 8px | вертикальный padding плашки «Нет связи»; gap кнопок в строке инлайн-подтверждения; gap строк блока «Для администратора» |
| `--tr-space-sm` | 12px | gap иконки и текста в плашках/callout'ах; padding callout'ов по вертикали |
| `--tr-space-md` | 16px | gap полей формы (как `LoginPage`); горизонтальный padding шапки и плашки; горизонтальный padding callout'ов; gap секций тела попапа |
| `--tr-space-xl` | 24px | отступ заголовка карточки до содержимого (`margin-bottom` заголовка, как `.login-title`); верхний отступ секции «Link» в карточке пользователя |
| `--tr-space-2xl` / `--tr-space-4xl` | 32 / 48px | padding `AuthShell` (унаследовано, `--tr-space-2xl --tr-space-4xl`) |

**Исключения (литеральные px вне шкалы — все документированы):**

| Величина | Где | Обоснование |
|----------|-----|-------------|
| 56px | высота шапки окна Link (было 48px в Фазе 42) | блок учётной записи — две строки: 21px (body-strong 14×1.5) + 16px (caption 12×1.35) без gap (строки стоят вплотную, разделяет их межстрочный интервал) = 37px, плюс вертикальный padding триггера 2×4px (`--tr-space-2xs`) = 45px — в 48px остаётся 1.5px до границы шапки, фокус-кольцо триггера обрезалось бы. 56px = 45 + ~5px воздуха сверху и снизу. Вкладки и `ThemeSwitcher` центрируются по вертикали (`align-items: center`) |
| 240px | ширина сайдбара окна Link; ширина ячейки `ThemeSwitcher` | унаследовано (Фаза 42) |
| 240px / 160px | `max-width` / `min-width` блока учётной записи в шапке (§6.7) | при минимуме окна 720px: 96 (лого) + вкладка «Чат» (`flex: none`, ~64px) + 240 (тема) + 3×16 gap + 2×16 padding = 480, учётке остаётся 240px. Если ширины не хватает (крупный системный шрифт), учётка сжимается с ellipsis до 160px; ниже не сжимается — `tabs-cell` теряет пустое место справа первым |
| 12px | `--tr-space-sm` — gap иконки и текста, вертикальный padding callout'ов | **токен Фазы 23** (шкала 4-кратная, 12 = 3×4), не литерал; вынесен сюда, потому что вне ряда 4/8/16/24/32/48/64 |
| 8px | диаметр точки состояния связи | читается рядом с текстом 12px; цвет — не единственный признак (рядом всегда слово) |
| 400px | `maxWidth` `AuthShell` на экранах Link (§6.3–§6.6) | у дефолта 360px строка отпечатка (95 символов mono) переносится на 4 строки; 400px — 3 строки |

Унаследованные литералы `link-ui` (`gap: 12px`, `padding: 8px 16px`) при правке файлов
переводятся на токены (`--tr-space-sm`, `--tr-space-xs --tr-space-md`); новых литералов нет.

## 6. Окно Link

### 6.1 Конечный автомат экранов

Окно Link в каждый момент показывает **ровно один** экран. Решение о том, какой, принимает
Rust-часть; webview получает состояние событием `link-event` и рисует экран по нему. Webview
не делает сетевых запросов (ADR 0002).

| Состояние | Экран | Окно открывается само? (D-18) |
|-----------|-------|-------------------------------|
| `starting` — читаем конфиг, проверяем отпечаток, пробуем SSO | «Подключение…» §6.2 | нет |
| `needs_setup` — конфига нет (ни машинного, ни пользовательского) | Первая настройка §6.3 | **да** |
| `pin_mismatch` — отпечаток сервера ≠ закреплённому | «Сертификат сервера изменился» §6.4 | **да** |
| `needs_login` — токена нет / сервер сказал «недействителен»; SSO не удался или недоступен | Вход §6.5 | **да** |
| `logged_out` — сотрудник нажал «Выйти из учётной записи» | Вход §6.5 в варианте «после выхода» | да (после нажатия) |
| `revoked` — сервер отозвал вход / устройство запрещено | Вход §6.6 с плашкой отзыва | **да** |
| `connected` | Каркас Фазы 42 + шапка учётной записи §6.7 | нет |
| `offline` — вход был, связи нет ≥ 5 с (в т.ч. при старте, D-25) | Каркас + плашка «Нет связи» §6.8 | нет |

Правила:
- Переход `offline → needs_login` — **только** когда сервер сам ответил, что вход
  недействителен (D-25). Обрыв сети форму пароля не открывает.
- `offline` из `connected` появляется с задержкой ~5 с (D-23); короткие обрывы — без изменений
  на экране и в трее. Возврат связи убирает плашку сразу, без тоста.
- После `revoked` автовход не повторяется (D-14), в том числе при следующем запуске, пока
  сервер не ответит, что устройство снова разрешено.
- Окно, открытое «само», получает фокус; фокус ставится на первое интерактивное поле экрана
  (код приглашения / логин) или на primary-кнопку, если полей нет.
- Повторный запуск exe при работающем экземпляре показывает и фокусирует окно (D-19) — экран
  не меняется.

Экраны §6.2–§6.6 рисуются через `AuthShell` (`maxWidth={400}`, без `stack`), **без** шапки и
сайдбара каркаса. Над заголовком карточки — `LinkLogo`, по центру, отступ снизу
`--tr-space-md`. Заголовок — `h1` с ролью H3, по центру, `margin-bottom: --tr-space-xl`.
Тема на этих экранах следует системе; `ThemeSwitcher` не показывается (он есть в шапке
подключённого окна).

Внизу карточки каждого экрана §6.3–§6.6 — строка «Сервер: trackly.example.local» (caption,
`--tr-text-tertiary`, по центру), если адрес сервера уже известен. На §6.3 её нет.

### 6.2 «Подключение…»

- `Spinner` по центру карточки, под ним текст (body, `--tr-text-secondary`, по центру):
  - пока проверяется сервер — «Подключение к серверу…»;
  - пока идёт SSO — «Выполняется автоматический вход…».
- Кнопок нет. Обычно окно в этот момент скрыто; экран виден, только если сотрудник открыл окно
  из трея во время старта.
- Если стадия длится дольше 15 с без ответа сервера — переход в `offline` (если вход был) или
  остаётся здесь с подписью caption «Сервер не отвечает. Link продолжает попытки.» (default).

### 6.3 Первая настройка (код приглашения)

Структура карточки:
1. Заголовок: «Подключение к Trackly».
2. Абзац (body, `--tr-text-secondary`): «Введите код приглашения. Его выдаёт администратор
   Trackly. Код нужен один раз — для подключения этого компьютера.»
3. `FormField` «Код приглашения», `Input` с `mono`, `autocomplete="off"`, `spellcheck=false`,
   одна строка. Вставленное значение тримится; переносы строк и пробелы внутри удаляются до
   разбора. Подсказка (hint): «Вставьте код целиком — так, как его прислал администратор.»
4. Primary `Button` «Подключить» на всю ширину карточки. В процессе — `loading`, поле
   `disabled`, текст кнопки не меняется.
5. Ошибки — под полем (`FormField error`), кроме несовпадения отпечатка (см. ниже).

Тексты ошибок:

| Случай | Текст |
|--------|-------|
| Поле пустое | «Введите код приглашения» |
| Код не разобран | «Код не распознан. Проверьте, что он скопирован целиком.» |
| Срок истёк | «Срок действия кода истёк. Попросите у администратора новый.» |
| Код уже использован / отозван | «Этот код уже использован или отозван. Попросите у администратора новый.» |
| Сервер недоступен | «Не удалось связаться с сервером trackly.example.local. Проверьте сеть и нажмите «Подключить» ещё раз.» |
| Отпечаток ≠ отпечатку из кода | поле очищается от ошибки; над кнопкой — danger-callout (как §6.4, компактно): «Сервер не прошёл проверку подлинности. Ничего не сохранено. Обратитесь к администратору.» + блок «Для администратора» §6.4 |

Ничего не сохраняется, пока отпечаток не совпал (D-03). Кнопки «Доверять» нет нигде.
Успех — без тоста: экран переходит в `starting` → далее по автомату (SSO или вход паролем).

### 6.4 «Сертификат сервера изменился»

Структура карточки:
1. Иконка-предупреждение (inline SVG, 32px, `--tr-danger`) по центру над заголовком.
2. Заголовок: «Сертификат сервера изменился».
3. Абзац (body, `--tr-text-primary`): «Link не может безопасно подключиться к серверу и ничего
   ему не отправляет. Обратитесь к администратору Trackly.»
4. Блок «Для администратора» (`--tr-surface-sunken`, `--tr-radius-md`, padding
   `--tr-space-sm --tr-space-md`, gap строк `--tr-space-xs`, текст выровнен влево):
   - заголовок блока (caption, `--tr-text-secondary`): «Для администратора»;
   - «Сервер:» (caption, `--tr-text-secondary`) + значение (body);
   - «Ожидаемый отпечаток (SPKI):» (caption, `--tr-text-secondary`) + значение `.tr-mono`;
   - «Полученный отпечаток (SPKI):» (caption, `--tr-text-secondary`) + значение `.tr-mono`;
   - отпечатки форматируются парами через двоеточие, верхний регистр (как в `NetworkSettings`).
5. Кнопки (строка, gap `--tr-space-xs`, по ширине карточки поровну):
   - secondary «Скопировать сведения» — кладёт в буфер текст блока целиком (4 строки);
     после копирования текст кнопки на 2 с меняется на «Скопировано»;
   - primary «Проверить снова» — повторяет TLS-рукопожатие; в процессе `loading`; при
     повторном несовпадении экран остаётся, полученный отпечаток обновляется.

Принять новый сертификат нельзя. Ни логина, ни кода приглашения на этом экране нет.

### 6.5 Вход

Структура карточки:
1. Заголовок: «Вход в Link».
2. **Callout причины** — только если перед этим был автовход и он не удался (D-09), либо
   сотрудник вышел (D-11). Варианты ниже. Callout стоит над формой, отступ снизу `--tr-space-md`.
3. Форма (gap `--tr-space-md`, как `LoginPage`):
   - `FormField` «Логин», `autocomplete="username"`, hint: «Логин Trackly или доменный, например
     EXAMPLE\ivanov»;
   - `FormField` «Пароль», `type="password"`, `autocomplete="current-password"`;
   - primary `Button` «Войти», на всю ширину.
4. Галочки «Запомнить» **нет** — вход запоминается всегда (D-10).
5. Если хранилища ОС нет (Linux без Secret Service) — под кнопкой caption
   (`--tr-text-tertiary`): «Вход сохранится только до закрытия Link: в системе нет хранилища
   паролей.»
6. Строка «Сервер: …» внизу (§6.1).

**Callout «Автоматический вход не выполнен»** (warning: `--tr-warning-soft` фон,
`--tr-warning-text` текст, `--tr-radius-md`, padding `--tr-space-sm --tr-space-md`):
- строка 1 (body-strong): «Автоматический вход не выполнен»;
- строка 2 (body): причина из таблицы;
- кнопка secondary `size="sm"` «Повторить автовход» — справа внизу callout'а. В процессе —
  `loading`. Успех → `connected`. Неудача → callout остаётся с новой причиной. Пароль при этом
  не отправляется (D-09).
- Кнопки «Повторить автовход» нет, если причина — «адрес по IP» или «автовход выключен на
  сервере» (повтор бессмыслен до действий администратора).

| Причина (D-09) | Текст строки 2 |
|----------------|-----------------|
| Адрес сервера — IP | «Сервер подключён по IP-адресу, а автовход работает только по имени сервера. Войдите по логину и паролю.» |
| SSO выключен на сервере | «Автовход выключен на сервере. Войдите по логину и паролю.» |
| Нет SPN / ошибка Kerberos | «Компьютер не смог подтвердить вашу доменную учётную запись. Войдите по логину и паролю или повторите позже.» |
| Учётная запись домена не сопоставлена | «Ваша доменная учётная запись не найдена в Trackly. Обратитесь к администратору или войдите по логину и паролю.» |
| Сервер не ответил на автовход | «Сервер не ответил на автоматический вход. Повторите позже или войдите по логину и паролю.» |

Технические детали (код Kerberos, SPN) в UI не показываются — только в лог, без токенов и
заголовков SPNEGO.

**Callout «после выхода»** (D-11, только на доменном Windows-ПК; info: `--tr-surface-sunken`
фон, `--tr-text-secondary` текст):
- текст (body): «Вы вышли из учётной записи. Можно войти другим логином или вернуться к
  автоматическому входу.»;
- кнопка secondary `size="sm"` «Войти автоматически».
- Вне домена и на macOS/Linux этого callout'а нет — только форма (D-15).

Ошибки формы (под кнопкой, `--tr-danger-text`, body, `role="alert"`):

| Случай | Текст |
|--------|-------|
| Логин пуст | под полем: «Введите логин» |
| Пароль пуст | под полем: «Введите пароль» |
| Неверная пара | «Неверный логин или пароль» |
| Учётная запись заблокирована | «Учётная запись заблокирована. Обратитесь к администратору.» |
| Компьютер запрещён (после отзыва) | «Вход с этого компьютера запрещён администратором. Обратитесь к администратору.» |
| Rate-limit | «Слишком много попыток входа. Повторите через минуту.» |
| Нет связи | «Нет связи с сервером. Проверьте сеть и повторите.» |
| Сервер аутентификации недоступен | «Сервер аутентификации недоступен. Повторите попытку позже или обратитесь к администратору.» (как в Trackly) |

После неудачной попытки пароль стирается, фокус — в поле «Пароль». Пароль никогда не
отправляется повторно автоматически.

### 6.6 Вход отозван администратором

Тот же экран §6.5, но вместо warning-callout — **danger-callout** (`--tr-danger-soft` фон,
`--tr-danger-text` текст, `role="alert"`):
- строка 1 (body-strong): «Вход отозван администратором»;
- строка 2 (body): «Этот компьютер отключён от Link. Войти снова можно после того, как
  администратор разрешит компьютер.»

Форма входа показывается (D-14). Если устройство ещё запрещено, попытка даёт ошибку «Вход с
этого компьютера запрещён администратором…» (§6.5). Кнопки автовхода нет.

**Если планировщик выбрал повторный допуск через новый код** (вариант Б, §8.2.3): строка 2 —
«Этот компьютер отключён от Link. Чтобы подключить его снова, получите у администратора новый
код приглашения.», под callout'ом — кнопка secondary «Ввести код приглашения», которая
открывает §6.3 (пользовательский конфиг перезаписывается только после успешной проверки
отпечатка). При варианте А этой кнопки нет.

### 6.7 Подключённое окно: шапка учётной записи

Каркас Фазы 42 сохраняется (лого · вкладки · тема / сайдбар / заглушка / служебная строка).
Высота шапки `.topbar` — **56px** вместо 48px (расчёт в §3, исключения). В шапку **между**
`tabs-cell` и `theme-cell` добавляется блок учётной записи `account-cell`:

```
[Link] [Чат ............] [● Иванов И.И.            ▾] [ тема ]
                          [  Доменный вход · trackly.example.local ]
```

- **Триггер — собственная кнопка, не встроенный триггер `ActionMenu`.** Проверено по
  `packages/kit/src/components/ActionMenu.svelte`: у `ActionMenu` варианты только
  `default | ghost-sm | ghost-md`, а встроенный триггер принимает лишь `label: string` +
  `icon: Snippet` — двухстрочный блок с точкой в него не помещается. Поэтому:
  - `account-cell` рендерит `Button variant="ghost"` (примитив `Button` вариант `ghost` имеет)
    с двухстрочным содержимым, `aria-haspopup="menu"`, `aria-expanded` из `onOpenChange`;
  - рядом — `ActionMenu trigger="none" panelMinWidth="240px"`, ссылка через `bind:this`;
  - `onclick` кнопки: `const r = btn.getBoundingClientRect(); menu.openAt(r.left, r.bottom)`;
    фокус при закрытии возвращается на кнопку (`openAt` запоминает предыдущий фокус —
    поведение примитива);
  - **изменять общий примитив `ActionMenu` в этой фазе не нужно.**
- Раскладка шапки: `.logo-cell` `flex: none` (96px); `.tabs-cell` `flex: 1 1 auto;
  min-width: 0`, сама вкладка «Чат» `flex: none` (не сжимается и не обрезается);
  `.account-cell` `flex: 0 1 240px; min-width: 160px; max-width: 240px`;
  `.theme-cell` `flex: none` (240px). При нехватке места сжимается только `account-cell`, обе
  строки — `overflow: hidden; text-overflow: ellipsis; white-space: nowrap`.
- Кнопка выровнена текстом влево, две строки:
  - строка 1: точка состояния (8px, круг) + ФИО (body-strong, ellipsis);
  - строка 2: «{способ входа} · {сервер}» (caption, `--tr-text-secondary`, ellipsis).
    Способ входа: «Доменный вход» / «Вход по паролю».
- Атрибут `title` — полный текст: «Иванов И.И. · Доменный вход · trackly.example.local · В сети».
- `aria-label` триггера: «Учётная запись: Иванов И.И., в сети».
- Точка и состояние связи:

| Состояние | Точка | Слово (в `title`, `aria-label` и меню) |
|-----------|-------|----------------------------------------|
| `connected` | `--tr-success` | «В сети» |
| первые ≤ 5 с после обрыва / первичное подключение | `--tr-text-tertiary` | «Подключение…» |
| `offline` | `--tr-warning` | «Нет связи» |

- Если ФИО ещё неизвестно (старт без сети, D-25) — строка 1: «Ожидание сервера», строка 2:
  только сервер.
- Меню (`ActionMenu`, портал по умолчанию — общее поведение примитива, не флаг на вызове).
  Содержимое — `children`-сниппет; примитив уже поддерживает разделители `<hr>` (стиль
  `.action-menu-panel :global(hr)`, вне навигации стрелками) и неинтерактивные блоки без
  `role="menuitem"` (прецедент — `div.menu-user` в `EmployeeLayout.svelte`):
  1. неинтерактивный `div.menu-account` (без `role="menuitem"`, не фокусируется): строка 1
     ФИО (body-strong), строка 2 «{способ входа} · {сервер} · {В сети / Нет связи}»
     (caption, `--tr-text-secondary`, перенос разрешён — в панели нет ellipsis);
  2. `<hr />`;
  3. `<button role="menuitem">` «Выйти из учётной записи»;
  4. только Linux без трея (§6.9): `<hr />` + `<button role="menuitem">` «Закрыть Link».
- «Выйти из учётной записи» — без подтверждения: действие обратимо и запрошено самим
  сотрудником. Результат: токен стёрт локально и отозван на сервере, окно → §6.5 в варианте
  «после выхода» (доменный ПК) или чистая форма. Если сервер недоступен, локальный выход
  выполняется всё равно, отзыв на сервере догоняется при следующей связи (default).

### 6.8 Плашка «Нет связи с сервером»

- Место: новая строка грида каркаса **между шапкой и сайдбаром/контентом**, на всю ширину
  (`grid-column: 1 / -1`). Шапка остаётся неподвижной; сайдбар и контент сжимаются по высоте
  (каждый скроллит свою область, `min-height: 0`).
- Вид: фон `--tr-warning-soft`, текст `--tr-warning-text`, нижняя граница `--tr-border`,
  padding `--tr-space-xs --tr-space-md`, `display:flex`, gap `--tr-space-sm`, выравнивание по
  центру по вертикали.
- Содержимое: иконка (inline SVG «облако с чертой» или «нет сигнала», 16px, `currentColor`) +
  текст (body): «Нет связи с сервером · переподключение…» + справа кнопка secondary
  `size="sm"` «Повторить сейчас».
- «Повторить сейчас» сбрасывает паузу backoff и пробует сразу; в процессе — `loading`. Если
  попытка не удалась — плашка остаётся, без отдельной ошибки.
- `role="status"`, `aria-live="polite"` — читается один раз при появлении.
- Появляется через ~5 с после обрыва, исчезает сразу при восстановлении (D-23). Тоста
  «соединение восстановлено» нет. Ресинк после возврата — тихий (D-24).
- Обратного отсчёта до следующей попытки нет (default: меньше таймеров и мигания).

### 6.9 Linux без системного трея (D-20, LNK-11)

- Окно видно на панели задач; закрытие окна **сворачивает** его (minimize), а не прячет.
- Выход — пунктом «Закрыть Link» в меню учётной записи (§6.7, п.4).
- На экранах без шапки (§6.2–§6.6) под карточкой `AuthShell` — кнопка `variant="link"`
  «Закрыть Link» (caption-размер не задаётся отдельно — примитив `link`), по центру, отступ
  сверху `--tr-space-md`.
- При наличии трея (Windows, macOS, Linux с AppIndicator) ни пункта, ни кнопки «Закрыть Link»
  в окне **нет** — единственный выход через меню трея (LNK-04).
- Признак «трея нет» приходит из Rust-части в состоянии (`tray_available: false`); webview не
  угадывает его сам.

### 6.10 Размеры и раскладка

- Окно: ~1000×700 по умолчанию, минимум ~720×500, размер и положение запоминаются (Фаза 42).
- `AuthShell` центрирует карточку в окне; при высоте окна меньше карточки — прокручивается
  вся область (`min-height: 100vh` примитива + `overflow-y: auto` на корне экрана).
- Каркас: `.shell` — `overflow: hidden`, каждая область скроллит себя (`height: 100%;
  min-height: 0`) — паттерн оболочки проекта.
- macOS: значка в Dock нет; иконка — в строке меню (D-20).

## 7. Трей

### 7.1 Иконка и подсказка

| Состояние Link | Иконка | Подсказка (tooltip) |
|----------------|--------|----------------------|
| `connected` | обычная — знак Link (D-12 Фазы 42) | «Trackly Link» |

Иконка пересоздаётся после перезапуска Explorer (по исследованию, M-7) — визуально без
изменений.

### 7.2 Меню трея (правый клик; на Linux — единственный способ)

Порядок пунктов (нативное меню ОС, без стилизации):

1. **«Открыть Link»** — на Windows пункт по умолчанию (жирный, если ОС поддерживает).
2. разделитель
3. строка состояния — неактивный пункт (disabled), текст по состоянию:
   - «Иванов И.И. · в сети»
   - «Иванов И.И. · нет связи»
   - «Вход не выполнен» (`needs_setup` / `needs_login` / `logged_out` / `revoked`)
   - «Сертификат сервера изменился» (`pin_mismatch`)
4. разделитель
5. **«Выйти из учётной записи»** — виден только при наличии входа (`connected` / `offline`).
   Действие как в §6.7; после него окно открывается на экране входа.
6. разделитель (если п.5 виден)
7. **«Закрыть»** — завершает Link полностью. Без подтверждения (default: это единственный
   выход, D-16; автозапуск поднимет Link при следующем входе в систему).

Левый клик (Windows, macOS при поддержке) — показать окно, если скрыто; скрыть, если видно и в
фокусе. Закрытие окна крестиком — прячет в трей (LNK-04), без тоста и без диалога.

Пункта «Автозапуск» нет (D-17).

## 8. Trackly: раздел «Link» (только администратор)

### 8.1 Сайдбар и страница

- Новый пункт в `sidebar-config.ts`: `{ kind: 'item', route: '/link', label: 'Link', roles:
  ['admin'] }` — **сразу после «Пользователи»**, в той же группе до разделителя. Счётчик
  `PINNED` в комментарии и связанные гейты (`check-sidebar-active.mjs` и др.) обновить.
- Страница `LinkPage` по паттерну оболочки: корень `height: 100%; min-height: 0`, скроллит
  свою внутреннюю область; `PageHeader title="Link"`, в `actions` — primary `Button`
  «Выпустить код приглашения».
- Под шапкой — `Tabs variant="underline"`, `ariaLabel="Разделы Link"`:
  1. «Входы» (по умолчанию) — со счётчиком `count` активных входов;
  2. «Коды приглашения».
  Фаза 45 добавляет свои вкладки сюда же. Активная вкладка хранится в query (`?tab=codes`),
  чтобы ссылка и `use:active` сайдбара работали (`sidebarActivePattern` допускает query).
- Список обновляется на лету по серверному событию (вход, отзыв, использование кода) через
  реестр инвалидации Фазы 43 — без перезагрузки и без тоста.

#### 8.2.2 Подтверждение «Отозвать вход»

`Modal` (size `md`), рендерится **на уровне страницы**, а не внутри `<td>` (иначе наследует
`white-space: nowrap` / `text-align` ячейки — урок проекта).

- Титул: «Отозвать вход?»
- Тело: «**Иванов И.И.** на компьютере **PC-EXAMPLE-01** будет сразу отключён от Link.
  Компьютер будет запрещён: войти с него не получится ни паролем, ни автоматически, пока вы его
  не разрешите.»
- Кнопки: destructive «Отозвать вход», secondary «Отмена». Фокус по умолчанию — «Отмена».
- Успех: модалка закрывается, строка уходит из «Активных входов» и появляется в «Запрещённых
  компьютерах», toast success «Вход отозван».
- Ошибка: toast error «Не удалось отозвать вход. Повторите.», модалка остаётся.

#### 8.2.3 Секция «Запрещённые компьютеры» и повторный допуск (D-13)

Показывается под активными входами, **только если** есть хотя бы один запрещённый компьютер.
Заголовок (`h2`, роль body-strong): «Запрещённые компьютеры».

| Колонка | Содержимое |
|---------|------------|
| Компьютер | `.tr-mono` |
| Последний сотрудник | ФИО |
| Запрещён | дата и время |
| Состояние | `Badge variant="destructive"` «Запрещён» |

Планировщик выбирает **один** вариант:

- **Вариант А — кнопка «Разрешить».** В колонке действий — `Button variant="secondary"
  size="sm"` «Разрешить». Без подтверждения (действие снимает запрет и ничего не ломает).
  Успех: строка исчезает, toast success «Компьютер PC-EXAMPLE-01 снова может входить в
  Link». Сотрудник после этого входит как обычно (§6.6, форма). В процессе — `loading` на
  кнопке. Ошибка: toast error «Не удалось разрешить компьютер. Повторите.», строка остаётся в

- **Вариант Б — только новый код.** Колонки действий нет; под заголовком секции caption

  приглашения.» Код, применённый на запрещённом компьютере, снимает запрет.

Сам код в таблице **не показывается** (на сервере хранится хэш; код виден только в момент

- Отзыв кода — инлайн-подтверждение в строке, по образцу удаления в `UserListRow`: текст

- Загрузка — `Spinner` по центру области таблицы (как §8.2.1).
- Ошибка загрузки — инлайн (body, `--tr-danger-text`): «Не удалось загрузить коды
  приглашения. Обновите страницу.» + toast error того же текста (как §8.2.1).
- Пусто: «Кодов приглашения нет» / «Выпустите код, чтобы подключить компьютер сотрудника к

### 8.4 Попап «Код приглашения»

`Modal` size `md`, два шага в одном окне.

**Шаг 1 — параметры:**
- Титул: «Код приглашения».
- Абзац (body, `--tr-text-secondary`): «Код подключает один компьютер к этому серверу Trackly.
  Он не входит в учётную запись: после подключения сотрудник войдёт сам — автоматически или
  паролем.»
- `FormField` «Адрес сервера для Link» — `Input`, предзаполнен адресом из настроек сети (имя,
  если известно). Hint: «Для автоматического входа укажите имя сервера, а не IP-адрес.»
- Если введён IP — под полем warning-callout: «По IP-адресу автоматический вход не работает:
  сотрудники будут входить по паролю.» (не блокирует выпуск).
- `FormField` «Срок действия» — **`Dropdown variant="select"`** (не нативный `<select>` и не
  обёртка `Select`): «1 час», «24 часа» (по умолчанию), «7 дней».
- Кнопки: primary «Выпустить код», secondary «Отмена». В процессе — `loading` на «Выпустить
  код», поля `disabled`.
- Ошибка сервера при выпуске: под полями, над футером — строка (body, `--tr-danger-text`,
  `role="alert"`) «Не удалось выпустить код. Повторите.»; модалка остаётся на шаге 1,
  введённые значения сохраняются; при следующем нажатии строка ошибки скрывается.
- Если сервер Trackly не запущен или сертификата нет — вместо полей danger-callout: «Сервер
  Trackly не запущен. Запустите его в разделе «Настройки → Сеть» и выпустите код снова.»;
  кнопка «Выпустить код» `disabled`.

**Шаг 2 — код выпущен:**
- Блок кода: `--tr-surface-sunken`, `--tr-radius-md`, padding `--tr-space-md`, код `.tr-mono`,
  `overflow-wrap: anywhere`, `user-select: all`.
- Под блоком caption (`--tr-text-secondary`): «Действует до 28.11.2026 14:30. Используется
  один раз. После закрытия окна код больше не показывается.»
- Строка caption: «Сервер: trackly.example.local».
- Кнопки: primary «Скопировать код» (после нажатия текст на 2 с — «Скопировано»), secondary
  «Готово».
- Закрытие (Esc, крестик, «Готово») — без подтверждения; код появляется в таблице §8.3 как
  «Активен».

## 9. «Настройки → Сеть»: SPKI-отпечаток (D-06)

В `NetworkSettings.svelte`, блок `server-info-block`, **после** строки «Отпечаток
сертификата:» — новая строка:

- лейбл (`.info-label`): «Отпечаток для Link (SPKI):»;
- значение: `<code class="fingerprint">` в том же формате (пары через двоеточие, верхний
  регистр);
- справа — `Button variant="secondary" size="sm"` «Скопировать отпечаток» (→ «Скопировано» на 2 с);
- под строкой caption (`--tr-text-secondary`): «Link сверяет этот отпечаток. Он не меняется
  при продлении сертификата — только при смене ключа.»

Строка видна, когда сертификат существует (даже если сервер остановлен — default; если
планировщику проще брать отпечаток только у запущенного сервера, строка следует видимости
блока). Прежняя строка «Отпечаток сертификата:» для браузеров не меняется.

Перевыпуск сертификата с сохранением ключа визуально не меняет SPKI-строку — это и есть
проверка для UAT.

## 10. Карточка пользователя: «Отозвать входы Link»

Карточка пользователя в Trackly — `UserFormModal` в режиме редактирования. Режим создания не
меняется.

- В конце тела модалки, перед футером, — секция с верхней границей `--tr-border` и отступом
  `--tr-space-xl`:
  - заголовок (caption, `--tr-text-secondary`): «Link»;
  - строка (body): «Активных входов: 2» (из ответа сервера; `pluralize` не нужен — число
    после двоеточия);
  - `Button variant="destructive" size="sm"` «Отозвать входы Link»; `disabled`, если входов 0,
    тогда рядом caption «Нет активных входов».
- Подтверждение — **инлайн в секции** (вложенная модалка запрещена): кнопка заменяется
  строкой «Отозвать все входы Link (2)? Компьютеры будут запрещены.» + destructive `sm`
  «Отозвать» + ghost `sm` «Отмена».
- Действие выполняется **сразу**, независимо от «Сохранить» модалки. Успех: строка
  «Активных входов: 0», toast success «Входы Link отозваны: 2». Ошибка: toast error «Не
  удалось отозвать входы Link. Повторите.»
- Подсказка блокировки: когда в той же модалке снимается галочка активности пользователя,
  под `Checkbox` появляется caption (`--tr-text-secondary`): «Блокировка также отзовёт все
  входы Link этого пользователя.» (D-12).

## 12. Доступность и взаимодействие

- Все экраны Link управляются клавиатурой: Enter в поле отправляет форму; Esc на экранах
  входа ничего не делает (окно скрывается только крестиком / из трея).
- Ошибки форм — `FormField error` (связь `aria-describedby`); ошибки уровня формы и
  danger-callout'ы — `role="alert"`; плашка «Нет связи» — `role="status"`.
- Смена экрана по событию из Rust переносит фокус по правилам §6.1; screen reader читает
  заголовок нового экрана (`h1` с `tabindex="-1"`, фокус на него, если полей нет).
- Контраст: все новые пары — существующие токен-пары гейта `check-contrast.mjs`
  (`--tr-warning-text` на `--tr-warning-soft`, `--tr-danger-text` на `--tr-danger-soft`,
  `--tr-text-secondary` на `--tr-surface-sunken`). Новых правил гейта не требуется.
- Кнопки копирования не полагаются на `navigator.clipboard` в Link без проверки: при отказе
  текст остаётся выделяемым (`user-select: text`), ошибки не показываются (как в
  `StatusLine`).
- Webview Link не делает сетевых запросов и не открывает внешние ссылки (CSP без сети,
  ADR 0002); все действия — `invoke` в Rust.

### 12.1 Проверка (UAT)

Живые проверки на Windows (SPNEGO, трей и перезапуск Explorer, RDS с двумя пользователями,
автозапуск, Linux без трея) — human-UAT; по моку/стенду они **UNVERIFIED**. Экраны §6
допускается проверить на стенде, подавая состояния автомата из мока Rust-части, но это не
заменяет живой прогон.
