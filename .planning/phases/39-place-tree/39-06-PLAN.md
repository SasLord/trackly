<objective>
Migrate the Devices entity — domain layer, repo layer, DTO/transport layer, and service layer —
off `locations`/`location_id` onto `place_id`, removing the implicit get-or-create helper
(`resolve_location_id_in_tx`) that RESEARCH.md Common Pitfall 4 flags as the single biggest
silent-trap in this phase's blast radius, and removing the whole `AutocompleteField::Location`
mechanism (superseded entirely by `PlacePicker`).

This plan owns MORE than the original scope: `domain/devices.rs`, `devices_sqlite.rs`,
`dto/device.rs`, `device_service.rs`, `tauri_cmds/devices.rs`, and `http/devices.rs` all live in
the same two crates (`trackly-core`/`trackly-infra` feed into `trackly-app`) and must stay mutually
consistent for `cargo build -p trackly-app` to succeed at ANY point after this plan starts landing
— Rust does not compile one file at a time, a rename in `domain/devices.rs` breaks `dto/device.rs`
immediately, a deleted service method breaks its `tauri_cmds`/`http` callers immediately. Splitting
this work across plans in different waves would leave `trackly-app` non-compiling for an entire
wave, which is exactly the "wave boundary not provably compilable" failure this revision closes.

Purpose: devices become the reference implementation every other entity migration (acts,
cartridges) in this wave follows for "caller passes a validated place_id, no auto-create," AND the
reference for "one plan owns everything one crate's compiler needs to see together." This plan also
extends `search_fts` so a place-path substring query surfaces devices located there (D-29/PLC-05).
Output: `domain/devices.rs`, `devices_sqlite.rs`, `dto/device.rs`, `device_service.rs`,
`tauri_cmds/devices.rs`, `http/devices.rs`, `tauri_cmds/printers.rs` all migrated; `search_fts`
matches devices by intrinsic fields OR live place-path substring; `cargo build -p trackly-app`
succeeds for every device-owned file (act/cartridge/report/request cross-entity call sites are
Plans 07/09/10's own responsibility, tracked there and now explicitly gated by their `depends_on`).
</objective>
