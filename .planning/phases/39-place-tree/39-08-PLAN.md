<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| `search(query)` caller input | Free-text, length-capped, never concatenated into SQL — filtered entirely in Rust against an already-fetched trusted candidate set |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-08-01 | Tampering | SQL injection via `search` query text | mitigate | Query text never enters a SQL string at all — it is compared in Rust against an already-fetched candidate set (`SELECT * FROM place_full_paths` with no caller-supplied predicate), structurally eliminating the injection surface for this specific method |
| T-39-08-02 | Denial of Service | Unbounded query length or unbounded candidate-set scan | mitigate | 100-char query cap (mirrors existing `locations_autocomplete` convention) + confirmed real scale (~300 place rows, RESEARCH.md) means the full-scan-in-Rust approach has no meaningful DoS surface at this data size |
| T-39-08-03 | Information Disclosure | `search`/`list_subtree_contents` returning archived places to a Manager | mitigate | `search` explicitly excludes `archived_at_utc IS NOT NULL` rows (D-15); `list_subtree_contents` is unaffected by archival status since archival only hides a node from `PlacePicker`, not from the content-of-place screen (D-15's literal scope) |
</threat_model>
