<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Tauri webview → `tauri::invoke` | Local IPC, still passes through `authorize()` — no different trust level than HTTP for this codebase's model |
| LAN browser → `POST /api/v1/places_*` | Untrusted network input (any device on the LAN can reach this if the server is running) — the primary target of D-20's dual-transport gate requirement |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-12-01 | Elevation of Privilege | Manager calling `places_delete`/`places_move` directly via HTTP, bypassing UI button-hiding | mitigate | `authorize(caller, &Action::MutatePlaces)` runs inside `build_places_*` (Task 1), reached identically by both `handler_*` (Task 2) and the Tauri command wrapper — proven by Task 3's role-matrix Manager-403 cases on both transports |
| T-39-12-02 | Information Disclosure | Employee probing `/api/v1/places_*` read endpoints directly | mitigate | `authorize(caller, &Action::ReadPlaces)` gate, proven by Task 3's Employee-403 cases |
| T-39-12-03 | Repudiation | A places_* Tauri command silently unreachable from the frontend because `specta_export.rs` registration was forgotten | mitigate | Task 3 explicitly runs the `export_bindings` check, which fails the build if any command is missing from `collect_commands!` |
</threat_model>
