`device_snapshot_json` (act_service.rs helper functions, previously unowned by any plan), which
join/read device rows for the return-item prefill and undo-snapshot paths respectively — both broke
silently (one at SQL-runtime via a dropped `locations` table, one at Rust-compile-time via renamed
`DeviceRow` fields) once Plans 01/06 land.

half of `act_service.rs`, positioned after Plan 06 (devices) because `device_snapshot_json` reads
`DeviceRow` fields Plan 06 renames — this plan cannot compile until Plan 06 has landed, hence the
added `depends_on`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Act create/update payload `place_id` | Caller-supplied, validated by FK constraint (`ON DELETE RESTRICT`) at write time — same trust model as Plan 06's device migration |
| `place_path_snapshot` at write time | Captured server-side via `repo.full_path`, never accepted as raw text from the client — prevents a caller from forging an arbitrary printed path unrelated to the actual `place_id` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-07-01 | Tampering | `place_path_snapshot` forged by a malicious client | mitigate | The service computes the snapshot server-side from the validated `place_id` via `PlaceRepository::full_path` — the client never supplies snapshot text directly |
| T-39-07-02 | Repudiation | Act audit-log entries losing place history when the column is renamed | mitigate | Audit-log JSON keys are renamed in lockstep with the column rename (Task 2), preserving the existing "mirror persisted columns into audit_log" invariant |
| T-39-07-03 | Repudiation | `device_snapshot_json`'s undo snapshot (D-Undo-01) silently dropping place data on a field-name mismatch | mitigate | Task 3 renames the JSON keys in lockstep with `DeviceRow`'s Plan 06 rename, keeping `restore_from_snapshot_in_tx`'s `snapshot.get("place_id")` read consistent with what is written here |
</threat_model>
