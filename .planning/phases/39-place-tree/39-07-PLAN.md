<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Act create/update payload `place_id` | Caller-supplied, validated by FK constraint (`ON DELETE RESTRICT`) at write time — same trust model as Plan 06's device migration |
| `place_path_snapshot` at write time | Captured server-side via `repo.full_path`, never accepted as raw text from the client — prevents a caller from forging an arbitrary printed path unrelated to the actual `place_id` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-07-01 | Tampering | `place_path_snapshot` forged by a malicious client | mitigate | The service computes the snapshot server-side from the validated `place_id` via `PlaceRepository::full_path` — the client never supplies snapshot text directly |
| T-39-07-02 | Repudiation | Act audit-log entries losing place history when the column is renamed | mitigate | Audit-log JSON keys are renamed in lockstep with the column rename (Task 1), preserving the existing "mirror persisted columns into audit_log" invariant |
</threat_model>
