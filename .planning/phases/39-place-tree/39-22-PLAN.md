<objective>
Close a compile/runtime-fixup gap across 31 existing test files (30 in `trackly-app`, 1 in
`trackly-infra`) that construct struct literals or hand-written SQL referencing the pre-Phase-39
`location`/`location_id`/`location_name` vocabulary. None of these files were declared in any of
this phase's other 21 plans' `files_modified` — they are pure CONSUMERS of the domain/DTO/schema
renames those plans make (Plans 03/06/07/09/10/11), not owners of any renamed production code. Once
those plans' renames land, every one of these 31 files fails to compile (`E0560`/`E0609` — unknown
struct field) or, for the handful with hand-written SQL against the dropped `locations` table, fails
at runtime with a SQLite error. This plan is a deterministic, closed-list distribution from the
orchestrator's full-repo consumer inventory — it does not search for additional files.

Purpose: this is a pure test-fixup plan with zero production-code changes. It exists as ONE
dedicated plan (not smeared across the 21 production plans) so a single owner can be verified
against the full test suite in one pass, avoiding same-wave file-ownership conflicts and keeping the
diff reviewable — the orchestrator's explicit instruction for this revision round.
Output: all 31 files compile and pass under the full `trackly-app`/`trackly-infra` test suites.
</objective>

  `location_id_override` → `place_id_override`; `location_name_override` field DELETED entirely.
