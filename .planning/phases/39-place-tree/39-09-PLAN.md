<objective>
Migrate the Cartridges entity fully off `locations`/freeform `location: String`: the DTO layer
(`dto/cartridge.rs`), the five `CartridgeTransitionOp` operations (Install/ReturnToStock/ToRefill/
FromRefill/WriteOff), AND the separately-discovered `create`/`update` CRUD path (a THIRD mutating
location surface distinct from the five transition ops, with its own inline `INSERT OR IGNORE INTO
locations` round-trip inside `CartridgeService::update` — the exact "third mutating path hides
behind create/update" failure class this phase's revision rounds have repeatedly found). Removes
`upsert_location_in_tx` (the cartridge-side twin of `resolve_location_id_in_tx`) and
`cartridges_suggest_location` (the cartridge-side twin of devices' `locations_autocomplete`,
reachable via Tauri + HTTP + specta_export — all three surfaces removed together). Wires Install's
printer-place default via a NEW device lookup (no such lookup currently exists in
`CartridgeService`).

Purpose: cartridges get the same "caller passes a validated place_id, no implicit create" contract
Plan 06 established for devices — D-12/D-13's core mechanics, now covering EVERY mutating surface,
not just the five named transition operations. This plan also extends `search` with a live
place-path join (D-29/PLC-05, the cartridge-side sibling of Plan 06's device fix — required because
`search`'s existing `like_hits` CTE still references the about-to-be-dropped `c.location` column)
and exposes `storage_place_ids()` over both transports (B4: it was previously service-internal
only).
Output: `dto/cartridge.rs` and `cartridge_service.rs`/`cartridges_sqlite.rs` migrated onto
`place_id`; `search` matches cartridges by intrinsic fields OR live place-path substring;
`cartridge_storage_place_ids` reachable via Tauri and `/api/v1/cartridge_storage_place_ids`;
`cartridges_suggest_location` gone from every transport.
</objective>
