# Phase 39 — UI Design Contract

> Визуальный и интеракционный контракт фазы «Дерево мест»: раздел «Места» (дерево + содержимое),
> общий контрол выбора места (PlacePicker) и отображение места во всём остальном приложении.
> Составлен gsd-ui-researcher, проверяется gsd-ui-checker.

## 2. Границы: что этот контракт НЕ покрывает

- **Никакой графики.** Чертежи, планы этажей, SVG-подложки, маркеры — Фазы 43–44. В фазе 39 не
  появляется ни одного пикселя плана.
- **Схема БД, хранение дерева, механика FTS, защита от циклов на бэкенде** — Claude's Discretion
  из `39-CONTEXT.md`, решает planner. Контракт задаёт только то, что видит пользователь.
- **Таймлайн истории перемещений** (Фаза 40), **карточка АРМ** (Фаза 41), **ранжирование
  принтеров** (Фаза 42) — вне фазы. §9 заранее оставляет место пятой вкладке «АРМ», но не
  реализует её.
- **Маршрут `/map`** не трогается (D-19) — он остаётся `Placeholder`, «Места» получают
  собственный маршрут.
- **Ролевой гейт как граница безопасности** — серверный (D-20). Скрытие пункта сайдбара и кнопок
  редактирования, описанное здесь, — только UX-слой, не защита.
- **Изменение вёрстки самих актов** — только подстановка полного пути вместо текста (D-16/D-27);
  типографика печатных форм принадлежит Фазам 34–36 и не переоткрывается.

## 3. Spacing Scale

Шкала Фазы 23 не меняется. Задействованные значения:

| Токен | Значение | Использование в Фазе 39 |
|-------|----------|--------------------------|
| `--tr-space-2xs` | 4px | gap между именем узла и бейджами «Склад»/«Архив»; gap иконки и текста в пункте меню |
| `--tr-space-xs` | 8px | базовый левый отступ строки дерева (уровень 0); gap chevron↔имя; padding строк выпадающей панели `PlacePicker` |
| `--tr-space-sm` | 12px | вертикальный padding тулбаров обеих панелей; gap полей в модалках; padding callout-блоков |
| `--tr-space-md` | 16px | **шаг отступа на уровень вложенности**; горизонтальный padding строк и тулбаров; gap grid-колонок мастер-детали; padding панелей |
| `--tr-space-lg` | 20px | вертикальный padding тела раздела |
| `--tr-space-xl` | 24px | горизонтальный padding тела раздела и шапки (`PageHeader`, унаследовано) |
| `--tr-space-2xl` | 32px | padding пустых состояний (`Table` empty, пустое дерево, пустая правая панель) |

**Формула отступа уровня (единственная новая композиция, не новое значение):**

```
padding-left: calc(var(--tr-space-xs) + var(--depth) * var(--tr-space-md));
```

`--depth` — CSS-переменная строки (0 для корня). 4 уровня вложенности дают 8 + 64 = 72px — при
ширине левой панели ≥320px имя узла остаётся читаемым.

**Исключения (литеральные px, не входящие в spacing-шкалу — все документированы):**

| Величина | Где | Обоснование |
|----------|-----|-------------|
| 32px (`--row-height-dense`) | высота строки дерева и строки панели `PlacePicker` | существующий layout-токен проекта; плотность нужна, чтобы этаж на 20 кабинетов помещался без скролла |
| 36px (`--touch-target-min`) | высота поля `PlacePicker`, поля поиска в тулбаре дерева | совпадает с `Input`/`LocationAutocomplete` — паритет полей форм |
| 28px | триггер `ActionMenu variant="ghost-sm"` в строке узла | принятый в проекте размер inline-действия в строке (quick 260820-rdj) |
| 16×16px | chevron раскрытия, иконка «+» строки создания | размер inline-SVG проекта |
| 320px | `max-height` выпадающей панели `PlacePicker` | у `LocationAutocomplete` было 240px; дерево при 32px-строках показывает 10 строк вместо 7,5 — минимально осмысленное окно для навигации по дереву |
| 320px / 480px | `min-width` левой / правой панели мастер-детали | скопировано дословно из `RequestsMasterDetail.svelte`, не пересчитывается |

## 4. Typography

Шкала Фазы 23 (9 ролей + mono) не меняется. Задействованные роли:

| Роль | Токен | Размер/Вес/LH | Где в Фазе 39 |
|------|-------|----------------|----------------|
| Заголовок H3 | `--tr-text-h3` | 20px/600/1.3 | титул `PageHeader` («Места»), имя выбранного узла в шапке правой панели, титул `Modal` |
| Текст | `--tr-text-body` | 14px/400/1.5 | имя узла в дереве, ячейки таблицы содержимого, строки панели `PlacePicker`, значение в поле `PlacePicker` |
| Текст · акцент | `--tr-text-body-strong` | 14px/600/1.5 | имя **выбранного** узла дерева; последний сегмент (совпавший лист) в режиме поиска `PlacePicker` |
| Подпись | `--tr-text-label` | 13px/500/1.4 | лейблы полей модалок создания/переименования/перемещения, подсказки под полями |
| Мелкий | `--tr-text-caption` | 12px/500/1.35 | тип узла в шапке правой панели, путь-предки (хлебные крошки), `<th>` таблицы содержимого, текст бейджей |
| Моноширинный | `--tr-text-mono` (+ `.tr-mono`) | 13px/500/tabular-nums | **счётчик содержимого на узле дерева**, инвентарный/серийный номер в таблице содержимого, числовой уровень этажа в форме |

**Обязательные применения:**
- Счётчик узла — только `.tr-mono` (`tabular-nums`): столбец чисел справа не должен «плясать».
- Инв. № и серийный № в таблице содержимого — `.tr-mono` (унаследованное правило DS-03).
- Ни одного размера/веса вне таблицы выше. Никаких `font-size: 15px`-подобных литералов.

## 5. Color: 60/30/10

Токены и роли Фазы 23 не меняются.

| Роль | Токен | Использование в Фазе 39 |
|------|-------|--------------------------|
| Доминанта (60%) | `--tr-surface-raised` | обе панели раздела «Места», выпадающая панель `PlacePicker`, тело модалок |
| Доминанта | `--tr-surface` | таблица содержимого внутри панели |
| Вторичная (30%) | `--tr-bg` | фон тела страницы, `thead` таблицы содержимого, фон тулбаров панелей |
| Вторичная (утопленная) | `--tr-surface-sunken` | фон неактивных счётчиков вкладок, поле поиска в тулбаре дерева |
| Границы | `--tr-border` / `--tr-border-strong` | рамки панелей и полей; `--tr-border-strong` — пунктирная зона «В корень дерева» при перетаскивании |
| Текст | `--tr-text-primary` / `-secondary` / `-tertiary` | имя узла / путь-предки и мета / счётчики, плейсхолдеры |
| Акцент (10%) | `--tr-accent`, `-soft`, `-text`, `--tr-focus-ring` | **строго список ниже** |
| Деструктив | `--tr-danger`, `-soft`, `-text` | кнопка «Удалить», error-callout, недопустимая цель перетаскивания |
| Предупреждение | `--tr-warning`, `-soft`, `-text` | callout последствий перемещения («переедет 3 места и 47 устройств») |
| Успех | `--tr-success-text` | только через существующий `Toast kind="success"` |
| Состояния строк | `--tr-row-hover`, `--tr-row-selected` | наведение и выделение в дереве и в таблице содержимого |

**Акцент зарезервирован строго за:**
1. фоном primary-кнопки «Создать место» (`PageHeader`, только Admin);
2. выделенным узлом дерева — фон `--tr-row-selected`, имя `--tr-text-body-strong` цвета `--tr-text-primary`, левая полоса 2px `--tr-accent`;
3. активной вкладкой фильтра содержимого (`Tabs variant="underline"` — унаследованное правило Фазы 28);
4. подсветкой **допустимой** цели перетаскивания — фон `--tr-accent-soft` + `box-shadow: inset 0 0 0 1px var(--tr-accent)`;
5. строкой «Создать «214» в «Здание А / 2 этаж»» в панели `PlacePicker` — текст `--tr-accent-text`;
6. бейджем «Склад» (`Badge variant="accent" appearance="soft" size="sm"`) — редкий, семантически значимый признак (D-08);
7. подсветкой совпавшего фрагмента в режиме поиска `PlacePicker` — цвет `--tr-accent-text` **без фоновой заливки** (заливка конфликтовала бы с `--tr-row-hover` активной строки);
8. focus-ring — глобальный `*:focus-visible` (3px `--tr-focus-ring`), не переопределяется.

**Акцент НЕ используется** для: chevron'ов раскрытия, счётчиков, бейджа «Архив», hover-состояния
строк, границ панелей, иконок действий.

**Запрещено (гейт `check-tokens.mjs`, правила 2 и 4):** любой hex- и `rgba()`-литерал внутри
`<style>` новых компонентов. Полупрозрачности берутся из `*-soft`/`--tr-focus-ring`.

## 7. Раздел «Места»: layout

- **Маршрут:** `/places`. `/map` не трогается (D-19).
- **Сайдбар:** пункт `{ kind: 'item', route: '/places', label: 'Места', roles: ['admin','manager'] }`
  ставится **сразу после «Карта»**, до первого разделителя. PINNED-комментарий в
  `sidebar-config.ts` обновляется: 12 пунктов + 4 разделителя = 16 записей.
- **Шапка:** `PageHeader title="Места"`; в слоте `actions` — `Button variant="primary"`
  «Создать место», **рендерится только для Admin** (D-20; серверная проверка — граница).
- **Тело:** `PlacesMasterDetail` — grid `35% / 65%`, `gap: var(--tr-space-md)`,
  `padding: var(--tr-space-lg) var(--tr-space-xl)`, `flex: 1 1 auto; min-height: 0`.
  Каждая панель скроллится внутри себя — правило App shell (`.content { overflow: hidden }`,
  `*-page { height: 100%; min-height: 0 }`).
- **Узкие окна:** ниже 1099px — `grid-template-columns: 380px 1fr; min-width: 900px`
  (унаследовано; адаптив под мобильные не требуется — раздел админский).
- **Фокальная точка:** первичный визуальный якорь экрана — **выделенный узел дерева**
  (`--tr-row-selected` + 2px accent-полоса слева, §8.2); вторичный — primary-кнопка
  «Создать место» в шапке. Больше ничто на экране не претендует на первый взгляд.
- **Deep link:** выбранный узел отражается в hash (`#/places?id=…`), чтобы кнопка «Показать
  содержимое» из ошибки удаления (D-14) и переходы из карточек вели в конкретный узел.

## 8. Левая панель: дерево

### 8.1 Тулбар дерева

Строка высотой 36px + `padding: var(--tr-space-sm) var(--tr-space-md)`, `border-bottom: 1px solid var(--tr-border)`:
- `Input` поиска, `placeholder="Поиск места"`, ширина 100%;
- `Checkbox` «Показывать архивные» — **по умолчанию выключен** (D-15);
- `Button variant="ghost"` «Обновить» (icon+text, `size="sm"`) — перезагрузка дерева; единственный
  путь повтора после ошибки загрузки (§13), поскольку `Toast` в проекте не имеет слота действия
  (`Toast.svelte` — только `kind` / `message` / `onClose`).

При непустом поиске дерево переключается в **плоский список совпадений по полному пути** (та же
логика, что в `PlacePicker`, §10.3) — два разных представления одного дерева, не два контрола.

### 8.2 Строка узла

```
[chevron 16] [имя] [бейдж «Склад»] [бейдж «Архив»]        [счётчик] [⋯]
```

| Элемент | Контракт |
|---------|----------|
| Высота строки | 32px (`--row-height-dense`) |
| Отступ | `padding-left: calc(var(--tr-space-xs) + var(--depth) * var(--tr-space-md))`; `padding-right: var(--tr-space-md)` |
| Chevron | inline SVG 16×16 на `currentColor`, `aria-hidden="true"` (состояние уже несёт `aria-expanded` на `treeitem` — иначе читается как отдельный безымянный контрол), цвет `--tr-text-tertiary`; повёрнут на 90° у раскрытого узла. **У листа слот сохраняется пустым** (16px), чтобы имена выравнивались по одной вертикали |
| Имя | `--tr-text-body`; у выделенного — `--tr-text-body-strong`; у архивного — цвет `--tr-text-tertiary` |
| Бейджи | `gap: var(--tr-space-2xs)`; «Склад» — `Badge variant="accent" appearance="soft" size="sm"`; «Архив» — `Badge variant="default" appearance="soft" size="sm"` |
| Счётчик (D-25) | справа, `.tr-mono`, цвет `--tr-text-tertiary`; **сумма с учётом вложенных**; `title="Всего с вложенными: 47"`. **Нулевой счётчик не рендерится вовсе** — пустота читается как пусто и не создаёт пары «disabled-текст на фоне», не покрытой контрастным гейтом |
| Меню действий | `ActionMenu variant="ghost-sm"`, только Admin; появляется на `:hover`/`:focus-within` строки и **постоянно виден у выделенной строки** (иначе клавиатурный пользователь его не найдёт). **Обязателен per-row `label={`Действия: ${node.name}`}`** — дефолтный `aria-label="Действия"` (`ActionMenu.svelte:13`) дал бы ~150 одинаковых кнопок для скринридера |
| Тип узла | в строке **не показывается** (шум при ~150 узлах); виден в `title` строки («Здание А / 2 этаж — этаж») и в шапке правой панели |
| Hover | `background: var(--tr-row-hover)` |
| Выделение | `background: var(--tr-row-selected)` + левая полоса `box-shadow: inset 2px 0 0 0 var(--tr-accent)` |

**Порядок братьев (D-05):** ручной `sort_order`, если задан; иначе `level` (для этажей, включая 0
и отрицательные — PLC-02); иначе натуральное сравнение имени («2» перед «10»).

### 8.3 Меню действий узла (Admin)

Пункты, ровно в этом порядке: **Переименовать** · **Создать вложенное место** ·
**Переместить в…** · **Архивировать** (или **Вернуть из архива**) · **Удалить**
(`--tr-danger-text`, отделён `border-top: 1px solid var(--tr-border)`).

Пункт «Удалить» **активен всегда** — счётчик в UI может устареть; отказ приходит с сервера и
показывается по D-14 (§11.5). Manager не видит меню вообще.

### 8.4 Перетаскивание (D-21)

- Перетаскивание доступно **только Admin** и **только как ускоритель** — клавиатурный паритет
  обеспечивается пунктом «Переместить в…» (обязательное требование Фазы 30).
- Перетаскиваемая строка: имя → `--tr-text-tertiary`. Никаких анимаций (конвенция проекта:
  `transition: none` в подобных местах + глобальный `prefers-reduced-motion`).
- **Допустимая цель:** `background: var(--tr-accent-soft)` + `box-shadow: inset 0 0 0 1px var(--tr-accent)`.
- **Недопустимая цель** (сам узел или его потомок): `background: var(--tr-danger-soft)`,
  `cursor: not-allowed`, drop игнорируется.
- **Только «внутрь узла».** Перетаскивание для смены порядка братьев не поддерживается — порядок
  автоматический (D-05), ручной задаётся полем «Порядок» в форме.
- **Перенос в корень (D-03):** только во время перетаскивания в конце списка появляется зона
  высотой 32px с текстом «В корень дерева», `border: 1px dashed var(--tr-border-strong)`,
  `border-radius: var(--tr-radius-sm)`.
- **Drop всегда открывает диалог перемещения** (§11.3) с показом последствий — перетаскивание
  задаёт цель, подтверждение общее для обоих путей. Отмена в диалоге ничего не меняет.

### 8.5 Клавиатура и ARIA

Контейнер — `role="tree"` с `aria-label="Дерево мест"`; узлы — `role="treeitem"` с `aria-level`,
`aria-expanded` (только у узлов с детьми), `aria-selected`; вложенные списки — `role="group"`.
Roving tabindex: в дереве ровно одна точка табуляции.

| Клавиша | Действие |
|---------|----------|
| ↑ / ↓ | предыдущий / следующий **видимый** узел |
| → | раскрыть узел; если раскрыт — перейти к первому потомку |
| ← | свернуть узел; если свёрнут — перейти к родителю |
| Home / End | первый / последний видимый узел |
| Enter | выбрать узел (загрузить содержимое справа) |
| F2 | открыть «Переименовать» (Admin) |
| Escape | очистить поиск в тулбаре, если он активен |

Изменения объявляются в `aria-live="polite"`: «Место «214» перемещено в «Здание А / 3 этаж»»,
«Найдено совпадений: 3».

## 10. PlacePicker — единый контрол выбора места (D-17)

### 10.1 Поле

Визуально идентично `Input`/бывшему `LocationAutocomplete`: высота 36px,
`padding: 0 var(--tr-space-md)`, `background: var(--tr-surface-raised)`,
`border: 1px solid var(--tr-border-strong)`, `border-radius: var(--tr-radius-sm)`,
`--tr-text-body`. Состояния `:focus-visible` / `.invalid` / `:disabled` — дословно как у
`LocationAutocomplete` (`--tr-accent` + `--tr-focus-ring`; `--tr-danger` + `--tr-danger-ring`;
`--tr-surface-sunken` + `--tr-text-tertiary`).

- Выбранное значение показывается **полным путём**: «Здание А / 2 этаж / 214».
- Плейсхолдер: «Выберите место».
- Кнопка очистки «×» справа внутри поля — 28px ghost, `aria-label="Очистить место"`, видна только
  при непустом значении.

### 10.2 Панель — режим дерева (по фокусу)

- Открывается **сразу по фокусу** (унаследованное поведение UAT-fix #3).
- Позиционируется `use:portal` + `use:dropdownAnchor`; корневой класс — **namespaced**
  `.dropdown--place` (урок WR-03: глобальные `.dropdown-item` коллизируют между компонентами).
- `background: var(--tr-surface-raised)`, `border: 1px solid var(--tr-border)`,
  `border-radius: var(--tr-radius-xs)`, `box-shadow: var(--tr-elev-2)`, `max-height: 320px`,
  `overflow-y: auto`.
- Строки — те же 32px, тот же шаг отступа `--tr-space-md`, тот же chevron, что в дереве раздела.
- Раскрыты: корни + вся ветка до текущего значения. Пустое значение — только корни.
- **Архивные узлы не показываются** (D-15); исключение — если архивный узел является текущим
  значением: он показывается с бейджем «Архив» и цветом `--tr-text-tertiary`.
- Выбирать можно **узел любого уровня**, не только лист (D-06). Клик по имени = выбор; клик по
  chevron = раскрытие без выбора.
- Состояние загрузки — строка «Загрузка…» (`Spinner` + `--tr-text-secondary`), как в `Dropdown`.

### 10.3 Панель — режим поиска (при наборе)

- Debounce 200мс; таймер обязательно очищается в `onDestroy` (WR-05).
- Плоский список совпадений по **полному пути**, максимум 50 строк, без отступов уровня.
- Рендер строки: предки — `--tr-text-secondary`, последний сегмент — `--tr-text-body-strong`;
  совпавший фрагмент — `--tr-accent-text` без фоновой заливки.
  Пример: «Здание А / 2 этаж / **214**».
- Escape двухступенчатый: первое нажатие возвращает панель в режим дерева и очищает запрос,
  второе — закрывает панель.

### 10.4 Создание из панели (D-18, только Admin)

Когда совпадений нет, **последней строкой** панели (над ней `border-top: 1px solid var(--tr-border)`):

```
[+] Создать «214» в «Здание А / 2 этаж»
```

`--tr-text-body`, цвет `--tr-accent-text`, иконка «+» 16×16. Родитель — узел, выделенный в панели;
если ничего не выделено — корень, и текст читается «Создать «214» в корне дерева».
Для Manager этой строки нет — вместо неё пустое состояние (§14).

### 10.5 Клавиатура и ARIA

`role="combobox"` + `aria-expanded` + `aria-controls` на поле; панель — `role="tree"`;
`aria-activedescendant` указывает на активную строку. ↑/↓ — по видимым строкам, →/← —
раскрыть/свернуть (только в режиме дерева), Enter — выбрать, Tab — выбрать активную и закрыть,
Escape — по §10.3. Число найденных совпадений объявляется в `aria-live="polite"`.

### 11.1 Создание / переименование места

Титул: «Новое место» / «Переименовать место».

|------|---------|---------|
| Название | `Input` | обязательное; автофокус |

### 11.2 Ошибка уникальности (D-04)

Инлайн под полем «Название», `--tr-danger-text`, поле в состоянии `.invalid`:
«В «Здание А / 2 этаж» уже есть место «214». Укажите другое имя.»

### 11.3 Перемещение узла

Титул: «Переместить место». Тело: `PlacePicker` с лейблом «Новое родительское место», под ним —
warning-callout последствий (D-21):

```
background: var(--tr-warning-soft);
border-left: 3px solid var(--tr-warning);
border-radius: var(--tr-radius-sm);
padding: var(--tr-space-sm) var(--tr-space-md);
color: var(--tr-warning-text);
font: var(--tr-text-body);
```

Текст: «Вместе с местом переедет 3 вложенных места и 47 устройств.»
Единственное число согласуется («1 вложенное место и 1 устройство»); нулевые части опускаются
(«Вместе с местом переедет 47 устройств.»); при полностью пустом узле callout не показывается.

Ошибка цикла (инлайн, `--tr-danger-text`): «Нельзя переместить место внутрь самого себя или
своего вложенного места.»

Кнопки: «Переместить» (primary) / «Отмена».

### 11.4 Архивация / возврат из архива (D-15)

Титул «Архивировать место?». Тело: «Место «214» скроется из выбора при заполнении форм, но
останется в дереве, в карточках, в истории и в уже выписанных актах.»
Кнопки: «Архивировать» (primary) / «Отмена».

Возврат: титул «Вернуть из архива?», тело «Место «214» снова появится в списках выбора.»,
кнопки «Вернуть» / «Отмена».

### 11.5 Удаление (D-14)

Титул «Удалить место?». Тело: «Место «214» будет удалено безвозвратно.»
Кнопки: «Удалить» (`Button variant="destructive"`) / «Отмена».

**Если сервер отказал** (узел не пуст) — тело модалки заменяется error-callout (та же геометрия,
что у warning, но `--tr-danger-soft` / `--tr-danger` / `--tr-danger-text`):

> Место нельзя удалить: в нём 12 устройств и 2 вложенных места. Перенесите содержимое или
> архивируйте место.

Под callout — две кнопки: «Показать содержимое» (`variant="ghost"` — выделяет узел в дереве,
включает показ вложенных и закрывает модалку) и «Архивировать» (переводит в §11.4). Кнопка
«Удалить» в этом состоянии скрывается. Никакого каскада и никакого автоподъёма содержимого.

## 12. Место в остальном приложении

- **Единый термин.** Во всём UI поле и колонка называются **«Место»**. Прежние варианты
  «Расположение» и «Размещение» удаляются из лейблов, плейсхолдеров, заголовков колонок,
  фильтров, CSV-заголовков импорта и текстов ошибок. Один термин — одно понятие.
- **В таблицах (D-26):** два последних сегмента пути («2 этаж / 214»), полный путь — в `title`
  ячейки и в карточке сущности. Ячейка — `--tr-text-body`, обрезка `text-overflow: ellipsis`.
- **Пустое место:** «—» цвета `--tr-text-tertiary` (`place_id` необязателен, D-07).
- **В карточках сущностей** (`DetailField`): полный путь целиком, без сокращения.
- **В фильтрах списков и отчётов (D-28):** `PlacePicker` вместо текстового автокомплита.
  Поведение фильтра всегда включает вложенные места — субдерево фиксировано и никогда не
  меняется, поэтому визуальная подсказка об этом избыточна. *UAT-правка (Прогон 1, GAP-3,
  2026-08-25):* исходно здесь была предписана подсказка `--tr-text-label`,
  `--tr-text-secondary`: «Включая вложенные места» под полем; пользователь на живом прогоне
  счёл её лишней и попросил убрать — сама фильтрация вложенных мест НЕ меняется, убран только
  текст подсказки (`ReportFilters.svelte`).
- **В формах операций картриджа (D-13):** `PlacePicker` в Install / Возврат на склад / В заправку /
  Из заправки / Списание, с предзаполнением (Install → место принтера, Возврат на склад →
  складское место). Поле не выносится в отдельный шаг.
- **Складское предложение статуса (D-11.3):** когда выбранное место складское, в форме появляется
  `Checkbox` «Перевести устройство в статус «На складе»», **включённый по умолчанию**;
  пользователь может снять. Принудительной смены статуса нет.
- **В печатных формах (D-27):** полный путь, снимок на момент выписки (D-16). Переименование узла
  **не меняет** уже выписанный документ. Типографика акта — Фазы 34–36, здесь не трогается.
- **CSV-импорт устройств:** колонка размещения разрешается по полному пути («Здание А / 2 этаж /
  214»); нераспознанное значение попадает в отчёт об ошибках импорта строкой: «Строка 12: место
  «Здание А / 2 этаж / 214» не найдено в дереве.»

| Поиск в дереве без результата | Ничего не найдено | Проверьте написание или очистите поиск. |
| `PlacePicker`, нет совпадений (Manager) | — | Ничего не найдено. Уточните запрос или обратитесь к администратору, чтобы добавить место. |
| `PlacePicker`, нет совпадений (Admin) | — | Строка действия: **Создать «214» в «Здание А / 2 этаж»** |

## 15. Accessibility Contract (Фаза 30, паритет обязателен)

- **Клавиатурный паритет с мышью:** любое действие, доступное перетаскиванием, доступно из
  `ActionMenu` («Переместить в…»). Drag-n-drop — только ускоритель (D-21).
- **Дерево:** `role="tree"`/`treeitem`/`group`, `aria-level`, `aria-expanded`, `aria-selected`,
  roving tabindex (одна точка табуляции на всё дерево). Клавиатурная карта — §8.5.
- **PlacePicker:** `role="combobox"` + `aria-expanded`/`aria-controls`/`aria-activedescendant`;
  панель `role="tree"`; двухступенчатый Escape.
- **`aria-live="polite"`** для результатов перемещения, архивации, удаления и числа найденных
  совпадений.
- **Focus ring** — только глобальный `*:focus-visible` (3px `--tr-focus-ring`); переопределять и
  гасить `outline` без замены запрещено (гейт `check-focus-outline.mjs`).
- **Контраст** — только пары токенов Фазы 23; `--tr-text-tertiary` допускается лишь для
  мета/счётчиков/плейсхолдеров (документированное исключение 3.0:1). Новых цветовых пар фаза не
  вводит.
- **Reduced motion** — раскрытие узлов и появление панели без анимаций; глобальный блок
  `prefers-reduced-motion` не переопределяется.
- **Паритет Tauri ↔ LAN-браузер:** раздел «Места» и `PlacePicker` проверяются в обоих окружениях
  (WKWebView/WebView2 и браузер). Напоминание: LAN-браузер отдаёт `ui/dist` — после правок фронта
  нужен `pnpm --dir ui build`, иначе проверяется старая сборка.

## 17. Решения researcher'а (Claude's Discretion)

Пользователь эти вопросы не решал; зафиксированы здесь, чтобы planner и executor не изобретали
заново:

1. **Тип узла не выводится в строке дерева** — только в `title` и в шапке правой панели. Причина:
   ~150 узлов × текстовая метка типа = удвоение визуального веса; иерархия и так читается.
2. **Нулевой счётчик не рендерится** — вместо серого «0». Причина: отсутствие числа читается как
   пусто и не создаёт цветовую пару вне контрастного гейта.
3. **Перетаскивание переносит только «внутрь узла»**, порядок братьев им не меняется — порядок
   автоматический по D-05, ручной задаётся полем «Порядок».
4. **Drop открывает тот же диалог подтверждения**, что и «Переместить в…» — один путь показа
   последствий, никакого «тихого» перемещения 47 устройств одним движением мыши.
5. **`PlacePicker` не строится на `Dropdown.svelte`** — тот поддерживает ровно два уровня; берём
   его визуальный язык и клавиатурный контракт, панель пишем свою (§6.2).
6. **Единый термин «Место»** вместо «Расположение»/«Размещение» во всём UI (§12) — требует правки
   лейблов за пределами новых экранов; вынести отдельной задачей плана.
7. **Фильтр содержимого — `Tabs variant="underline"` со счётчиками**, а не самодельные чипы:
   D-23 просит «фильтр-чипами», но в проекте эту роль уже играют underline-табы (Заявки, Отчёты);
   счётчиков у `variant="segmented"` нет.
8. **Ширина панелей 35% / 65%** — дословно из `RequestsMasterDetail.svelte`, новых значений нет.
