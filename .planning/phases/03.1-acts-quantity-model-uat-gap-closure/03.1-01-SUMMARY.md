# Plan 03.1-01: Clone-on-Handover Backend Summary

**G-12 архитектурный shift: handover qty>1 → N независимых device-rows + N act_items; G-7 display-rule и G-11 recompute_parent_archived работают на COUNT distinct device_id вместо SUM(quantity).**

- **Duration:** ~2 часа (с учётом resume после session limit)

- **Completed:** 2026-05-31 (Task 4 commit e1f6661)
- **Tasks:** 4 из 5 (Task 5 manual smoke deferred)
- **Files modified:** 7 (включая regenerated ui/src/bindings.ts)
- **Tests added:** 11 integration tests + 2 переписанных тестов

## Accomplishments

- **V015 schema migration** применяется чисто (idempotent через refinery version table; unconditional data-migration step но structurally no-op для PRE-V015 БД без qty>1 act_items).
- **clone_device_in_tx** в SqliteDeviceRepository: INSERT … SELECT с inv_number/serial_number = NULL (W-5); audit-log `custom:device_clone_for_handover` per clone (T-03.1-04 repudiation).
- **ActService::create** теперь поддерживает qty>1 — клонирует N-1 device-rows + создаёт N act_items с parent_act_item_id provenance; каждый device проходит через индивидуальный status update + audit (undo path работает per-device).
- **ActService::validate_return + do_return** переведены на canonical `device_ids[]` с прозрачным legacy fallback на `[device_id]` — все 12 prior acts_returns тестов остались зелёными.
- **outstanding_device_ids** заполняется в `get(act_id)` через SQL `SELECT … EXCEPT` (B-1 compliant — soft-delete только на acts через JOIN, не на act_items).
- **MAX_CLONE_QTY=1000 bound** в validate_create защищает от DoS-style payloads (T-03.1-02).
- **11 integration tests** в acts_clone_handover.rs покрывают: clone count, partial/full return, «в»→«в1»/«в2» display rule, outstanding_device_ids correctness, foreign device_id rejection, max-qty bound, W-5 serial NULL, undo-cycle restoration.
