<objective>
Реализовать **G-12 архитектурный shift «clone-on-handover»** — при handover с `quantity > 1` бэкенд клонирует N независимых device-rows + создаёт N независимых `act_items`, по одному device_id на строку. Закрывает G-7 (display-rule на новой модели) и G-11 (recompute_parent_archived по count distinct device_id). Это backend-only план — wave 1, foundational; все UI-планы (02–04, 06) зависят от его DTO-формы и backend-семантики.

Purpose: Текущая модель «1 act_item с quantity=N» несовместима с «devices.status_id это per-row» — partial return не работает (UAT.md G-11/G-12). Переход на N device-rows + N act_items решает проблему универсально и упрощает UI (чекбокс per device, без quantity-counting).

Output:
- V015 schema migration (consolidated: handover_date_utc + parent_act_item_id для clone provenance + data-migration существующих qty>1 act_items).
- ActService::create: при `quantity > 1` клонирует source device через `SqliteDeviceRepository::clone_device_in_tx`, создаёт N act_items (1 на каждый device_id).
- ActService::do_return / validate_return: работает на `Vec<i64>` device_ids per item (старый `quantity` ignored as derived).
- ActService::get + load_items: возвращает `outstanding_device_ids` per ActItemDto.
- recompute_parent_archived: count distinct device_id вместо SUM(quantity).
- format_act_number: остаётся, но source-of-truth — count distinct returned device_id.
- Integration tests (3+ cases) в `acts_clone_handover.rs`.
- Existing tests `acts_returns.rs`, `acts_display_rule.rs`, `acts_undo.rs` обновлены под новый ActReturnItemDto shape.
- Updated `bindings.ts` (через `cargo test --test export_bindings`) + `ui/src/lib/api/acts.ts` types resync.

**Autonomous:** false — checkpoint:human-verify ПЕРЕД применением V015 на dev DB (data-migration risk).

**Schema note (B-1 / V004):** `act_items` НЕ имеет колонки `deleted_at_utc` (только `id, act_id, device_id, condition_at_time, complectation_at_time, quantity`). Soft-delete живёт ТОЛЬКО на `acts` — при `acts.deleted_at_utc IS NOT NULL` все его `act_items` rows CASCADE-DELETED. Всё SQL в этом плане использует **только** `acts.deleted_at_utc IS NULL` через JOIN; никогда `ai.deleted_at_utc IS NULL` или `rai.deleted_at_utc IS NULL`.
