## Implementation Decisions

### G-12 (CORE ARCHITECTURAL DECISION): clone-on-handover quantity model

**Решение:** Вариант **B** — при handover с qty > 1 в act_item, backend **клонирует** соответствующее количество independent device rows.

#### Mechanics
- При `ActService::create` — для каждого `payload.items[i]` с `quantity = N`:
  - Если `N == 1`: использовать существующий device_id напрямую (как сейчас).
  - Если `N > 1`: внутри одной writer-tx — `SELECT * FROM devices WHERE id = source_device_id` → клонировать N-1 rows (новые id, same name/inv_pattern/condition/location/status и т.д. кроме нового inv_number если пользователь хочет distinguishable). После клонирования source device + N-1 clones = N rows, все статусом «в работе», все в новом handover act_item.
  - `act_items.quantity` сохраняется как denormalized count, **но canonical source — count(distinct device_id) per act_item**.
- Альтернатива внутри решения: не клонировать device row, а **создать N независимых rows в act_items** (один act_item per device). Это упрощает return UX (галочка per item, без quantity counting), но размывает понятие «позиция акта» для документа. **Outcome:** оставить N device rows + 1 act_item с denormalized count. Detail to be finalized by researcher/planner.

#### Inv.№ generation для clones
- Для clone device row inv_number должен быть либо:
  - **(a)** auto-generated (например `{source_inv}-{idx}`: `BL-001` → `BL-001-1`, `BL-001-2`, ...) с возможностью пользовательского override до коммита.
  - **(b)** NULL (для расходников inv.№ часто отсутствует) — `devices.inv_number TEXT NULL` уже допускает.
- **Решение:** (b) — для clones inv_number = NULL по умолчанию; если у source inv_number есть, для каждого clone UI генерирует suggestion `{base}-{idx}` но позволяет редактировать ДО подтверждения handover. Planner финализирует.

#### Return model
- `ReturnItemDto` теперь содержит `device_ids: Vec<i64>` (а не `device_id + quantity`). Frontend ReturnModal показывает per-handover-item чекбоксы для каждого выданного device_id.
- `validate_return` дедуп остаётся (CR-03 HashSet), но теперь по `device_id` без quantity-проверки (count check вместо SUM check).
- CR-04 quantity bound → становится cardinality check: `requested_device_ids ⊆ outstanding_device_ids_for_(parent_act, act_item)`.

#### recompute_parent_archived
- Новый SQL:
  ```sql
  -- handover_device_count = total devices in handover act
  SELECT COUNT(*) FROM act_items_devices WHERE act_id = ?
  -- returned_device_count = total devices returned across all return acts
  SELECT COUNT(DISTINCT raid.device_id) FROM act_items_devices raid
  JOIN acts ra ON ra.id = raid.act_id
  WHERE ra.parent_act_id = ? AND ra.deleted_at_utc IS NULL
  -- archived = (handover_count == returned_count)
  ```
  (Имена таблиц — пример; реальная схема может остаться `act_items` с FK на device_id если 1 act_item = 1 device row.)

#### Display rule
- partial vs full = `returned_device_count < handover_device_count` → «42в1»/«42в2» (partial); `returned_device_count == handover_device_count` AND это **единственный** return → «42в»; else «42в{N}».
- Существующая `format_act_number` остаётся, но переходит на новые counters.

#### Migration V015 (new)
- При наличии acts со старыми `act_items.quantity > 1` (которых, скорее всего, ещё нет в проде, т.к. UAT обнаружил bug сразу), V015 либо:
  - **(a)** clone existing act_items с qty>1 в N independent rows (data migration);
  - **(b)** drop quantity column как deprecated (если решено не сохранять);
  - **(c)** оставить quantity как hint/denorm, добавить computed view с counts.
- **Решение:** (a) data migration + (c) сохранение quantity как denorm для отчётности и backward-compat. V015 SQL writes by planner.

### G-6: ReturnModal per-row override UX

**Решение:** при `apply_to_all = false` — **и `condition`, и `location` разблокированы per-row** в `ReturnItemsTable`. Bulk-поля сверху модала блокируются. Симметрично, без inconsistency.

### G-5: People autocomplete source (текущая фаза)

**Решение:** Новый tauri command `acts.suggest_person(field: "giver" | "receiver", prefix: &str) -> Vec<String>`.

#### Backend
- `ActService::suggest_person(field, prefix, limit=20)`:
  ```sql
  SELECT giver_name AS name, COUNT(*) AS freq
  FROM acts
  WHERE giver_name LIKE ?1 || '%' ESCAPE '\'
    AND deleted_at_utc IS NULL
  GROUP BY giver_name
  ORDER BY freq DESC, giver_name ASC
  LIMIT ?2
  ```
  (Тот же query для `receiver_name` через match field; field валидируется enum на DTO уровне.)
- LIKE escape через ту же `escape_like(s)` helper из `acts_search` (Phase 3-05).
- HTTP endpoint: `POST /api/v1/acts_suggest_person` (axum router, не bind'нется в Phase 3.1 — для server-mode Phase 8).

#### Frontend
- Новый shared component `ui/src/lib/components/PersonAutocomplete.svelte`:
  - Props: `field: "giver" | "receiver"`, `value: string`, `placeholder?: string`, `onSelect?: (v: string) => void`.
  - Внутри: дебаунс 200ms → `acts.suggestPerson` → dropdown.
- Интегрировать в `DocumentAcceptanceModal` (Кто передал / Кто принял), `ActFormModal` (Кто сдал / Кто принял), `ReturnModal` (Кто возвращает / Кто принимает).
- В **ReturnModal** дополнительно: default values — **swap** из parent handover (giver→receiver, receiver→giver). Editable.

#### Future (Phase 5)
- В Phase 5 (AD/Auth) расширить SQL до UNION с AD displayName: `SELECT name FROM (acts UNION ad_users) ...`. PersonAutocomplete signature не меняется — только источник за `acts.suggestPerson` расширяется.

### G-1: Modal backdrop-dismiss discipline

**Решение:** разделить `mousedown`/`mouseup` на backdrop. Закрытие модала срабатывает только если ОБА события произошли на backdrop element (не если mousedown был в модале и mouseup ушёл на backdrop из-за text-selection drag).

#### Pattern (Svelte 5)
```svelte
<div class="backdrop"
  on:mousedown={(e) => mouseDownOnBackdrop = (e.target === e.currentTarget)}
  on:mouseup={(e) => {
    if (mouseDownOnBackdrop && e.target === e.currentTarget) onClose();
    mouseDownOnBackdrop = false;
  }}>
```

#### Альтернатива
Слушать `click` (composite of mousedown+mouseup at same target) вместо отдельных событий — но Svelte click не fires if mousedown в одном элементе, mouseup в другом → нужный invariant получается «бесплатно». Принять решение — planner.

### G-8a: PDF column overflow

**Решение:** в `pdf/renderer.rs::render_table_section` (или эквивалент) — заменить «pixel-absolute draw text at x,y» паттерн на column-aware layout:

#### Подход
1. Compute column widths из расчёта `available_width / N_columns` с возможностью override через DocSpec hints `column_weights: Vec<f32>`.
2. Per cell: `truncate_text_to_width(text, font, font_size, cell_width)` — возвращает text + boolean is_truncated.
3. Если truncated → добавить ellipsis `…` в конце.
4. Альтернатива (advanced): word-wrap на пробелах, увеличение row height на N lines. **Решение:** ellipsis в Phase 3.1 (proven и простой); word-wrap отложен.

#### Integration test
- `tests/pdf_column_overflow.rs` — fixture с одним очень длинным name в одной cell → assert renders без visual overlap. Возможно через текстовый extract проверить что соседняя cell не содержит фрагменты длинного name.

### G-8b: PdfPreviewModal save / print / open actions

**Решение:** 3 кнопки в footer PdfPreviewModal'а:

#### «Сохранить как…»
- `tauri-plugin-dialog::save({ defaultPath: filename, filters: [{name:"PDF", extensions:["pdf"]}] })` → fs::writeBinaryFile.

#### «Печать»
- Path A: `tauri-plugin-shell::open(temp_pdf_path)` → системный PDF viewer берёт на себя печать.
- Path B: `window.print()` на iframe — webview-native. Может не работать на WebView2 без extra setup.
- **Решение:** Path A (`tauri-plugin-shell::open`). Path B как fallback если open недоступен.

#### «Открыть в системе»
- `tauri-plugin-shell::open(temp_pdf_path)` — то же что Path A для Печати. Кнопка дублирует, но семантически разная (user намерение).

#### Filename pattern
- Handover: `Акт_приёма-передачи_№{number}_{handover_date}.pdf`
- Return: `Возврат_к_акту_№{parent_number}_{return_date}.pdf`
- Acceptance (DEV-14): `Документ_приёма_{inv_number}_{date}.pdf`
- Запрещённые символы (`/`, `\`, `:`, etc.) escape'аются в `_`.

#### Tauri capabilities
- `tauri-plugin-dialog` уже добавлен (Phase 1). Capability `dialog:default` permissions check.
- `tauri-plugin-shell` — нужно добавить если ещё не подключён, с capability `shell:allow-open` ограниченным на `.pdf` файлы в temp dir (security).

### G-9: Logo aspect-ratio correctness

**Решение:** Расширить `draw_logo_top_right` в `pdf/renderer.rs`:

#### Algorithm
```rust
fn draw_logo_top_right(surface: &mut Surface, logo_bytes: &[u8], mime: &str, …) {
    let (orig_w, orig_h) = match mime {
        "image/png" => parse_png_dimensions(logo_bytes)?,
        "image/jpeg" => parse_jpeg_dimensions(logo_bytes)?,
        _ => return,
    };
    let max_w = 80.0;
    let max_h = 40.0;
    let scale = (max_w / orig_w as f32).min(max_h / orig_h as f32);
    let final_w = orig_w as f32 * scale;
    let final_h = orig_h as f32 * scale;
    // … push_transform + draw_image(image, Size::from_wh(final_w, final_h)) + pop
}
```

#### PNG IHDR dimensions
- Bytes 16..24: width (4 bytes big-endian), height (4 bytes big-endian). Простой parser ~10 строк.

#### JPEG SOF dimensions
- Поиск marker `0xFFC0..0xFFCF` (SOF segments), читать height (2 bytes), width (2 bytes) из payload. Минимальный parser ~20 строк ИЛИ использовать crate `image::ImageReader::new(Cursor::new(bytes)).with_guessed_format()?.into_dimensions()?` — добавляет ~500 KB к binary но даёт robust парсинг для других форматов.
- **Решение:** добавить crate `image = { version = "0.25", default-features = false, features = ["png", "jpeg"] }` — только нужные формат-features → ~200 KB. Простота важнее. Planner финализирует.

#### Unit test
- `tests/pdf_logo_aspect.rs`: фикстура 200×100 PNG → assert final size width=80 (constrained), height=40. Фикстура 100×200 PNG → height=40, width=20.
