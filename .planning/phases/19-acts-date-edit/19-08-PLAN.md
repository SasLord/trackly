<objective>
Close WR-02 (edit-mode group/quantity picker silently drops N-1 devices) and IN-01 (todayISO uses local calendar accessors while the rest of the date pipeline uses UTC).

- WR-02: In edit mode the items table renders the same group/quantity picker as create mode, but `ActUpdateItemDto` carries only `{device_id, complectation_at_time}` and the edit submit maps each row to one device_id (ActFormBody.svelte:150-155). A user who picks a group ×5 / sets quantity 5 silently adds ONE device with no error.
- IN-01: `todayISO()` uses `getFullYear/getMonth/getDate` while `unixToIso()`/`isoToUnix()` use UTC — a day-boundary off-by-one risk and an inconsistent convention.

Purpose: make edit-mode saves faithful (visible quantity == persisted devices) and unify the date TZ convention.
Output: mode-gated single-device added rows + a UTC `todayISO()`.
</objective>
