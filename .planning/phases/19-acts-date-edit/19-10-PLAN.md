<objective>
Close Gap 2 (D-11) and Gap 3 (D-12 + D-13) — both frontend-only, in two independent files.

- **D-11 (ActsPage.svelte):** After an edit is saved the detail card stays stale. Root cause: `handleEditSaved(act)` sets `selectedActId = act.id`, which is a no-op when the edited act is already selected → the detail `$effect` (keyed on `selectedActId`) does not refetch. Fix: mirror `handleReturnSuccess` — assign `selectedAct = act` directly (the `acts.update()` response is a full `ActDto` via `self.get`, with items + outstanding_device_ids).
- **D-12 + D-13 (ActDetail.svelte):** Replace the disabled placeholder buttons with omission. Render «Редактировать» ONLY when `onEdit && act.act_type === 'handover' && !act.archived`; render «Возврат» ONLY when `onReturn && act.act_type === 'handover' && !act.archived`; otherwise render nothing (no disabled span). «Печать» and «Удалить» unchanged (always rendered).

Purpose: live UAT showed stale detail after edit, and unwanted disabled Редактировать/Возврат buttons on returns and archived acts.
Output: edited `ActsPage.svelte` and `ActDetail.svelte`.

Out of scope (do NOT plan): return-act editing (making Редактировать active on returns / reopening the return dialog / backend) — deferred to a future phase per D-13/Deferred. This round only OMITS the buttons.
</objective>
