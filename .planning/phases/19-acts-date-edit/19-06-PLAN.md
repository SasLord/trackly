<objective>
Close CR-01 (BLOCKER): `ActService::update` mutates the act's device set (add → в_работе, remove → restore) but never recomputes the derived `acts.archived` flag, unlike every sibling mutation (`do_return`, `delete_soft`). This silently corrupts `archived` in two UI-reachable scenarios (archived act + add device strands a device в_работе with no return path; removing the last outstanding device leaves the act falsely active).

Purpose: make saved edits leave `archived` consistent with the true outstanding-device count — the "работает надёжно" contract this phase exists to deliver.
Output: gated `recompute_parent_archived` call inside `update()`'s transaction + two `archived`-asserting regression tests (the first `archived` assertions in the suite — current grep = 0 matches).
</objective>
