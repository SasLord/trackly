<objective>
Close WR-01 and WR-03, the two remaining data-integrity/audit warnings on the edit path.

- WR-01: `update_act_header_in_tx` renames only `WHERE id = ?`; return acts store a COPY of the parent `number`. After a rename, the return rows keep the old number, and the number-uniqueness check (`SELECT EXISTS ... WHERE number=?1`) counts those orphans → the old number is permanently unreusable (silent leak).
- WR-03: step 7 overwrites a retained row's `act_items.complectation_at_time` with a bare UPDATE and writes NO audit row; the act-level audit (step 10) diffs only header fields, so комплектация edits are untraceable.

Purpose: keep act numbers reusable after rename and make комплектация edits auditable — closing "изменения сохраняются без ошибок" for the remaining edit paths.
Output: a same-tx number cascade + a conditional audit row for комплектация changes, each with a regression test.
</objective>
