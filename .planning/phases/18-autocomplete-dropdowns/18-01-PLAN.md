<objective>
Переписать backend-контракт `list_grouped()` для группы устройств `group_by_condition=true`
(единственный вызывающий — пикер устройства в форме акта): ключ группировки становится
`(type_id, name, model)` вместо `(type_id, name, condition)` (D-05), сортировка — по остатку
(`count DESC`) вместо алфавита (D-04), и добавляется реальный текстовый фильтр по
наименованию + инвентарному № + серийному № через переиспользование существующего FTS5
sanitizer'а (`build_fts_query`) вместо мёртвого поля `name_prefix` (AUTO-03). Ветка
`group_by_condition=false` (страница Устройства) остаётся полностью нетронутой.

Purpose: сейчас `name_prefix` парсится, но никогда не участвует в SQL `list_grouped` —
фильтрация в пикере устройства фактически не работает (AUTO-03 регресс). Группировка по
condition вместо model означает, что одинаковые устройства с разными моделями сегодня
неверно объединяются/разделяются относительно D-05. Это фаза "backend contract" — без неё
фронтенд-пикер (Plan 18-04/18-05) не может отобразить корректные группы.

Output: `list_grouped()` с новой семантикой true-ветки; обновлённые док-комментарии на
`DeviceFilter`/`DeviceGroupRow`; регрессионные + новые тесты в `devices_grouping.rs`.
</objective>
