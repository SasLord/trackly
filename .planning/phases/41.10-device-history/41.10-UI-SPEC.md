# Phase 41.10 — UI Design Contract

> Визуальный и интеракционный контракт фазы «История» вместо «Истории перемещений»: единая
> лента событий устройства (перемещения, состав, статус) с чипами-фильтрами, лента группы с
> составом, переключатель истории в шапке попапа просмотра — вторая колонка на широком экране
> и панель на узком.
> Составлен gsd-ui-researcher, проверяется gsd-ui-checker.
>
> **Макета нет.** Дизайн-система — Фаза 23 (`ui/src/styles/_tokens.scss`, гейт
> `check-tokens.mjs`), примитивы — Фазы 24–25, анатомия строки ленты — Фаза 40
> (`MovementTimeline.svelte`), структура документа — `41.8-UI-SPEC.md`. Контракт **не
> переоткрывает** решения `41.10-CONTEXT.md` (D-01…D-23), он их дополняет. Всё, что здесь не
> названо, остаётся как есть.
> Новых npm-зависимостей — **ноль**. Новый токен — **один** (`--modal-max-width-split`, §5.2).
> Новый размер `Modal` — **один** (`split`, §8.1). Новый слот `Modal` — **один**
> (`headerActions`, §8.1).
>
> **Приватность (жёсткое условие, репозиторий публичный):** все примеры вымышлены: «АРМ-3»,
> «АРМ-5», «Системный блок #4», «Монитор #2», «Разбор #7», «Склад», «Каб. 12», «Каб. 14»,
> «Иванов И.И.», «Петров П.П.»; номера актов и заявок — «№N» или условные «№123», «№17».

## 1. Характер фазы

Новых разделов и экранов нет. Фаза меняет одну общую ленту и её четыре потребителя, плюс
шапку общего `Modal`.

| # | Поверхность | Решения | Раздел |
|---|-------------|---------|--------|
| 1 | Строка ленты: значок вида, тексты событий состава и статуса, комбинированная строка | D-04, D-05, D-07, D-20, D-23 | §7 |
| 2 | Чипы-фильтры над лентой | D-21 | §6 |
| 3 | Пустые состояния, сноски, ошибка ленты | D-03, D-13, D-22 | §11.2, §11.3 |
| 4 | Попап просмотра (`PlaceEntityViewModal`): кнопка-переключатель, две колонки, панель на узком экране, флаг в `localStorage` | D-14…D-19 | §8 |
| 5 | Общий `Modal`: слот `headerActions`, размер `split` | D-15, D-16 | §8.1 |
| 6 | Лента группы (`GroupPanel`, вкладка «История») | D-09, D-11 | §9 |
| 7 | Боковые панели `PrinterDetail` и `CartridgeDetail`: переименование секций | D-10, D-12, D-13 | §10 |
| 8 | Витрина `MovementTimelineSection` | — | §12 |

**Фокальная точка фазы** — строка ленты. Пользователь читает судьбу устройства сверху вниз
(новые сверху, D-22) и по ссылкам уходит к акту, заявке, группе или месту. Новых primary-кнопок
фаза **не вводит**: переключатель — ghost-иконка, чипы — тумблеры.

## 2. Границы: что контракт НЕ покрывает

- **Отчёт «Перемещения» (HST-04)** — не меняется ни видом, ни данными (HST-07).
- **Схема таблицы событий, имена видов в Rust-enum, форма DTO склеенной ленты, индексы** —
  Claude's Discretion планировщика (D-01, D-02). Контракт задаёт только видимое пользователю и
  **требования к данным** (§7.6), без которых строку нельзя собрать без склейки на клиенте.
- **Новые события картриджа** — вне фазы (D-12). Картридж получает только заголовок «История».
- **Переключатель-колонка в боковых панелях «Принтеры» и «Картриджи»** — отклонён (D-13).
- **Запоминание чипов** — не делается (D-21).
- **Блок «Ремонты (N)» и `RepairDeviceHistoryModal`** (`historyOpen`/`historyToken`/
  `visitCount` в `PlaceEntityViewModal`) — другой блок, не трогается (D-19).
- **«Журнал операций» картриджа** — остаётся отдельной секцией, меняется только текст его
  пустого состояния (§10.2, R-07).

## 5. Color

### 5.1 60/30/10

Токены и роли Фазы 23 не меняются. Светлая тема — дефолт, тёмная — `[data-theme='dark']`.

| Роль | Токен | Использование в Фазе 41.10 |
|------|-------|----------------------------|
| Доминанта (60%) | `--tr-surface` | тело попапа и обе его колонки; фон ненажатого чипа (прозрачный поверх surface) |
| Вторичная (30%) | `--tr-bg`, `--tr-surface-sunken` | фон боковых панелей и страницы (унаследовано); hover кнопки-переключателя и ненажатого чипа — `--tr-surface-sunken` |
| Границы | `--tr-border` / `--tr-border-strong` | разделитель колонок и строк ленты — `--tr-border`; рамка ненажатого чипа — `--tr-border-strong` |
| Текст | `--tr-text-primary` / `-secondary` / `-tertiary` | текст события, автор, основание / значок вида, разделители «—», «·», «→», подпись ненажатого чипа / пустые состояния и сноски |
| Акцент (10%) | `--tr-accent`, `-soft`, `-text`, `--tr-focus-ring` | **строго список ниже** |
| Деструктив | `--tr-danger-text` | только текст ошибки загрузки ленты (унаследовано из `.timeline-error`) |

**Акцент зарезервирован строго за:**
1. ссылками в строке ленты — место, акт, заявка, группа, устройство (`.timeline-link`,
   `--tr-accent-text`, унаследовано);
2. нажатым чипом-фильтром: фон `--tr-accent-soft`, рамка 1px `--tr-accent`, текст и галочка
   `--tr-accent-text` (§6.2);
3. нажатой кнопкой-переключателем истории: фон `--tr-accent-soft`, иконка `--tr-accent-text`
   (§8.2);
4. focus-ring — `box-shadow: 0 0 0 3px var(--tr-focus-ring)` у переключателя, чипов и ссылок
   (унаследовано).

Акцент **не** используется: для значков вида события (они `--tr-text-secondary`), для
названий статусов «было → стало» (обычный текст), для заголовка «История», для разделителя
колонок, для сносок.

**Контраст (расчёт исследователя, sRGB source-over):** `--tr-accent-text` на композите
`--tr-accent-soft` поверх `--tr-surface` — светлая 5.9:1, тёмная 6.4:1 (порог 4.5:1);
`--tr-text-secondary` на `--tr-surface` — светлая 6.3:1. Новых правил `check-contrast.mjs` фаза
не вводит. Если в R1 гейта нет пары «`--tr-accent-text` на композите `--tr-accent-soft`» —
добавить её ячейкой в R1 (обе темы, порог 4.5:1), а не новым правилом.

## 6. Чипы-фильтры по видам (D-21)

### 6.1 Где и когда

- Чипы рисует **сама `MovementTimeline`** над списком — один владелец для всех четырёх
  потребителей (попап, `PrinterDetail`, `CartridgeDetail`, `GroupPanel`).
- Ряд чипов показывается, только если в загруженной ленте **два и более** разных вида. Чип
  вида, которого в ленте нет совсем, не рисуется. Один вид — ряда нет вовсе (картридж всегда
  без чипов; устройство, у которого были только перемещения, — тоже без чипов).
- Пустая лента — чипов нет, только пустое состояние.
- Порядок чипов фиксирован: **«Перемещения» · «Состав» · «Статус»**. В ленте группы чипа
  «Статус» нет никогда (D-11).
- Состояние — локальное `$state` компонента; при каждом открытии карточки/попапа все чипы
  включены. Не пишется ни в `localStorage`, ни в URL.

### 6.2 Анатомия чипа

Нативный `<button type="button" aria-pressed>` внутри `<div role="group" aria-label="Виды
событий">`. Существующий `Button` не подходит: `variant="primary"` у трёх включённых по
умолчанию чипов дал бы три сплошных синих пятна над лентой (нарушение 10% акцента), а у
`Button` нет «мягкого» нажатого состояния. Стиль — локальный в новом компоненте
`lib/components/HistoryKindChips.svelte` (или внутри `MovementTimeline` — на выбор
исполнителя, но один файл).

| Состояние | Фон | Рамка | Текст | Галочка слева |
|-----------|-----|-------|-------|---------------|
| Включён (`aria-pressed="true"`) | `--tr-accent-soft` | 1px `--tr-accent` | `--tr-accent-text` | есть, 12×12, `currentColor` |
| Выключен (`aria-pressed="false"`) | прозрачный | 1px `--tr-border-strong` | `--tr-text-secondary` | нет |
| Hover выключенного | `--tr-surface-sunken` | без изменений | `--tr-text-primary` | нет |
| Фокус | `box-shadow: 0 0 0 3px var(--tr-focus-ring)` + `outline: none` (пара для `check-focus-outline`) | | | |

Геометрия: высота 28px, `padding: 0 var(--tr-space-sm)`, `border-radius: var(--tr-radius-full)`,
`gap: var(--tr-space-2xs)` между галочкой и подписью, `gap: var(--tr-space-2xs)` между чипами,
`flex-wrap: wrap`, `margin-bottom: var(--tr-space-sm)` у ряда. Включённость читается не только
цветом (WCAG 1.4.1): галочка + `aria-pressed`.

### 6.3 Поведение

- Клик / `Enter` / `Space` переключает чип. Фокус остаётся на чипе.
- Выключить можно все чипы — тогда показывается пустое состояние «Нет событий выбранных видов»
  (§11.2), ряд чипов остаётся на месте.
- Комбинированная строка (§7.4) видна, если включён **хотя бы один** из её видов.
- Фильтрация — на клиенте по полю видов строки (это выбор показа, не формула; зеркала Rust
  нет).

## 7. Строка ленты (D-20, D-04, D-05, D-07, D-23)

### 7.1 Анатомия

```
[значок] ДД.ММ.ГГГГ — {текст события} · {автор} · {основание}
```

- Порядок, разделители («—», «·»), `flex-wrap`, `min-height` 32px, нижняя граница
  `--tr-border` — унаследованы из `.timeline-row`.
- **Значок** — новый первый элемент строки, 16×16, `--tr-text-secondary`, `aria-hidden="true"`,
  `flex: none`. Смысл строки целиком несёт текст, значок — только ориентир для глаза.
- **Текст события** — у перемещения прежнее «{откуда} → {куда}» со ссылками на места и полным
  путём в `title`; у состава и статуса — фраза §7.2. Имена групп и устройств в фразе — ссылки
  `.timeline-link` внутри «ёлочек»: кавычки — текст, имя — кнопка (как нынешнее «в составе
  группы «…»»).
- **Автор** — `actor_display` (снимок ФИО, как сейчас).
- **Основание** — §7.5.
- Длинные имена переносятся (`overflow-wrap: anywhere` на строке), строка не уезжает за край
  колонки.

### 7.2 Тексты событий — лента устройства (устройство, принтер)

| Вид | Значок | Текст события (середина строки) |
|-----|--------|---------------------------------|
| Перемещение | `move` | «Склад → Каб. 12» (без изменений) |
| Включение в группу | `membership` | «Включено в группу «АРМ-5»» |
| Вывод из группы | `membership` | «Выведено из группы «АРМ-5»» |
| Перенос между группами (D-05) | `membership` | «Перемещено из группы «АРМ-3» в «АРМ-5»» |
| Образование группы (у якоря, D-07) | `membership` | «Образована группа «Системный блок #4»» |
| Расформирование группы (у якоря, D-07) | `membership` | «Группа «Системный блок #4» расформирована» |
| Смена статуса | `status` | «Статус: В работе → На списание» |
| Нераспознанный вид (D-23) | `unknown` | «событие не определено» |

- Участники, вошедшие при создании группы, получают обычное «Включено в группу «…»» с
  основанием «при создании группы»; участники при расформировании/списании — «Выведено из
  группы «…»» с основанием «при расформировании группы» / «при списании группы» (D-07).
- Названия статусов — снимок подписи из события. Если снимок пуст — подпись текущего
  справочника по коду (стор статусов, как `check-device-status-labels`); если и её нет —
  «неизвестный статус». Сырой код статуса пользователю **не показывается никогда**.
- Если группа удалена и ссылаться некуда (сервер не отдал `group_id`), имя из снимка
  показывается обычным текстом в тех же «ёлочках».

| `move` | стрелка вправо — тот же путь, что `arrow-right` в `ChatEventIcon`: `M3 8h10M9 4l4 4-4 4` |
| `membership` | два перекрывающихся квадрата (состав): `rect x=2 y=5 w=7 h=7 rx=1` + `path M7 5V3.5a1 1 0 0 1 1-1h4.5a1 1 0 0 1 1 1V8a1 1 0 0 1-1 1H9` |
| `status` | ярлык (тег): `path M2.5 2.5h5l6 6-5 5-6-6z` + `circle cx=5.5 cy=5.5 r=1` |
| `unknown` и любое иное значение | точка: `circle cx=8 cy=8 r=1.5 fill=currentColor` (как fallback `ChatEventIcon`) |

Иконка переключателя (`IconHistory.svelte`) — часы со стрелкой против часовой (D-15):
`path M2.5 8a5.5 5.5 0 1 0 1.6-3.9` + `path M2.5 2.5V5H5` + `path M8 5v3l2 1.5`.

### 7.4 Комбинированная строка (D-04, D-05)

Одна операция, которая меняет сразу несколько вещей, — одна строка. Сегменты середины
идут в фиксированном порядке **состав → место → статус**, через «; ».

| Случай | Текст события |
|--------|---------------|
| Место + статус (акт, ремонт, возврат на склад) | «Склад → Каб. 12; статус: На складе → В работе» |
| Перенос между группами + место | «Перемещено из группы «АРМ-3» в «АРМ-5»; место: Каб. 12 → Каб. 14» |
| Перенос между группами + место + статус | «Перемещено из группы «АРМ-3» в «АРМ-5»; место: Каб. 12 → Каб. 14; статус: На складе → В работе» |
| Включение + место (акт с одиночным включением) | «Включено в группу «АРМ-5»; место: Склад → Каб. 12» |

Правила: префикс «место:» ставится, только если место — не первый сегмент; статус первым
сегментом — «Статус: …» с заглавной, не первым — «статус: …» со строчной. Значок строки —
вид **первого** сегмента. Основание и автор — одни на строку (общий идентификатор операции).
Строку собирает сервер (D-04); клиент только раскладывает сегменты по шаблону.

### 7.5 Основание (причина)

Ссылочные основания — кнопки `.timeline-link`, как сейчас. Словарь — единый модуль
`ui/src/lib/historyEvents.ts` (подписи видов и оснований новых событий); подписи источников
перемещения остаются в `movementReason.ts`.

| Основание | Текст |
|-----------|-------|
| Вручную (карточка, меню строки, быстрые действия) | «вручную» |
| Акт | «актом №123» (номер — ссылка на акт) |
| Ремонтная заявка | «по ремонтной заявке №17» (номер — ссылка) |
| Перенос группы на другое место (41.8 D-34) | «при переносе группы «АРМ-5»» (имя — ссылка) |
| Создание группы | «при создании группы» |
| Расформирование группы | «при расформировании группы» |
| Списание устройства | «при списании» |
| Списание группы | «при списании группы «Системный блок #4»» (имя — ссылка) |
| Разбор | «при разборе «Разбор #7»» (имя — ссылка) |
| Нераспознанное основание | «причина не определена» (существующая константа `UNKNOWN_MOVEMENT_REASON`) |

Внутри перемещения хвост акта и группы (`actTail`: «перенос группы», «в составе группы «…»»)
сохраняется без изменений.

### 7.6 Требования к данным строки

Чтобы строку можно было нарисовать без склейки на клиенте, каждая строка DTO ленты обязана
нести: (1) упорядоченный список видов её сегментов (`move`/`membership`/`status`, строки, а не
enum в TS — для D-23); (2) для каждого сегмента — его поля: места `from/to` (id + полный и
короткий путь, как сейчас), группы (id, снимок имени; для переноса — обе), статусы
(код + снимок подписи «было/стало»), вид события состава (включение/вывод/перенос/образование/
расформирование); (3) общие автор, дата, основание со ссылками (акт, заявка, группа, разбор).
Точная форма полей — решение планировщика.

### 8.2 Кнопка-переключатель

```svelte
<Button variant="ghost" size="sm" iconOnly ariaLabel="История" title="История"
        ariaPressed={pressed} onclick={toggleHistory}><IconHistory /></Button>
```

- Квадрат 28×28 (как «×»), ghost, иконка 16px. Подсказка `title` и `aria-label` — «История»
  в обоих состояниях (D-15); состояние — только `aria-pressed`.
- Видимое нажатое состояние — новое правило в `global.scss` рядом с `.tr-btn-ghost-icon`:
  `.tr-btn-ghost-icon[aria-pressed='true'] { background: var(--tr-accent-soft); color:
  var(--tr-accent-text); }`. Hover нажатой кнопки — без изменения фона.
- `pressed` = флаг `localStorage` на широком экране; = «панель открыта» на узком (§8.4).
- Кнопка есть у всех трёх видов: устройство, принтер, картридж (D-14). Пока основные данные
  грузятся или не загрузились — кнопка **доступна**: история грузится независимо (§8.5).
- Начальный фокус попапа: первый фокусируемый элемент теперь — переключатель (раньше «×»).
  Это допустимо: `Enter` на нём обратим тем же нажатием. `initialFocus` не задаётся.

### 8.3 Широкий экран: две колонки (D-16, D-17)

Широкий экран — `window.matchMedia('(min-width: 1024px)')` (`$bp-lg`, тот же порог, что
`Layout.isDesktop`). Слушатель `change` снимается в cleanup `$effect`.

| Флаг | `Modal size` | Тело |
|------|--------------|------|
| выключен | `md` (как сейчас) | только данные, блок истории снизу **удалён** (D-14) |
| включён | `split` | сетка из двух колонок |

Сетка `.view-split`: `display: grid; grid-template-columns: minmax(0, calc(var(--modal-max-width)
- 2 * var(--tr-space-xl))) minmax(360px, 1fr); column-gap: var(--tr-space-xl); height: 100%;
min-height: 0`.

- **Левая колонка** — прежнее содержимое без изменений: `DeviceFormBody`/`CartridgeFormBody`
  readonly, «Из разбора», вложения, «История вложений». `overflow-y: auto; min-height: 0`.
  Ширина — до 592px (ширина содержимого `md`), при нехватке места сжимается первой.
- **Правая колонка** — `<section aria-labelledby>` с `DetailSection heading="История"` → чипы →
  лента → сноски. `border-left: 1px solid var(--tr-border); padding-left: var(--tr-space-xl);
  overflow-y: auto; min-height: 0`. Высота попапа от длины истории не растёт: колонка
  прокручивается сама в пределах 760px.
- Нажатие переключателя пишет флаг в `localStorage` (`trackly:view-history`, значения `'1'` /
  `'0'`) — один флаг на устройство, принтер и картридж (D-17). Модуль-стор по образцу
  `theme.svelte.ts`: чтение в `try/catch`, недоступный `localStorage` = выключено, ошибка записи
  молча игнорируется. На сервер не уходит.
- Попап, открытый при включённом флаге на широком экране, сразу открывается размером `split`.
- Фокус при переключении **остаётся на кнопке**: колонка появляется/исчезает рядом, диктор
  объявляет смену `aria-pressed`. Фокус в колонку не переносится — на широком экране данные
  остаются на месте, и пользователь сам решает, идти ли в ленту по `Tab`.

### 8.4 Узкий экран: панель поверх данных (D-18)

При `(min-width: 1024px)` = `false`:

- Ширина попапа не меняется (`size="md"`), флаг `localStorage` **не читается и не пишется**.
  Попап всегда открывается с данных.
- Нажатие переключателя открывает панель «История»: блок данных получает атрибут `hidden`
  (остаётся смонтированным — состояние и вложения не перезагружаются), на его месте в теле
  модалки рисуется панель: `DetailSection heading="История"` → чипы → лента → сноски.
  Прокручивается обычное тело модалки. `aria-pressed="true"`.
- Позиция прокрутки данных запоминается при открытии панели и восстанавливается при возврате.
- При открытии панели фокус переносится на её заголовок «История» (`tabindex="-1"`), чтобы
  диктор прочитал смену содержимого. Повторное нажатие переключателя возвращает данные, фокус
  остаётся на переключателе.
- `Esc` при фокусе внутри панели закрывает **панель**, а не попап: обработчик `keydown` на
  панели делает `preventDefault()` и возвращает фокус на переключатель (`Modal` пропускает
  `Esc` с `defaultPrevented`, FE-CR-03). `Esc` вне панели — закрывает попап, как сейчас.
- Подвал попапа («Перейти к…», «Ремонты (N)», «Редактировать») виден в обоих видах панели.
- Пересечение порога при открытом попапе: широкий → узкий — попап переходит на `md`, панель
  закрыта, показаны данные, флаг не меняется; узкий → широкий — панель сбрасывается, размер
  берётся из флага.

### 8.5 Загрузка (D-19)

- Лента грузится при первом включении (колонка или панель) либо сразу при открытии, если флаг
  включён на широком экране. Повторные включения в пределах жизни попапа не перезапрашивают.
- Загрузка истории **отделена** от основной загрузки: её ошибка не превращает попап в «Не
  удалось загрузить данные», а показывается только внутри колонки/панели (§11.4). Основной
  `loading`/`loadError` больше не включает ленту.
- Пока грузится: в колонке/панели под заголовком — `Spinner size="sm"` и «Загружаем историю…»
  в `aria-live="polite"`.
- Защита от устаревшего ответа — токен запроса (как `historyToken`), но **отдельная**
  переменная: существующие `historyOpen`/`historyToken`/`visitCount` (ремонты) не
  переиспользуются и не переименовываются.
- Навигация по ссылкам ленты закрывает попап, как сейчас (`push` → `onClose`).

Вход в группу, выход из неё и смену статуса программа записывает с обновления, в котором появилась эта лента; более ранних таких событий здесь нет.» |
| `cartridge` | 1. (первичное размещение, без изменений) |
| `group` | 1. «Переносы группы показаны за всё время. Вход и выход устройств, образование группы и вложение в другие группы программа записывает с обновления, в котором появилась эта лента; более ранних таких событий здесь нет.» |

Проп `showInitialPlacementNote` заменяется пропом `variant: 'device' | 'cartridge' | 'group'`
(по умолчанию `device`), который выбирает пустое состояние, сноски и набор возможных чипов.

### 11.4 Ошибки

| Ситуация | Текст |
|----------|-------|
| Лента не загрузилась (все потребители) | Не удалось загрузить историю. Проверьте подключение и откройте карточку снова. |
| Основные данные попапа не загрузились | Не удалось загрузить данные. Закройте окно и попробуйте ещё раз. *(без изменений; ошибка ленты сюда больше не попадает, §8.5)* |
| Нераспознанный вид события | событие не определено *(строка не роняет ленту, D-23)* |
| Нераспознанное основание | причина не определена *(без изменений)* |

### 11.5 Деструктивные действия фазы

**Нет.** Фаза только показывает историю; подтверждений не вводит.

## 13. Состояния и доступность

### 13.1 Клавиатура

| Клавиша | Где | Действие |
|---------|-----|----------|
| `Enter` / `Space` | переключатель | включить/выключить историю |
| `Enter` / `Space` | чип | переключить вид |
| `Tab` | попап `split` | шапка → левая колонка → правая колонка (чипы → ссылки ленты) → подвал; ловушка `Modal` охватывает обе колонки |
| `Esc` | панель на узком экране | закрыть панель, фокус на переключатель (§8.4) |
| `Esc` | вне панели | закрыть попап (без изменений) |

### 13.2 Экранный диктор

- Переключатель: «История, кнопка-переключатель, нажата / не нажата».
- Колонка/панель: `<section aria-labelledby="{id заголовка «История»}">`.
- Ряд чипов: `role="group"`, `aria-label="Виды событий"`; каждый чип — `aria-pressed`.
- Значки видов — `aria-hidden="true"`; текст строки самодостаточен.
- Загрузка ленты — `aria-live="polite"`.

### 13.3 Только в живом приложении (Tauri и LAN-браузер)

Синтетический стенд не заменяет проверку (WKWebView/WebView2). Проверить вживую:
1. Попап просмотра из строки таблицы «Места»: переключатель рядом с «×», нажатое состояние
   видно в обеих темах; текст в колонках переносится (наследование `td.cell` сброшено).
2. Флаг: включить у устройства → закрыть → открыть принтер и картридж — открываются с
   колонкой; перезапуск приложения — флаг сохранён.
3. Длинная история (20+ строк): попап не выше 760px, правая колонка прокручивается сама,
   левая — сама.
4. Окно уже 1024px (и LAN-браузер на телефоне): попап узкий, панель поверх данных, `Esc`
   закрывает панель, флаг не меняется; расширение окна при открытой панели — §8.4.
5. Чипы: у устройства с одними перемещениями чипов нет; у картриджа нет никогда; «все
   выключены» — пустое состояние, сноски на месте.
6. `PrinterDetail`: «Журнал опросов» и «История» рядом, подписи не путаются.

## 16. Решения researcher'а (Claude's Discretion)

| # | Решение | Обоснование | Отвергнуто |
|---|---------|-------------|------------|
| R-01 | Двухколоночный попап — новый размер `Modal` `split` (1200px, токен), а не `xwide` (1000px) | В `xwide` при сохранении левой колонки шириной `md` (592px) правой остаётся ~311px — строка ленты рвётся после каждого слова; «вдвое» (D-16) честнее даёт 1200px | `xwide` с сужением левой колонки до ~450px (ломает ряд «Инв. № / Серийный № / Количество» в `DeviceFormBody`, а D-16 требует левую колонку без изменений) |
| R-02 | Фиксированная максимальная высота попапа `split` — 760px, колонки прокручиваются сами | D-16: высота не растёт от длины истории; иначе сетка тянула бы ряд по самой длинной колонке | Высота по левой колонке через `position: absolute` правой (короткая карточка картриджа давала бы колонку истории в 3 строки) |
| R-03 | Порог узкого режима — `$bp-lg` 1024px, а не только телефон | Ниже 1024px окно (`100vw − 64px` < 960px) не вмещает 360px ленты рядом с формой; тот же порог, что `Layout.isDesktop` | `$bp-md` 768px (при 768–1023 правая колонка сжималась бы до нечитаемой) |
| R-04 | Панель на узком экране — замена содержимого тела (`hidden` у данных), а не абсолютный слой поверх | Визуально то же «поверх» (D-18), но без второго прокручиваемого слоя внутри прокручиваемого тела и без утечки фокуса в скрытые данные | Абсолютный слой с `inert` на данных (двойная прокрутка, сложнее ловушка Tab) |
| R-05 | Чипы — собственный тумблер с мягким нажатым состоянием, а не `Button primary/secondary` | Три включённых по умолчанию чипа `primary` — три сплошных синих пятна над лентой, нарушение 10% акцента; галочка даёт не-цветовой признак | `Button` primary/secondary (образец `RepairMoveModal` — там выбор одиночный); `Tabs segmented` (одиночный выбор) |
| R-06 | Секция опросов SNMP в `PrinterDetail` переименована в «Журнал опросов» | Развести «смену статуса устройства» (чип «Статус» новой ленты, D-21 зафиксировал подпись) и результаты сетевого опроса; «Журнал» уже закреплён за служебной лентой | Переименовать чип «Статус» (зафиксирован D-21); оставить обе «истории статусов» |
| R-07 | Пустое состояние «Журнала операций» картриджа «История пуста» → «Операций ещё не было» | Рядом появляется секция «История» — «История пуста» под другим заголовком читалась бы как пустая «История» | Оставить как есть |
| R-08 | Комбинированная строка: порядок сегментов состав → место → статус, префикс «место:» только не первым сегментом | Сохраняет пример D-04 («Склад → Каб. 12; статус: …») и D-05 («Перемещено из группы …») буквально; один шаблон для всех сочетаний | Отдельные шаблоны на каждое сочетание |
| R-09 | Чипы рисует `MovementTimeline`, а не каждый потребитель | Четыре потребителя, одна анатомия (принцип Фазы 40 «3 потребителя — 1 формула») | Чипы в каждом родителе |
| R-10 | Ряд чипов показывается только при двух и более видах в ленте | Обобщение D-21 («у картриджа только перемещения — чипов нет»): один чип ничего не фильтрует | Показывать единственный чип |
| R-11 | Загрузка истории в попапе отделена от основной загрузки | Ошибка ленты не должна прятать данные устройства; лента грузится лениво (D-19) | Общий `loadError`, как сейчас |
| R-12 | Начальный фокус попапа остаётся «первый фокусируемый» — теперь переключатель | Действие обратимо тем же нажатием; `initialFocus` на «×» усложнил бы `Modal` ради одного случая | `initialFocus=".modal-close"` |
