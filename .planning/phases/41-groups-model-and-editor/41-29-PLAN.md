<objective>
Закрыть обход защиты «обязательное» через скрытие свойства (W-B01): после «скрыть -> отметить обязательным -> показать» любой `set_values` на группе без значения падал, включая правку несвязанных полей.

Purpose: GAP-3. Не потеря данных, но пользователь заперт. Подтверждено чтением кода в верификации.
Output: инвариант «скрытое свойство не обязательное» на трёх входах сервера + три теста, красные на коде до правки.

Почему не просто «запустить проверку нарушителей в un-hide» (дословная рекомендация верификации): вторая дорога к той же дыре достижима из интерфейса без обхода — свойство обязательное (нарушителей нет) -> «Скрыть» -> создана новая группа (скрытое свойство в её форме не требуется) -> «Вернуть». Одна проверка при un-hide здесь отказала бы, а выйти пользователь не смог бы: у скрытой строки чекбоксы disabled, значение скрытого свойства в форме группы не заполнить. Поэтому обязательность снимается при скрытии (значения остаются, D-13), а проверка при un-hide остаётся защитным поясом для наследных строк «скрыто + обязательное» (V045 ещё не выпущена, такие строки возможны только в dev-БД).
</objective>
