# Phase 41.13 Plan 03: запись USB-хоста принтера на сервере Summary

**Сервер умеет принять USB-хост принтера при создании (блок принтера) и при редактировании (`DevicePatch`), с проверкой самоссылки / несуществующего / мягко удалённого хоста. Код написан и компилируется; поведение записи этим планом НЕ доказано - тесты и мутации в плане 04.**

## Как реализована запись

**Создание.** В `sync_printer_row_in_tx` (ветка внутри exists-гарда) значение `printer_override.and_then(|b| b.usb_host_device_id)`; если оно `Some`, до `create_in_tx` вызывается `validate_usb_host_in_tx`; значение уходит в `PrinterNew.usb_host_device_id` вместо жёсткого `None`. Блок без IP, но с хостом не отбрасывается (гейта по IP в этой ветке нет). Хост вместе с IP сервер не запрещает. Блок на не-принтере по-прежнему отклоняет существующая проверка T-40.3-09; `bulk_create` не менялся.

**Редактирование и почему это мимо exists-гарда.** `sync_printer_row_in_tx` создаёт строку `printers` только под `if !exists_for_device_in_tx(...)`; на существующей строке она не выполняется, поэтому «сохранить хост через неё» при правке молча не сделало бы ничего. Запись хоста в `DeviceService::update` - отдельный блок в writer-замыкании СРАЗУ ПОСЛЕ `sync_printer_row_in_tx` (строка 1116; вызов `set_usb_host_in_tx` - 1123): при одновременной смене типа на «Принтер» строка к этому моменту уже создана. Значение патча читается ДО `patch.into()` (`let usb_host_patch` - строка 1052, `patch.into()` - 1053). Вызов `sync_printer_row_in_tx(.., None)` на существующей строке ничего не затирает (проверено чтением кода, мины затирания нет).

**Три случая `Option<Option<i64>>`:**
- `None` (поле не передано): блок `if let Some(host) = usb_host_patch` не выполняется, уже записанный хост не меняется.
- `Some(None)` (null): для принтера `set_usb_host_in_tx(.., None, ..)` пишет NULL; для не-принтера - ничего.
- `Some(Some(id))`: для принтера - валидация и запись; для не-принтера - `Validation { field: "usb_host_device_id" }`.

`set_usb_host_in_tx` делает `UPDATE printers SET usb_host_device_id, updated_at_utc, version = version + 1 WHERE device_id = ?`; 0 затронутых строк -> `NotFound { entity: "printer" }`. `validate_usb_host_in_tx`: `host == device` -> Validation; `EXISTS devices WHERE id = ? AND deleted_at_utc IS NULL` ложно -> Validation; оба с `field = "usb_host_device_id"`. SQL параметризован.

Новых `fn` в `device_service.rs` нет (`git diff -U0 | grep -E '^\+\s*(pub )?(async )?fn '` пуст), реестр записей не затронут. `broadcast_entities` и аудит не менялись. Смена типа Принтер -> Устройство по-прежнему удаляет строку printers вместе с хостом (существующее поведение).
