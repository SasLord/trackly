## Главные находки (читать до остального)

1. **`GroupPropertiesForm.svelte` не был в списке, но ломается от нового значения `origin`.** Три
   места фильтруют по литералу `'usb'`: `ui/src/features/groups/GroupPropertiesForm.svelte:37`
   (`usbPrinters`, условие показа блока «Подключённые принтеры» для типа без свойства-ссылки),
   `:275-276` (`card.printers.filter((x) => x.origin !== 'usb')` для второго и далее свойства
   `device_refs`), плюс `GroupPrintersList.svelte:75` и `:90`. Если появится значение `member`, то
   (а) для типа группы без свойства «Ссылки на устройства» принтеры-члены не покажутся вообще,
   (б) в списках вторичных свойств `device_refs` появятся «чужие» строки-члены.
2. **`member_of_group_id` в `DeviceFilter` исключает якорь группы.** Макрос
   `group_subtree_members_sql!` (`crates/trackly-infra/src/repos/devices_sqlite.rs:62-76`) отдаёт
   поддерево «без якоря». Для АРМ якорь, как правило, и есть системный блок, то есть самый вероятный
   USB-хост. Брать этот фильтр для секции «В составе «…»» в форме нельзя без дополнения якорем;
   `usb_printers_for_group` (`groups_sqlite.rs:621`) якорь НЕ исключает (хост берётся из
   `group_devices` целиком).
3. **«Мина» `sync_printer_row_in_tx` сейчас не затирает хост.** Тело ветки обёрнуто в
   `if !printer_repo.exists_for_device_in_tx(...)` (`device_service.rs:579`): на существующей строке
   `printers` вызов с `None` ничего не делает. Строка 2197 - это `bulk_create`, а не обновление
   (обновление - только 1106). Тест «не затирает» НЕ упадёт на нынешнем коде; он нужен как мина под
   НОВУЮ реализацию (когда ветку превратят в upsert, `None` вместо блока обнулит колонку). Проверять
   его надо мутацией: подставить в UPDATE безусловное `usb_host_device_id = NULL` и убедиться, что
   тест краснеет.
4. **Смена типа Принтер -> Устройство удаляет строку `printers` вместе с хостом**
   (`delete_by_device_id_in_tx`, `device_service.rs:618`). Возврат типа создаёт строку с
   `usb_host_device_id: None`. Это существующее поведение (UI-SPEC §4.6 его не меняет), но сценарий
   «хост пропал после двойной смены типа» стоит осознанно записать в тест или в SUMMARY.
5. **`ui/src/bindings-phase6.ts` ведётся ВРУЧНУЮ и закоммичен**, а `ui/src/bindings.ts`
   сгенерирован и в `.gitignore`. Новые поля `PrinterDto` (имя и инв. № хоста) надо руками дописать
   в `bindings-phase6.ts`; гейта синхронности нет. `PrinterCreateBlockDto` и `GroupPrinterDto`
   живут в `bindings.ts` (генерируется тестом `export_bindings`).
6. **Сочетания `variant="combobox"` + `flat={true}` + `getGroupSection` в проекте нет ни в одном
   месте.** Есть по отдельности: `combobox`+`flat` (`GroupPrintersList`), `combobox`+секции без
   `flat` (`ActFormItemsTable`, `GroupContentsTable`), `select`+`flat`+секции (`AddToGroupModal`).
   Строка UI-SPEC «образец - `GroupPrintersList.svelte:221-222`» верна только для пары
   `combobox`+`flat`; секций в нём нет.
7. **Подводный камень секций в `Dropdown`.** `sectionHeadingAt` (`Dropdown.svelte:405-412`) при
   `getGroupSection(...) === undefined` заголовок не рисует вовсе, даже если выше была другая секция.
   Чтобы «Все устройства» получила заголовок, когда секция 1 есть, замыкание `getGroupSection` обязано
   возвращать `'Все устройства'` для таких строк именно в этот момент и `undefined`, когда секции 1
   нет. Формулировка UI-SPEC §4.4 «безымянная секция 2 возвращает `undefined`» без этого уточнения
   даст список вообще без заголовка «Все устройства».

## Pattern Assignments

### 1. Запрос с несколькими происхождениями и дедупликацией

Прямого образца «один SQL с UNION и литералом-источником для принтеров группы» нет. В проекте две
готовые техники, обе нужны:

**(a) Дедупликация в сервисе по `HashSet` (ТО, ЧТО УЖЕ РАБОТАЕТ для usb+link)** -
`crates/trackly-app/src/services/group_service.rs:1503-1535`:

```rust
// Единый список принтеров: USB-производные + явные ссылки на принтеры, дедуп по device_id.
let link_candidates: Vec<i64> = live_refs.iter().map(|r| r.device_id).collect();
let link_printers = repo.live_printer_device_ids(conn, &link_candidates)?;
let explicit: HashSet<i64> = live_refs
    .iter()
    .map(|r| r.device_id)
    .filter(|d| link_printers.contains(d))
    .collect();
let mut printers: Vec<GroupPrinterDto> = Vec::new();
let mut seen: HashSet<i64> = HashSet::new();
for r in repo.usb_printers_for_group(conn, id)? {
    if seen.insert(r.device_id) {
        printers.push(GroupPrinterDto {
            device_id: r.device_id,
            name: r.name,
            inventory_number: r.inventory_number,
            serial_number: r.serial_number,
            origin: "usb".to_string(),
            has_explicit_link: explicit.contains(&r.device_id),
        });
    }
}
for r in live_refs {
    if explicit.contains(&r.device_id) && seen.insert(r.device_id) {
        printers.push(GroupPrinterDto { /* ... */ origin: "link".to_string(), has_explicit_link: true });
    }
}
printers.sort_by(|a, b| a.name.cmp(&b.name).then(a.device_id.cmp(&b.device_id)));
```

Порядок циклов задаёт приоритет (кто вставил первым, тот победил). Для `USB > Ссылка > В составе`
третий цикл (`member`) ставится ПОСЛЕДНИМ, после `live_refs`, тем же `seen.insert`. Сортировка в
конце уже есть и соответствует R-11. Существующий тест приоритета - `card_dedup_usb_and_link_collapse_to_one_row`
(`crates/trackly-app/tests/groups_values_card.rs:1023-1068`): утверждает `origin == "usb"`,
`has_explicit_link == true`, одну строку. Для `member` нужен такой же тест: принтер-член + USB-привязанный +
ссылка = одна строка `usb`.

**(b) Новый репозиторный метод - копия `usb_printers_for_group`** -
`crates/trackly-infra/src/repos/groups_sqlite.rs:617-642` (обход поддерева через `SUBTREE_CTE`,
`:38-43`):

```rust
const SUBTREE_CTE: &str = "WITH RECURSIVE sub(id) AS (
        SELECT id FROM groups WHERE id = ?1 AND deleted_at_utc IS NULL
        UNION
        SELECT g.id FROM groups g JOIN sub ON g.parent_group_id = sub.id
        WHERE g.deleted_at_utc IS NULL
     )";

pub fn usb_printers_for_group(&self, conn: &Connection, group_id: i64)
    -> Result<Vec<PrinterRefRow>, AppError> {
    let sql = [
        SUBTREE_CTE,
        " SELECT d.id, d.name, d.inventory_number, d.serial_number
          FROM printers p
          JOIN devices d ON d.id = p.device_id AND d.deleted_at_utc IS NULL
          WHERE p.usb_host_device_id IN (
            SELECT gd.device_id FROM group_devices gd
            JOIN sub ON gd.group_id = sub.id
            JOIN devices h ON h.id = gd.device_id AND h.deleted_at_utc IS NULL
          )
          ORDER BY d.name, d.id",
    ]
    .concat();
    let mut stmt = conn.prepare(&sql).map_err(map_rusqlite)?;
    let rows = stmt
        .query_map(rusqlite::params![group_id], printer_ref_from_row)
        .map_err(map_rusqlite)?
        .collect::<Result<Vec<_>, _>>()
        .map_err(map_rusqlite)?;
    Ok(rows)
}
```

Для членства: тот же `SUBTREE_CTE`, затем
`FROM group_devices gd JOIN sub ON gd.group_id = sub.id JOIN devices d ON d.id = gd.device_id AND d.deleted_at_utc IS NULL JOIN printers p ON p.device_id = d.id ORDER BY d.name, d.id`
(определение «принтер» = есть строка `printers`, как в `live_printer_device_ids`, `:877-889`; это же
решает и сносит расхождение «принтерности» из CONTEXT/Deferred в пользу таблицы, не справочника типов).
Возвращает тот же `PrinterRefRow` и `printer_ref_from_row` (`:523-530`).

**(c) SQL с UNION ALL и литеральным признаком источника** (если решат делать одним запросом) -
`crates/trackly-infra/src/repos/places_sqlite.rs:381-440`:

```rust
"{cte}SELECT 'device' AS kind, d.id, d.name, d.inventory_number, ...
 FROM devices d ... WHERE ...
 UNION ALL
 SELECT 'printer' AS kind, d.id, d.name, d.inventory_number, ..."
```

Это только образец литерала `'...' AS kind`. Дедупликации внутри SQL там нет (ветки взаимоисключающие
по типу). Для пересекающихся происхождений через UNION ALL понадобится `GROUP BY d.id` с
`MIN(rank)`; готового такого запроса в проекте нет. Рекомендация карте: образец (a)+(b) надёжнее, он
уже покрыт тестами и сохраняет `has_explicit_link` без переписывания.

**Тестовый образец репозитория** - `crates/trackly-infra/tests/groups_repo.rs:750-811`
(хелперы `insert_device`, `insert_printer(conn, id, usb_host)` `:552`, `make_group`, `add_device`,
`set_parent`, `soft_delete_device`, `ids()` `:745`). Проверяет: корень + вложенная, чужая группа
отсутствует, мягко удалённый принтер и мягко удалённый хост выпадают:

```rust

assert_eq!(ids(&found), vec![11, 12], "корень + вложенная, без чужой группы");

Для членства добавить: принтер, лежащий в корне / во вложенной / в чужой группе / вне групп; сетевой
принтер-член тоже попадает (правило не зависит от IP).

**Сервисные тестовые хелперы** - `crates/trackly-app/tests/groups_values_card.rs`: `seed_group` `:105`,
`seed_device` `:130`, `seed_printer(ctx, name, inv, usb_host)` `:356-370`, `arm_group` `:270`,

**Существующие тесты, которые изменят смысл.** В `card_usb_*` принтеры сеются через `seed_printer`

function subOf(d: DeviceDto): string | undefined {
  const parts = [
    d.inventory_no ? `инв. ${d.inventory_no}` : null,
    d.serial_no ? `SN ${d.serial_no}` : null,
  ].filter((p): p is string => p !== null);
  return parts.length > 0 ? parts.join(' · ') : undefined;
}
```

## Shared Patterns

### Единый слой `build_*` для двух транспортов
**Источник:** `crates/trackly-app/src/tauri_cmds/devices.rs:60-86` и `crates/trackly-app/src/http/devices.rs:181-228`.
**Применять к:** любой новой/изменённой операции (обновление устройства с блоком принтера).
```rust
// tauri_cmds/devices.rs
pub async fn build_devices_update(ctx: &AppCtx, caller: &Identity, id: i64, version: i64, patch: DevicePatch)
    -> Result<DeviceSaveOutcome, AppError> {
    authorize(caller, &Action::MutateDevices)?;
    ctx.devices.update(caller, id, version, patch).await
}
// http/devices.rs
pub async fn handler_update(State(ctx): State<AppCtx>, session: Session, Json(payload): Json<UpdatePayload>)
    -> Result<Json<DeviceSaveOutcome>, AppErrorResponse> {
    let identity = session_identity(&session).await.map_err(AppErrorResponse::from)?;
    Ok(Json(build_devices_update(&ctx, &identity, payload.id, payload.version, payload.patch)
        .await.map_err(AppErrorResponse::from)?))
}
```

### Запись принтера в той же транзакции, что и устройство
**Источник:** `device_service.rs:1098-1106` (update) и `:660-676` (create) - `sync_printer_row_in_tx`
вызывается ВНУТРИ `self.writer.execute(move |conn| { let tx = conn.transaction()...; ... })` сразу после
`repo.update_in_tx` / `repo.create_in_tx`. Любая запись хоста идёт туда же, не вторым вызовом. Единая
точка записи - `WriterHandle` (CLAUDE.md, «Concurrent-доступ»).

### Права
Чтение: `authorize(caller, &Action::ReadData)` / `Action::ReadGroups`; мутация устройства:
`Action::MutateDevices`. Принтерные мутации в `PrinterService`: `Action::MutatePrinters`
(`printer_service.rs:~277`). Хост меняется через `devices_update`, значит право `MutateDevices`.

### Запросы только параметризованные
`groups_sqlite.rs` шапка файла: ввод никогда не конкатенируется в SQL; единственная сборка текста -
`vec!["?"; n].join(",")` для `IN (...)`. Применять к новому SQL.

### Мягкое удаление
И принтер, и хост, и члены - `deleted_at_utc IS NULL` (см. `usb_printers_for_group`). Исключение -
отображение имени хоста в детали (находка в разделе 4).

### Обработка ошибок на клиенте
`DeviceFormBody.svelte:~886-905`: `err.code === 'VALIDATION' && err.details?.field` ->
`fieldErrors[field]` + `pushToast('error', ...)`; `OPTIMISTIC_LOCK_MISMATCH` - отдельный тост.

### Копирайт и приватность
Тексты - из `41.13-UI-SPEC.md` §7. Примеры и фикстуры вымышленные («АРМ #3», «Принтер А»,
«инв. 114»); гейт приватности работает в pre-commit и CI (память «Фаза 37»), но ФИО он не ловит.
