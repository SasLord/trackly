# Phase 41.13 Plan 02: имя и инв. номер USB-хоста в DTO принтера Summary

**`printers_get` / `printers_get_by_device_id` теперь несут `usbHostName` и `usbHostInventoryNo` USB-хоста (в том числе мягко удалённого) через `LEFT JOIN devices h` в `SELECT_PRINTERS`, так что UI сможет показывать имя вместо «устройство #22» (D-08).**

## Accomplishments

- `SELECT_PRINTERS`: добавлены `h.name AS usb_host_name`, `h.inventory_number AS usb_host_inventory_no` (позиции 15 и 16) и `LEFT JOIN devices h ON h.id = p.usb_host_device_id`. Псевдоним `h` не конфликтует с `d`, `p`, `pfp`; запрос списка (`ORDER BY p.id DESC`) и остальные пользователи константы не менялись по составу и порядку строк (LEFT JOIN по FK-полю, дублей не порождает: один хост на принтер).
- `PrinterRow`, `map_row_printer` (`row.get(15)`, `row.get(16)`), `PrinterDto` + `From<PrinterRow>`.
- `ui/src/bindings-phase6.ts`: `usbHostName: string | null`, `usbHostInventoryNo: string | null` сразу после `usbHostDeviceId`.

## Мутационная проверка

- Якорь: `LEFT JOIN devices h ON h.id = p.usb_host_device_id`. Доказательство уникальности ДО мутации (python, `str.count`): якорь - **1** вхождение; более короткая подстрока `devices h ON` - тоже **1**.
- Мутант: `... ON h.id = p.device_id` (подмена колонки, а не удаление JOIN). Результат: `printers_get_returns_usb_host_name_and_inventory_number ... FAILED`, `left: Some("Принтер А")`, `right: Some("Рабочая станция А")`; остальные 8 тестов файла зелёные. То есть тест не вакуумный: фикстура даёт разные строки до и после (имя принтера != имя хоста; у живого принтера без хоста при мутации пришло бы собственное имя вместо None).
- Восстановление: файл возвращён из копии, снятой до мутации; `cmp` - `IDENTICAL`; `git diff --exit-code` по файлу - чисто; затем тест прогнан повторно - зелёный (9/9).
