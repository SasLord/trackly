# Phase 41.13 — UI Design Contract

> Визуальный и интеракционный контракт фазы «Принтеры: подключение к АРМ»: пометка
> происхождения у строк «Подключённых принтеров» в карточке группы, выбор USB-хоста в форме
> устройства, имя хоста вместо сырого `#id` в деталях и списке принтеров.
> Составлен gsd-ui-researcher, проверяется gsd-ui-checker.
>
> **Макета нет, новых экранов нет.** Дизайн-система зафиксирована Фазой 23
> (`ui/src/styles/_tokens.scss`, closed-world гейт `ui/scripts/check-tokens.mjs`), примитивы —
> Фазами 24–25. Этот документ **не переоткрывает** токены и решения `41.13-CONTEXT.md`
> (два механизма, набор устройств в выборе хоста). Новых токенов, hex'ов, шкал, компонентов и
> npm-зависимостей — **ноль**. Фаза правит четыре существующие поверхности.
>
> **Приватность (жёсткое условие проекта, репозиторий публичный):** все примеры ниже
> вымышленные: «АРМ #3», «Стойка #1», «Системный блок #4», «Принтер #1», «инв. 114»,
> «SN AB123». Реальные названия организации, реквизиты, ФИО в код, копирайт, тесты, фикстуры и
> `.planning/`-артефакты не попадают.

## 2. Границы: чего контракт НЕ покрывает

- **Полноценная форма редактирования принтера** и эндпоинт обновления принтера — вне объёма
  (CONTEXT, Deferred). Поле хоста живёт в форме устройства.
- **Расхождение «принтерности»** через `places_group_members` — вне объёма, UI не трогается.
- **Редизайн карточки группы** — запрещён. Таблица «Подключённых принтеров» сохраняет те же
  четыре колонки (Название · Инв. № / Серийный № · Связь · меню).
- **Схема БД, DTO, имена команд и роутов, способ объединения трёх источников на сервере (UNION
  или сборка в сервисе), разбивка на планы** — Claude's Discretion планировщика. Контракт
  задаёт только то, что видит пользователь, и требования к данным (§9).
- **Серверная валидация хоста** (самоссылка, удалённое устройство) — серверная; UI-слой
  ниже — зеркало и подсказка, не граница безопасности.
- **Карта, ранжирование принтеров в заявке** — другие фазы.

## 5. Пометка происхождения в «Подключённых принтерах» (locked: CONTEXT решения 1, 3, 4)

### 5.1 Форма пометки

**Текстовый `Badge` в существующей колонке «Связь»** — колонка и заголовок остаются, значений
становится три. Решение (Claude's Discretion, п. 3 CONTEXT):

| Происхождение | Текст | Вариант | Меню `⋯` |
|---------------|-------|---------|----------|
| принтер подключён по USB к устройству из поддерева группы | `USB` | `accent` (как сейчас) | «Убрать ссылку» — только если есть явная ссылка |
| явная ссылка (свойство типа «Ссылки на устройства») | `Ссылка` | `default` (как сейчас) | «Убрать ссылку» |
| принтер является членом группы (прямым или вложенным) | `В составе` | `default` | **нет** — состав правится в «Составе» группы, не здесь |

Обоснование: бейдж с текстом читается без наведения мыши (условие 3 CONTEXT), не вводит новой
колонки и нового компонента, в обеих темах использует уже проверенные токены. Значок без
текста отвергнут (нужна подсказка наведением), отдельная колонка отвергнута (раздувает
четырёхколоночную таблицу в узкой карточке).

Заголовок колонки — `Связь` (без изменений). Остальные колонки не меняются.

### 5.2 Приоритет при нескольких происхождениях (locked: CONTEXT п. 4; решение записать в SUMMARY)

Одна строка на принтер (дедупликация обязательна). Если происхождений несколько, **показывается
один бейдж по приоритету**:

```
USB  >  Ссылка  >  В составе
```

| Комбинация | Бейдж | Меню |
|------------|-------|------|
| член + USB | `USB` | нет (ссылки нет) |
| член + ссылка | `Ссылка` | «Убрать ссылку» |
| USB + ссылка | `USB` | «Убрать ссылку» (как сейчас, `has_explicit_link`) |
| член + USB + ссылка | `USB` | «Убрать ссылку» |

Обоснование приоритета: чем **явнее** пользовательское утверждение, тем выше. USB-хост —
самое конкретное («воткнут вот сюда»); ссылка — явное решение человека добавить принтер;
членство — следствие того, что принтер просто лежит в составе, и оно уже видно в «Составе».
Порядок сохраняет нынешнее серверное правило «при совпадении побеждает `usb`»
(`GroupPrinterDto.origin`) и лишь добавляет третье значение ниже.

Если происхождений больше одного, у `Badge` выставляется `title` со всеми источниками:
`Также: ссылка, в составе` (перечень без главного). Это **дополнение**, не носитель смысла:
главная пометка читается без наведения.

### 5.3 Порядок строк

Клиент строки **не пересортировывает**: сервер отдаёт их по названию (затем по `device_id`),
независимо от происхождения. Строки ссылок, добавленные в форме до сохранения, по-прежнему
дописываются в конец (унаследованное поведение `GroupPrintersList`).

### 5.4 Данные строки (контракт на DTO, не на схему)

`GroupPrinterDto.origin` расширяется третьим значением (`member` — имя на усмотрение
планировщика; UI мапит его на текст «В составе»). Должен прийти **полный набор источников**
строки (чтобы собрать `title` из §5.2 и не гадать), либо три флага. Клиент не выводит
происхождение сам.

## 6. Пустое состояние «Подключённых принтеров»

Текст `GroupPrintersList.svelte:178` сегодня обещает невозможное и **заменяется**. Новое
поведение: принтер появляется сам, если входит в состав, подключён по USB к устройству состава
или добавлен ссылкой.

| Элемент | Копирайт |
|---------|----------|
| Заголовок | `Принтеров нет` (без изменений) |
| Тело, когда можно добавить ссылку (`canEdit && canLink`) | `Принтер появится здесь, если он входит в состав, подключён по USB к устройству состава или добавлен ссылкой. Сетевой принтер добавьте ссылкой ниже.` |
| Тело, когда ссылку добавить нельзя | `Принтер появится здесь, если он входит в состав или подключён по USB к устройству состава.` |

Предложение «ниже» показывается **только** при наличии поля добавления — иначе текст ссылается
на то, чего на экране нет. Слово «групп*» в тексте не используется (файл в `features/groups`,
но формулировка не должна зависеть от allowlist).

## 7. Поле «Устройство-хост (USB)» в форме устройства

### 7.1 Когда поле видно

| Условие | Поведение |
|---------|-----------|
| тип устройства ≠ «Принтер» | поля нет в DOM |
| тип «Принтер», **создание**, IP-адрес пуст | поле видно |
| тип «Принтер», **создание**, IP-адрес заполнен | поля нет в DOM, значение не отправляется (сетевой принтер USB-хоста не имеет) |
| тип «Принтер», **редактирование** | поле видно, если у принтера нет IP (известно из `printers.getByDeviceId`); блок IP/community при редактировании остаётся скрытым, как сегодня |
| форма `readonly` | поле видно, `disabled` |

Решение (Claude's Discretion): поле доступно **и при редактировании**. Причина: у всех уже
заведённых принтеров `usb_host_device_id` пуст (ROADMAP), а отдельной формы принтера нет;
поле только при создании оставило бы существующие принтеры без способа указать хост. Это
требует, чтобы путь обновления устройства принимал и **сохранял** хост (см. «мину»
`sync_printer_row_in_tx` в CONTEXT). Если планировщик обнаружит, что поддержать
редактирование нельзя в рамках фазы, — это эскалируется, а не молча урезается до создания.

Размещение: внутри блока принтера, **после** IP/community, под тем же разделителем
`border-top`. При редактировании блок содержит только это поле. Порядок в форме остаётся:
… · блок принтера · «Состояние».

### 7.2 Анатомия поля

```
Устройство-хост (USB)
┌──────────────────────────────────────────────────┐
│ Системный блок #4 · инв. 114                  ▾  │
└──────────────────────────────────────────────────┘
Системный блок, в который воткнут принтер. Необязательно.
```

| Свойство | Значение |
|----------|----------|
| Подпись | `Устройство-хост (USB)`; `<label for="f-printer-usb-host">` |
| Компонент | **собственный `Dropdown`**, `variant="select"`, `flat={true}`, поиск в панели включён. **Не** нативный `<select>` и **не** обёртка `Select` (повторное требование пользователя, фазы 27/28) |
| `id` | `f-printer-usb-host` |
| Плейсхолдер | `Не указан` |
| Подсказка под полем | `Системный блок, в который воткнут принтер. Необязательно.` — `--tr-text-label` / `--tr-text-secondary`, отступ от поля `--tr-space-2xs` |
| Строка значения | `Имя` либо `Имя · инв. 114`, если инв. № есть (инв. № различает одноимённые устройства) |
| Сброс значения | первый пункт панели `Не указан` (виден только при пустом запросе); выбор очищает хост |
| `disabled` | при `readonly` формы |
| `invalid` | при ошибке (§7.6) |

### 7.3 Набор устройств и секции (locked: CONTEXT «Набор устройств в выборе USB-хоста»)

Выбор идёт по **всем** устройствам, с поиском, без фильтра по группе, типу, статусу или
месту. Единственное исключение — **само редактируемое устройство** (принтер не может быть
своим хостом); это не фильтр по набору, а защита от самоссылки, и сервер её тоже обязан
отклонять.

Секции панели (заголовки — `getGroupSection`, пустая секция заголовка не рисует, секции
непрерывны — список сортируется по номеру секции до передачи в проп):

| # | Заголовок секции | Что в ней | Когда есть |
|---|------------------|-----------|------------|
| — | (без заголовка) | пункт `Не указан` | только при пустом запросе |
| 1 | `В составе «АРМ #3»` | устройства **той группы, в которой состоит принтер** (прямые и вложенные, плоским списком), отфильтрованные по запросу на клиенте | только если принтер уже состоит в группе (редактирование) |
| 2 | `Все устройства` | результат серверного поиска по всем устройствам, **минус** уже показанные в секции 1 | всегда |

Правила:
- Если принтер **не** состоит в группе (и всегда при создании), секция 1 отсутствует, список
  плоский, **заголовков нет вовсе**.
- Если секция 1 пуста (в группе нет других устройств или запрос ничего в ней не нашёл),
  заголовок `Все устройства` тоже **не рисуется** — единственная секция без заголовка.
- Дедупликация: устройство из секции 1 не повторяется в секции 2.
- Серверный поиск — по префиксу названия / инвентарному / серийному номеру тем же механизмом,
  что в `GroupPrintersList` (`devices.list`, без `type_id`), окно 20 результатов, дебаунс
  `Dropdown` (250 мс, при открытии — сразу).
- Образцы: секции — `getGroupSection` в `ActFormItemsTable.svelte` (`sectionOf` + сортировка по
  `SECTION_ORDER`); панель-список устройств — `GroupPrintersList` (`flat`, `getGroupSub`).
  `GroupedPrinterSelect` в этой задаче не переиспользуется (группирует по месту, а не по
  составу), но прецедент `variant="select"` оттуда берётся.

|-----------|-----------|
| Загрузка | `Dropdown loading` — строка «Загрузка…» в панели (встроенная) |
| Нет результатов | встроенное пустое состояние `Dropdown` |
| Ошибка загрузки списка | список пуст + инлайн-текст под полем (§7.6); форму сохранять можно |
| Хост уже выбран и устройство удалено | значение показывается как `Имя (удалено)`, `--tr-text-secondary`; хост можно сменить или сбросить; сохранение без смены хоста не пытается переписать значение |

### 7.6 Тексты и ошибки

| Случай | Текст | Канал |
|--------|-------|-------|
| Подпись | `Устройство-хост (USB)` | `<label>` |
| Подсказка | `Системный блок, в который воткнут принтер. Необязательно.` | под полем |
| Плейсхолдер / пункт сброса | `Не указан` | поле / панель |
| Заголовки секций | `В составе «АРМ #3»` · `Все устройства` | панель |
| Список не загрузился | `Не удалось загрузить список устройств. Попробуйте ещё раз.` | `.field-error` под полем |
| Сервер отклонил хост (самоссылка, удалено, не найдено) | `Это устройство нельзя выбрать хостом. Выберите другое.` | `.field-error` под полем, `invalid` на `Dropdown` |
| Прочие ошибки сохранения формы | сообщение сервера как есть (унаследовано) | существующий канал формы |

Деструктивных действий фаза не вводит; сброс хоста обратим повторным выбором и подтверждения
не требует.

### 7.7 Клавиатура и ARIA

Полностью унаследованы от `Dropdown` (Фазы 25, 30): открытие по клику/фокусу, `↑`/`↓` по
видимому списку, `Enter` — выбор, `Esc` — закрытие, `aria-activedescendant`; заголовки секций
не фокусируемы и пропускаются. Подпись связана с полем через `for`/`id`. Новых горячих клавиш
нет. Поле находится в обычном порядке табуляции формы между IP/community и «Состоянием».

## 8. Имя хоста в деталях и списке принтеров

### 8.1 Деталь принтера (`PrinterDetail.svelte:435`)

| Элемент | Было | Станет |
|---------|------|--------|
| Подпись строки | `Подключение` | `Подключение` (без изменений) |
| Значение | `Подключён по USB к: устройство #22` | `Подключён по USB к: Системный блок #4 · инв. 114` |

- Формат строки хоста — тот же, что в поле формы: `Имя`, затем ` · инв. ` + номер, если он есть.
  Инв. № внутри значения — в `<span class="tr-mono">` (как инв. № в соседних строках детали).
- Имя — обычный текст, **не** ссылка (деталь не уводит пользователя; переход к устройству —
  отдельная возможность, вне фазы).
- Хост удалён: `Подключён по USB к: Системный блок #4 (удалено)`.
- Имя не удалось определить (устройство не найдено): `Подключён по USB к: устройство не найдено`.
  Сырой `#id` в интерфейсе **не показывается ни при каких условиях**.
- Условие показа строки не меняется: `ipAddress` пуст и `usbHostDeviceId` задан.

### 8.2 Строка списка (`PrinterListRow.svelte:76`)

- Видимый признак остаётся прежним: текст `USB` вместо IP (условие `isUsb` не меняется, логика
  групповых пунктов меню — тоже).
- Добавляется `title` на ячейку: `Подключён по USB к: Системный блок #4`. Это дополнение;
  главный признак (`USB`) читается без наведения.
- Имя хоста приходит готовым с сервера, отдельных запросов из строки списка нет (N+1 запрещён).

## 9. Требования к данным (контракт на DTO, не на схему)

| Поверхность | Что должно прийти с сервера |
|-------------|-----------------------------|
| Строка принтера группы | `device_id`, `name`, инв. №, серийный №, **множество источников** (USB / ссылка / член), признак явной ссылки; строки уже дедуплицированы |
| Деталь и строка списка принтера | `usbHostDeviceId` **и** имя хоста, инв. № хоста, признак «хост удалён» (чтобы не делать второй запрос на каждую строку) |
| Поле хоста в форме | список устройств через существующий `devices.list`; список устройств **группы принтера** (состав с вложенными) — только при редактировании; текущий хост — с именем |
| Сохранение | `usb_host_device_id` в блоке принтера при создании и при обновлении; обновление устройства **без** изменения хоста обязано сохранять уже записанное значение |

Тексты вида «Принтер #1 (3 устройства)» и подобные склейки собирает клиент через
`pluralizeRu`; сервер склеенных подписей не присылает.

## 10. Состояния сводно

| Поверхность | Loading | Empty | Error |
|-------------|---------|-------|-------|
| Принтеры группы | унаследовано (карточка грузится целиком) | §6 | унаследовано |
| Поле хоста | `Dropdown loading` | встроенное пустое состояние `Dropdown`; без секции 1 список плоский | §7.6 |
| Деталь принтера | унаследовано | строка «Подключение» не рисуется, если хоста нет и IP пуст (как сегодня) | `устройство не найдено` (§8.1) |
| Список принтеров | унаследовано | `USB` не показывается без хоста (как сегодня) | — |

**Проверяется только в живом приложении** (компилирующие гейты этого не видят):
1. `Badge` трёх значений в светлой и тёмной теме в карточке группы (десктоп и LAN-браузер);
2. принтер, одновременно член группы и USB-привязанный, даёт **одну** строку с бейджем `USB`;
3. поле хоста: секции видны в нужном порядке при редактировании принтера, состоящего в группе;
   при создании — плоский список без заголовков;
4. выбранный хост переживает последующее редактирование **другого** поля устройства
   (мина `sync_printer_row_in_tx`);
5. после сохранения хоста карточка группы показывает принтер без ручного обновления;
6. новый маршрут/команда отвечают по LAN **телом ответа**, а не `index.html` с кодом 200
   (урок `spa_fallback`); перед проверкой — свежий `pnpm --dir ui build`.

Русский, «вы» без обращения, без восклицательных знаков. Ошибка = что произошло + что делать.

| Empty state heading | `Принтеров нет` |

## 12. Accessibility

- Пометка происхождения — текст в `Badge`: читается диктором как часть строки, не зависит от
  цвета (различимы по тексту), не требует наведения.
- Контраст — только пары Фазы 23; новые пары запрещены; `check-contrast.mjs` обязан остаться
  зелёным. Подсказка поля хоста — `--tr-text-secondary` (смысловой текст, ≥4.5:1), не tertiary.
  Прочерк «—» — tertiary допустим (документированное исключение 3.0:1).
- Меню `⋯` у строки (`ActionMenu`) сохраняет `aria-label` `Действия: <имя принтера>`.
- Поле хоста — `Dropdown` с `aria-activedescendant`, подпись по `for`/`id`, ошибка
  объявляется (`role="alert"` на `.field-error`, как сейчас).
- Ни одного нового нативного `<select>`, ни одного раскрывателя на `div` с `onclick`.

слеп к порядку.

форму устройства) должна сбрасывать кэш карточки группы; планировщику проверить, подпадает ли
она под существующий реестр, и при необходимости добавить запись.

## 15. Решения researcher'а (Claude's Discretion)

| # | Решение | Обоснование | Отвергнутая альтернатива |
|---|---------|-------------|--------------------------|
| R-01 | Пометка = текстовый `Badge` в существующей колонке «Связь» | читается без наведения, ноль новых компонентов/колонок/токенов, обе темы уже проверены | значок без текста (нужен `title`); отдельная колонка «Источник» (раздувает узкую карточку) |
| R-02 | Приоритет `USB > Ссылка > В составе`, один бейдж на строку | явность утверждения: хост конкретнее ссылки, ссылка явнее членства; совпадает с нынешним серверным «побеждает `usb`» | показывать все бейджи сразу (шум, дублирует «Состав» группы); `В составе` выше `Ссылка` (скрывает явное решение человека) |
| R-03 | Бейдж `В составе` нейтральный, акцент остаётся только у унаследованного `USB` | акцент — 10%, членство самое слабое утверждение | акцентный бейдж для всех трёх |
| R-04 | У строки-члена меню `⋯` нет | убрать принтер из состава — действие раздела «Состав», здесь оно было бы вторым путём к одному и тому же | пункт «Вывести из состава» (дублирует и размывает границы) |
| R-05 | Поле хоста доступно и при редактировании | иначе существующие принтеры (у всех хост пуст) нельзя исправить; отдельной формы принтера нет и она вне объёма | только при создании (оставляет данные пользователя без пути) |
| R-06 | Поле скрыто, если у принтера есть IP | сетевой принтер USB-хоста не имеет (D-32: членом одного АРМ он быть не может); совпадает с подсказкой блока SNMP | показывать всегда (два конфликтующих способа подключения) |
| R-07 | `Dropdown variant="select"` + пункт `Не указан` для сброса | у поля есть сохранённое значение, которое нужно показывать и снимать; `combobox` показывает только набираемый запрос | `combobox` как в `GroupPrintersList` (не отображает выбранное); крестик-кнопка (новый паттерн) |
| R-08 | Заголовок секции 1 — `В составе «{имя}»`, секция 2 — `Все устройства`; без секции 1 заголовков нет | совпадает по слову с бейджем «В составе»; единственная секция с заголовком — шум | `Устройства группы …` (тянет слово «групп*» и allowlist вне `features/groups`) |
| R-09 | Само редактируемое устройство исключено из списка | самоссылка бессмысленна; это не фильтр набора, сервер обязан отклонять тоже | не исключать (даёт ошибку после сохранения) |
| R-10 | Строка хоста = `Имя · инв. N`, инв. № в `.tr-mono` в детали | одноимённые устройства («Системный блок») иначе неразличимы | только имя |
| R-11 | Сырой `#id` не показывается нигде; при сбое — `устройство не найдено` | требование CONTEXT (`PrinterDetail:435`), id пользователю ничего не говорит | падение на `#id` как запасной вариант |
| R-12 | Членство считается по поддереву группы (прямые и вложенные), как USB | единый смысл «принтер где-то внутри этого АРМ/стойки»; планировщику подтвердить на сервере | только прямые члены (контейнер «Стойка» с вложенными АРМ показывал бы меньше, чем USB) |
| R-13 | Строки принтеров группы сортирует сервер (название, затем `device_id`), клиент не пересортировывает | предсказуемый порядок независимо от происхождения; нет дрожания при добавлении ссылки | сортировка по происхождению |

### Отложено (не входит в контракт)

- Переход из детали принтера к устройству-хосту ссылкой.
- Полноценная форма редактирования принтера с эндпоинтом обновления.
- Расхождение «принтерности» в `places_group_members`.
- Поле хоста для сетевых принтеров и массовая привязка нескольких принтеров к хосту.
