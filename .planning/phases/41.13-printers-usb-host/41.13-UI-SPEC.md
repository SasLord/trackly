# Phase 41.13 — UI Design Contract

> Контракт фазы «Принтеры: подключение к АРМ»: пометка происхождения у строк «Подключённых
> принтеров» в карточке группы, выбор USB-хоста в форме устройства, имя хоста вместо сырого
> `#id` в детали принтера.
> Составлен gsd-ui-researcher, проверяется gsd-ui-checker.
>
> **Макета нет, новых экранов нет.** Токены, шкалы и примитивы унаследованы от Фаз 23–25 и
> `41.2-UI-SPEC.md` (§3 spacing, §4 typography, §5 color); здесь перечислено только то, что
> вводит эта фаза. Новых токенов, hex'ов, компонентов и npm-зависимостей — **ноль**.
>
> **Приватность (репозиторий публичный):** все примеры вымышленные («АРМ #3», «Системный блок
> #4», «Принтер #1», «инв. 114», «SN AB123»). Реальные названия организации, реквизиты и ФИО в
> код, копирайт, тесты, фикстуры и `.planning/` не попадают.

## 3. Пометка происхождения в «Подключённых принтерах»

### 3.1 Форма

Текстовый `Badge` в существующей колонке «Связь» (заголовок и остальные три колонки без
изменений). Читается без наведения мыши, работает в обеих темах.

| Происхождение | Текст | Вариант | Меню `⋯` |
|---------------|-------|---------|----------|
| USB-привязка к устройству из поддерева группы | `USB` | `accent` (как сейчас) | «Убрать ссылку» — только при `has_explicit_link` |
| явная ссылка (свойство типа «Ссылки на устройства») | `Ссылка` | `default` (как сейчас) | «Убрать ссылку» |
| член группы (прямой или вложенный) | `В составе` | `default` | **нет** — состав правится в «Составе» группы |

### 3.2 Приоритет (запись в SUMMARY обязательна)

Одна строка на принтер, **один бейдж**, один источник в DTO:

```
USB  >  Ссылка  >  В составе
```

Приоритет применяет сервер при дедупликации (продолжение нынешнего «при совпадении побеждает
`usb`»); `has_explicit_link` остаётся отдельным флагом и по-прежнему включает пункт «Убрать
ссылку», даже когда виден бейдж `USB`. Основание порядка: чем явнее пользовательское
утверждение, тем выше — хост конкретнее ссылки, ссылка явнее членства (членство и так видно
в «Составе»).

Клиент: строки принтера строятся из **всех** трёх происхождений, не только `usb`; ссылка,
добавленная в форме до сохранения на принтер-члена, переключает бейдж строки на `Ссылка`
(тот же приоритет).

### 3.3 Состав набора и порядок

- Членство считается по **поддереву** группы (прямые члены и члены вложенных групп) — тем же
  рекурсивным обходом, что `usb_printers_for_group` (`SUBTREE_CTE`,
  `crates/trackly-infra/src/repos/groups_sqlite.rs:38` и `:621`). Это требование к новому
  запросу, а не гипотеза: у USB- и «членских» принтеров один и тот же смысл «внутри этого
  АРМ/стойки».
- Сервер отдаёт строки по названию, затем по `device_id`; клиент не пересортировывает
  (ссылки, добавленные в форме до сохранения, дописываются в конец, как сейчас).

### 3.4 Пустое состояние (текст `GroupPrintersList.svelte:178` заменяется)

| Элемент | Копирайт |
|---------|----------|
| Заголовок | `Принтеров нет` (без изменений) |
| Тело, когда есть поле добавления ссылки (`canEdit && canLink`) | `Принтер появится здесь, если он входит в состав, подключён по USB к устройству состава или добавлен ссылкой. Сетевой принтер добавьте ссылкой ниже.` |
| Тело, когда поля добавления нет | `Принтер появится здесь, если он входит в состав или подключён по USB к устройству состава.` |

«Ссылкой ниже» показывается только при наличии поля — иначе текст ссылается на то, чего на
экране нет.

## 4. Поле «Устройство-хост (USB)» в форме устройства

### 4.1 Когда поле видно (locked: решение пользователя, 2026-10-28)

Поле доступно **и при создании, и при редактировании** устройства. Основание: у всех уже
заведённых принтеров хост пуст, отдельной формы принтера нет; без режима редактирования
фаза не починит ни одной существующей записи.

| Условие | Поведение |
|---------|-----------|
| тип ≠ «Принтер» | поля нет в DOM |
| «Принтер», создание, IP пуст | поле видно |
| «Принтер», создание, IP заполнен | поля нет в DOM; хост не отправляется (§4.6) |
| «Принтер», редактирование, у принтера нет IP | поле видно, блок IP/community скрыт, как сегодня |
| «Принтер», редактирование, у принтера есть IP | поля нет |
| форма `readonly` | поле видно, `disabled` |

**Следствия для объёма — часть контракта:**
1. Серверный путь **обновления** устройства принимает `usb_host_device_id` в блоке принтера и
   сохраняет его; обновление, в котором хост не менялся, уже записанное значение не затирает.
2. Форма редактирования подгружает текущий хост (имя и инв. № хоста — для строки значения,
   §4.2) тем же источником, что деталь принтера.
3. Сервер отклоняет ссылку устройства на самого себя, а также несуществующий и удалённый хост
   (текст ошибки — §4.5).

Размещение: внутри блока принтера, после IP/community, под тем же разделителем `border-top`;
при редактировании блок содержит только это поле. Порядок формы: … · блок принтера ·
«Состояние».

### 4.2 Анатомия

```
Устройство-хост (USB)
┌──────────────────────────────────────────────────┐
│ Системный блок #4 · инв. 114                     │
└──────────────────────────────────────────────────┘
Системный блок, в который воткнут принтер. Необязательно.
```

| Свойство | Значение |
|----------|----------|
| Подпись | `Устройство-хост (USB)`; `<label for="f-printer-usb-host">` |
| Компонент | собственный `Dropdown` (конфигурация — §4.3). **Не** нативный `<select>` и **не** обёртка `Select` |
| `id` | `f-printer-usb-host` |
| Плейсхолдер | `Не указан` |
| Подсказка | `Системный блок, в который воткнут принтер. Необязательно.` |
| Строка значения (в поле и в детали) | `Имя`, либо `Имя · инв. 114`, если инв. № есть (одноимённые устройства иначе неразличимы) |
| Сброс | первый пункт панели `Не указан`, виден только при пустом запросе |
| `disabled` / `invalid` | при `readonly` формы / при ошибке сервера |

### 4.3 Конфигурация `Dropdown` и механизм поиска

**Берётся `variant="combobox"`, `flat={true}`** (проп `searchable` относится к `select` и не
задаётся). Это не вкусовой выбор, а следствие исходника `Dropdown.svelte`:

| Конфигурация | Что происходит | Годится? |
|--------------|----------------|----------|
| `select` + `flat` + `searchable` | при непустом запросе включается **клиентский фильтр по имени** (`Dropdown.svelte:293-296`: `getGroupName(g).toLowerCase().includes(q)`) и скрывает результаты сервера, найденные по инв. или серийному № | нет |
| `flat={false}` (любой `variant`) | работает авто-схлопывание AUTO-05 (`Dropdown.svelte:170-190`): единственная оставшаяся запись **раскрывается как группа** через `onExpandGroup`, панель переходит в режим членов с заголовком-карточкой; у каждой строки рисуются счётчик `×N` и шеврон; подстрока не моноширинная | нет |
| `combobox` + `flat` | клиентского фильтра нет (`variant !== 'select'`), AUTO-05 не запускается (`if (flat) return`), подстрока `.tr-mono`, галочка у выбранного, секции работают | **да** (образец — `GroupPrintersList`) |

**Кто фильтрует:**
- **Секция «Все устройства» — сервер.** Запрос уходит через `onSearch`: при открытии/фокусе
  сразу, при вводе — после внутреннего дебаунса `Dropdown` в 250 мс (`scheduleSearch`). Поиск
  ведётся существующим `devices.list` тем же FTS5-механизмом, что в пикере акта, — по
  названию, инвентарному и серийному №; окно 20 результатов; фильтров по типу, статусу и месту
  нет. **Проверено оркестратором:** `devices_fts` объявлен как
  `fts5(name, inventory_number, serial_number, model, content='devices')` —
  `migrations/V012__indexes_and_fts.sql:40-44`, то есть инвентарный и серийный № покрыты, и
  `build_fts_query` (`crates/trackly-infra/src/repos/devices_sqlite.rs:338`) превращает каждый
  токен в префиксный `"tok"*`. Имя поля фильтра (`name_prefix`) вводит в заблуждение, но
  индексируются все четыре колонки. Открытого вопроса здесь больше нет.
- **Секция «В составе «…»» — клиент.** Её содержимое загружается один раз при открытии формы;
  по запросу фильтруется подстрокой (без учёта регистра) по названию, инв. и серийному №.
  Это фильтр самой фазы, а не `Dropdown`: клиентского фильтра по имени внутри `Dropdown` в
  выбранной конфигурации **нет**.
- Выбранный хост показывается в поле, пока панель закрыта; при фокусе запрос, равный строке
  текущего значения, трактуется как **пустой** (иначе открытие панели искало бы «Системный
  блок #4 · инв. 114» и ничего не находило). Уход с поля без выбора возвращает в поле строку
  текущего значения.

### 4.4 Набор устройств и секции (locked: CONTEXT «Набор устройств в выборе USB-хоста»)

Выбор по **всем** устройствам, с поиском, без жёсткого фильтра по группе, типу, статусу или
месту. Единственное исключение — само редактируемое устройство (самоссылка, §4.1 п. 3).

**Факт схемы:** устройство состоит максимум в одной группе —
`migrations/V045__groups.sql:93`, `group_devices.device_id INTEGER PRIMARY KEY`. Правила для
«принтера в нескольких группах» не нужны. Группы при этом вложенные, поэтому в секцию 1
входит **поддерево группы принтера**: её собственные члены плюс члены вложенных групп, плоским
списком, без самого принтера (тот же обход, что в §3.3).

| # | Заголовок секции | Что в ней | Когда есть |
|---|------------------|-----------|------------|
| — | (без заголовка) | пункт `Не указан` | только при пустом запросе |
| 1 | `В составе «АРМ #3»` | устройства поддерева группы принтера | только при редактировании принтера, состоящего в группе, и если после фильтра в секции есть строки |
| 2 | `Все устройства` | результат серверного поиска минус показанное в секции 1 | всегда; заголовок рисуется **только если** в текущем списке есть строки секции 1 |

Заголовки — через `getGroupSection`; секции непрерывны (список сортируется по номеру секции
до передачи в проп); пункт сброса и «безымянная» секция 2 возвращают `undefined`. Образец —
`sectionOf` и сортировка по `SECTION_ORDER` в `ActFormItemsTable.svelte`.

**Что происходит, когда поиск оставил одну секцию.** `Dropdown` рисует заголовок любой секции,
чьё значение определено и отличается от предыдущего видимого элемента (`sectionHeadingAt`,
`Dropdown.svelte:~405`), — в том числе у единственной. Поэтому:
- осталась только секция 1 — заголовок `В составе «АРМ #3»` **остаётся** (он сообщает, откуда
  строки); это нормально и не подавляется;
- осталась только секция 2 (или принтер не состоит в группе, или создание) — заголовок
  `Все устройства` **подавляется** правилом выше; список плоский, без заголовков.
AUTO-05 в этой конфигурации не участвует (§4.3).

### 4.5 Пункт панели, состояния, тексты

| Слот | Содержимое | Пример |
|------|------------|--------|
| имя | название устройства | `Системный блок #4` |
| подстрока (`getGroupSub`, `.tr-mono`) | `инв. 114 · SN AB123` (то, что есть) | `инв. 114 · SN AB123` |
| счётчик / раскрываемость | `0` / `false` (в `flat` не рисуются) | — |
| выбранный | галочка `isGroupSelected` для текущего хоста | — |

| Состояние / случай | Поведение и текст |
|--------------------|-------------------|
| Загрузка | встроенная строка «Загрузка…» (`loading`) |
| Нет результатов | встроенное «Ничего не найдено» |
| Список не загрузился | список пуст + `.field-error` под полем: `Не удалось загрузить список устройств. Попробуйте ещё раз.`; форму сохранять можно |
| Сервер отклонил хост | `.field-error` + `invalid`: `Это устройство нельзя выбрать хостом. Выберите другое.` |
| Прочие ошибки сохранения | сообщение сервера (унаследовано) |

Деструктивных действий нет; сброс хоста обратим повторным выбором, подтверждения не требует.

### 4.6 Что происходит с выбранным хостом при скрытии поля

| Действие пользователя | Состояние хоста | Сообщение |
|-----------------------|-----------------|-----------|
| вводит IP при уже выбранном хосте (создание) | поле уходит из DOM; значение **остаётся** в состоянии формы, но пока IP непуст **не отправляется** | нет |
| стирает IP обратно | поле возвращается с прежним значением | нет |
| меняет тип с «Принтер» на другой | блок принтера уходит из DOM, хост не отправляется; значение в состоянии формы сохраняется до закрытия формы | нет |
| возвращает тип «Принтер» | поле возвращается с прежним значением | нет |

Пользователю об этом **не сообщается**: исчезновение поля и есть сигнал, альтернативы
(IP-подключение vs USB) взаимоисключающи, а подсказка блока SNMP уже говорит «оставьте пустым
для USB». Тихое сохранение значения в состоянии формы защищает от потери выбора при случайном
наборе IP. При редактировании IP вводить нельзя, поэтому первых двух строк там нет; смена типа
уже заведённого принтера и судьба его строки в `printers` — существующее поведение, фаза его не
меняет.

### 4.7 Клавиатура и ARIA

Унаследованы от `Dropdown` (Фазы 25, 30): открытие по фокусу, `↑`/`↓`, `Enter` — выбор,
`Esc` — закрытие, `aria-activedescendant`; заголовки секций не фокусируемы. Подпись связана с
полем через `for`/`id`; ошибка — `role="alert"`. Новых горячих клавиш нет; поле стоит в
обычном порядке табуляции между IP/community и «Состоянием».

| Было | Станет |
|------|--------|
| `Подключён по USB к: устройство #22` | `Подключён по USB к: Системный блок #4 · инв. 114` |

- Формат строки хоста — тот же, что в поле (§4.2); инв. № — в `<span class="tr-mono">`.
  Имя — обычный текст, не ссылка.
- Имя хоста приходит в DTO принтера готовым (отдельного запроса из детали нет).
- Сырой `#id` в интерфейсе **не показывается ни при каких условиях**. Если имя в ответе
  отсутствует, строка выводит `Подключён по USB` без «к: …».
- Условие показа строки не меняется: `ipAddress` пуст и `usbHostDeviceId` задан.

## 6. Требования к данным (контракт на DTO, не на схему)

| Поверхность | Что должно прийти |
|-------------|-------------------|
| Строка принтера группы | `device_id`, `name`, инв. №, серийный №, **одно** происхождение (`usb` / `link` / `member` — имя значения на усмотрение планировщика) с уже применённым приоритетом, флаг `has_explicit_link`; строки дедуплицированы |
| Деталь принтера и форма редактирования | `usbHostDeviceId`, имя и инв. № хоста |
| Поле хоста | устройства через существующий `devices.list`; устройства поддерева группы принтера — только при редактировании |
| Сохранение | `usb_host_device_id` в блоке принтера при создании **и** обновлении (§4.1) |

## 8. Проверяется глазами в живом приложении

Компилирующие гейты этого не видят:
1. `Badge` трёх значений в светлой и тёмной теме в карточке группы (десктоп и LAN-браузер).
2. Принтер, одновременно член группы и USB-привязанный, даёт **одну** строку с бейджем `USB`.
3. Поле хоста при редактировании принтера, состоящего в группе: секция «В составе» первой;
   при создании — плоский список без заголовков; поиск по инвентарному и серийному № находит
   устройство, у которого название запрос не содержит.

## 10. Решения researcher'а (Claude's Discretion)

| # | Решение | Обоснование |

| R-01 | Пометка — текстовый `Badge` в колонке «Связь» | читается без наведения, ноль новых колонок/компонентов, обе темы проверены. Отвергнуто: значок без текста, отдельная колонка |
