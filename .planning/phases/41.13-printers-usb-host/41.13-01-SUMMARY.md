# Phase 41.13 Plan 01: принтеры в составе группы Summary

**Принтер, состоящий в группе (в том числе во вложенной), попадает в «Подключённые принтеры» карточки как origin = member; при нескольких происхождениях сервер отдаёт одну строку по приоритету USB > ссылка > в составе.**

## Accomplishments

- `member_printers_for_group` в `groups_sqlite.rs`: SUBTREE_CTE + `group_devices` + живые `devices` + `JOIN printers`, один параметр через `rusqlite::params`, сортировка `d.name, d.id`.
- `group_service.rs`: третий цикл `member` после цикла `live_refs`, общий `seen`; `has_explicit_link` считается независимо (`explicit.contains`).
- `GroupPrinterDto`: doc-комментарии обновлены (`usb | link | member`, приоритет). Тип поля не менялся (String), bindings не затронуты.

## Выбранный приоритет и порядок циклов

Приоритет: USB > ссылка > в составе. Реализован ПОРЯДКОМ циклов (кто первым вставил device_id в `seen`, тот победил):

1. `for r in repo.usb_printers_for_group(...)` -> "usb"
2. `for r in live_refs` (если принтер) -> "link"
3. `for r in repo.member_printers_for_group(...)` -> "member"

Итоговая сортировка (название, затем device_id) не менялась.

## Мутационная проверка

### Задача 1 (репозиторий)

- Якорь с контекстом нового метода: `"JOIN devices d ON d.id = gd.device_id AND d.deleted_at_utc IS NULL\n              JOIN printers p ON p.device_id = d.id"`.
- Доказательство уникальности ДО мутации (python, `source.count`): голая подстрока `JOIN printers p ON p.device_id = d.id` встречается **2** раза (вторая - в `live_printer_device_ids`, как и предупреждал план); выбранный якорь с контекстом - **1** раз.
- Мутант: `JOIN printers` -> `LEFT JOIN printers` в `member_printers_for_group`. Результат: `member_printers_follow_membership_including_nested_group ... FAILED`, `18 passed; 1 failed`, exit=101 (в результат попало обычное устройство).
- Восстановление: файл возвращён из копии, снятой до мутации; `cmp` - `IDENTICAL`, `grep -c "LEFT JOIN printers"` = 0; после этого тест прогнан повторно - зелёный.
