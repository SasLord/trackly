# Phase 41.13 Plan 07: отправка USB-хоста, имя в детали принтера, гейт Summary

**Выбранный USB-хост уходит на сервер при создании (блок принтера) и правке (патч только при касании поля), блокирует «Количество», ошибка поля показывается фиксированным текстом, деталь принтера печатает имя и инв. № вместо `#id`; конфигурация поля охраняется гейтом с 22 мутантами. Компиляция, lint и сборка зелёные, поведение в рантайме НЕ проверено.**

## Как хост уезжает на сервер

**Создание** (`submitSingleCreate`, `DeviceFormBody.svelte`). Блок принтера собирается так:
- не принтер -> `null`;
- принтер с непустым IP -> прежний `{ ipAddress, community }` БЕЗ хоста (при непустом IP поле скрыто, значение `usbHost` остаётся в состоянии, но не уходит);
- принтер с пустым IP и выбранным хостом -> `{ ipAddress: null, community: null, usbHostDeviceId: usbHost.id }`;
- принтер с пустым IP без хоста -> `null`.

**Правка** (`submitEdit`). Три состояния различаются наличием ключа в `DevicePatch`:
- «не трогать» - ключа `usb_host_device_id` в патче нет (поле не касались ИЛИ оно скрыто / тип не принтер);
- «поставить / заменить» - `usb_host_device_id: <число>`;
- «сбросить» - `usb_host_device_id: null` (выбран пункт «Не указан»).
Ключ присваивается только внутри `if (usbHostTouched && typeId === PRINTER_TYPE_ID && showUsbHost)`; `usbHostTouched` ставится в `pickHost`.

**Количество.** В `quantityDisabled` добавлен дизъюнкт `(typeId === PRINTER_TYPE_ID && usbHost !== null)`. Голого `inventoryNo.trim() !== ''` он не содержит, $effect сброса количества и ветка `devices.bulkCreate` не менялись (в `git diff` из них только мой комментарий со словом `bulkCreate`).

## Ошибка поля

В `handleSubmit`, ветка `err.code === 'VALIDATION' && err.details?.field === 'usb_host_device_id'`, ставит `fieldErrors.usb_host_device_id = HOST_REJECTED_ERROR` («Это устройство нельзя выбрать хостом. Выберите другое.») и такой же тост; серверный `message` для этого поля не показывается (T-41.13-23). Под полем рисуется `<p class="field-error" role="alert">`, Dropdown получает `invalid`. Ошибка снимается при выборе другого значения (`pickHost`) и при новой отправке.

**Форма ошибки совпадает с доказанной планом 04:** тот доказал HTTP-ответ 400 с телом-объектом `{ code: "VALIDATION", details: { field: "usb_host_device_id" } }` (Case 87) и `Validation(usb_host_device_id)` в тестах T2/T3/T7/T8/T9. Клиент читает ровно `code === 'VALIDATION'` и `details.field`, как и прежний код ветки. Совпадение проверено чтением кода и теста, живая отправка отказа из формы НЕ запускалась.

## Что печатает деталь принтера

Ветка `{:else if printer.usbHostDeviceId}` (условие не менялось): при непустом `usbHostName` - «Подключён по USB к: <имя>», при наличии `usbHostInventoryNo` дописывается « · инв. » и значение в `<span class="tr-mono">`; при пустом имени - «Подключён по USB». Шаблон «устройство #» и вывод числа убраны. `PrinterListRow.svelte` не трогался.

## Мутационная проверка гейта

**Selftest (22 мутанта + зелёный контроль на копиях в памяти).** Каждый мутант строится через `mutate()`, который бросает ошибку, если якорь встречается не ровно 1 раз; selftest запускался и не бросил ни разу, т.е. для всех 22 якорь уникален. Мутанты: A - `combobox->select`, снятие `flat={true}`, снятие `getGroupSection`, тег `<Select>` вместо `<Dropdown>`; B - снятие `usbHostTouched` из условия, ПЕРЕСТАНОВКА присваивания перед условием, снятие `showUsbHost` из условия; C - удаление `usbHostDeviceId`, ПЕРЕСТАНОВКА хоста в ветку с IP; D - `usbHost` убран из `quantityDisabled`; E - `{#if !isEdit && showUsbHost}`, `{#if true}`; F - вставка `member_of_group_id`; G - «устройство #», сырой `usbHostDeviceId` в разметке, замена `usbHostName`; H - `sectionFor` без `hasSectionOne`, ПЕРЕСТАНОВКА ветвей тернарника, переименование вызова `isUsbHostFieldVisible(`, снятие `export`; нет instance-`<script>`; ловушка `/*` внутри `//`. Зелёный контроль: запретные токены внутри комментариев (в том числе HTML) не краснят.

Два первых прогона selftest дали честные красные: (12) `{#if true}` не ловился, потому что E проверял «любое охватывающее условие содержит showUsbHost» (внешнее условие содержит) - правило ужесточено до БЛИЖАЙШЕГО охватывающего условия; (21) мутант с подменой первого `</script>` ломал модульный, а не instance-блок - мутант переписан (подмена последнего `</script>`). Первая редакция гейта также не видела `<script module>` - исправлено сбором всех блоков `<script>`.

## Deviations from Plan

**1. [Rule 2 - критичная мелочь] Снятие ошибки хоста при выборе другого значения и тост с фиксированным текстом.** План требовал текст под полем; без снятия при `pickHost` красная ошибка висела бы до следующей отправки, а серверный `message` просочился бы в тост мимо подмены (T-41.13-23). Добавлено в `pickHost` и `handleSubmit`.

**2. [Rule 1 - доработка гейта по итогам собственного selftest]** см. выше (ужесточение правила E, сбор всех блоков `<script>`, пересборка мутанта 21). Правило (C) дополнено проверкой, что `usbHostDeviceId` стоит в ветке, условие которой упоминает `usbHost` (иначе перестановка хоста в IP-ветку оставалась бы зелёной).

**3. Правило (H)**: в плане сказано «sectionFor содержит литерал 'Все устройства'»; фактически литерал лежит в константе `SECTION_ALL`, а `sectionFor` возвращает её. Гейт требует `export const SECTION_ALL = 'Все устройства'` и условие `hasSectionOne` в теле `sectionFor` с правильным порядком ветвей.

Иных отклонений нет.
