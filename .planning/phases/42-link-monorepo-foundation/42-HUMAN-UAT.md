# Фаза 42: отложенная human-UAT

Пункты требуют живой Windows-среды или реальных данных. Фаза 42 закрывается без них (D-07), но пункт 1 блокирует планирование Фазы 45. Все данные в документе обезличены; результаты записывать без имён, адресов и реквизитов.

## 1. Пилот DST-06 (блокирует планирование Фазы 45)

- **Что открыть:** `docs/pilot/README.md`, сборка из артефакта `trackly-link-0.1.0-nsis` dry-run `release-link.yml`, скрипты `install-silent.ps1` и `diag.ps1`.
- **Условие:** 2-3 ПК без прав администратора и один RDS-сервер с несколькими сеансами; на части ПК включены AppLocker/SRP (Enforce и Audit).
- **Ожидаемо:** чек-лист из README заполнен; запуск из `%LOCALAPPDATA%\Programs\Trackly Link\` даёт события 8002/8003 и не даёт 8004; итог оформлен в `docs/pilot/RESULT.md` по шаблону.
- **Как воспроизвести отклонение:** запустить `trackly-link.exe` под AppLocker в режиме Enforce с правилом, запрещающим пользовательские каталоги, и найти событие 8004 в журнале AppLocker.

- **Результат (2026-11-26):** ОТЛОЖЕН пользователем — установка скриптами и пилот в следующих фазах; Фаза 45 по-прежнему не планируется без него.

## 2. Окно Link и запоминание положения

- **Что открыть:** установленный `trackly-link.exe`.
- **Ожидаемо:** видны компоненты `LinkLogo` (слева вверху), `Tabs` с вкладкой «Чат» справа от логотипа, `aside`-сайдбар, `StatusLine` с версией Link, версией WebView2 и путём. После закрытия и повторного открытия размер и положение окна восстановлены.
- **Как воспроизвести отклонение:** перед закрытием задать размер, отличный от 1000x700, и сместить окно к краю экрана; при повторном открытии окно с размером 1000x700 по центру означает, что `tauri-plugin-window-state` не сохранил состояние.

- **Результат (2026-11-26):** passed со слов пользователя — Link установлен обычной установкой на Windows, работает.

## 3. CSP и IPC в WebView2

- **Что открыть:** то же окно `trackly-link.exe`, на чистом ПК без предустановленного WebView2 и на ПК с ним.
- **Ожидаемо:** окно не белое, `StatusLine` заполнена версиями и путём (допущение A10: команда `link_info` проходит по IPC под принятой CSP).
- **Как воспроизвести отклонение:** белое окно или пустая служебная строка означают блокировку CSP или IPC; открыть DevTools (если включены) и посмотреть консоль на нарушения CSP.

- **Результат (2026-11-26):** passed со слов пользователя — окно не белое, приложение работает (чистый ПК без WebView2 отдельно не проверялся).

## 4. Фактический путь установки NSIS

- **Что открыть:** `install-silent.ps1 -Installer <установщик>` без прав администратора.
- **Ожидаемо:** `trackly-link.exe` лежит в `%LOCALAPPDATA%\Programs\Trackly Link\` (при явном `/D=`), в HKCU есть запись удаления, создан ярлык.
- **Как воспроизвести отклонение:** запустить установщик без `/D=`; штатный путь NSIS `currentUser` отличается (`%LOCALAPPDATA%\Trackly Link`). Зафиксировать фактический путь и сверить с каноническим из ADR 0005.

- **Результат (2026-11-26):** ОТЛОЖЕН пользователем вместе с пилотом (установка скриптами — в следующих фазах).

## 5. Десктопная сборка Trackly после переезда (UNVERIFIED, допущение D-21)

- **Что открыть:** десктопная сборка Trackly (`cargo tauri dev` или собранный установщик), не LAN-браузер.
- **Ожидаемо:** вход и выход работают через Tauri-invoke ветку пакета `packages/transport`; при протухшей сессии срабатывает `onUnauthorized` и показывается экран входа; блок вложений открывает просмотр.
- **Как воспроизвести отклонение:** завершить сессию на стороне сервера (например, удалить её в таблице сессий вымышленного пользователя) и выполнить любое действие; без перехода на экран входа хук 401 не подключён.

- **Результат (2026-11-26):** passed со слов пользователя — «в самом Trackly всё по-прежнему, ничего не сломалось».

## 6. Карточка с вложениями и 403 в LAN-браузере на реальных данных

- **Что открыть:** сервер Trackly с собранным `ui/dist`, раздел «Устройства», карточка устройства с блоком вложений, затем LAN-браузер с другого ПК.
- **Условие:** в БД есть устройство с загруженным вложением (в БД стенда устройств не было, поэтому пункт не проверен машинно); есть пользователь с ролью, которой запрещено действие над этим устройством.
- **Ожидаемо:** блок вложений отображается, просмотр открывается без `console.error` и без 404 на ассеты; запрещённое действие даёт ответ 403 и срабатывает `onForbidden` (понятное сообщение, без белого экрана).
- **Как воспроизвести отклонение:** войти пользователем с ограниченной ролью, открыть карточку и выполнить запрещённое действие; отсутствие сообщения означает, что хук 403 не подключён в транспорте.

- **Результат (2026-11-26):** принят со слов пользователя по общей проверке Trackly в Windows-сети; сценарий 403 отдельно не прогонялся.
