    Add two props to the `Props` interface: `framed?: boolean` (default `true`) and
    `footer?: Snippet` (default `undefined`, not rendered when absent — same `{#if footer}...{@render footer()}{/if}`
    guard as `Modal.svelte`'s `footer`).

    Wrap the existing `<div class="tr-table-wrapper">...</div>` in a new outer
    `<div class="tr-table-framed" class:framed>` and render the optional footer as a sibling
    `<footer class="tr-table-footer">{@render footer()}</footer>` INSIDE that same outer div, after
    the wrapper div closes (so the footer sits inside the frame, below the scroller, per UI-SPEC §3.14/У:104-137).

    `.tr-table-framed.framed` styles: `border:1px solid var(--tr-border); border-radius:8px;
    overflow:hidden; box-shadow:var(--tr-elev-1);`. When `framed` is `false`, none of these rules
    apply (plain unstyled wrapper div — do not use `display:contents`, since the footer needs to be
    a flex/block sibling of the table wrapper either way).

    `.tr-table-footer` styles (§3.14, У:137): `padding:9px 14px; border-top:1px solid var(--tr-border);
    font-size:13px; color:var(--tr-text-secondary); background:var(--tr-bg);`.

    Do NOT merge `.tr-table-framed`'s `overflow:hidden` with `.tr-table-wrapper`'s existing
    `overflow-x:auto` (line 72) — these are two different elements serving two different purposes
    (rounded-corner clipping vs. horizontal table scroll) per UI-SPEC §3.14's explicit warning.
  </action>
