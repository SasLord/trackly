  <what-built>
    Two windows matching Claude Design's mockup (Дашборд, Устройства) on a shared adaptive admin
    shell (Layout/Sidebar/PageHeader/Table-frame), across both light and dark themes, from
    ~1440px desktop down to ~480px mobile widths, with all pre-existing filter/CRUD/CSV/print
    functionality unchanged.
  </what-built>
  <how-to-verify>
    Run the app in BOTH modes: (a) `cargo tauri dev` for the desktop webview, (b) after
    `pnpm --dir ui build`, launch server mode and open the LAN URL in a regular browser (fresh build
    required — stale `ui/dist` is a known gotcha). For EACH mode, EACH theme (toggle via
    «Оформление» in the sidebar footer), and EACH width (1440 / 1200 / 900 / 480px), check:

    1. **Дашборд** (`#/dashboard` or equivalent route): PageHeader fixed 56px, period selects match
       §3.9, stat row of 4 cards (30px/700 numbers, pill breakdowns, «Низкий остаток» warning still
       shows in Cartridges card retoned to `--tr-warning-soft`), full-width chart below with
       `#3b6fe0`/`#1a9d5f`/`#d8820e` bar colors, legend below a `border-top` divider. Confirm NO
       "+ Создать акт" button exists (D-03) and NO fabricated "Низкий остаток %"/"Последние заявки"/
       "Мониторинг картриджей" panels exist (D-01) — this is intentional, not a gap.
    2. **9px value-label legibility (dark theme only, §5/§12 п.6):** zoom to 100% on a real screen
       (not a scaled screenshot) and read the small numbers printed just above each chart bar. If
       illegible, apply the ONE documented fallback: bump `font-size="9"` → `font-size="11"` in
       `ChartWidget.svelte` and record this as accepted deviation O-11 in the SUMMARY — do NOT use
       10px.
    3. **Error string parity:** stop the backend (or disable network) with the dashboard open,
       confirm BOTH the stat-card error and the chart error show the identical string "Не удалось
       загрузить. Смените период или обновите страницу." (§9) — a mismatch between the two is a gap.
    4. **Устройства** (`#/devices`): PageHeader wrap variant (16px/24px padding, flex-wrap on
       narrow widths), filters row using `Input`+magnifier icon / `Tabs` underline / `Checkbox`,
       table wrapped in the new border+radius8+elev-1 frame with the "Показано N из M"/"Групп: N"
       footer inside that frame. Click all 5 status tabs, type a search term (confirm ~250ms debounce
       before the list refreshes), toggle "Группировать похожие", create/edit/delete a device, run
       CSV import and export, print an acceptance document — every one of these must behave exactly
       as before this phase (SC #3).
    5. **Dark-theme border legibility (§8 п.2, the phase's single highest visual risk):** in dark
       theme specifically, confirm the stat-card borders, chart-card border, and table frame border
       are visibly distinguishable from the `--tr-surface` body behind them — `--tr-elev-1`'s shadow
       is nearly invisible in dark theme, so `--tr-border` alone must do the separating work. If cards
       visually merge into the background, this is a BLOCKER gap, not an accepted deviation.
    6. **Mobile drawer (< 1024px, both windows):** click the burger, confirm the sidebar slides in
       with a backdrop, Escape/backdrop-click/any-nav-link-click closes it, focus moves to the first
       nav link on open and returns to the burger on close, and the closed panel does not receive
       keyboard focus (Tab) while hidden.
    7. **Table consumer regression (§12 п.8):** open the design-system showcase's Table section
       (`TableSection.svelte`, admin-only route) and confirm it now also shows the new framed border
       — this is an accepted IMPROVEMENT (UI-SPEC §6.5), not a regression, as long as its rows/content
       are otherwise unchanged.
    8. **Accepted deviations — do NOT log these as defects:** the seven untouched windows now showing
       cards that blend into the newly-`--tr-surface` body (D-13); `Tabs`'s 4px tab gap vs the
       mockup's 2px (O-1); `Checkbox`'s 10px gap vs the mockup's 9px (O-2); `Checkbox`'s label color
       vs the mockup's (O-3). See UI-SPEC §10 for the full accepted-deviation list (O-1..O-11).
  </how-to-verify>
