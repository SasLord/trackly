# Phase 41.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Derived from `41.1-RESEARCH.md` § Validation Architecture. JS test runner is forbidden in this project (decided in Phase 41 VALIDATION) — UI behaviour is covered by structural `node` gates plus live human verification.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Rust: `cargo test` (libtest, `#[tokio::test]` for services). UI: `svelte-check`, `eslint` + `prettier`, zero-dependency `node ui/scripts/check-*.mjs` wired into `pnpm lint` |
| **Config file** | `/Cargo.toml` (workspace), `ui/package.json` (`lint`), `clippy.toml` |
| **Quick run command** | `TRACKLY_AD_MOCK=1 TRACKLY_SNMP_MOCK=1 cargo test -p trackly-app --test <file>` · `cargo test -p trackly-infra --test <file>` · `node ui/scripts/check-<gate>.mjs [--selftest]` |
| **Full suite command** | `cargo test --workspace --no-fail-fast -- --test-threads=1` + `pnpm --dir ui svelte-check && pnpm --dir ui lint` + `cargo clippy --workspace --all-targets -- -D warnings` |
| **Estimated runtime** | targeted `--test`: ~10–60 s · full workspace: ~80 min (one run per phase boundary, background, raw output to file) |

**Run constraints (project lessons):**
- Only one `cargo test` at a time.
- Whole-package `trackly-app` runs need `-- --skip login_remember_persistent_cookie` (pre-existing hang).
- `cargo test -p trackly-app --test export_bindings` must run before `svelte-check` / `lint`.
- `cargo fmt --check`: старый дрейф, о котором говорила эта строка, на границе фазы 41.1 отсутствует — `cargo fmt --all -- --check` по всему дереву дал код 0 (CI запускает именно его), поэтому проверять только изменённые файлы больше не нужно.
- Linker `exit 69` after an Xcode update → prefix `DEVELOPER_DIR=/Library/Developer/CommandLineTools`.
- CI is a single sequential job: the first red step skips every later gate — run steps in CI order.
- `trackly-app` tests require `TRACKLY_AD_MOCK` / `TRACKLY_SNMP_MOCK` and a real pnpm-built `ui/dist`.
- A `cargo test … -- <name-filter>` command exits 0 when the filter matches nothing. Every filter-based verify must also assert at least one test ran (`grep -E 'test result: ok\. [1-9][0-9]* passed'`); a `0 tests` run fails the task.
- Structural rules over `.svelte` files are proven by a `--src=<copy>` run over a copy with a mutated REAL source (clean copy green, mutated copy red), not only by in-memory fixtures; exit codes go to the plan SUMMARY.

---

## Sampling Rate

- **After every task commit:** targeted `cargo test -p <crate> --test <file>` for the touched layer (~10–60 s) + the relevant `node ui/scripts/check-*.mjs`; for UI tasks also `pnpm --dir ui svelte-check`
- **After every plan wave:** all of the wave's targeted `--test` runs + `pnpm --dir ui lint` (after `export_bindings`); one background full-workspace run at the wave boundary only when schema or services changed
- **Before `/gsd-verify-work`:** full workspace green (background, `timeout` up to 2 h, raw output to file) + `svelte-check` + `lint` + `clippy -D warnings` green, then the human checklist below in **both** Tauri and the LAN browser
- **Max feedback latency:** 60 s per task

### Перенесённый долг и ограничения (не теряются)

1. `crates/trackly-app/src/tauri_cmds/printers.rs:171` — `status_id: 1` у принтера, принятого по SNMP; Rust-гейт освобождает его самоинвалидирующимся счётным пунктом (конверсия сайта потребует снять освобождение).
2. Якорь вложенной группы внутри подерева другого якоря считается членом внешнего и скрывается `hide_anchor_members`; план 09 вложенность не запрещает; починка — одно условие в `anchor_members_sql!` (план 12).
3. Отмена или правка более раннего акта над устройством, ставшим якорем, возвращает ошибку. Намеренно; ограничение снимается в фазе 41.2.
4. `discover` не считает IP скрытого (мягко удалённого) принтера дубликатом, а UNIQUE на `printers.ip_address` нет: восстановление старого устройства может оставить два устройства с одним IP — вне охвата фазы (план 22).
5. `deviceListMode.ts` не делит фикстуру с серверными правилами скрытия и K: он решает лишь КОГДА ставить флаг; совпадение `hidden_member_count` с видимой разницей проверяет только человек.
6. В режиме «свернуть одинаковые» якоря грузятся одной страницей до 200 строк; превышение молча не показывается.
7. `highlightId` не сбрасывается — «Свернуть одинаковые» после «Перейти к устройству» отдано пункту 16 чек-листа.
8. `AddToGroupModal`: для пустого поиска только штатное «Ничего не найдено» из `Dropdown`; вторая подсказка из критериев плана 14 отсутствует, фильтрация по имени группы — функция `Dropdown`, не локальная.
9. UI-SPEC §16.2 хранит прежнюю формулировку «Сформировать группу», которую план 16 убрал как захардкоженную встроенную подпись.
