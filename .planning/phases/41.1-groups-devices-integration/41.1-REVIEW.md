## Critical Issues

### CR-01: Приглушённый чип статуса контрастнее действующего; гейт R1 измеряет не тот фон

**Файлы:**
`ui/src/styles/_tokens.scss:49-50,59-60,132-133,142-143`,
`ui/scripts/check-contrast.mjs:196-213`,
`ui/src/lib/components/Badge.svelte:174-180,198-203`

**Issue:**
Правило R1 сравнивает контраст `--tr-*-muted-text` и `--tr-*-text` **к
`--tr-surface`**. Но `Badge` в `appearance="soft"` рисует текст на подложке
`--tr-*-soft` / `--tr-*-muted-soft`, а не на чистом `--tr-surface`. На
фактическом композите соотношение инвертируется:

| тема / тон | фон чипа (композит) | контраст текста к своему фону |
|---|---|---|
| light warning **действующий** (`#8f590a` на `rgba(185,114,12,.14)`) | `#f5ebdd` | **4.95** |
| light warning **приглушённый** (`#915c0f` на `rgba(185,114,12,.07)`) | `#faf5ee` | **5.17** |

То есть «приглушённый» чип читается ЯРЧЕ действующего — ровно наоборот
заявленному в UI-SPEC §10.2 и в комментарии к токенам. R1 этого не ловит, потому
что к `--tr-surface` разница есть (зазор ≥ `MIN_CONTRAST_GAP = 0.1`), а к
реальному фону её нет.

Вторая половина проблемы — сама различимость пары. Контраст между двумя
подложками: light warning **1.087:1**, light danger **1.093:1**, dark warning
**1.161:1**, dark danger **1.123:1**; цвета текста отличаются на
`#8f590a` ↔ `#915c0f` и `#b02f2f` ↔ `#b43939` — визуально это один и тот же
цвет. Прежний вариант различал пару формой (`appearance: 'dot'`), и он
удалён (`deviceStatuses.svelte.ts:41,44`), так что «Ожидает ремонта» и
«В ремонте» («На списание» и «Списано») теперь различаются только подписью.
Комментарий в `check-contrast.mjs:41-45` этот риск фиксирует («Текст почти
неразличим»), но выбранная компенсация (альфа ≤ 0.65) даёт различие порядка 1 %
светлоты — ниже порога восприятия на небольшом чипе.

**Fix:**
1. Измерять R1 на том фоне, на котором чип реально рисуется — композит
   `*-soft` / `*-muted-soft` поверх `--tr-surface`, а не на голом
   `--tr-surface`. Функция смешивания нужна в любом случае, R2 (альфа) без неё
   проверяет косвенный признак:

```js
// check-contrast.mjs
function overAlpha(fgHex, alpha, bgHex) {
  const f = hexToRgb(fgHex), b = hexToRgb(bgHex);
  return {
    r: Math.round(f.r * alpha + b.r * (1 - alpha)),
    g: Math.round(f.g * alpha + b.g * (1 - alpha)),
    b: Math.round(f.b * alpha + b.b * (1 - alpha)),
  };
}
// R1': контраст приглушённого текста к СВОЕЙ подложке обязан быть НИЖЕ
// контраста действующего текста к ЕГО подложке, минимум на MIN_CONTRAST_GAP.
const mutedC  = contrastRgb(hexToRgb(mutedText),  overAlpha(mutedSoftRgb,  mutedAlpha,  surface));
const activeC = contrastRgb(hexToRgb(activeText), overAlpha(activeSoftRgb, activeAlpha, surface));
if (mutedC > activeC - MIN_CONTRAST_GAP + EPS) violations.push(/* … */);
```

2. Подобрать `--tr-*-muted-text` так, чтобы неравенство выполнялось на
   композите (т. е. сдвинуть приглушённый текст заметно ближе к фону, а не на
   2 единицы по каждому каналу), и поднять `MIN_CONTRAST_GAP` до величины,
   которую видно (ориентир — не меньше 0.6–0.8).
3. Вернуть в пару НЕцветовой признак различия (точка-маркер, пунктирная рамка,
   пониженная насыщенность плюс курсив — что угодно, что переживёт печать в
   ч/б и дейтеранопию), либо явно задокументировать решение «различие несёт
   только подпись» и снять из комментариев утверждение «различается яркостью».

### CR-02: Кеш детей псевдогруппы инвалидируется при ОТКРЫТИИ модалки, а не после сохранения — устаревшая строка ребёнка

**Файл:** `ui/src/features/devices/DeviceGroupRow.svelte:137-148`
(`handleEdit`), эффект `:128-130`; `ui/src/features/devices/DevicesPage.svelte:337-340`
(`openEdit`), `:486` (`onEdit={openEdit}`)

**Issue:**
`handleEdit(d)` выставляет `loadedKey = null` и сразу вызывает `onEdit(d)`.
`onEdit` в `DevicesPage` — это `openEdit`, которая только **открывает модалку**
(`editTarget = d; modalOpen = true`), никакой мутации ещё нет. Из-за
`loadedKey = null` эффект немедленно перечитывает детей и ставит
`loadedKey = idsKey` — **до** того, как пользователь что-либо сохранил.

Дальше пользователь сохраняет. `onSaved` → `refresh()` → список перечитан.
Страница «Устройства» сворачивает по `(type_id, name)`, поэтому правка модели,
серийного номера, состояния, места или статуса ребёнка **не меняет
`group.ids`** → `idsKey` остаётся прежней строкой → `$effect` не
перезапускается (`loadedKey === idsKey`) → строка ребёнка внутри раскрытой
свёртки продолжает показывать данные ДО правки, пока состав группы не изменится
или страницу не перезагрузят.

Воспроизведение: режим «Свернуть одинаковые» → раскрыть группу → меню строки
ребёнка → «Редактировать» → сменить «Состояние»/«Статус»/«Модель» → Сохранить →
строка ребёнка не обновилась (строка-представитель группы при этом обновляется,
что делает расхождение особенно заметным).

Побочный эффект той же ошибки: лишний `devices.listByIds(group.ids)` при
каждом открытии модалки правки.

Механизм предсуществующий (до-фиксовая версия ставила `children = null` в том
же месте и вела себя так же), но комментарий `:137-141`, добавленный этим
планом, утверждает противоположное: «После мутации (правка/удаление/действие из
меню) родитель перечитывает список… Здесь кеш помечается устаревшим, и эффект
перечитывает детей». Это неверно для правки.

**Fix:**
Инвалидировать кеш ПОСЛЕ мутации, а не при открытии редактора. Самый дешёвый
вариант — отдельный счётчик обновлений списка, приходящий сверху, и ключ кеша,
включающий его:

```svelte
// DevicesPage.svelte: публиковать номер поколения успешного refresh()
let listGeneration = $state(0);
// в refresh(), после прохождения охраны поколения:
listGeneration += 1;
// …и передать его в DeviceList → DeviceGroupRow как проп `generation`

// DeviceGroupRow.svelte
const { group, generation, /* … */ } = $props();
const idsKey = $derived(`${generation}:${groupIdsKey(group.ids)}`);

function handleEdit(d: DeviceDto) {
  onEdit(d); // кеш не трогаем — его обновит смена generation после refresh()
}
function handleDelete() {
  onDelete();
}
```

И поправить комментарий: он должен описывать, что именно инвалидирует кеш.
Правило [G] гейта `check-device-list-mode.mjs` стоит расширить мутантом
«правка ребёнка, состав не изменился» (сейчас он проверяет только привязку кеша
к составу).

### WR-01: `loadAnchorMembers` / `failAnchor` не защищены номером поколения — та же гонка, что чинил план 29

**Файл:** `ui/src/features/devices/DevicesPage.svelte:219-239` (`failAnchor`,
`loadAnchorMembers`), `:246-272` (`reloadExpandedAnchors`)

**Issue:**
План 29 ввёл `anchorsSeq` только в `reloadExpandedAnchors`. Соседний путь
записи того же состояния — `loadAnchorMembers(groupId)`, вызываемый из
`toggleAnchor` при раскрытии якоря, — пишет `anchorMembers` без всякой охраны:

```ts
const state = await fetchAnchorMembers(groupId);
anchorMembers = { ...anchorMembers, [groupId]: state };   // ← охраны нет
```

Сценарий: пользователь раскрывает якорь X (запрос A в полёте) → срабатывает
`refresh()` (смена фильтра, сохранение, WS-инвалидация) → `reloadExpandedAnchors`
видит X в `expandedAnchors` и шлёт запрос B → B приходит первым и пишет
`anchorMembers = fresh` → A приходит вторым и перезатирает свежий состав
устаревшим. Аналогично `failAnchor([groupId])` в `catch` свернёт строку и
покажет тост по устаревшей ошибке.

**Fix:** протянуть тот же номер поколения в `loadAnchorMembers` и `failAnchor`:

```ts
async function loadAnchorMembers(groupId: number) {
  const aSeq = ++anchorsSeq;
  anchorMembers = { ...anchorMembers, [groupId]: { loading: true, items: [], total: 0 } };
  try {
    const state = await fetchAnchorMembers(groupId);
    if (aSeq !== anchorsSeq) return;
    anchorMembers = { ...anchorMembers, [groupId]: state };
  } catch {
    if (aSeq !== anchorsSeq) return;
    failAnchor([groupId]);
  }
}
```
и добавить в правило [H] код [H6] для `loadAnchorMembers` (сейчас гейт про эту
функцию не знает вовсе).

### WR-02: `list` / `list_all` молча игнорируют `place_id`, `state` и `name_prefix`; текст ошибки экспорта советует сузить выборку, которую сузить нечем

**Файлы:** `crates/trackly-infra/src/repos/devices_sqlite.rs:756-790`
(`count_list_rows`), `:792-840` (`select_list_rows`),
`crates/trackly-app/src/services/device_service.rs:1825-1841` (`export_csv`)

**Issue:**
`export_csv` аккуратно переносит `place_id`, `state`, `name_prefix` из запроса
в `domain_filter`, но WHERE в `count_list_rows`/`select_list_rows` содержит
только `include_deleted`, `status_id`, `type_id` и флаги якорей. Три поля
фильтра принимаются по контракту и молча отбрасываются. Для `name_prefix` это
задокументировано (`dto/device.rs:311-315`), для `place_id` и `state` — нет.

Новый потолок делает это заметным: при переполнении пользователь получает
«Сузьте выборку (например, выберите статус)» — и действительно, только статус и
тип что-то сужают; фильтр по месту (который естественно выбрать первым)
не изменит ни выборку, ни ошибку. Через LAN-эндпойнт
`POST /api/v1/devices_export_csv` фильтр по месту тоже принимается и
игнорируется, то есть клиент, попросивший одну комнату, получает всю
организацию.

**Fix:** либо реализовать предикаты, либо отвергать непустые поля явно:

```rust
// devices_sqlite.rs — добавить в общий предикат
"(?10 IS NULL OR d.place_id = ?10) AND (?11 IS NULL OR d.condition = ?11) AND "
```
(с привязкой `filter.place_id` / `filter.state` в обоих запросах), либо в
`export_csv` вернуть `AppError::Validation { field: "place_id", … }` на
непустое значение — молчаливое игнорирование хуже обоих вариантов. Заодно
снять из текста ошибки пример «выберите статус», если набор сужающих полей
изменится.

### WR-03: Изоляция `Modal` — список из трёх свойств, а не граница наследования; гейт закрепляет ровно эти три

**Файлы:** `ui/src/lib/components/Modal.svelte:256-269`,
`ui/scripts/check-modal-isolation.mjs:42-47` (`REQUIRED`)

**Issue:**
Сброс на `.modal-backdrop` перечисляет `white-space`, `text-align`, `cursor`, а
гейт [M2] требует ровно их. Но `Modal` монтируется на месте вызова, и ячейки
таблиц задают и другие НАСЛЕДУЕМЫЕ свойства: `.cell { font-size; color }`
(`PrinterListRow.svelte:186-189`, `DeviceGroupRow.svelte:199-202`,
`DeviceListRow`, `CartridgeListRow`, `ActListRow`, `RequestListRow`),
`.cell-meta`/`.cell-sub` — `font-size: caption` и `color: text-secondary`,
`.name-text` — `font-weight: semibold`. Сегодня видимого дефекта нет (значения
совпадают с глобальными), но следующий `letter-spacing`/`text-transform`/
`font-size` в классе ячейки протечёт внутрь модалки молча: гейт зелёный, потому
что проверяет фиксированный список.

**Fix:** заменить денай-лист на границу. Либо портал (решает заодно WR-04):

```svelte
<div class="modal-backdrop" use:portal …>
```
либо явная изоляция контейнера:

```scss
.modal-container {
  // наследование от места монтирования обрывается здесь
  font: var(--tr-font-body);
  color: var(--tr-text-primary);
  white-space: normal;
  text-align: start;
  cursor: auto;
  letter-spacing: normal;
  text-transform: none;
}
```
и в [M2] проверять не список свойств, а присутствие этого правила изоляции
(или `all: revert`-подобной конструкции), чтобы правило не устаревало при
добавлении нового наследуемого свойства в ячейку.

### WR-04: Охрана `click` поставлена на call-site, а не в `Modal`; гейт [F4] знает только три файла строк

**Файлы:** `ui/src/features/printers/PrinterListRow.svelte:105-111`,
`ui/src/features/devices/DeviceListRow.svelte:82`,
`ui/src/features/devices/DeviceGroupRow.svelte:132`,
`ui/scripts/check-device-row-menu.mjs:133-136` (`REQUIRED_TD_CLICK_ROWS`),
`ui/src/lib/components/Modal.svelte:256`

**Issue:**
Корневая причина WR-02 первой итерации — `Modal` не портальный, поэтому
`click`/`dblclick`/`contextmenu` из модалки всплывают в строку. Починка
сделана тремя одинаковыми охранами `if (isRowOverlayEvent(e.target)) return;`
в трёх компонентах строк, а гейт [F4] обязывает к ней только файлы из
`REQUIRED_TD_CLICK_ROWS` (сейчас — один, `PrinterListRow`). Любая новая строка
с `onclick` на `<td>` и `Modal` внутри воспроизведёт тот же дефект, и ни один
гейт не покраснеет. Это ровно та схема «флаг на каждом вызове вместо исправления
общего поведения», которая в этом проекте уже плодила регрессии.

**Fix:** закрыть причину в `Modal` — остановить всплытие указательных событий
на корне, где уже стоит сброс типографики:

```svelte
<div
  class="modal-backdrop"
  onclickcapture={(e) => e.stopPropagation()}
  ondblclickcapture={(e) => e.stopPropagation()}
  oncontextmenucapture={(e) => e.stopPropagation()}
  …
>
```
(или портал в `document.body`). Охраны в строках после этого остаются как
дешёвая вторая линия, но перестают быть единственной. В `check-modal-isolation`
добавить правило на это объявление, а `REQUIRED_TD_CLICK_ROWS` строить
перечислением ОТ репозитория (все `*ListRow.svelte`/`*Row.svelte` c `onclick`
на `<td>`), а не списком имён.

### WR-06: [D1] проверяет присутствие имён, но не полярность условия

**Файл:** `ui/scripts/check-device-form-quantity-gate.mjs:326-356`

**Issue:**
`[D1]` считает нарушением только отсутствие `membershipLoaded`, `storageIntent`,
`isEdit` в тексте условия ДО присваивания. Полярность не проверяется: замена
`(!isEdit || storageIntent)` на `(isEdit || storageIntent)` (снимает охрану при
создании и оставляет её при правке — ровно наоборот) или на
`(isEdit && storageIntent)` проходит гейт зелёным. Среди 29 фикстур мутанта на
полярность нет: есть только «имя удалено», «имя после присваивания» и замена
всей скобки на голый `storageIntent`. Аналогично `membershipLoaded` может быть
инвертирован в `!membershipLoaded` без покраснения.

**Fix:** проверять подвыражение целиком, а не имена:

```js
const REQUIRED_SUBEXPRS = [
  /\bmembershipLoaded\b(?!\s*===\s*false)/,           // не отрицание
  /\(\s*!\s*isEdit\s*\|\|\s*storageIntent\s*\)/,       // ровно эта форма
];
```
и завести два мутанта: `(isEdit || storageIntent)` и `!membershipLoaded` —
оба обязаны дать [D1].

### WR-07: Инвентарь [F5] пропускает `<Badge>`, у которого в атрибутах нет слова `tone` или `statusTone(`

**Файл:** `ui/scripts/check-device-status-labels.mjs:620-626`,
`:97-103` (`MIN_STATUS_BADGES = 5`)

**Issue:**
Тег учитывается, только если его текст содержит `tone` или `statusTone(`:

```js
if (!/\btone\b/.test(tag) && !/statusTone\(/.test(tag)) continue;
```
Шестое место вызова, написанное как `const chip = $derived(statusTone(code))`
+ `variant={chip.variant} appearance={chip.appearance}` (без слова `tone` в
теге), будет **молча пропущено**: не посчитано, не проверено, `badgeTags`
останется 5 и порог `MIN_STATUS_BADGES = 5` сойдётся. Порог — нижняя граница
по числу, а не инвентарь, построенный от репозитория; ровно этот способ
занижения охвата в проекте уже ловили.

**Fix:** определять «Badge статуса» по файлу-импортёру и по тому, что хотя бы
один атрибут ссылается на переменную, чьё объявление в `<script>` —
`$derived(statusTone(...))`; разрешить произвольное имя источника:

```js
const toneVars = [...script.matchAll(/\b(?:const|let)\s+(\w+)\s*=\s*\$derived\(\s*statusTone\(/g)]
  .map((m) => m[1]);
const isStatusBadge = /statusTone\(/.test(tag) || toneVars.some((v) => new RegExp(`\\b${v}\\.`).test(tag));
```
и покраснеть [F5], если в файле-импортёре есть `<Badge>`, не попавший ни в одну
категорию.

### WR-08: [G] не связывает подлежащее `{#each}` с результатом `visibleChildren`

**Файл:** `ui/scripts/check-device-list-mode.mjs:662-712` (`checkGroupRow`)

**Issue:**
`[G2]` краснеет только на буквальном `{#each children`. `[G1]` требует импорта
`visibleChildren`. Но ничто не проверяет, что `shownChildren` — это и есть
`visibleChildren(children, group.ids)`. Написать
`const shownChildren = $derived(children ?? [])`, оставив `visibleChildren`
использованным где-нибудь ещё (чтобы eslint не ругнулся на неиспользуемый
импорт), — гейт зелёный, фильтрация ушедших детей мертва.

**Fix:** привязать подлежащее к источнику:

```js
const each = /\{#each\s+([A-Za-z_$][\w$]*)\b/.exec(text);
const decl = each && new RegExp(
  `\\b(?:const|let)\\s+${each[1]}\\s*=\\s*\\$derived\\(\\s*visibleChildren\\(`
).test(text);
if (!decl) out.push({ code: 'G2', msg: `{#each ${each?.[1]}} — подлежащее не результат visibleChildren(...)` });
```
и добавить соответствующий структурный мутант.

### WR-09: `EXPORT_MAX_ROWS` не покрыт тестом на уровне сервиса; между COUNT и SELECT в `list_all` окно для молчаливого усечения

**Файлы:** `crates/trackly-app/src/services/device_service.rs:57-61`,
`crates/trackly-infra/src/repos/devices_sqlite.rs:842-866` (`list_all`),
`crates/trackly-app/tests/devices_csv_export.rs:788-855`

**Issue:**
1. Потолок проверяется только в `trackly-infra` с `max_rows = 3`. Сам
   `EXPORT_MAX_ROWS = 50_000` и путь «сервис вернул `Validation` c полем
   `export`» не покрыт ни одним тестом; константу можно удалить/обнулить, и
   сюита останется зелёной.
2. `list_all` делает COUNT и SELECT двумя отдельными операторами на
   пулированном reader-соединении, без транзакции. Если между ними
   зафиксируется вставка, COUNT ≤ `max_rows` пройдёт, а
   `LIMIT max_rows` МОЛЧА обрежет выборку — ровно то, что константа должна была
   исключить («молчаливого усечения нет» в комментарии `:58-60`).

**Fix:**
```rust
// list_all: читать обе выборки в одном снимке
let tx = conn.unchecked_transaction().map_err(map_rusqlite)?;
let total = count_list_rows(&tx, filter)? as u64;
if total > max_rows { return Err(/* … */); }
let rows = select_list_rows(&tx, filter, (max_rows + 1) as i64, 0)?;
if rows.len() as u64 > max_rows { return Err(/* … */); }  // пояс и подтяжки
```
и добавить сервисный тест: подменить константу через параметр или собрать
`max_rows` из конфигурации, чтобы проверять ошибку без 50 000 вставок.
