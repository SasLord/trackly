# Phase 41.1 Plan 15: UI разбора Summary

«Создать деталь» внутри записи разбора двумя вызовами (создание, затем groups.addDevices) с честным сообщением при сбое второго, происхождение в форме и попапе просмотра, якорь не предлагается к выводу из состава.

## Что сделано

1. **Форма устройства** (`DeviceFormModal`, `DeviceFormBody`): новые необязательные пропы `presetPlaceId`, `presetStatusCode`, `originGroup`. Статус по умолчанию ставится один раз, когда справочник статусов загружен, и остаётся редактируемым. `onSaved` дополнен полем `created` (одиночное создание и `bulkCreate`); прежние вызывающие не затронуты. Строка «Из разбора:» со ссылкой на запись разбора показывается в create-режиме (из `originGroup`) и при правке (из `target.origin_group_*`), только если происхождение есть. Условия `quantityDisabled`/автоподстановки не тронуты, `check-device-form-quantity-gate.mjs` (оба режима) зелёный.
2. **Состав записи** (`GroupContentsTable`): кнопка «Создать деталь» рядом с «Добавить несколько…» (только `canEdit` и `type_behavior === 'teardown'`). `handleDetailSaved` сначала вызывает `notifyPlaceContentChanged` по местам созданных деталей, затем `groups.addDevices`, на успехе повторно уведомляет по `changed_place_ids`; на сбое показывает тост, называющий созданное («Устройство «…» создано, но не добавлено в запись разбора: … Добавьте его вручную через поиск в составе.» или «Создано N устройств, но они не добавлены…»). Состав и счётчики перечитываются на обеих ветках. «Вывести из состава» скрыт для якорного устройства своей группы; если пунктов нет, меню не рендерится.
3. **Попап просмотра** (`PlaceEntityViewModal`): поле «Из разбора» выше «Истории перемещений», только для устройств с `origin_group_id`. `MovementTimeline` не менялся (D-19).
