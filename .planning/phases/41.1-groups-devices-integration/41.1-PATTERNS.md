### [F1] `migrations/V047__device_statuses_lifecycle.sql` и `V048__group_anchor_device_origin.sql` (migration, batch)

**Следующий свободный номер:** `V047` (последняя — `V046__place_movements_batch.sql`). Перед планированием проверить `ls migrations | tail`.

**Аналог формы файла — `migrations/V046__place_movements_batch.sql` (стр. 1-25).** Почему: свежайшая аддитивная миграция в проекте, три `ADD COLUMN` без перестройки таблицы, частичные индексы, в шапке явно сказано про урок V042.

```sql
-- V046: ... Только три ALTER ... ADD COLUMN; перестройка place_movements запрещена
-- (урок V042: перестройка в refinery-транзакции теряет данные).
ALTER TABLE place_movements ADD COLUMN batch_id TEXT NULL;
ALTER TABLE place_movements ADD COLUMN entity_label TEXT NULL;
ALTER TABLE place_movements ADD COLUMN group_id INTEGER NULL;

CREATE INDEX idx_place_movements_batch
  ON place_movements(batch_id) WHERE batch_id IS NOT NULL;
CREATE INDEX idx_place_movements_group
  ON place_movements(group_id) WHERE group_id IS NOT NULL;

PRAGMA user_version = 46;
```

**Аналог «переименование справочной строки + код» — `V014__acts_indexes_and_status_codes.sql` стр. 23-29.** Почему: единственная миграция, которая вводит `device_statuses.code` и фиксирует, что `code` — машинный ключ, а `name` — подпись.

```sql
ALTER TABLE device_statuses ADD COLUMN code TEXT;
UPDATE device_statuses SET code = 'на_ремонте' WHERE name = 'На ремонте';
CREATE UNIQUE INDEX idx_device_statuses_code_unique ON device_statuses(code) WHERE code IS NOT NULL;
```

В V047 переименование идёт по `WHERE code = 'на_ремонте'` (не по `name`), `code` не трогается (D-02). Схема из `V001` стр. 25-29: `device_statuses(id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE)` без AUTOINCREMENT — новые строки получат id 5 и 6, но в коде завязываться на id нельзя (A6).

**Аналог «ADD COLUMN + частичный уникальный индекс» — `V014` стр. 29 и `V044` стр. 150** (`CREATE UNIQUE INDEX … WHERE …`). `UNIQUE` прямо в `ADD COLUMN` SQLite запрещает; уникальность `groups.anchor_device_id` — отдельным `CREATE UNIQUE INDEX idx_groups_anchor ON groups(anchor_device_id) WHERE anchor_device_id IS NOT NULL` (форма из RESEARCH, Pattern 1).

**Жёсткие ограничения (из CONTEXT, Claude's Discretion):** только `ALTER … ADD COLUMN`, `UPDATE`, `INSERT`, `CREATE [UNIQUE] INDEX`; ни `DROP`, ни пересоздания `devices`/`groups`/`device_statuses`. `PRAGMA foreign_keys = OFF` внутри файла в refinery — no-op (V042 стёр `act_items`). Колонка с `REFERENCES` при включённых FK обязана иметь `DEFAULT NULL` (RESEARCH Pattern 1, `[CITED: sqlite.org]`). Каждый файл заканчивается `PRAGMA user_version = NN;`.

### [F3] `GroupService::create_group` (создание от устройства), охранные проверки, отказ `Validation` (service, CRUD в одной транзакции)

**Аналог многострочной транзакции — `group_service.rs::add_devices` (стр. 699-805).** Почему: один `writer.execute`, одна `conn.transaction()`, цикл по устройствам, на любой ошибке `?` откатывает всё (tx не закоммичена), аудит и `broadcast_entities` ПОСЛЕ коммита вне замыкания.

```rust
let (result, added) = self.writer.execute(move |conn| {
    let tx = conn.transaction().map_err(map_rusqlite)?;
    let deps = GroupMoveDeps::new();
    let group = deps.groups.get_group_in_tx(&tx, group_id)?;
    for device_id in &device_ids {
        let device = match deps.devices.get_in_tx(&tx, *device_id) { Ok(d) => d,
            Err(AppError::NotFound { .. }) => return Err(device_ids_error("Устройство не найдено.".to_string())),

        if device.deleted_at_utc.is_some() { return Err(device_ids_error(format!("Устройство «{}» удалено …", device.name))); }
        if let Some(existing) = deps.groups.group_of_device_in_tx(&tx, *device_id)? { … return Err(device_ids_error(format!("… уже входит в группу «{}». Сначала выведите его из состава.", …))); }

// После коммита:
```

**База для `create_group` — тот же файл, стр. 420-497** (сейчас: `type_repo.get_type` → проверка места → `next_seq_in_tx` → `insert_group_in_tx` → `group_dto_on` → `audit_repo.insert` → `tx.commit()`; в конце `broadcast_entities("create_group", place_ids, Vec::new(), vec![out.id])` на стр. ~490-494). Расширение под `source_device_id`: внутри той же `tx` после `insert_group_in_tx` — проверки устройства (живое, не «Списано»/«На списание» по `code`, не член другой группы, не сетевой принтер), `place_id` группы := `devices.place_id` устройства, `add_device_in_tx`, для `substitute`/`teardown` — `UPDATE groups SET anchor_device_id`, для `teardown` — смена статуса на `на_списание` + аудит. **Аналог отката «как единое целое» — тест `groups_move.rs::move_atomic_failure_on_fourth_device_rolls_back_everything` (стр. 551-585).** Приём: через `ctx.writer.execute` ставится SQL-триггер `RAISE(ABORT, 'boom')` на нужную запись, затем вызов должен вернуть ошибку, а снимок (`state_snapshot`, стр. 256-272: места групп и устройств, `COUNT(*)` из `place_movements` и `audit_log`) обязан совпасть с «до».

```rust

    conn.execute_batch(&format!(
        "CREATE TRIGGER fail_fourth BEFORE UPDATE OF place_id ON devices \
         WHEN NEW.id = {fourth} BEGIN SELECT RAISE(ABORT, 'boom'); END;"))
        .map_err(map_rusqlite)

let before = state_snapshot(&ctx, &f).await;
let err = ctx.groups.move_group(&admin(), f.root, v, f.place_b).await.expect_err("…");
```

Для нового теста триггер вешать на последний шаг цепочки (смена статуса для `teardown`, `UPDATE groups SET anchor_device_id` для `substitute`) и сверять: нет строки в `groups`, нет в `group_devices`, статус устройства прежний, `audit_log` не вырос. Префикс теста — `rollback_`/`p4_` (по соглашению реестра такие тесты сценариями не считаются).

**Аналог охраны, отказывающей `Validation` внутри writer-транзакции с числом в тексте — `group_type_service.rs::delete_type` (стр. 398-446).** Почему: это ровно форма D-20 (запрет `delete_group` разбора, пока в нём есть детали) — предпроверка внутри `tx`, сообщение с числом через плюрализатор, до любой записи.

```rust
let groups = repo.count_groups_of_type(&tx, id)?;
if groups > 0 {
    return Err(AppError::Validation {
        field: "id".to_string(),
        message: format!("Тип нельзя удалить: у него {}. Удалите или перенесите их.", plural_groups(groups)),
    });
}
```

Для D-20 числительное — через `crate::services::plural::ru_plural(n, "деталь", "детали", "деталей")` (`services/plural.rs`, `pub(crate)`; тот же помощник использует `place_service.rs::build_delete_blocked_message`, стр. ~1010-1090).
