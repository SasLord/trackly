# Phase 41.1 Plan 04: status_code в содержимом места Summary

Строка содержимого места несёт `status_code` рядом с `status_name`, чтобы в плане 13 бейдж статуса в «Местах» выбирал тон по коду, а не по русской подписи.

## Выполненные задачи

| Задача | Коммит | Суть |
|---|---|---|
| 1 | 8d66957d | поле в `PlaceContentRow`/`PlaceContentDto`, колонка 7 в union (`ds.code` x2, `NULL` x1), 4 теста |

## Проверка

- `cargo test -p trackly-app --test places_contents`: 9/9 (5 существующих и 4 новых).
- `cargo build -p trackly-app`: без ошибок; других мест, где `PlaceContentRow` собирается литералом, нет.
- `check-privacy`: 0 нарушений перед коммитом. Имена вымышленные.

### Мутационная проверка (тесты не вакуумны)

Каждая мутация заменяла одно вхождение `ds.code AS status_code` на `NULL AS status_code` (по порядку вхождения), файл после каждой восстанавливался из копии:

- ветка device: красные `devices_carry_status_code_next_to_status_name` и `status_code_survives_status_rename`;
- ветка printer: красный `printer_carries_status_code`.

Ветка cartridge охраняется `cartridge_has_no_status_code` (ожидает `None` при непустом `status_name`).
