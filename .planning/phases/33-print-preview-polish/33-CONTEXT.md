# Phase 33: Полировка предпросмотра печати - Context

**Gathered:** 2026-08-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Модалка предпросмотра печати (`PdfPreviewModal.svelte`, режимы `handover` / `acceptance` /
`report`) показывает документ как стопку листов A4 на сероватой подложке, с видимыми полями,
и то же самое уходит на печать.

**Фаза чисто фронтендовая.** HTML-шаблоны (`crates/trackly-app/templates/*.html`) НЕ
изменяются — см. D-01. Бэкенд-путь рендера (`acts_render_pdf`, `devices_render_acceptance_pdf`,
`reports_export_pdf` → HTML-строка) не меняется.

**Не в этой фазе:** содержимое/вёрстка самих документов, новые типы документов, экспорт в PDF
файлом, редактор шаблонов в UI.

</domain>

<decisions>
## Implementation Decisions

### Источник полей листа (PRV-02, PRV-03)

- **D-01:** Шаблоны `act_handover.html` / `act_acceptance.html` / `report.html` **не
  изменяются**. `@page { size: A4 portrait; margin: 20mm 15mm }`, который уже есть во всех трёх,
  остаётся **единственным источником полей** и для экрана, и для печати — Paged.js (D-04) читает
  именно его и строит для каждой страницы область, отступлённую на эти поля.
  **История решения:** сначала был выбран вариант с обёрткой `.sheet { padding }` +
  `@page { margin: 0 }`. После выбора Paged.js он **отменён** — одна обёртка вокруг всего
  содержимого конфликтует с пагинацией (padding применился бы только к первой и последней
  странице).
  **Следствия, важные для планировщика:** не нужен снапшот `_legacy_defaults/v21/`; ограничение
  fail-closed авто-апгрейда (`html_templates.rs:134`) не срабатывает; пользователи с вручную
  правленными шаблонами получают фикс автоматически.

- **D-02:** Деградация вместо поломки: если Paged.js не отработал (не загрузился, упал,
  выбросил), модалка показывает документ как раньше — непагинированный, в iframe — а не пустой
  экран. Формулировка изначального решения «страховка в оболочке» сохраняется в этом виде.

- **D-03:** Граница приёмки PRV-03 — **дефолтные настройки диалога печати** (масштаб 100%, поля
  по умолчанию). Ручные правки пользователя в диалоге вне зоны гарантии. Плюс короткая
  строка-подсказка в футере модалки — тот же приём, что уже применён для колонтитулов
  (Phase 16, D-12).

### Механизм многостраничного предпросмотра (PRV-01)

- **D-04:** Пагинация — **Paged.js** (полифилл CSS Paged Media). Отвергнуты: свой пагинатор по
  блокам верхнего уровня (не разбивает длинные таблицы отчёта по строкам) и визуальные зазоры
  каждые 1123px (не учитывают `page-break-inside: avoid`, маркер врёт).
  **Оговорено с пользователем:** нативную фрагментацию браузера на экране получить нельзя в
  принципе, любой многолистовой предпросмотр — приближение другим движком. D-06 закрывает этот
  разрыв.

- **D-05:** Рендер остаётся в `<iframe srcdoc>`, но `sandbox` меняется с `""` на
  **`"allow-scripts"`** — без `allow-same-origin`. Документ в opaque origin: скрипты Paged.js
  работают, доступа к приложению нет, **изоляция CSS сохраняется** (стили документа в `pt` со
  своими шрифтами не текут в приложение). Отвергнуты: рендер в top-level DOM (смешение стилей) и
  `allow-scripts allow-same-origin` (фактически снимает sandbox, а шаблон — редактируемый
  пользователем HTML).

- **D-06:** **Печать тоже идёт через Paged.js.** Обе ветки печати — desktop (temp `.html` →
  системный браузер) и LAN (инъекция в top-level `#act-print-root`) — печатают уже разбитую
  Paged.js разметку, а не исходный поток. Один движок на экран и на бумагу = настоящий WYSIWYG,
  буквально то, чего требует PRV-03. Обе ветки переделываются и перепроверяются.

- **D-07:** Пока Paged.js пагинирует — **спиннер с прогрессом страниц** («Страница N…»,
  Paged.js даёт событие на каждую готовую страницу). Кнопка «Печать» заблокирована до
  завершения пагинации — это обязательно, так как печать теперь зависит от её результата.
  Переиспользуется существующее состояние `state-loading` со `Spinner`.

### Подложка, лист, тема (PRV-01)

- **D-08:** Подложка — `--tr-surface-sunken` (`#e4e8f0` светлая / `#0a0d12` тёмная), то есть
  **следует теме приложения**. Лист — **всегда белый**, это бумага. Так же ведёт себя превью
  печати Chrome. Текущий баг именно здесь: `.pdf-page-frame` использует `--tr-surface`, который
  в светлой теме `#ffffff` ([PdfPreviewModal.svelte:325](ui/src/features/acts/PdfPreviewModal.svelte:325)).
  Отвергнут вариант с инверсией самого листа в тёмной теме — ломает PRV-03.

- **D-09:** Оформление листа — тень `--tr-elev-2` (уже применяется к текущему iframe) +
  вертикальный зазор между листами, **без рамки**. Штатный `interface.css` от Paged.js не
  используется: его цвета и тени не согласованы с дизайн-системой Trackly и не знают про тёмную
  тему.

- **D-10:** Счётчик страниц («3 страницы») — **в шапке/футере модалки, вне документа**. Так он
  гарантированно не попадёт на бумагу и не нарушит WYSIWYG. Отвергнута подпись «1 / 3» под
  каждым листом на подложке.

### Масштаб

- **D-11:** **Авто-вписывание по ширине** через `transform: scale`, с потолком 100% (лист
  никогда не увеличивается сверх натуральной величины). Горизонтального скролла нет никогда.
  Трансформ чисто экранный, на печать не влияет. Отвергнуты: фикс 100% с горизонтальным скроллом
  (текущее поведение, неудобно в LAN-браузере на узком экране) и явный контрол зума (больше кода
  и UI без явной потребности).

- **D-12:** Размеры модалки **не меняются** — `.modal-pdf-preview` остаётся
  `min(95vw, 1100px) × min(90vh, 920px)` ([Modal.svelte:203](ui/src/lib/components/Modal.svelte:203)).
  Многостраничность решается вертикальным скроллом по подложке. `Modal.svelte` не трогаем — он
  общий для всего приложения.

### Регресс-защита

- **D-13:** Структурный автотест: все три шаблона содержат `@page` с одинаковыми `size` и
  `margin` (дешёвая защита от рассинхрона между документами — Success Criteria #4) **плюс**
  ручной UAT на реальной печати/PDF. Обоснование ручной части зафиксировано ранее: текстовые
  тесты не видят наложений и переполнения, нужен рендер реального документа.

### Ограничения, вытекающие из решений (не обсуждались — выведены)

- **C-01:** При opaque origin (D-05) родительское окно **не может** прочитать `scrollHeight`
  iframe. Инжектированный в `srcdoc` скрипт обязан передавать наружу через `postMessage`:
  итоговую высоту, число страниц, прогресс пагинации. Этот же канал питает D-07 и D-10.
- **C-02:** Бандл Paged.js должен **инлайниться в `srcdoc`** вместе с документом — CDN
  запрещён (portable + self-contained, Phase 16 D-11). То же касается temp-файла desktop-ветки
  печати (D-06).
- **C-03:** Desktop-ветка печати сейчас вызывает `window.print()` через `setTimeout` после
  события `load` ([PdfPreviewModal.svelte:186](ui/src/features/acts/PdfPreviewModal.svelte:186)).
  С Paged.js авто-печать должна ждать **завершения пагинации**, а не `load`.

### Claude's Discretion

- Точная величина зазора между листами и радиус/параметры тени в пределах токенов.
- Формулировка строки-подсказки про настройки диалога печати (D-03).
- Формат текста счётчика страниц и его точное место в шапке или футере (D-10).
- Механика передачи цвета подложки в `srcdoc` и реакция на переключение темы при открытой
  модалке (D-08).

</decisions>

## Existing Code Insights

### Reusable Assets
- `.pdf-page-frame` / `.pdf-iframe` уже реализуют зачаток «лист A4»: фикс 794×1123, центрирование,
  `box-shadow: var(--tr-elev-2)`, `overflow: auto`. Основа под подложку уже стоит — меняется
  цвет фона (D-08) и фиксированная высота (D-04).
- Состояния `state-loading` / `state-error` / `state-empty` со `Spinner` — переиспользуются для
  D-07, добавляется только текст прогресса.
- `Modal.svelte` уже включает `iframe` в список focusable-элементов для Tab-ловушки — смена
  `sandbox` (D-05) этого не ломает.
- Токены обеих тем в `ui/src/styles/_tokens.scss`: `--tr-surface-sunken` (25/103 строки),
  `--tr-elev-2`, `--tr-border`.

### Established Patterns
- Ветвление по `isTauri` (`'__TAURI_INTERNALS__' in window`) для desktop/LAN — существующий
  паттерн, D-06 его сохраняет, но обе ветки переписывает.
- Self-contained документ без сетевых запросов (Phase 16 D-11) — из этого следует C-02.
- Скрипт-гейты в `pnpm lint` / CI (`ui/scripts/check-tokens.mjs`, `check-contrast.mjs` из
  Phase 30) — образец для структурного теста D-13.

### Integration Points
- Строка HTML приходит из трёх бэкенд-вызовов (`acts.renderPdf`, `acts.renderAcceptancePdf`,
  `apiCall('reports_export_pdf')`) — сигнатуры не меняются.
- `printViaTopLevel` инжектит `<style>` документа в `document.head` приложения. При D-06 туда
  поедет и CSS Paged.js (`.pagedjs_*`, `pt`/`mm`) — нужен строгий scoping под
  `@media print` + `#act-print-root`, иначе риск задеть вёрстку приложения.
- `printViaSystemBrowser` пишет temp-файл через `tauri-plugin-fs` и открывает через
  `tauri-plugin-shell` — файл должен стать самодостаточным вместе с бандлом Paged.js (C-02).
