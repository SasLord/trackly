## Где живут поля листа

### Вопрос 1 — источник полей

| Option | Description | Selected |
|--------|-------------|----------|
| Шаблон: .sheet + @page margin:0 | Обёртка .sheet с padding, @page margin:0 — WYSIWYG по построению; цена: меняется печатный путь, нужен снапшот v21, кастомные шаблоны фикс не получат | ✓ (позже отменено) |
| Шаблон: @media screen padding | @page без изменений + @media screen padding; нулевой риск для печати, но значение дублируется | |
| Только оболочка превью | Шаблоны не трогаем, screen-only CSS в срcdoc; экранные поля — копия чисел в другом слое | |

**User's choice:** «Шаблон: .sheet + @page margin:0»
**Notes:** Решение **отменено** позже в этой же сессии — см. «Многостраничность», вопрос 5. Выбор
Paged.js сделал `.sheet` контрпродуктивным: одна обёртка вокруг всего содержимого мешает
пагинации.

### Вопрос 2 — fail-closed авто-апгрейд шаблонов

| Option | Description | Selected |
|--------|-------------|----------|
| Страховка в оболочке | v21-снапшот + fallback-отрисовка листа снаружи iframe, если .sheet не найден | ✓ |
| Только v21-снапшот | Кастомные шаблоны — ответственность автора правки; инструкция в релиз-заметках | |
| Предупреждение в UI | Подсказка в модалке «шаблон не обновлён, поля могут расходиться» | |

**User's choice:** «Страховка в оболочке»
**Notes:** После отмены D-01 вопрос снят в исходной форме — шаблоны не меняются вовсе. Принцип
сохранён в CONTEXT.md как D-02: деградация вместо поломки, если Paged.js не отработал.

## Многостраничность

### Вопрос 1 — как показываем длинный документ

| Option | Description | Selected |
|--------|-------------|----------|
| Один лист, авто-высота | Лист A4-ширины, высота по содержимому, внешний скролл; просто, но разрывов не видно | |
| Несколько листов, как в Word | Настоящая пагинация, отдельные листы с зазором; дороже | ✓ |
| Один лист + маркеры разрывов | CSS-пунктир каждые 1123px без JS; маркер может врать | |

**User's choice:** «Несколько листов, как в Word»
**Notes:** Перед выбором механизма пользователю явно сказано: нативную фрагментацию браузера на
экране получить нельзя, любой многолистовой предпросмотр — приближение другим движком, то есть
источник расхождения с бумагой.

### Вопрос 2 — механизм пагинации

| Option | Description | Selected |
|--------|-------------|----------|
| Свой пагинатор по блокам | JS-мерка блоков верхнего уровня, ноль зависимостей; длинные таблицы не разбиваются по строкам | |
| Paged.js | Полифилл CSS Paged Media, честно разбивает таблицы, умеет @page; +~100KB, требует скриптов | ✓ |
| Зазоры каждые 1123px | Визуальная имитация без JS; page-break-inside не учитывается | |

**User's choice:** «Paged.js»

### Вопрос 3 — где рендерим (Paged.js нужны скрипты)

| Option | Description | Selected |
|--------|-------------|----------|
| iframe, sandbox="allow-scripts" | Скрипты разрешены, allow-same-origin нет — opaque origin, изоляция CSS сохраняется | ✓ |
| Top-level DOM в модалке | Один DOM для превью и LAN-печати; риск смешения стилей документа и приложения | |
| iframe, allow-scripts + same-origin | Удобнее в разработке, но фактически снимает sandbox с редактируемого пользователем HTML | |

**User's choice:** «iframe, sandbox="allow-scripts"»

### Вопрос 4 — печатный путь

| Option | Description | Selected |
|--------|-------------|----------|
| Печать тоже через Paged.js | Обе ветки печатают уже разбитую разметку; один движок = настоящий WYSIWYG; обе ветки переделываются | ✓ |
| Печать остаётся нативной | Нулевой риск сломать работающее; расхождение возможно на краевых случаях | |
| Нативная + сверка на UAT | Печать нативная, но в UAT явно сверяем число страниц и точки разрыва | |

**User's choice:** «Печать тоже через Paged.js»

### Вопрос 5 — пересмотр D-01

| Option | Description | Selected |
|--------|-------------|----------|
| Отменить .sheet, @page остаётся | Шаблоны не трогаем вовсе; @page — единственный источник; не нужен v21-снапшот, кастомные шаблоны получают фикс автоматически | ✓ |
| Оставить .sheet как fallback | @media screen padding на случай падения Paged.js; цена — v21-снапшот и дублирование значений | |
| Оставить D-01 как есть | Заставить Paged.js работать поверх .sheet + @page margin:0 | |

**User's choice:** «Отменить .sheet, @page остаётся»
**Notes:** Конфликт был поднят Claude до записи контекста: Paged.js сам строит для каждой
страницы область по полям из `@page`, а одна обёртка вокруг всего содержимого даёт padding
только на первой и последней странице.

### Вопрос 6 — состояние во время пагинации

| Option | Description | Selected |
|--------|-------------|----------|
| Спиннер до готовности | Держим существующее состояние загрузки до конца пагинации | |
| Показать сразу, потом заменить | Быстрее первый пиксель, но видимый скачок вёрстки | |
| Спиннер + прогресс страниц | «Страница N…» по событию Paged.js на каждую страницу | ✓ |

**User's choice:** «Спиннер + прогресс страниц»
