<interfaces>
Текущий `WsEvent` (crates/trackly-app/src/dto/printer.rs:175-204):
```
#[derive(Debug, Clone, Serialize, Deserialize, Type)]
#[serde(tag = "type", rename_all = "snake_case")]
pub enum WsEvent {
    NewRequest { request_id: i64, request_type: String, requester_name: String },
    RequestStatusChanged { request_id: i64, new_status: String, requested_by_user_id: i64 },
    PrinterAlert { printer_id: i64, printer_name: String, alert_type: String },
}
```
Образец правильного паттерна из `RequestTransitionPayload` (crates/trackly-app/src/dto/request.rs:198-220):
```
#[serde(tag = "op")]
pub enum RequestTransitionPayload {
    #[serde(rename_all = "camelCase")]
    Accept { request_id: i64, version: i64, assigned_to_user_id: Option<i32> },
    ...
}
```
Каждый variant имеет СВОЙ `#[serde(rename_all = "camelCase")]`, внешний `tag` не получает rename_all (или получает — он управляет только значением тега, не полями). Это нужно скопировать на `WsEvent`: внешний атрибут оставить `#[serde(tag = "type", rename_all = "snake_case")]` (тег `"request_status_changed"` и т.п. должен остаться snake_case — фронтенд `ws.ts`/`EmployeeLayout.svelte` сравнивает `event.type !== 'request_status_changed'`), но добавить per-variant `#[serde(rename_all = "camelCase")]` на каждый из трёх вариантов (NewRequest, RequestStatusChanged, PrinterAlert), чтобы их ПОЛЯ (request_id → requestId, new_status → newStatus, requested_by_user_id → requestedByUserId и т.д.) сериализовались в camelCase.

`EmployeeLayout.svelte`'s `statusToastText()` (строки 32-43) уже содержит правильную логику по `newStatus` — менять её НЕ нужно, баг только в том, что поле приходит как `new_status` (snake_case) с бэкенда, а TS-тип/код ожидает `newStatus`.
</interfaces>
