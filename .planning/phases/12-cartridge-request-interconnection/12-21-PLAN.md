Round 5 живого UAT (`12-HUMAN-UAT.md`, R4-1/R4-3): закрыть единственный
структурный баг, из-за которого блок «Предыдущий картридж» НИКОГДА не
появляется ни в cartridge-centric, ни в request-centric установке, хотя
backend (авто-возврат, привязка `current_printer_device_id`) полностью
рабочий.

**Подтверждённая причина (GAP-12-13):** `effectivePrinterId` в
`OperationModal.svelte` — это ВСЕГДА device_id (из `PrinterSelect`'s
`String(p.deviceId)` либо из `preFillPrinterId = request.printerDeviceId`).
Лукап-эффект (строки 204-230) вызывает `printers.get(effectivePrinterId)` →
бэкендовая `printers_get`, которая резолвит `WHERE p.id = ?1` — первичный
ключ ЗАПИСИ printers, а не device_id. Результат: `printerContext` остаётся
`null` (или резолвит чужую запись, если id записи случайно совпал), хинт
показывает голый `#id`, `currentCartridgeId` никогда не читается —
`previousCartridge` остаётся `null`, блок не рендерится. Оператор не может
задать `previous_cartridge_state_id`/`previous_cartridge_location` для
смещаемого картриджа — он молча уходит «Пустой»/без расположения.

Это план чинит ТОЛЬКО структурную причину + две сопутствующие UX-правки,
зафиксированные пользователем в Round 5 (`12-HUMAN-UAT.md` `open_round5`):

- **GAP-12-13** (основной фикс): новая read-команда
  `printers_get_by_device_id(deviceId) -> PrinterDto`, резолв по
  `device_id` (как уже делает `printers_get_compatible_models` — тот же
  установленный в проекте паттерн device-id-keyed read). `printers_get`
  (резолв по id записи) НЕ трогаем — используется в др. местах по другому
  контракту.
- **DEC-A**: в cartridge-centric входе (виден `PrinterSelect`) хинт
  показывает `#id + IP`, без имени — имя уже видно в самом селекторе. В
  request-centric входе (селектор не виден) хинт остаётся имя+IP — без
  изменений.
- **DEC-B**: в cartridge-centric входе после выбора принтера через
  селектор поле «Расположение» (НЕ «Расположение (предыдущий картридж)»)
  автозаполняется `printerContext.deviceLocation` выбранного принтера —
  тем же исправленным лукапом, без второго запроса — оставаясь
  редактируемым и не перезатирая ручной ввод оператора.

Вне scope этого раунда (отдельные tracked-задачи, НЕ трогать):
WR-01 (limit:500→200), drum-state default, WR-03 (ws.ts race), WR-04.
