<objective>
Закрыть GAP-12-12: авто-возврат старого картриджа — привязка к принтеру + актор в истории.

Текущее состояние (код-инспекция cartridges_sqlite.rs::transition_in_tx, 340-602):
- (1) `current_printer_device_id` УЖЕ ставится на install в той же UPDATE (строка 432)
  при наличии `printer_device_id`, и снимается (NULL) при авто-возврате (строка 509).
  НО при cartridge-centric входе `printer_device_id` приходил None (это следствие
  GAP-12-11; устранено планом 12-18 на фронте — теперь модалка передаёт preFillPrinterId
  → printer_device_id и в cartridge-centric). Бэкенд-логика привязки уже корректна; нужно
  подтвердить её регрессионным тестом, что привязка проставляется при любом install с
  printer_device_id, и снимается при возврате/заправке.
- (2) Авто-возврат УЖЕ выполняется в одной транзакции (480-565), НО его `payload_json`
  строится из `auto_return_op = ReturnToStock { state_id, location, notes: None }` через
  `op_payload_json` (строка 548). Вариант `ReturnToStock` НЕ имеет полей актора, поэтому
  в истории «Возвращён на склад» актор ПУСТ. Нужно записать ИНВЕРТИРОВАННЫЙ актор
  (продуктовое решение AskUserQuestion 2026-06-24): given_by = given_to новой установки
  (получатель сдаёт старый), given_to = given_by новой установки (склад/выдававший
  принимает). UI истории (CartridgeDetail.svelte:77-78) читает `p.given_by_name` →
  «выдал X» и `p.given_to_name` → «получил Y» — заполнение этих ключей в payload_json
  авто-возврата автоматически отрисует инверсию без правок UI.
- (3) Поля «Предыдущий картридж» (state_id default 3, location) УЖЕ применяются к
  возвращаемому картриджу (строки 487-488, 508-518). Покрыто тестом
  install_auto_return_uses_previous_cartridge_overrides_when_present. Нужно подтвердить
  работу в обоих входах (cartridge-centric теперь тоже передаёт printer_device_id после 12-18).

Дуальный транспорт: правка ВНУТРИ `transition_in_tx`, общего для Tauri и axum (оба идут
через build_cartridges_transition → CartridgeService::transition → transition_in_tx).
Новых эндпоинтов/команд НЕ добавляется, RBAC-матрица не расширяется, биндинги не
регенерируются (форма payload не меняется).

Purpose: следующая заявка на замену для этого принтера найдёт «предыдущий» картридж
(привязка), а история возврата покажет, кто сдал и кто принял (инверсия).
Output: правка auto-return payload в cartridges_sqlite.rs + расширенные тесты.
