    Переписать `ws.ts`, сохранив публичный контракт (`onWsEvent`, `connectWs`,
    `disconnectWs`) и существующую логику reconnect/backoff/toast:
    1. Ввести модульный `let refCount = 0;` и `let activeCleanup: (() => void) | null = null;`.
       Идемпотентность строится на refCount, НЕ на проверке `ws !== null` (browser-ветка
       обнуляет `ws` на каждом reconnect, поэтому проверка по `ws` ненадёжна).
    2. `connectWs()`:
       - инкремент `refCount`.
       - если `refCount === 1` (первый потребитель): реально установить соединение —
         Tauri: `listen('trackly-event', e => dispatch(e.payload))`, сохранить unlisten
         в `activeCleanup`; browser: `connectBrowser()`, `activeCleanup` = функция,
         глушащая `ws.onclose` и закрывающая `ws` (как текущий `cleanup`, строки 100-106).
       - вернуть из `connectWs()` функцию-release: при вызове декрементит `refCount`,
         и ТОЛЬКО когда `refCount` достигает 0 — вызывает `activeCleanup()`, обнуляет
         `activeCleanup`, и (browser) сбрасывает reconnect-состояние (`reconnecting=false`,
         `reconnectDelay=1000`). Release должен быть идемпотентен (повторный вызов одним
         и тем же потребителем не уводит refCount ниже 0 — например, через локальный
         `let released = false` в замыкании).
    3. Browser reconnect: соединение пересоздаётся в `onclose` ТОЛЬКО пока `refCount > 0`.
       Когда последний потребитель отписался и `activeCleanup` заглушил `onclose`,
       reconnect-петля не должна возрождать соединение (текущий код уже зануляет
       `ws.onclose` в cleanup — сохранить это поведение внутри release при refCount→0).
    4. `disconnectWs()`: привести к семантике «принудительно сбросить всё» — обнулить
       `refCount = 0`, вызвать `activeCleanup()` если есть, обнулить `activeCleanup`.
       (Сохранить экспорт; он может вызываться при logout.)
    5. `dispatch()`/`onWsEvent()`/`handlers` — НЕ менять (подписки потребителей
       по-прежнему независимы; дубль убирается на уровне ЕДИНОГО соединения, а не
       обработчиков). НЕ менять текст/логику toast переподключения.
    Вызывающие три файла НЕ редактировать — их teardown уже вызывает возвращённый cleanup
    (теперь это release) и `unsubscribe()`.
