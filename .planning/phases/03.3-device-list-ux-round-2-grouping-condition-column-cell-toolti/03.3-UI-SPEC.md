## ITEM-1 — Колонка «Состояние» в таблице устройств

### Позиция в thead

Финальная структура таблицы (8 колонок на «Все», 7 на конкретном статусе):

| # | Колонка | Всегда / Условно |
|---|---------|-----------------|
| 1 | Наименование | всегда |
| 2 | Инвентарный № | всегда |
| 3 | Серийный № | всегда |
| 4 | Модель | всегда |
| 5 | Расположение | всегда |
| 6 | **Состояние** (НОВАЯ) | всегда |
| 7 | Статус | только `showStatus=true` (вкладка «Все») |
| 8 | Действия | всегда |

Источник порядка: RESEARCH.md §ITEM-3 colspan map; «после Расположение, перед Статус» — логический порядок, верифицирован через RESEARCH открытый вопрос 2.

### Заголовок th

```html
<th class="th th-condition">Состояние</th>
```

CSS класс `th-condition`:
- `width: 120px` (идентично `th-status` — симметрия)
- Все прочие свойства — от родительского `.th` (padding, font-size, color, white-space — унаследованы, без переопределений)

### Ячейка DeviceListRow (обычная строка)

```svelte
<td class="cell" title={device.state ?? ''}>{device.state ?? '—'}</td>
```

- Поле данных: `device.state` (TypeScript binding; в БД: `condition`)
- Отображение: значение `device.state` либо `—` если null
- Усечение: `.cell` уже имеет `white-space: nowrap; overflow: hidden; text-overflow: ellipsis; max-width: 0` — новая ячейка наследует автоматически
- Выравнивание: `text-align: left` (по умолчанию `.cell`)
- title: всегда равен значению поля (пустая строка если null, но `—` — UI-замена, а `title` хранит оригинал)

Дополнительный CSS не нужен — ячейка полностью соответствует паттерну `.cell`.

### Ячейка DeviceGroupRow (свёрнутая группа)

```svelte
<td class="cell" title={conditionDisplay}>{conditionDisplay}</td>
```

Где:
```ts
const conditionDisplay = $derived(
  group.condition_distinct_count > 1 ? 'разное' : (group.repr.state ?? '—')
);
```

**Правило «разное»** (ЗАФИКСИРОВАНО пользователем, UAT-ITEMS §Решения п.1):
- Если `condition_distinct_count > 1` → показать литерал **«разное»**
- Если `condition_distinct_count === 1` → показать `group.repr.state` (или `—` если null)
- Цвет «разное»: `--color-text-primary` (не выделять акцентом, не курсивить — это просто информационный текст)
- title на td: тот же `conditionDisplay`

### colspan-карта (ITEM-1 + ITEM-3 совместно)

| Место | Текущее | После ITEM-1+ITEM-3 |
|-------|---------|---------------------|
| Skeleton в `DeviceList` (кол-во ячеек) | `{ length: 7 }` | `{ length: showStatus ? 8 : 7 }` |
| `DeviceGroupRow` collapsed `colspan="4"` (Наим+Инв+Серийный+Модель) | 4 | **не меняется — 4** (Состояние идёт отдельной ячейкой, не входит в wide-ячейку) |
| Loading row в `DeviceGroupRow` | `colspan="7"` | `colspan={showStatus ? 8 : 7}` |

Источник: RESEARCH.md §ITEM-3 «Подсчёт colspan».

## ITEM-2 — Tooltip с полным содержимым ячейки

### Подход

Нативный HTML атрибут `title=` на все текстовые ячейки. Кастомный tooltip-компонент не вводится. Логика «только для обрезанных» (scrollWidth > clientWidth) не применяется — UAT-ITEMS прямо допускает «для всех ячеек».

Источник: UAT-ITEMS §ITEM-2 + RESEARCH §ITEM-2.

### DeviceListRow — ячейки с title

```svelte
<td class="cell cell-name"   title={device.name}>{device.name}</td>
<td class="cell cell-numeric" title={device.inventory_no ?? ''}>{device.inventory_no ?? '—'}</td>
<td class="cell cell-numeric" title={device.serial_no ?? ''}>{device.serial_no ?? '—'}</td>
<td class="cell"              title={device.model ?? ''}>{device.model ?? '—'}</td>
<td class="cell"              title={device.location ?? ''}>{device.location ?? '—'}</td>
<td class="cell"              title={device.state ?? ''}>{device.state ?? '—'}</td>
```

Ячейка «Статус» (Badge) и ячейка «Действия» (DeviceContextMenu) `title` не получают — это не текстовые ячейки, у них своё UI.

### DeviceGroupRow — ячейки с title (collapsed-строка)

```svelte
<td class="cell cell-name-wide" colspan="4" title={group.repr.name}>...</td>
<td class="cell"                title={group.repr.location ?? ''}>{group.repr.location ?? '—'}</td>
<td class="cell"                title={conditionDisplay}>{conditionDisplay}</td>
```

Ячейка «Статус» (Badge) и «Действия» (count-pill) — без `title`.

### Поведение

- Нативный tooltip (браузер / WebView2 / WKWebView)
- Задержка и стиль — браузерный дефолт
- Никаких анимаций, никаких CSS
- title выставляется всегда, независимо от того, обрезан ли текст — без JavaScript-проверки

## ITEM-3 — Колонка «Статус» только на вкладке «Все»

### Условие видимости

```
showStatus = (statusFilter === null)
```

- Вкладка «Все» (`statusFilter === null`) → `showStatus = true` → колонка «Статус» видна
- Любая другая вкладка (`statusFilter !== null`) → `showStatus = false` → колонка «Статус» скрыта

### Проп-цепочка

```
DevicesPage
  └─ showStatus={statusFilter === null}
       └─> DeviceList (props: showStatus)
             ├─> DeviceListRow (props: showStatus)
             └─> DeviceGroupRow (props: showStatus)
```

### DeviceList — thead

```svelte
{#if showStatus}<th class="th th-status">Статус</th>{/if}
```

Позиция: после `<th class="th th-condition">Состояние</th>`, перед `<th class="th th-actions">Действия</th>`.

### DeviceListRow — ячейка Статус

```svelte
{#if showStatus}
<td class="cell cell-status">
  <Badge variant={statusVariant}>{statusLabel}</Badge>
</td>
{/if}
```

### DeviceGroupRow — ячейка Статус (collapsed)

```svelte
{#if showStatus}
<td class="cell cell-status">
  <Badge variant={statusVariant}>{statusLabel}</Badge>
</td>
{/if}
```

### DeviceGroupRow — ячейка Статус (expanded children)

Дочерние строки рендерятся через `<DeviceListRow>` — тот же `showStatus` проп пробрасывается.

### Skeleton в DeviceList

```svelte
{#each { length: showStatus ? 8 : 7 } as _}
  <td class="skeleton-cell"><div class="skeleton-block"></div></td>
{/each}
```

### Loading row в DeviceGroupRow

```svelte
<td colspan={showStatus ? 8 : 7} class="children-loading">Загрузка…</td>
```

### Значение по умолчанию пропа

`DeviceList`: `showStatus?: boolean = true` (безопасный дефолт — старое поведение).

## ITEM-4 — Автокомплит «Расположение»: вторая секция «Все расположения»

### Scope

Только `DeviceAutocompleteField` при `field="location"`. Другие поля (`name`, `model`, `specs`, `kit`, `state`) не изменяются.

### Структура dropdown (только для field="location")

```
┌─────────────────────────────────────────────────┐
│ [dropdown-header] Ранее использовалось с «…»:   │  ← первая секция (существующая, условная)
│  item A                                          │
│  item B                                          │
├─────────────────────────────────────────────────┤
│ [dropdown-header] Все расположения:             │  ← НОВАЯ вторая секция
│  Склад №1                                        │
│  Серверная                                       │
│  …                                               │
└─────────────────────────────────────────────────┘
```

### Заголовок второй секции

```
Все расположения:
```

Точный текст. Отображается классом `dropdown-header` (уже существует):
- font-size: `--font-size-label` (13px)
- color: `--color-text-secondary`
- background: `--color-surface-sunken`
- border-bottom: `1px solid var(--color-border)`
- font-style: italic (унаследован от `.dropdown-header`)

### Порядок секций

1. Первая: «Ранее использовалось с «{contextName}»:» (существующая контекстная) — отображается только при наличии `contextName` и suggestions
2. Вторая: «Все расположения:» — всегда при `field="location"` и наличии allLocationSuggestions

### Источник данных второй секции

`locations_autocomplete` (Tauri command / HTTP endpoint) — тот же источник, что использует `LocationAutocomplete.svelte`. Параметр: текущее значение поля как prefix.

### Дедупликация

Из `allLocationSuggestions` убираем элементы, уже присутствующие в основной секции `suggestions`:
```ts
allLocationSuggestions = allLocs.filter(l => !suggestions.includes(l));
```

Если после дедупликации `allLocationSuggestions` пуст — секция «Все расположения:» не отображается.

### Стиль dropdown-item второй секции

Идентичен существующим `.dropdown-item`:
- padding: `var(--space-xs) var(--space-sm)`
- font-size: `--font-size-body`
- color: `--color-text-primary`
- hover: `background: var(--color-surface-sunken)`
- active (клавиатура): `background: color-mix(in srgb, var(--color-accent) 12%, transparent); color: var(--color-accent)`

Ключи `#each`: использовать `'all_' + s` чтобы не конфликтовать с основной секцией (у элементов из обеих секций может быть одинаковый текст после дедупликации в граничных случаях — нет, не может; но уникальный префикс ключа всё равно нужен для стабильности).

### Keyboard navigation

Navigation по ArrowUp/ArrowDown сквозная через обе секции. `activeIndex` охватывает объединённый массив: `[...suggestions, ...allLocationSuggestions]`. При нажатии Enter/Tab выбирается элемент из объединённого списка. Реализация — через объединённый массив `allItems = $derived([...suggestions, ...allLocationSuggestions])` и единый `activeIndex`.

### Новые токены

Не вводятся.

## Accessibility

- Нативный `title=` tooltip: встроенная поддержка assistive technologies
- `th` с текстом «Состояние» для новой колонки: достаточно для screen readers
- Условное скрытие `{#if showStatus}` убирает элемент из DOM полностью (не `visibility: hidden`) — screen reader не зачитывает скрытый th/td
- ARIA для второй dropdown-секции: `dropdown-header` без `role` (декоративный заголовок); `dropdown-item` имеет `role="option"` (унаследован от существующего паттерна)
