## ITEM-1 — Состояние не разбивает группу в списке устройств (+ колонка «Состояние»)

**Что не так сейчас:** DEF-2B (03.2-02) добавил `d.condition` в `GROUP BY` функции
`list_grouped` (`crates/trackly-infra/src/repos/devices_sqlite.rs`). Из-за этого на странице
«Устройства» два устройства с одинаковым Наименованием, но разным Состоянием попадают в
**разные** группы.

**Чего хочет пользователь:**
- На странице «Устройства» (`DevicesPage` → `devices.listGrouped`) Состояние **НЕ должно**
  разбивать группу. Откатить SQL-разбивку по `condition` **только для этого вызова**.
- Вместо разбивки — добавить **колонку «Состояние»** в таблицу устройств
  (`DeviceList.svelte` thead, `DeviceListRow.svelte`, `DeviceGroupRow.svelte`).
- Для **свёрнутой группы со смешанными** значениями Состояния показывать **«разное»**.
  (Конкретные значения видны при разворачивании группы — по строкам.)

**КРИТИЧНО — не сломать акт-форму:** `ActFormItemsTable.svelte` (автокомплит при создании
Акта) вызывает **тот же** `devices.listGrouped`. Там разбивка по Состоянию **должна
остаться как сейчас** (поведение DEF-2B). Значит два вызова нужно развести:
- Вариант A: добавить флаг в `DeviceFilter` (напр. `group_by_condition: bool`) — страница
  Устройства передаёт `false`, акт-форма `true`.
- Вариант B: отдельный repo-метод / параметр у `list_grouped`.
- Точное решение — за фазой планирования/ресёрча.

**Поле:** в UI зовётся `state`, в БД — `condition` (см. маппинг в `devices_sqlite.rs`).

**Затронутые файлы (ожидаемо):**
- `crates/trackly-infra/src/repos/devices_sqlite.rs` (list_grouped: условная разбивка)
- `crates/trackly-core/src/ports/devices.rs` / `domain/devices.rs` (DeviceFilter / сигнатура)
- `crates/trackly-app/src/services/device_service.rs`, `http/devices.rs`, `tauri_cmds/devices.rs`
- `ui/src/features/devices/DeviceList.svelte` (новая колонка thead + colspan-ы)
- `ui/src/features/devices/DeviceListRow.svelte` (ячейка Состояние)
- `ui/src/features/devices/DeviceGroupRow.svelte` (ячейка Состояние группы: значение или «разное»)
- `ui/src/features/devices/DevicesPage.svelte` (передать group_by_condition=false)
- `ui/src/features/acts/ActFormItemsTable.svelte` (передать group_by_condition=true — сохранить)
- тесты: `crates/trackly-app/tests/devices_grouping.rs`

## ITEM-2 — Tooltip с полным содержимым ячейки при наведении

(обрезается ellipsis), при наведении курсора показывать hint/tooltip с полным содержимым.

через сравнение `scrollWidth > clientWidth`. Решение — за планом.

## ITEM-4 — Автокомплит «Расположение» при добавлении устройства: + секция всех локаций

**Что есть сейчас:** в форме добавления устройства (`DeviceFormBody.svelte`) поле
«Расположение» использует `DeviceAutocompleteField` (field="location"), который предлагает
локацию по совпадению **Наименования** ранее добавленного устройства (помечается в дропдауне).

**Чего хочет пользователь:** оставить контекстную подсказку по Наименованию, но **добавить
ниже вторую секцию** со **всеми** возможными вариантами Расположения из БД (distinct по полю
`location` всех устройств). Нужно, потому что похожее устройство может быть в другом месте, и
для добавления **нового** устройства (которого ещё не было в БД).

**Заметки:** в проекте уже есть `ui/src/lib/components/LocationAutocomplete.svelte` (источник
distinct-локаций) — переиспользовать его источник данных или добавить вторую группу в
`DeviceAutocompleteField` для field="location". Решение — за планом.

**Затронутые файлы:**
- `ui/src/features/devices/DeviceAutocompleteField.svelte` (вторая секция «все локации»)
- возможно backend: эндпоинт distinct-локаций (проверить, чем питается LocationAutocomplete)
- `ui/src/features/devices/DeviceFormBody.svelte` (если меняется проп/компонент)
