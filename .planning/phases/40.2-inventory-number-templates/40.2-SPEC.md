# Phase 40.2: Шаблоны инвентарных номеров — Specification

**Created:** 2026-09-18
**Ambiguity score:** 0.16 (gate: ≤ 0.20)
**Requirements:** 16 locked

## Goal

Номера устройств и принтеров, актов, картриджей и фотобарабанов подставляются по шаблонам, которые администратор ведёт в «Настройки / Организация». Сейчас номера берутся из жёстких счётчиков, и шаблонов нет. Следующий номер сервер вычисляет по существующим данным и умеет предлагать номер из разрыва и max+1. Во всех трёх пространствах номеров дубликаты запрещены.

## Background

Как нумерация устроена сейчас (по коду):

- **Акты.** `acts.number` — `INTEGER` (`migrations/V004__acts.sql`). Уникальность `(number, COALESCE(sub_number,0))` проверяется только среди живых актов. Следующий номер считается как `MAX(number)+1` среди живых актов (`next_act_number_from_max`, `act_service.rs`) и отдаётся через `acts_peek_next_number` (Tauri + `POST /api/v1/acts_peek_next_number`). Номер удалённого акта освобождается. Акты возврата показывают номер родителя с суффиксом: «42в», при нескольких возвратах «42в1» и «42в2» (`format_act_number`, D-Numbering-01). Ручной номер можно задать через `number_override` при создании и при правке; такая операция пишется в аудит как `custom:act_number_override`. В форме номер вводит `ui/src/features/acts/ActNumberField.svelte` (бейдж «авто/override»).
- **Картриджи и фотобарабаны.** Обе сущности живут в одной таблице `cartridges`, различаются полем kind. Столбец `code TEXT NOT NULL UNIQUE` уникален глобально, включая мягко удалённые записи. Если код не введён, он генерируется из счётчиков `counters.cartridge_seq` (`C-NNNNNN`) и `counters.drum_seq` (`D-NNNNNN`, V017). Ручной код передаётся через `code_override` (`CartridgeFormBody.svelte`, поле «Код», переключатель «Что добавляем»). При правке код не меняется.
- **Устройства и принтеры.** Столбец `devices.inventory_number TEXT NULL`: уникальности нет, в живой БД возможны дубли. Принтер — это устройство (`printers.device_id`). Поле «Инвентарный №» есть в `DeviceFormBody.svelte` и в попапе «Новый принтер». Импорт CSV (`DeviceImportCsvModal.svelte`, `device_service.rs`) дубли не проверяет.
- **Счётчики.** Таблица `counters` (V009) хранит `act_number`, `cartridge_seq` и `drum_seq`. Для актов она уже фактически заменена на MAX+1.
- **Настройки.** Экран организации — `ui/src/features/settings/OrgSettings.svelte`. Иконки «Вставка» (папка с листком) в наборе нет. Кнопка GHOST есть в витрине (`Button.svelte`). Меню-компонент — `ActionMenu.svelte`.

Чего нет: сущности «шаблон номера», вычисления следующего номера по маске, запоминания последнего шаблона попапа, проверки уникальности инвентарных номеров, попапов «номер занят» и «не соответствует шаблону».

## Requirements

1. **Сущность и CRUD шаблонов**: в самом низу «Настройки / Организация» появляется блок «Шаблоны для инвентарных номеров», где шаблоны можно создавать, просматривать, редактировать и удалять.
   - Current: шаблонов нет. Номера задают счётчики V009/V017 и MAX+1.
   - Target: у шаблона есть тип и маска (строка). Типов ровно 4: «Устройства и принтеры», «Акты», «Картриджи», «Фотобарабаны». Маска уникальна внутри типа. Список показывает тип, маску и следующий номер либо статус «переполнен». В блоке есть краткая справка по токенам с примерами `ОРГ-00-[XXXXXX]` и `[YYYY]/[MM]-[X]`. Права на CRUD такие же, как на остальные поля «Настройки / Организация». Данные живут в БД и переносятся вместе с portable-сборкой.
   - Acceptance: через UI создаётся шаблон типа «Акты» с маской `[YYYY]/[MM]-[X]`. Он появляется в списке с предпросмотром следующего номера, редактируется и удаляется. После перезапуска приложения шаблон на месте. Второй шаблон с той же маской и тем же типом отклоняется с понятной ошибкой.

2. **Синтаксис маски**: подставляются только токены `[YYYY]`, `[YY]`, `[MM]`, `[DD]` и `[X…]`. Любой другой текст, включая `[Q]`, остаётся буквальным.
   - Current: масок нет.
   - Target: `[YYYY]` — год из 4 цифр, `[YY]` — год из 2 цифр, `[MM]` — месяц 01–12, `[DD]` — день 01–31. Дата берётся на сервере в момент вычисления. `[X]` — число от 1 без дополнения нулями и без верхней границы. `[X…]` из N букв X — число шириной N с ведущими нулями, от 1 до 10^N−1. Токены распознаются только в верхнем регистре, в точном написании. В маске должен быть ровно один токен `[X…]`; маска без него или с двумя такими токенами не сохраняется, форма показывает ошибку.
   - Acceptance: маска `ОРГ-00-[XXXXXX]` на пустой базе даёт `ОРГ-00-000001`. `[YYYY]/[MM]-[X]` 18.09.2026 даёт `2026/09-1`. `A[Q]-[XX]` даёт `A[Q]-01`. Маски `ОРГ-[YYYY]` и `[X]-[XX]` отклоняются при сохранении.

3. **Предпросмотр в форме шаблона**: форма создания и редактирования шаблона показывает следующий номер вживую, пока пользователь вводит маску.
   - Current: нет.
   - Target: предпросмотр пересчитывается на каждое изменение маски или типа и учитывает существующие записи этого типа.
   - Acceptance: пользователь вводит `C-[XXXXXX]` при существующих `C-000001..C-000005`, и предпросмотр показывает `C-000006`.

4. **Вычисление следующего номера по данным**: сервер вычисляет «первый свободный» и «max+1» по живым записям пространства номеров, которые подходят под маску. Отдельный счётчик не хранится.
   - Current: номера берутся из счётчиков (`counters`) или MAX+1 по актам.
   - Target: запись подходит под маску, если после trim и без учёта регистра совпадают буквальные части и развёрнутые сегодняшние даты, а на месте `[X…]` стоят ровно N цифр (для `[X]` — одна или больше цифр). Последовательность считается отдельно для каждого развёрнутого префикса, поэтому шаблон с `[MM]` каждый месяц начинает заново, с `[DD]` — каждый день. «Первый свободный» — наименьшее свободное число ≥ 1 в пределах разрядности. «max+1» — максимум + 1. Если свободных чисел ниже максимума нет, оба значения совпадают. Если записей нет, результат — 1. Мягко удалённые записи номер не занимают. Импорт, ручной ввод и удаление учитываются автоматически, потому что состояние нигде не хранится.
   - Acceptance: для `ОРГ-00-[XXXXXX]` при живых `…000001..000016` и `…000020` предлагаются `ОРГ-00-000017` и `ОРГ-00-000021`. При живых только `…000500..000510` предлагаются `…000001` и `…000511`. При `…000001..000003` оба значения равны `…000004`. После мягкого удаления `…000002` первым свободным становится `…000002`. `2026/10-…` не учитывается в последовательности `2026/09-…`.

5. **Переполнение**: шаблон считается переполненным, когда в его разрядности не осталось ни одного свободного числа.
   - Current: нет.
   - Target: если max+1 не помещается в разрядность, но разрыв есть, в поле подставляется разрыв, а переключателя ↑/↓ нет. Если свободных чисел нет совсем, шаблон в контекстном меню «Вставка» серый и недоступен, а в списке настроек помечен «переполнен». Если запомненный шаблон попапа переполнен, пользователь получает сообщение о переполнении, и поле остаётся пустым. Для `[X]` переполнения не бывает.
   - Acceptance: для `[XX]` при занятых `01..99` шаблон в меню недоступен и помечен в настройках. При занятых `01..16, 18..99` подставляется `17`, кнопки ↑/↓ нет.

6. **Поле номера с шаблоном в четырёх попапах**: поле ввода номера заменяется компонентом с автоподстановкой в «Новое устройство» и «Новый принтер» (поле «Инвентарный №»), «Новый акт» (поле «№ *») и «Новый картридж/фотобарабан» (поле «Код»).
   - Current: обычные поля ввода. У акта — `ActNumberField` с бейджем «авто/override».
   - Target: подписи полей остаются прежними. При открытии попапа поле заполняется «первым свободным» по последнему использованному в этом попапе шаблону (см. п. 8). Если шаблон не запомнен, поле пустое. Справа от поля стоит прозрачная квадратная кнопка варианта GHOST из витрины с новой иконкой «Вставка» (папка с листком). Она открывает контекстное меню со всеми шаблонами соответствующего типа и пунктом «Без шаблона». Выбор шаблона сразу заполняет поле его следующим номером.
   - Acceptance: в каждом из четырёх попапов есть кнопка «Вставка». Меню показывает только шаблоны своего типа: в попапе устройства нет шаблонов актов. Выбор шаблона меняет значение поля на его следующий номер.

7. **Переключатель разрыва ↑/↓**: если «первый свободный» отличается от «max+1», внутри поля справа появляется маленькая кнопка со стрелкой.
   - Current: нет.
   - Target: при подставленном «первом свободном» кнопка показывает стрелку вверх, нажатие меняет значение на max+1, и стрелка становится стрелкой вниз. Повторное нажатие возвращает «первый свободный». Кнопка видна только пока значение поля равно одному из двух предложенных. Когда оба значения совпадают, кнопки нет.
   - Acceptance: при `…000016` и `…000020` поле показывает `…000017` со стрелкой ↑. Нажатие даёт `…000021` со стрелкой ↓, ещё одно нажатие даёт `…000017`. При ручной правке значения кнопка исчезает.

8. **Серверная память последнего шаблона попапа**: сервер хранит последний использованный шаблон (или «без шаблона») отдельно для 5 контекстов: «Новое устройство», «Новый принтер», «Новый акт», «Новый картридж», «Новый фотобарабан». Память общая для всех пользователей и режимов (десктоп и LAN).
   - Current: нет.
   - Target: после успешного создания записи контекст запоминает выбранный шаблон, если номер ему соответствует. Если пользователь подтвердил несоответствие (п. 10) или шаблон не был выбран, запоминается «без шаблона». В этом состоянии попап по умолчанию ничего не подставляет, пока пользователь сам не выберет шаблон через «Вставка». Если запомненный шаблон удалили, контекст переходит в «без шаблона». В «Новом картридже/фотобарабане» смена «Что добавляем» переключает поле на шаблон, запомненный для выбранного вида, и подставляет его следующий номер.
   - Acceptance: пользователь А создаёт устройство по шаблону T, и у пользователя Б в LAN-браузере следующий попап «Новое устройство» открывается с номером по T. После создания с подтверждённым несоответствием следующий попап открывается с пустым полем. После удаления T попап открывается пустым. Переключение «Картридж ↔ Фотобарабан» меняет номер на следующий номер своего запомненного шаблона.

9. **Уникальность номеров в трёх пространствах**: сервер не даёт сохранить номер, который уже есть у живой записи того же пространства. Сравнение идёт после trim и без учёта регистра.
   - Current: у устройств уникальности нет. Код картриджа уникален глобально, включая удалённые. Акты уникальны среди живых.
   - Target: пространств три: (а) инвентарные номера устройств и принтеров, (б) номера актов, (в) коды картриджей и фотобарабанов. Мягко удалённые записи номер освобождают. Пустой инвентарный номер устройства под проверку не попадает. Правило действует при создании и при редактировании (везде, где номер можно изменить), в Tauri и в HTTP одинаково, и гарантируется на стороне сервера при одновременных запросах.
   - Acceptance: создать второе живое устройство с `ОРГ-00-000001`, в том числе как `орг-00-000001 ` с пробелом, нельзя. После мягкого удаления первого устройства создать можно. Код `C-000001` при живом картридже `C-000001` отклоняется, при мягко удалённом принимается. Номер акта `2026/09-1` не конфликтует с инвентарным номером `2026/09-1`. Правка устройства на уже занятый номер отклоняется. Из двух параллельных запросов с одним номером успешен ровно один.

10. **Попап «Номер занят»**: при попытке сохранить занятый номер появляется попап с краткой информацией о записи, которая уже под этим номером.
    - Current: у картриджа только текст ошибки под полем. У остальных сущностей попапа нет.
    - Target: попап показывает вид записи (устройство, принтер, картридж, фотобарабан или акт) и её ключевые данные: наименование или модель, место и статус; для акта — дату и стороны. Если в поле активен шаблон, есть кнопка «Взять следующий свободный»: она запрашивает у сервера актуальный следующий номер, подставляет его в поле и закрывает попап. Есть кнопка закрытия.
    - Acceptance: при сохранении с занятым `ОРГ-00-000005` попап показывает сведения о записи с этим номером. «Взять следующий свободный» подставляет актуальный свободный номер. Повторное сохранение проходит.

11. **Попап «Не соответствует шаблону»**: если в поле выбран шаблон, а введённое значение ему не соответствует, при сохранении появляется небольшой попап.
    - Current: нет.
    - Target: текст попапа сообщает, что значение не соответствует шаблону. Кнопки: «Поправлю» — отмена, возврат в форму; «Продолжить» — красная, danger, сохраняет номер как есть. После «Продолжить» контекст попапа запоминает «без шаблона» (п. 8). Если шаблон не выбран, этот попап не показывается. Любой номер, не похожий на маску, разрешён.
    - Acceptance: при активном `ОРГ-00-[XXXXXX]` и значении `ИНВ-7` появляется попап. «Поправлю» ничего не сохраняет. «Продолжить» сохраняет `ИНВ-7`, и следующий такой попап открывается с пустым полем.

12. **Предупреждение о смешении кириллицы и латиницы**: при сохранении появляется неблокирующий попап «Поправлю / Продолжить», если номер содержит буквы и кириллицы, и латиницы, или если после замены похожих букв он совпадает с существующим живым номером того же пространства.
    - Current: нет.
    - Target: предупреждение не запрещает сохранение. При подтверждении запись сохраняется с введённым номером.
    - Acceptance: `OPГ-00-000001` (O и P латинские) вызывает предупреждение. Если `ОРГ-00-000001` уже существует, в тексте предупреждения упоминается совпадение-«двойник». `ОРГ-00-000001` при отсутствии двойника сохраняется без предупреждения.

13. **Замена счётчиков шаблонами + засев**: счётчики `act_number`, `cartridge_seq` и `drum_seq` больше нигде в коде не используются. Миграция засевает шаблоны, которые воспроизводят текущую схему.
    - Current: номера генерируются из `counters` или MAX+1.
    - Target: миграция создаёт шаблоны `[X]` («Акты»), `C-[XXXXXX]` («Картриджи») и `D-[XXXXXX]` («Фотобарабаны») и назначает их запомненными для контекстов «Новый акт», «Новый картридж» и «Новый фотобарабан». Для устройств и принтеров шаблона нет, контексты в состоянии «без шаблона». Без шаблона поле «№ *» акта и поле «Код» картриджа или фотобарабана обязательны: пустое значение даёт ошибку валидации, серверной автогенерации нет. «Инвентарный №» устройства и принтера остаётся необязательным.
    - Acceptance: после обновления существующей БД попап «Новый акт» предлагает MAX+1 от существующих номеров актов, «Новый картридж» — следующий `C-NNNNNN`, как было до обновления. Grep по коду сервисов не находит чтений или записей `act_number`, `cartridge_seq`, `drum_seq` в `counters`. Создание акта с пустым № отклоняется ошибкой валидации.

14. **Номер акта — текст, возвраты — суффикс родителя**: номер акта передачи хранится как строка и может быть любым, например `2026/09-1`. Акт возврата наследует номер родителя по текущему правилу суффикса «в».
    - Current: `acts.number` — `INTEGER`, возврат выводится через `format_act_number`.
    - Target: существующие номера конвертируются без потерь («42» остаётся «42»). У возврата номер = номер родителя + «в» или «вN» по действующему правилу D-Numbering-01, например `2026/09-1в`. Шаблон и поле номера с автоподстановкой относятся только к актам передачи. Номера возвратов в последовательности шаблона не участвуют.
    - Acceptance: после миграции номера всех существующих актов и возвратов в списке совпадают с номерами до миграции. Возврат по акту `2026/09-1` отображается как `2026/09-1в`. При наличии `42в` шаблон `[X]` всё равно предлагает `43`.

15. **Миграция дублей инвентарных номеров**: перед введением уникальности существующие дубли среди живых устройств переименовываются автоматически, и миграция не падает.
    - Current: дубли возможны.
    - Target: внутри каждой группы совпадающих номеров (trim, без учёта регистра) номер сохраняет самая ранняя запись. Остальные получают `ДУБЛЬ-NNNNNN (<исходный номер>)` из одной сквозной последовательности шириной 6 с началом от 000001. Каждая замена пишется в журнал аудита.
    - Acceptance: БД с тремя живыми устройствами `ОРГ-00-000007` (id 3, 8, 12) после миграции: у id 3 номер `ОРГ-00-000007`, у id 8 — `ДУБЛЬ-000001 (ОРГ-00-000007)`, у id 12 — `ДУБЛЬ-000002 (ОРГ-00-000007)`. Для каждой замены есть запись в аудите. Миграция завершается успешно.

16. **Импорт CSV проверяет дубли**: строка, чей инвентарный номер занят в БД или встречался выше в том же файле, не импортируется и попадает в отчёт об ошибках. Остальные строки импортируются.
    - Current: дубли не проверяются.
    - Target: причина в отчёте — «номер уже занят». Соответствие маскам при импорте не проверяется.
    - Acceptance: файл из 5 строк, где строка 3 дублирует существующий номер, а строка 5 дублирует строку 1, импортирует 3 строки, и в отчёте две ошибки с номерами строк.

## Boundaries

**In scope:**
- Таблица шаблонов (тип + маска) и серверная память последнего шаблона для 5 контекстов попапов
- Блок «Шаблоны для инвентарных номеров» внизу «Настройки / Организация»: CRUD, справка по токенам, предпросмотр, статус «переполнен»
- Серверное вычисление «первый свободный / max+1» по данным (Tauri command + HTTP-эндпоинт с одинаковой логикой)
- Компонент поля номера с кнопкой «Вставка» (GHOST, новая иконка в наборе и витрине), контекстным меню шаблонов и переключателем ↑/↓ внутри поля
- Встраивание компонента в попапы «Новое устройство», «Новый принтер», «Новый акт», «Новый картридж/фотобарабан» (с переключением по «Что добавляем»)
- Серверная уникальность в трёх пространствах при создании и правке, освобождение номера при мягком удалении
- Попапы «Номер занят» (с «Взять следующий свободный»), «Не соответствует шаблону», предупреждение о смешении кириллицы и латиницы
- Миграции: `acts.number` в текст с сохранением отображения, дубли в `ДУБЛЬ-…`, засев шаблонов, уникальность кода картриджа только среди живых записей
- Отказ от счётчиков `act_number`, `cartridge_seq` и `drum_seq` и от серверной автогенерации номеров
- Проверка дублей при импорте CSV устройств

**Out of scope:**
- Шаблоны и автоподстановка в формах редактирования. При правке только проверяется уникальность. Пользователь просил менять поля именно в попапах создания.
- Изменение кода картриджа при редактировании. Сейчас это не поддерживается, и фаза этого не расширяет.
- Отдельная нумерация актов возврата по шаблону. Решено: возврат наследует номер родителя с суффиксом.
- Поля номера в других местах: клоны V015 (инв. № = NULL), заявки, АРМ (Фаза 41). Номеров там нет, или они вне этой фичи.
- Персональная память шаблона для каждого пользователя. Решено: память общая, серверная.
- Проверка соответствия маске при импорте CSV. Решено: только дубли.
- Физическое удаление таблицы `counters`. Достаточно, что код её не использует. Решение о DROP — на уровне discuss-phase.
- Иные токены (часы, квартал, код места и т. п.). Пользователь ограничил набор шестью видами токенов.

## Constraints

- Портативность: шаблоны и память контекстов хранятся в SQLite рядом с БД и не пишутся в системные пути.
- Единый писатель: все записи (CRUD шаблонов, память контекстов, создание записей) идут через writer-сервис. Tauri и HTTP — тонкие адаптеры к одной бизнес-логике (CLAUDE.md, Dual access path).
- Номер и уникальность считает сервер. Клиент может показывать предпросмотр, но итоговую проверку делает сервер в транзакции записи. Это покрывает гонку двух пользователей (п. 9).
- Миграции на живой БД не должны падать ни на дублях, ни на нечисловых данных. Отображаемые номера существующих актов не меняются.
- UI и тексты только на русском. Контекстное меню использует существующие компоненты меню и dropdown; нативный `<select>` не используется (память: native_select_vs_custom_dropdown).
- Приватность: в тестах, фикстурах и артефактах только вымышленные маски и номера (`ОРГ-00-…`, `C-…`). Реальные инвентарные номера организации запрещены.
- Инвалидация: создание, удаление и правка записей и шаблонов должны обновлять предпросмотр и меню у других клиентов по существующему механизму инвалидации (память: invalidation_write_sites_enumerate_from_server).

## Acceptance Criteria

- [ ] Блок «Шаблоны для инвентарных номеров» внизу «Настройки / Организация» поддерживает создание, правку и удаление шаблонов 4 типов и показывает справку по токенам
- [ ] Маска без `[X…]` или с двумя `[X…]` не сохраняется; `[Q]` остаётся буквальным текстом
- [ ] Форма шаблона показывает вживую предпросмотр следующего номера с учётом существующих записей
- [ ] `ОРГ-00-[XXXXXX]` при `…01..16` и `…20` предлагает `…17`, переключатель ↑ даёт `…21`, ↓ возвращает `…17`
- [ ] При записях только `…500..510` предлагается `…000001`, по ↑ — `…000511`
- [ ] Для `[YYYY]/[MM]-[X]` последовательность начинается заново с новым месяцем
- [ ] Переполненный шаблон (нет свободных чисел в разрядности) в меню «Вставка» серый и недоступен, в настройках помечен; при max+1 за разрядностью, но с разрывом, подставляется разрыв без ↑/↓
- [ ] В 4 попапах есть кнопка GHOST «Вставка» с новой иконкой; меню показывает только шаблоны своего типа и пункт «Без шаблона»
- [ ] Последний шаблон (или «без шаблона») запоминается на сервере для 5 контекстов и одинаков для всех пользователей и режимов
- [ ] Смена «Что добавляем» переключает поле «Код» на запомненный шаблон выбранного вида
- [ ] После «Продолжить» в попапе несоответствия следующий попап этого контекста открывается пустым
- [ ] Удаление запомненного шаблона переводит контекст в «без шаблона»
- [ ] Живой дубль номера отклоняется при создании и при правке (trim, без учёта регистра) в каждом из трёх пространств; мягко удалённая запись номер не занимает
- [ ] Попап «Номер занят» показывает вид и ключевые данные занявшей записи; «Взять следующий свободный» подставляет актуальный номер
- [ ] Из двух параллельных сохранений с одним номером успешно ровно одно
- [ ] Смешение кириллицы и латиницы или совпадение-двойник вызывает неблокирующее предупреждение «Поправлю / Продолжить»
- [ ] Код сервисов не читает и не пишет `counters.act_number`, `cartridge_seq`, `drum_seq`; пустой № акта или код картриджа без шаблона даёт ошибку валидации
- [ ] После миграции существующие шаблоны `[X]`, `C-[XXXXXX]`, `D-[XXXXXX]` засеяны и назначены своим контекстам; следующие номера совпадают с теми, что выдавались до обновления
- [ ] После миграции номера всех существующих актов и возвратов отображаются как до неё; возврат по `2026/09-1` отображается как `2026/09-1в`
- [ ] Миграция живой БД с дублями инвентарных номеров проходит: самая ранняя запись сохраняет номер, остальные получают `ДУБЛЬ-NNNNNN (<исходный>)` с записью в аудит
- [ ] Импорт CSV пропускает строки с номерами, занятыми в БД или выше в файле, и перечисляет их в отчёте об ошибках
