    `value` на другое из двух значений, фокус остаётся на стрелке. Любой РУЧНОЙ ввод (`oninput`,
    значение перестаёт совпадать ни с одним из двух) скрывает стрелку немедленно.

    Живая подсказка «занят» (D-02/D-03): debounce 400 мс после `oninput`, пустое значение не
    проверяется, вызов `number_templates_is_occupied(context, value.trim(), exclude_id=null)`
    (`exclude_id` — проп, передаётся формой-хостом при РЕДАКТИРОВАНИИ, если этот компонент вообще

    отбрасываются по номеру запроса (`requestId` инкремент + сравнение при получении ответа).
    Результат `Some(record)` → строка под полем «Занят: {вид} «{наименование}»» (для акта —
    «Занят: акт от {дата}») — `aria-live="polite"`, warning-цвет, поле НЕ помечается `invalid`.
    Кир/лат и двойник НЕ показываются в этой подсказке (D-03 — только при сохранении, реализуется
    формой-хостом через отдельный вызов при клике «Создать»).

    Приоритет строки под полем (UI-SPEC §2, по убыванию): 1) `errorMessage` (проп, `--tr-danger-
    text`) 2) «Шаблон {маска} переполнен…» (если выбранный шаблон `overflowed`) 3) «Занят: …» 4)
    «Шаблон: {маска}» (`--tr-text-tertiary`, когда `selectedTemplateId !== null` и ничего из
    1-3 не активно) 5) ничего. Одна строка, `overflow:hidden;text-overflow:ellipsis;white-space:
    nowrap`, `title` = полный текст, `aria-describedby` связывает с `Input`.

    Тихая замена (D-14, W6): подписаться на `WsEvent::NumberSpaceChanged` там, где сейчас
    подписывается остальной WS-клиент проекта (найти существующий паттерн подписки перед

    "тип шаблона → контекст" на клиенте, НИКАКОЙ локальной копии `action_for_context`/
    `template_type` (это и была ошибка предыдущей редакции плана — устранена по W6, память
