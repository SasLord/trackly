# Phase 40.2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Как читать этот контракт.** Фаза встраивается в зрелую дизайн-систему Trackly (собственные
токены `--tr-*` и библиотека `ui/src/lib/components/*`, фазы 23–30). Новых токенов нет. Новое —
одна иконка, один составной компонент поля номера, блок в «Настройки / Организация» и три
попапа проверки при сохранении. Всё, что не зафиксировано SPEC.md / CONTEXT.md, вынесено в
**§ Claude's Discretion** в конце, а не спрятано в таблицах.

Все примеры в этом документе вымышленные (`ОРГ-00-…`, `C-…`, «Иванов И.И.»). Реальные номера,
названия и ФИО организации сюда и в тесты не попадают (CLAUDE.md, приватность).

## Spacing Scale

Новых значений нет. Используется существующая шкала `--tr-space-*` из `ui/src/styles/_tokens.scss`
(все значения кратны 4, кроме давно существующего 2px `3xs`, который эта фаза не использует).

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| `--tr-space-2xs` | 4px | Зазор подпись → поле → строка под полем (как `FormField`); отступ стрелки ↑/↓ от правого края поля; вертикальный отступ разделителя в меню «Вставка» |
| `--tr-space-xs` | 8px | Зазор между полем и кнопкой «Вставка»; зазор колонок внутри пункта меню (галочка · маска · следующий номер); зазор кнопок в подвале попапов |
| `--tr-space-sm` | 12px | Горизонтальный padding ячеек таблицы шаблонов; горизонтальный padding пунктов меню (как `ActionMenu`) |
| `--tr-space-md` | 16px | Зазор между полями в модалке шаблона; зазор между строками карточки в попапе «Номер занят»; `padding-top`/`margin-top` блока шаблонов (как `.path-section`) |
| `--tr-space-xl` | 24px | Внутренний padding `.settings-section` (существующий, не меняется) |

Фиксированные размеры элементов (все кратны 4):

| Элемент | Размер |
|---------|--------|
| Кнопка «Вставка» | 36×36px (высота `Input` = высота `Button size="md"`) |
| Хит-зона стрелки ↑/↓ внутри поля | 28×28px, иконка 16×16px |
| Иконка «Вставка» | 20×20px |
| `padding-right` поля, когда стрелка видна | 36px (вместо 16px) |
| Панель меню «Вставка» | `min-width: 280px`, `max-width: 420px` |

Exceptions (все значения — существующие токены или кратны 4):
- **12px (`--tr-space-sm`)** — горизонтальный padding пунктов меню «Вставка» и ячеек таблицы шаблонов. Существующий токен шкалы; совпадает с padding пунктов `ActionMenu` (`8px 12px`), поэтому меню «Вставка» выглядит как остальные меню приложения.
- **`padding-right: 36px` у поля номера, пока видна стрелка ↑/↓** = 4px отступ + 28px хит-зона стрелки + 4px зазор до текста. Без стрелки остаётся штатный padding `Input` (16px).

## Typography

Новых размеров и начертаний нет. Эта фаза использует 4 роли из существующих:

| Role | Size | Weight | Line Height | Usage in this phase |
|------|------|--------|-------------|---------------------|
| Subsection heading | 14px | 500 (`--tr-font-weight-medium`) | 1.5 | «Шаблоны для инвентарных номеров» — клон существующего `.subsection-title` в `OrgSettings.svelte` |
| Body | 14px | 400 | 1.5 | Текст попапов, пункты меню, ячейки «Тип», поле номера, вводный текст блока |
| Label | 13px | 500 | 1.4 | Подписи полей («Тип», «Маска», «Следующий номер»), заголовки столбцов, строка под полем (шаблон / «Занят: …» / ошибка), справка по токенам |
| Mono | 13px | 500 | 1.4 (tabular-nums) | Маски и номера: столбцы «Маска» и «Следующий номер», предпросмотр в модалке, маска и номер в пунктах меню, токены в справке, поле «Маска» (`<Input mono>`) |

Заголовки модалок и попапов — существующий `.modal-title` (20px / 600 / 1.3), не меняется.

Размеры 13px и 14px — существующие системные токены (`--tr-font-size-label`, `--tr-font-size-body`), новых размеров нет. Заголовок подраздела совпадает с body по размеру (14px) и отличается от него начертанием 500 и отступами (`margin: 0 0 var(--tr-space-xs)` и `border-top` + `padding-top: 16px` у обёртки блока), как у существующего `.subsection-title` в `OrgSettings.svelte`.

Начертания, которые эта фаза вводит в новый текст: ровно 2 — 400 (regular) и 500 (medium).
600 (semibold) появляется только внутри переиспользуемых компонентов (`Button`, `.modal-title`),
этой фазой не добавляется.

Поле номера в четырёх попапах создания **не** переводится в моноширинный шрифт: оно остаётся
обычным `Input`, как сейчас (без визуального скачка относительно соседних полей).

предложениях. Кавычки — «ёлочки».

### Справка по токенам (компонент `NumberMaskHelp`, показывается в блоке под таблицей и в модалке)

| Токен | Текст |
|-------|-------|
| `[YYYY]` | год, 4 цифры — 2026 |
| `[YY]` | год, 2 цифры — 26 |
| `[MM]` | месяц — 01…12 |
| `[DD]` | день — 01…31 |
| `[X]` | порядковый номер без нулей — 1, 2 … 125 |
| `[XXXX]` | порядковый номер с нулями, сколько X — столько цифр — 0001 … 9999 |
| Правило | «В маске ровно один порядковый номер ([X], [XX], [XXX] …). Остальной текст, включая другие скобки, остаётся как есть. Токены пишутся заглавными латинскими буквами.» |
| Пример 1 | `ОРГ-00-[XXXXXX]` → `ОРГ-00-000001` |
| Пример 2 | `[YYYY]/[MM]-[X]` → `2026/09-1` — «нумерация начинается заново каждый месяц» |

### 2. Анатомия поля номера (`NumberTemplateField`)

```
Инвентарный №                              ← подпись (существующая, не меняется)
┌──────────────────────────────┬─┐ ┌────┐
│ ОРГ-00-000017              ↑ │ │ │ 📁 │ ← Input + стрелка внутри справа | кнопка «Вставка» 36×36
└──────────────────────────────┴─┘ └────┘
Шаблон: ОРГ-00-[XXXXXX]                    ← одна строка под полем (приоритеты ниже)
```

- Ряд: `display: flex; gap: var(--tr-space-xs); align-items: center`. Поле — `flex: 1 1 auto; min-width: 0`, кнопка — `flex: none`.
- **Стрелка ↑/↓ (D-19):** `<button type="button">` поверх `Input` в `position: absolute; right: 4px; top: 50%; transform: translateY(-50%)`, 28×28, фон прозрачный всегда (без hover-фона), цвет `--tr-text-secondary`, hover — `--tr-text-primary`, `:focus-visible` — `box-shadow: 0 0 0 3px var(--tr-focus-ring); border-radius: var(--tr-radius-xs)`. Иконка — шеврон 16px (`M4 10l4-4 4 4` вверх / `M4 6l4 4 4-4` вниз, `viewBox="0 0 16 16"`). Пока стрелка видна, `Input` получает `padding-right: 36px`.
- **Видимость стрелки:** только если первый свободный ≠ max+1, max+1 помещается в разрядность, и значение поля (после trim, без учёта регистра) равно одному из двух предложенных. Любая ручная правка → стрелка исчезает. Нажатие переключает значение между двумя номерами; фокус остаётся на стрелке.
- **Кнопка «Вставка» (D-20):** триггер `ActionMenu variant="ghost-md"` с `IconInsertTemplate`: прозрачный фон, без рамки, цвет `--tr-text-primary`, hover — `--tr-surface-sunken`, `:focus-visible` — кольцо `--tr-focus-ring` 3px + `border-color: var(--tr-accent)`, `aria-haspopup="menu"`, `aria-expanded`. Кнопка видна всегда (D-13), в режиме `readonly`/`disabled` формы — `disabled`.
- **Строка под полем** — одна, 13px (label). Приоритет, по убыванию:
  1. ошибка валидации (`--tr-danger-text`, поле `invalid`);
  2. «Шаблон {маска} переполнен…» (`--tr-warning-text`);
  3. «Занят: …» (`--tr-warning-text`, поле **не** помечается `invalid` до попытки сохранить);
  4. «Шаблон: {маска}» (`--tr-text-tertiary`);
  5. ничего (строка не занимает место).
  Текст в одну строку, `overflow: hidden; text-overflow: ellipsis; white-space: nowrap`, полный текст в `title`. Строка связана с `Input` через `aria-describedby`; «Занят: …» объявляется через `aria-live="polite"`.
- **Живая подсказка «занят» (D-02, D-03):** запрос к серверу через 400 мс после последнего ввода; пустое значение не проверяется; во время запроса индикатора нет; устаревший ответ (значение уже изменилось) отбрасывается. Кир/лат и двойник в подсказке не показываются.
- **Открытие попапа создания:** если контекст помнит шаблон — поле заполняется первым свободным; пока идёт запрос, `placeholder` = «Загрузка…», поле доступно для ввода (ручной ввод отменяет автоподстановку). Если контекст «без шаблона» — поле пустое, строки под полем нет.
- **Тихая замена (D-14):** по событию инвалидации поле перезапрашивает номера и заменяет значение без анимации и без toast, только если значение всё ещё равно ранее предложенному.
- **Картридж ↔ фотобарабан:** смена «Что добавляем» переключает активный шаблон на запомненный для нового вида и подставляет его первый свободный (или очищает поле, если вид «без шаблона»). Ручное значение при этом заменяется — коды двух видов живут в разных шаблонах (SPEC п. 8, приёмка).
- Поле `readonly` в формах, открытых только на просмотр — существующее поведение `readonly` сохраняется.

### 3. Меню «Вставка»

```
┌────────────────────────────────────────────┐
│ ✓  ОРГ-00-[XXXXXX]        → ОРГ-00-000017   │ ← активный: галочка (accent)
│    ИНВ-[YYYY]-[XXXX]      → ИНВ-2026-0004   │
│    Т-[XX]                   переполнен      │ ← серый, недоступен
│ ─────────────────────────────────────────── │
│ ✓  Без шаблона                              │ ← если поле без шаблона
└────────────────────────────────────────────┘
```

- **Позиционирование:** панель рендерится в `<body>` через `use:portal`, `position: fixed`, `z-index: 1000` (как `.tr-dropdown-panel`), чтобы её не обрезал `overflow-y: auto` тела `Modal`. Правый край панели выровнен по правому краю кнопки, отступ 4px вниз; если снизу меньше места, чем высота панели, — открывается вверх. `max-height: 280px`, прокрутка внутри.
- **Внешний вид панели:** существующий `.action-menu-panel` (`--tr-surface-raised`, `--tr-border`, `--tr-radius-md`, `--tr-elev-2`, padding 4px), `min-width: 280px`, `max-width: 420px`.
- **Пункт шаблона:** `<button type="button" role="menuitem">`, сетка `16px | 1fr | auto`, зазор 8px, padding 8px 12px, `white-space: nowrap`. Колонка 1 — галочка 16px (`--tr-accent-text`) у активного, иначе пусто. Колонка 2 — маска `.tr-mono`, `--tr-text-primary`, обрезка многоточием. Колонка 3 — «→ {номер}» `.tr-mono`, `--tr-text-tertiary`. `aria-label` = «{маска}, следующий номер {номер}», у активного добавляется «, выбран».
- **Сортировка:** по маске, по алфавиту (`localeCompare(…, 'ru')`). «Без шаблона» — всегда последним, после разделителя (`role="separator"`, 1px `--tr-border`, отступ 4px сверху и снизу).
- **Переполненный пункт:** `aria-disabled="true"` (остаётся в порядке фокуса стрелками, но не выбирается), весь текст `--tr-text-disabled`, в колонке 3 — «переполнен», hover без фона, `cursor: not-allowed`, клик не закрывает меню и ничего не делает.
- **Выбор шаблона:** значение поля заменяется его первым свободным (при переполненной разрядности, но с разрывом — разрывом, без стрелки); строка «Шаблон: …» обновляется; меню закрывается, фокус возвращается в поле ввода (не на кнопку), курсор — в конец значения.
- **«Без шаблона»:** снимает активный шаблон; если значение всё ещё равно предложенному — поле очищается, если пользователь его правил — остаётся. Фокус в поле.
- **Нет шаблонов своего типа (D-13):** вместо списка — текст 13px `--tr-text-secondary`, padding 8px 12px, `white-space: normal`. Для администратора «Настройки / Организация» — `<button role="menuitem">` со стилем ссылки (`--tr-accent-text`, подчёркивание); нажатие закрывает попап создания и переходит в `#/settings?section=org` с прокруткой к блоку шаблонов. Ниже — разделитель и «Без шаблона».
- **Загрузка:** меню открывается сразу со списком масок (список шаблонов уже есть у поля), номера в колонке 3 — «…» до ответа сервера.
- **Клавиатура:** существующее поведение `ActionMenu` (↓ на кнопке открывает, ↑/↓/Home/End по пунктам, Esc закрывает с возвратом фокуса на кнопку). Фокус при открытии — на активном пункте, если он есть, иначе на первом.

### 5. Модалка шаблона (`NumberTemplateModal`, D-09, D-10)

- `Modal size="md"`, поля сверху вниз с зазором 16px: «Тип» → «Маска» → предпросмотр «Следующий номер» → `NumberMaskHelp`.
- «Тип» — `Dropdown variant="select" flat searchable={false}` (не нативный `<select>`, не `Select.svelte`), 4 варианта. В правке — `disabled` + подсказка D-10 под полем.
- «Маска» — `Input mono`, автофокус при открытии (в правке — тоже на маске).
- Предпросмотр и проверка маски — **с сервера** (без JS-копии логики маски; память `js_rust_mirror_needs_fixture_gate`): запрос через 300 мс после изменения типа или маски; ответ несёт либо номера, либо ошибку маски. Ошибка показывается под полем «Маска» (`--tr-danger-text`, поле `invalid`), предпросмотр при этом «—». Устаревшие ответы отбрасываются.
- Значение предпросмотра — `.tr-mono`, 13px, `--tr-text-primary`; пояснение «(после максимального — …)» — `--tr-text-tertiary`.
- «Создать шаблон» / «Сохранить шаблон» `disabled`, пока не выбран тип, маска пуста или последняя проверка вернула ошибку; `loading` во время записи. Ошибка дубля с сервера при сохранении — под полем «Маска», модалка не закрывается. Успех — модалка закрывается, toast.
- Esc / клик по фону / «Отмена» закрывают без сохранения (существующее поведение `Modal`).

### 6. Цепочка попапов при сохранении (D-01, D-04, D-05)

Порядок строгий: предпроверка «занят» → «Номер занят» (стоп) → «Не соответствует шаблону» (только при активном шаблоне и только в попапах создания) → «Проверьте буквы в номере». Каждый — отдельный вложенный `Modal size="md"` поверх формы; одновременно открыт не больше одного.

- Пока идёт цепочка, существующая основная кнопка попапа создания («Создать» из `DeviceFormModal` и соседей, эта фаза её не переименовывает) в состоянии `loading`.
- **«Номер занят»:** карточка — список «подпись | значение» (`<dl>`, сетка `120px 1fr`, зазор 8px по вертикали, подписи 13px `--tr-text-secondary`, значения 14px `--tr-text-primary`); «Место» — короткий путь, полный в `title`. «Взять следующий свободный» — `loading` на время запроса; успех → новое значение в поле, попап закрыт, фокус в поле, форма **не** сохраняется автоматически (пользователь нажимает «Создать» ещё раз). Ошибка → toast «Не удалось получить следующий номер…», попап остаётся. «Закрыть» / Esc → фокус в поле номера, поле помечается `invalid` с текстом «Номер уже занят.» под полем до следующей правки.
- **«Не соответствует шаблону»:** фокус по умолчанию на «Поправлю». «Поправлю» / Esc → возврат в форму, фокус в поле номера, ничего не сохранено. «Продолжить» → цепочка идёт дальше (к кир/лат-проверке или к записи), контекст запомнит «без шаблона».
- **«Проверьте буквы в номере»:** показывается, когда сервер вернул структурированное предупреждение (D-04). Фокус по умолчанию на «Поправлю». «Продолжить» → повтор запроса с флагом подтверждения. Номер и номер-двойник в тексте — `.tr-mono`.
- Если итоговая запись всё же упала на «занят» (гонка) — снова открывается «Номер занят» со свежими данными.
- В формах правки устройства и акта (D-05): «Номер занят» без кнопки «Взять следующий свободный», «Проверьте буквы в номере» — как в создании; «Не соответствует шаблону» не бывает. Живая подсказка D-02 в правке — по усмотрению planner'а; если подключается, то тем же видом строки под полем.

### 7. Состояния по поверхностям

| Поверхность | Загрузка | Пусто | Ошибка |
|-------------|----------|-------|--------|
| Таблица шаблонов | скелетон `Table`, 3 строки (только первая загрузка) | «Шаблонов пока нет» / «Добавьте шаблон — и в окнах создания номер будет подставляться сам.» | текст ошибки + «Повторить» вместо таблицы |
| Предпросмотр в модалке | «Считаем…» | «—» | ошибка маски под полем «Маска» |
| Поле номера при открытии | `placeholder` «Загрузка…» | пустое поле, без строки под ним | toast «Не удалось получить следующий номер…», поле пустое и доступно |
| Меню «Вставка» | «…» вместо номеров | D-13 текст + «Без шаблона» | текст ошибки + «Без шаблона» |
| Попап «Номер занят» | карточка приходит вместе с ответом предпроверки — отдельной загрузки нет; «Взять следующий свободный» — `loading` | — | toast |

### 8. Доступность

- Кнопка «Вставка» и стрелка ↑/↓ — иконки без текста, поэтому обязательны `aria-label` и `title` (Copywriting). У `IconInsertTemplate` и шевронов — `aria-hidden="true"`.
- Подсказка «Шаблон: …» и «Занят: …» связаны с полем через `aria-describedby`; «Занят» — `aria-live="polite"`.
- Кольца фокуса — только существующие (`--tr-focus-ring` 3px; у destructive — `--tr-danger-ring`). Никаких `outline: none` без замены (гейт `check-focus-outline`).
- Попапы — существующий `Modal` (ловушка фокуса, Esc, стек); порядок кнопок в подвале — вторичная слева, основная / destructive справа.

### 9. Контур иконки «Вставка» (IconInsertTemplate)

`viewBox="0 0 20 20"`, `fill="none"`, `stroke="currentColor"`, `stroke-width="1.5"`, скругления round. Папка с листком, выглядывающим сверху:

- лист: `M6.5 8V3.5h5l2 2V8` и линия текста `M8.5 6h3`;
- папка: `M2.5 7.5A1.5 1.5 0 0 1 4 6h2.5l1.5 2h8A1.5 1.5 0 0 1 17.5 9.5v6A1.5 1.5 0 0 1 16 17H4a1.5 1.5 0 0 1-1.5-1.5z`.

Исполнитель может подправить контур, сохраняя: 20px, stroke 1.5, currentColor, силуэт «папка + лист». Проверяется визуально в витрине в светлой и тёмной теме.

### 10. Проверка для плана: `ghost-md` не должен расходиться с `Button` (D-20)

D-20 требует, чтобы кнопка «Вставка» была вариантом GHOST из `Button.svelte`. Её рисует триггер `ActionMenu variant="ghost-md"`, то есть второй экземпляр стилей, и со временем он может разойтись с `Button`. План обязан закрыть это одним из двух способов:
- **(а)** в витрине (`ButtonsSection.svelte`, строка «Ghost — только иконка») рядом стоят `Button variant="ghost" size="md" iconOnly` и `ActionMenu variant="ghost-md"` с одной и той же иконкой. Проверка в работающем приложении, в светлой и тёмной теме, в состояниях обычное / hover / focus-visible / disabled: размер 36×36, радиус, цвет иконки, фон при hover и кольцо фокуса совпадают попиксельно на глаз. Результат фиксируется в SUMMARY плана как проверенный, либо как UNVERIFIED, если проверки не было;
- **(б)** стили GHOST md iconOnly выносятся в один общий класс (например, глобальный `.tr-btn-ghost-icon` или общий SCSS-миксин) и используются обоими компонентами. Тогда совпадение гарантировано конструкцией, а строка в витрине остаётся как демонстрация.

Предпочтителен вариант (б). Вариант (а) допустим, если выносить стили общим классом дорого.

## Claude's Discretion

Решения, которые не зафиксированы SPEC.md / CONTEXT.md и приняты здесь по образцу существующих паттернов:

1. **«Набор иконок» = новый каталог `lib/components/icons/`.** CONTEXT D-20 просит добавить иконку «в набор», но набора в кодовой базе нет: все иконки — inline SVG в месте использования (stroke 1.5, currentColor). Иконка нужна минимум в 2 местах (поле номера и витрина), поэтому она оформляется первым отдельным компонентом `IconInsertTemplate.svelte` в стиле существующих inline-иконок, а в витрине появляется строка «Ghost — только иконка».
2. **Кнопка «Вставка» — это триггер `ActionMenu` в новом варианте `ghost-md`, а не `Button`.** `ActionMenu` сам владеет кнопкой-триггером и её `aria-expanded`. Вариант `ghost-md` повторяет стиль `.btn-ghost.btn-md` из `Button.svelte` один в один, поэтому визуально это «GHOST из витрины». `Button` параллельно получает `iconOnly` / `ariaLabel` / `title` для витрины и будущих иконок-кнопок.
3. **Панель меню через `portal` + `position: fixed`.** Тело `Modal` имеет `overflow-y: auto` и обрезало бы абсолютно позиционированную панель `ActionMenu`. `Dropdown` решает ту же задачу через `use:portal`; меню «Вставка» делает так же (новый проп `portal` у `ActionMenu`).
4. **Строка «Занят: …» — цвет warning, а не danger, и поле не `invalid` до сохранения.** Во время ввода это предупреждение, ошибкой оно становится при попытке сохранить (попап «Номер занят»).
5. **«Продолжить» — destructive в обоих мягких попапах.** SPEC п. 11 требует красную кнопку для «не соответствует шаблону»; п. 12 цвет не указывает. Для единообразия цепочки D-01 кнопка красная в обоих, фокус по умолчанию на «Поправлю».
6. **Ссылка «Настройки / Организация» в пустом меню** закрывает попап создания и ведёт на `#/settings?section=org`. `SettingsPage` сейчас всегда открывает вкладку «Сеть», поэтому ему нужно читать `section` из hash (по образцу `parseIdFromHash` на других страницах). Несохранённый ввод в попапе при этом теряется — это приемлемо, потому что шаблона своего типа ещё нет и форма обычно только открыта.
7. **«Без шаблона» очищает поле только если значение не правили вручную.** SPEC не описывает, что происходит со значением при выборе «Без шаблона».
8. **Смена типа устройство ↔ принтер внутри формы создания** (если форма это позволяет) переключает контекст «Новое устройство» ↔ «Новый принтер» по правилу D-14: значение заменяется запомненным для нового контекста только если его не правили вручную. Для картриджа и фотобарабана значение заменяется всегда (п. 2 §2, приёмка SPEC п. 8).
9. **В таблице настроек показывается только первый свободный номер,** пара «первый свободный / после максимального» — только в предпросмотре модалки. Так столбец остаётся узким в `max-width: 640px`.
10. **Кнопка «Добавить шаблон» — `secondary size="sm"` в строке заголовка подраздела,** по образцу кнопок логотипа в том же экране. Основные кнопки раздела («Сохранить…») остаются единственными primary.
11. **Интервалы debounce:** 400 мс для живой подсказки «занят» (D-02), 300 мс для предпросмотра в модалке шаблона.
12. **Слот «Инвентарный №» в форме устройства получает `flex: 2`** в ряду с «Серийный №» и «Количество», чтобы кнопка 36px не сжимала поле; в режиме правки ряд прежний.
13. **Возврат фокуса после выбора пункта меню — в поле ввода, а не на кнопку.** Отличие от стандартного `ActionMenu`: следующий шаг пользователя — проверить или поправить номер.
