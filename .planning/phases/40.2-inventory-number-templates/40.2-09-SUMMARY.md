## Decisions Made

1. **ghost-md триггер не получает scoped `.action-menu-trigger`.** Svelte-скоупинг компилирует `.action-menu-trigger` в `.action-menu-trigger.svelte-xxxx` (специфичность 0-2-0), что выше плоского глобального `.tr-btn-ghost-icon` (0-1-0) — независимо от порядка объявления в файле. Если бы ghost-md получал оба класса, `border`/`color` из `.action-menu-trigger` молча победили бы `.tr-btn-ghost-icon`, и триггер визуально разошёлся бы с `Button.iconOnly` — то есть именно то расхождение, которое общий класс должен предотвратить (UI-SPEC §10). Решение: `class:action-menu-trigger={variant !== 'ghost-md'}` — ghost-md получает только `.tr-btn-ghost-icon`.
2. **`max-width`/`max-height`/`overflow` только на `.action-menu-panel--portal`.** UI-SPEC §3 требует `max-height: 280px` со скроллом и `max-width: 420px` для меню «Вставка», но добавление этого в базовый `.action-menu-panel` затронуло бы 3 существующих вызова (`DevicesPage` «Импорт и экспорт», `DeviceFormModal` «Тип устройства», `PlaceTreeNode` «Действия: …») — нарушая acceptance criterion «не меняют поведения». Ограничение вынесено в отдельный модификатор-класс, применяемый только при `portal=true`.
3. **`NUM-06` НЕ отмечен выполненным, несмотря на `requirements: [NUM-06]` во фронтматтере плана.** NUM-06 требует полного end-to-end поведения (автоподстановка «первого свободного», реальное меню «Вставка» со списком шаблонов) — этот план строит только UI-примитивы (иконка, `Button.iconOnly`, `ActionMenu.ghost-md`), без самого `NumberTemplateField` и без серверной интеграции. `gsd-sdk query requirements.mark-complete NUM-06` по умолчанию выполнил это (следуя фронтматтеру), но результат вручную отменён в `REQUIREMENTS.md` (`NUM-06` возвращён в `Pending`/`[ ]`) — проектное правило «не отмечать requirement выполненным, если план не доставляет его end-to-end» имеет приоритет. `NUM-06` будет отмечен в плане 12.
4. **Добавлен `disabled` проп в `ActionMenu`** (Rule 2, не было в буквальном тексте плана). Нужен по двум причинам: (а) сам план требует в витрине «обычную и disabled версии обеих» кнопок, а у `ActionMenu` до этого не было способа выключить триггер; (б) UI-SPEC §2 явно требует, чтобы кнопка «Вставка» была `disabled` в readonly/disabled-форме — без этого примитива план 12 не смог бы это реализовать. Реализовано нативным HTML `disabled` на `<button>` (Escape/click/keydown автоматически не срабатывают), плюс базовый disabled-стиль для `.action-menu-trigger` (opacity 0.45, pointer-events none) — не влияет на существующие вызовы, ни один из которых `disabled` не передаёт.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] CSS-специфичность Svelte-скоупинга ломала бы «общий класс» гарантию из UI-SPEC §10**
- **Found during:** Task 2 (проектирование триггера `ActionMenu` `ghost-md`)
- **Issue:** План предписывал применить `tr-btn-ghost-icon` ВМЕСТЕ с существующим scoped-классом `.action-menu-trigger` (`class="action-menu-trigger ... tr-btn-ghost-icon"`). Из-за механизма скоупинга Svelte (`.action-menu-trigger` компилируется в `.action-menu-trigger.svelte-xxxx`, специфичность 0-2-0) это молча перебило бы `border`/`color` из глобального `.tr-btn-ghost-icon` (0-1-0) — совпадение с `Button.iconOnly` не было бы гарантировано конструкцией, ради чего и затевался общий класс.
- **Fix:** Триггер `ghost-md` получает ТОЛЬКО `.tr-btn-ghost-icon` (условно исключён из базового `.action-menu-trigger` через `class:action-menu-trigger={variant !== 'ghost-md'}`), с комментарием в коде, объясняющим причину.
- **Files modified:** `ui/src/lib/components/ActionMenu.svelte`
- **Verification:** `pnpm --dir ui lint` + `pnpm --dir ui svelte-check` + `pnpm --dir ui build` — все зелёные, 0 ошибок
- **Committed in:** `4989aedd` (часть коммита Task 2)

**2. [Rule 2 - Missing functionality] `ActionMenu` не поддерживал `disabled`**
- **Found during:** Task 2 (виртина требует «обычную и disabled версии обеих» кнопок)
- **Issue:** У `ActionMenu` не было пропа `disabled` — ни для витрины этого плана, ни для будущего использования в `NumberTemplateField` (план 12), где UI-SPEC §2 требует делать кнопку «Вставка» `disabled` в readonly/disabled-форме
- **Fix:** Добавлен `disabled?: boolean = false` проп, нативный HTML `disabled` на `<button>`, базовый disabled-стиль для `.action-menu-trigger`
- **Files modified:** `ui/src/lib/components/ActionMenu.svelte`
- **Verification:** grep всех существующих вызовов `<ActionMenu` — ни один не передаёт `disabled`, поведение не меняется; витрина демонстрирует disabled-версию
- **Committed in:** `4989aedd` (часть коммита Task 2)
