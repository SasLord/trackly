# Phase 40.2 Plan 06: Acts on NumberTemplateService (V042 migration + create/update rewrite) Summary

**`acts.number` migrated from INTEGER to free TEXT (V042, 12-step SQLite rebuild), and `ActService::create`/`update` fully rewired onto `NumberTemplateService` — no server-side auto-generate, no `counters` table reference anywhere in the acts path, occupied-check extended to a live return's displayed number (D-06), and `update()` structurally forbidden from ever checking template mismatch (D-05).**

## Accomplishments

- `migrations/V042__acts_number_text.sql` — the riskiest RESEARCH item (Pattern 2, SQLite table rebuild) closed: `acts.number` INTEGER → TEXT via the standard 12-step rebuild (mirrors `V030`), `CAST(number AS TEXT)` preserves every existing value byte-for-byte, `id` preserved so `act_items`/`place_movements` FKs resolve transparently by name after rename, `idx_acts_number_sub_unique`/`idx_acts_parent`/`idx_acts_parent_act_id` recreated (not renamed with the table). Verified against a hand-probed exact column list (via a temporary `sqlite3` CLI schema dump, not guessed from scattered `ALTER TABLE`s) and through the REAL refinery pipeline (`db::migrations::tests::run_applies_all_known_migrations_on_fresh_db`).
- Domain layer (`trackly-core`) widened to match: `ActRow.number`/`parent_number`, `ActPatch.number`, `ActNew.number_override` all `String`/`Option<String>` — `format_act_number` takes `&str`/`Option<&str>`, works identically for a templated non-numeric number (new test coverage added).
- `ActService::create()`: D-08 explicit `.trim()` validation (empty → `Validation{field:"number"}`, no more `next_act_number_from_max` fallback); D-01 confirmation chain as async pre-checks before the writer transaction opens — occupied (including live returns' displayed number, D-06) → template mismatch (create-only) → script-mix; `NUM-08` `remember_context` wired; `WsEvent::NumberSpaceChanged` broadcast on success (the first real dispatch of Plan 05's contract).
- `ActService::update()`: pre-fetches the act's current number and only runs the occupied/script-mix chain when it actually changed (D-05's "editing unrelated fields must never re-open a numbering warning"); `ActNumberEditInput` structurally has no `template_id` field at all, making "update never checks mismatch" a compile-time guarantee, not a runtime convention.
- `is_act_number_occupied_including_returns` — the D-06 extension: scans live return acts, computes each one's DISPLAYED number via `format_act_number` (never stored in a column — depends on parent's number + live sibling count), and rejects a candidate matching any of them. Proven end-to-end in `acts_numbering.rs` on both `create()` and `update()` with the literal review scenario (act #42 → returned → "42в" → new/renamed act rejected).
- `counters` table fully retired from the acts path: `next_act_number_from_max`, `increment_counter_in_tx`/`peek_counter`/`peek_counter_in_tx` removed from `acts_sqlite.rs` (the latter moved to `cartridges_sqlite.rs`, its only remaining caller); 4 tests that asserted the now-gone mechanism deleted rather than adapted (documented inline in each file).
- Full `cargo test -p trackly-app` / `-p trackly-infra` regression: **870/61** and **215/23** respectively — every remaining failure traced (by grepping every panic message) to cartridges/drums still reading the dropped `counters` table, Plan 07's scope. `cargo clippy --tests -- -D warnings` clean on both crates. `pnpm --dir ui build`/`lint`/`svelte-check` all clean (0 TS errors, after a real, minimal `ActFormBody.svelte` fix — see Deviations).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `act_number_display.rs` and `number_template_service.rs` read `acts.number` as `i64`**
- **Found during:** Task 2, `cargo check -p trackly-app --lib` after the domain-layer String widening
- **Issue:** Both files ran raw SQL reading `acts.number`/`number` into an `i64` local — a direct, immediate runtime panic (`InvalidColumnType`) against the now-TEXT column, for the timeline/report act-number display path and the numbering-templates occupied-check's ActNumber space respectively.
- **Fix:** Changed both to read `String` directly (matching what the column now actually is).
- **Files modified:** `crates/trackly-app/src/services/act_number_display.rs`, `crates/trackly-app/src/services/number_template_service.rs`
- **Verification:** Full `trackly-app` test suite run, no new failures beyond the cartridge baseline.
- **Committed in:** `4217bb61` (Task 2 commit)

**2. [Rule 3 - Blocking] `role_endpoint_matrix.rs`'s raw JSON act payloads still used `number_override`**
- **Found during:** Full-suite verification run after Tasks 3/4 compiled
- **Issue:** Two RBAC-rejection test cases (Employee → `acts_create`/`acts_update` → expected 403) built raw JSON payloads by hand with the old field name. With `number_input` now a REQUIRED field, axum's `Json` extractor rejected the payload with 422 before `authorize()` ever ran, so the tests asserted `403` but got `422` — a genuine test regression, not a pre-existing issue.
- **Fix:** Updated both payloads to `number_input` in each type's own actual wire casing (`NumberFieldInput` is `camelCase` per its own `#[serde(rename_all)]` from Plan 04; `ActNumberEditInput` is plain `snake_case`).
- **Files modified:** `crates/trackly-app/tests/role_endpoint_matrix.rs`
- **Verification:** `cargo test -p trackly-app --test role_endpoint_matrix` — 1 passed / 0 failed.
- **Committed in:** `92d54159` (Tasks 3+4 commit)

**3. [Rule 3 - Blocking] `ui/src/features/acts/ActFormBody.svelte` failed `svelte-check` with real TS errors**
- **Found during:** Post-implementation UI verification (`pnpm --dir ui exec svelte-check`)
- **Issue:** Unlike `ui/src/lib/api/acts.ts` (which calls `apiCall<ActDto>(...)`, a loosely-typed generic immune to backend shape drift), `ActFormBody.svelte` constructs the typed `ActCreateDto`/`ActUpdateDto` object literal directly — 3 hard TypeScript errors (`number_override` does not exist on type `ActCreateDto`/`ActUpdateDto`, plus a `string | null` vs `number | null` prefill mismatch from `ActDto.number_raw` also changing type).
- **Fix:** Rewrote the number-field wiring to build `number_input` instead: kept `ActNumberField.svelte`'s existing `number | null` contract completely untouched (its Plan-14 replacement is out of scope here), added a local `predictedNumber` state (mirrors `ActNumberField`'s own `peekNextNumber()` call) so "auto mode" (no explicit override typed) still submits the SAME non-empty number the field visually shows, instead of an empty string that would now hard-fail NUM-13's validation. Doc-commented as a compile/functionality compat shim, not the real NUM-13 UX (template picker + confirmation popups remain Plan 11/14's job).
- **Files modified:** `ui/src/features/acts/ActFormBody.svelte`
- **Verification:** `pnpm --dir ui exec svelte-check` — 0 errors (was 3); `pnpm --dir ui lint` and `pnpm --dir ui build` both clean.
- **Committed in:** `92d54159` (Tasks 3+4 commit)
