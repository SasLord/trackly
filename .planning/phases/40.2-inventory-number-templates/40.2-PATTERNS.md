```rust
/// INSERT a new cartridge model row inside a transaction.
pub fn insert_model_in_tx(
    &self,
    tx: &Transaction<'_>,
    new: &CartridgeModelNew,
    now_utc: i64,
) -> Result<i64, AppError> {
    tx.execute(
        "INSERT INTO cartridge_models \
         (brand, model, kind_id, color, notes, created_at_utc, updated_at_utc, version) \
         VALUES (?1, ?2, ?3, ?4, ?5, ?6, ?6, 1)",
        params![new.brand, new.model, new.kind_id, new.color, new.notes, now_utc],
    )
    .map_err(map_rusqlite)?;
    Ok(tx.last_insert_rowid())
}

/// UPDATE an existing cartridge model row inside a transaction.
pub fn update_model_in_tx(&self, tx: &Transaction<'_>, id: i64, version: i64, /* ... */, now_utc: i64) -> Result<(), AppError> {
    let affected = tx.execute(
        "UPDATE cartridge_models SET brand=?1, model=?2, kind_id=?3, color=?4, notes=?5, \
         updated_at_utc=?6, version=version+1 \
         WHERE id=?7 AND version=?8 AND deleted_at_utc IS NULL",
        params![brand, model, kind_id, color, notes, now_utc, id, version],
    ).map_err(map_rusqlite)?;

    if affected == 0 {
        // NotFound vs OptimisticLockMismatch disambiguation — copy this exact
        // secondary SELECT + match pattern for number_templates too.
        let actual: Option<i64> = tx.query_row(
            "SELECT version FROM cartridge_models WHERE id = ?1", params![id], |r| r.get(0),
        ).optional().map_err(map_rusqlite)?;
        return match actual {
            None => Err(AppError::NotFound { entity: "cartridge_model", id }),
            Some(actual) => Err(AppError::OptimisticLockMismatch {
                entity: "cartridge_model", id, expected: version, actual,
            }),
        };
    }
    Ok(())
}
```

**Service create/update with pre-check + audit** (`cartridge_service.rs:629-705, 707-770`):
```rust
pub async fn model_create(&self, payload: CartridgeModelCreateDto) -> Result<CartridgeModelDto, AppError> {
    if payload.brand.trim().is_empty() {
        return Err(AppError::Validation { field: "brand".into(), message: "Укажите бренд модели".into() });
    }
    let now = self.clock.unix_seconds();
    let cart_repo = self.cart_repo.clone();
    let audit_repo = self.audit_repo.clone();

    let model_id = self.writer.execute(move |conn| {
        let tx = conn.transaction().map_err(map_rusqlite)?;

        // Pre-check for duplicate to return a Russian conflict reason instead
        // of leaking the raw SQLite UNIQUE error to the UI (WR-02).
        let exists: bool = tx.query_row(
            "SELECT EXISTS(SELECT 1 FROM cartridge_models WHERE brand = ?1 AND model = ?2 AND deleted_at_utc IS NULL LIMIT 1)",
            params![payload.brand.trim(), payload.model.trim()], |r| r.get(0),
        ).map_err(map_rusqlite)?;
        if exists {
            return Err(AppError::Conflict {
                reason: format!("Модель «{} {}» уже существует", payload.brand.trim(), payload.model.trim()),
            });
        }

        let model_id = cart_repo.insert_model_in_tx(&tx, &new, now)?;
        audit_repo.insert(&tx, AuditEntry {
            entity_type: "cartridge_model", entity_id: model_id, action: "create",
            user_id: None, before_json: None, after_json: None, payload_json: None,
            created_at_utc: now,
        })?;
        tx.commit().map_err(map_rusqlite)?;
        Ok(model_id)
    }).await?;

    self.model_get(model_id).await
}
```

**Apply to `NumberTemplateService::create/update/delete/list`**: pre-check duplicate `(type_id, mask)` inside the same transaction as `cartridge_service.rs` does for `(brand, model)` (satisfies the D-09/copy "Шаблон с такой маской для типа «{Тип}» уже есть" error); `delete` should mirror `soft_delete_model_in_tx` EXCEPT the phase spec (D-12) calls for **physical** delete with `ON DELETE SET NULL` on `number_template_contexts.template_id` — do not copy the soft-delete shape verbatim, only the transaction/pre-check/audit skeleton.

### `migrations/V041__number_templates.sql` (+ optional `V042`) — table creation, seed, and `acts.number`/`cartridges.code` rebuild

**Analog:** `migrations/V030__printers_drop_connectivity_check.sql` (full file, reproduced below) — the canonical 12-step SQLite table-rebuild recipe already proven in this repo for exactly this situation (no `ALTER COLUMN`, no `DROP CONSTRAINT` in SQLite).

```sql
-- V030: Drop the connectivity CHECK constraint on `printers`.
--
-- SQLite has no `ALTER TABLE ... DROP CONSTRAINT`, so the only way to remove
-- a CHECK is the standard 12-step rebuild pattern: create a replacement table
-- without the constraint, copy rows, drop the old table, rename the new one
-- into place. `printer_readings.printer_id` and `printer_alerts.printer_id`
-- reference `printers(id)` via `ON DELETE CASCADE`; SQLite resolves FKs by
-- table name (not rowid/oid), so renaming `printers_new` -> `printers`
-- restores FK integrity for those tables without touching them.
--
-- Foreign keys are checked immediately (not deferred) in this project's
-- connections, so `DROP TABLE printers` while reader rows still reference it
-- via FK would be blocked. The reconstruction is therefore wrapped in an
-- explicit `PRAGMA foreign_keys = OFF;` / `= ON;` pair scoped to this
-- migration file only (refinery runs one file per transaction —
-- set_grouped(false) — so this window never overlaps user traffic).

PRAGMA foreign_keys = OFF;

CREATE TABLE printers_new (
  id                  INTEGER PRIMARY KEY AUTOINCREMENT,
  device_id           INTEGER NOT NULL UNIQUE REFERENCES devices(id),
  ip_address          TEXT    NULL,
  -- ... every other column unchanged, copied verbatim from CREATE TABLE printers ...
  version             INTEGER NOT NULL DEFAULT 1
);

INSERT INTO printers_new (id, device_id, ip_address, /* ... */ version)
SELECT id, device_id, ip_address, /* ... */ version
FROM printers;

DROP TABLE printers;
ALTER TABLE printers_new RENAME TO printers;

PRAGMA foreign_keys = ON;
PRAGMA user_version = 30;
```

**Apply verbatim (structure) for**:
1. `acts.number INTEGER → TEXT` — `CREATE TABLE acts_new (... number TEXT NOT NULL ...)`, `INSERT INTO acts_new SELECT id, CAST(number AS TEXT), ... FROM acts` (preserve `id` exactly so `act_items.act_id`/`parent_act_id` FKs stay valid), `DROP TABLE acts`, `RENAME`, then **recreate** `idx_acts_number_sub_unique` (indexes are lost on `DROP TABLE`, not renamed with it — see `V004__acts.sql` for the exact original index definition to recreate).
2. `cartridges.code TEXT NOT NULL UNIQUE` (column-level, global) → drop the column-level `UNIQUE`, add `CREATE UNIQUE INDEX ... ON cartridges(code) WHERE deleted_at_utc IS NULL` afterward (same rebuild — a column-level `UNIQUE` cannot be dropped without a table rebuild either).
3. `DROP TABLE counters;` (D-15) — no rebuild needed, straight drop, in the **same** migration file per D-15.

**Critical detail from V030's own comment:** the `PRAGMA foreign_keys = OFF`/`= ON` pair must stay inside one migration file (refinery commits one file per transaction) — do not split the rebuild's OFF/ON pragmas across `V041`/`V042` if splitting into two files.

**Seed migration for D-16** (`[X]` for Акты, `C-[XXXXXX]` for Картриджи, `D-[XXXXXX]` for Фотобарабаны + context assignment) — no direct file analog for the *seed* step; write as plain `INSERT INTO number_templates (...) VALUES (...)` / `INSERT INTO number_template_contexts (...) VALUES (...)` rows appended to the same migration, guarded to also run against a fresh empty DB (i.e. unconditional `INSERT`, not `INSERT ... SELECT WHERE EXISTS`). **Remember Pitfall 1** (see Shared Patterns) — the cartridge/drum seed mask width must be computed from `MAX(LENGTH(...))` over existing live rows, not hardcoded to 6, or NUM-13's continuity acceptance criterion silently breaks on any DB that already has cartridges.

**Dedup rename for NUM-15** (`ДУБЛЬ-…`) — no direct analog; a `UPDATE devices SET inventory_number = 'ДУБЛЬ-' || inventory_number || ' (' || id || ')' WHERE id IN (...)`-style statement, paired with an `AuditEntry` insert per rename (see Shared Patterns → Audit entry below) run either in the same SQL migration (if refinery's SQL-only migrations can do the audit insert directly — they can, `audit_log` is a plain table) or as a Rust migration (refinery supports both; CONTEXT leaves this to Claude's Discretion).

```typescript
// (a) This is NOT a WebSocket. Invalidation solves a same-tab/same-session
//     staleness problem for a cache the CURRENT client already loaded — it

export const placeContentEventsStore = $state<{ seq: number; placeIds: number[] }>({ seq: 0, placeIds: [] });
```
