## Fixed Issues

### BE-CR-01 / BE-CR-02: V042/V043 rebuilds ran `DROP TABLE` with FKs on

**Commit:** 86e00e46
**Files:** `crates/trackly-infra/src/db/migrations.rs`, `crates/trackly-infra/tests/acts_number_text_migration.rs`, `crates/trackly-infra/tests/cartridges_code_unique_migration.rs`
**Applied fix:** the runner now turns FKs off on the connection before refinery starts. This happens outside any transaction, and the runner fails if the pragma did not take effect. After the run it compares `PRAGMA foreign_key_check` with a pre-run baseline, turns FKs back on, and fails startup on any NEW violation. Violations that already existed in legacy data do not block startup. If no migration is pending, the FK dance is skipped. The `run_up_to(conn, version)` test hook uses the same path. Both migration test files were rewritten to go through the real runner: a real V041/V042 database, populated `act_items` (CASCADE), a return act (`parent_act_id` RESTRICT), `place_movements.act_id` (SET NULL) and `requests.completed_cartridge_id`. The tests prove zero data loss, preserved links, FKs back on and 0 violations. A mutation check with the FK-off step removed made every new test fail: the silent cascade (`act_items` → `[]`), the RESTRICT failure and the cartridge FK failure.

### BE-CR-03: NUM-12 doppelganger ignored without a script mix

**Commit:** 3204bb36
**Applied fix:** `detect_warnings` always runs the doppelganger lookup. Exact case/trim matches are excluded, because those count as "occupied". The warning fires on a script mix OR a doppelganger. The message quotes the EXISTING number. Test: a Cyrillic «С-0005» next to a seeded Latin «C-0005» warns, and an exact «c-0005» does not.

### BE-CR-04: D-14 `NumberSpaceChanged` missing on part of the mutations

**Commit:** 8cccdb30
**Applied fix:** `NumberTemplateService` gained `with_ws_tx` (wired in `AppCtx::build`). It now broadcasts after template create/update/delete (to the contexts of the template's type) and after `number_template_contexts_set`. Broadcasts were also added to device `delete_soft`, cartridge `delete`, act `delete_soft` (which includes deleting a return) and `do_return`. Number writes through `restore_from_snapshot_in_tx` are gone (BE-WR-06). The registry gate `crates/trackly-app/tests/number_space_broadcast_gate.rs` runs each mutation against a shared channel and asserts the event. Its header tells future authors to add a case for every new number-writing method.

### BE-CR-05: mask edge whitespace breaks the template

**Commit:** 168d7aa0
**Applied fix:** masks are trimmed before validation, the duplicate check and saving (create / update_mask / preview_mask).

### BE-WR-01: template type not checked against the context

**Commit:** 41b91f40
**Applied fix:** the check now lives in the service/repository, not only in the transport. `set_context_in_tx` / `remember_context` return `NotFound` for a missing template and `Validation` (`template_id`) for a template of another type. The act/cartridge/device create chains fetch the template through `get_for_context`. The peek transport uses `peek_next_for_context`. `create_single_with_number_check` accepts only `device_create` / `printer_create`.

### BE-WR-02: context memory written in a separate transaction after the commit

**Commit:** 108ecaa0
**Applied fix:** the context is remembered through `remember_context_in_tx` inside the transaction that creates the act/cartridge/device. If the template disappeared or changed type since the pre-check, the context falls back to "no template" and the new record is not rolled back.

### BE-WR-03: D-06 enforced only one way; acts hint blind to returns

**Commit:** 97512985
**Applied fix:** the act number space is now the DISPLAYED number of every live act. This covers `number_templates_is_occupied` (live hint / D-01 pre-check), the doppelganger check and `is_occupied`. `exclude_id` skips the act AND its own returns, so renaming 42→42в next to its own return is allowed. `ensure_act_family_display_free_in_tx` runs on the writer transaction after the rename cascade, after `do_return` (42в → 42в1/42в2) and after deleting a return (42в1 → 42в). Tests cover the hint, the self-rename, a second return colliding with a handover «42в1», and a cascade colliding with «43в».

### BE-WR-04: final uniqueness check outside the writer; DB index weaker than Rust

**Commit:** 8faeb51b
**Applied fix:** `ensure_number_free_in_tx` repeats the occupied check on the writer transaction in device create/update/bulk_create, cartridge create and act create/rename. With a single writer, the race is gone. A unit test (`number_key_parity_with_sql_index`) evaluates the live V044 index expression. It proves the Rust key and the SQL key agree on Cyrillic, Latin and mixed input, and that everywhere else SQL-equal implies Rust-equal, so the index is never stricter than the service. `map_rusqlite` turns a numbering unique-index violation into a Russian `Conflict`. A new concurrency test (`race-NN` vs `RACE-NN`, 10 rounds) fails with the in-transaction check removed. The indexes themselves were deliberately NOT strengthened: a case-folded cartridge index would make the upgrade fail on legacy case-variant codes, and the check inside the writer transaction already gives the guarantee.

### BE-WR-05: V044 blanks break the unique index

**Commit:** dd31be3c
**Applied fix:** V044 turns blank / whitespace-only numbers into NULL before building the index, and the index `WHERE` also excludes `TRIM(...) = ''`. Added a real-runner upgrade test from V043 with duplicates and blanks.

### BE-WR-06: `restore_from_snapshot_in_tx` bypasses the occupied check

**Commit:** f01aaae8
**Applied fix:** undo no longer restores `inventory_number`, since act mutations never change it. Test: renumber the device after the act and reuse its old number elsewhere; deleting the act then succeeds and the device keeps its new number.

### BE-WR-07: u64 overflow in `compute_next`

**Commit:** e736be5d

### BE-WR-10: no length/control-character limits

**Commit:** 9680b1e0

Cartridge codes keep their stricter existing rule.

## No Change Needed

### BE-IN-04: four independent `NumberTemplateService` instances

**Reason:** the service holds no state (Arc'd writer/readers/clock plus zero-sized repos), so separate instances do not affect correctness. The concern was that BE-CR-04 would need `ws_tx` wired in four places, but that did not happen. The act/cartridge/device services broadcast D-14 themselves through their own `ws_tx`. Only the `AppCtx` instance, which serves template CRUD and context memory, needed `with_ws_tx`.
