**Единая точка автоподстановки номера — Input + стрелка ↑/↓ + меню «Вставка» (ActionMenu ghost-md) + строка статуса, вся числовая логика на сервере (peek_next/is_occupied), клиент делает только чистое string-equality сравнение и WS-membership проверку.**

## Accomplishments

- `NumberTemplateField.svelte` — единственный новый файл, реализует оба auto-таска плана:
  - **Структура (Task 1):** `Input` + абсолютно спозиционированная стрелка ↑/↓ внутри поля +
    `ActionMenu variant="ghost-md" portal panelMinWidth="280px"` с `IconInsertTemplate` как
    триггер «Вставка». Меню: сортировка шаблонов по маске (`localeCompare(..., 'ru')`), галочка
    у активного, переполненные — `aria-disabled` + серый текст + `stopPropagation` на клике,
    «Без шаблона» — последний пункт за `role="separator"`. D-13 пустое состояние: текст +
    (для `canManageSettings`) ссылка на «Настройки / Организация». Кнопка «Вставка» видна
    ВСЕГДА (не обёрнута в `{#if templates.length}`), получает `disabled` только от прямого
    прописа `disabled`.
  - **Поведение (Task 2):** автоподстановка запомненного шаблона на mount и при смене `context`
    (NUM-08 — реализовано через единый `$effect`, ключ по `context`, различает первый прогон и
    смену через `didInit`/`previousContext`); Discretion #8 — cartridge↔drum контексты ВСЕГДА
    заменяют значение, device↔printer — только если значение не правили вручную
    (`contextAlwaysReplaces()` матчит по строковому значению `context`, без второй копии
    серверной связи тип→контекст); переключатель ↑/↓ через чистое `normalize()`-сравнение;
    живая подсказка «Занят: …» с 400 мс debounce и отбрасыванием устаревших ответов по
    `occupiedRequestId`; тихая замена по `WsEvent::NumberSpaceChanged` — чистое
    `event.contexts.includes(context)`, без клиентского маппинга тип→контекст.
- Приоритет строки под полем (ошибка → переполнен → занят → «Шаблон: …» → ничего) реализован
  как единый `$derived.by` (`statusLine`), избегая дублирования условий в разметке.
- WS-подписка через существующий singleton (`connectWs`/`onWsEvent` из `$lib/api/ws.ts`) —
  не заведён второй WebSocket-клиент.

## Decisions Made

См. `key-decisions` во фронтматтере — кратко:
1. Task 1/Task 2 объединены в один коммит (общий набор реактивных переменных, split создал бы
   нерабочий промежуточный срез без пользы).
2. `showingAlt` — `$derived`, не отдельный `$state` (anti-pattern guard: чистое сравнение, не
   кэшируемый флаг).
3. `occupiedLineText` для акта использует `record.title.toLowerCase()` вместо даты — DTO не
   несёт даты для акта (тот же прецедент, что план 11).
4. Числа в меню «Вставка» берутся из уже загруженного `templates` (single-call API), без
   отдельного per-item live-запроса.
5. Ссылка «Настройки / Организация» — только навигация, закрытие попапа/routing `?section=org`
   вне файловой области плана.
6. `excludeId` — задел интерфейса для будущих форм правки, не проверен end-to-end в этом плане.
