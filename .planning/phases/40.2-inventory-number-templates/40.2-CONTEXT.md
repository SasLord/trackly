**Gathered:** 2026-09-18

<domain>
## Phase Boundary

Администратор ведёт шаблоны номеров (тип + маска) в «Настройки / Организация»; четыре попапа
создания (устройство, принтер, акт, картридж/фотобарабан) подставляют следующий номер по
шаблону — «первый свободный» с переключением на max+1 — с серверной памятью последнего шаблона
для 5 контекстов; во всех трёх пространствах номеров сервер запрещает живые дубли. Счётчики
`counters` уходят, номер акта становится текстом.

<decisions>
## Implementation Decisions

### Цепочка проверок при сохранении

- **D-01 (Порядок: занят → шаблон → кир/лат):** при сохранении сначала блокирующий попап
  «Номер занят» — подтверждать мягкие предупреждения для номера, который всё равно нельзя
  сохранить, бессмысленно. Затем «Не соответствует шаблону» (только если в поле активен шаблон),
  затем предупреждение о смешении кириллицы/латиницы или двойнике. Мягкие предупреждения
  показываются по одному, каждое своим попапом «Поправлю / Продолжить». Чтобы «занят» шёл
  первым, клиент перед показом мягких попапов делает серверную предпроверку номера (та же
  команда, что для подсказки D-02); итоговая проверка всё равно в транзакции записи (SPEC п. 9).
- **D-02 (Живая подсказка «занят» при вводе):** после паузы в вводе (debounce) клиент
  спрашивает сервер, занят ли номер в своём пространстве, и под полем появляется одна короткая
  строка «Занят: <вид> <наименование>». Нужна новая пара Tauri-команда + HTTP-эндпоинт
  (одна бизнес-логика — Dual access path). Попап «Номер занят» при сохранении остаётся.
- **D-03 (Подсказка при вводе — только «занят»):** кир/лат и двойник в живой подсказке НЕ
  показываются — только при сохранении.
- **D-04 (Кир/лат и двойник — на сервере):** проверку смешения алфавитов и поиск двойника
  (совпадение после замены похожих букв с живым номером того же пространства) делает сервер.
  Сохранение без флага подтверждения возвращает структурированное предупреждение (а не ошибку)
  с текстом и, если есть, сведениями о двойнике; клиент показывает попап и при «Продолжить»
  повторяет запрос с флагом подтверждения. Таблица похожих букв — одна, в Rust; JS-копии нет.
- **D-05 (Формы правки):** в формах правки устройства и акта (где шаблонов нет) действуют
  «Номер занят» (попап с карточкой записи, но **без** кнопки «Взять следующий свободный» —
  шаблона нет) и предупреждение кир/лат/двойник. «Не соответствует шаблону» в правке не бывает.
  Живая подсказка D-02 в формах правки — на усмотрение planner'а (тот же компонент, если дёшево).

### Номер акта как текст

- **D-06 (Коллизия с отображаемыми номерами возвратов):** пространство «номера актов»
  проверяется по **отображаемым** номерам: номер акта передачи `42в` запрещён, если существует
  живой возврат, отображаемый как `42в` (и `42в1`, `42в2` …). В списке и на печати не бывает
  двух разных актов с одинаковым видимым номером. Сравнение — trim + без учёта регистра.
- **D-07 (Дата токенов — сегодня на сервере, как в SPEC):** для актов `[YYYY]/[MM]/[DD]`
  разворачиваются по серверной дате в момент вычисления, **не** по дате передачи из формы.
  Акт задним числом — ручная правка номера (сработает попап «не по шаблону»). SPEC п. 2 не
  меняется.
- **D-08 (Хранение номера — trim, регистр как ввели):** во всех трёх пространствах сервер
  сохраняет номер с обрезанными краевыми пробелами; регистр не меняется. Сравнение на
  уникальность и совпадение с маской — без учёта регистра.
- Существующий каскад номера родителя на возвраты при правке акта
  (`act_service.rs` ~1054–1070, WR-01) сохраняется и переводится на текст.

### Блок шаблонов в настройках

- **D-09 (Таблица + модалка):** блок внизу `OrgSettings.svelte` — таблица с колонками
  «Тип · Маска · Следующий номер» (или «переполнен»), у строки `ActionMenu` (Изменить / Удалить),
  кнопка «Добавить шаблон». Создание и правка — в `Modal`: тип (кастомный Dropdown, не нативный
  `<select>`), маска, живой предпросмотр, справка по токенам с примерами.
- **D-10 (Тип неизменяем):** после создания редактируется только маска. Для смены типа шаблон
  удаляют и создают заново. В модалке правки тип показан, но недоступен.
- **D-11 (Меню «Вставка»):** пункты — маска + следующий номер серым
  (`ОРГ-00-[XXXXXX]  → ОРГ-00-000017`), галочка у активного шаблона поля, сортировка по
  алфавиту маски; переполненный — серый, недоступный, с пометкой «переполнен»; «Без шаблона» —
  внизу за разделителем.
- **D-12 (Удаление с подтверждением и перечнем контекстов):** подтверждение удаления; если
  шаблон запомнен в каких-то контекстах, текст перечисляет их («используется по умолчанию в
  „Новый акт“ — после удаления поле будет пустым»). Удаление физическое; записи с шаблоном не
  связаны.
- **D-13 (Нет шаблонов типа):** кнопка «Вставка» видна всегда; если шаблонов своего типа нет,
  меню показывает подсказку «Шаблонов нет — создайте в Настройки / Организация» (плюс «Без
  шаблона»). Для пользователя без прав на настройки — тот же текст, без ссылки.

### Поле номера (компонент)

- **D-14 (Гонка при открытом попапе):** по событию инвалидации (существующий механизм) поле
  перезапрашивает «первый свободный / max+1» и **тихо** заменяет значение, только если оно всё
  ещё равно ранее предложенному (пользователь не правил). Ручной ввод не трогается. Попап «Номер
  занят» с «Взять следующий свободный» остаётся страховкой.
- **D-19 (Переключатель ↑/↓):** иконка-стрелка без фона внутри поля справа + тултип,
  называющий следующее действие («Следующий после максимального: …021» / «Первый свободный:
  …017»). Без текстовой подписи в поле.
- **D-20 (Иконка «Вставка»):** берётся из того же источника/набора, что и текущие иконки
  приложения (researcher определяет источник), — «папка с документом» в едином стиле;
  добавляется в набор и в витрину. Кнопка — вариант GHOST из `Button.svelte`, квадратная.

### Миграции и counters

- **D-15 (DROP counters):** таблица `counters` удаляется (`DROP TABLE`) в той же миграции —
  других счётчиков в ней нет (только `act_number`, `cartridge_seq`, `drum_seq`, V009/V017).
  Забытое обращение к ней в коде упадёт в тестах — это и есть гейт. Порты `peek_next_number`
  (`ports/acts.rs:50`) и `peek_next_code` (`ports/cartridges.rs:40`) и инкремент в
  `acts_sqlite.rs:449` удаляются/заменяются вычислением по шаблону.
- **D-16 (Засев и в новой БД):** шаблоны `[X]` (Акты), `C-[XXXX]` (Картриджи),
  `D-[XXXX]` (Фотобарабаны) и их назначение контекстам «Новый акт / картридж / фотобарабан»
  создаются одной миграцией — и на обновлённой, и на пустой БД.
  **Уточнение 2026-09-18 (plan-phase):** ширина 4, а не 6 — совпадает с текущим форматом
  `assign_code_in_tx` (`{seq:04}` → `C-0001`), поэтому нумерация продолжается с существующих
  кодов. Существующие коды (включая редкие более длинные) не переписываются.
  6-разрядные маски сочтены избыточными.
- **D-17 (Память хранит id шаблона):** контекст ссылается на шаблон по id; правка маски
  применяется к контексту сразу (следующий попап подставляет номер по новой маске — так акты
  переводятся с `[X]` на `[YYYY]/[MM]-[X]` одной правкой). Удаление шаблона → «без шаблона»
  (SPEC п. 8; напр. `ON DELETE SET NULL`).
- **D-18 (Аудит переименования дублей):** запись аудита с `user_id = NULL` (система) и
  отдельным action (рабочее имя `custom:inventory_number_dedup`), в payload — старый и новый
  номер. Отличима от ручной правки.

### Claude's Discretion

- Точное имя и форма таблиц (`number_templates`, `number_template_contexts` или колонка),
  нормализованные колонки/индексы для уникальности (напр. генерируемая колонка + частичный
  UNIQUE-индекс `WHERE deleted_at_utc IS NULL`), способ перестройки `acts`/`cartridges` в SQLite.
- SQL- или Rust-миграция для `ДУБЛЬ-…` и засева (refinery поддерживает оба варианта).
- Таблица похожих кириллических/латинских букв (состав — стандартный набор гомоглифов А/A, В/B,
  Е/E, К/K, М/M, Н/H, О/O, Р/P, С/C, Т/T, Х/X, У/Y и строчные).
- Debounce-интервал живой подсказки; нужна ли подсказка в формах правки (D-05).
- Форма ответа-предупреждения (код/поле в `AppError` или отдельный вариант DTO) — лишь бы
  одинаково в Tauri и HTTP.
