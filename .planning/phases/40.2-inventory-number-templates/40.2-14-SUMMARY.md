## Accomplishments

- `ui/src/features/acts/ActFormBody.svelte`: create-mode «№» is now `NumberTemplateField` (context `act_create`, no per-type toggle unlike devices/printers); edit mode keeps a plain `Input` (D-05 — no templates/«Вставка»/↑↓ in edit). `handleSubmit` split into `submitCreate()` (occupied → mismatch → script-mix → NUM-08 `remember_context` via `acts.create`'s `ActSaveOutcome`) and `submitEdit()` (occupied → script-mix only, via `acts.update`'s `ActSaveOutcome`), sharing one `activePopup`/`pendingConfirm` state machine — identical structure to `DeviceFormBody.svelte`'s Plan 13 orchestration, per the plan's own explicit instruction to reuse that pattern for consistency across the three forms.
- `ui/src/features/acts/ActFormModal.svelte`: renders `NumberTakenPopup`/`NumberMismatchPopup`/`NumberScriptWarningPopup` as top-level `Modal` siblings driven by a new `onPopupChange` callback from `ActFormBody` — same pattern as `DeviceFormModal.svelte` (Plan 13), avoiding nesting a `Modal` inside a component whose ancestor `Modal` already has `backdrop-filter: blur(2px)` (confirmed present on the same `Modal.svelte` component both forms share).
- `ui/src/lib/api/acts.ts`: `create()`/`update()` retyped `ActSaveOutcome` (their real backend return type since Plan 06); `peekNextNumber()` wrapper removed.
- Final NUM-13 cleanup for acts (now safe — frontend no longer calls the old command): deleted `ActNumberField.svelte`; deleted `act_service.rs::peek_next_number()` (Plan 06's temporary shim) and `acts_peek_next_number`/`build_acts_peek_next_number` end-to-end — `tauri_cmds/acts.rs` command + builder, `http/acts.rs` handler + router route + import, `specta_export.rs` registration, `export_bindings.rs` assertion. Deleted `acts_crud.rs`'s `peek_next_number_frees_on_delete_of_last_act` test (exercised only the deleted shim).
- Full D-01 chain (occupied → mismatch → script-mix) works for the create popup; D-05 (occupied → script-mix, never mismatch) works for the edit form, including «Взять следующий свободный» (create only), the «Номер уже занят.» inline field error after «Закрыть», and re-invoking `handleSubmit()` after «Продолжить»/mismatch «Продолжить».
