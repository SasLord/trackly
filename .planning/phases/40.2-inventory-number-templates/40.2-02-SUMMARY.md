## Decisions Made
- `classify_token` counts raw `X` characters (`1` for `[X]`, `N>=2` for `[X…]`) and the width-vs-unbounded decision (`digit_width: Option<u32>`) is made only at the `parse_and_expand` boundary — keeps `Segment::Number` a simple `u32` count without an extra enum variant for "unbounded".
- `expand_date_tokens` uses `OffsetDateTime::from_unix_timestamp(...).unwrap_or(UNIX_EPOCH)` rather than propagating an error for an out-of-range timestamp — the caller is a trusted internal service passing "now" or a test fixture, never untrusted input, so a defensive fallback is simpler than adding a new `Result` layer to a function whose only realistic failure mode is a test bug.
- `extract_digits` bails out (`None`) if case-folding changes a string's character count (documented as a defensive guard for scripts like German ß) rather than assuming 1:1 char alignment — this codebase's number space is Cyrillic/Latin/digits/punctuation only, where the assumption always holds, but the guard costs nothing and avoids a silent mis-slice if that assumption is ever violated.
