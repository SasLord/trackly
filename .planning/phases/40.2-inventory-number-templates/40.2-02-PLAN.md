      это и есть основа для D-07 в плане 06).
    - `validate_mask(mask: &str) -> Result<(), AppError>` — синтаксическая проверка без
      разворачивания дат: ровно один `[X…]`-токен, остальной текст (включая нераспознанные
      скобочные конструкции типа `[Q]`) остаётся буквальным. Вызывается ДО сохранения шаблона
      (план 04) и вживую в форме шаблона (план 10) через 300-мс debounce round-trip на сервер —
      сам факт, что проверка ЖИВЁТ здесь, а не дублируется в JS, и есть требование
      `js_rust_mirror_needs_fixture_gate`.
    - `expand_date_tokens(mask: &str, today_utc: i64) -> String` — вспомогательная функция,
      разворачивающая `[YYYY]`/`[YY]`/`[MM]`/`[DD]` в конкретные цифры по `today_utc` (использовать
      `time` crate, уже в зависимостях проекта — см. CLAUDE.md «Рекомендуемый стек», НЕ chrono).
    - `render_number(parsed: &ParsedMask, n: u64) -> String` — `prefix + (если digit_width:Some(w)
      — n с ведущими нулями до ширины w, иначе — n без нулей) + suffix`.
    - `extract_digits<'a>(parsed: &ParsedMask, candidate: &'a str) -> Option<u64>` — обратная
      операция: если `candidate` (после `.trim()`, без учёта регистра буквальных частей —
      сравнение литералов case-insensitive, см. D-08 в плане 06/07/08) начинается с `prefix`,
      заканчивается `suffix`, а между ними — ровно `digit_width` (если `Some`) цифр или 1+ цифр
      (если `None`), возвращает разобранное число; иначе `None`. Эта функция — единственное
      место, где текстовое значение записи превращается в число «принадлежит ли эта запись
      последовательности шаблона» (план 03 будет вызывать её для каждой живой строки).
