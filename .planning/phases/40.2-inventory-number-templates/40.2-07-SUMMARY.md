## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test scenario for "live + soft-deleted same code" seeded an impossible pre-migration state**
- **Found during:** Task 1, first test run of `cartridges_code_unique_migration.rs`
- **Issue:** The plan's own action text described seeding "a live cartridge AND a soft-deleted cartridge, both with code C-0042" as two coexisting rows before applying V043. Taken literally, this meant the post-migration verification insert of a THIRD live C-0042 row would conflict with the still-live first row, not prove the intended "soft-deleted code frees up" claim.
- **Fix:** Reinterpreted as a single row's lifecycle (created live, later soft-deleted — the OLD column-level UNIQUE made even this trivial transition permanently reserve the code forever, the actual NUM-09 pain point) rather than two coexisting rows.
- **Files modified:** `crates/trackly-infra/tests/cartridges_code_unique_migration.rs`
- **Verification:** All 4 tests in the file pass.
- **Committed in:** `9a61dcf2` (Task 1 commit)

**2. [Rule 3 - Blocking] `role_endpoint_matrix.rs`'s raw JSON cartridge payload still used `code_override`**
- **Found during:** Full-suite verification run after Task 3 compiled
- **Issue:** Case 5 (Employee → `cartridges_create` → expected 403) built a raw JSON payload by hand with the old field name. With `number_input` now a REQUIRED field, axum's `Json` extractor rejected the payload with 422 before `authorize()` ever ran — got 422, expected 403. Identical class of bug to Plan 06's acts_create fix.
- **Fix:** Updated the payload to `number_input` in `NumberFieldInput`'s own camelCase wire casing.
- **Files modified:** `crates/trackly-app/tests/role_endpoint_matrix.rs`
- **Verification:** `cargo test -p trackly-app --test role_endpoint_matrix` — 1 passed / 0 failed.
- **Committed in:** `487ceb6c` (Task 3 commit)

**3. [Rule 3 - Blocking] `ui/src/features/cartridges/CartridgeFormBody.svelte` failed `svelte-check` with real TS errors**
- **Found during:** Post-implementation UI verification (`pnpm --dir ui exec svelte-check`)
- **Issue:** This component constructs the typed `CartridgeCreateDto` object literal directly — 2 hard TypeScript errors (`code_override` does not exist on type `CartridgeCreateDto`; then, after the first fix, `template_id` does not exist on `NumberFieldInput` — its OWN `#[serde(rename_all = "camelCase")]` requires `templateId`/`confirmMismatch`/`confirmScriptMix`).
- **Fix:** Rewired the code field to build `number_input` (camelCase inner fields), added client-side non-empty-code validation on create (mirroring the new server rule, avoiding a pointless round-trip), disabled the code field during edit (it was already ignored by `update()`, just no longer misleadingly editable), and updated the now-inaccurate "auto-code" hint copy. Deliberately did NOT add a peek-next-code prediction (unlike Plan 06's `ActFormBody.svelte`, which reused a PRE-EXISTING `acts_peek_next_number` endpoint) — cartridges never had an equivalent peek endpoint to reuse, and building one is out of this plan's declared scope (Plan 11/14/15's job).
- **Files modified:** `ui/src/features/cartridges/CartridgeFormBody.svelte`
- **Verification:** `pnpm --dir ui exec svelte-check` — 0 errors; `pnpm --dir ui lint` and `pnpm --dir ui build` both clean.
- **Committed in:** `487ceb6c` (Task 3 commit)
