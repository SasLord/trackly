## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Employee session → timeline endpoint | Untrusted with respect to this data — must be rejected, not just hidden in the UI |
| Manager/Admin session → timeline endpoint | Trusted, full read access to all entities' history (no per-item ownership filter, per D-12's stated scope) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-21 | Elevation of Privilege | BOLA — Employee crafting a request for an arbitrary entity_id's history | mitigate | `Action::ReadPlaces` gate is role-based (Admin+Manager only), checked before any DB query runs — Employee is denied the entire surface regardless of entity_id, no per-item logic to bypass |
| T-40-22 | Elevation of Privilege | Transport asymmetry — gate present on Tauri but not HTTP (or vice versa) | mitigate | Both `build_place_movements_get_timeline` (Tauri) and `handler_get_timeline` (HTTP) route through the SAME `PlaceMovementService::get_timeline`, which is where `authorize()` lives — a missed transport-side check cannot bypass the gate, only a change inside the shared service method could, and Plan 40-14's role-matrix tests verify both transports explicitly |
| T-40-23 | Information Disclosure | Unknown `source` token leaking a raw/garbage string to the UI without a safe fallback | mitigate | `MovementSource::from_str_lenient` (Plan 40-01) is available for any Rust-side consumer needing a typed match with a safe fallback label; the DTO passes the raw token through by design (UI composes the final phrase per UI-SPEC) but never panics on an unrecognized value |
</threat_model>
