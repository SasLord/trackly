# Phase 40 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Reading this spec:** Phase 40 is an integration phase in a mature design system (Trackly's
own tokens + component library, shipped Phases 23–30). There is nothing to invent — every
value below is either a literal existing `--tr-*` token/component or an explicit new copy
string modeled on an existing sibling string. Where CONTEXT.md left a decision to Claude's
Discretion, the choice is called out explicitly in **§ Claude's Discretion** at the end,
never silently folded into a table above it.

## Color

This phase introduces **zero new color tokens**. It reuses the existing light/dark `--tr-*`
palette exactly as `CartridgeDetail.svelte`, `ReportTable.svelte`, and `PlaceContents.svelte`
already do.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--tr-bg` / `--tr-surface` | Modal body, report page background, panel surfaces |
| Secondary (30%) | `--tr-surface-raised` / `--tr-surface-sunken` / `--tr-border` | `DetailSection` dividers, table header row, timeline row bottom border (`--tr-border`) |
| Accent (10%) | `--tr-accent-text` | **Reserved for exactly two elements per timeline row: the clickable place segment and the clickable act number (D-19).** No other new element in this phase uses accent color. |
| Destructive | `--tr-danger` / `--tr-danger-text` | Not used by this phase — the phase introduces no destructive action (D-28's bulk move is a place change, not a deletion; see Copywriting Contract) |

Additional semantic reuse (not part of the 60/30/10 split, but load-bearing for D-25):

| Role | Value | Usage |
|------|-------|-------|
| Neutral/archived marker | `Badge variant="default"` (`--tr-surface-sunken` bg / `--tr-text-primary`) | «Удалено» marker on soft-deleted report rows (D-25) — clones the exact `<Badge variant="default">Архив</Badge>` pattern already used for archived places in `PlaceContents.svelte:234` |

Accent reserved for: the place-path link and the act-number link inside a movement/timeline
row, and their exact equivalents in the report table (place cells stay plain per D-26's
existing convention — only the two links inside the **timeline** row, not report table cells,
carry accent color; report cells are read-only text, consistent with all 12 existing reports).

### Timeline row anatomy (D-17, D-18, D-19, D-11)

Canonical row format (confirmed in CONTEXT.md discussion, reproduced verbatim with an invented
example — the org name and any real identifiers are never used):

```
01.09 — Здание А / 2 эт. / 214 → Склад · Иванов И.И. · актом №123
```

Contract per element:

| Element | Source | Rendering rule |
|---------|--------|------------------|
| Date | `created_at_utc` | `ДД.ММ.ГГГГ` — same manual `padStart` formatting already used by `CartridgeDetail.svelte::formatDate` (no `Intl`/locale dependency, per the project's established single-tz convention) |
| «Откуда» place | `from_place_path` snapshot, shortened server-side (D-18) | Rendered as a clickable inline-text link (`--tr-accent-text`, underline on hover) — **not** a `Button` component, styled exactly like `PlaceContents.svelte`'s `.crumb` pattern but colored accent instead of `color: inherit` (this row is a real navigation link, not passive breadcrumb text); `title` attribute carries the FULL stored path snapshot (native tooltip, D-17 — no new Tooltip component, none exists in the codebase and none is needed) |
| Arrow | literal `→` | Plain text, `--tr-text-secondary` |
| «Куда» place | `to_place_path` snapshot, shortened server-side | Same clickable-link contract as «Откуда» |
| Separator | `·` (middle dot) | Plain text, `--tr-text-secondary`, matches the existing `formatHistoryEntry` separator style (`;`/`—`) in spirit — middle dot chosen for a 3-part row per the discussed format |
| «Кем» | `actor_display` (ФИО, else login, else «система» — D-11) | Plain text, `--tr-text-primary`, never a link (no user-detail screen exists to link to) |
| «Причина» | `source` + `note`, OR `act_id` → act number | If `source == 'act'`: literal text «актом №{act_number}» where the number itself is a clickable link (`--tr-accent-text`, same inline-link styling used for the place links, D-19) navigating to `#/acts?id={act_id}` via `parseIdFromHash`-compatible hash write (mirrors `PlaceEntityViewModal::handleGoTo`'s `push()`-before-`onClose()` sequencing — the ActsPage must accept the same `?id=` hash query the device/cartridge/printer pages already do, extending the existing `parseIdFromHash` convention to the Acts section for the first time). If `source == 'manual'` and `note` is empty: literal text «вручную». If `note` is non-empty: «вручную · {note}». `map`/`workstation` sources are UNREACHABLE in this phase's data (D-07 defines them, no write site produces them yet) but MUST still render a safe fallback label if ever seen, never crash the row (Pitfall 6 from RESEARCH.md) |
| Clickable-link CSS contract (both place segments and act number) | new, but modeled | `background: none; border: none; font: inherit; padding: 0; color: var(--tr-accent-text); cursor: pointer;` on hover: `text-decoration: underline;` on `:focus-visible`: `outline: none; box-shadow: 0 0 0 3px var(--tr-focus-ring); border-radius: var(--tr-radius-xs);` — this is `PlaceContents.svelte`'s `.crumb` rule set with `color: inherit` replaced by `var(--tr-accent-text)`, nothing else changed |

Ordering and pagination (D-20): `ORDER BY created_at_utc DESC` — newest row first, entire list
rendered at once, no "load more"/pagination control of any kind (none exists in this phase's
scope; do not add one).

### Accessibility notes

- **Table focus ring:** the movements report table uses the project's SETTLED first-cell inset
  focus ring (`box-shadow: inset 0 0 0 3px var(--tr-focus-ring)` on `> td:first-child:focus-visible`,
  `TableRow.svelte`). **Do not** propose a full-row focus ring for this report — that pattern was
  explicitly evaluated and abandoned project-wide (see project memory: "Table focus-ring decision").
- **Tooltip mechanism:** native `title=` attribute only. The codebase has no dedicated Tooltip
  component (confirmed: zero matches for a `Tooltip.svelte` anywhere in `ui/src`); D-17's
  "full path on hover" requirement is satisfied entirely by the browser's native title tooltip,
  exactly as `ReportTable.svelte::formatCellTitle` already does for place-path columns.
- **Clickable inline-text links** (place segments, act number) must be real `<button type="button">`
  elements (not `<a href>`/`<span onclick>`) — matches `PlaceContents.svelte`'s `.crumb` pattern,
  keeps them in the natural tab order and gives them the standard `:focus-visible` ring above.
- **Role gate is cosmetic-only in the UI layer:** the Employee role never sees the «Перемещения»
  report domain tab nor the timeline sections (D-12), but per the project's established
  999.1 backlog item, hiding these in the UI is a UX nicety — the real security boundary is the
  backend `Action::ReadPlaces` gate on both transports. No UI-only work should be treated as the
  access-control mechanism.
- **Bulk-move confirm dialog** keyboard/focus behavior clones `DeviceContextMenu`'s existing
  delete-confirm `Modal` exactly (focus trap, Escape-to-close, footer button order Отмена→primary).

## Claude's Discretion

Per the autonomous-mode instruction, these choices were NOT locked by CONTEXT.md and are
recorded here explicitly rather than silently assumed:

1. **New «Просмотр» context-menu item for devices (D-14 entry point).** CONTEXT.md says the
   modal "opens from the device list" but does not specify the exact UI trigger. Chosen: a new
   first item «Просмотр» in `DeviceContextMenu.svelte`'s existing kebab menu, above «Редактировать»
   — consistent with the menu-driven interaction model already used for every list action in this
   codebase (no row-click-to-open exists anywhere in the device list today, so introducing one
   would be a new, unrequested interaction pattern; the kebab menu is the established affordance).
2. **Report type label «Все перемещения».** D-22 fixes the domain label («Перемещения») but not
   the single report-type tab label under it. Chosen to mirror the existing «Все» pattern used by
   the Заявки domain's first tab (`REQUEST_REPORTS[0]`), scoped to this domain's single entity:
   «Все перемещения».
3. **Accent color reserved specifically for the two D-19 links, nowhere else.** Not explicitly
   stated in CONTEXT.md; chosen to keep the 10% accent allocation tight and matches the project's
   general accent-discipline (accent = one clear "this is the interactive/primary thing" signal,
   never decorative).
4. **Bulk-move action classified as `variant="primary"`, not `variant="destructive"`.** CONTEXT.md
   (D-28) describes the action's mechanics but not its visual danger-level. Chosen: primary, not
   destructive — the action changes location, it does not delete or lose data, and D-13 confirms
   this phase does not touch mutation-permission or danger classification.
5. **Modal size stays `"md"` for the extended `PlaceEntityViewModal`.** D-15 mandates minimum
   content (no new actions, no act list) — a single new `DetailSection` fits the existing `"md"`
   width without needing `"wide"`.
6. **`ActsPage` gains hash-query support (`?id=`) for the D-19 act-number link.** No other phase-40
   decision covers this; it is a necessary consequence of D-19 ("act number is clickable → navigates
   to the act card") combined with the fact that `ActsPage.svelte` does not yet consume
   `parseIdFromHash` the way `DevicesPage`/`CartridgesPage`/`PrintersPage`/`PlacesPage` already do.
   This is a small, mechanical extension of an existing, proven pattern — not a new navigation
   design.
