<objective>
Wire D-03's undo-scoped deletion into `delete_soft`'s existing per-act LIFO cascade loop. This plan was
split out of Plan 40-09 per plan-checker feedback: 40-09 originally carried FOUR tasks covering two of
the phase's highest-risk pitfalls (Pitfall 4 — NULL-skip on the return flow — and Pitfall 5 — undo-cascade
scoping) inside the same large `act_service.rs`, pushing that single plan's context budget too high.
Splitting Pitfall 5's undo-scoping work into its own focused plan keeps each plan's scope tight while
preserving the dependency this work genuinely has on Plan 40-09 (both plans touch `act_service.rs` and
the same test file, so they cannot run in the same wave — this plan runs strictly after 40-09).

Purpose: deleting an act must correctly and precisely un-happen its own movement history, without
leaving orphaned rows for other acts or destroying a sibling act's history.
Output: `delete_soft`'s Handover-cascade loop and standalone-return delete path each get their own
`DELETE FROM place_movements WHERE act_id = ?1` at their own point in the existing flow; a dedicated
test proves the nested-cascade scoping is exact.
</objective>
