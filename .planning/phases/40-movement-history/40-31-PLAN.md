Tauri command (via `apiCall`, camelCase args): `cartridges_operation_default_place(op: string,
cartridgeId: number | null) -> number | null`. `op` is exactly `'to_refill'` or `'from_refill'`
(any other value is a server-side `AppError::Validation` — the frontend never sends anything
else since it only calls this from those two `op` branches).

From `ui/src/features/cartridges/api.ts` (existing pattern to mirror):
```
export const cartridges = {
  list: (filter: CartridgeFilter, pagination: Pagination) =>
    apiCall<CartridgeListResponse>('cartridges_list', { filter, pagination }),
  ...
  lowStock: () => apiCall<LowStockItemDto[]>('cartridges_low_stock'),
};
```

From `ui/src/features/cartridges/OperationModal.svelte` (existing WR-01 autofill pattern to
mirror exactly — install's printer-place autofill, lines ~230-296):
```
$effect(() => {
  if (!(open && op === 'install' && effectivePrinterId !== undefined)) { ... return; }
  let cancelled = false;
  printers.getByDeviceId(effectivePrinterId).then((printer) => {
    if (cancelled) return null;
    if (printer.devicePlaceId !== null && (placeId === null || placeAutofilled)) {
      placeId = printer.devicePlaceId;
      placeAutofilled = true;
    }
    ...
  });
  return () => { cancelled = true; };
});
```
Form-state fields already present: `let placeId = $state<number | null>(null);`,
`let placeAutofilled = $state(false);`. Reset effect (lines ~128-149) already sets both to
`null`/`false` on every `open`/`op` change — the new effect runs AFTER that reset, same
ordering the install-autofill effect already relies on.

PlacePicker's shared field block for `to_refill` (lines ~776-788, inside
`{#if op === 'install' || op === 'to_refill'}`) already resets `placeAutofilled = false` on
manual `onChange`. The `return_to_stock`/`from_refill` shared block (lines ~817-825) currently
does NOT — Task 1 below adds that reset there too, so `from_refill`'s new autofill follows the
identical WR-01 guarantee.

`effectiveCartridge` (`$derived(cartridge ?? selectedCartridge)`) is always non-null when
`op` is `'to_refill'`/`'from_refill'` — those two ops are never opened with `cartridge={null}`
(only `install`'s request-centric flow does that, per D-01/D-02, Phase 12).
