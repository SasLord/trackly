1. **CR-03 / gap 1**: `DeviceService::update` каскадирует место принтера на прикреплённые
   картриджи БЕЗУСЛОВНО, включая переход `Some(P) -> None` (очистка места принтера) — каскад
   стирает `place_id` каждого прикреплённого картриджа в NULL, а D-06-гейт
   `is_reportable_place_change` делает `record_movement_if_applicable` тихим no-op для
   `Some -> None`, так что ни строки `place_movements`, ни строки `audit_log` не остаётся —
   данные о месте картриджа теряются безвозвратно и незаметно.

2. **CR-02 / gap 2**: `last_known_storage_place_in_tx` при авто-возврате картриджа без явного
   `previous_cartridge_place_id` ищет складское место ТОЛЬКО среди `to_place_id` строк
   `place_movements`. По собственному правилу D-06 этой фазы первое назначение места картриджу
   (в т.ч. переход `NULL -> склад` при создании) никогда не пишет строку истории — так что
   самый обычный жизненный цикл (создан на складе → установлен в принтер → второй картридж
   вытесняет первый) не даёт ни одной подходящей `to_place_id`-строки, и авто-возврат обнуляет
   место вместо возврата на склад. Существующий регрессионный тест
   `install_auto_return_falls_back_to_last_known_storage_place` зелёный только потому, что
   вручную досеивает недостижимую в реальном коде строку `place_movements` сырым SQL.
