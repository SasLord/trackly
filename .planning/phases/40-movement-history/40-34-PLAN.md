<objective>
Закрыть UAT4-01: автокомплит «Кому выдал» теряет имена, введённые при заправке картриджа, как
только более поздняя операция того же картриджа перезаписывает cartridges.holder_name другим
значением — потому что holder_name хранит только ТЕКУЩЕЕ значение, а не историю.

Purpose: `40-HUMAN-UAT.md`, UAT4-01. Код-верификация (не доверие тексту UAT) показала, что
`suggest_person` УЖЕ содержит симметричную арку для Giver (`given_by_name_arm`, добавлена в Фазе
12, commit `3adeb6ee`, читает `audit_log.payload_json` для полной истории install/to_refill) — но
для Receiver симметричной арки НЕТ, а doc-комментарий над `suggest_person` прямо утверждает
(ошибочно), что `given_to_name` «уже покрыт» существующей аркой `cartridges.holder_name`. Это
верно только для ПОСЛЕДНЕГО значения на картридже — holder_name перезаписывается каждым новым
install/to_refill, так что более ранние получатели структурно теряются.

Output: новая UNION ALL арка `given_to_name_arm`, зеркалящая `given_by_name_arm` буквально,
исправленный doc-комментарий, 4 новых теста включая прямую регрессию на реальный симптом
(перезапись holder_name НЕ должна стирать имя из подсказок).

act_service.rs::suggest_person (full body already read by the planner, ~line 2467-2549) currently
builds SQL with three components: (1) a per-field arm over the acts table (giver_name or
receiver_name column, whitelisted via the SuggestPersonField enum, never string-interpolated from
user input), (2) an unconditional arm over cartridges.holder_name (applies to BOTH Giver and
Receiver identically — the cartridges table has no giver/receiver distinction, holder_name is its
only person-name column), and (3) given_by_name_arm — a UNION ALL arm that is non-empty ONLY for
SuggestPersonField::Giver, matched via a Rust match field { Giver => "...", Receiver => "" }. That
Giver-only arm's SQL body is: SELECT json_extract(payload_json, '$.given_by_name') AS name,
COUNT(*) AS freq FROM audit_log WHERE entity_type = 'cartridge' AND action IN ('custom:install',
'custom:to_refill') AND json_extract(payload_json, '$.given_by_name') IS NOT NULL AND
json_extract(payload_json, '$.given_by_name') != '' AND json_extract(payload_json,
'$.given_by_name') LIKE ?1 ESCAPE '\\' GROUP BY json_extract(payload_json, '$.given_by_name').
This whole arm string is spliced into the outer query via a {given_by_name_arm} format
placeholder, itself inside a UNION ALL chain that is finally wrapped in an outer SELECT name,
SUM(freq) AS total_freq FROM (...) GROUP BY name ORDER BY total_freq DESC, name ASC LIMIT ?2. The
outer query and its LIMIT/ORDER BY/params![pattern, bounded_limit] binding do not need to change —
only a second per-field arm needs to be added and spliced in alongside the first.

Every field in the outer format!() macro call is named (col, given_by_name_arm) — adding a second
named placeholder (given_to_name_arm) is a straightforward extension of the same format! call, no
restructuring needed.

audit_log.payload_json's given_to_name key exists for the SAME two actions as given_by_name
(custom:install, custom:to_refill) — confirmed by op_payload_json (cartridges_sqlite.rs) writing
both keys together in the same JSON object for both ops. The GAP-12-12 auto-return branch
(transition_in_tx, install cascading an auto-return of a previous cartridge) ALSO writes
given_by_name/given_to_name into its own payload_json under action custom:return_to_stock — this
is deliberately OUT OF SCOPE here, mirroring the existing given_by_name_arm's own scope decision
(action IN ('custom:install', 'custom:to_refill') only, confirmed by test
suggest_person_excludes_given_by_name_from_irrelevant_action in acts_suggest.rs) — do not widen
the action filter beyond what the Giver arm already uses.

acts_suggest.rs test fixture to mirror exactly — seed_audit_log_given_by_name (~line 511-541):
inserts one audit_log row with a caller-chosen entity_type/action, a payload_json literal
containing BOTH given_by_name and given_to_name keys (the helper's own payload always includes
both, mirroring the real write shape) and a caller-chosen given_by_name value. Reuse this SAME
helper unmodified for the new given_to_name tests — its payload_json already carries a
given_to_name key ("Кому Выдал" literal), which is enough for the new tests' assertions when they
target given_to_name specifically; where a distinct given_to_name value matters, add a second
helper given_to_name-parametrized the same way (mirror the existing helper's shape, do not modify
it — it's shared with the existing Giver tests at lines 546-666, which must keep passing
unmodified).
