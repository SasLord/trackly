# Phase 41.7 Plan 03: публичный bootstrap первого администратора Summary

**Публичный `POST /api/v1/auth_bootstrap` создаёт первого администратора по LAN: граница — «нет активного админа», проверяемая внутри той же writer-транзакции, что и вставка; роль навязывается сервером; свой governor 1/с burst 5; аудит без автора (`custom:bootstrap`).**

## Что сделано

- `AuthService::bootstrap_first_admin(UserNew)`: без `authorize` (публичный; обоснование в доккомментарии), `role = "admin"` ставится раньше `validate_user_new`, предпроверка `needs_bootstrap` до argon2, затем в writer-замыкании `count_active_admins(&tx) != 0` -> `Conflict` ("Первоначальная настройка уже выполнена"), вставка, коммит.
- `count_active_admins` — приватный помощник с тем же SQL, что был в `needs_bootstrap`; вызывается из `needs_bootstrap` и из `bootstrap_first_admin` (определение + 2 вызова + тестовые ссылки = 4 вхождения в файле).
- `insert_user_in_tx` + `NewUserRow` выделены из `create_user` (revive soft-deleted логина / insert / audit_log); `create_user` сохранил действия «create»/«revive» и `caller_id`; для bootstrap `caller_id = None`, действие `custom:bootstrap`.
- HTTP: `BootstrapPayload { userNew }`, `build_auth_bootstrap`, `handler_auth_bootstrap` (ни `Session`, ни `session_identity`); маршрут в `http/mod.rs` с собственным `GovernorConfigBuilder` (`per_second(1)`, `burst_size(5)`), шапка обновлена.
- Tauri: `build_auth_bootstrap_tauri` (напрямую в сервис, не через `resolve_tauri_identity`) + команда `auth_bootstrap`, зарегистрирована в `collect_commands!`.
- Миграций нет: `audit_log.user_id` допускает NULL, `action` — свободный текст.

## Тест, доказывающий отказ (граница безопасности)

Отказ при «админ уже есть» доказывают:
- `bootstrap_route_closed_after_first_user` — второй POST после первого админа -> 409, в БД один админ и один пользователь;
- `bootstrap_route_race_exactly_one_wins` — два параллельных POST (`tokio::join!`) -> ровно `[200, 409]`, один админ;
- `bootstrap_tauri_and_http_share_one_path` — второй вызов Tauri- и HTTP-билдера -> `AppError::Conflict`.

Открытая сторона: `bootstrap_route_open_when_needs_bootstrap` (200, роль `admin` при присланной `employee`, `needs_bootstrap` -> false, ровно одна строка аудита `custom:bootstrap` с `user_id IS NULL`) и `bootstrap_route_open_when_only_non_admins_exist` (сотрудник не закрывает окно — предикат «нет админа», а не «нуль пользователей»).

Прочее: `bootstrap_route_rate_limited_per_peer` (первые 5 не 429, дальше 429), `bootstrap_invalid_input_rejected` (400, админ не создан, окно открыто), `users_create_still_requires_session` (401 без сессии при `needs_bootstrap == true`).
