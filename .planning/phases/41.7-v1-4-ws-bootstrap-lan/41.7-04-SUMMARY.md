# Phase 41.7 Plan 04: F17 и перевод мастера на auth_bootstrap Summary

**Неизвестный `/api/...` теперь отвечает `404 application/json` (`code: NOT_FOUND`) вместо `index.html` с кодом 200; мастер первого запуска создаёт администратора через публичный `auth_bootstrap`, а не через `users_create`, который по LAN давал 401.**

## Что сделано

- `spa_fallback` (`crates/trackly-app/src/http/mod.rs`): сразу после вычисления `path` ранний возврат `AppErrorResponse(AppError::NotFound { entity: "api_route", id: 0 })`, если `path == "api"` или `path.starts_with("api/")`. Сверка по границе сегмента: `/apiary` остаётся SPA-путём. Доккомментарий дополнен исключением.
- `http_route_parity.rs`: новый тест `unknown_api_path_answers_json_404_not_spa` — `POST /api/v1/zzz_unknown`, `GET /api/zzz`, `GET /api` -> 404, `application/json`, `code == "NOT_FOUND"`. Охранные кейсы (только при собранном `ui/dist/index.html`, иначе печатается причина пропуска): `GET /` -> 200, `GET /apiary` -> не JSON-404. На этом прогоне `ui/dist/index.html` был на диске, охранные кейсы выполнены.
- Устаревшие комментарии в шапке и у `live_router_answers_every_tauri_command_path` (описывали дефект как действующий) и текст сообщения об ошибке паритета обновлены: исправлено в Фазе 41.7 (F17). Сам `live_router_...` не менялся — эталон из двух фиктивных имён остаётся рабочим (оба ответа теперь одинаковый 404 JSON).
- `FirstRunWizard.svelte`: `'users_create'` -> `'auth_bootstrap'` (один вызов), тело `userNew`, последующий `auth_login` и переход на `#/` не менялись. Путь показа ошибки уже выводит `e.message`, поэтому 409 («Первоначальная настройка уже выполнена») не проглатывается; состояние и вёрстка не менялись.
