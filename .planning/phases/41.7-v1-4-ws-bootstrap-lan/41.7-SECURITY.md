## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| сервис → WS-канал → LAN-браузер | события рассылаются на сокеты всех аутентифицированных клиентов; фильтр по роли — `WsEvent::is_visible_to` перед отправкой в сокет (`http/ws.rs:141`) | числовые id мест/устройств/групп |
| WS-handshake с cookie → сервер | `ws_auth_middleware`: без сессии 401; роль берётся из сессии | cookie сессии, роль |
| сервис → десктопный webview | мост в `main.rs:304-320` шлёт событие БЕЗ `is_visible_to` — осознанно (принятый риск T-41.7-04) | числовые id |
| LAN-браузер (аноним) → `POST /api/v1/auth_bootstrap` | публичный маршрут без сессии создаёт первого администратора | логин, ФИО, пароль, e-mail; роль навязывается сервером |
| тело запроса → роль пользователя | клиент присылает поле `role`; сервер перезаписывает его до валидации | `UserNew` |
| любой клиент → неизвестный `/api/`-путь | до F17 отдавался `index.html` с кодом 200; теперь 404 JSON | путь запроса |
| строка поиска пользователя → SQL | `trackly_act_number(...) LIKE ?1` — связанный параметр, `%`/`_` вычищены | текст поиска |
| пользовательская SQL-функция → соединение SQLite | ошибка вместо паники через FFI; функция живёт только на соединении | act_type, number, sub_number, parent_number |

| Risk ID | Threat Ref | Rationale | Accepted By | Date |
|---------|------------|-----------|-------------|------|
| AR-01 | T-41.7-04 | Десктопный мост (`main.rs:304-320`) доставляет `EntitiesChanged` без `is_visible_to`.
