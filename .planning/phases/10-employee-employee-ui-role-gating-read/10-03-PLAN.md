<objective>
Close the two backend gaps CONTEXT.md identifies that 10-01/10-02 do not cover: (1) D-REQ-01 — force-override the requester filter server-side so an Employee's `requests_list`/`counts` always scope to their own rows regardless of client input, and (2) the BOLA gap in `request_service::get()`/`get_history()` where a request is fetchable by bare numeric ID with no ownership check on either transport, and (3) D-GATE-03 — give the Employee dashboard a genuinely separate, narrow query path instead of a client-filterable copy of the org-wide payload.

Purpose: An Employee who can already only see their own requests in `requests_list` (existing `exclude_ad_register` precedent extended here) must not be able to bypass that scoping by calling `requests_get`/`requests_get_history` directly with another user's request ID, and must never receive the organization's device/cartridge/printer counts inside the dashboard response — even if the frontend never renders those fields, the data must not cross the wire.

Output: `request_service.rs` with caller-threaded `get`/`counts`/`get_history` and a `requested_by_user_id` override in `list`; `dashboard_service.rs` with an `Employee`-only `get_employee_widgets` method; both transports updated to thread identity through; CI cases 16-20 appended to `role_endpoint_matrix.rs` asserting response bodies, not just status codes.
</objective>
