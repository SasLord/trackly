<objective>
Close the BFLA (API5:2023) gap across the five resource domains explicitly named
in CONTEXT.md D-GATE-01/D-GATE-02: devices, acts, cartridges, printers, reports.
Every read `build_*` helper in these five domains currently takes only `ctx:
&AppCtx` (no `caller: &Identity`), and every corresponding HTTP handler discards
`_identity` while every Tauri wrapper skips `resolve_tauri_identity` entirely.
This plan retrofits ALL of them to the established 3-layer pattern already used
correctly by `request_service.list` -> `http/requests.rs::handler_list` ->
`tauri_cmds/requests.rs::requests_list` (RESEARCH.md's one complete reference
example) and by `users_list` (already correctly gated via `build_users_list_tauri`
+ `resolve_tauri_identity`, confirmed in this codebase).

Purpose: With Plan 10-01's matrix fix landed, `authorize(caller, &Action::ReadData)`
now correctly rejects Employee — but only at call-sites that actually invoke it.
This plan IS those call-sites: every read `build_*` helper across the five domains
gets a `caller: &Identity` parameter and an `authorize(caller, &Action::ReadData)`
call; every HTTP handler stops discarding `_identity` and passes it through;
every Tauri wrapper calls `resolve_tauri_identity` first. Two distinct fixes are
required per domain per RESEARCH.md Pitfall 5: the HTTP side currently HAS an
identity (just discards it, a rename fix), the Tauri side is MISSING the
`resolve_tauri_identity` call entirely (an addition, not a rename).

Output: ~25 read methods across 5 domains gated on both transports; CI matrix
extended with explicit Employee=403 / Manager=200 cases for one representative
read endpoint per domain (devices_list, acts_list, cartridges_list,
printers_list, a representative reports endpoint) plus an explicit users_list
case proving the pre-existing correct gating. No DB migration — `authorize()` is
pure in-memory role logic; no schema change needed (RESEARCH.md confirmed).
</objective>

#[tauri::command]
#[specta::specta]
pub async fn requests_list(
    state: tauri::State<'_, AppCtx>,
    filter: RequestFilter,
    pagination: Pagination,
) -> Result<RequestListResponse, AppError> {
    let caller = resolve_tauri_identity(state.inner()).await?;
    build_requests_list(state.inner(), &caller, filter, pagination).await
}

// http/requests.rs::handler_list — identity is USED, not discarded:
pub async fn handler_list(
    State(ctx): State<AppCtx>,
    session: Session,
    Json(p): Json<ListPayload>,
) -> Result<Json<RequestListResponse>, AppErrorResponse> {
    let identity = session_identity(&session).await.map_err(AppErrorResponse::from)?;
    Ok(Json(build_requests_list(&ctx, &identity, p.filter, p.pagination).await
        .map_err(AppErrorResponse::from)?))
}

<!-- The ALREADY-CORRECT users_list precedent (CR-03), proving this exact pattern
     is the established convention — not a new invention by this plan.
     Source: crates/trackly-app/src/tauri_cmds/users.rs (verified in codebase). -->

pub async fn resolve_tauri_identity(ctx: &AppCtx) -> Result<Identity, AppError> {
    let lock = ctx.auth.get_desktop_lock_enabled().await?;
    if lock {
        Ok(ctx.auth.desktop_identity().await)
    } else {
        Ok(Identity::trusted_admin())
    }
}

pub async fn build_users_list_tauri(
    ctx: &AppCtx,
    filter: UserFilter,
    pagination: Pagination,
) -> Result<UserListResponse, AppError> {
    let caller = resolve_tauri_identity(ctx).await?;
    ctx.auth.list_users(filter, pagination, &caller).await
}
