<objective>
Implement the three frontend-only decisions CONTEXT.md locks for Phase 10 that no prior plan covers: D-UI-01 (a genuinely separate, minimal `EmployeeLayout.svelte` shell — not a conditional branch inside the existing sidebar `Layout.svelte` — landing on the Employee's own Заявки), D-DENY-01 (an `AccessDenied.svelte` screen shown when an Employee navigates directly to a forbidden route, plus the matching 403-handling branch in `ui/src/lib/api/client.ts` for both the Tauri and HTTP transports), and D-GATE-03's frontend half (a «Мои заявки» `StatWidget` summary card on the Employee landing page, wired to the employee-scoped branch of `dashboard_get_all_widgets` built in 10-03 — without this, D-GATE-03's backend scoping has no UI surface and is unverifiable by an actual user).

Purpose: The backend (10-01, 10-02, 10-03) now correctly returns 403 for every Employee read attempt outside Заявки, and 10-03 already scopes `dashboard_get_all_widgets` to the caller's own requests for the Employee role. Without this plan, the frontend still renders the full Admin/Manager sidebar shell and routes for an Employee (so a 403 either crashes the page, shows nothing, or the Employee sees navigation links to sections they can never use), and the employee-scoped dashboard branch has no consumer at all (D-GATE-03 would be backend-only, unobservable). This plan makes the UI honest about what the Employee role can do and surfaces the scoped dashboard data, while keeping the real enforcement entirely server-side.

Output: Two new Svelte components (`EmployeeLayout.svelte`, `AccessDenied.svelte`), a role-based shell/route switch in `App.svelte`/`routes.ts`, symmetric 403 handling in `client.ts`, and a «Мои заявки» `StatWidget` card wired into the existing `RequestsPage.svelte` employee landing page. Zero new visual primitives — reuses existing tokens, `Button`, `ThemeSwitcher`, `StatWidget`, `pushToast`.

From ui/src/lib/api/client.ts (full file, 42 lines — current 401-only handling to extend with a symmetric 403 branch):
```ts
import { parseAppError } from './errors';
import { authStore } from '$lib/stores/auth.svelte';
const isTauri = typeof window !== 'undefined' && '__TAURI_INTERNALS__' in window;
export async function apiCall<R>(name: string, args = {}): Promise<R> {
  if (isTauri) {
    const { invoke } = await import('@tauri-apps/api/core');
    try { return await invoke<R>(name, args); }
    catch (e) {
      const err = parseAppError(e);
      if (err && typeof err === 'object' && 'code' in err) {
        const code = (err as { code: string }).code;
        if (code === 'UNAUTHORIZED' || code === 'Unauthorized') { authStore.user = null; window.location.hash = '#/login'; }
      }
      throw err;
    }
  }
  const res = await fetch(`/api/v1/${name}`, { method: 'POST', headers: {...}, body: JSON.stringify(args) });
  if (!res.ok) {
    const body = await res.json().catch(() => ({}));
    const err = parseAppError(body);
    if (res.status === 401) { authStore.user = null; window.location.hash = '#/login'; }
    // 403 → throw only (current behavior — this plan adds a toast here)
    throw err;
  }
  return res.json();
}
```
