# Phase 9 — UI Design Contract

> Visual and interaction contract for the AD-аутентификация phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Brownfield phase.** Every screen below EXTENDS an already-built screen. Reuse the existing token set in `ui/src/styles/_tokens.scss`, the existing primitives in `ui/src/lib/components/`, and the established component patterns. **Do NOT introduce new color/spacing/type tokens or new primitive components.** Where this spec names a value, it is the existing token — cited so the executor copies it, not invents it.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-rolled Svelte 5 + SCSS; no shadcn/Tailwind — confirmed: no `components.json`, no `tailwind.config.*`) |
| Preset | not applicable |
| Component library | none — local primitives in `ui/src/lib/components/` (`Button`, `Input`, `Select`, `Textarea`, `Badge`, `Modal`, `Spinner`, `Toast`) |
| Icon library | none in use — text + Badge only (no icon dependency; do not add one) |
| Font | `--font-family-base`: `-apple-system, 'Segoe UI', 'Roboto', 'Helvetica Neue', 'Arial', sans-serif` |
| Tokens source | `ui/src/styles/_tokens.scss` (auto-prepended into every `<style lang="scss">` via vite `prependData`) |
| Theming | light + dark via `[data-theme]` CSS custom props — all new SCSS MUST use `var(--…)`, never hardcoded hex |
| Language | RU-only (v1). All copy in Russian. |

**Primitive prop signatures (reuse — do not re-implement):**
- `Button`: `variant: 'primary'|'secondary'|'destructive'|'ghost'|'link'`, `size: 'sm'|'md'`, `loading`, `disabled`, `type`, `onclick`, `children`.
- `Badge`: `variant: 'default'|'accent'|'success'|'warning'|'destructive'`, `size: 'sm'|'md'`, `children`.
- `Select`: `value` (bindable), `disabled`, `invalid`, `id`, `onchange(value)`, `children` (`<option>`s).
- `Modal`: `open`, `title`, `onClose`, default slot body, `{#snippet footer()}` for action buttons.
- `Textarea`: `value`, `placeholder`, `id`, `oninput(v)`.

> Login screen does NOT use the `Button`/`Input` primitives today — it hand-rolls `.btn-submit` / `.form-input` inside `LoginPage.svelte` (a deliberate full-screen auth shell). Phase 9 keeps that local pattern for the login card and its sibling auth screens (pending/blocked) for visual consistency. New auth screens reuse `LoginPage.svelte`'s `.login-card` shell classes.

## Spacing Scale

Declared values (existing `--space-*` tokens — multiples of 4; do not add new ones):

| Token | Value | Usage |
|-------|-------|-------|
| `--space-xs` | 4px | Label↔field gap, badge gaps, inline gaps |
| `--space-sm` | 8px | Compact element spacing, button groups, checkbox↔label |
| `--space-md` | 16px | Default field spacing, card inner padding, modal body gaps |
| `--space-lg` | 24px | Section padding, settings-section padding, title↔form gap |

| `--space-2xl` | 48px | Login-card horizontal padding (existing `.login-card`) |

**Layout constants (existing):** `--modal-max-width: 640px` (approval modal), `--touch-target-min: 36px`, `--row-height: 40px` (request rows). Login/pending/blocked card: `max-width: 360px` (existing `.login-card`).

Exceptions: none. The login card already uses `--space-2xl` for horizontal padding — restoration/pending screens reuse the same `.login-card` shell so spacing is inherited, not redefined.

## Typography

Existing `--font-size-*` / `--font-weight-*` / `--line-height-*` tokens. Four sizes, three weights are already defined system-wide; this phase uses the subset below.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | `--font-size-body` 14px | `--font-weight-regular` 400 | `--line-height-body` 1.5 |
| Label | `--font-size-label` 13px | `--font-weight-medium` 500 | `--line-height-label` 1.4 |
| Heading (card/section title) | `--font-size-heading` 20px | `--font-weight-semibold` 600 | `--line-height-heading` 1.3 |
| Display | `--font-size-display` 28px | `--font-weight-semibold` 600 | `--line-height-display` 1.2 |

Phase-9 usage:
- Login / pending / blocked **card title** → `--font-size-heading` + `--font-weight-semibold` (matches existing `.login-title`).
- Settings → «Active Directory» **section titles** → `--font-size-heading` + semibold (matches `.section-title`).
- Field labels, helper text, error text, badges → `--font-size-label`.
- Body copy (pending/blocked messages, helper text, confirm bodies) → `--font-size-body` at 1.5.
- Display 28px is NOT used this phase (no full-page hero).

## Color

Existing palette from `_tokens.scss` (light values shown; dark variants auto-resolve via `[data-theme='dark']`). 60/30/10 split below describes how the existing tokens map to the dominant/secondary/accent roles — **no new colors**.

| Role | Token (light) | Usage |
|------|-------|-------|
| Dominant (~60%) | `--color-bg` #ffffff | Page background, login-screen backdrop, input backgrounds |
| Secondary (~30%) | `--color-surface` #f5f6f8 (+ `--color-surface-sunken` #eaecef) | Cards (login/pending/blocked card, settings-section), hover states, sunken rows |
| Accent (~10%) | `--color-accent` #2563eb (hover `--color-accent-hover`) | See reserved-for list below |
| Destructive | `--color-destructive` #dc2626 | «Отклонить» action + reject-confirm modal button; destructive confirmation copy |
| Success | `--color-success` #16a34a | Confirmation/success badges + success toasts (request approved, restore submitted) |
| Warning | `--color-warning` #d97706 | `in_progress` status badge (existing requests convention); not introduced this phase |
| Borders / text | `--color-border`, `--color-text-primary/secondary/muted/inverse` | Field borders, body/label/muted text |

**Accent (`--color-accent`) reserved EXACTLY for:**
1. Primary submit button («Войти», «Сохранить настройки», «Подтвердить» in approval modal, «Отправить запрос на восстановление»).
2. The enabled-state of the «Использовать Active Directory» toggle (accent fill when ON — matches existing checkbox `accent-color: var(--color-accent)` and active-tab `color-mix(--color-accent 10%)`).
3. `open` request status Badge (`variant="accent"` — existing requests convention; the `ad_register` badge follows it).
4. Focus rings (`--color-accent-focus`, global `:focus-visible`).
5. Selected list-row left border + tint (existing `.row.selected` pattern) for the selected `ad_register` request.

Accent is NOT used for: body text, secondary buttons, the reserved (disabled) SSO button area, helper text, or decorative fills. Secondary actions use `Button variant="secondary"` (neutral surface). The reserved SSO button area renders visually muted/disabled (see Screen 1) — never accent.

## Screen Contracts

Each screen below names the file it extends, the states it must render, and the reused primitives/classes. The executor builds against this; the checker validates against it.

### Screen 1 — Redesigned login form
**Extends:** `ui/src/features/auth/LoginPage.svelte` (keep `.login-container` / `.login-card` shell, `.login-title`, `.form-field`, `.form-input`, `.field-error`, `.server-error`, `.btn-submit` classes).
**Changes / states:**
- Single credentials block: `Логин` + `Пароль` + `Войти` (existing). Server does local→AD fallback transparently — UI sends one `auth_login` call, no auth-type selector (D-UX-01).
- Add **«Запомнить меня»** checkbox below the password field, above the submit button. Style per existing `.checkbox-label` pattern from `NetworkSettings.svelte` (16px box, `accent-color: var(--color-accent)`, `--space-sm` gap). Sends `remember: boolean` to the login call (persistent vs session cookie — D-UX-02).
- Add **format hint** helper text under the login field (`--font-size-label`, `--color-text-muted`): `Логин: us100, user@domain или DOMAIN\user`.
- **Error state:** generic `Неверный логин или пароль` in `.server-error` block for all credential/account failures. AD-unreachable → distinct `.server-error` copy (see contract). No field-level enumeration.
- **Reserved SSO area (visual only, NO logic — D-UX-03):** below the submit button, a disabled/muted full-width button placeholder shaped like the future «Войти как <display name>». Rendered with `disabled`, muted text (`--color-text-muted`), neutral surface (`--color-surface-sunken`), NOT accent. Either visually present-but-disabled OR omitted behind a build flag — executor's discretion, but if present it must be visibly non-interactive and carry no click handler. Do not show a fabricated display name; if shown, label it `Вход по учётной записи Windows (скоро)`.
- Loading: submit shows `Вход…`, inputs `disabled` (existing).

### Screen 2 — Pending screen (auto-accept OFF)
**Extends:** reuse `.login-container` + `.login-card` shell from `LoginPage.svelte` (same centered 360px card).
**States:** single informational state.
- Heading (`.login-title` style): `Заявка отправлена`.
- Body paragraph (`--font-size-body`, `--color-text-secondary`, line-height 1.5): pending body copy.
- Secondary action: `Войти под другим пользователем` rendered as `Button variant="link"` or text-link → returns to login form (clears session/credentials, shows Screen 1).
- No primary/accent CTA (purely informational). No spinner (it is a terminal wait state, not loading).

### Screen 3 — Blocked / removed-user screen
**Extends:** same `.login-card` shell (centered 360px card).
**States — TWO:**
1. **Blocked (default):**
   - Heading: `Доступ закрыт`.
   - Body: blocked body copy.
   - Primary CTA (accent, `.btn-submit` style): `Запросить восстановление доступа` (loading `Отправка…`).
   - Secondary: `Войти под другим пользователем` (link → back to Screen 1).
2. **Restore submitted (confirmation):** after the restore request succeeds, replace card body in place:
   - Heading: `Запрос отправлен`.
   - Body: restore-submitted copy.
   - Secondary only: `Войти под другим пользователем`.
   - Success toast `Запрос на восстановление отправлен` on submit (existing Toast/`pushToast` pattern).
- Error on submit failure → `.server-error` block, generic retry copy.

### Screen 4 — Settings → «Active Directory» tab
**Extends:** add a new section to `ui/src/features/settings/SettingsSubNav.svelte` (`SECTIONS` array) — insert `{ key: 'ad', label: 'Active Directory' }` — and a new component `ui/src/features/settings/ActiveDirectorySettings.svelte` mirroring `NetworkSettings.svelte` structure (`.network-settings` → `.ad-settings` wrapper at `max-width: 640px`, `.settings-section` cards, `.section-title`, `.checkbox-label`, `.helper-text`, `.form-grid`/`.form-field`, `.save-row`).
**Layout (top→bottom inside a single `.settings-section` card, or two cards):**
1. **Enable toggle:** checkbox `Использовать Active Directory` (existing `.checkbox-label` pattern) + helper text. When OFF, the rest of the form is disabled/dimmed (`opacity: 0.6` per existing disabled convention).
2. **Registration mode:** two radio options (`Автоматически принимать` / `Требовать подтверждения`) each with helper text. Use native radios styled with `accent-color: var(--color-accent)` (consistent with checkbox styling) OR a `Select` — radios preferred for two mutually-exclusive labelled options with descriptions.
3. **«Расширенные настройки» collapsible:** native `<details>`/`<summary>` (no new component) OR a toggle-driven block; collapsed by default. Helper text explaining auto-detect-first. Inside, a `.form-grid` (existing 2-col grid, `--full` for wide fields): host:port, домен, Base DN, атрибут ФИО (default `displayName`), and the `Не проверять TLS-сертификат (небезопасно)` checkbox.
4. **Actions row** (`.save-row`): `Сохранить настройки` (primary) + `Проверить подключение` (secondary). Connection test feedback via toast (success/error copy in contract); button shows `Проверка…` while testing. If a connection-test endpoint is not delivered this phase, render the button `disabled` with helper `Доступно после сохранения` — but prefer shipping it.
- All loads/saves use the existing `apiCall` + `pushToast` pattern from `NetworkSettings.svelte`. Settings persist server-side (`app_settings`).

### Screen 5 — Requests: admin-only `ad_register`
**Extends:** `ui/src/features/requests/RequestListRow.svelte`, `RequestDetail.svelte`, and the list filtering in `RequestsMasterDetail.svelte` / `RequestsList.svelte`.
**Visibility:** `ad_register` rows render ONLY for `identity.role === 'admin'` (REQ-06). Non-admins never see them (filter at list level; do not rely on row-level hide alone).
**Row (`RequestListRow.svelte`):**
- Extend `typeLabel` derivation: `ad_register` → `Регистрация AD`. Use `Badge variant="default" size="sm"` (existing type-badge slot).
- Restore variant (D-REG-03 sub-flag): show an additional small chip/badge `Восстановление доступа` (use `Badge variant="warning" size="sm"` to distinguish from first-time register) when the request is a restore.
- `shortDesc` → requested ФИО (display name from AD).
- Status badge unchanged (existing `accent`/`warning`/`success`/`default` mapping; `open` → accent).
**Detail (`RequestDetail.svelte`):**
- Render `ad_register` info fields: ФИО, логин, тип (`Регистрация` / `Восстановление доступа`).
- Admin actions when `status === 'open'`:
  - `Подтвердить` (primary/accent) → opens **approval modal** (Screen 5b).
  - `Отклонить` (destructive) → opens existing reject-confirm `Modal` with the appropriate destructive copy (pending vs auto-register-delete vs restore — see Destructive table).
- Reuse the existing lifecycle section structure, `.actions` flex row, and history section (REQ-07) unchanged.

### Screen 5b — Approval modal
**Extends:** reuse `Modal` primitive (`--modal-max-width` 640px) and the footer-snippet button pattern from `RequestDetail.svelte`'s reject modal.
- Title: `Подтвердить регистрацию` (restore: `Восстановить доступ`).
- Body: `Пользователь <ФИО> получит доступ к системе с выбранной ролью.`
- **Role `Select`** (existing primitive): label `Роль`, options `Сотрудник` (default/selected) · `Специалист` · `Администратор`. Default MUST be `Сотрудник` (D-REG-02).
- Footer: `Отмена` (secondary) + `Подтвердить` (primary, loading `Подтверждение…`).
- Success → `pushToast('success', 'Пользователь подтверждён')` (restore: `Доступ восстановлен`), close modal, refresh list (`onTransition` pattern).
