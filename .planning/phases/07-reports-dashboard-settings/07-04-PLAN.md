<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Logo file bytes from browser | User uploads a file via input[type=file]; bytes flow to backend for size/MIME validation |
| Template body textarea | User-editable MiniJinja template; must never be rendered in browser — only sent to backend for validation |
| DB path (browser move flow) | Not available in browser context; enforced by UX guard (show error) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04-01 | Tampering | OrgSettings logo upload | mitigate | Frontend checks file.size <= 512*1024 before sending; backend enforces same limit (defense in depth per RESEARCH Pitfall 3); MIME validated frontend + backend |
| T-07-04-02 | Tampering | TemplateEditor — MiniJinja template body | mitigate | Template body sent to backend endpoint for validation (never eval'd in browser); backend uses build_safe_env() with fuel limit and strict mode |
| T-07-04-03 | Tampering | StorageSettings DB move | mitigate | Requires Tauri desktop context (not available in browser); user must confirm via modal; backend validates UNC rejection and integrity_check |
| T-07-04-04 | Information Disclosure | BackupSettings backup folder path | accept | Backup folder path is org sysadmin data; stored in app_settings (same trust level as other settings); not exposed to lower-privilege roles |
| T-07-04-05 | Tampering | XSS via SVG logo display | mitigate | Logo bytes served as data: URL in <img src="data:image/..."> — NOT injected as raw HTML/SVG markup; SVG only rendered in <img> context which blocks scripts |
| T-07-04-SC | Tampering | npm/pip/cargo installs | accept | No new npm packages; tauri-plugin-dialog already in package.json |
</threat_model>
