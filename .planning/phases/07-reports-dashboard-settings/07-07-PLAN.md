<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP /api/v1/reports_* | LAN browser users can call these; session_identity check required for all |
| HTTP /api/v1/settings_* write endpoints | Must require ManageSettings role (admin only) |
| Tauri commands | Desktop context — trusted; desktop identity used for mutations |
| DB path move | Only available via Tauri (not HTTP) — DB path must never be settable from web |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07-01 | Elevation of Privilege | HTTP settings mutation endpoints | mitigate | All write /api/v1/org_*, /api/v1/backup_*, /api/v1/templates_update call authorize(&caller, &Action::ManageSettings)?; non-admin session gets 403 |
| T-07-07-02 | Injection | SQL injection via report filters on HTTP | mitigate | HTTP handlers call same build_* helpers → same ReportService parameterized SQL (plan 03); no filter value ever concatenated into SQL string |
| T-07-07-03 | Tampering | DB move via HTTP | mitigate | settings_move_db is Tauri-only command (not registered in HTTP router); LAN browser users cannot trigger DB move |
| T-07-07-04 | Tampering | Supervisor duplicate task claim via race | mitigate | Atomic UPDATE WHERE status!='running'; rows_affected=0 → skip; tauri-plugin-single-instance prevents dual process (Phase 1) |
| T-07-07-05 | Information Disclosure | Backup file listing in retention cleanup | accept | Backup folder is admin-chosen; file listing only reads filenames matching trackly-backup-*.db pattern; no exposure to HTTP layer |
| T-07-07-SC | Tampering | npm/pip/cargo installs | accept | No new packages in this plan; all wiring uses existing workspace deps |
</threat_model>
