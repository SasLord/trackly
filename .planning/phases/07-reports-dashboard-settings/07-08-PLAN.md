  <action>
    Diagnose the runtime error in get_consumption_chart:

    Step 1 — Check column order mismatch: The SQL SELECT order is "model_label, month_key, installs"
    but ConsumptionPoint field order is { month_key, model_label, installs }. The rusqlite
    query_map assigns columns positionally (r.get(0) → model_label, r.get(1) → month_key,
    r.get(2) → installs). Verify this matches the struct population code:
      model_label: r.get(0)?,
      month_key: r.get(1)?,
      installs: r.get(2)?,
    If the struct init puts month_key first but get(0) is model_label, this is a
    positional mismatch — swap to assign by SQL column position, not struct field order.

    Step 2 — Check JOIN NULL issue: The query INNER JOINs cartridges + cartridge_models.
    If any cartridge in audit_log has a NULL model_id, the INNER JOIN silently drops it —
    this should not cause an error but could cause an empty result. Verify with LEFT JOIN
    if any error originates from NULL model_label.

    Step 3 — Check rusqlite type coercion: installs is i64 in Rust but COUNT(*) in SQLite
    returns INTEGER which maps cleanly to i64. month_key uses strftime which returns TEXT.
    If any row has NULL month_key (e.g., NULL created_at_utc), r.get::<_, String>(1)? will
    fail with a type error.

    Apply the fix identified by diagnosis:

    Most likely fix (column order): In the query_map closure, ensure the positional assignments
    match the SELECT column order. The SELECT is "model_label, month_key, installs":
      - r.get(0) → model_label (String)
      - r.get(1) → month_key (String)
      - r.get(2) → installs (i64)
    The ConsumptionPoint struct init must use this same order regardless of struct field
    declaration order.

    If month_key can be NULL (strftime on NULL timestamp): change r.get::<_, String>(1)?
    to r.get::<_, Option<String>>(1)?.unwrap_or_default() and filter out empty month_keys,
    OR add WHERE al.created_at_utc IS NOT NULL to the query.

    After fixing, write or update the dashboard_widgets integration test to assert that
    get_consumption_chart returns Ok([]) for an empty DB (no install events) — confirming
    no error for the zero-rows case.
