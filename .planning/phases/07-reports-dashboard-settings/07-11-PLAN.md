<objective>
Fix two Settings UX gaps: missing vertical spacing between section cards (GAP-S1), and
the page being one uninterrupted scroll (GAP-S2).

GAP-S1: The .settings-content container in SettingsPage.svelte has no gap/margin applied
between the child section components (NetworkSettings, OrgSettings, etc.). Add consistent
vertical gap.

GAP-S2: Add a SettingsSubNav switch-bar at the top of the Settings page. Each tab
corresponds to a settings subsection. Clicking a tab scrolls to that section OR shows
only that section (simpler approach). The simpler approach (show/hide sections) avoids
needing scroll-into-view and is consistent with other switch-bar patterns in the app.

The subsections are:
- Сеть (NetworkSettings)
- Организация (OrgSettings)
- Хранилище (StorageSettings)
- Бэкапы (BackupSettings)
- Порог остатка (ThresholdSettings)
- Шаблоны (TemplateEditor)

Purpose: Pure frontend UX fix. No Rust changes, no new API calls.

Output: New SettingsSubNav.svelte component + updated SettingsPage.svelte.
</objective>

    Step 1 — Create ui/src/features/settings/SettingsSubNav.svelte:

    A simple switch-bar component. Props:
      activeSection: string;
      onSectionChange: (_s: string) => void;

    Sections array (match the component render order in SettingsPage):
      [
        { key: 'network', label: 'Сеть' },
        { key: 'org', label: 'Организация' },
        { key: 'storage', label: 'Хранилище' },
        { key: 'backup', label: 'Бэкапы' },
        { key: 'threshold', label: 'Порог остатка' },
        { key: 'templates', label: 'Шаблоны' },
      ]

    Template: a <nav class="settings-sub-nav"> containing <button class="tab"> elements
    per section. Apply class:active when section.key === activeSection. On click, call
    onSectionChange(section.key). Follow the tab/active SCSS pattern from ReportSubNav
    (border, border-radius, accent background on active, height 32px). Add
    role="tablist" to nav and role="tab" + aria-selected to buttons.

    SCSS for SettingsSubNav: minimal — .settings-sub-nav { display: flex; gap: 2px;
    flex-wrap: wrap; } .tab { ... (match ReportSubNav .tab style) }.

    Step 2 — Update ui/src/pages/SettingsPage.svelte:

    Add import SettingsSubNav.
    Add $state activeSection = 'network' (default to first section).

    In template: add <SettingsSubNav {activeSection} onSectionChange={(s) => activeSection = s} />
    as the first child inside .settings-content.

    Below the sub-nav, conditionally render only the active section:
      {#if activeSection === 'network'}
        <NetworkSettings />
      {:else if activeSection === 'org'}
        <OrgSettings />
      {:else if activeSection === 'storage'}
        <StorageSettings />
      {:else if activeSection === 'backup'}
        <BackupSettings />
      {:else if activeSection === 'threshold'}
        <ThresholdSettings />
      {:else if activeSection === 'templates'}
        <TemplateEditor />
      {/if}

    GAP-S1 fix — .settings-content: Add gap: var(--space-lg) to the existing .settings-content
    rule. This applies to the sub-nav + section component. The sub-nav sits above the
    section with a natural gap. Additionally, on each section component SCSS (they each have
    their own .settings-section class), ensure there is no explicit margin: 0 that overrides.
    Since all section components use their own .settings-section with border-radius card
    styling, the parent gap handles spacing. No per-component changes needed for GAP-S1.

    Update the .page-title header style if needed: keep the page-header as-is, only the
    .settings-content needs gap added.

    Keep the existing .settings-content SCSS: flex: 1; overflow: auto; padding:
    var(--space-lg) var(--space-xl); — add gap: var(--space-lg) to it.
    Also change .settings-content from implicit flow to flex-direction: column for
    explicit gap application: add display: flex; flex-direction: column; gap: var(--space-lg);
    to the existing .settings-content class.
