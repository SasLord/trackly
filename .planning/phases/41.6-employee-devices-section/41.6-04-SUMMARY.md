# Phase 41.6 Plan 04: Предзаполнение формы заявки Summary

RequestFormModal принимает необязательный `prefill` (тип + deviceId), предзаполняет тип и устройство/принтер после сброса при открытии и отдаёт `joined` в `onSuccess`; порядок «сброс, затем prefill» и подавление тоста закреплены гейтом с мутацией-перестановкой.

## Сделано

- Props: `prefill?: { type: 'repair' | 'cartridge_replace'; deviceId: number }`, `onSuccess({ id, status, joined? })`.
- В блоке открытия после сброса и запуска загрузок: `requestType = pf.type`, затем `applyRepairPrefill` (после `await loadRepairDevices()`, с проверкой свежести загрузки и счётчика открытий; `repairChoice` ставится только если устройство есть в списке) или `applyPrinterPrefill` (после `loadPrinters()`, только если принтер есть в списке). Если нет в списке, поле пустое, штатная ошибка формы. Фокус в режиме prefill уходит в поле описания.
- `loadRepairDevices` теперь возвращает `true`, если ответ актуален (раньше ничего не возвращал); присваивание под `gen === repairLoadGen` не тронуто.
- Тосты успеха под `if (!prefill)`. Ремонт передаёт `onSuccess({ ...res.request, joined: res.joined })`. `RequestsPage.svelte` не менялся.
- Гейт `check-request-prefill.mjs` (P1-P6) с `--selftest` на 5 мутантах (перестановка prefill выше сброса, нет ветки cartridge, тост без охраны, нет joined, страница передаёт prefill), подключён в `lint` после `check-request-flow`.
