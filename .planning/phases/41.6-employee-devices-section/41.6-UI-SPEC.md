# Phase 41.6 — UI Design Contract

> Визуальный и интеракционный контракт фазы «Раздел „Устройства“ для сотрудника»: вкладки
> «Заявки» / «Устройства» в шапке `EmployeeLayout` со счётчиком непрочитанного, плоский список
> устройств сотрудника (таблица на широком экране, плитки на узком), меню строки (кебаб + правый
> клик), карточка устройства только для чтения, заявка из строки с предзаполнением и тост со
> ссылкой. Составлен gsd-ui-researcher (режим `--auto`, вопросов пользователю не задавалось),
> проверяется gsd-ui-checker.
>
> **Макета нет.** Дизайн-система зафиксирована Фазой 23 (`ui/src/styles/_tokens.scss`, гейты
> `ui/scripts/check-tokens.mjs` и `check-contrast.mjs`), брейкпоинты — Фазой 26
> (`ui/src/styles/_breakpoints.scss`), примитивы — Фазами 24–25, a11y — Фазой 30, меню строки —
> Фазой 41.1, пометка происхождения принтера — Фазой 41.13, счётчик непрочитанного — Фазой 41.5.
> Документ **не переоткрывает** ни токены, ни решения `41.6-CONTEXT.md` (D-01…D-21, включая
> уточнения D-04, D-07, D-11, D-19 от 2026-11-20), ни критерии ROADMAP. Новых токенов, hex'ов,
> шкал и npm-зависимостей — **ноль**.
>
> **Приватность (жёсткое условие, репозиторий публичный):** все примеры вымышленные —
> «Иванов И.И.», «АРМ #1», «АРМ #2», «Корпус 1 / Этаж 2 / Каб. 204», «Принтер 2-го этажа»,
> «заявка №42», инв. № «000123», серийный «SN-0001». Реальные ФИО, названия организации,
> рабочих мест, кабинетов и данные из живой БД в код, копирайт, тесты, фикстуры, скриншоты UAT и
> `.planning/`-артефакты не попадают.

персонал и десктоп раздел не видят (сервер для них вернёт пустой список — это не ошибка UI).

## 2. Границы: что контракт НЕ покрывает

- Поиск, фильтры, сортировка по колонкам — **нет** (D-06; deferred). Порядок задаёт сервер:
  по типу, затем по наименованию. Клиент не пересортировывает.
- Группировка по АРМ, дерево мест, раскрытие состава — **нет** (D-04: плоский список).
- История перемещений и актов, IP, community, SNMP-серийники, имя USB-хоста — **нет** (D-16, D-17).
- Правка устройств, заявка «Другое» из строки — **нет** (deferred).
- Выбор строки (selected-подсветка, мастер-деталь) — **нет**: карточка открывается модалкой.
- Права — серверные (D-14). Скрытие пунктов меню в UI — удобство, не защита.

| `--tr-space-md` | 16px | горизонтальный padding плитки; горизонтальный padding шапки и `page-content` на узком экране; зазор между секциями плитки |

| Величина | Где | Обоснование |

## 4. Typography

Шкала Фазы 23 (9 ролей + mono) не меняется. Задействованные роли:

| Роль | Токен | Размер/Вес/LH | Где в Фазе 41.6 |
|------|-------|----------------|------------------|
| Заголовок страницы | `--tr-font-size-h3` | 20px/600/1.3 | «Устройства» в `PageHeader` (унаследовано); «Trackly» в шапке (унаследовано) |
| Текст | `--tr-text-body` | 14px/400/1.5 | ячейки таблицы; текст вкладки (неактивная); значения полей карточки; тело пустого состояния |
| Текст · акцент | `--tr-text-body-strong` | 14px/600/1.5 | **имя устройства в плитке**; заголовок пустого состояния/ошибки (унаследовано `Table`) |
| Подпись | `--tr-text-label` | 13px/500/1.4 | заголовки колонок (унаследовано `Table`); активная вкладка (вес 500); «Тип · Модель» в плитке; значения в плитке; подписи полей карточки (унаследовано `DetailField`); процент тонера в карточке (`TonerGauge`) |
| Мелкий | `--tr-text-caption` | 12px/500/1.35 | процент в компактном индикаторе тонера; подписи «Инв. №», «Место» в плитке; подсказка под пунктом меню (§10.3); дата опроса тонера; итог «Устройств: N» в футере таблицы; дата заявки в карточке |
| Микро | `--tr-text-micro` | 11px/500/1.3 | число в `UnreadBadge` на вкладке; текст `Badge size="sm"` (заявка, происхождение) |
| Моно | `.tr-mono` 13px | — | инв. №, серийный №, номер заявки в метке |

**Правила:**
- Ячейки таблицы — одна строка, `white-space: nowrap; overflow: hidden; text-overflow: ellipsis;`
  полный текст — в `title` ячейки (как `DeviceListRow`).
- Плитка и карточка переносят текст (`white-space: normal; overflow-wrap: anywhere;`), явно
  заданный на корне — карточка-модалка рендерится на уровне страницы, **не внутри `<td>`**
  (память «Modal наследует стили ячейки таблицы»), и всё равно задаёт `text-align: left`.
- Даты — локальное время, `formatDateTimeShort` из `ui/src/lib/utils/date.ts` (`дд.ММ.гггг ЧЧ:мм`).
- Проценты — `font-variant-numeric: tabular-nums`.
- **Унаследованное отступление:** шкала проекта использует три веса (400 / 500 / 600); она
  закрыта Фазой 23, фаза не добавляет ни одной роли и ни одного веса.

## 5. Color: 60/30/10

Новых токенов и пар light/dark фаза не вводит.

| Роль | Токен | Использование в Фазе 41.6 |
|------|-------|----------------------------|
| Доминанта (60%) | `--tr-surface-raised` / `--tr-surface` | фон таблицы (рамка `Table`), фон плиток, фон карточки-модалки, фон шапки и `PageHeader` (унаследовано) |
| Вторичная (30%) | `--tr-bg` | фон `employee-shell` и `page-content` — подложка, на которой лежат таблица/плитки |

| Границы | `--tr-border` / `--tr-border-strong` | рамка плитки 1px `--tr-border`; рамка трека индикатора 1px `--tr-border`; разделители строк (унаследованы `TableRow`) |
| Текст | `--tr-text-primary` / `-secondary` / `-tertiary` | значения / неактивная вкладка, «Тип · Модель», иконка принтера / подписи полей в плитке, «—», дата опроса |
| Акцент (10%) | `--tr-accent`, `-soft`, `-text`, `--tr-focus-ring` | **строго список ниже** |
| Предупреждение / опасность | `--tr-warning`, `--tr-danger` | **только** заливка индикатора тонера 10–24% / < 10% (порог `TonerGauge`, без изменений) |
| Деструктив | — | деструктивных действий в фазе **нет**; `--tr-danger-text` — только текст ошибки загрузки в `role="alert"` |

**Акцент зарезервирован строго за:**
1. активной вкладкой шапки (фон `--tr-accent-soft`, текст `--tr-accent-text`, нижняя полоса
   3px `--tr-accent`);
2. счётчиком непрочитанного на вкладке «Заявки» (`UnreadBadge` = `Badge solid accent sm`,
   унаследовано 41.5);
3. меткой-ссылкой «Заявка №N» (`Badge variant="accent" appearance="soft" size="sm"` внутри `<a>`,
   прецедент — бейдж-ссылка якоря в `DeviceListRow`);
4. primary-кнопкой «Заявка на ремонт» / «Перейти к заявке №N» в футере карточки;
5. ссылкой «Открыть заявку» в тосте (унаследовано `Toast`);
6. заливкой индикатора тонера ≥ 25% (унаследованный порог `TonerGauge`);
7. бейджем происхождения `USB` (унаследовано 41.13 §3.1) и тоном статуса «В работе»
   (унаследовано `statusTone`);
8. focus-ring (глобальный, не переопределяется).

Акцент **не** используется: для имён устройств, иконки принтера, бейджей `Ссылка` / `В составе`,
метки чужой заявки «Есть заявка», кебаба, плиток, подписей полей.

## 6. Вкладки в шапке сотрудника (D-01…D-03)

### 6.1 Анатомия

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ Trackly   [ Заявки (2) ] [ Устройства ]        Иванов И.И. Сотрудник ◐ Выйти │
└─────────────────────────────────────────────────────────────────────────────┘
           ↑ 24px от бренда                         (правая группа без изменений)
```

- Левая группа шапки: `<span class="employee-brand">Trackly</span>` + `<nav aria-label="Разделы">`,
  `display:flex; align-items:center; gap: var(--tr-space-xl)`.
- Внутри `nav` — две ссылки-вкладки `<a href="#/requests">Заявки</a>`, `<a href="#/devices">Устройства</a>`,
  `gap: var(--tr-space-2xs)`. Порядок фиксирован: «Заявки», затем «Устройства».
- Вкладка: `display:inline-flex; align-items:center; gap: var(--tr-space-xs); height: 36px;
  padding: 0 var(--tr-space-sm); border-radius: var(--tr-radius-sm);` текст 14px/400
  `--tr-text-secondary`, без подчёркивания.
- Hover: `background: color-mix(in srgb, var(--tr-text-primary) 5%, transparent); color: var(--tr-text-primary)`
  (как `.nav-link` сайдбара).
- **Активная:** `background: var(--tr-accent-soft); color: var(--tr-accent-text);
  font-weight: var(--tr-font-weight-medium); box-shadow: inset 0 -3px 0 var(--tr-accent);`
  плюс `aria-current="page"`.
- Активность — по текущему маршруту через `svelte-spa-router/active` с тем же шаблоном, что у
  сайдбара (`sidebarActivePattern(route)` из `sidebar-config.ts`), чтобы `#/requests?id=42&tab=chat`
  оставлял активной «Заявки». Если гейт `ui/scripts/check-sidebar-active.mjs` сканирует только
  сайдбар — расширить его область на `EmployeeLayout` или добавить отдельную проверку (решает
  планировщик; вакуумный проход недопустим).
- Focus-visible: `outline:none; box-shadow: inset 0 0 0 2px var(--tr-focus-ring)` (как `.nav-link`).

### 6.2 Счётчик (D-03)

- Справа от текста «Заявки»: `<UnreadBadge count={unreadStore.requestsWithUnread} label="Заявок с непрочитанным" />`.
- Ноль — счётчика нет (поведение `UnreadBadge`); > 99 — «99+». Счётчик виден на обеих вкладках
  (и когда активна «Устройства»).
- Источник — уже запущенный в `EmployeeLayout.onMount` `startChatRealtime()`; второй подписки нет.
- Accessible name вкладки: «Заявки» + `aria-label` бейджа «Заявок с непрочитанным: 2».

### 6.3 Узкий экран

- `@media (max-width: 559px)` (`bp.$bp-sm`): `.user-name` и `.user-role` скрываются
  (`display:none`), padding шапки `0 var(--tr-space-md)`, зазор бренд—вкладки `var(--tr-space-sm)`.
  Вкладки, переключатель темы и «Выйти» остаются; вкладки **не** сворачиваются в меню.
- Шапка остаётся 56px (`--header-height`); перенос на вторую строку недопустим — при нехватке
  места первым скрывается бренд «Trackly» на ширине < 400px (`@media (max-width: 399px)`).

## 7. Страница раздела

### 7.1 Каркас и прокрутка

```
EmployeeLayout .employee-content (flex:1; min-height:0)
└─ .employee-devices-page   display:flex; flex-direction:column; height:100%; min-height:0
   ├─ PageHeader title="Устройства"           (без actions)
   └─ .page-content   flex:1; min-height:0; display:flex; flex-direction:column;
```

  плиток. Страница и `.employee-content` двойного скролла не дают (память `app_shell_scroll_pattern`).
  `.employee-content` остаётся `overflow:auto` ради «Заявок»; новая страница его не использует,
  потому что сама занимает `height:100%`.
- На `< 768px` padding `.page-content` — `var(--tr-space-md)` со всех сторон.
- Заголовок `PageHeader` повторяет прецедент `RequestsPage` (тот же компонент у сотрудника).

### 7.2 Футер таблицы

`Table footer`: подпись 12px `--tr-text-secondary` «Устройств: 7». В режиме плиток — та же
подпись под списком плиток, `padding-top: var(--tr-space-xs)`.

## 9. Взаимодействие со строкой (D-09)

Повторяет модель `DeviceListRow` (41.1) с собственным набором пунктов.

| Действие | Результат |
|----------|-----------|
| Двойной клик по строке | открывает карточку (§13). Двойной клик по кебабу, ссылке-метке, кнопке — **не** открывает (`closest('button, a')`) |
| Правый клик по строке | `preventDefault()` и меню у курсора (`ActionMenu.openAt(x, y)`) — то же меню, что у кебаба |
| Правый клик по ссылке-метке «Заявка №N» | меню строки (не родное меню браузера) — единообразно со всей строкой |
| Кебаб | то же меню, якорь — кнопка |
| Одинарный клик | ничего (выбора строки нет); по метке — переход к заявке |
| Enter на первой ячейке | карточка |
| Shift+F10 / клавиша ContextMenu на первой ячейке | меню, якорь — первая ячейка (`openFromElement`) |
| Tab | первая ячейка строки → метка-ссылка (если есть) → кебаб → следующая строка |

- Первая ячейка — единственная точка фокуса строки: `<td role="button" tabindex="0"
  aria-haspopup="menu">`. **Focus-ring — inset-кольцо только на первой ячейке** (глобальное
  правило `TableRow`, память `table_focus_ring_decision`); кольцо на всю строку не делать.
- Охрана порядка: `if (isRowOverlayEvent(e.target)) return;` — **первым** оператором в
  `oncontextmenu`/`ondblclick`/`onkeydown`, до `preventDefault()` (память `counting_gate_blind_to_order`).
  Предикаты `isRowOverlayEvent` / `isOwnKeyEvent` переиспользуются из `devices/deviceRowMenu.ts`
  (модуль без импортов — employee-замыкание чистое). Привязку `ondblclick=` на строке проверяет
  гейт `check-device-row-menu`: прочесть его область до разметки и расширить на новые файлы,
  а не обходить.
- Модалки (карточка, форма заявки) рендерятся **на уровне страницы**, одним экземпляром, не внутри
  строки: тогда родное контекстное меню внутри полей формы сохраняется естественно.
- Кебаб в таблице виден **всегда** (не только при наведении): аудитория раздела — сотрудники, часто
  с сенсорных устройств.

## 11. Метка открытой заявки (D-07)

Рендерится в первой ячейке после имени (и в плитке — в строке статуса), учитывает открытые
заявки «Ремонт» и «Замена картриджа».

| Случай | Вид | Поведение |
|--------|-----|-----------|
| Открытая заявка, где сотрудник автор/участник | `<a href={requestTargetHref(N,'info')}>` + `Badge variant="accent" appearance="soft" size="sm"` с текстом «Заявка №42» (номер — `.tr-mono`) | клик — переход в «Заявки» с открытой заявкой; `aria-label` / `title` «Открыть заявку №42» |

| Нет открытых | ничего | — |

## 12. Компактный индикатор тонера (D-18)

Колонка «Тонер» (таблица) и строка статуса плитки; только у принтеров.

```
[████░░░░] 12%        ← трек 32×8px, радиус --tr-radius-xs, рамка 1px --tr-border; 4px; процент 12px tabular
```

- Значение — **минимальный** известный уровень среди цветов последнего опроса (encoding percent,
  `< 0` = неизвестно). Цвет заливки — те же пороги, что `TonerGauge`: ≥ 25% `--tr-accent`,
  10–24% `--tr-warning`, < 10% `--tr-danger`. Функцию порога выносить в общий чистый хелпер
  (`tonerFillColor(pct)` рядом с `TonerGauge`) и звать из обоих мест — один источник формулы.
- `role="img"` и `aria-label`/`title`: «Тонер: минимум 12% (Пурпурный) · опрос 19.11.2026 14:05».
- Уровни всех цветов неизвестны: трек пустой `--tr-surface-sunken`, текст «—», `title` «Уровень тонера неизвестен».
- Опросов не было: только «—» без трека, `title` «Нет данных опроса».
- Не принтер: пустая ячейка (без «—», чтобы не шуметь в колонке).

## 14. Заявка из строки (D-12, D-13)

### 14.1 Предзаполнение формы

`RequestFormModal` получает необязательный проп `prefill?: { type: 'repair' | 'cartridge_replace';
deviceId: number }`. Применяется внутри существующего reset-блока открытия **после** сброса:
- `repair` → тип «Ремонт», загрузка списка устройств формы, выбрано устройство `deviceId`;
- `cartridge_replace` → тип «Замена картриджа», после загрузки принтеров выбран `deviceId`.

Тип и устройство остаются изменяемыми (D-12). Фокус после открытия — в поле описания (тип и
устройство уже выбраны). Если `deviceId` нет в списке формы (гонка) — поле пустое, у поля
существующая ошибка формы; дополнительного текста нет. Без `prefill` форма ведёт себя как сейчас
(единственный прежний вызывающий — `RequestsPage`).

### 14.2 Тост после создания

Форма в режиме `prefill` **не** показывает собственный тост «Заявка отправлена» (один тост, а не
два) — либо проп `suppressToast`, либо расширенный `onSuccess({ id, status, joined })`; выбор за
планировщиком. Страница показывает:

| Исход | Тост | Ссылка |
|-------|------|--------|
| Создана новая заявка | `success` «Заявка №42 создана» | «Открыть заявку» → `requestTargetHref(42, 'info')` |
| Присоединился к открытой ремонтной | `success` «Вы присоединились к заявке №42» | «Открыть заявку» → `requestTargetHref(42, 'info')` |

Пользователь остаётся в «Устройствах»; список перечитывается, метка §11 появляется в строке.
Ошибки формы (403 «устройство вне области», валидация) — без изменений, их показывает форма.

### 16.3 Взаимодействие
- Тело плитки — `role="button" tabindex="0" aria-haspopup="menu"`; **одинарный** клик/тап по
  телу открывает карточку (выбора строки нет, двойной тап на мобильных конфликтует с масштабом);
  двойной клик мышью открывает её же один раз (открытие идемпотентно).
- Кебаб (`ActionMenu variant="ghost-md"`, 36×36) — то же меню; клик/тап по кебабу и меткам
  карточку не открывает.
- Долгое нажатие (событие `contextmenu`, где браузер его шлёт) и правый клик — меню у точки, с той
  же охраной, что в строке (§9).
- Enter — карточка; Shift+F10 / ContextMenu — меню. Focus — глобальное кольцо `*:focus-visible`
  вокруг плитки (не переопределяется).

## 20. Доступность

- Вкладки — обычные ссылки в `nav aria-label="Разделы"`, активная — `aria-current="page"`;
  порядок Tab: бренд не фокусируется → «Заявки» → «Устройства» → правая группа.
- Таблица — `aria-label="Мои устройства"`; первая ячейка строки — `role="button"`,
  `aria-haspopup="menu"`, accessible name = наименование устройства.
- Меню — `role="menu"`/`menuitem` (унаследовано `ActionMenu`), Esc закрывает и возвращает фокус
  на источник (кебаб или первая ячейка).
- Индикатор тонера — `role="img"` с полным `aria-label`; полосы карточки — `role="progressbar"`
  (унаследовано `TonerGauge`).
- Цвет никогда не единственный носитель смысла: процент тонера текстом, статус — подписью,
  происхождение — текстом бейджа.
- Контраст — через гейт `check-contrast.mjs`; новых пар цветов нет.

## 21. Проверка в живом приложении (для human-verify планов)

Проверять в LAN-браузере под сотрудником (после `pnpm --dir ui build`) и при необходимости в
WKWebView/WebView2; синтетический харнесс — не доказательство (память). Каждый пункт готовит
условие воспроизведения:

1. Сотрудник привязан к «АРМ #1» и «АРМ #2», общий принтер в обоих → в «Устройствах» одна строка
   принтера, в «АРМ» — «АРМ #1, АРМ #2», один бейдж происхождения.
2. Устройство вложенной подгруппы «АРМ #1» → в колонке «АРМ» именно «АРМ #1».
3. Сотрудник без групп → пустое состояние «Нет привязанных рабочих мест».
4. Устройство в «Списано» не видно; в «На списание» видно.
5. Вкладка «Заявки» показывает счётчик при непрочитанном сообщении, пока открыта «Устройства».
6. `#/requests?id=…` держит активной «Заявки»; `#/places` → «Доступ запрещён».
7. Кебаб, правый клик и Shift+F10 открывают одно меню; двойной клик по строке — карточку;
   двойной клик по кебабу/метке — нет.
8. «Замена картриджа» есть только у принтеров; форма открывается с выбранным принтером.
9. Устройство в ремонте по чужой заявке → у пункта подсказка «вы присоединитесь», после отправки
   тост «Вы присоединились к заявке №N», в строке — метка «Заявка №N».
10. Свою заявку из строки → тост «Заявка №N создана» со ссылкой, метка появилась без перезагрузки.
11. Тонер ниже 10% → красная заливка в строке и в карточке; у принтера без опросов — «—».
12. Админ в другом окне переименовал/переместил устройство → строка обновилась без перезагрузки.
13. Окно < 768px → плитки; тап открывает карточку, кебаб — меню; шапка не переносится.
14. Прокрутка длинного списка — только тело таблицы/список плиток, двойного скролла нет.
