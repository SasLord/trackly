### `services/employee_device_service.rs` (service, read-only request-response)

**Analog:** `crates/trackly-app/src/services/repair_service.rs`

**Imports / helpers** (стр. 11-33, 98-117) — копировать только нужное; без `WriterHandle` (сервис read-only, вне области реестрового гейта 41.9):

    AppError::Internal { source_chain: format!("spawn_blocking: {e}") }

**Core pattern — скоуп + readers + spawn_blocking** (стр. 239-303). Отличие для новой команды: БЕЗ staff-обхода, `user_id == None` -> `Forbidden`, скоуп по `caller.user_id` для любой роли (RESEARCH Pattern 2, A4):
```rust
authorize(caller, &Action::CreateRequest)?;
let user_id = caller.user_id.ok_or(AppError::Forbidden)?;
let readers = self.readers.clone();
let repo = self.repo.clone();
tokio::task::spawn_blocking(move || -> Result<_, AppError> {
    let conn = readers.acquire();
    let scope: HashSet<i64> = repo.employee_device_ids(&conn, user_id)?.into_iter().collect();
    // SQL как в device_options (JOIN device_types, LEFT JOIN place_full_paths),
    // + JOIN device_statuses ds (подпись и code в DTO),
    // + WHERE d.deleted_at_utc IS NULL AND ds.code <> '<константа списано>'   -- D-20 (фильтр ЗДЕСЬ, не в employee_device_ids)
    // ORDER BY dt.name, d.name, d.id                                        -- D-06
    items.retain(|o| scope.contains(&o.id));
    // in_repair / метки: repo.open_repair_requests_for_devices(&conn, &ids)?
    Ok(items)
})
.await
.map_err(join_err)?
```

**Участие в заявке (D-07)** — переиспользовать `request_visibility_clause` и `OPEN_REPAIR_CLAUSE` из `repairs_sqlite.rs:29-41`; номер чужой заявки НЕ отдавать:
```rust
pub const OPEN_REPAIR_CLAUSE: &str = "r.request_type = 'repair' \
     AND r.status IN ('open', 'in_progress', 'in_repair') \
     AND r.deleted_at_utc IS NULL";
pub fn request_visibility_clause(user_param: &str) -> String {
    format!("(r.requested_by_user_id = {p} OR EXISTS (SELECT 1 FROM request_participants rp \
         WHERE rp.request_id = r.id AND rp.user_id = {p}))", p = user_param)
}
```
Заявки «замена картриджа» (U-1/D-07): `requests.request_type='cartridge_replace'`, `printer_device_id`, статус `open|in_progress` — собственный запрос рядом, но с тем же `request_visibility_clause`.

**Тонер (D-17)** — собственный запрос, НЕ `PrinterService`/`PrinterDto` (несёт IP). Образец запроса последнего чтения: `printers_sqlite.rs:517-534`:
```sql
SELECT ts_utc, COALESCE(toner_levels, '{}') FROM printer_readings
 WHERE printer_id = ?1 ORDER BY ts_utc DESC LIMIT 1
```
`printers.id` != `devices.id`: join `printers p ON p.device_id = d.id`. `toner_levels` = JSON `{label: level}` (percent; `< 0` неизвестно) — как `PrinterDetail.svelte:313`.

**Error handling:** `map_rusqlite`, `AppError::Forbidden`; без `anyhow`.

### `repairs_sqlite.rs` + `employee_device_origins` (repo)

**Analog:** `employee_device_ids` (стр. 563-604) — тот же CTE `bound -> sub -> members` и три ветки UNION; новую функцию строить на той же CTE, чтобы объединение `device_id` совпало с `employee_device_ids` (инвариант-тест обязателен).
```rust
const SQL: &str = "
    WITH RECURSIVE bound(id) AS (
        SELECT DISTINCT g.id FROM group_property_values v
        JOIN group_type_properties p ON p.id = v.property_id AND p.data_type = 'users'
        JOIN groups g ON g.id = v.group_id AND g.deleted_at_utc IS NULL
        WHERE v.value_ref = ?1 ),
    sub(id) AS ( SELECT id FROM bound UNION
        SELECT g.id FROM groups g JOIN sub ON g.parent_group_id = sub.id WHERE g.deleted_at_utc IS NULL ),
    members(id) AS ( SELECT gd.device_id FROM group_devices gd JOIN sub ON gd.group_id = sub.id
        JOIN devices d ON d.id = gd.device_id AND d.deleted_at_utc IS NULL )
    SELECT id FROM members UNION
    SELECT d.id FROM group_property_values v
      JOIN group_type_properties p ON p.id = v.property_id AND p.data_type = 'device_refs'
      JOIN bound b ON b.id = v.group_id
      JOIN devices d ON d.id = v.value_ref AND d.deleted_at_utc IS NULL
    UNION
    SELECT d.id FROM printers pr JOIN devices d ON d.id = pr.device_id AND d.deleted_at_utc IS NULL
      WHERE pr.usb_host_device_id IN (SELECT id FROM members) ORDER BY 1";
```
Отличие: «АРМ» = привязанная группа (`bound`, а не подгруппа `sub` — A1/D-04 уточнение); нужно отслеживать `(device_id, bound.id, bound.name, source)`. Для вложенных подгрупп нужна рекурсия с корнем `bound.id AS root`.

**Приоритет происхождения USB > ссылка > в составе** — единый источник логики в `group_service.rs:1487-1541` (три цикла с общим `seen`; порядок = приоритет), источники: `usb_printers_for_group` (`groups_sqlite.rs:717`), `ref_devices_for_group` (:748) + `live_printer_device_ids` (:975), `member_printers_for_group` (:688). Не править карточку группы (риск повторной UAT 41.13) — в origins продублировать приоритет и покрыть тестом против карточки.
```rust
let mut seen: HashSet<i64> = HashSet::new();
for r in repo.usb_printers_for_group(conn, id)? { if seen.insert(r.device_id) { /* origin "usb" */ } }
for r in live_refs { if explicit.contains(&r.device_id) && seen.insert(r.device_id) { /* "link" */ } }
for r in repo.member_printers_for_group(conn, id)? { if seen.insert(r.device_id) { /* "member" */ } }
```
Для строки с несколькими группами — лучший по приоритету источник среди групп; имена всех групп через запятую.

Репо-конвенции файла: `map_rusqlite`, плейсхолдеры, `format!` только для списков `?` (`placeholders(n)` стр. 73).
