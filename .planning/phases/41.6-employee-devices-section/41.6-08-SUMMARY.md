# Phase 41.6 Plan 08: клиентский слой раздела «Устройства» сотрудника

Обёртка команды `employee_devices_list`, чистая логика меню под golden-гейтом с мутантами и карточка устройства только для чтения.

## Что сделано

- `api.ts`: `employeeDevices.list()` через `apiCall('employee_devices_list')`; типы только `import type` из `bindings`.
- `employeeDeviceMenu.ts` (нет runtime-импортов): `buildEmployeeMenu(row)` даёт секции «Открыть» / «Заявка на ремонт», «Замена картриджа» (только принтер), «Перейти к заявке №N» по возрастанию номера / «Скопировать инв. номер» (только при непустом номере после trim); пустые секции отфильтрованы. «Заявка на ремонт» скрыта при участии в ремонте; при чужом ремонте активна с подсказкой без номера. Экспортированы `JOIN_REPAIR_HINT` и `JOIN_REPAIR_FOOTER_NOTE`.
- `check-employee-device-menu.mjs`: 14 golden-кейсов, структурные [M1] нет runtime-импортов, [M2] нет `DeviceRowMenu` в `src/features/employee/**`, [M3] счётный минимум; `--selftest` с 9 мутантами реального модуля (якорь строго уникален, иначе selftest падает) и 3 структурными. Подключён в `lint` после `check-employee-tabs`.
- `EmployeeDeviceViewModal.svelte`: Modal md, бейдж статуса из `deviceStatusTone`, секции «Сведения» (АРМ с бейджем происхождения), «Тонер» (TonerGauge percent + дата опроса, либо «Принтер ещё не опрашивался»), «Мои заявки по устройству» (ссылка `requestTargetHref`, строка о чужой открытой заявке без номера); футер по UI-SPEC §13.3; клики по заявкам и кнопкам сначала закрывают карточку. Истории перемещений и актов нет.

## Ручная мутация реального модуля

В `employeeDeviceMenu.ts` охрана `if (row.isPrinter) second.push(` заменена на `if (true) second.push(`: `check-employee-device-menu.mjs` покраснел на 10 golden-кейсах (картридж появился у не-принтера). Откат выполнен копией исходника, `git diff` пуст, гейт снова зелёный.
