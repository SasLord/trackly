# Phase 41.6 Plan 06: команда чтения устройств сотрудника

Одна read-команда на оба транспорта: минимальный DTO (без IP/community/SNMP, для принтера только тонер), скоуп по `employee_device_ids`, фильтр «Списано» в SQL, АРМ и происхождение из `employee_device_origins`, метки заявок только при участии сотрудника.

## Что сделано

- `dto/employee_device.rs`: DTO в camelCase, id как i32 для specta; полей ip, community, snmp, oid, usb-хоста, id групп и мест нет.
- `EmployeeDeviceService::list_for_employee`: `authorize(CreateRequest)`, затем `user_id` обязателен; `has_groups`; область = `employee_device_ids`; запрос с `ds.code IS NULL OR ds.code <> ?1` (параметр `DEVICE_STATUS_CODE_WRITTEN_OFF`), порядок тип/наименование/id; `arm_names` по уникальным именам групп; `printer_origin` по минимальному `rank()`; тонер из последнего `printer_readings` (значения `< 0` дают `None`, поддержан и вид `{pct}`); заявки одним запросом с `request_visibility_clause` (номер только при участии, иначе флаг `other_open_request`), `in_repair` и `my_repair_request_id` через `open_repair_requests_for_devices`; история карточки: открытые сверху, закрытых не более 10.
- `build_employee_devices_list` + `#[tauri::command] employee_devices_list` (без параметров) и axum-маршрут `POST /api/v1/employee_devices_list`; команда в `collect_commands!`.
- `AppCtx.employee_devices` сконструирован во всех 10 местах: `context.rs`, `http/health.rs`, `tauri_cmds/health.rs` и шесть тестовых файлов.
- `ui/src/bindings.ts` перегенерирован (gitignored): есть `EmployeeDevicesDto`, `employeeDevicesList`.
