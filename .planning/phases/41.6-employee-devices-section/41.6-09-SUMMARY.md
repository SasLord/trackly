# Phase 41.6 Plan 09: визуальные компоненты списка устройств сотрудника

Метки заявок, меню строки на ActionMenu, строка таблицы и плитка узкого экрана. Компоненты API не вызывают, сообщают о действиях колбэками; пока нигде не смонтированы (страница — план 10).

## Что сделано

- `RequestLabels`: свои открытые заявки по возрастанию номера ссылками (`requestTargetHref`, `stopPropagation`), чужая — нессылочный бейдж «Есть заявка» с `title`.
- `EmployeeDeviceMenu`: `ActionMenu` без пропа `portal`, `panelMinWidth="240px"`, `aria-label` «Действия: {name}», один `<hr role="separator">` между секциями, подсказка D-11 второй строкой внутри той же `role="menuitem"`. Экспортирует `openAt`, `openFromElement`, `openView`.
- `EmployeeDeviceRow`: 10 колонок по UI-SPEC §8.1, первая ячейка `role="button"`, `PrinterMark isPrinter`, `TonerMini` у принтера, бейдж происхождения USB / Ссылка / В составе из DTO, `armNames.join(', ')`. Три обработчика начинаются с охраны. Место выводится из `placeFull` (DTO короткого пути не отдаёт).
- `EmployeeDeviceTile`: плитка по §16.2, пустые поля скрыты через `{#if}`, кебаб `ghost-md`.
