# Phase 41.3 — UI Design Contract

> Визуальный и интеракционный контракт фазы «Вложения»: блок «Вложения» в карточках заявки,
> устройства, принтера и картриджа (плитки, загрузка кнопкой / перетаскиванием / Ctrl+V),
> попап просмотра фото и PDF, плитка «Файл не найден», мягкое удаление и администраторский
> просмотр удалённых, события в истории родителя, раздел «Вложения» в настройках.
> Составлен gsd-ui-researcher, проверяется gsd-ui-checker.
>
> **Макета нет.** Дизайн-система зафиксирована Фазой 23 (`ui/src/styles/_tokens.scss`, гейт
> `ui/scripts/check-tokens.mjs`), примитивы — Фазами 24–25, мастер-деталь — Фазой 27, a11y —
> Фазой 30. Документ **не переоткрывает** ни токены, ни решения `41.3-CONTEXT.md` (D-01…D-23),
> ни критерии ROADMAP. Новых токенов, hex'ов, шкал и npm-зависимостей — **ноль**.
>
> **Приватность (жёсткое условие, репозиторий публичный):** все примеры — вымышленные:
> «Иванов И.И.», «Петров П.П.», «скан-акта.pdf», «фото-шильдика.jpg», «Принтер #2»,
> «Картридж К-000014». Реальные файлы, ФИО, названия организации в код, копирайт, тесты,
> фикстуры, скриншоты UAT и `.planning/`-артефакты не попадают. Тестовые вложения в фикстурах —
> сгенерированные (однотонный PNG, PDF из одной пустой страницы), а не взятые с диска.

## 1. Характер фазы и поверхности

Фаза вводит **один переиспользуемый блок** и **один попап**, которые встраиваются в четыре
существующие карточки, плюс подраздел настроек. Новых разделов в сайдбаре и новых маршрутов
нет.

| # | Поверхность | Файл-владелец | Решения | Раздел |
|---|-------------|---------------|---------|--------|
| 1 | Блок «Вложения» в карточке заявки (специалист и сотрудник-автор) | `ui/src/features/requests/RequestDetail.svelte` | D-02, D-05…D-08, D-11, D-14 | §6, §7 |
| 2 | Блок в карточке принтера | `ui/src/features/printers/PrinterDetail.svelte` | D-03, D-11 | §6 |
| 3 | Блок в карточке картриджа | `ui/src/features/cartridges/CartridgeDetail.svelte` | D-03, D-11 | §6 |
| 4 | Блок в «Просмотре» устройства / принтера / картриджа (единственная карточка устройства — у устройств нет мастер-детали) | `ui/src/features/places/PlaceEntityViewModal.svelte` (открывается из «Устройств» → «Просмотр» и из «Мест») | D-03, D-11 | §6.2 |
| 5 | Попап просмотра фото и PDF | **новый** `ui/src/features/attachments/AttachmentViewer.svelte` | D-12, D-13 | §8 |
| 6 | События в истории родителя | `RequestDetail` («История»), `CartridgeDetail` («Журнал операций»), новая секция «История вложений» в `PrinterDetail` и `PlaceEntityViewModal` | D-14 | §10 |
| 7 | Подраздел «Вложения» в настройках | вкладка «Хранилище», **новый** `ui/src/features/settings/AttachmentSettings.svelte` | D-07, D-20, D-21 | §11 |

**Фокальная точка** — сетка плиток. Primary-кнопок фаза в карточки **не добавляет**: кнопка
«Приложить файлы» — `secondary size="sm"` (как «Редактировать» в заголовке секции
`PrinterDetail`), потому что в карточке уже есть своя primary (например, «Выполнить» в заявке).
Единственная primary фазы — «Скачать» в футере попапа просмотра и «Сохранить лимит» в настройках.

**Сотрудник (Employee).** В 41.3 у сотрудника есть только раздел «Заявки» (`employeeRoutes`),
поэтому видимая ему поверхность — блок в карточке своей заявки (прикладывать может, D-02).
Вложения устройств своих АРМ и принтеров (D-03) сервер отдаёт уже в 41.3, но экран для них
появится в Фазе 41.6. Блок обязан поддерживать режим `readonly` (§6.6), чтобы 41.6 встроила его
без правок.

## 2. Границы: что контракт НЕ покрывает

- Схема таблиц, формат хэша, раскладка подкаталогов, транспорт загрузки (multipart в axum /
  путь Tauri), механизм отдачи файла в десктопе — Claude's Discretion планировщика. Контракт
  задаёт только видимое поведение и **требования к данным** (§12).
- Ролевые проверки — серверные (D-04). Скрытие кнопок в UI — удобство, не защита.
- Вложения к сообщениям переписки (41.5), к результатам ремонта (41.4) — не в этой фазе; блок
  проектируется так, чтобы принять нового родителя пропом `parentKind`.
- Редактирование файлов, переименование вложений, комментарии к вложениям, сортировка
  пользователем, массовый выбор — **нет**.
- Предпросмотр DOC/XLS/ODT/TXT/ZIP — **нет**: только скачивание (D-12).
- Миниатюра PDF — **нет**: у PDF иконка типа (миниатюры сервер делает только для фото, D-11).
- Глобальный список всех удалённых вложений по всем карточкам — **нет**: администратор видит
  удалённые в карточке их родителя (§9.3); в настройках — только число (§11.3).
- Ручной запуск проверки целостности — **нет** (D-20: при запуске фоново). Отчёт показывает
  результат последней проверки.

## 3. Spacing Scale

Шкала Фазы 23 не меняется. Задействованные значения:

| Токен | Значение | Использование в Фазе 41.3 |
|-------|----------|----------------------------|
| `--tr-space-2xs` | 4px | зазор между строками подписи плитки (имя ↔ размер ↔ «кто, когда»); зазор иконки и текста в кнопке-ссылке имени файла |
| `--tr-space-xs` | 8px | внутренний отступ подписи плитки (`padding: 8px`); зазор между строками списка ошибок загрузки; отступ ActionMenu плитки от угла превью |
| `--tr-space-sm` | 12px | `gap` сетки плиток (по обеим осям); gap кнопок футера попапа (унаследован `Modal`) |
| `--tr-space-md` | 16px | отступ «заголовок секции ↔ сетка» (унаследован `DetailSection`); отступ сетки ↔ список ошибок; отступ сетки ↔ раскрывашка «Удалённые»; внутренний отступ пустой зоны перетаскивания |
| `--tr-space-xl` | 24px | внутренний отступ зоны перетаскивания в пустом состоянии по вертикали |
| `--tr-space-2xl` | 32px | `margin-bottom` секции (унаследован `DetailSection`) |

**Исключения (литеральные px вне шкалы):**

| Величина | Где | Обоснование |
|----------|-----|-------------|
| `minmax(136px, 1fr)` | ширина колонки сетки плиток (`grid-template-columns: repeat(auto-fill, minmax(136px, 1fr))`) | 4 плитки помещаются в `Modal size="md"` (640px − 2×24px отступа = 592px ≥ 4×136 + 3×12 = 580px) и 3–5 плиток в панели мастер-детали; кратно 4 |
| 96px | высота области превью плитки (миниатюра / иконка типа) | фиксированная, чтобы плитки разной природы стояли ровной линией; кратно 4 |
| 32×32px | inline-SVG иконки типа файла в области превью | читается на 96px без доминирования; кратно 4 |
| 28px | триггер `ActionMenu variant="ghost-sm"` в углу превью | унаследованный размер варианта `ghost-sm` |
| 36px (`--touch-target-min`) | кнопки «‹ / ›» навигации попапа, поле лимита в настройках | паритет с прочими контролами |
| 2px dashed | рамка зоны перетаскивания (пустое состояние и подсветка при перетаскивании) | единственный пунктир фазы, читается как «сюда можно бросить» |
| 70vh / 75vh | `max-height` фото в попапе в режиме «вписать» / высота `<iframe>` PDF | попап не выходит за экран на 768px-ноутбуке; значения именно `max-height`/`height` тела попапа |
| 120px | ширина поля «Максимальный размер файла» | достаточно для трёх цифр и суффикса «МБ» |

## 4. Typography

Шкала Фазы 23 (9 ролей + mono) не меняется. Задействованные роли:

| Роль | Токен | Размер/Вес/LH | Где в Фазе 41.3 |
|------|-------|----------------|------------------|
| Заголовок H3 | `--tr-text-h3` | 20px/600/1.3 | титул `Modal` попапа просмотра (имя файла), титулы модалок подтверждения удаления (унаследовано) |
| Текст | `--tr-text-body` | 14px/400/1.5 | текст пустой зоны, тексты модалок подтверждения, строки отчёта целостности, строки истории |
| Текст · акцент | `--tr-text-body-strong` | 14px/600/1.5 | заголовок секции «Вложения» (унаследован `DetailSection`) |
| Подпись | `--tr-text-label` | 13px/500/1.4 | **имя файла** под плиткой; строки списка ошибок загрузки; подписи полей настроек; кнопка раскрывашки «Удалённые (2)» |
| Мелкий | `--tr-text-caption` | 12px/500/1.35 | размер файла и строка «кто · когда» под плиткой; метка «Файл не найден» на превью; бейдж расширения на иконке типа («PDF», «DOCX»); счётчик «2 из 5» в шапке попапа; мета-строка в футере попапа; подсказка под полем лимита |

**Правила:**
- Имя файла — одна строка с `text-overflow: ellipsis`, полное имя — в `title` и в
  `aria-label` кнопки плитки. Перенос имени по словам **запрещён**: плитки одной строки сетки
  обязаны оставаться одной высоты.
- Размер файла **не** `.tr-mono`: это фраза с единицей («1,2 МБ»), а не машинный номер.
- Хэш файла в интерфейсе **не показывается нигде** (ни в плитке, ни в попапе, ни в настройках).
- **Унаследованное отступление:** шкала проекта использует три веса (400 / 500 / 600) и пару
  12/13px; она закрыта Фазой 23, фаза не добавляет ни одной роли.

## 5. Color: 60/30/10

Новых токенов и пар light/dark фаза не вводит.

| Роль | Токен | Использование в Фазе 41.3 |
|------|-------|----------------------------|
| Доминанта (60%) | `--tr-surface` / `--tr-surface-raised` | фон плитки, тело попапа просмотра |
| Вторичная (30%) | `--tr-bg` | фон панели мастер-детали (унаследован); фон области превью за миниатюрой с прозрачностью (PNG/GIF/WebP) |
| Утопленная | `--tr-surface-sunken` | фон области превью у иконки типа и у плитки «Файл не найден»; фон-подложка фото в попапе вокруг вписанного изображения |
| Границы | `--tr-border` / `--tr-border-strong` | рамка плитки 1px `--tr-border`; при наведении — `--tr-border-strong`; пунктир пустой зоны — `--tr-border-strong` |
| Текст | `--tr-text-primary` / `-secondary` / `-tertiary` | имя файла / размер и «кто · когда», строки отчёта / иконка типа, «Загрузка…» |
| Акцент (10%) | `--tr-accent`, `-soft`, `-text`, `--tr-focus-ring` | **строго список ниже** |
| Деструктив | `--tr-danger`, `-text` | только: пункты меню «Удалить» и «Удалить навсегда» (`danger: true` в `ActionMenu`), кнопки `destructive` в модалках подтверждения, текст списка ошибок загрузки (`--tr-danger-text`) |
| Предупреждение (приглушённое) | `--tr-warning-muted-text` | метка «Файл не найден» на плитке; число потерянных файлов > 0 в отчёте целостности. **Красный для потерянного файла запрещён** (D-13) |
| Тени | `--tr-elev-3` | `Modal` (унаследовано). Плитка теней не имеет |

**Акцент зарезервирован строго за:**
1. подсветкой зоны перетаскивания, пока над ней несут файлы: рамка 2px dashed `--tr-accent`,
   фон `--tr-accent-soft`, текст `--tr-accent-text`;
2. кликабельным именем файла в строке истории (`Button variant="link"`, `--tr-accent-text`);
3. primary-кнопкой «Скачать» в футере попапа просмотра и «Сохранить лимит» в подразделе настроек;
4. focus-ring — глобальный `*:focus-visible` (3px `--tr-focus-ring`), в том числе на кнопке
   плитки; не переопределяется.

Акцент **не** используется: для рамки плитки при наведении, для иконок типа файла, для бейджа
расширения, для кнопки «Приложить файлы» (она `secondary`), для счётчика «2 из 5».

## 6. Блок «Вложения»

### 6.1 Новый компонент и место в карточках

`ui/src/features/attachments/AttachmentsBlock.svelte` — единственная реализация блока для всех
родителей. Пропсы (контракт, имена — на усмотрение планировщика): `parentKind`
(`'request' | 'device' | 'cartridge'`; принтер — это устройство, D-03), `parentId`, `canAttach`,
`readonly`. Блок сам грузит список, сам подписан на `entities_changed` (D-15) и сам рисует
попап просмотра.

**Правило размещения — одно для всех карточек:** секция «Вложения» стоит **непосредственно
перед первой секцией-историей** карточки. Данные о предмете — выше, хронология — ниже, файлы —
между ними.

| Карточка | Секция до | **«Вложения»** | Секция после |
|----------|-----------|----------------|--------------|
| `RequestDetail` | «Информация» и блок резолюции / мини-форма «Выполнить» | ← здесь | «История» |
| `PrinterDetail` | «Совместимые модели картриджей» | ← здесь | «История статусов» |
| `CartridgeDetail` | «Информация» | ← здесь | «Журнал операций» |
| `PlaceEntityViewModal` (устройство, принтер, картридж) | тело формы `readonly` и поле «Из разбора» | ← здесь | «История перемещений» |

В формах **редактирования** (`DeviceFormModal`, `CartridgeFormModal`, `RequestFormModal`) блока
**нет**: загрузка не входит в транзакцию сохранения формы, а файл, приложенный к ещё не
созданной записи, некуда привязать.

### 6.2 Заголовок секции

`DetailSection` без пропа `heading`; внутри — строка заголовка по образцу
`PrinterDetail .section-heading-row`:

```
Вложения (3)                                    [ Приложить файлы ]
```

- Текст заголовка: `Вложения`; при наличии активных вложений — `Вложения (3)` (число активных,
  без удалённых). При нуле — просто `Вложения`.
- Кнопка `Приложить файлы` — `Button variant="secondary" size="sm"`; рисуется только при
  `canAttach && !readonly`. Нажатие открывает системный выбор файлов через скрытый
  `<input type="file" multiple accept="…">` (§7.1).

### 6.3 Сетка плиток

Семантика: `<ul class="attachments-grid">` + `<li>` на плитку.
`grid-template-columns: repeat(auto-fill, minmax(136px, 1fr)); gap: var(--tr-space-sm)`.

**Порядок:** по времени приложения, **старые первыми** (новые добавляются в конец сетки, туда
же, где появляются плитки загрузки §7.3 — ничего не прыгает).

### 6.4 Анатомия плитки

```
┌──────────────────────┐
│                  [⋯] │  ← ActionMenu ghost-sm, правый верхний угол превью
│   миниатюра 96px     │     (фото: object-fit: cover)
│   или иконка + «PDF» │     (прочее: SVG 32px + бейдж расширения)
├──────────────────────┤
│ скан-акта.pdf        │  ← --tr-text-label, primary, 1 строка, ellipsis
│ 1,2 МБ               │  ← --tr-text-caption, secondary
│ Иванов И.И. · 07.11.2026 14:32 │ ← caption, secondary, 1 строка, ellipsis
└──────────────────────┘
```

| Часть | Правило |
|-------|---------|
| Контейнер | рамка 1px `--tr-border`, `--tr-radius-md`, фон `--tr-surface`; наведение — рамка `--tr-border-strong`, курсор `pointer` на кнопке плитки |
| Кнопка плитки | превью + подпись обёрнуты в **одну** `<button type="button">` (основное действие, §6.5); `ActionMenu` — **соседний** элемент внутри `<li>`, абсолютно позиционирован поверх угла превью. Вложенных кнопок нет |
| Превью фото | `<img loading="lazy" alt="">` миниатюры с сервера, `object-fit: cover`, фон `--tr-bg`. Пока миниатюра грузится — тот же фон без спиннера. Миниатюра не загрузилась (ошибка запроса) — показывается иконка типа «изображение», как у не-фото |
| Превью прочих типов | фон `--tr-surface-sunken`, по центру inline-SVG 32px (`--tr-text-tertiary`), под ним бейдж расширения: верхний регистр, `--tr-text-caption`, `--tr-text-secondary` («PDF», «DOCX», «XLSX», «ODT», «TXT», «CSV», «LOG», «ZIP», «7Z»). Иконок три: «изображение», «документ» (PDF, DOC/DOCX, ODT, TXT, CSV, LOG), «таблица» (XLS/XLSX, ODS), «архив» (ZIP, 7z) — итого четыре рисунка, один компонент `AttachmentTypeIcon.svelte` |
| Имя | исходное имя файла (HEIC — с расширением `.jpg`, D-10) |
| Размер | §6.7 |
| «Кто · когда» | `{ФИО загрузившего} · {дд.ММ.гггг ЧЧ:мм}` в локальном времени; нет ФИО (пользователь удалён) — `Пользователь удалён · 07.11.2026 14:32` |
| ActionMenu | `variant="ghost-sm"`, `label="Действия с файлом"`, портал по умолчанию. Виден всегда (не только по наведению) — на сенсорном ноутбуке наведения нет; фон кнопки `--tr-surface-raised` с рамкой `--tr-border`, чтобы читаться поверх фото |

**Пункты ActionMenu плитки:**

| Пункт | Кому | Условие |
|-------|------|---------|
| `Открыть` | всем, у кого есть плитка | только просматриваемые типы (§8.1) |
| `Скачать` | всем | файл не потерян; у потерянного пункт `disabled` |
| `Удалить` (`danger`) | загрузивший (своё), Admin, Manager (D-16) | не `readonly`; отделён от остальных разделителем |

### 6.5 Основное действие плитки (клик / Enter / Space)

| Тип | Действие |
|-----|----------|
| JPEG, PNG, WebP, GIF, HEIC→JPEG, PDF | открыть попап просмотра на этом вложении (§8) |
| Прочие (DOC/DOCX, XLS/XLSX, ODT/ODS, TXT/CSV/LOG, ZIP, 7z) | скачать через общий `saveFile` (системный диалог сохранения в десктопе, загрузка браузера в LAN) |
| Потерянный файл (любой тип) | открыть попап в состоянии «Файл не найден» (§8.6), без попытки скачивания |

`aria-label` кнопки плитки: `Открыть «скан-акта.pdf»` / `Скачать «отчёт.xlsx»` /
`Файл не найден: «скан-акта.pdf»`.

### 6.6 Состояния блока

| Состояние | Что видно |
|-----------|-----------|
| Загрузка списка | вместо сетки — `Spinner size="sm"` в строке высотой 96px (паттерн `.history-loading`) |
| Ошибка загрузки списка | текст `Не удалось загрузить вложения.` + `Button variant="link" size="sm"` `Повторить`; **без тоста** |
| Пусто, может прикладывать | пунктирная зона (2px dashed `--tr-border-strong`, `--tr-radius-md`, отступы 24px/16px, текст по центру): заголовок-строка `Файлов пока нет` (`--tr-text-body`, primary) и под ней `Перетащите файлы сюда, вставьте скриншот из буфера (Ctrl+V) или нажмите «Приложить файлы».` (`--tr-text-label`, secondary) |
| Пусто, только просмотр (`readonly` или нет права) | одна строка `Файлов нет` (`--tr-text-body`, `--tr-text-tertiary`), без рамки — по образцу `history-empty` |
| Есть вложения | сетка; зона перетаскивания — вся секция (рамки в покое нет) |
| Над секцией несут файлы | вся секция получает рамку 2px dashed `--tr-accent` + фон `--tr-accent-soft`; поверх сетки по центру — `Отпустите, чтобы приложить` (`--tr-text-body-strong`, `--tr-accent-text`). Подсветка снимается на `dragleave` за пределы секции и на `drop` |
| `readonly` | нет кнопки, нет зоны перетаскивания, нет обработки Ctrl+V, в меню только `Открыть` / `Скачать` |

### 6.7 Формат размера

Основание 1024, десятичный разделитель — запятая, пробел перед единицей (неразрывный):
`512 Б` · `48 КБ` (КБ — целые) · `1,2 МБ` (МБ — один знак, `,0` отбрасывается: `20 МБ`) ·
`1,4 ГБ` (только в отчёте настроек). Одна функция `formatFileSize` в `ui/src/lib/utils/`,
используется плиткой, попапом, сообщениями об ошибках и настройками.

## 7. Загрузка (D-05…D-08, D-10)

### 7.1 Три способа — один путь

Кнопка, перетаскивание и Ctrl+V сводятся к одному списку `File[]` и одной функции загрузки.
Отдельного пути через системный диалог Tauri **нет**: скрытый `<input type="file" multiple>`
работает и в WebView2, и в WKWebView, и в браузере.

- `accept` (подсказка выбора, не защита): `.jpg,.jpeg,.png,.webp,.gif,.heic,.heif,.pdf,.doc,.docx,.xls,.xlsx,.odt,.ods,.txt,.csv,.log,.zip,.7z`.
- **Перетаскивание в десктопе.** В Tauri 2 окно по умолчанию перехватывает перетаскивание
  файлов (`dragDropEnabled: true`), и HTML5-событие `drop` в webview файлов не получает.
  Требование контракта: в окне `crates/trackly-app/tauri.conf.json` выставлено
  `"dragDropEnabled": false`, чтобы перетаскивание шло тем же HTML5-путём, что в браузере.
  Существующее перетаскивание узлов в `PlaceTree.svelte` — внутристраничное HTML5 и от этой
  настройки не ломается; проверить живым прогоном (UAT §13).
- Перетащена папка (или элемент без `File`) — она не загружается, получает ошибку в списке
  (§7.4); остальные файлы того же броска загружаются.
- **Ctrl+V / ⌘V.** Вставка обрабатывается, если: блок не `readonly` и `canAttach`; фокус **не**
  в редактируемом поле (`input`, `textarea`, `[contenteditable]`) — иначе вставка остаётся
  обычной вставкой текста; блок находится в самом верхнем открытом контексте (блок в панели
  мастер-детали игнорирует вставку, пока открыт любой `Modal`; блок внутри
  `PlaceEntityViewModal` обрабатывает её, только если эта модалка — верхняя в стеке). Из буфера
  берутся только файлы/изображения; текст из буфера блок не трогает. Имя изображения без имени:
  `Скриншот 2026-11-07 14-32-05.png` (локальное время вставки).

### 7.2 Предварительная проверка в UI

До отправки UI отсекает **только размер** (лимит приходит с сервера вместе со списком
вложений, D-07) и пустые файлы. Тип в UI не проверяется — его определяет сервер по сигнатуре
(D-08); у неподходящего типа ошибка придёт с сервера тем же списком (§7.4).

### 7.3 Плитка загрузки

На каждый принятый к отправке файл в конец сетки сразу добавляется плитка загрузки:
превью — фон `--tr-surface-sunken` + `Spinner size="sm"` по центру; подпись — имя файла и строка
`Загрузка…` (`--tr-text-caption`, `--tr-text-tertiary`). Процентов **нет** (у Tauri-транспорта
прогресса нет; паритет транспортов). Файлы отправляются **последовательно**, по одному, чтобы
отказ одного не срывал остальные и порядок плиток совпадал с порядком выбора.

- Успех → плитка загрузки заменяется настоящей плиткой на том же месте. **Тоста об успехе нет**:
  появившаяся плитка и есть подтверждение.
- Отказ → плитка загрузки убирается, строка добавляется в список ошибок (§7.4).
- Пока идёт загрузка, кнопка «Приложить файлы» остаётся активной: новые файлы встают в очередь.
- Уход с карточки (выбор другой записи / закрытие модалки) во время загрузки: уже отправленный
  файл досылается, неотправленные из очереди отбрасываются без сообщений.
- Живой регион `aria-live="polite"` блока объявляет: `Загружается файлов: 3` при старте пакета и
  `Загружено файлов: 2 из 3` по завершении пакета.

### 7.4 Ошибки по файлам (D-06)

Ошибки **не тосты** (пакет из 10 отказов не должен засыпать экран). Под сеткой — блок
`role="alert"`, список `<ul>`, одна строка на отклонённый файл, текст `--tr-text-label`
`--tr-danger-text`, справа от заголовка списка — `Button variant="link" size="sm"` `Скрыть`,
очищающий список. Заголовок списка: `Не приложено файлов: 2` (форма «файлов: N» не склоняется, `pluralizeRu` не нужен).
Список при следующем пакете **не** очищается автоматически — только кнопкой или уходом с карточки.

| Причина (код сервера → UI) | Строка |
|-----------------------------|--------|
| Больше лимита | `«{имя}» — больше {лимит} МБ (размер файла {размер}).` |
| Пустой файл | `«{имя}» — файл пустой.` |
| Тип не из белого списка / сигнатура не совпала | `«{имя}» — такой файл приложить нельзя. Подходят фото (JPEG, PNG, WebP, GIF, HEIC), PDF, документы Word, Excel и OpenDocument, TXT, CSV, LOG, архивы ZIP и 7z.` |
| HEIC не сконвертировался | `«{имя}» — не удалось преобразовать фото HEIC. Сохраните его в JPEG и приложите снова.` |
| Папка / не файл | `«{имя}» — это папка. Приложите файлы из неё.` |
| Нет доступа / родитель удалён | `«{имя}» — нет доступа к карточке или она удалена.` |
| Сеть / прочее | `«{имя}» — не удалось загрузить. Проверьте подключение и попробуйте ещё раз.` |

Имена в строках — в ёлочках. Длинная строка обрезается с конца через CSS ellipsis, полный текст —
в `title`.

## 8. Попап просмотра (D-12, D-13)

### 8.1 Что открывается

Просматриваемые: JPEG, PNG, WebP, GIF (анимация проигрывается), HEIC→JPEG, PDF. Навигационный
набор — просматриваемые **непотерянные** вложения того же родителя и той же группы (активные
или, у администратора, удалённые — §9.3), в порядке сетки. Потерянный файл открывается
одиночно (без навигации) в состоянии §8.6.

### 8.2 Анатомия

`Modal size="pdf-preview"` (ширина `min(95vw, 1100px)`, унаследовано).

```
┌─────────────────────────────────────────────────────────────────────┐
│ фото-шильдика.jpg                                 2 из 5        [×] │
├─────────────────────────────────────────────────────────────────────┤
│ [‹]                                                             [›] │
│                ┌───────────────────────────────┐                    │
│                │      изображение / PDF         │                    │
│                └───────────────────────────────┘                    │
├─────────────────────────────────────────────────────────────────────┤
│ 1,2 МБ · Иванов И.И. · 07.11.2026 14:32       [ Закрыть ] [ Скачать ]│
└─────────────────────────────────────────────────────────────────────┘
```

- Титул — имя файла (ellipsis, полное имя в `title`). Счётчик `2 из 5` — в `titleExtra`,
  `--tr-text-caption`, `--tr-text-secondary`; при одном вложении в наборе счётчика нет.
- Кнопки `‹` / `›` — `Button variant="ghost" iconOnly` 36×36 у левого и правого края тела по
  вертикальному центру, `aria-label` `Предыдущее вложение` / `Следующее вложение`. На первом /
  последнем — `disabled` (по кругу **не** листается). При одном вложении кнопок нет.
- Футер: слева мета-строка `--tr-text-caption` secondary (`{размер} · {ФИО} · {дата время}`),
  справа `Закрыть` (`secondary`) и `Скачать` (`primary`).
- Попап рендерится как **соседний** экземпляр `Modal` верхнего уровня компонента блока, а не
  внутри чужого `Modal`-контента; поверх `PlaceEntityViewModal` он ложится через общий стек
  `openStack` (Esc закрывает только верхний). `check-modal-isolation.mjs` остаётся зелёным.

### 8.3 Фото

- По умолчанию — «вписать»: `max-width: 100%`, `max-height: 70vh`, по центру, подложка
  `--tr-surface-sunken`.
- Клик по фото (или Enter / Space — фото обёрнуто в `<button>` с `aria-label`
  `Увеличить` / `Уменьшить`) переключает «вписать» ↔ «100%»: в режиме 100% изображение в
  натуральном размере, тело попапа прокручивается в обе стороны, курсор `zoom-out`; в режиме
  «вписать» — `zoom-in`. Если натуральный размер меньше вписанного, переключение ничего не
  меняет и курсор обычный.
- Переход к другому вложению сбрасывает масштаб на «вписать».

### 8.4 PDF

`<iframe>` во всю ширину тела, высота 75vh, `title` = имя файла; рисует встроенный просмотрщик
webview / браузера. Сторонних PDF-библиотек нет. Если встроенный просмотрщик недоступен
(iframe пуст), пользователь пользуется кнопкой «Скачать» — отдельной ветки UI под это нет.

### 8.5 Клавиатура и фокус

- `←` / `→` — предыдущее / следующее, когда фокус не внутри `<iframe>` (внутри PDF стрелки
  принадлежат просмотрщику; кнопки `‹ ›` доступны Tab'ом всегда).
- `Esc`, крестик, клик по подложке, `Закрыть` — закрыть; фокус возвращается на плитку, с
  которой открыли (унаследовано `Modal` + restore focus).
- Начальный фокус — кнопка `Скачать`.

### 8.6 Состояния тела

| Состояние | Тело | «Скачать» |
|-----------|------|-----------|
| Загрузка | `Spinner size="md"` + `Загружаем файл…` по центру, высота тела как у фото (70vh) — попап не «прыгает» | `disabled` |
| Файл не найден (D-13) | по центру: `Файл не найден` (`--tr-text-body-strong`, primary) и ниже абзац `--tr-text-body` secondary: `Файла «скан-акта.pdf» нет в каталоге вложений. Возможно, каталог перенесли без него или файл удалили вручную. Сообщите администратору — файл можно вернуть из резервной копии.` | `disabled` |
| Ошибка загрузки (сеть) | `Не удалось открыть файл.` + `Button variant="secondary" size="sm"` `Повторить` | активна |
| Вложение удалили, пока попап открыт (D-15) | `Вложение удалено.` (`--tr-text-body`); стрелки продолжают работать по оставшимся | `disabled` |
| Вложение удалено (просмотр администратором из «Удалённых») | над изображением полоса `--tr-text-caption` secondary: `Удалено · Петров П.П. · 07.11.2026 15:10` | активна |

Ни одно из состояний не даёт тоста и не роняет экран.

## 9. Удаление, восстановление, «Удалить навсегда» (D-16…D-18)

### 9.1 Мягкое удаление

Пункт `Удалить` в меню плитки → `Modal size="md"`:

- Титул: `Удалить вложение?`
- Тело (загрузивший / Manager): `Файл «скан-акта.pdf» исчезнет из карточки. Вернуть его сможет только администратор.`
- Тело (Admin): `Файл «скан-акта.pdf» переместится в «Удалённые» этой карточки. Его можно будет восстановить или удалить навсегда.`
- Кнопки: `Отмена` (`secondary`, начальный фокус) · `Удалить` (`destructive`).
- Успех: плитка исчезает, `Toast kind="success"` `Вложение «скан-акта.pdf» удалено`.
- Ошибка: модалка остаётся открытой, `Toast kind="error"`
  `Не удалось удалить вложение. Попробуйте ещё раз.`

### 9.2 Что видят роли после удаления

| Роль | После мягкого удаления |
|------|------------------------|
| Загрузивший-сотрудник, Manager | вложения нет нигде: ни плитки, ни раскрывашки, ни кликабельного имени в истории (D-16) |
| Admin | плитка уходит в раскрывашку «Удалённые» той же карточки (§9.3) |

### 9.3 Раскрывашка «Удалённые» (только Admin)

- Рисуется под сеткой активных (отступ 16px), только если удалённых ≥ 1 и роль Admin.
- Кнопка: `RowChevron` + `Удалённые (2)` (`--tr-text-label`, secondary), `aria-expanded`.
  **Свёрнута по умолчанию**; состояние не сохраняется между карточками.
- Раскрытая — та же сетка плиток. Отличия плитки удалённого: в левом верхнем углу превью —
  `Badge variant="default" size="sm"` `Удалено`; третья строка подписи вместо «кто · когда» —
  `Удалил: Петров П.П. · 07.11.2026 15:10` (кто приложил — во второй строке футера попапа).
- Меню плитки удалённого: `Открыть` (просматриваемые) · `Скачать` · разделитель ·
  `Восстановить` · `Удалить навсегда` (`danger`).
- `Восстановить` — **без** подтверждения (обратимо); плитка возвращается в активную сетку на
  своё место по времени приложения; `Toast kind="success"` `Вложение «скан-акта.pdf» восстановлено`.
  Ошибка: плитка остаётся в «Удалённых», `Toast kind="error"`
  `Не удалось восстановить вложение. Попробуйте ещё раз.`
- `Удалить навсегда` → `Modal size="md"`:
  - Титул: `Удалить навсегда?`
  - Тело: `Вложение «скан-акта.pdf» будет удалено безвозвратно. Восстановить его из интерфейса будет нельзя.`
  - Кнопки: `Отмена` (`secondary`, начальный фокус) · `Удалить навсегда` (`destructive`).
  - Успех: плитка исчезает; `Toast kind="success"` `Вложение «скан-акта.pdf» удалено навсегда`.
  - Ошибка: модалка остаётся открытой, `Toast kind="error"`
    `Не удалось удалить вложение навсегда. Попробуйте ещё раз.`
  - Стирание файла на диске по последней ссылке (D-18) пользователю не сообщается — это
    внутреннее правило хранения.

### 9.4 Удаление и восстановление родителя (D-19, D-26)

Отдельного UI нет. Существующие модалки удаления записей **не** меняют текст: при мягком
удалении родителя вложения скрываются вместе с ним и возвращаются при восстановлении.
Безвозвратного удаления родителей в приложении нет (D-26), поэтому предложения о
безвозвратной потере вложений в модалках удаления нет.

## 10. События в истории (D-14)

### 10.1 Формат строки

Существующий формат истории заявки: `{дата время} — {действие}; {ФИО}`. События вложений
пишутся тем же форматом **без глагола в роде** (ФИО может быть любого рода):

| Событие | Строка |
|---------|--------|
| Приложен | `07.11.2026 14:32 — Приложен файл «скан-акта.pdf»; Иванов И.И.` |
| Удалён | `07.11.2026 15:10 — Удалён файл «скан-акта.pdf»; Петров П.П.` |
| Восстановлен | `07.11.2026 15:20 — Восстановлен файл «скан-акта.pdf»; Петров П.П.` |
| Удалён навсегда | `07.11.2026 15:30 — Файл «скан-акта.pdf» удалён навсегда; Петров П.П.` |

Пакет из N файлов даёт N строк (по одной на файл). Имя файла в строке — снимок на момент
события (переименования нет, но вложение может быть стёрто).

### 10.2 Кликабельное имя

Имя файла (без ёлочек внутри ссылки — ёлочки снаружи) — `Button variant="link" size="sm"`
инлайн, **пока вложение активно** у видящего (для Admin — и пока оно мягко удалено). Клик
повторяет основное действие плитки (§6.5): просматриваемое → попап, прочее → скачивание,
потерянное → попап «Файл не найден». Вложение удалено (для не-Admin) или удалено навсегда →
имя обычным текстом `--tr-text-primary`.

### 10.3 Где выводится

| Карточка | Куда |
|----------|------|
| `RequestDetail` | существующая секция «История» — события вперемешку с жизненным циклом заявки, по времени |
| `CartridgeDetail` | существующая секция «Журнал операций» |
| `PrinterDetail`, `PlaceEntityViewModal` | у устройств и принтеров общей audit-истории в UI **нет**; добавляется секция `История вложений` **сразу после** «Вложения», тем же рисунком списка, что `.history-list` заявки. Секция рисуется только при наличии событий — пустой заголовок не показывается |

Сотрудник в истории своей заявки видит события вложений своей заявки по тем же правилам
(удалённые им или специалистом — без ссылки).

## 11. Настройки: подраздел «Вложения» (D-07, D-20, D-21)

### 11.1 Место

Вкладка `Хранилище` (`StorageSettings.svelte`), **вторая** `section.settings-section` под

расположение», которое только десктопное).

### 11.2 Состав

| Строка | Содержимое |
|--------|-----------|
| `Каталог вложений` | путь в `code` (как путь БД); под ним `--tr-text-caption` secondary: `По умолчанию — папка attachments рядом с базой данных. Другой путь задаётся параметром attachments_path в trackly.config.toml.`; кнопка `Открыть папку с вложениями` (`ghost sm`) — только в десктопе, по образцу «Открыть папку с базой данных» |
| `Максимальный размер файла` | `Input` шириной 120px, целое число, суффикс `МБ` справа от поля; подсказка `--tr-text-caption`: `От 1 до 100 МБ. По умолчанию 20 МБ.`; кнопка `Сохранить лимит` (`primary sm`) рядом, `disabled`, пока значение не изменено или невалидно. Ошибка под полем (`role="alert"`, `--tr-danger-text`): `Укажите целое число от 1 до 100.` Успех: `Toast kind="success"` `Лимит размера файла: 25 МБ`. Ошибка сервера или сети: значение остаётся в поле, `Toast kind="error"` `Не удалось сохранить лимит. Попробуйте ещё раз.` Уже приложенные файлы больше нового лимита не трогаются |
| `Проверка целостности` | подзаголовок `--tr-text-body-strong`; строки через `DetailField`: `Занято на диске` — `1,4 ГБ (312 файлов)`; `Потерянные файлы` — число; `Файлы-сироты` — число; `Удалённые вложения` — `5 (48 МБ)`; `Последняя проверка` — `07.11.2026 09:01` |

Пояснения под строками отчёта (`--tr-text-caption`, secondary), показываются **только при
значении > 0**:

- Потерянные (число окрашено `--tr-warning-muted-text`): `Записи есть, а файлов нет. Такие вложения показываются плиткой «Файл не найден». Верните файлы в каталог вложений из резервной копии.`
- Сироты: `Файлы без записей в базе. Удаляются автоматически при следующем запуске, если старше суток.`

Состояния отчёта: проверка ещё идёт после запуска — `Проверка выполняется…` +
`Spinner size="sm"`; проверки ещё не было — `Проверка ещё не выполнялась.`; ошибка запроса —
`Не удалось получить отчёт. Обновите страницу.`

## 12. Требования к данным (контракт на DTO, не на схему)

Чтобы блок рисовался без N+1 запросов и без вранья:

- Элемент списка вложений: `id`, `original_name`, `mime` (итоговый, после конвертации HEIC),
  `size_bytes`, `has_thumbnail`, `viewable` (сервер решает, а не JS-зеркало белого списка),
  `missing` (файл отсутствует на диске), `uploaded_by_name` (снимок или JOIN; `null` → «Пользователь удалён»),
  `uploaded_by_id` (для права удалить своё), `created_at_utc`; для удалённых —
  `deleted_by_name`, `deleted_at_utc`.
- Ответ списка несёт `max_size_bytes` (для предварительной проверки §7.2) и права вызывающего
  на этого родителя: `can_attach`, `can_delete_any`, `can_manage_deleted` — UI **не** вычисляет
  права по роли сам.
- Отказ загрузки приходит с машинным кодом причины (`too_large`, `empty`, `type_not_allowed`,
  `heic_failed`, `forbidden`), по которому UI выбирает строку §7.4. Текст ошибки сервера в UI
  не выводится.
- Событие истории вложения несёт `attachment_id`, снимок имени и признак текущего состояния
  (`active` / `deleted` / `purged`), чтобы §10.2 решался без отдельного запроса.
- Миниатюра, файл и список отдаются одинаково в Tauri и LAN; URL / blob — на усмотрение
  планировщика, но `<img>` миниатюры обязан работать в обоих режимах без отдельной ветки
  разметки.

## 15. Доступность

- Секция — `<section aria-labelledby>` на заголовок «Вложения».
- Все действия доступны без мыши: «Приложить файлы» (Tab + Enter) заменяет перетаскивание и
  вставку; плитка — `<button>`; меню — `ActionMenu` (унаследованная клавиатура).
- Живой регион §7.3; список ошибок — `role="alert"`.
- `alt` миниатюры пустой (имя уже озвучено `aria-label` кнопки плитки); `alt` фото в попапе —
  имя файла.
- Focus-ring глобальный, не переопределяется; на плитке кольцо рисуется на кнопке плитки, не
  на `<li>`.

## 16. Проверка в живом приложении (для human-verify планов)

Компиляционные гейты (`svelte-check`, `pnpm lint`, `pnpm build`) рантайм не видят; CSS-харнесс в
Chromium ≠ WKWebView/WebView2. Пункты, которые планы обязаны отдать пользователю, с условием
воспроизведения:

1. Десктоп (WKWebView и WebView2): перетащить 3 файла из Finder/Проводника на карточку
   принтера — появляются 3 плитки; перетаскивание узла в «Местах» по-прежнему работает
   (`dragDropEnabled: false`).
2. Ctrl+V скриншота в карточке заявки при фокусе вне полей — плитка `Скриншот …png`; Ctrl+V в
   поле «Комментарий специалиста» — вставляется текст, вложение не создаётся.
3. Пакет «фото + .exe + файл 30 МБ при лимите 20» — фото приложено, две строки ошибок, тостов нет.
4. Попап: ←/→ по 3 фото и PDF, увеличение по клику, «Скачать» в десктопе (диалог) и в LAN
   (загрузка браузера).
5. Переименовать файл в каталоге вложений вручную → плитка «Файл не найден», попап с
   сообщением, ни одного красного тоста при повторных рендерах.
6. Manager удаляет вложение — у Admin в соседнем окне/браузере плитка уходит в «Удалённые» без
   перезагрузки (D-15); «Восстановить» возвращает её.
7. Сотрудник в LAN: прикладывает файл к своей завершённой заявке; кнопки «Удалить» у чужого
   вложения нет.
8. HEIC с iPhone (вымышленный снимок, не рабочий) → плитка `.jpg` с миниатюрой.

## Решения на усмотрение UI-SPEC (Claude's Discretion CONTEXT, к подтверждению при проверке)

1. Место блока — перед первой секцией-историей во всех карточках (§6.1); у устройств — в
   «Просмотре» (`PlaceEntityViewModal`), не в форме редактирования.
2. События у устройств и принтеров — новая секция «История вложений» (§10.3), потому что общей
   audit-истории устройства в UI нет.
3. Удалённые вложения для Admin — раскрывашка в карточке родителя; глобального списка в
   настройках нет (§2, §9.3).
4. Ошибки загрузки — встроенный список, не тосты; успех загрузки — без тоста (§7.3, §7.4).
5. Диапазон лимита в настройках — 1–100 МБ (§11.2).
6. Строки истории — безличные формы («Приложен файл»), а не «приложил» из примера D-14, чтобы не
   угадывать род по ФИО (§10.1).
7. У администратора имя файла в истории остаётся кликабельным и для мягко удалённого вложения
   (расширение D-14 по D-17: Admin видит и открывает удалённые, §10.2).
