# Phase 41.3 Plan 05: Чтение вложений и доступ Summary

Единая точка авторизации вложений (`AttachmentService::authorize`), list с правами и флагом `missing`, `open_for_read` с путём только из хеша строки, событие `AttachmentsChanged` и подключение сервиса к `AppCtx` вместе с бэкапом блобов.

## Что сделано

- **Задача 1** (6c10e4ef): DTO без поля хеша; `WsEvent::AttachmentsChanged { parentKind, parentId, requestedByUserId }`, видимо Admin/Manager всегда, Employee только при совпадении автора (с `None` не видно никому из Employee). Тесты видимости и сериализации.
- **Задача 2** (135e47e5): `AttachmentService`. Родитель читается живой строкой (мягко удалённый или отсутствующий — `NotFound`, возвращается при восстановлении родителя). Request: Admin/Manager, Employee только автор в любом статусе. Device/Cartridge: только Admin/Manager; Employee — `Forbidden`. ManageDeleted — только Admin. `list`: `missing` вычисляется при чтении, удалённые строки только при `can_manage_deleted`. `open_for_read`: путь строится через `AttachmentStore` из валидированного хеша; нет файла — `NotFound{attachment_file}`. В `AppCtx::build` резолвится каталог, `ensure_dirs` (ошибка — остановка старта без паники), `with_ws_tx`, `with_attachments_dir` у `BackupService`.
- **Задача 3** (e49ece6a): 5 интеграционных тестов (`roles`, `parent_follow`, `bola_by_id`, `missing_file`, неизвестный вид родителя). Права Admin/Manager/Employee-автор, чужая заявка, устройство/принтер/картридж для Employee, id без доступа, исчезнувший блоб.

Критерий плана «grep AttachmentListDto в bindings.ts» поэтому отложен до регистрации команд.
