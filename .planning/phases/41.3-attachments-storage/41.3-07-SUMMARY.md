# Phase 41.3 Plan 07: Конвейер загрузки Summary

Загрузка вложений на уровне сервиса: приём в staging с потоковым лимитом, сниффинг сигнатуры, HEIC-хук, хеш итоговых байт, миниатюра, атомарный коммит блоба вместе со строкой и аудитом в одной транзакции писателя, событие после коммита.

## Что сделано

- **Задача 1** (00c60045): `authorize_attach`, `effective_limit` (min(настройка, 100 МиБ)), `begin_staging`, `StagedUpload::write_chunk`, `ingest`. Блокирующая стадия (`prepare`) под `Semaphore(2)`: голова 32 КиБ, полный буфер только для OLE2, sniff, HEIC (без фичи — `heic_failed`, расширение имени → `.jpg`), sha256 итогового файла, миниатюра с проглоченной ошибкой. Затем один `writer.execute`: вставка строки, `audit_log` `custom:attachment_added` (payload `attachment_id` + `name`), `commit_staged` (перенос только если блоба нет), `tx.commit`. `AttachmentsChanged` отправляется после `.await?` писателя (`let _ =`), вне замыкания. Имя: percent-decode, затем `sanitize_file_name`. В реестр `OUT_OF_SCOPE_WRITERS` добавлен `attachment_service.rs`.
- **Задача 2**: тесты конкурентности и укрепления лежат в том же файле и закоммичены вместе с задачей 1 (один файл, единый прогон): 8 параллельных загрузок одинаковых байт (`tokio::join!`) дают 8 строк и один блоб, `.tmp` пуст; отказы не оставляют временных файлов; имя с разделителями/CR/LF/кавычками санитизируется, путь блоба не содержит имени; PNG-бомба сохраняется файлом без миниатюры; мягко удалённый родитель — `NotFound`.
