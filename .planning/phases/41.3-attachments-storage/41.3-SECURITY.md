## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| конфиг → резолвер путей | `attachments_path` из TOML, правит администратор | путь хранилища (в т.ч. UNC) |
| загружаемые байты → sniff / декодеры | содержимое и имя файла полностью недоверенные | любые байты, имя файла |
| HEIC → libheif (C/C++) | недоверенные байты разбирает нативный код | HEIC-контейнер |
| хеш → путь на диске | путь строится только из проверенного hex | `content_hash` |
| вызывающий → родительский объект | Employee — только своя заявка (или участник) | `parent_kind`, `parent_id`, `id` вложения |
| LAN-браузер → axum | сессия + multipart / GET файла | тело загрузки, id |
| webview → схема `trackly-att` | путь URI под влиянием любого скрипта в webview | id и вид (`file` / `thumb`) |
| каталог вложений → папка бэкапа / новая папка БД | имена в исходном каталоге недоверенные | блобы |
| файловая система → разрушающий скан целостности | отмонтированный каталог выглядел бы как «всё сироты» | блобы, `.tmp` |
| данные сервера → DOM | имена файлов и людей из БД / `audit_log` | строки |
| рабочая копия → публичный репозиторий | файлы вложений, UAT, скриншоты | реальные данные (жёсткое условие проекта) |
| CI → vcpkg / crates | сторонние входы сборки | libheif, libde265, `infer`, `libheif-rs` |
