## Pattern Assignments

### `migrations/V050__attachments.sql` (migration, CRUD)

**Analog:** `migrations/V049__act_group_effects.sql` (последняя миграция; комментарий-шапка обязателен).

**Правила** (из шапки V049, строки 1-40): только `CREATE TABLE` / `CREATE INDEX`, ни одного `DROP`/перестройки (урок V042: refinery-транзакция + DROP родителя каскадно стирает детей); полиморфная ссылка БЕЗ FK и БЕЗ `CHECK` на `parent_kind` (валидация только в Rust, неизвестный токен деградирует при чтении); ссылки на `users` без FK.

```sql
-- V049 (образец оформления): комментарий «почему без FK / без CHECK», затем
CREATE TABLE act_group_effects (
    id                   INTEGER PRIMARY KEY AUTOINCREMENT,
    act_id               INTEGER NOT NULL,
    kind                 TEXT    NOT NULL,
    ...
    created_at_utc       INTEGER NOT NULL
```
Колонки для V050 (RESEARCH Pattern 1): `id`, `parent_kind TEXT NOT NULL`, `parent_id INTEGER NOT NULL`, `original_name`, `mime`, `size_bytes`, `content_hash` (sha256 hex), `uploaded_by_user_id NULL`, `created_at_utc`, `deleted_at_utc NULL`, `deleted_by_user_id NULL`; индексы `idx_attachments_parent(parent_kind,parent_id,created_at_utc,id)` и `idx_attachments_hash(content_hash)`. Принтер - строка `devices`, поэтому `parent_kind='device'` покрывает принтеры. `app_settings` уже есть - отдельной миграции под лимит не нужно (ключи `attachment_max_bytes`, `attachments_integrity_report`).

### `crates/trackly-infra/src/paths.rs` + `config.rs` (config, file-I/O)

**Analog:** сами файлы.

**Путь по `db_path`, а не по exe** (D-21): резолв делается в `AppCtx::build` рядом с `db_path` (см. `context.rs` строки 154-158):
```rust
let db_path: PathBuf = if !config.paths.db_path.is_empty() {
    PathBuf::from(&config.paths.db_path)
} else {
    paths.db_path().to_path_buf()
};
```
Новая строка по тому же шаблону: `attachments_path` непустой -> он, иначе `db_path.parent().join("attachments")`. Не использовать `dirs::*` (запрет `clippy.toml`).

**UNC (D-28 - РАЗРЕШЁН для вложений)**: `Paths::resolve_for_exe_dir` (paths.rs 43-58) отвергает UNC для exe_dir/БД - эту проверку для `attachments_path` НЕ копировать; в доках `paths.rs` зафиксировать отличие (WAL-ограничение не касается файлов вложений). Путь БД по-прежнему отвергает UNC.

**Конфиг** (`config.rs` 83-88). Новое поле ОБЯЗАНО иметь `#[serde(default)]`, т.к. у `db_path` field-level default нет:
```rust
#[derive(Debug, Deserialize, Clone, Default)]
pub struct PathsConfig {
    pub db_path: String,
    // + #[serde(default)] pub attachments_path: String,
}
```
`trackly.config.toml.example` проверяется `crates/trackly-infra/tests/config_example_test.rs` - пример (закомментированная строка в `[paths]`, стиль: single-quoted литерал `'D:\trackly-data\attachments'`) должен продолжать разбираться.

### `crates/trackly-app/src/services/attachment_service.rs` (service, CRUD + file-I/O + event-driven)

**Analog:** `services/request_service.rs` (структура, BOLA, `ws_tx`), `services/cartridge_service.rs::delete` (writer-транзакция + audit).

**Структура и конструктор** (request_service.rs 48-67): `writer`, `readers`, `clock`, репозитории как `Arc<dyn ...>`/`Arc<Sqlite...>`, `ws_tx: Arc<broadcast::Sender<WsEvent>>` (`pub(crate)`), подключается `.with_ws_tx(ws_broadcast.clone())` в `context.rs` (строки 229, 315-365).

**Авторизация read (BOLA, D-04)** - скопировать принцип из `RequestService::get` (request_service.rs 76-101):
```rust
if matches!(caller.role, trackly_core::auth::Role::Employee)
    && dto.requested_by_user_id != caller.user_id.unwrap_or(-1)
{
    return Err(AppError::Forbidden);
}
```
Единая точка `AttachmentService::authorize(parent, caller, intent)`; ВСЕ пути (list/file/thumb/upload/delete/restore/purge/HTTP GET/Tauri-протокол) идут через неё. Для `parent_kind='request'` - прочитать владельца заявки и применить этот же шаблон (можно вызвать `RequestService::get` или общий helper). Для device/cartridge: Employee -> `Forbidden` (D-27, deny-by-default); единая точка-заглушка `employee_can_read_device(...) -> false` с пометкой «открывает 41.6». Admin/Manager - проверка через `authorize(caller, &Action::...)` из `trackly_core::auth` (по образцу `tauri_cmds/requests.rs` 56-60). Родитель мягко удалён -> `NotFound`/`Forbidden` (D-19/D-26).

**Writer-транзакция + audit** (request_service.rs 540-567 / cartridge_service.rs 527-581):
```rust
self.writer.execute(move |conn| {
    let tx = conn.transaction().map_err(map_rusqlite)?;
    /* INSERT / UPDATE */
    audit_repo.insert(&tx, AuditEntry {
        entity_type: "request",           // 'request' | 'device' | 'cartridge'
        entity_id: parent_id,
        action: "custom:attachment_added", // _deleted / _restored / _purged
        user_id,
        before_json: None, after_json: None,
        payload_json: Some(r#"{"attachment_id":N,"name":"скан-акта.pdf"}"#.into()),
        created_at_utc: now,
    })?;
    tx.commit().map_err(map_rusqlite)?;
    Ok(...)
}).await?;
```
`AuditEntry.entity_type` - `&'static str` (audit_log_sqlite.rs 27-36), поэтому для parent_kind нужен match в литералы. Идемпотентные soft-delete/restore: `UPDATE ... WHERE deleted_at_utc IS [NOT] NULL` (version-колонки у таблицы нет).

**Rename temp -> `<h2>/<hash>` и физическое стирание по нулевому refcount - ТОЛЬКО внутри замыкания writer** (закрывает гонку upload-дубликата vs purge, Pitfall 3).

**Рассылка D-25** - ПОСЛЕ `.await?`, вне замыкания (request_service.rs 574-578; правило D-04 фазы 41.7 из `entities_broadcast.rs` 1-8):
```rust
let _ = self.ws_tx.send(WsEvent::RequestStatusChanged { request_id, new_status, requested_by_user_id: dto.requested_by_user_id });
```
Для вложений: `WsEvent::AttachmentsChanged { parent_kind, parent_id, requested_by_user_id: Option<i64> }`. Не использовать `send_entities_changed` и не вызывать `broadcast_entities` (дерево мест не перезагружать).

**spawn_blocking для тяжёлого** (request_service.rs 80-99): `tokio::task::spawn_blocking(move || {...}).await.map_err(|e| AppError::Internal{source_chain: format!("spawn_blocking: {e}")})??`. Декод/миниатюры/HEIC - под `Semaphore(2)`.

**Лимит и настройки**: `read_setting`/`upsert_setting` из `backup_service.rs` (строки 288-319) - скопировать (они приватные `fn`; вынести общий helper либо продублировать), запись лимита - `authorize(caller, &Action::ManageSettings)?` (backup_service.rs 177-181).

**Старт-скан (D-20)**: `tokio::spawn` после `AppCtx::build`, не блокирует старт; внутри `spawn_blocking`; ничего не удалять при недоступном каталоге (Pitfall 9); отчёт одной записью через writer в `app_settings` (`attachments_integrity_report`).

Авторизовать ДО чтения тела (см. RESEARCH Code Examples). **GET**: `/api/v1/attachments/{id}/file|thumb` через `ServeFile::new_with_mime(path, &mime).oneshot(req)`, пути строить только из `content_hash` строки БД. ## Shared Patterns

### Один сервис, два транспорта (S-1/S-2)
**Source:** `crates/trackly-app/src/tauri_cmds/requests.rs` 1-60 + `http/requests.rs` 1-12.
**Apply to:** `tauri_cmds/attachments.rs`, `http/attachments.rs`, `attachments_protocol.rs`.
Логика только в `AttachmentService`; Tauri-команда и axum-handler - тонкие адаптеры над общим `build_*`; identity: Tauri - `resolve_tauri_identity(ctx)`, axum - `session_identity(&session)` (`http/auth.rs`). WS-рассылку handler не дублирует.

### BOLA / D-REQ-01 (ядро безопасности)
**Source:** `services/request_service.rs` 76-101.
**Apply to:** каждый путь `AttachmentService` (list/file/thumb/upload/delete/restore/purge/history).
Employee + чужой родитель = `AppError::Forbidden`; знание id/хэша доступа не даёт. Тесты на оба транспорта (`build_*` и `oneshot(build_router)`), строки в `role_endpoint_matrix.rs` (образец кейсов 20-22: Employee -> 403 на чужую заявку).

### Единственная точка записи
**Source:** `WriterHandle::execute(move |conn| {...})` (request_service.rs 540-567).
**Apply to:** все мутации вложений. Транзакция `conn.transaction()` -> SQL + `audit_repo.insert` -> `tx.commit()`; файловые rename/remove для refcount внутри замыкания.

### Рассылка событий после коммита
**Source:** `services/entities_broadcast.rs` 1-12 (контракт) и request_service.rs 574-578.
**Apply to:** `attachment_service.rs` - `ws_tx.send(...)` после `.await?`, вне замыкания; best-effort (`let _ =`).

### Ошибки
**Source:** `trackly_core::error::AppError` (`Validation{field,message}`, `NotFound{entity,id}`, `Forbidden`, `Internal{source_chain}`), `map_rusqlite` (`trackly_infra::error_conversions`), `AppErrorResponse::from` на axum-стороне.
**Apply to:** весь Rust. Машинные коды причин отказа загрузки (`too_large`, `empty`, `type_not_allowed`, `heic_failed`, `forbidden`) передаются в поле `field`/коде, UI выбирает строку; текст сервера в UI не показывается.

### Приватность в тестах и .planning
**Source:** CLAUDE.md §Constraints, `scripts/check-privacy.mjs`.
**Apply to:** все фикстуры/тесты/примеры: вымышленные имена и сгенерированные байты; перед коммитом грепать артефакты.

### Токены и UI-гейты
**Source:** `ui/scripts/check-tokens.mjs`, `check-modal-isolation.mjs`, `check-contrast.mjs`, `check-action-menu-portal.mjs`.
**Apply to:** все новые `.svelte`. Только `var(--tr-*)`, без hex/`rgba()`; `pnpm lint` НЕ включает `svelte-check` - гонять отдельно.
