# Phase 41.3 Plan 10: Десктопный транспорт вложений Summary

Tauri-команды вложений (JSON + бинарная загрузка) и схема `trackly-att`, отдающая файлы и миниатюры через тот же `AttachmentService`, что и HTTP; окно без перехвата drag-drop.

## Что сделано

- **Задача 1** (94230c16): `build_attachments_{list,delete,restore,purge,history,get_limit,set_limit,report,upload}` и тонкие команды через `resolve_tauri_identity`. Имена совпадают с будущими маршрутами. В `build_attachments_upload` порядок: `authorize_attach` (строка 1) -> `effective_limit` и сравнение длины с лимитом -> `begin_staging`/`write_chunk` -> `ingest`; превышение лимита возвращает `reject_code = too_large` до записи на диск. Заголовки `x-att-parent-kind/-id/-name` декодируются percent_encoding; не-Raw тело - `Validation`.
- **Задача 2** (a7d063ba): `parse_uri` (только `/<цифры>/file|thumb`), `content_disposition` (ASCII-фолбэк без CR/LF/кавычек/`\`/`;` + `filename*`), `build_response` (Content-Type из БД с белым списком символов, nosniff, ACAO, Cache-Control), `error_response` (404/403/500 с пустым телом), `handle` (identity -> `open_for_read` -> чтение в `spawn_blocking`, потолок 100 МиБ). Регистрация `register_asynchronous_uri_scheme_protocol("trackly-att", ...)` в `main.rs`. `dragDropEnabled: false` в `tauri.conf.json` (D-05).

## Deviations from Plan

**1. [Rule 3 - Blocking] attachments_upload вне specta.** `tauri::ipc::Request` не реализует `specta::Type`, команда не компилировалась в `collect_commands!`. Решение: обычная `#[tauri::command]` без `#[specta::specta]`, диспетчер в `main.rs` (`generate_handler!` для upload + specta-обработчик для остальных). Следствие: в `bindings.ts` её нет (UI вызывает `invoke('attachments_upload', bytes, {headers})` ручной обёрткой), а `grep -c attachments_` по `specta_export.rs` равен 8, а не >= 9. Плану 11 учесть эту команду в таблице паритета вручную.

**2. [Rule 3] `#[allow(clippy::result_unit_err)]` на `parse_uri`** - сигнатура `Result<_, ()>` задана планом; любая ошибка разбора означает 404.
