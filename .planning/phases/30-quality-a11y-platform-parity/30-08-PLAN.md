<objective>
Закрыть Gap 3 (UAT re-run Test 3) — select-вариант Dropdown с поиском авто-фокусируется корректно
(подтверждено пользователем как работающее), но (1) показывает нежелательное синее кольцо фокуса на
всегда-сфокусированном поле поиска, и (2) ввод текста НЕ фильтрует список опций вообще ни для одного
существующего консьюмера («zero filtering» контракт компонента — консьюмер обязан фильтровать сам,
но ни один из 11 flat+select+searchable консьюмеров, мигрированных с нативного `<select>`, этого не
делает — все передают статический `groups` + no-op `onSearch={() => {}}`).

Purpose: QA-02 (ROADMAP SC #2 — видимое, не шумное кольцо фокуса; клавиатурная доступность списка
через реальную фильтрацию, а не декоративное поле). Root cause (диагностировано, не гипотеза): (1)
`.tr-dropdown-search-input:focus-visible { box-shadow: 0 0 0 2px var(--tr-focus-ring); }`
(Dropdown.svelte) рисует кольцо КАЖДЫЙ раз, когда панель открыта, потому что Gap-3-эффект (уже
существующий `$effect`, Dropdown.svelte:572-582, из предыдущего раунда 30-04) переводит DOM-фокус в
поиск немедленно при открытии — кольцо видно ВСЕГДА, а не как реакция на клавиатурную навигацию,
поэтому воспринимается как визуальный шум, а не accessibility-сигнал. (2) Dropdown — намеренно
«zero data-fetching» примитив (props doc: «Current, already-filtered group/option list — Dropdown
performs zero data-fetching itself», строки 45-47) — фильтрация всегда была ответственностью
консьюмера через `onSearch`. Ни один из 11 select+flat+searchable консьюмеров (найдено grep'ом:
CartridgeFilters, CartridgeFormBody×3, ModelFormModal×2, BackupSettings, TemplateEditor,
NetworkSettings, RequestFormModal, RequestDetail, UserFormModal, CartridgeSelect) этого не
реализовал — все передают статический `groups` и `onSearch={() => {}}`. Вместо правки 11 файлов по
отдельности (широкий, рискованный diff), этот план добавляет ОДНУ внутреннюю, опциональную
клиентскую фильтрацию в сам Dropdown.svelte (активна только когда `variant === 'select' && flat &&
searchable`, что покрывает все 11 существующих потребителей без единой правки в консьюмерах) —
тот же «widest blast radius» подход, что уже применён в 30-02 (TableRow chevron) и 30-05 (TableRow
row-ring).

Output: `Dropdown.svelte` без визуального кольца на search-input (whitelisted через
`check-focus-outline: ignore`) + встроенная фильтрация `visibleGroups`; `CartridgeFilters.svelte`'s
«Тип»-фильтр с `searchable={false}`.
</objective>
