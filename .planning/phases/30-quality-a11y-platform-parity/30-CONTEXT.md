## Phase Boundary

Финальная фаза milestone v1.2. Доводит переработанный UI (все окна Фаз 23–29) до планки
**доступности** (WCAG AA-контраст в обеих темах + видимое кольцо фокуса на **всех**
интерактивных элементах) и **визуального паритета** между Tauri WebView и LAN-браузером.
Требования: **QA-02**, **QA-03**.

**Ключевой факт из скаута (меняет характер фазы — это audit/gap-closure, не построение):**
- **Инфраструктура фокуса уже есть.** `ui/src/styles/global.scss:40` содержит глобальный
  `*:focus-visible { outline: none; box-shadow: 0 0 0 3px var(--tr-focus-ring); }`, плюс
  skip-link (`global.scss:71`). Токены `--tr-focus-ring` / `--tr-danger-ring` определены для
  светлой (`_tokens.scss:21/55`) и тёмной (`_tokens.scss:98/132`) тем. Примитивы (Button, Input,
  Checkbox, Dropdown, Modal, DatePicker, ActionMenu) сами переприменяют кольцо. Значит риск QA-02
  — **не «нет колец»**, а «кольцо гасят локальным `outline:none` без замены» и «box-shadow-кольцо
  режется `overflow:hidden`» (строки таблиц, списки Dropdown). У `ui/src/lib/components/Tabs.svelte`
  своего `focus-visible` нет.
- **Токен-контраст централизован.** Все цвета идут через `--tr-*` из `_tokens.scss`; правка одного
  токена расходится по всему UI (и по обеим темам) — но может увести от палитры Claude Design.
- **Фронтенд-тестов нет.** Гейты milestone — `pnpm lint` (вкл. `check-tokens.mjs`), `svelte-check`,

  (closed-world, роняют сборку). Both-theme визуальный UAT-чекпоинт — прецедент Фаз 26–29.
- **Dev-среда macOS:** Tauri = WKWebView; Windows/WebView2 тестируется на отдельной машине
  (память проекта: AD/принтеры/Windows недоступны с dev-мака).

**В границах фазы:**
- **QA-02 контраст:** durable-скрипт, считающий WCAG-отношения по парам токенов из `_tokens.scss`
  (обе темы); падает при <AA. Починка провалов — правкой центрального токена; крупный текст (3:1) —
  документированное исключение (D-01).
- **QA-02 фокус:** сохранить глобальный baseline; аудит по типам интерактива на два дефекта (голый
  `outline:none` без замены; кольцо, режущееся `overflow:hidden`); точечная починка найденного,
  включая переход на inset-ring там, где клип неизбежен (D-02).
- **QA-03 паритет:** side-by-side WKWebView ↔ LAN Chrome на маке, репрезентативная выборка
  (дашборд, устройства, акты, логин), обе темы; Windows/WebView2 — документированный best-effort

- **Форма сдачи:** гибрид — автогейт (скрипт контраста + лёгкий линт на голый `outline:none`) +
  финальный both-theme ручной UAT (D-04).
- Обе темы (светлая и тёмная) — унаследовано от D-17 Фазы 26.

**Вне границ:**
- **Любое изменение полей, действий, workflow, бизнес-логики, API, бэкенда** — фаза чисто
  качественная/визуальная. Правки касаются только токен-значений, focus-стилей и мелкой полировки
  ради паритета.
- **Редизайн раскладок / компонентов** — паритет и AA достигаются точечно, не переработкой.
- **Полноценная мобильная адаптивность** экранов, не покрытых WIN-12.
- **Реальный прогон паритета на целевом Windows/WebView2 как блокирующий критерий фазы** — только
  документированный чек-лист (D-03); фактический прогон — на отдельной Windows-машине вне dev-мака.
- **Рабочий SSO / прочие функциональные заглушки** — вне QA-фазы.

<decisions>
## Implementation Decisions

### Серая зона A — AA-контраст: метод проверки + политика починки

- **D-01:** **Durable-скрипт по токен-парам.** Новый `ui/scripts/check-contrast.mjs` (по образцу
  `check-tokens.mjs`/`verify-value-map.mjs`) парсит `_tokens.scss`, считает WCAG-отношения для
  осмысленных пар «текст на фоне» в **обеих темах** и **падает при <AA** (4.5:1 обычный текст,
  3:1 крупный). Подключается в `pnpm lint`/CI. При провале — **правим центральный токен** в
  `_tokens.scss` (глобальный эффект, обе темы); для крупного текста допускается **документированное
  исключение 3:1** (с явным списком пар-исключений в скрипте/комментарии).
  **Обоснование:** совпадает со скрипт-гейтовым паттерном проекта, даёт регресс-защиту на закрытии
  milestone; централизованные токены делают правку по одному месту. Отклонены ручной чек-лист (нет
  регресс-защиты) и только axe/devtools (разово, только текущие состояния).
  **Действие для планировщика:** определить каноничный набор пар текст↔фон (какие `--tr-text-*` на
  каких `--tr-surface-*`/`--tr-accent`/семантике реально встречаются) — скрипт видит только пары
  токенов, не фактические наложения; недостающее добирается глазами на UAT. Свериться с
  `23-UI-SPEC.md` (все hex обеих тем). Правку токена под AA согласовать с палитрой Claude Design —
  если AA требует заметного сдвига, вынести на человеческий чекпоинт.

### Серая зона B — Кольцо фокуса: охват аудита

- **D-02:** **Baseline + тип-аудит + фикс клипов.** Глобальный `*:focus-visible` (`global.scss:40`)
  **сохраняется** как safety-net. Аудит по **типам интерактива** (button, input/select/textarea,
  checkbox, link, table-row, tab, dropdown-item, menu-item) на **два дефекта**:
  (1) локальный `outline:none` без замены на видимое кольцо;
  (2) `box-shadow`-кольцо, режущееся родительским `overflow:hidden` (строки таблиц, панели Dropdown,
  Tabs). Точечно чиним найденное; где клип неизбежен — переходим на **inset-ring**
  (`box-shadow: inset 0 0 0 2px …`) или `outline` с `outline-offset`, чтобы кольцо не обрезалось.
  Известные кандидаты: `Tabs.svelte` (нет своего `focus-visible`), строки таблиц/`Dropdown` внутри
  `overflow:hidden`.
  **Обоснование:** baseline уже покрывает «кольцо на всём», поэтому полный поэлементный проход
  избыточен; реальная работа — найти, где baseline **гасится** или **режется**. Отклонены полный
  ручной поэлементный аудит (дорого, baseline снимает бóльшую часть) и только-точечный-фикс (риск
  пропустить неочевидное без систематического перечня типов).
  **Действие для планировщика:** составить перечень интерактивных типов и их файлов-владельцев;
  grep на `outline:\s*none` и на `overflow:\s*hidden` в контейнерах интерактивных строк — как
  отправная карта аудита.

### Серая зона C — Паритет платформ (QA-03)

- **D-03:** **Мак: WKWebView ↔ LAN Chrome сейчас; Windows/WebView2 — best-effort.** В фазе
  проверяем Tauri (WKWebView на маке) против LAN-браузера (Chrome) на **репрезентативной выборке
  из SC**: дашборд, устройства, акты, логин — **в обеих темах**, side-by-side скриншотами.
  Определение «идентично»: **одинаковая раскладка, токены и отсутствие дивергенции нативных
  контролов**; допустимая разница — рендер шрифта и вид скроллбара (платформенное, не баг).
  Прогон на целевом **Windows/WebView2** оформляется как **документированный чек-лист** для отдельной
  машины и **не блокирует** закрытие фазы на маке.
  **Обоснование:** dev-мак физически не имеет WebView2; требовать его в фазе — блокировать закрытие
  milestone. Отклонены «требовать Win/WebView2 в фазе» (блокер, нет машины) и «только desktop»
  (не закрывает QA-03 по сути — паритет именно про два вьюпорта).
  **Действие для планировщика:** гоча-напоминание — LAN-браузер отдаёт `ui/dist`, поэтому перед
  паритет-проверкой обязателен `pnpm --dir ui build` (а `prebuild` тянет `cargo test … export_bindings`);
  `cargo tauri dev` хотрелоадит только desktop-webview. Зафиксировать список окон и обеих тем как
  явный UAT-скоуп. Windows-чек-лист положить как артефакт фазы (напр. `30-...WINDOWS-PARITY.md` или
  секцию UAT-хендоффа).

### Серая зона D — Форма сдачи

- **D-04:** **Гибрид: автогейт + ручной UAT.** Durable-часть — скрипт контраста (D-01) в `pnpm lint`/CI
  **плюс лёгкий линт-гейт на голый `outline: none`** (эвристика: `outline:none` без сопутствующего
  `box-shadow`/`outline` фокус-кольца — по образцу правил `check-tokens.mjs`). Ручная часть —
  **финальный both-theme визуальный UAT-чекпоинт** (прецедент Фаз 26–29), который ловит то, что
  машина не видит: реальные клипы колец (D-02) и паритет WKWebView↔Chrome (D-03).
  **Обоснование:** контраст и голый `outline:none` машина ловит надёжно и даёт регресс-защиту на
  закрытии milestone; клипы/наложения/паритет требуют глаз. Отклонены «только ручной UAT» (нет
  регресс-защиты после фазы) и «только автоскрипты» (клипы и паритет не видны машине).
  **Действие для планировщика:** линт на `outline:none` — эвристика с риском ложных срабатываний;
  предусмотреть whitelist/inline-исключения (как у прочих скрипт-гейтов). Чекпоинт UAT — блокирующий,
  не авто-продвигаемый (урок Фазы 24: авто-одобрение маскировало непроверенное, ложный `[VERIFIED]`).

### Claude's Discretion
- Точный набор канонических пар текст↔фон для `check-contrast.mjs` и точные пары-исключения крупного
  текста (D-01) — выводятся из `_tokens.scss` + `23-UI-SPEC.md` + фактических сочетаний в окнах.
- Точная реализация inset-ring vs `outline`+`outline-offset` там, где кольцо режется клипом (D-02) —
  по месту, без изменения раскладки.
- Форма и размещение Windows-паритет-чек-листа (отдельный файл vs секция UAT-хендоффа) (D-03).
- Эвристика линта на голый `outline:none` и механизм исключений (D-04).
- Дробление на волны/планы (прецедент D-19 Фазы 26: скрипт-гейты/общие артефакты — первыми; затем
  аудит-починка по окнам; финальный UAT-чекпоинт последним).
- Конкретные значения токенов при правке под AA — из `_tokens.scss`/`23-UI-SPEC.md`; заметный сдвиг
  от палитры Claude Design выносится на человеческий чекпоинт.

</decisions>

## Existing Code Insights

### Reusable Assets
- **`global.scss:40` глобальный `*:focus-visible`** — safety-net кольца на всём; фаза его сохраняет
  и точечно чинит места, где он гасится/режется (D-02).
- **Токены `--tr-focus-ring`/`--tr-danger-ring`** обеих тем уже в `_tokens.scss` — новых токенов
  фокуса, скорее всего, не нужно.
- **`check-tokens.mjs`/`verify-value-map.mjs`** — готовый шаблон скрипт-гейта для `check-contrast.mjs`
  и линта `outline:none`.
- **Both-theme UAT-чекпоинт Фаз 26–29** — готовый паттерн финального ручного гейта.

### Established Patterns
- Стили — scoped `<style lang="scss">` в каждом компоненте; фокус-кольцо через
  `box-shadow: 0 0 0 3px var(--tr-focus-ring)` на `&:focus-visible` (Button/Input/Checkbox/Dropdown/
  Modal/DatePicker/ActionMenu уже так делают).
- **Фронтенд-тестов нет.** Гейты: `pnpm lint` (вкл. `check-tokens.mjs`), `pnpm svelte-check`,
  `pnpm --dir ui build`. Визуал — только глазами.
- **`:global()` в plain `.scss` не работает** (урок Фазы 24) — учесть при добавлении focus-фиксов.

### Integration Points
- **Скрипт-гейты** подключаются в `ui/package.json` → `scripts.lint`
  (`eslint … && prettier --check . && node scripts/check-tokens.mjs`) — сюда добавляются
  `check-contrast.mjs` и линт `outline:none` (D-01/D-04).
- **`Tabs.svelte`** (нет своего `focus-visible`) и строки таблиц/`Dropdown`-панели в `overflow:hidden`
  — первичные кандидаты аудита клипов (D-02).
- **Гоча паритета (память проекта):** перед проверкой LAN-браузера обязателен `pnpm --dir ui build`
  (серверный режим отдаёт `ui/dist`); `prebuild` тянет `cargo test -p trackly-app --test export_bindings`;
  `cargo tauri dev` хотрелоадит только desktop-webview (D-03).
