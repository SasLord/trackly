обрезается) — оба из блокирующего UAT re-run 30-03 Task 3, оба в общем примитиве `TableRow.svelte`
(плюс `Table.svelte` для Gap 7), поэтому один план вместо двух параллельных (во избежание
конфликтующих правок одного файла в разных волнах).

Purpose: QA-02 (ROADMAP SC #2 — согласованная, видимая, не обрезаемая модель кольца фокуса таблиц).

Gap 9 root cause (диагностировано, не гипотеза): `.tr-row:has(:focus-visible) :global(> td)` (и
парные `:first-child`/`:last-child`/`.selected` варианты) срабатывают от ЛЮБОГО фокусируемого
потомка строки — это было НАМЕРЕННЫМ поведением плана 30-05 для строк с единой точкой входа
(первая ячейка Актов/Картриджей/Принтеров/Заявок). Но `.tr-row-group` (групповые строки Устройств,
`DeviceGroupRow.svelte`) НЕ задуманы как row-focusable в принципе — единственный фокусируемый
элемент там — сам `.tr-row-chevron`, у которого уже есть collственное inset-кольцо (`&:focus-visible
{ box-shadow: inset 0 0 0 2px var(--tr-accent); }`, добавлено планом 30-02). Селектор `:has()` не
делает разницы между «строка со своей единой точкой входа» и «строка, где единственный фокусируемый
элемент — маленькая toggle-кнопка», поэтому фокус на шевроне ЗАПУСКАЕТ ОБА кольца одновременно
(узкое на кнопке + широкое на всей строке) — визуальное дублирование, которого нет ни в одной другой
таблице приложения. Плюс `.tr-row-chevron` (18×18px кнопка) не имеет `border-radius` вообще —
квадратные углы у его собственного inset-кольца, не совпадающие со скруглённым дизайном остальных
маленьких кнопок (кебаб уже скруглён, `var(--tr-radius-xs)`).

Gap 7 (3-я по счёту диагностика этого класса дефекта — предыдущие 30-02/30-05 фиксы не закрыли его
в конкретно master-detail списках): инсет box-shadow МАТЕМАТИЧЕСКИ не может выступать за пределы
padding-box элемента, на котором он объявлен (это и есть определение `inset`) — поэтому теория
«внешний overflow:hidden клипает inset-кольцо» некорректна сама по себе; наблюдаемый клип — известный
рендеринг-артефакт WebKit/WKWebView, когда inset box-shadow объявлен на ТОМ ЖЕ элементе, который сам
имеет `overflow: hidden` (здесь: `PrinterListRow.svelte`'s `.cell-name { overflow: hidden; max-width:
0; }` — необходим для work-around'а `text-overflow: ellipsis` в `table-layout: auto` ячейках, НЕ
может быть убран без риска сломать сжатие колонки) — рендерер иногда обрезает ближний край
inset-тени ровно на границе, где элемент клипует сам себя. Практический фикс (тот же, что указан в
UAT missing-пункте): дать физический запас между истинным краем таблицы и краем клип-контейнера
(`Table.svelte`'s `.tr-table-wrapper`, ранее без единого пикселя padding) — небольшой горизонтальный
padding поглощает субпиксельную рендеринг-неточность, не давая границе кольца и границе клипа
совпадать буквально в одной точке.

Output: `TableRow.svelte` с `:not(.tr-row-group)` во всех 4 row-wide-ring селекторах +
`border-radius` на `.tr-row-chevron`; `Table.svelte` с небольшим `padding` на `.tr-table-wrapper`.
