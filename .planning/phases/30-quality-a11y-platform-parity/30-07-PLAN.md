Purpose: QA-02 (ROADMAP SC #2 — видимое, не обрезаемое, не «прилипающее» кольцо фокуса) и QA-03
(ROADMAP SC #3 — desktop↔LAN layout-паритет; изолированный скролл контентной области — часть
паритетного контракта, WKWebView и LAN Chrome должны вести себя идентично относительно того, ЧТО

Gap 1 (3-я итерация): 30-06 заменил outward-кольцо на inset (`box-shadow: inset 0 0 0 2px
var(--tr-accent)`), что устранило КЛИП (кольцо больше не обрезано сверху границей карточки), но
`.toggle-btn`'s `padding: 2px 1px 5px` оставляет только 1px горизontального запаса — inset-кольцо
рисуется ВНУТРИ бокса, поэтому при 1px паддинге оно вплотную прилегает к глифам текста «3 мес.» —
разные дефекты (клип vs. запас), 30-06 закрыл только первый.

Gap 2 (3-я итерация, диагностировано глубже, не гипотеза): 30-06 добавил `min-height: 0` на
`.dashboard-grid` (тот же класс фикса, что уже работал в ActsPage.svelte FIX B1 и Phase 29
EmployeeLayout commit 61feaa7) — это НЕ закрыло гэп, потому что реальная причина на этот раз лежит
на уровень выше, в `Layout.svelte`, а не в `DashboardPage.svelte`. `.app-layout { display: grid;
grid-template-columns: var(--sidebar-width) 1fr; height: 100vh; overflow: hidden; }` не объявляет
`grid-template-rows` — единственная implicit-строка получает CSS Grid default `auto`-размер, который
вычисляется по MAX-CONTENT вкладу элементов строки (`.sidebar-container`/`.content`). Это отдельный
механизм от «automatic minimum size» (который клэмпит MIN-размер grid-item к 0 при
overflow!=visible) — max-content вклад НЕ клэмпится overflow:auto/hidden потомков, он использует
полную, неклиппированную высоту содержимого. `DevicesPage`/`PrintersPage`/`ActsPage` не показывают
этот гэп не потому что `Layout.svelte` для них работает иначе (структура идентична), а потому что их
контент (виртуализированные/постраничные списки, MasterDetail с собственным definite-height
containment) на практике не создаёт max-content вклад настолько большой, чтобы превысить 100vh.
Дашборд — единственный маршрут, где ВСЕГДА полностью отрендерены 4 `StatWidget` (min-height 120px
каждый) + `ChartWidget` (min-height 220px) без виртуализации, поэтому его полная содержимое-высота
рутинно превышает 100vh на обычных экранах, обнажая гэп в grid-row-sizing, который остаётся скрытым
на других страницах. Фикс: `grid-template-rows: minmax(0, 1fr)` делает единственную строку гибкой
(`fr`) — по спецификации CSS Grid `fr`-треки получают долю ДОСТУПНОГО (заданного, 100vh)
пространства контейнера, а НЕ max-content-based размер, поэтому `.content` получает истинную
definite stretch-height 100vh независимо от содержимого потомков. Дополнительно (по прямому
указанию UAT root-cause «missing»-поля) `.content` переводится на `display: flex; flex-direction:
column;`, завершая definite-height цепочку сверху вниз до `DashboardPage.svelte`'s `.dashboard-page
{ height: 100%; }` (не трогается в этом плане — уже корректен).

Output: `PeriodToggle.svelte` с `padding: 2px 8px 5px` на `.toggle-btn`; `Layout.svelte` с
`grid-template-rows: minmax(0, 1fr)` на `.app-layout` и `display: flex; flex-direction: column;` на
`.content`.
