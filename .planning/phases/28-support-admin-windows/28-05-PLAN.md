  <action>
    Заменить raw `<input class="form-input" type="number">` на `<Input type="number" id="threshold-
    input" value={String(threshold)} oninput={(v) => (threshold = Number(v) || 0)} />`. **Важно:
    `Input.svelte` не имеет `onblur`-пропа и не форвардит произвольные DOM-события** — текущее
    поведение «сохраняется автоматически при потере фокуса» реализовано через нативный
    `onblur={saveThreshold}` на `<input>`. **Нативное DOM-событие `blur` НЕ всплывает** — оборачивание
    `<Input>` в `<div onblur={saveThreshold}>` НЕ СРАБОТАЕТ (частая ошибка спутать `blur` с
    `focusout`; НЕ использовать этот подход). Два корректных варианта: (а) обернуть `<Input>` в
    `<div onfocusout={saveThreshold}>` — `focusout`, В ОТЛИЧИЕ ОТ `blur`, ВСПЛЫВАЕТ по DOM, событие с
    внутреннего `<input>` дойдёт до wrapper-div; ОБЯЗАТЕЛЬНО проверить в браузере, что toast «Порог
    обновлён» появляется при потере фокуса, прежде чем считать задачу выполненной; либо (б) сохранить
    нативный `<input type="number">` для ЭТОГО единственного поля с локальными `.form-input`-стилями
    как оправданное raw-исключение (низкий риск, единственное место в фазе, где примитив не покрывает
    нужный API 1:1) и задокументировать решение в SUMMARY. Предпочтителен вариант (а) при условии, что
    `focusout`-всплытие подтверждено рабочим в браузере; если нет — использовать (б), не тратить время
    на дальнейшую отладку всплытия. Значение суффикса «штук» и helper-text — KEEP дословно.
    `saveThreshold`/`onMount`-логика — НЕ менять.
  </action>
