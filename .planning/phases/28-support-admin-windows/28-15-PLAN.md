<objective>
Diagnose GAP-4 (28-VERIFICATION.md): «Отчёты -> Устройства -> Возвраты» shows «Не удалось
загрузить отчёт». Static analysis (this plan's own investigation, cross-referencing the DB schema,
the DTO, the SQL, and `git blame`) found a high-confidence root cause that is backend/data, NOT a
Phase 28 frontend regression:

- `migrations/V004__acts.sql` declares `acts.sub_number` as `INTEGER NULL` (line 13).
- `dto/reports.rs`'s `ReportRow.sub_number` is typed `Option<String>` (line 63).
- `report_service.rs`'s `query_acts_inner` SQL (shared by BOTH `list_device_acts` [act_type=
  "handover"] and `list_device_returns` [act_type="return"]) selects `a.sub_number` RAW —
  unlike the adjacent `number` column, which IS explicitly cast: `CAST(a.number AS TEXT) as
  number`. rusqlite's `FromSql` for `String` requires the underlying SQLite value to be `Text`;
  when a row actually has an `INTEGER` in `sub_number` (which only ever happens for **return**
  acts — handover acts always have `sub_number = NULL`, so `Option<String>` sees `Null` and
  succeeds trivially), the conversion fails at the driver level, producing an `AppError::Internal`
  that surfaces to the frontend as the generic "Не удалось загрузить отчёт" toast — for the
  Возвраты (returns) report ONLY, exactly matching the reported symptom.
- `git blame` confirms this exact SQL line (`a.sub_number, \`, no CAST) was introduced in commit
  `aa7ca3f5` (2026-06-16, "feat(07-03): implement ReportService with 8 report queries") — Phase 7,
  months before Phase 28. **This predates Phase 28 and was not introduced by this phase's
  frontend-only work.**

Per the gap-closure routing rule ("if backend/data, hand to /gsd-debug rather than guessing"),
this plan's job is to (1) prove the diagnosis with an automated regression test using a real
SQLite DB + real `ActService`/`ReportService` (not guessing), and (2) get an explicit human
decision on whether to apply the trivial, well-understood 1-line SQL fix now (same `CAST(...AS
TEXT)` treatment already used for the `number` column) or defer to `/gsd-debug` as a separate
follow-up outside Phase 28's declared visual-only boundary.

Purpose: resolve the ambiguity in "predates the phase or not" with evidence, not speculation, and
respect the phase's backend-change boundary via an explicit checkpoint rather than silently
patching Rust code.
Output: a reproducible regression test; a human-confirmed decision; if approved, the 1-line CAST
fix applied and the test flipped to green.
</objective>
