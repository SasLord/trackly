<objective>
Close GAP-2 (28-VERIFICATION.md): the Заявки master/detail panels overflow off-screen instead of
filling available height with bottom padding, and the request list overflows horizontally, hiding
the «Автор»/«Статус» columns. Root-cause analysis (this plan's diagnostic read) found the actual
defect is NOT in `RequestsMasterDetail.svelte`/`RequestsList.svelte`/`RequestListRow.svelte`'s
Table/TableRow wiring — those already match `ActsMasterDetail`/`ActsList`/`ActListRow` byte-for-byte
(plans 28-01/28-02 already ported the FIX B1 flex-fill pattern correctly at that layer). The actual
defect is one level up: `RequestsPage.svelte`'s `.page-content` wrapper is missing the flex
container properties (`display: flex; flex-direction: column; min-height: 0;`) and uses `overflow:
auto` (both axes) instead of `overflow-x: auto; overflow-y: hidden` — unlike `ActsPage.svelte`'s
`.page-content`, which already has this exact fix. Without it, `RequestsMasterDetail`'s own `flex:
1 1 auto; min-height: 0` has no effect (flex properties only apply to children of a flex/grid
container), so the whole `.master-detail` block sizes to natural content height and the ENTIRE
page scrolls, instead of the Table/DetailPanel scrolling internally within a height-bounded panel.
Separately, the request row's `cell-type` column (two badges: type + optional "Восстановление
доступа") has no width budget, so on typical panel widths it can push «Автор»/«Статус» past the
visible area, requiring horizontal scroll that most users don't notice.

Purpose: fix the real root cause (page-level flex context), not just re-verify already-correct
child-level CSS, and give the Автор column a guaranteed width share.
Output: RequestsPage.svelte matches ActsPage.svelte's page-content pattern; RequestListRow.svelte
has a width budget across its 4 columns; both verified in a human checkpoint (light + dark).
</objective>
