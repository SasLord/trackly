<objective>
D-CAT-01: категория заявки должна (а) отображаться текстовым названием из `request_categories.name`, а не числовым `category_id`, и (б) выдаваться формой создания через серверный список `{ id, name }` (оба транспорта), чтобы форма слала корректный `category_id` вместо хардкода.

Purpose: UAT-находка после Phase 9/10 — деталь заявки рисует число «3» вместо «Программное обеспечение». Имя категории — производное от FK, считается на сервере (как `requester_name`), один read-путь покрывает все запросы заявок. Вторая половина D-CAT-01 (locked в CONTEXT строка 24): список категорий должен возвращать `{ id, name }`; сейчас `requests_categories_list`/`requests_list_categories` отдаёт `SELECT name` → `string[]`, а `RequestFormModal.svelte` держит хардкод-массив `CATEGORIES` (строки ~41-46) — анти-паттерн (PATTERNS строки 168-172).
Output: `category_name` прокинут через `RequestRow` → `RequestDto` → `RequestDetail.svelte`; LEFT JOIN добавлен последним столбцом без сдвига индексов. Эндпоинт категорий мигрирует на `Vec<RequestCategoryDto { id, name }>` в оба транспорта, биндинги регенерированы, `RequestFormModal.svelte` потребляет серверный список и хардкод-массив УДАЛЁН.
</objective>
