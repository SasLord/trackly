<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| service-layer broadcast → per-client WS | `is_visible_to(&identity)` на сервере решает, кому уходит каждое событие. |
| WS-событие → webview (тост/нотификация) | Клиентская фильтрация — только UX, НЕ безопасность. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-03-I | Information Disclosure (BOLA) | WsEvent::is_visible_to RequestStatusChanged | mitigate | Серверный split-arm: `identity.user_id == Some(requested_by_user_id)` — сотрудник получает ТОЛЬКО свои события статуса. Unit-тест на 3 кейса (автор→true, чужой→false, admin/manager→true) — обязательный regression guard (D-RBAC-03). Клиентская проверка не заменяет серверную. |
| T-11-03-E | Elevation of Privilege | client-side filter как защита | mitigate | НЕ полагаться на клиент: фильтр в is_visible_to на сервере. Если бы прошёл всем employee — утечка статусов чужих заявок (anti-pattern явно запрещён). |
| T-11-03-T | Tampering (XSS) | Notification body / тост текст | mitigate | `statusToastText` возвращает фиксированные RU-строки (не пользовательский ввод); `new Notification(..., {body})` принимает plain text, не HTML; Svelte-тост автоэкранирует. |
| T-11-03-D | DoS / permission-abuse | Notification.requestPermission | accept | Деликатный запрос только по жесту пользователя (после отправки заявки), один раз; браузер сам ограничивает повторы. Низкий риск на LAN. |
| T-11-03-SC | Tampering | npm/cargo installs | mitigate | Новых пакетов нет (RESEARCH §Package Legitimacy: N/A) — Notification/Page Visibility — браузерные стандарты, не пакеты. Install-задач нет. |
</threat_model>
