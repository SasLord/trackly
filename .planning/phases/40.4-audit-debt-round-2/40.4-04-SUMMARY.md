# Phase 40.4 Plan 04: Автоподстановка номера не блокирует массовое создание Summary

**Автоподставленный (не тронутый) инвентарный номер больше не блокирует «Количество» в форме устройства/принтера — `NumberTemplateField` прокидывает наружу готовый NUM-07 компаратор `onEditedByHandChange`, а bulk-payload для qty>1 безусловно несёт `inventory_no: null`, так что серверный guard `bulk_create_with_printer` не отклоняет запрос.**

## Accomplishments

- `NumberTemplateField.svelte` exposes a new `onEditedByHandChange?: (editedByHand: boolean) => void` prop, fired from a dedicated `$effect` on every change of `!isValueUnedited()` — reuses the existing NUM-07 string-equality comparator verbatim, no new heuristic.
- `DeviceFormBody.svelte`'s create-mode `quantityDisabled` now reads `(inventoryNo.trim() !== '' && inventoryNoEditedByHand)` instead of the bare `inventoryNo.trim() !== ''` — an autofilled-but-untouched number no longer blocks «Количество», while a hand-typed/edited number still does (CR-02/40.3-07 regression preserved: `serialNo`/`ipAddress` conditions untouched).
- `handleSubmit`'s qty>1 branch now builds `DeviceNew.inventory_no: null` unconditionally (was `inventoryNo.trim() || null`) — closes the critical regression risk flagged in RESEARCH.md/PATTERNS.md: without this, the newly-unblocked bulk path would hit the server's `bulk_create_with_printer` guard (`count > 1` + non-empty `inventory_no` → `AppError::Validation`) on every real attempt.
- Deviation: fixed a build-blocking specta annotation gap in `CsvImportReport.affected_place_ids` (introduced by 40.4-02, same wave, different plan) that broke `ui`'s `prebuild` step (`cargo test --test export_bindings`) and therefore this plan's own `pnpm build` verification gate.

## Decisions Made

- Followed RESEARCH.md's explicit recommendation: unconditional `null` for the bulk-create `inventory_no`, not a conditional based on `inventoryNoEditedByHand` — count of ANY autofilled number is meaningless for bulk-create regardless of edited state, since the server can't assign N distinct numbers in a single call.
- Kept `serialNo`/`ipAddress` conditions in `quantityDisabled` untouched — those are plain, non-autofilled fields; only the template-backed `inventoryNo` needed the "edited by hand" distinction.
