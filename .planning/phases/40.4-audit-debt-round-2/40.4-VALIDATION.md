## Sampling Rate

- **After every task commit:** targeted `cargo test -p <crate> <module>` для затронутых файлов,
  или `pnpm --dir ui lint` для UI-задач
- **After every plan wave:** full suite command (полный прогон пакета, не «зелено по своим
  файлам» — project memory `executor_file_scope_vs_package_gate`)
- **Before `/gsd-verify-work`:** full suite зелёный + живая UAT в `cargo tauri dev` для N-3
  (инвалидация дерева) и NEW-3 (массовое создание). Playwright/Chromium-харнесс НЕ засчитывается
  как верификация Svelte-рантайма (project memory `synthetic_harness_not_verification`)
- **Max feedback latency:** 300 s

### Поправка к REVIEW.md

WR-01 предлагал воспроизвести расхождение правкой номера родителя **через сервисный API**.
Это не работает: `act_service.rs:1222` каскадит новый номер на дочерние акты возврата
(«cascade the new number to any child return acts»), поэтому через публичный API две
величины держатся синхронно. Расхождение живёт в ДАННЫХ — строки, переименованные до
появления каскада, и любая правка номера в обход сервиса. Фикстура G4 воспроизводит именно
это (прямой `UPDATE` родителя), а ожидаемый номер нигде не захардкожен: и канонический, и
«устаревший» варианты вычисляются из значений, прочитанных обратно из сервиса — фаза 40.5
переработает нумерацию суффиксов (плотные в1..вN), и тест обязан выжить по построению.
