# Phase 40.4 Plan 03: CSV-import place-tree invalidation Summary

**CSV import with a place column now updates the «Места» tree node counters immediately after import (no screen switch needed) by threading `CsvImportReport.affected_place_ids` through `onImported` into `notifyPlaceContentChanged`, with the new write-site registered in the permanent INV-7 registry gate.**

## Accomplishments
- `DeviceImportCsvModal.svelte`'s `onImported` prop signature changed from `() => void` to `(placeIds: number[]) => void`; `handleDone()` now passes `report?.affected_place_ids ?? []` (read from the already-populated `report` state before `resetState()` clears it).
- `DevicesPage.svelte`'s inline `onImported` handler now conditionally calls `notifyPlaceContentChanged(placeIds)` when `placeIds.length > 0`, symmetric to the existing `onSaved`'s `changedPlaceIds.length > 0` gate — no invalidation event fires for imports where no row carried a place.
- `check-place-tree-invalidation.mjs::MUTATING_COMPONENTS` gained `{ component: 'DeviceImportCsvModal', props: ['onImported'] }` — the permanent INV-7 static gate now knows about this write-site.
- Gate liveness was proven, not assumed: temporarily removed the `notifyPlaceContentChanged(placeIds)` call from `DevicesPage.svelte`, re-ran `node scripts/check-place-tree-invalidation.mjs`, confirmed it FAILED with the exact expected diagnostic (`резолвленный обработчик не вызывает notifyPlaceContentChanged()`), then restored the file and re-confirmed PASS.
