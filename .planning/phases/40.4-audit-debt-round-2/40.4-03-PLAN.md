<objective>
Закрыть клиентскую половину N-3 (SC2, инвалидация): импорт CSV с указанием места сегодня НЕ
инвалидирует счётчики узлов дерева «Места» — `DevicesPage.svelte`'s `onImported` обработчик
(проброшенный в `DeviceImportCsvModal`) вызывает `refresh()`/`refreshCounts()`/`pushToast(...)`, но
никогда `notifyPlaceContentChanged(...)`, и сам `onImported: () => void` сегодня не несёт данных о
том, КАКИЕ места затронуты. План 40.4-02 добавил `CsvImportReport.affected_place_ids` — backend
уже знает список; этот план прокидывает его через `onImported` до вызова
`notifyPlaceContentChanged`, по буквальному образцу уже существующего `DevicesPage.onSaved`
(единичное create/edit устройства, тот же паттерн дедупликации через `Set`).

Реестр INV-7 (`check-place-tree-invalidation.mjs::MUTATING_COMPONENTS`) — постоянный,
registry-driven гейт, ловящий именно класс регрессии «новый write-site места забыт» (три раунда
верификации подряд до этого находили ровно такой пропуск на РАЗНЫХ экранах). Новая запись —
обязательная часть фикса, не дополнение.

Purpose: пользователь, импортировавший CSV с указанием мест, видит актуальные счётчики дерева
«Места» сразу после импорта, не дожидаясь смены экрана/перезагрузки.
Output: `onImported` несёт `placeIds: number[]`; `DevicesPage.svelte` инвалидирует затронутые
узлы; `check-place-tree-invalidation.mjs` знает про новый write-site.
</objective>

`ui/src/features/devices/DevicesPage.svelte::onSaved` (~строки 167-183) — эталон:
```
function onSaved(result?: { typeId: number; placeId: number | null }) {
  const oldPlaceId = editTarget?.place_id ?? null;
  const newPlaceId = result?.placeId ?? null;
  const changedPlaceIds = Array.from(
    new Set([oldPlaceId, newPlaceId].filter((id): id is number => id !== null)),
  );
  if (changedPlaceIds.length > 0) notifyPlaceContentChanged(changedPlaceIds);
  modalOpen = false;
  refresh();
  refreshCounts();
}
```

(`$lib/stores/placeContentEvents.svelte` — сверить точный путь импорта в самом файле DevicesPage.svelte).
