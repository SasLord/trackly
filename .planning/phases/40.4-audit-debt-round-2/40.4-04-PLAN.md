<objective>
Закрыть NEW-3: `DeviceFormBody.svelte`'s `quantityDisabled` блокирует «Количество» > 1 при ЛЮБОМ
непустом `inventoryNo`, включая значение, автоподставленное сервером при монтировании формы
(`autofillOnMount` по умолчанию `true`, NUM-08) — как только сервер помнит шаблон для контекста
`device_create`/`printer_create`, поле заполняется НЕМЕДЛЕННО, делая массовое создание
недостижимым с первого рендера, даже если пользователь ничего не вводил руками.

`NumberTemplateField.svelte` уже несёт готовый компаратор «значение автоподставлено vs введено
вручную» (`isValueUnedited()`/`matchesLast`/`matchesAlt`, реализован для стрелки ↑/↓, NUM-07) —
этот план прокидывает его наружу через новый callback-проп `onEditedByHandChange`, по образцу уже
существующего `onSelectedTemplateChange`, вместо изобретения новой эвристики.

**Критический со-фикс (риск регрессии, найден в RESEARCH, не в тексте аудита):** бэкенд УЖЕ
жёстко отклоняет `bulk_create` с `count > 1` и непустым `inventory_no`
(`bulk_create_rejects_when_inventory_no_set`, `device_service.rs:1560-1579`). Просто ослабить
`quantityDisabled` без очистки `inventoryNo` в payload для qty>1-ветки означает, что пользователь
при каждой попытке массового создания с автоподставленным номером получит СЕРВЕРНУЮ ошибку
валидации вместо рабочего массового создания — находка формально «починена» (Количество
разблокировано), но реальный сценарий использования остаётся сломанным. Фикс ОБЯЗАН включать
безусловное обнуление `inventory_no` в payload для qty>1 (количество любого автоподставленного
номера теряет смысл при массовом создании — сервер не умеет присвоить РАЗНЫЕ номера N устройствам
за один вызов, так что обнуление — корректная семантика, не костыль).

Purpose: пользователь, которому сервер УЖЕ подсказал следующий свободный номер по шаблону, может
сразу создать несколько одинаковых устройств одной операцией — не должен вручную стирать
подсказанный номер, чтобы разблокировать «Количество».
Output: `NumberTemplateField`'s новый проп `onEditedByHandChange`; `DeviceFormBody.svelte`'s
`quantityDisabled` и `handleSubmit` qty>1-ветка учитывают «редактировалось вручную».
</objective>
