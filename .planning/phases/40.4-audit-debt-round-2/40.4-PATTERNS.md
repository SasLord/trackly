## Pattern Assignments

### 1. `crates/trackly-infra/src/repos/devices_sqlite.rs::restore_from_snapshot_in_tx` (NEW-1)

**Эталон:** тот же файл, `update_in_tx` (~255-300) и trait-impl `update` (~680-725) — оба уже
переведены Фазой 40.3 (CR-03 / NUM-09) с `COALESCE` на `CASE WHEN` для `Option<Option<T>>`
DTO-полей.

**Эталонный SQL-паттерн** (буквально из `update_in_tx`):
```rust
"UPDATE devices SET
   name             = COALESCE(?1, name),
   type_id          = COALESCE(?2, type_id),
   inventory_number = CASE WHEN ?3 = 1 THEN ?4 ELSE inventory_number END,
   serial_number    = CASE WHEN ?5 = 1 THEN ?6 ELSE serial_number END,
   model            = CASE WHEN ?7 = 1 THEN ?8 ELSE model END,
   condition        = CASE WHEN ?9 = 1 THEN ?10 ELSE condition END,
   complectation    = CASE WHEN ?11 = 1 THEN ?12 ELSE complectation END,
   place_id         = CASE WHEN ?13 = 1 THEN ?14 ELSE place_id END,
   status_id        = COALESCE(?15, status_id),
   notes            = CASE WHEN ?16 = 1 THEN ?17 ELSE notes END,
   version          = version + 1,
   updated_at_utc   = ?18
 WHERE id = ?19 AND version = ?20 AND deleted_at_utc IS NULL",
rusqlite::params![
    patch.name.as_deref(),
    patch.type_id,
    patch.inventory_no.is_some() as i64,
    patch.inventory_no.as_ref().and_then(|v| v.as_deref()),
    patch.serial_no.is_some() as i64,
    patch.serial_no.as_ref().and_then(|v| v.as_deref()),
    ...
```

**Флаг присутствия в эталоне:** источник — `Option<Option<T>>` DTO-поле (`patch.serial_no`),
флаг = `patch.serial_no.is_some()`, значение = `.and_then(|v| v.as_deref())` (внутренний
`Option<String>` → `Option<&str>`). Два уровня `Option` различают «поле не передано в PATCH»
(внешний `None`) от «поле передано явно как `null`» (внешний `Some(None)`).

**Текущий (баг) код цели** (`restore_from_snapshot_in_tx`, ~430-484):
```rust
let state: Option<&str> = snapshot.get("state").and_then(|v| v.as_str());
let kit: Option<&str> = snapshot.get("kit").and_then(|v| v.as_str());
let name: Option<&str> = snapshot.get("name").and_then(|v| v.as_str());
let model: Option<&str> = snapshot.get("model").and_then(|v| v.as_str());
let serial_no: Option<&str> = snapshot.get("serial_no").and_then(|v| v.as_str());
let specs: Option<&str> = snapshot.get("specs").and_then(|v| v.as_str());
...
"UPDATE devices SET \
   type_id          = COALESCE(?1, type_id), \
   name             = COALESCE(?2, name), \
   serial_number    = COALESCE(?3, serial_number), \
   model            = COALESCE(?4, model), \
   condition        = COALESCE(?5, condition), \
   complectation    = COALESCE(?6, complectation), \
   notes            = COALESCE(?7, notes), \
   status_id        = ?8, \
   place_id         = ?9, \
   version          = version + 1, \
   updated_at_utc   = ?10 \
 WHERE id = ?11 AND deleted_at_utc IS NULL"
```

**Чем цель отличается от эталона:** источник здесь — `&serde_json::Value`, не типизированная
структура. Presence-флаг нужно брать ДО `.and_then`, отдельным вызовом `.get(key).is_some()`
(ключ присутствует в JSON, даже если значение — `null`), а не из результата `.and_then(as_str)`
(который стирает разницу между «отсутствует» и «есть, но `null`»):

```rust
// Правильно (по образцу update_in_tx, адаптировано под serde_json::Value):
let serial_present = snapshot.get("serial_no").is_some() as i64;
let serial_value: Option<&str> = snapshot.get("serial_no").and_then(|v| v.as_str());
// ... аналогично model/state("condition")/kit("complectation")/specs("notes") ...

"UPDATE devices SET \
   type_id          = COALESCE(?1, type_id), \
   name             = COALESCE(?2, name), \
   serial_number    = CASE WHEN ?a = 1 THEN ?b ELSE serial_number END, \
   model            = CASE WHEN ?c = 1 THEN ?d ELSE model END, \
   condition        = CASE WHEN ?e = 1 THEN ?f ELSE condition END, \
   complectation    = CASE WHEN ?g = 1 THEN ?h ELSE complectation END, \
   notes            = CASE WHEN ?i = 1 THEN ?j ELSE notes END, \
   status_id        = ?8, \
   place_id         = ?9, \
   ..."
```

**ЛОВУШКА (Pitfall 1 из RESEARCH):** НЕ вычислять флаг как `serial_value.is_some()` (после
`.and_then`) — это будет эквивалентно старому багу под новым именем переменной, потому что
`.and_then(|v| v.as_str())` уже возвращает `None` и для отсутствующего ключа, и для
`Value::Null`. Флаг обязан читаться из `snapshot.get(key)` НАПРЯМУЮ, до `.and_then`.

**Отображение JSON-ключ → SQL-столбец** (важно не перепутать):
| JSON-ключ снепшота | SQL-столбец | Комментарий |
|---|---|---|
| `serial_no` | `serial_number` | |
| `model` | `model` | |
| `state` | `condition` | имена расходятся |
| `kit` | `complectation` | имена расходятся |
| `specs` | `notes` | имена расходятся |

`status_id`/`place_id` остаются БЕЗ CASE (прямая перезапись — уже намеренное поведение,
комментарий "BE-WR-06" рядом не трогать). `inventory_no`/`type_id`/`name` — вне объёма
(Claude's discretion в RESEARCH — рекомендован минимальный фикс, только 5 полей).

**Writer снепшота** (для понимания реалистичности "ключ отсутствует"): `device_snapshot_json`
(`crates/trackly-app/src/services/act_service.rs:3591-3606`) — единственный писатель формата,
всегда кладёт все 12 ключей через `serde_json::json!({...})`, значит на практике ключ
физически всегда присутствует (может быть `null`, не отсутствовать) — защитный код на случай
гипотетических старых `audit_log`-записей.

### 2B. `crates/trackly-app/src/services/device_service.rs::import_csv_commit` (N-3, шторм broadcast)

**Эталон:** тот же файл, `bulk_create_with_printer` (~1532-1651) — single-broadcast-after-loop:

**Текущий broadcast-хелпер** (переиспользуется как есть, ~183-189):

```rust
fn broadcast_number_space_changed(&self) {
    if let Some(ws_tx) = &self.ws_tx {
        let _ = ws_tx.send(WsEvent::NumberSpaceChanged {
            contexts: vec!["device_create".to_string(), "printer_create".to_string()],

```

**Текущий код цели** — `create()` (~375-392) шлёт broadcast БЕЗУСЛОВНО при `number_set`:
```rust
pub async fn create(&self, new: DeviceNew) -> Result<DeviceSaveOutcome, AppError> {
    Self::validate_new(&new)?;
    let trimmed = new.inventory_no.as_deref().map(|v| v.trim().to_string());
    if let Some(t) = trimmed.as_deref().filter(|s| !s.is_empty()) {
        self.reject_if_occupied(t, None).await?;
    }
    let mut new = new;
    new.inventory_no = trimmed.filter(|s| !s.is_empty());
    let number_set = new.inventory_no.is_some();

    let dto = self.insert_new_and_get(new, None, None).await?;
    if number_set {
        self.broadcast_number_space_changed();
    }
    Ok(DeviceSaveOutcome::Created(Box::new(dto)))
}
```
`import_csv_commit` вызывает `self.create(new_device).await` ВНУТРИ per-row цикла (~1077-1237) —
каждая успешная строка с номером шлёт отдельный `NumberSpaceChanged` (шторм при импорте N>1
строк, канал `broadcast::channel::<WsEvent>(128)` фиксированной ёмкости, `context.rs:214`).

**Рекомендованный рефакторинг** (по принципу `bulk_create_with_printer`, НЕ его буквальному
батч-вызову — см. Pitfall 2 ниже): завести приватный `create_without_broadcast`, тело идентично
`create()` минус финальный `if number_set { self.broadcast_number_space_changed(); }`; `create()`
становится тонкой обёрткой над ним + broadcast (аналогично `bulk_create` → `bulk_create_with_printer`).
`import_csv_commit` вызывает `create_without_broadcast` внутри цикла, копит `any_number_set: bool`:
```rust
let mut any_number_set = false;
for row in &session.all_rows {
    // ... существующая per-row логика, self.create_without_broadcast(new_device) ...
    if inserted_ok && new_device.inventory_no.is_some() {
        any_number_set = true;
    }
}
if any_number_set {
    self.broadcast_number_space_changed();
}
```

**Pitfall 2 (НЕ повторять):** нельзя заменить per-row `create()` на единый вызов `bulk_create` —
`bulk_create` вставляет `count` КОПИЙ ОДНОГО `DeviceNew` (одно имя/место/номер), CSV-строки все
РАЗНЫЕ, и per-row ошибки обрабатываются НЕЗАВИСИМО (не транзакция «всё или ничего»). Сохранить
per-row цикл, вынести только broadcast.

**Risk of regression:** `create()` остаётся публичным с тем же broadcast-поведением (единственный
другой вызывающий помимо CSV — legacy `PrinterCreateModal.svelte` create-путь) — правится ТОЛЬКО
CSV-импорт, переключаемый на новый внутренний метод.

## Shared Patterns

### CASE WHEN по presence вместо COALESCE (для clearable-полей)
**Источник:** `crates/trackly-infra/src/repos/devices_sqlite.rs` (`update_in_tx`/`update`,
Фаза 40.3) → расширяется на `restore_from_snapshot_in_tx` (эта фаза).
**Применить к:** любому SQL UPDATE, где присутствие ключа/поля должно отличаться от его
пустого/null значения. Разница источника флага: типизированный `Option<Option<T>>` (DTO) vs
`serde_json::Value::get(key).is_some()` (сырой JSON) — оба ведут к одному и тому же SQL-приёму.

### Один broadcast на операцию, не на строку/элемент
**Источник:** `crates/trackly-app/src/services/device_service.rs::bulk_create_with_printer`.
**Применить к:** `import_csv_commit` (эта фаза) — любой будущий цикл вставки должен копить
локальный `bool`/аккумулятор и слать `broadcast_number_space_changed()` ОДИН раз после цикла, не
внутри него.

### Реестр INV-7 — place-tree инвалидация
**Источник:** `ui/scripts/check-place-tree-invalidation.mjs::MUTATING_COMPONENTS` +
`ui/src/features/devices/DevicesPage.svelte::onSaved`.
**Применить к:** любому новому write-site, меняющему `place_id` устройства/картриджа —
обязательный вызов `notifyPlaceContentChanged(placeIds)` в резолвленном обработчике + строка в
реестре, иначе гейт (`pnpm --dir ui lint`) падает автоматически при регистрации компонента без
вызова.

### «Значение автоподставлено vs введено вручную» — единый компаратор
**Источник:** `ui/src/lib/components/NumberTemplateField.svelte::isValueUnedited`/`matchesLast`/
`matchesAlt` (NUM-07).
**Применить к:** любому UI-сигналу, различающему «поле хранит серверное предложение» от «поле
правили руками» — не дублировать логику новой эвристикой (diff/timestamp/dirty-flag), прокидывать
существующий компаратор наружу через callback-проп.

### Единый источник отображаемого номера акта
**Источник:** `crates/trackly-app/src/dto/act.rs::format_act_number` →
`crates/trackly-app/src/services/act_number_display.rs::resolve_movement_act_number` →
`ActDto.number`.
**Применить к:** любому новому потребителю, которому нужен «человекочитаемый номер акта с
суффиксом» — переиспользовать `ActDto.number`, не парсить/реконструировать строку заново
(анти-паттерн, названный в doc-комментарии `act_number_display.rs` как «WR-03/WR-08 duplication
anti-pattern»).

### Версионирование файловых шаблонов
**Источник:** `crates/trackly-app/src/pdf/html_templates.rs::KNOWN_LEGACY_DEFAULTS` +
`crates/trackly-app/templates/_legacy_defaults/vNN/`.
**Применить к:** ЛЮБОЙ правке тела файла из `DEFAULT_HTML_TEMPLATES` — снепшот ПРЕЖНЕГО тела
обязателен ДО правки активного файла, иначе `upgrade_untouched_defaults_on_startup` перестаёт
узнавать нетронутые инсталляции и апгрейд тихо не доходит.

### Gate-скрипты `ui/scripts/check-*.mjs` с `--selftest`
**Источник:** `ui/scripts/check-act-number-no-regex-split.mjs` — usage-блок (~47-49):
