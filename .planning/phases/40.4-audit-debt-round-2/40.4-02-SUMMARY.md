# Phase 40.4 Plan 02: CSV import broadcast storm + place-id DTO Summary

**`import_csv_commit` now sends exactly one `WsEvent::NumberSpaceChanged` per CSV import (not one per row) via a new `create_without_broadcast` helper, and `CsvImportReport` carries a deduplicated `affected_place_ids: Vec<i64>` for client-side place-tree invalidation.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 2 completed
- **Files modified:** 3

## Accomplishments
- `CsvImportReport.affected_place_ids: Vec<i64>` — dedup list of `place_id` for every row that actually inserted (excludes rows that failed validation/place-resolution).
- `DeviceService::create_without_broadcast` factored out of `create()` — identical body minus the broadcast call; `create()` is now a thin wrapper (`create_without_broadcast` + conditional broadcast).
- `import_csv_commit`'s per-row loop calls `create_without_broadcast` and batches ONE `broadcast_number_space_changed()` call after the loop if any row set a number — closes T-40.4-03 (broadcast-channel DoS risk on the fixed-capacity `broadcast::channel::<WsEvent>(128)`).
- Two new integration tests (`import_commit_collects_affected_place_ids`, `import_commit_failed_row_place_not_in_affected_place_ids`) plus a broadcast-storm regression (`import_commit_sends_single_broadcast_not_per_row`) and a new `make_service_with_ws_tx()` test fixture.

## Decisions Made
- `create()` delegates to `create_without_broadcast()` rather than duplicating logic (plan's explicit action) — single source of truth, no behavior drift risk between the two paths.
- Captured `new_device.place_id` into a local (`row_place_id`) BEFORE calling `self.create_without_broadcast(new_device)` in the per-row loop, since `new_device` is moved by value into that call — reading `new_device.place_id` after the `.await` would not compile (use-after-move). Not called out explicitly in the plan's action text but required for it to compile; matches the plan's own `new_device.place_id` intent exactly, just captured at the correct point in the borrow/move timeline.
- `bulk_create`/`bulk_create_with_printer` left untouched — explicitly out of scope per plan (their broadcast logic already single-fires after their own loops).
