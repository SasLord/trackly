<objective>
Закрыть NEW-2: печатная форма акта (`act_service.rs::render_pdf`) сегодня собирает отображаемый
номер вручную — `act.number_raw` (сырое значение) + `suffix`, вычисленный отдельной функцией
`compute_suffix_from_display`, которая при несовпадении `display.strip_prefix(number_raw)` ищет
литеральную кириллическую «в» ГДЕ УГОДНО в строке (`display.find('в')`) — хрупко для произвольной
маски шаблона номера, содержащей «в» в литеральной части до цифр (риск F7 из аудита — акты АРМ,
Фаза 41, унаследуют тот же дефект, если пойдут через тот же контекст печати).

Канонический источник УЖЕ существует и уже используется таймлайном и отчётом «Перемещения»:
`act_number_display.rs::resolve_movement_act_number` вызывает тот же `format_act_number`, что и
`ActDto::from(row)` при построении `act.number` — значит `act.number` в `render_pdf` УЖЕ буквально
равен тому, что видит пользователь в таймлайне/отчёте. Фикс не вычисляет ничего нового, только
прокидывает уже готовое значение под новым ключом контекста `act.number_display`, БЕЗ удаления
существующих `number`/`number_raw`/`suffix` (backward-compat для уже кастомизированных
пользователями файловых шаблонов, D-05: «an existing file is never overwritten»).

**Обязательная процедура версионирования шаблонов** (Pitfall 3 из RESEARCH — пропуск ломает
апгрейд для существующих инсталляций МОЛЧА, не крахом): тело `act_handover.html` меняется ЭТИМ
планом → снепшот ПРЕЖНЕГО (до правки) тела ОБЯЗАН попасть в `_legacy_defaults/v29/` и в
`KNOWN_LEGACY_DEFAULTS` ДО того, как активный файл будет отредактирован — иначе
`upgrade_untouched_defaults_on_startup` перестаёт узнавать нетронутые инсталляции структурно, и
апгрейд до них никогда не доходит.

**Обязательный со-фикс, не в тексте аудита:** `template_service.rs::demo_context_for_kind`
(демо-данные превью редактора шаблонов, рендерится под `UndefinedBehavior::Strict`) должен
получить тот же новый ключ — иначе живой предпросмотр в TemplateEditor и существующий тест
`validate_preview_act_handover_returns_html_with_title_marker` падают с `UndefinedError`
сразу после правки шаблона (project memory `template_preview_strict_undefined`).

**Явное решение по F7 (гейт-покрытие, критический риск #4 из планирования):** существующий
`check-act-number-no-regex-split.mjs` сканирует ТОЛЬКО `ui/src` — серверная/шаблонная половина
дефекта физически вне его области видимости (zero-dependency node-скрипт, не читает `.rs`/
`.html`). Расширять JS-гейт на Rust-файлы означало бы изобретать новый механизм сканирования
внутри существующего файла ради одного разового случая. Вместо этого — постоянный Rust-тест
(Task 3, в `html_act_render.rs`, том же файле, что уже держит `ACT_HANDOVER_HTML` const через
`include_str!` для другого структурного гейта) ассертит, что АКТИВНЫЙ `act_handover.html` больше
не содержит сырую конкатенацию `{{ act.number }}{{ act.suffix` — постоянный regression-гейт,
живущий в естественном для Rust-контекста месте, не half-scoped JS-скрипт.

Purpose: печатная форма акта не должна расходиться с таймлайном/отчётом «Перемещения» в
отображении номера, и не должна ломаться на произвольной маске шаблона номера.
Output: `act.number_display` в контексте печати; 3 сайта шаблона переведены; снепшот v29 +
реестр; demo-контекст со-фикс; справка UI редактора шаблонов; постоянный regression-тест.
</objective>
