## Название организации

### Как убрать хардкод полного наименования

| Option | Description | Selected |
|--------|-------------|----------|
| Два поля в настройках | Новое поле «полное юридическое» + существующее короткое; шапка рендерит «полное (короткое)» | ✓ |
| Одно поле org.name | В существующую настройку вписывается полное наименование, скобочный вариант исчезает | |
| Два поля, скобки опциональны | Скобки только если короткое непусто и отличается от полного | |

**User's choice:** Два поля в настройках
**Notes:** Разведка показала, что реквизиты для печати идут из `org_settings`, а не из `org.json` — значит поле добавляется туда (миграция + DTO + форма).

### Кто задаёт переносы строк в наименовании

| Option | Description | Selected |
|--------|-------------|----------|
| Автоперенос по ширине | Однострочное поле, браузер ломает по ширине блока 80mm | |
| Многострочное поле | textarea, переводы строк → `<br>` при рендере | ✓ |
| Авто + ширина подобрана | Ширина блока подгоняется под конкретное наименование | |

**User's choice:** Многострочное поле
**Notes:** В образце наименование разбито на три строки осмысленно, автоперенос это не воспроизводит.

### Что показывать, пока новое поле пустое

| Ничего не показывать | Строка не рендерится, как и остальные реквизиты | ✓ |

**User's choice:** Ничего не показывать

### Связка двух полей

| Option | Description | Selected |
|--------|-------------|----------|
| Исчезает вместе | Нет полного — нет и скобок; блок названия целиком | |
| Короткое без скобок | Нет полного → короткое обычной строкой | |
| Каждое поле само по себе | Две независимые условные строки | ✓ |

**User's choice:** Каждое поле само по себе
**Notes:** Следствие (C-01 в CONTEXT.md): существующая установка сразу после апгрейда покажет только короткое название в скобках, без строки над ним.

### Где преобразовывать переводы строк в `<br>`

| Option | Description | Selected |
|--------|-------------|----------|
| В Rust, готовый HTML | Сервис экранирует и вставляет `<br>`, шаблон печатает через `\| safe` — как logo_data_uri | ✓ |
| Фильтр в шаблоне | Свой minijinja-фильтр nl2br | |
| Цикл по строкам | Массив строк + `{% for %}`, никакого `\| safe` | |

**User's choice:** В Rust, готовый HTML
**Notes:** Security-значимо — порядок «экранировать → вставить `<br>`» обязателен, иначе инъекция HTML через настройку организации.

## Гарантия одинаковости

| Option | Description | Selected |

### Как реализовать partial при запрете FS-загрузчика

| Option | Description | Selected |
|--------|-------------|----------|
| Регистрация в памяти | Приложение читает `_header.html` само и регистрирует вторым именованным шаблоном; загрузчик остаётся выключен | ✓ |
| Включить FS-загрузчик | `set_loader` с ограничением на каталог templates — отменяет решение Фазы 16 | |
| Назад к копии + гейт | Отказаться от partial'а | |

**User's choice:** Регистрация в памяти
**Notes:** Ограничение всплыло при разведке — `build_safe_html_env` намеренно без загрузчика как мера против T-16-02 (Фаза 16). Выбранный вариант сохраняет это свойство.
