## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-01-01 | Tampering / Elevation of Privilege | `org_full_name_html` (`minijinja_env.rs`) | mitigate | `minijinja::HtmlEscape` runs FIRST, `.replace('\n', "<br />")` runs SECOND — any `<`, `>`, `&`, `"`, `'` typed into the full-name field is neutralized to an HTML entity before any literal `<br />` tag is inserted, so a `<script>` payload can never reach the `| safe` template output as executable markup (wired to the template in Plan 34-03; this plan only proves the helper itself is safe in isolation). |
| T-34-01-02 | Information Disclosure | `org_settings.full_name` storage | accept | Same trust level as every other `org_settings` requisite field (`org_name`, `inn`, `address`, ...) — no new sensitivity class introduced; write path reuses the existing `authorize(caller, &Action::ManageSettings)` guard in `save_fields` unchanged. |
| T-34-01-SC | Tampering | npm/pip/cargo installs | accept | No new package-manager dependency in this plan — `minijinja::HtmlEscape` is already available via the existing `minijinja ^2.20` Cargo dependency (confirmed present in `crates/trackly-app/Cargo.toml`). |
