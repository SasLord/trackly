# Phase 13: Редизайн совместимости Принтеры↔Картриджи по уникальному наименованию + свёрнутые chip-задачи — Specification

**Created:** 2026-06-25
**Ambiguity score:** 0.16 (gate: ≤ 0.20)
**Requirements:** 8 locked

## Goal

Модель совместимости «принтер↔картридж» переходит с per-device junction-таблицы `printer_cartridge_models` (Phase 12, V029) на free-text-связь по уникальному наименованию/типу принтера (`cartridge_model_compatibility`, V005): V029 удаляется, UI совместимости из Phase 12 сносится и заменяется одним блоком «Совместимые принтеры» в форме модели картриджа; карточка принтера показывает совместимость только как read-only агрегаты и получает блок данных устройства; дополнительно закрываются две свёрнутые chip-задачи (kind-aware дефолт состояния в авто-возврате и рассогласование лимита списка принтеров 500-vs-200).

## Background

Сегодня в системе сосуществуют **два** механизма совместимости:

1. **`cartridge_model_compatibility` (V005)** — free-text: `cartridge_model_id` + `printer_brand` TEXT + `printer_model` TEXT. Редактируется через `ui/src/features/cartridges/CompatibilityEditor.svelte`.
2. **`printer_cartridge_models` (V029)** — per-device junction: `device_id` ↔ `cartridge_model_id` по id, двустороннее редактирование. Введён в Phase 12 (планы 12-05/12-07) как промежуточное решение. Редактируется через `CompatibleDevicesEditor.svelte` (со стороны модели картриджа) и `CompatibleModelsEditor.svelte` (со стороны принтера, `ui/src/features/printers/`).

Пользователь **отверг** per-device-модель (V029): не масштабируется на парк 40+ принтеров и дублирует настройку для каждого физического устройства одной модели. Также из Phase 12 осталось два фоновых дефекта (chip-задачи): (а) авто-возврат картриджа в `crates/trackly-infra/src/repos/cartridges_sqlite.rs` (~:474) пишет `previous_cartridge_state_id.unwrap_or(3)` — cartridge-only state (3=Пустой) для фотобарабана (kind=2, валидные состояния 4/5/6) → тихая порча данных; фронт `OperationModal.svelte` (~:506-514) хардкодит состояния 1/2/3 вместо реюза `stateOptions`/`DRUM_STATES`; (б) `OperationModal.svelte` (~:277) шлёт `limit:500`, а бэкенд `printers_sqlite.rs:314` капит `page.limit.min(200)` без пагинации → на парке >200 совместимый принтер за пределами первых 200 (`ORDER BY p.id DESC`) недоступен.

Парк сейчас ~40 принтеров — лимит-дефект пока не триггерится, но является скрытой ловушкой.

## Requirements

1. **Drop V029 junction**: Per-device junction-таблица совместимости удаляется из схемы.
   - Current: Таблица `printer_cartridge_models` (V029) существует, наполнена при Phase 12, читается/пишется методами `SqlitePrinterRepository::set_compatible_models_in_tx` / `set_compatible_devices_in_tx` и фильтром `compatible_with_printer_device_id` в `CartridgeRepository::list()`.
   - Target: Новая миграция `DROP TABLE printer_cartridge_models`; весь Rust-код, читающий/пишущий эту таблицу, удалён или переведён на V005; сборка `cargo build` и `cargo test` зелёные.
   - Acceptance: `grep -r "printer_cartridge_models" crates/ migrations/` не находит ни одной живой ссылки (кроме DROP-миграции и исторических комментариев); `cargo test` проходит.

2. **Compatibility via V005 free-text**: Совместимость ключуется по `cartridge_model_compatibility` (printer_brand + printer_model TEXT), per-model (не per-device).
   - Current: Совместимость для нового UI хранилась в V029 по `device_id`.
   - Target: Единственный источник истины совместимости — `cartridge_model_compatibility` (V005). Существующие строки V005 **сохраняются** (не очищаются). Фильтрация «совместимый картридж для принтера» резолвится сопоставлением brand/model принтера с записями V005.
   - Acceptance: Картридж-модель, у которой в V005 указан принтер с наименованием/типом совпадающим с конкретным физическим принтером, считается совместимой с этим принтером в выборе картриджа при установке; per-device-привязка более не участвует.

3. **Единый блок «Совместимые принтеры» (B2)**: В формах «Новая модель»/«Редактирование модели» картриджа — один блок совместимости вместо двух нынешних редакторов.
   - Current: В форме модели картриджа два отдельных редактора — `CompatibilityEditor.svelte` (free-text V005) и `CompatibleDevicesEditor.svelte` (per-device V029).
   - Target: Один блок «Совместимые принтеры», пишущий в V005. `CompatibleDevicesEditor.svelte` удалён. Поле выбора с автокомплитом предлагает уникальные наименования/типы принтеров (`SELECT DISTINCT` по принтерам — devices `type_id=2`), при этом допускает свободный ввод наименования модели, отсутствующей в БД (сохраняется как текст в V005, «под будущее»).
   - Acceptance: В форме модели картриджа ровно один блок совместимости; добавление существующего (из автокомплита) и нового (свободный ввод) наименования сохраняется и перечитывается после reload; в БД появляется строка(и) `cartridge_model_compatibility`.

4. **Карточка принтера — агрегаты совместимости (read-only)**: Блок совместимости на карточке принтера только отображает, не редактирует.
   - Current: `CompatibleModelsEditor.svelte` на карточке принтера редактирует per-device совместимость (V029).
   - Target: `CompatibleModelsEditor.svelte` удалён. На карточке принтера — read-only блок: список совместимых моделей картриджей с агрегатами по статусам (напр. «Cactus CS-TL-5120: В работе 2, На складе 4»). Редактирование совместимости доступно только со стороны модели картриджа (Req 3).
   - Acceptance: На карточке принтера нет элементов редактирования совместимости (кнопок добавить/удалить связь); отображается список совместимых моделей с числовыми агрегатами по статусам; данные совпадают с V005-связями для наименования/типа этого принтера.

5. **Карточка принтера — блок данных устройства + редактирование**: Карточка принтера показывает поля устройства и даёт перейти к редактированию устройства.
   - Current: Карточка принтера (`PrinterDetail.svelte`) не показывает Инвентарный №/Серийный №/Состояние в выделенном блоке устройства и не имеет входа в редактирование устройства.
   - Target: На карточке принтера — блок с полями устройства (type=2): **Инвентарный №**, **Серийный №**, **Расположение**, **Состояние**. Рядом — кнопка «Редактировать» (либо иконка карандаша), открывающая диалоговое окно «Редактирование устройства» для этого устройства.
   - Acceptance: Блок отображает все четыре поля из `devices` для устройства принтера; клик по «Редактировать»/карандашу открывает диалог «Редактирование устройства»; сохранение в диалоге обновляет поля и отражается на карточке после перечтения.

6. **Установленный картридж по коду+наименованию**: На карточке принтера установленный картридж показывается по коду и наименованию модели, не по внутреннему №.
   - Current: Установленный картридж может отображаться по `#id`/№.
   - Target: Установленный картридж отображается как код (C-XXXXXX) + наименование модели (brand/model).
   - Acceptance: На карточке принтера с установленным картриджем виден код вида `C-000123` и наименование модели; внутренний числовой id не показывается.

7. **Kind-aware дефолт состояния в авто-возврате (chip-задача 1)**: Авто-возврат предыдущего картриджа использует дефолт состояния, корректный для типа модели (картридж vs фотобарабан).
   - Current: `cartridges_sqlite.rs` (~:474) делает `previous_cartridge_state_id.unwrap_or(3)` — всегда 3 (Пустой, cartridge-only), что невалидно для фотобарабана (kind=2 → валидные состояния 4/5/6); `OperationModal.svelte` (~:506-514) хардкодит состояния 1/2/3.
   - Target: Дефолт состояния при авто-возврате выбирается по `model_kind_id` предыдущего картриджа (kind=1 → cartridge-state дефолт; kind=2 → drum-state дефолт из валидного диапазона). Фронт переиспользует `stateOptions`/`DRUM_STATES` вместо хардкода 1/2/3.
   - Acceptance: Регресс-тест: авто-возврат фотобарабана (kind=2) без явного `previous_cartridge_state_id` записывает валидное drum-состояние (из 4/5/6), а не 3; авто-возврат картриджа (kind=1) сохраняет прежнее поведение; в `OperationModal.svelte` нет хардкода списка состояний 1/2/3.

8. **Фикс лимита списка принтеров (chip-задача 2)**: Рассогласование лимита 500-vs-200 устранено — совместимый принтер не теряется при выборе.
   - Current: `OperationModal.svelte` (~:277) запрашивает `limit:500`, бэкенд `printers_sqlite.rs:314` капит `page.limit.min(200)`; принтеры за пределами первых 200 (`ORDER BY p.id DESC`) недоступны.
   - Target: Кап бэкенда поднят/параметризован так, что запрошенный фронтом лимит обслуживается консистентно (без полной пагинации). Фронт и бэкенд согласованы по значению.
   - Acceptance: Запрос списка принтеров с фронтовым лимитом возвращает все принтеры до согласованного предела (≥ запрошенного фронтом значения); `printers_sqlite.rs` больше не капит ниже фронтового запроса; тест/проверка подтверждает, что принтер с большим id не отсекается.

## Boundaries

**In scope:**
- Миграция: `DROP TABLE printer_cartridge_models` (V029); строки V005 `cartridge_model_compatibility` сохраняются.
- Удаление Rust-кода чтения/записи V029 и фильтра `compatible_with_printer_device_id` (перевод на V005).
- Удаление фронт-редакторов `CompatibleDevicesEditor.svelte` (сторона картриджа) и `CompatibleModelsEditor.svelte` (сторона принтера).
- Единый блок «Совместимые принтеры» в форме модели картриджа: автокомплит по DISTINCT наименованиям принтеров + свободный ввод, запись в V005.
- Карточка принтера: read-only блок агрегатов совместимости.
- Карточка принтера: блок данных устройства (Инвентарный №, Серийный №, Расположение, Состояние) + кнопка/карандаш «Редактировать» → диалог «Редактирование устройства».
- Карточка принтера: установленный картридж по коду + наименованию.
- Chip-задача 1: kind-aware дефолт состояния авто-возврата + реюз stateOptions на фронте + регресс-тест.
- Chip-задача 2: простой фикс/параметризация капа лимита принтеров.

**Out of scope:**
- **Нормализованный каталог моделей принтеров** (отдельная таблица `printer_models` с FK) — выбран free-text V005, нормализация не делается.
- **Миграция данных V029 → новая модель** — чистый старт, V029 просто дропается без переноса связей.
- **Слияние/автодедупликация дублей текстовых наименований принтеров** в V005 — не в этой фазе.
- **Полная пагинация списка принтеров** в OperationModal — только фикс капа; настоящая пагинация откладывается.
- **Очистка/wipe существующих строк V005** — строки сохраняются.

## Constraints

- SQLite + refinery: новая миграция получает следующий номер `V032__*` и должна корректно отрабатывать на существующей БД с наполненными V005/V029.
- Portable-режим: миграция выполняется на БД рядом с исполняемым файлом; необратимый `DROP` V029 допустим (чистый старт согласован).
- Двойной транспорт (Tauri invoke + axum HTTP): любые изменения read/write команд совместимости отражаются в обоих адаптерах и в `specta`-экспорте `bindings.ts`; матрица `role_endpoint_matrix` обновляется при изменении набора эндпоинтов.
- Парк ~40 принтеров — текущий объём; фикс капа должен покрывать рост без полной пагинации.
