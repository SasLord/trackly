# Phase 13 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** Phase 13 is backend-heavy (V032 migration, drop V029, V005 free-text matching) but has four concrete frontend surfaces: (1) a single «Совместимые принтеры» block in the cartridge-model form, (2) a read-only compatibility-aggregates block on the printer card, (3) a device-data block + edit dialog on the printer card, (4) installed-cartridge by code+name, plus the chip-task front fix in OperationModal (reuse stateOptions/DRUM_STATES). This phase introduces **no new design tokens** — it consumes the established `ui/src/styles/_tokens.scss` system verbatim. The contract below documents those existing tokens (so the checker can validate against them) and adds the phase-specific copywriting + interaction contracts.

## Spacing Scale

Declared values (all multiples of 4, from existing `_tokens.scss`):

| Token | Value | Usage |
|-------|-------|-------|
| `--space-xs` | 4px | Icon gaps, inline field gaps, list-row vertical padding |
| `--space-sm` | 8px | Compact element spacing, section-internal gap (label↔value rows) |
| `--space-md` | 16px | Default element spacing, input horizontal padding, meta-row column gap |

| `--space-2xl` | 48px | Empty-state padding |

Exceptions: icon-only buttons (`remove-btn`, pencil/edit button) are 28×28px per the existing `CompatibilityEditor` convention — below the 36px touch-target token but matching established desktop-density precedent in this codebase. No new exceptions introduced this phase.

## Color

From existing `_tokens.scss` (light + dark themes both defined; reference tokens — they auto-switch on `[data-theme]`):

| Role | Token (light / dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `--color-bg` #ffffff / #0f1419 | Detail panel background, input background |
| Secondary (30%) | `--color-surface` #f5f6f8 / #1a1f26, `--color-surface-sunken` #eaecef / #252b33 | Cards, dropdowns, list-row hover, section surfaces |
| Accent (10%) | `--color-accent` #2563eb / #3b82f6 | See reserved list below |
| Destructive | `--color-destructive` #dc2626 / #ef4444 | Remove-compatibility `✕` hover, delete affordances |

Supporting text tokens (not part of 60/30/10, semantic neutrals): `--color-text-primary`, `--color-text-secondary`, `--color-text-muted`, `--color-border`. Status semantics for aggregates and badges reuse `--color-success` (В сети / На складе context), `--color-warning`, `--color-destructive` via the existing `Badge` variants — **do not invent per-status colors for the aggregate block; it is plain text** («Cactus CS-TL-5120: На складе 4, На заправке 1, В работе 2»), counts in `--color-text-primary`, model name and status labels in `--color-text-secondary`.

Accent reserved for: primary buttons (`Button variant="primary"` — «Обновить сейчас», «Сохранить» in the device-edit dialog), input focus ring (`--color-accent-focus` 3px box-shadow on `:focus-visible`), active autocomplete option highlight, and the «Редактировать» edit affordance hover/focus state. Accent is **never** applied to the read-only aggregate block, body text, or the device-data label/value rows.

## Interaction Contracts

- **Compatibility autocomplete (cartridge-model form):** focus-open dropdown; debounced 200ms on input; ArrowUp/Down to move `activeIndex`, Enter/Tab to select, Escape to close; `onmousedown preventDefault` on options (prevents blur-before-select); click-outside via `.compat-field` `closest` guard — all matching the existing `CompatibilityEditor` behavior. Free-text input that matches no suggestion is **kept and saved** (D-06), shown via the «Нет совпадений — будет сохранено как есть» dropdown message.
- **Aggregate block (printer card):** strictly read-only. No add/remove/edit controls. Renders one row per compatible cartridge model, statuses in fixed order На складе → На заправке → В работе (D-07), «Списано» excluded. List rows at `--row-height-dense`.
- **Device block + edit (printer card):** four label/value rows (`Данные устройства`), then a `Редактировать` button or pencil icon-button (aria-label `Редактировать устройство`) that opens `DeviceFormModal` for the printer's `device_id`. On dialog save → re-fetch printer/device → block reflects updated values (Req 5 acceptance).
- **OperationModal state default (chip-task 1):** the auto-return state `<Select>` options derive from the previous cartridge's `model_kind_id` — `kind=1` → cartridge states (1/2/3 set), `kind=2` → drum states (4/5/6 set), default 5 «Изношенный» for drum (D-10/D-11). No hardcoded 1/2/3 list remains.
- **Theme:** every surface must render correctly in both `[data-theme='light']` and `[data-theme='dark']` via tokens (UI-02); no literal colors. Verified by reuse of token-only styling.
