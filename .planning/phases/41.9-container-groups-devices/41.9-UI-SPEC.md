# Phase 41.9 — UI Design Contract

> Визуальный и интеракционный контракт фазы «Контейнерные группы в разделе „Устройства“»: строка
> АРМ с раскрытием состава, вложенные группы в раскрытии, автоподгрузка списка при прокрутке,
> догрузка усечённого состава группы.
> Составлен gsd-ui-researcher, проверяется gsd-ui-checker.
>
> **Макета нет.** Дизайн-система зафиксирована Фазой 23 (`ui/src/styles/_tokens.scss`, гейт
> `ui/scripts/check-tokens.mjs`), якорная строка — Фазой 41.1 (`41.1-UI-SPEC.md`, §9). Этот документ
> не переоткрывает ни токены, ни решения `41.9-CONTEXT.md` (D-01…D-17). Новых токенов, hex'ов, шкал
> и npm-зависимостей — **ноль**. Решения, которых нет в CONTEXT, выделены в §15 с пометкой R-NN.
>
> **Приватность (жёсткое условие проекта, репозиторий публичный):** все примеры вымышленные:
> «АРМ #3», «Системный блок #4», «Монитор #2», «Каб. 101». Реальные названия, реквизиты, ФИО и
> номера в код, копирайт, тесты, фикстуры и скриншоты не попадают.

Новых разделов и экранов нет. Новых primary-кнопок нет: единственная primary «Устройств»
(«Добавить устройство») остаётся единственной. Новых модалок нет, деструктивных действий нет.

| # | Поверхность | Решения | Раздел |
|---|-------------|---------|--------|
| 1 | Строка АРМ в таблице | GRD-07, D-01, D-02, D-03 | §7 |

| 3 | Раскрытие состава и вложенность | D-11, D-12, D-15, D-16 | §9 |

**Фокальная точка фазы** — первая ячейка строки АРМ: шеврон и жирное имя группы. Это сигнал
«здесь лежит состав», которого сейчас нет, и из-за которого непонятно, какие устройства уже входят
в АРМ.

**Вне контракта:** управление группой из «Устройств» (переименование, перенос, удаление —
только раздел «Группы», D-03); автоподгрузка в других разделах (D-08); список сотрудника; вид
состава якорных групп верхнего уровня (остаётся плоским, D-11); механика объединённого запроса,
форма DTO и разбивка на планы (Claude's Discretion планировщика, требования к данным — §13).

## 7. Строка АРМ

### 7.1 Вид (D-01)

```
▸ АРМ #3  [ Группа ]  [ 5 шт. ]   │ — │ — │ — │ Каб. 101 │ — │ — │ ⋯
│  600/14  accent soft  count,mono
шеврон     =ссылка #/groups?id=N
```

| Колонка | Содержимое |
|---------|------------|
| Наименование | шеврон, имя, бейдж-ссылка, счётчик, при усечённом составе иконка догрузки |
| Инвентарный №, Серийный №, Модель | «—» |
| Место | `place_path_short` группы, `title` — полный путь; места нет — «—» |
| Состояние | «—» |
| Статус | «—» (колонка есть всегда, где есть строка АРМ: на вкладке статуса строк АРМ нет) |
| Действия | `ActionMenu variant="ghost-sm"` |

Значения, которых у группы нет, не агрегируются и не выдумываются. Прочерк — обычный текст ячейки,
не `.tr-mono`. Строка собирается на `TableRow` в обычном режиме (не `group`): фон обычный,
наведение `--tr-row-hover`.

### 7.2 Первая ячейка

Разметка и классы — по образцу `.anchor-cell` из `DeviceListRow`: `display: flex`,
`align-items: center`, `gap: var(--tr-space-xs)`, `min-width: 0`. Сама ячейка `<td role="button"
tabindex="0" aria-haspopup="menu" title={имя группы}>`.

| Элемент | Контракт |
|---------|----------|
| Шеврон | `RowChevron`, обработчик гасит всплытие |
| Имя | 600/14px, `min-width: 0`, `text-overflow: ellipsis` |
| Бейдж-ссылка | `<a href="#/groups?id={id}">` вокруг `Badge`; `text-decoration: none`, при наведении `underline`, фокус — глобальное кольцо, `flex-shrink: 0` |
| Счётчик | считает физические устройства с вложенными на любую глубину (D-13), `flex-shrink: 0` |
| Иконка догрузки | §11, `flex-shrink: 0`, последний элемент ячейки |

### 7.3 Клики и клавиатура (D-02, D-03)

| Действие | Результат |
|----------|-----------|
| Одиночный клик по строке | ничего (как у якорной строки) |
| Клик по шеврону | раскрыть или свернуть |
| Двойной клик по строке | переход `#/groups?id={id}`; снимается выделение текста; охраны первыми операторами: `isRowOverlayEvent`, затем `closest('button, a')` |
| Клик по бейджу | переход в раздел «Группы» |
| Правый клик | меню `openAt(x, y)`, родное меню погашено; охрана `isRowOverlayEvent` первым оператором, **до** `preventDefault`; одинаково в Tauri и LAN-браузере |
| «⋯» | то же меню от триггера |
| `Enter` на первой ячейке | переход в раздел «Группы» (эквивалент двойного клика) |
| `ContextMenu` / `Shift+F10` на первой ячейке | меню `openAt(rect.left, rect.bottom)` от `getBoundingClientRect()` первой ячейки (как внутри `DeviceRowMenu`; `ActionMenu` не расширять) |
| `Tab` | шеврон, бейдж, иконка догрузки, «⋯» по порядку; `Enter`/`Space` срабатывают нативно |

Клавишные обработчики охраняются `isOwnKeyEvent`. Отдельных `ondblclick` на вложенных элементах
нет (гейт `check-device-row-menu`).

**Меню:** ровно два пункта `role="menuitem"` без разделителя: «Открыть группу», затем «Раскрыть»
или «Свернуть». Строится на `ActionMenu` (панель в `<body>`), `DeviceRowMenu` не переиспользуется:
он привязан к `DeviceDto`.

### 7.4 Узкая колонка

Колонка «Наименование» не расширяется. Порядок ужатия: сначала имя (многоточие, полный текст в
`title`), затем у **якорной** строки бейдж с именем группы (`.anchor-link`: `flex-shrink: 1`,
`min-width: 0`, `overflow: hidden`; бейдж АРМ «Группа» короткий и не ужимается). Шеврон, счётчик
и иконка догрузки не ужимаются никогда.

### 7.5 Маркер принтера (D-20)

Строка с `type_id = 2` показывает перед именем иконку принтера 14×14, штрихом `currentColor` в цвете второстепенного текста, по образцу SVG из `RowChevron`. Логика и вид живут в одном компоненте `PrinterMark.svelte`; для других типов он ничего не рисует.

- Где: `DeviceListRow` (обычная ветка и `.anchor-cell`, после шеврона) и строка свёртки `DeviceGroupRow`. Ячейку свёртки рисует `TableRow`, поэтому у него появляется необязательный сниппет `groupLead` между шевроном и именем; без него разметка прежняя. Строки состава рисует `DeviceListRow`, поэтому маркер там появляется сам.
- Отступ до имени: шаг из шкалы §3. В `.anchor-cell` иконка не сжимается. Обрезка длинного имени многоточием сохраняется.
- Доступность: `role="img"`, `aria-label="Принтер"`, подсказка `title="Принтер"`. Иконка не интерактивна, клик и правый клик проходят в строку.
- Строка АРМ маркера не имеет. Другие разделы не меняются (D-08).

## 8. Показ строки АРМ по режимам

Строка АРМ показывается, только если группа **корневая** (D-12) и в ней есть хотя бы одно
физическое устройство с учётом вложенных (D-17).

| Режим | Строки АРМ | Члены АРМ | Порядок |
|-------|-----------|-----------|---------|
| Обычный список | есть | скрыты | вперемешку с устройствами, общий `ORDER BY` по имени с устойчивым tie-break (D-04) |
| «Свернуть одинаковые» (вид по умолчанию) | есть | скрыты | в блоке с якорями над свёртками, блок сортируется по имени (D-05); АРМ в свёртке не участвует |
| Поиск | только совпавшие по имени группы; раскрываются как обычно | показаны обычными строками | блок АРМ первым, ниже результаты устройств в их порядке (R-01) |
| Вкладка статуса | нет | показаны обычными строками | как сейчас |
| Переход по `focusId` | нет | показаны обычными строками | как сейчас |

**Приоритет:** вкладка статуса и `focusId` сильнее поиска: если задан любой из них, строк АРМ нет,
даже при введённом запросе. Правила совпадения имени группы при поиске те же, что у поиска
устройств.

Устройство при поиске может быть видно дважды — в раскрытой строке АРМ и обычной строкой; это
принято (тот же случай у якорей, D-10 фазы 41.1).

Вложенные группы и их устройства, включая якорное устройство вложенной группы, на верхнем уровне
не показаны (D-12). Принтер-член АРМ скрыт снаружи и показан в составе обычной строкой (D-15).
Принтер, связанный с АРМ только по USB или ссылкой, остаётся строкой общего списка и в раскрытии
не показывается (D-16).

## 9. Раскрытие состава

### 9.1 Состав АРМ (D-11)

Прямые устройства и вложенные группы одним списком, общая сортировка по имени с устойчивым
tie-break.

```
▾ АРМ #3 [Группа] [5 шт.]
    ИБП
    Монитор #2
    ▸ Системный блок #4  [Группа] [3 шт.]     ← вложенный АРМ или якорная строка
```

| Элемент | Рендер |
|---------|--------|
| Устройство, принтер | `DeviceListRow` с отступом, все колонки и меню как у обычной строки |
| Вложенная якорная группа | якорная строка `DeviceListRow` со своим шевроном; её состав вида D-11 не меняет |
| Вложенный АРМ | `DeviceContainerRow` с отступом; двойной клик открывает **эту** вложенную группу |
| Вложенный АРМ без физических устройств | не показывается (D-17) |

Состав якорной группы верхнего уровня остаётся плоским (41.1 §9.4).

### 9.2 Отступы

| Глубина | `padding-left` первой ячейки |
|---------|------------------------------|
| 0 (верхний уровень) | 10px, унаследовано |
| 1 | 32px, унаследовано от `indent` |
| 2 | 48px, `--tr-space-4xl` |
| 3 и глубже | 64px, `--tr-space-5xl`; дальше отступ не растёт |

### 9.3 Закрытие состава

Усиленная нижняя граница `group-last-child` (2px `--tr-border-strong`) ставится только на последнюю
**видимую** строку раскрытия корневой группы. Вложенные раскрытия своей усиленной границы не
получают, иначе в таблице появляются двойные линии.

### 9.4 Состояния

| Состояние | Вид |
|-----------|-----|
| Загрузка состава | заглушка на всю ширину «Загрузка…», с отступом глубины (существующий `.members-note`) |
| Перечитывание после мутации | прежний состав остаётся на экране, «Загрузка…» не мигает (унаследовано) |
| Ошибка раскрытия | Toast и сворачивание строки назад (унаследовано) |
| Пустой состав | штатно недостижимо (D-17); при гонке с изменением состава показывается существующая заглушка |

Раскрытие хранится в общем для якорей и АРМ наборе по `group_id`, живёт в рамках сессии страницы
и переживает перезагрузку списка. Свёрнутый родитель прячет детей, но их состояние раскрытия
сохраняется.

## 10. Автоподгрузка списка

Применяется во всех режимах «Устройств» (D-07), другие разделы не меняются (D-08).

### 10.1 Поведение

| Свойство | Контракт |
|----------|----------|
| Прокручиваемая область | `.tr-table-wrapper` (режим `fillHeight`) |
| Порог | до конца прокрутки осталось не больше 240px |
| Размер порции | 50 строк верхнего уровня |
| Одновременность | один запрос порции за раз; ответ устаревшего поколения отбрасывается |
| Короткая первая порция | если контент не заполняет область, а данные ещё есть, следующая порция грузится без прокрутки |
| Порядок | строки порции только дописываются в конец; видимые строки не перестраиваются и не сдвигаются |
| Конец списка | индикатор исчезает, запросов больше нет |
| Свёртка | блок якорей и АРМ приходит целиком с первой порцией, порциями идут только свёртки; нынешний предел 200 у блока не должен молча обрезать якоря и АРМ (D-07: весь список достижим) |
| Поиск | блок совпавших АРМ приходит целиком с первой порцией |

### 10.2 Индикатор

Находится в футере таблицы, справа, по образцу `CartridgesList` (`.list-footer`: `display: flex`,
`justify-content: space-between`, `align-items: center`; `min-height: 28px` добавляется этой фазой, в образце его нет). Футер не прокручивается,
поэтому индикатор виден сразу и не сдвигает строки (R-03).

Содержимое: `Spinner size="sm"` + «Загрузка», gap 8px, 13px, `--tr-text-secondary`. Контейнер с
`role="status"` присутствует в DOM постоянно, меняется только его содержимое, иначе диктор
объявление пропустит. Первичная загрузка по-прежнему показывает скелетон `Table`, индикатора в
футере в это время нет.

### 10.3 Ошибка порции

На месте индикатора: «Не удалось загрузить продолжение списка.» + `Button variant="link" size="sm"`
«Повторить». Уже загруженные строки остаются. Автоматические повторы останавливаются до нажатия
ссылки: прокрутка новых запросов не шлёт. Toast **не показывается**, иначе прокрутка у неисправного
соединения даёт серию тостов.

### 10.4 Сброс и инвалидация

| Событие | Поведение |
|---------|-----------|
| Смена запроса, вкладки статуса, «Свернуть одинаковые» | список с первой порции, `scrollTop = 0` |
| Мутация или WS-инвалидация | загруженный объём и `scrollTop` сохраняются; скелетона и мигания нет; строки обновляются на месте |
| Подгрузка при открытом меню строки | меню не закрывается (ключи `{#each}` стабильны, новые строки только дописываются) |
| `focusId` | прокрутка к подсвеченной строке только однократно при первой загрузке; строка из поздней порции не должна выдёргивать пользователя из текущей позиции |

## 11. Иконка догрузки состава

### 11.1 Вид

`<Button variant="ghost" size="sm" iconOnly ariaLabel=… title=…>` (28×28) с `RowReload`: SVG 14×14,
`viewBox="0 0 24 24"`, `fill="none"`, `stroke="currentColor"`, `stroke-width="2.5"`, скругления
`round`, `aria-hidden="true"`; две стрелки по кругу:

```
M3 12a9 9 0 0 1 9-9 9.75 9.75 0 0 1 6.74 2.74L21 8
M21 3v5h-5
M21 12a9 9 0 0 1-9 9 9.75 9.75 0 0 1-6.74-2.74L3 16
M8 16H3v5
```

Иконка не вращается в покое и не окрашивается акцентом.

### 11.2 Условие показа

Строка группы **раскрыта**, загрузка состава завершена и `items.length < total`. Одинаково для АРМ
и якорных групп, включая вложенные (D-10): у каждой усечённой группы своя иконка. На свёрнутой
строке иконки нет.

### 11.3 Поведение (D-09)

| Шаг | Контракт |
|-----|----------|
| Нажатие | одним действием догружается **весь** остаток состава |
| Загрузка | `Button loading`: на месте иконки крутилка, кнопка заблокирована, ширина не меняется; показанные строки остаются |
| Успех | строки дописываются, иконка исчезает, **фокус переводится на шеврон этой строки** (иначе фокус теряется вместе с кнопкой) |
| Ошибка | Toast (§6), иконка возвращается, строка **не** сворачивается, показанные строки остаются; отличие от `failAnchor` сознательное |
| Перечитывание после мутации | группа, догруженная целиком, перечитывается целиком: иконка не возвращается сама |
| Свернуть и раскрыть | догруженный состав сохраняется в рамках сессии страницы |

Двойной клик по иконке группу не открывает: охрана `closest('button, a')` (§7.3).

## 12. Футер таблицы

| Режим | Текст |
|-------|-------|
| Обычный список | `Показано N из M`, при скрытых `(+K в составе групп)` |
| «Свернуть одинаковые» | `Свёрнуто: N`, при скрытых `(+K в составе групп)` (R-02) |
| Поиск, вкладка статуса, `focusId` | `Показано N из M`, без хвоста: скрытие выключено |

- N и M считают **строки списка верхнего уровня**: АРМ — одна строка. Строки раскрытого состава в
  N не входят.
- K — скрытые устройства: члены якорных групп и АРМ, с вложенными на любую глубину, наравне (D-13).
- Счётчики вкладок статуса остаются физическими и включают скрытых.
- Смысл `Свёрнуто: N` не меняется; при автоподгрузке N растёт вместе с загруженными строками.

## 13. Требования к данным строки (контракт на DTO, не на схему)

Строка собирается из одного ответа списка, без запроса на строку:

| Что нужно | Зачем |
|-----------|-------|
| признак вида строки (устройство или АРМ), `group_id`, имя группы | §7, смешанный список |
| место группы: короткий и полный путь | колонка «Место» |
| число физических устройств с вложенными | счётчик, отсев пустых АРМ |
| у состава: прямые устройства и вложенные группы, `total` | §9.1, условие иконки §11.2 |
| признак «есть ещё» для режимов без `total` (свёртка) | конец списка, §10.1 |
| `hidden_member_count`, включая членов АРМ, также в режиме свёртки | футер §12 |

Оба транспорта (Tauri и `/api/v1/*`) обязаны отдавать одно и то же: отсутствующий маршрут
маскируется `spa_fallback`, возвращающим 200. Пикеры актов, автодополнение и экспорт CSV новых
флагов не ставят и видят все устройства. `DevicesPage` задаёт `type_id: 1`: принтеры-члены (D-15)
обязаны проходить фильтр состава.

## 14. Accessibility и проверка

**Экранный диктор.** Раскрытие — `aria-expanded` шеврона; количество — текстом в бейдже;
индикатор и ошибка подгрузки — `role="status"`; иконка догрузки — `aria-label` с именем группы.
Подсказка — нативный `title`, отдельного компонента подсказок в проекте нет. Спиннер анимируется
по глобальному правилу `prefers-reduced-motion`; значимость несёт надпись «Загрузка».

**Контраст.** Новых цветовых пар нет; `check-contrast.mjs` остаётся зелёным.

**Гейты (отдельные команды):** `pnpm lint` (включая `check-tokens`, `check-focus-outline`,
`check-group-vocabulary`, `check-device-list-mode`, `check-device-row-menu`,
`check-action-menu-portal`), `svelte-check`, clippy, fmt.

**Только в запущенном приложении (WKWebView, WebView2) и LAN-браузере:**

1. В виде по умолчанию («Свернуть одинаковые») строка АРМ стоит в блоке с якорями, члены снаружи не видны.
2. Прокрутка до конца при больше чем 50 устройствах: индикатор виден, вся выборка достижима.
3. Правка устройства в глубине длинного списка: позиция прокрутки и загруженный объём сохранены.
4. Двойной клик по строке АРМ открывает группу; по шеврону, бейджу, иконке, «⋯» — нет.
5. Правый клик по строке АРМ: короткое меню и в Tauri, и в браузере; у нижнего края открывается вверх.
6. Узкое окно: шеврон, имя, бейдж, счётчик, иконка и «⋯» не сталкиваются; на глубине 3 счётчик не обрезан.
7. Группа больше 200 элементов: иконка, догрузка, исчезновение иконки, фокус на шевроне, иконка не возвращается после правки устройства.
8. Обрыв соединения в LAN при подгрузке: одна подпись с «Повторить», серии тостов нет.
9. Обе темы: бейдж «Группа» и иконка различимы на наведении.

## 15. Решения контракта, которых нет в CONTEXT

| # | Решение | Почему |
|---|---------|--------|
| R-01 | При поиске совпавшие АРМ идут блоком над результатами устройств | у поиска свой порядок, D-06 выводит его из-под D-04, а место в CONTEXT не задано; порядок релевантности с именами групп несравним |
| R-02 | В режиме свёртки футер получает хвост `(+K в составе групп)` | свёртка — вид по умолчанию (`grouped = initialFocusId === null`); без хвоста критерий 2 и GRD-08 в основном виде не наблюдаемы. Расширяет поведение 41.1, где хвост был только у плоского списка |
| R-03 | Индикатор автоподгрузки в футере, а не строкой в конце таблицы | футер всегда на экране, строки не сдвигаются, есть образец в `CartridgesList` |
| R-04 | При вкладке статуса или `focusId` строк АРМ нет даже при введённом запросе | D-14 задаёт оба правила, не определяя их приоритет; `focusId` живёт всю сессию страницы |
| R-05 | Текст бейджа АРМ — «Группа», счётчик — «5 шт.» | эталон CONTEXT («[Группа]»); имя группы уже стоит рядом, форма счётчика — как у якорной строки |
| R-06 | Ошибка порции без тоста, с ручным «Повторить» | прокрутка иначе порождает серию запросов и тостов |
| R-07 | Маркер принтера — иконка перед именем, §7.5 | решение пользователя D-20; без новой колонки |
