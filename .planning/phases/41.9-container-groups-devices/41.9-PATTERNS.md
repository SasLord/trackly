## Pattern Assignments

### `crates/trackly-infra/src/repos/devices_sqlite.rs` — правка CTE скрытия (repository, чтение)

**Analog:** он сам, `anchor_members_sql!` (стр. 43-56).

**Текущий код:**
```rust
macro_rules! anchor_members_sql {
    () => {
        "WITH RECURSIVE a(gid, anchor) AS ( \
           SELECT id, anchor_device_id FROM groups \
           WHERE anchor_device_id IS NOT NULL AND deleted_at_utc IS NULL \
           UNION \
           SELECT g.id, a.anchor FROM groups g JOIN a ON g.parent_group_id = a.gid \
           WHERE g.deleted_at_utc IS NULL) \
         SELECT gd.device_id FROM group_devices gd JOIN a ON a.gid = gd.group_id \
         WHERE gd.device_id <> a.anchor"
    };
}
```

**Что менять:** добавить второй засев (корневые контейнеры без якоря, `group_types.behavior = 'container'`, `parent_group_id IS NULL`, `deleted_at_utc IS NULL`) через `UNION`, и заменить `<>` на `IS NOT` (при `anchor = NULL` `<>` даёт NULL и скрытия нет). Образец идиомы `IS NOT` в этом же файле: `group_subtree_members_sql!` (стр. 70: `gd.device_id IS NOT (SELECT anchor_device_id ...)`).

**Где подставляется (одна правка даёт согласованность во всех трёх):** `LIST_FLAG_PREDICATES` (стр. 100-113), `grouped_flag_predicates!` (стр. 80-94), `count_hidden_anchor_members` (стр. 397-418). Не переименовывать флаг `hide_anchor_members`.

**Тест-образец и ловушки:** вакуумный тест — прогнать до правки и убедиться, что красный; мутация «вернуть `<>`».

### `devices_sqlite.rs` — новые `list_entries` / `head_block` / `group_children` (repository, пагинация)

**Analog:** `count_list_rows` + `select_list_rows` (стр. 868-960).

**Общий предикат на COUNT и SELECT (копировать приём):**
```rust
conn.query_row(
    &format!(
        "SELECT COUNT(*) FROM devices d WHERE
               (?1 = 1 OR d.deleted_at_utc IS NULL) AND
               (?2 IS NULL OR d.status_id = ?2) AND
               (?3 IS NULL OR d.type_id = ?3) AND
               {LIST_FLAG_PREDICATES} AND
               {LIST_FILTER_PREDICATES}"
    ),
    rusqlite::params![ /* те же индексы ?1..?13, что и в SELECT */ ],
    |r| r.get(0),
).map_err(map_rusqlite)
```
и SELECT: `{SELECT_DEVICES} WHERE ... ORDER BY d.name, d.id LIMIT ?4 OFFSET ?5`.

**Для объединённого запроса:** `SELECT k,id,name FROM (устройства UNION ALL корневые непустые контейнеры) ORDER BY name, k, id LIMIT/OFFSET`. Предикат устройств держать константой/макросом, общей для ключей и COUNT (урок 41.11). Сортировка BINARY как в `select_list_rows`, tie-break `k, id`. Физический счётчик состава — формула `tree_counts` (`groups_sqlite.rs:731-756`, рекурсивный `closure`), вторую не писать:
```sql
WITH RECURSIVE closure(root, id) AS (
  SELECT id, id FROM groups WHERE deleted_at_utc IS NULL
  UNION ALL
  SELECT c.root, g.id FROM groups g JOIN closure c ON g.parent_group_id = c.id
  WHERE g.deleted_at_utc IS NULL)
SELECT c.root, COUNT(d.id) FROM closure c
LEFT JOIN group_devices gd ON gd.group_id = c.id
LEFT JOIN devices d ON d.id = gd.device_id AND d.deleted_at_utc IS NULL
GROUP BY c.root
```
**Имя группы и поиск:** `lower()` SQLite не сворачивает кириллицу; совпадение имени при поиске делать в Rust по образцу пути места в `search_fts` (`.to_lowercase()`), чистую функцию вынести в `trackly-core`.

**Прямые дети группы (D-11):** образец — `group_subtree_members_sql!` (плоское поддерево, для D-11 не подходит) и `groups_sqlite.rs::member_devices` (прямые устройства, `ORDER BY name, id`). Новое: прямые устройства + прямые дочерние группы; у дочерней якорной группы ребёнок — её якорное устройство.

### `crates/trackly-app/src/services/device_service.rs` (service)

**Analog:** `list` (стр. 985-1025) и `list_grouped` (стр. 1501-1553).

**Паттерн (копировать):**
```rust
let (items, total, hidden_member_count) = tokio::task::spawn_blocking(move || {
    let conn = readers.acquire();
    let (rows, total) = repo.list(&conn, &domain_filter, &domain_page)?;
    let hidden_member_count = if domain_filter.hide_anchor_members {
        repo.count_hidden_anchor_members(&conn, &domain_filter)?
    } else { 0 };
    let mut items: Vec<DeviceDto> = rows.into_iter().map(DeviceDto::from).collect();
    enrich_devices(&conn, items.iter_mut())?;

.await
.map_err(|e| AppError::Internal { source_chain: format!("spawn_blocking: {e}") })??;
```
Читатели — `readers.acquire()`, без писателя. Гидратация: `enrich_devices` (стр. 286) для устройств; путь места группы сокращать через `compute_place_path_short_with_conn` (`services/place_path_display.rs`), не писать своё. Сервис отвергает `limit > 200` (стр. ~965-970) — серверный максимум не поднимать; остаток состава догружать циклом страниц по 200.

## Shared Patterns

### Авторизация чтения
**Source:** `tauri_cmds/devices.rs:140`, `http/devices.rs:307-309`
**Apply to:** все новые команды и обработчики.
```rust
authorize(caller, &Action::ReadData)?;   // Tauri/общий build_*
let identity = session_identity(&session).await.map_err(AppErrorResponse::from)?;  // HTTP
```

### Два транспорта на одну логику
**Source:** `build_*` в `tauri_cmds` вызываются и Tauri-командой, и HTTP-обработчиком; регистрация — `collect_commands!` + `.route`. Бизнес-логика только в сервисе.

### Чтение через читателя из пула, без записи
**Source:** `device_service.rs:999-1010` (`spawn_blocking` + `readers.acquire()`). Ошибки — `map_rusqlite` из `crate::error_conversions`.

### Параметризованный SQL, макросы-литералы
**Source:** `devices_sqlite.rs:30-113` (`concat!` из макросов-литералов; текст пользователя в SQL не попадает, флаги — целочисленные параметры).
