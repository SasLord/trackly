- **D-01:** Колонки строки АРМ: шеврон + имя группы («АРМ #3») + бейдж-ссылка группы + счётчик состава в «Наименовании»; колонка «Место» заполнена местом группы; «Инвентарный №», «Серийный №», «Модель», «Состояние», «Статус» — прочерк. ## Summary

Фаза почти целиком поднимается на уже существующей механике 41.1. Серверное скрытие членов — это один рекурсивный CTE (`anchor_members_sql!` в `crates/trackly-infra/src/repos/devices_sqlite.rs`), который подставляется во все три пути (`list`, `list_grouped`, `count_hidden_anchor_members`). Сейчас он засевается только якорными группами. Контейнерные группы без якоря (`behavior = 'container'`, `anchor_device_id IS NULL`) туда не попадают, поэтому их члены показываются снаружи. Минимальная и правильная правка — добавить в засев корневые контейнерные группы и заменить сравнение `gd.device_id <> a.anchor` на `IS NOT` (иначе при `anchor = NULL` строка отбрасывается по правилам трёхзначной логики и скрытия нет вообще). Вся остальная серверная работа — это новые чтения: объединённый список «устройства + строки АРМ» (D-04), блок якорей и АРМ для «Свернуть одинаковые» (D-05), прямые дети группы для раскрытия (D-11) и поиск АРМ по имени (D-14).

Главная архитектурная развилка: строки АРМ не являются устройствами, поэтому `devices_list` с его `Vec<DeviceDto>` для них не подходит. Рекомендация — новые команды с DTO-строкой «устройство или контейнер», зарегистрированные парой Tauri-команда + HTTP-маршрут (иначе `spa_fallback` не маскирует, а `http_route_parity.rs` краснит, но проверять нужно явно). Пагинация — по ключам `(name, kind, id)` в одном `UNION ALL ... ORDER BY ... LIMIT/OFFSET`, затем гидратация строк пачкой. Важный инвариант, который нужно удержать единым переключателем: «строка АРМ показана» тогда и только тогда, когда «члены АРМ скрыты» (оба = `hide_anchor_members`); два независимых флага дают исчезающие устройства.

Автоподгрузка (D-07) — чисто фронтенд-механика плюс одно серверное требование: признак «есть ещё» для режима свёртки (там нет `total`). Таблица не отдаёт прокручиваемый контейнер наружу, поэтому нужен аддитивный проп в `Table.svelte`. Догрузка состава (D-09) требует снять лимит 200 для одной группы: сервис отвергает `limit > 200`, поэтому остаток догружается циклом страниц по 200, а не одним запросом.

**Обновление (D-18):** принтеры теперь входят в общий список, фильтр `type_id: 1` снимается. Выводы про расхождение K и бейджа АРМ и про «тривиальность» D-16 отозваны, см. раздел «Принтеры в общем списке (D-18)». Объём правки малый (один литерал в `DevicesPage` плюс три пути, которые уже не фильтруют тип), но меняется видимое содержимое списка и поведение «Свернуть одинаковые» и экспорта.

**Primary recommendation:** расширить `anchor_members_sql!` засевом корневых контейнеров (`IS NOT`), добавить один новый серверный список строк (`UNION ALL` ключей + гидратация) под единым флагом `hide_anchor_members`, вынести новые правила в `deviceListMode.ts` с фикстурой, а автоподгрузку строить на scroll-слушателе внутри прокручиваемого контейнера `Table` с поколением запроса.

## Architecture Patterns

### Ключевая находка 1: скрытие членов контейнера (GRD-08)

Текущий CTE [VERIFIED: devices_sqlite.rs:45-56]:

```sql
WITH RECURSIVE a(gid, anchor) AS (
  SELECT id, anchor_device_id FROM groups
   WHERE anchor_device_id IS NOT NULL AND deleted_at_utc IS NULL
  UNION
  SELECT g.id, a.anchor FROM groups g JOIN a ON g.parent_group_id = a.gid
   WHERE g.deleted_at_utc IS NULL)
SELECT gd.device_id FROM group_devices gd JOIN a ON a.gid = gd.group_id
 WHERE gd.device_id <> a.anchor
```

Правка: добавить второй засев и сменить `<>` на `IS NOT`:

```sql
  -- корневые контейнерные группы без якоря
  SELECT g.id, NULL FROM groups g JOIN group_types t ON t.id = g.type_id
   WHERE t.behavior = 'container' AND g.anchor_device_id IS NULL
     AND g.parent_group_id IS NULL AND g.deleted_at_utc IS NULL
...
 WHERE gd.device_id IS NOT a.anchor
```

Следствия, которые обязан увидеть планировщик:

1. **`<>` с NULL отбрасывает строку** — без `IS NOT` скрытие АРМ молча не сработает, а тест «якорь виден» останется зелёным. Нужен тест, где у АРМ есть член и проверка, что он скрыт.
2. Макрос подставляется в три места (`LIST_FLAG_PREDICATES`, `grouped_flag_predicates!`, `count_hidden_anchor_members`), поэтому правка одной точки даёт согласованное скрытие и счётчик K. Корень-контейнер без якоря не засевает «якорь» вложенных групп: якорное устройство вложенной якорной группы внутри АРМ является членом вложенной группы и при рекурсии от корня-контейнера (`anchor = NULL`) скрывается автоматически (D-12). Для вложенных групп с собственным якорем второй засев (`anchor = их якорь`) оставляет их якорь видимым в их собственной выдаче, но он уже скрыт строкой родителя — проверить тестом.
3. **Блок якорей в «Свернуть одинаковые»** сейчас запрашивается с `hide_anchor_members: false, anchors_only: true` [VERIFIED: deviceListMode.ts:65-66]. Якорное устройство вложенной группы внутри АРМ в этот блок попадёт, нарушив D-12. Нужно либо включить скрытие и для запроса якорей, либо исключать якоря, чьи группы лежат в поддереве корня-контейнера. Рекомендация: серверный «блок вершины» (см. ниже) формирует список сам и не использует `anchors_only` + клиентскую склейку.
4. Имя флага `hide_anchor_members` остаётся (переименование ломает гейт `check-device-list-mode.mjs`, реестр фильтров и три теста); смысл расширяется до «члены якорных и контейнерных групп»; зафиксировать в комментарии DTO и в реестре.
5. **Фильтр типа (пересмотрено по D-18).** Прежний вывод «принтеры в общий список не попадают, K считает только тип 1, D-16 тривиален» относился к `type_id: 1` и больше не действует. С `type_id: null` K и бейдж АРМ считают одно множество (все живые устройства, в том числе принтеры); подробности и все места влияния — в разделе «Принтеры в общем списке (D-18)».

### Ключевая находка 2: «корневая» группа и «пустая» группа

- Группы удаляются жёстко (`DELETE FROM groups`), вложенные получают `parent_group_id = NULL` [VERIFIED: groups_sqlite.rs:179-192]. Корень = `parent_group_id IS NULL AND deleted_at_utc IS NULL`.
- Физический счётчик с вложенными: `tree_counts` (рекурсивный CTE `closure`, считает только живые устройства) [VERIFIED: groups_sqlite.rs:731-756]. Это формула D-13; не писать вторую. Для отсева пустых (D-17) использовать тот же счётчик `> 0` внутри объединённого запроса.
- Тип АРМ: `group_types.behavior = 'container'` (код `workstation`) [VERIFIED: group_type_service.rs:845]. Контейнерным считать по `behavior`, а не по коду или имени (тип «АРМ» пользователь может переименовать; `behavior` неизменяем триггером `trg_group_types_immutable`).
- Другие поведения без якоря (`teardown`; `substitute` с убранным якорем) в фазе не требуются; решение для вложенных групп таких типов внутри АРМ вынесено в Open Questions. `teardown` не может содержать другие группы, но может лежать в контейнере [VERIFIED: set_parent_in_tx].

### Ключевая находка 3: объединённый запрос (D-04)

Рекомендуемая форма — двухшаговая, чтобы `ORDER BY`, `LIMIT/OFFSET` и `total` считались по одному тексту предиката (урок 41.11: COUNT и SELECT делят один предикат, иначе `total` расходится со строками):

1. **Ключи:**
```sql
SELECT k, id, name FROM (
  SELECT 0 AS k, d.id, d.name FROM devices d WHERE <предикаты устройств, как в select_list_rows>
  UNION ALL
  SELECT 1 AS k, g.id, g.name FROM groups g JOIN group_types t ON t.id = g.type_id
   WHERE <корневой контейнер без якоря> AND <в нём есть живое устройство>
) ORDER BY name, k, id LIMIT ?4 OFFSET ?5
```
2. **Гидратация:** устройства — через существующий `SELECT_DEVICES ... WHERE d.id IN (...)` + `enrich_devices`; группы — один запрос по `id IN (...)` с `place_full_paths`, `place_effective_variant`, счётчиком `tree_counts` и (для расширения) `group_place_paths`. Порядок возвращается по ключам первого шага.
3. `total` = `COUNT(*)` по тому же `UNION ALL`.

Порядок сортировки: существующий `ORDER BY d.name, d.id` использует двоичное сравнение (`BINARY`) [VERIFIED: devices_sqlite.rs:946]. Для согласованности смешанного списка с остальным использовать ту же `BINARY`-сортировку (заглавные кириллические идут раньше строчных); менять collation только для смешанного запроса нельзя — строки устройств внутри списка поменяют относительный порядок. Tie-break `k, id` обязателен (устройство и группа с одинаковым именем).

Строки АРМ включаются только когда `hide_anchor_members = true` и `status_id IS NULL` (единый переключатель). Иначе запрос совпадает с обычным `list`.

Блок вершины для «Свернуть одинаковые» (D-05) — отдельное чтение без пагинации: якоря + корневые непустые АРМ, `ORDER BY name, k, id`. Ограничение «до 200», действующее на якоря сейчас (`ANCHOR_MEMBERS_LIMIT`, сервис отвергает `limit > 200` [VERIFIED: device_service.rs:965-970, 1003]), этим чтением снимается; страховочный потолок задать константой и вернуть признак усечения, а не молча обрезать (урок «молчаливое усечение», UI-SPEC §10.1).

`has_more` для свёрток: `list_grouped` возвращает `Vec<DeviceGroup>` без `total` [VERIFIED: device_service.rs:1501-1553]. Вариант без изменения контракта: запрашивать `limit = 51` при размере порции 50 и обрезать на клиенте; `ORDER BY d.name` при фиксированном `type_id` детерминирован. Альтернатива — поле в ответе (тогда контракт `devices_list_grouped` меняется и затрагивает пикеры актов, которые им пользуются [ASSUMED: пикер акта использует `group_by_condition: true`; проверить grep по `listGrouped`]).

### Ключевая находка 4: поиск (D-14, R-01)

`devices_search` FTS5 не принимает флагов и по построению не скрывает членов [VERIFIED: device_service.rs:1414 комментарий D-10]. Строки АРМ при поиске нужно найти по имени группы: у групп FTS-таблицы нет, а `lower()` SQLite не сворачивает кириллицу [VERIFIED: комментарий в V045__groups.sql]. Прецедент — `search_fts` делает сопоставление пути места в Rust через `.to_lowercase()` [VERIFIED: devices_sqlite.rs:1184-1212]. Рекомендация: загрузить корневые непустые контейнеры (их десятки-сотни), отфильтровать в Rust (каждый токен запроса — префикс слова имени в нижнем регистре; те же токены, что `build_fts_query`), блок вернуть целиком с первой порцией (offset = 0), поиск устройств пагинируется как раньше. Вынести совпадение в чистую функцию в `trackly-core` с юнит-тестами (кириллица, регистр, несколько токенов, пустой результат sanitizer-а).

### Ключевая находка 5: раскрытие состава (D-11)

Существующий `member_of_group_id` отдаёт поддерево плоско и без якоря [VERIFIED: devices_sqlite.rs:58-75]. Для D-11 нужны прямые дети: устройства из `group_devices.group_id = ?` плюс прямые дочерние группы. Для дочерней якорной группы ребёнком является её якорное устройство (`DeviceDto` с `anchor_group_id`, строка отрисовывается как якорная), для дочерней группы без якоря — строка АРМ. Новая команда `devices_group_children(group_id, offset, limit)` с тем же DTO-элементом «устройство или контейнер», сортировка `name, k, id`, `total` и признак усечения. Принтеры-члены проходят, потому что запрос не ставит `type_id` (как нынешний `fetchAnchorMembers`).

Состав якорной группы верхнего уровня остаётся плоским (UI-SPEC §9.1) и по-прежнему запрашивается через `member_of_group_id`.

Догрузка остатка (D-09): сервис отвергает `limit > 200`; догрузка идёт циклом страниц по 200 до `total`, с защитой от изменения состава между страницами (повторный `total`, остановка при пустой странице). Не поднимать серверный максимум (`T-02-03-05` — осознанный лимит).

### Pattern 1: единый переключатель «скрытие = строки АРМ»

**What:** `shouldHideAnchorMembers(ctx)` уже есть; строки АРМ в непоисковых режимах включаются тем же булевым значением. Отдельной функции «показывать ли АРМ» в непоисковых режимах нет, в поиске правило своё (R-04: вкладка статуса и focusId сильнее запроса).
**When to use:** любое место, где решается показ строки АРМ или скрытие членов.
**Example:**
```ts
// ui/src/features/devices/deviceListMode.ts — расширение (новая чистая функция + кейсы в cases.json)
export function shouldShowContainerRows(ctx: ListModeContext): boolean {
  // непоисковые режимы: ровно тогда, когда члены скрыты
  if (!ctx.searchActive) return shouldHideAnchorMembers(ctx);
  // поиск: строки АРМ по имени, но вкладка статуса и focusId сильнее (R-04)
  return ctx.statusFilter === null && ctx.focusId === null;
}
```
Расхождение «строка АРМ показана, а члены скрыты» или наоборот даёт исчезающие устройства: закрепить таблицей истинности в фикстуре.

### Pattern 2: автоподгрузка с поколением запроса

**What:** порция дописывается в конец; ответ устаревшего поколения отбрасывается; в полёте один запрос; ошибка порции останавливает автоповторы до нажатия «Повторить».
**Reuse:** `refreshSeq`/`listGen`/`anchorsSeq` уже есть в `DevicesPage.svelte` [VERIFIED: строки 114-140] — добавить поколение порций по тому же образцу (снять номер ДО `await`, писать только если поколение текущее).
**Правила:** смена запроса/вкладки/«Свернуть одинаковые» — сброс на первую порцию и `scrollTop = 0`; мутация/инвалидация — перечитать уже загруженный объём (`offset 0, limit = загружено`, но не больше 200 за запрос: перечитывать циклом) и не трогать `scrollTop`.

```ts
// Source: паттерн DevicesPage.refresh() (поколение до await)
async function loadMore() {
  if (loadingMore || !hasMore || moreError) return;
  const gen = pageGen;
  loadingMore = true;
  try {
    const part = await devices.listEntries(filter, { offset: rows.length, limit: PAGE });
    if (gen !== pageGen) return;           // смена фильтра за время запроса
    rows = [...rows, ...part.rows];
    hasMore = part.has_more;
  } catch { if (gen === pageGen) moreError = true; }   // без тоста (R-06)
  finally { if (gen === pageGen) loadingMore = false; }
}
```

### Anti-Patterns to Avoid

- **Клиентское слияние АРМ и устройств.** Нарушает D-04; страницы перестают быть детерминированными.
- **Отдельный флаг показа строк АРМ независимо от флага скрытия.** Исчезающие/дублированные устройства.
- **Своя формула счётчика состава.** Использовать `tree_counts` (физические устройства, живые, с вложенными).
- **`lower()`/`LIKE` по кириллице в SQL.** Не сворачивает регистр; сопоставление в Rust.
- **Поднятие серверного максимума `limit`.** Остаток состава догружается циклом страниц по 200.
- **Ставить новые флаги в пикерах/автодополнении/экспорте CSV.** Они видят все устройства (инвариант 41.1, гейт `[D]` в `check-device-list-mode.mjs`).
- **Строка АРМ как `DeviceDto` с подменой полей** (прочерки «выдуманными» значениями). Нужен отдельный тип строки.

### 2. Колонки, форма строки, меню, просмотр

- **Колонки.** Все семь колонок строки — поля `devices` (`name`, `inventory_no`, `serial_no`, `model`, место, `state`, статус), у принтера они те же [VERIFIED: DeviceListRow.svelte]. Недостающих полей нет. Не показывается: IP, SNMP, уровень тонера, онлайн-статус принтера (это раздел «Принтеры»). «Статус» — статус устройства из справочника `device_statuses`, не состояние опроса.
- **Меню строки (GRD-05).** Одно и то же `DeviceRowMenu`. Различия для принтера: нет пункта «Опросить сейчас» (`onPoll` в «Устройствах» не передаётся); быстрые действия, создающие группу, только у `type_id = 1` (D-38), у принтера остаётся «Добавить в группу»; «Печать документа приёма» есть и у принтера (`onPrintAcceptance` передаётся всем строкам) [VERIFIED: deviceRowMenu.ts:60-90, DeviceRowMenu.svelte].
- **Двойной клик и «Просмотр».** `showView()` строит строку `kind = 'printer'` (`type_id === 2`) и открывает `PlaceEntityViewModal` с заголовком «Просмотр принтера»; кнопка «Перейти к принтеру» ведёт в `#/printers` (по `devices.id`). Правка из просмотра и пункт «Редактировать» открывают ту же `DeviceFormModal`, в форме есть блок принтера (IP, community, USB-хост) [VERIFIED: PlaceEntityViewModal.svelte шапка, DeviceFormBody.svelte `PRINTER_TYPE_ID`]. Новой формы или маршрута не нужно.
- **Мутации.** Удаление идёт через `devices_delete` на любом пути (то же, что в «Принтерах»); якорь удалить нельзя, отказ ведёт в группу (D-14). Смена типа в форме (устройство <-> принтер) обслуживается `sync_printer_row_in_tx`; сервер отвергает IP, community и USB-хост у не-принтера [VERIFIED: device_service.rs:1158-1200]. Из группы принтер не запрещён: запрет «сетевой принтер не может входить в группу» снят (41.13, D-15/D-16) и охраняется `group_network_printer_ban_guard.rs`. Групповые действия блокируются статусами `списано` и `на_списание` для любого типа.
- **Различимость в списке.** Колонки «Тип» нет; принтер от устройства визуально не отличается (Open Question 7).

### 3. Зависимости других путей (D-08: не должны измениться)

Фильтр `type_id: 1` существует только в `DevicesPage` (`rawFilter` и литерал экспорта). Все остальные вызывающие собирают свой `DeviceFilter` и от него не зависят [VERIFIED: grep `devices.list(`, `devices.search(`, `devices.listGrouped(`]: пикер акта (`ActFormItemsTable`), добавление устройств в группу (`GroupAddDevicesModal`), форма устройства (`DeviceFormBody`), автодополнение (отдельная команда), раздел «Принтеры» (`printers_list` по таблице `printers`, не по `devices_list`). Серверный умолчательный тип отсутствует, поэтому снятие литерала не может изменить эти пути. Единственный общий риск — ошибочно перенести правку «по умолчанию» на сервер: так нельзя (опт-ин инвариант 41.1, гейт `[D]` в `check-device-list-mode.mjs`).

### 4. Инвалидация

- Реестровый гейт INV-7 (`check-place-tree-invalidation.mjs`) относится к `notifyPlaceContentChanged` (счётчики дерева «Мест»), а не к ключам списка «Устройств»; список перечитывается самой страницей через `refresh()` [VERIFIED: DevicesPage.svelte, гейт].
- `DevicesPage` не подписана на `entities_changed` WS: страница создаётся заново при входе в раздел, поэтому правки принтера в «Принтерах», в акте или в заявке видны при следующем открытии. Правка чужим пользователем при уже открытой странице не подхватывается (так и для устройств).
- Write-site внутри страницы, которые теперь затрагивают строки принтеров, уже зовут `refresh()` и `refreshCounts()`: `DeviceFormModal.onSaved`, `onDelete`/`onChanged` строки (удаление, «Добавить в группу», быстрые действия, правка из просмотра), импорт CSV. Новых write-site для видимости принтеров добавлять не требуется.
- Что добавить: (а) перечитывание состава раскрытых групп включает принтеры (уже так: `fetchAnchorMembers` без типа); (б) если появится порционная подгрузка, правка принтера не должна сбрасывать загруженный объём (общее требование Pitfall 6); (в) правка из просмотра принтера должна доходить до `onChanged` (проверено: `handleViewChanged`). При сквозной инвентаризации от серверных мутаций (урок 40.1/INV-7) отдельная строка в реестр для принтеров нужна только если планировщик подпишет страницу на WS; тогда мутации `printers_*`, меняющие `devices`, и `devices_update` с сменой типа входят в перечень.

### 5. Поведение hide-флагов и K при `type_id: null`

- `hide_anchor_members`, `anchors_only`, `exclude_anchors`, `member_of_group_id` от типа не зависят: предикаты опираются на `groups`/`group_devices` [VERIFIED: devices_sqlite.rs:36-113]. Принтер-член АРМ или якорной группы скрыт снаружи так же, как устройство.
- K = `COUNT(*)` скрытых по тому же предикату и тому же `?3 IS NULL OR` => теперь включает принтеров-членов, и совпадает с бейджем АРМ (D-13) и с физическим счётчиком `tree_counts` (тот типа не фильтрует). Расхождение, описанное в прежней версии находки, исчезает.
- D-16 нетривиален: принтер, связанный с АРМ только по USB (`printers.usb_host_device_id`) или ссылкой (`ref_devices_for_group`, `usb_printers_for_group`), не входит в `group_devices` и скрытием не затрагивается. Он остаётся отдельной строкой общего списка и в раскрытии АРМ не показывается. Нужен тест: принтер с USB-хостом, который является членом АРМ, и принтер с USB-хостом, который членом не является.
- Общие принтеры (приписаны к нескольким АРМ) остаются видимыми в общем списке: это согласуется с D-16.
- Типы справочника кроме принтера (Монитор и т.п.): ведут себя как устройства, отдельного правила не требуют.

### 6. Риски

- Видимый скачок содержимого: в списке и в счётчиках «Показано N из M» теперь больше строк; вкладка «Все» по числу совпадёт со счётчиком вкладок (раньше счётчик был больше списка).
- «Свернуть одинаковые»: принтеры без серийного/инвентарного номера с одинаковым именем и моделью свернутся в набор; для сетевого принтера в таком наборе дети показываются обычными строками, но IP/место набора берутся по представителю (`place_distinct_count` > 1 гасит место) [VERIFIED: структура запроса list_grouped].
- Экспорт и импорт CSV: выгрузка с принтерами не ломает импорт (тип по подписи), но объём выгрузки растёт; потолок `EXPORT_MAX_ROWS` может сработать раньше.
- Устройства добавленных типов (id >= 3) внезапно появляются в списке: ожидаемо, но видимо для пользователя.
- Различимость принтера в списке не решена (Open Question 7).
- Автоподгрузка и `total`: `total` объединённого запроса теперь включает принтеры; тесты «сумма страниц = total» должны содержать принтеры.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Счётчик физических устройств группы с вложенными | Новый рекурсивный подсчёт | `tree_counts` (`groups_sqlite.rs:731`) или тот же CTE `closure` внутри запроса | Единая формула с «Местами» и «Группами»; защита от цикла и учёт удалённых |
| Сокращённый путь места группы | Своё сокращение | `compute_place_path_short_with_conn` (`services/place_path_display.rs`) | Гейт `check-place-path-short` запрещает полный путь в тексте ячейки; формула одна |
| Скрытие членов | JS-фильтр поверх страницы | серверный CTE (`anchor_members_sql!`) | JS-зеркало Rust-формулы нужно гейтить общей фикстурой; здесь правило только серверное |
| Шеврон, меню, бейдж, спиннер | Свои компоненты | `RowChevron`, `ActionMenu`, `Badge`, `Spinner`, `Button` (UI-SPEC §2) | Паритет, гейты `check-action-menu-portal`, `check-device-row-menu` |
| Охрана событий строки | Свои проверки | `isRowOverlayEvent`, `isOwnKeyEvent` (`deviceRowMenu.ts`) | Правый клик внутри модалки меню не должен гаситься |
| Регистрация команд | Ручной список | `collect_commands!` в `specta_export.rs` + `.route` в `http/devices.rs` | Гейт `http_route_parity.rs` читает оба списка от исходников |
| Сортировка/сравнение кириллицы | `COLLATE NOCASE` | прежний `ORDER BY name, id` (BINARY) | Согласованность порядка со всем остальным списком |

**Key insight:** новизна фазы не в механике скрытия (она одна правка CTE), а в том, что строка списка перестала быть устройством. Пока этого не признать на уровне DTO, всё остальное превращается в клиентские костыли.

## Common Pitfalls

### Pitfall 1: `<>` против NULL якоря
**What goes wrong:** после добавления засева контейнеров с `NULL`-якорем `gd.device_id <> a.anchor` даёт NULL, и члены АРМ не скрываются; тесты скрытия якорей остаются зелёными.
**How to avoid:** `IS NOT`; отдельный тест «член АРМ скрыт», мутационная проверка (вернуть `<>` — тест краснеет).
**Warning signs:** K в футере не растёт после создания АРМ.

### Pitfall 2: расхождение `total` и строк в объединённом запросе
**What goes wrong:** COUNT и SELECT собраны из разных текстов предиката.
**How to avoid:** один макрос/константа предиката на оба (как `LIST_FLAG_PREDICATES`); тест «сумма строк по всем страницам = total, без повторов и пропусков» на данных с одинаковыми именами устройства и группы.

### Pitfall 3: тайбрейк
**What goes wrong:** устройство и группа с одним именем меняются местами между страницами, строка дублируется или пропадает.
**How to avoid:** `ORDER BY name, k, id`; тест на странице размером 1-2 по набору с совпадающими именами.

### Pitfall 4: отсутствие маршрута скрыто `spa_fallback`
**What goes wrong:** новая команда есть в Tauri, маршрута нет; LAN-браузер получает `index.html` с 200 (так счётчики отчётов не работали с фазы 28).
**How to avoid:** каждая команда сразу парой; `http_route_parity.rs` обязан остаться зелёным; плюс HTTP-смоук нового маршрута (образец `devices_http_smoke.rs`). После Фазы 41.7 неизвестный `/api/v1/*` отвечает JSON 404 [CITED: заголовок `http_route_parity.rs`], но проверять нужно явно.

### Pitfall 5: прокручиваемый контейнер скрыт внутри `Table`
**What goes wrong:** слушать `scroll` на окне нечего; `.tr-table-wrapper` в `Table.svelte` не доступен снаружи [VERIFIED: Table.svelte:51].
**How to avoid:** аддитивный проп (например, `bind:wrapperEl` или `onNearEnd`) в `Table.svelte`; остальные разделы не меняются (D-08). Проверка «короткая первая порция»: если контент не заполняет область, а данные есть — грузить следующую без прокрутки (`ResizeObserver` на содержимое или проверка после каждой порции).

### Pitfall 6: мутация сбрасывает позицию и загруженный объём
**What goes wrong:** `refresh()` сейчас перечитывает с `offset 0, limit 50` — после подгрузки список «схлопывается» к 50 строкам, `scrollTop` прыгает.
**How to avoid:** после мутации перечитывать столько строк, сколько загружено (циклом по ≤200 за запрос), заменять на месте по ключам; не пересоздавать `{#each}`.

### Pitfall 7: догрузка состава теряет фокус и возвращает иконку
**What goes wrong:** кнопка исчезает вместе с фокусом; перечитывание после мутации снова усекает состав до 200 и иконка возвращается.
**How to avoid:** фокус на шеврон строки (UI-SPEC §11.3); флаг «догружена целиком» хранится рядом с кешем состава и задаёт объём перечитывания (`reloadExpandedAnchors` сейчас всегда берёт `ANCHOR_MEMBERS_LIMIT`).

### Pitfall 8: `focusId` и подсветка строки из поздней порции
**What goes wrong:** `DeviceList` прокручивает к `device-row-{id}` один раз при первой загрузке [VERIFIED: DeviceList.svelte:72-81]; при автоподгрузке устройство из поздней порции не рендерится, прокрутки нет.
**How to avoid:** при `focusId` режим уже плоский без свёртки; перейти по `id` серверно (вернуть порцию, содержащую устройство, либо отдельное чтение устройства и вставка первой строкой) — решение планировщика; не выдёргивать пользователя из текущей позиции для строки из поздней порции (UI-SPEC §10.4).

### Pitfall 9: компиляционные гейты не видят рантайм-ошибок рун
**What goes wrong:** `svelte-check`/`eslint`/`build` не ловят `state_unsafe_mutation`, циклы эффектов, `effect_update_depth_exceeded` в новой подгрузке.
**How to avoid:** проверка в запущенном приложении и LAN-браузере (список в UI-SPEC §14); не использовать синтетический стенд как верификацию.

### Pitfall 10: `Показано N из M` при смешанных строках
**What goes wrong:** `footerText({ shown: items.length, ... })` берёт `items.length` устройств; строки АРМ в N/M не учтены.
**How to avoid:** N = число загруженных строк верхнего уровня, M = серверный `total` объединённого запроса; K — `hidden_member_count` (устройства). Закрепить в `deviceListMode.ts` и фикстуре; режим свёртки получает хвост `(+K ...)` (R-02), для чего K должен прийти и из блока вершины.

### Pitfall 12: правка `type_id` не там
**What goes wrong:** фильтр типа «убирают» на сервере или в `deviceListMode.ts`, и пикеры актов, добавление в группу и автодополнение меняют поведение (D-08).
**How to avoid:** правка только в `DevicesPage` (`rawFilter` и, по решению, литерал экспорта); тест реестра фильтров подтверждает, что серверного умолчания по типу нет; регресс-тест пикера без `type_id` не меняется.

### Pitfall 11: вакуумные тесты
**What goes wrong:** тест «члены АРМ скрыты» проходит и без исправления, если фикстура не отличает до- и после-фикс.
**How to avoid:** прогнать новый тест по замороженному состоянию (до правки CTE) и убедиться, что он красный; для гейтов — мутация реального исходника (уникальный якорь замены).

## Open Questions

1. **D-15/D-16 и `type_id: 1` — ЗАКРЫТ решением пользователя (D-18).** Принтеры показываются в общем списке, фильтр типа снимается. Остаток вопросов, порождённых решением, вынесен ниже (вопросы 7-9).

2. **Вложенные группы без якоря не-АРМ типа внутри АРМ (`teardown`, `substitute` без якоря).**
   - Known: D-11 покрывает «якорная» и «вложенный АРМ».
   - Recommendation: любая вложенная группа без якоря рисуется строкой АРМ (универсальная «группа без якоря»); решение отметить в плане.

3. **Блок якорей при вложенном якоре внутри АРМ (D-12).**
   - Recommendation: серверный блок вершины сам исключает якоря, лежащие в поддереве корня-контейнера; тест по данным.

4. **Режим `focusId` при автоподгрузке.** Как подтянуть строку устройства, лежащую за пределами первой порции (Pitfall 8). Recommendation: серверная порция «страница, содержащая id» или прицельное чтение; выбор за планировщиком, проверить на живом переходе из «Мест».

5. **Размер порции и потолок блока вершины.** Рекомендация: порция 50 (как сейчас, UI-SPEC §10.1), потолок блока вершины — константа с признаком усечения.

6. **Новые требования D-07..D-10 и D-18.** Завести GRD-09/GRD-10/GRD-11 в REQUIREMENTS.md и критерии фазы в ROADMAP до планирования (CONTEXT прямо просит).

7. **ЗАКРЫТ решением пользователя (D-20): иконка принтера перед именем.** Ниже — исходная постановка.
   **Как отличить принтер от устройства в списке.**
   - Known: у таблицы нет колонки «Тип», UI-SPEC её не вводит; строка принтера выглядит как строка устройства.
   - Unclear: нужен ли маркер типа (бейдж, иконка), либо различия достаточно в «Просмотре» (заголовок «Просмотр принтера») и в меню.
   - Recommendation: не менять колонки без решения пользователя; вынести как вопрос к UI-SPEC (дизайн-контракт утверждён без принтеров).

8. **Экспорт CSV из «Устройств».** `exportCsv` в `DevicesPage` строит свой литерал с `type_id: 1`. Recommendation: снять и здесь (выгрузка должна совпадать с тем, что на экране; колонка «Тип» из справочника различает принтеры), но это отдельный литерал, D-18 его прямо не называет: подтвердить.

9. **Подпись «+ Добавить устройство» и текст пустого состояния.** Создание принтера из «Устройств» уже возможно (форма знает `PRINTER_TYPE_ID`); тексты «Устройств пока нет» остаются как есть, менять не требуется. Подтвердить, что формулировки устраивают.

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| SQL-инъекция через имя группы / поисковую строку | Tampering | параметризованные запросы, сопоставление имён в Rust, `build_fts_query` для устройств |
| Раскрытие данных не той роли через новый маршрут | Information disclosure | регистрация в матрице ролей; тест роли на каждом новом маршруте |
| DoS огромным `limit`/частыми порциями | Denial of service | лимит 200 на сервере, одна порция в полёте на клиенте, ошибка без автоповторов |
| Рекурсия по циклу групп | DoS | `UNION` (не `UNION ALL`) в CTE, как в существующих макросах |
