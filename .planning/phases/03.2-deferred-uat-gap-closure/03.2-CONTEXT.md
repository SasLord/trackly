## Implementation Decisions

### DEF-1 — Focus-open autocomplete (LOCKED)
Привести `PersonAutocomplete` и `DeviceAutocompleteField` к тому же поведению, что
уже реализовано в `LocationAutocomplete` (commit b2c43a5): focus → сразу показать
первые 20 suggestions (даже empty prefix), ArrowDown при закрытом dropdown тоже
триггерит fetch.

**Canonical pattern (реплицировать):** `LocationAutocomplete.svelte:59-63` —
```
function handleFocus() { suppress = false; scheduleFetch(value, 0); }
```
плюс `onfocus={handleFocus}` на input и ветка ArrowDown-при-закрытом (`:80-85`).

**Текущее состояние:**
- `PersonAutocomplete.svelte` — нет onfocus; debounce-fetch только на input; есть
  `suppressDropdown` (edit-mode pre-fill suppression). handleFocus должен снять
  suppressDropdown и fetch с delay 0. Backend `acts.suggest_person` УЖЕ поддерживает
  empty prefix (frequency DESC) — backend менять НЕ нужно.
- `DeviceAutocompleteField.svelte` — fetch через `$effect` на `value` с guard
  `v.length < 1` (`:102`) → пустой prefix сейчас НЕ фетчит. Нужен handleFocus +
  onfocus, и снять/обойти `v.length < 1` early-return для focus-триггера. Проверить
  backend `devices.autocomplete(field, prefix, …)`: поддерживает ли empty prefix;
  если есть non-empty restriction — снять (вернуть top-20 frequency/alpha).

**Acceptance:** во ВСЕХ трёх autocomplete (Location/Person/Device) фокус в пустое
поле показывает first-20; edit-mode pre-fill по-прежнему НЕ открывает dropdown до
явного focus/keystroke (не регрессировать suppress-логику).

### DEF-2A — Dedupe уже-выбранных devices в picker (LOCKED)
В `ActFormItemsTable.svelte` device picker НЕ должен предлагать группы/devices, уже
выбранные в других строках items. Backend `validate_create` уже отлавливает дубли
(HashSet dedup) — это чисто UI-фильтр для предотвращения.

**Скоуп:** в `pickGroup` + в списке suggestions исключать уже выбранные
`group.repr.id` / `group.ids` (devices, занятые другими items текущей формы).
**Acceptance:** добавив группу в строку 1, в dropdown строки 2 эта группа/её
devices не появляются (или disabled).

### DEF-2B — Sub-group по condition → ВАРИАНТ 2 (LOCKED)
Группировать `DeviceGroup` по `(name, model, condition)` вместо `(name, model)`.
Тогда «DVD-ROM ASUS, Хорошее ×1» и «DVD-ROM ASUS, Новое ×1» — две отдельные строки,
и при handover клон наследует condition выбранного представителя группы корректно.

**Скоуп:**
- `crates/trackly-infra/src/repos/devices_sqlite.rs` `list_grouped` — добавить
  `condition` (DB-колонка) в GROUP BY group-key. (DTO-имя поля — `state`.)
- `crates/trackly-core/src/ports/devices.rs` + `device_service.rs` — обновить
  тип DeviceGroup/сигнатуру, если group-key экспонируется.
- UI: tooltip/подпись группы показывает condition (`state`), чтобы пользователь
  различал «Хорошее» vs «Новое».
- Тесты `list_grouped` с новым group-key (две записи same name+model, разный
  condition → две группы; same condition → одна группа count=2).
**Отвергнуто:** Вариант 1 (раскрытие индивидуальных devices в dropdown) — future,
не в этой фазе.

### DEF-3 — Devices table показывает location активного handover → ВАРИАНТ A (LOCKED)
`ActService::create` пишет **resolved** `devices.location_id` при handover для каждого
device_id (в том же writer-tx, что меняет status на «в_работе»); на return — restore.

**Grounding (подтверждённый баг):** `act_service.rs` уже вызывает
`update_status_and_location_in_tx(..., in_work_status_id, payload.location_id, ...)`
(≈`:420-424`), НО передаёт **сырой** `payload.location_id` вместо
`resolved_location_id`, вычисленного из `location_name` на `:258-262`. Поскольку акты
теперь создаются через `location_name` (commit b2c43a5), `payload.location_id`=None →
devices.location_id не обновляется. **Fix Варианта A:** передавать `resolved_location_id`
в handover-UPDATE.

**Return-путь:** `do_return` уже резолвит и пишет location в `devices.location_id`
(resolved_bulk_location_id / per-item override, ≈`:662-667`). Проверить, что на возврат
devices.location_id корректно восстанавливается (resolved location или, при отсутствии
override, осмысленный fallback — НЕ затирать в None молча).
**Минус принят:** careful tracking pre-handover location — допустимо опираться на
существующее поведение do_return как source of truth для return location.

### Claude's Discretion
- Точная механика снятия `suppressDropdown` в Person/Device на focus (сохранить
  edit-mode pre-fill контракт).
- Сигнатура DeviceGroup при добавлении condition в key (новое поле vs расширение repr).
- Формат UI-tooltip для condition в группе.
- Нужна ли DB-миграция для DEF-2B (вероятно НЕТ — только SQL запроса list_grouped).
