<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Untrusted staged/HEAD file content → gate's tokenizer/regex engine | Any file in the repo, including attacker-crafted filenames in a future PR, is fed to `execFileSync`/`fs.readFileSync` |
| Gate's own stdout/stderr → public CI logs | Anything printed by the gate on a public-repo CI runner is world-readable forever |
| `--hashes` file → gate's trust decision | The gate's entire detection capability is only as good as this file's contents; a missing/empty file must never silently mean "nothing to check" |
