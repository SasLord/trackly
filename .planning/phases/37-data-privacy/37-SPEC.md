## Goal

Из HEAD удалены все реальные данные организации и людей (реквизиты, ФИО, инфраструктурные
идентификаторы, бинарные reference-артефакты) — 17 текстовых файлов и 3 бинарных, — а повторная
утечка блокируется единым durable-гейтом, который сравнивает SHA-256 токенов из файла
и работает в двух точках: `pre-commit` (staged-файлы) и CI (весь HEAD).

   - Acceptance: запуск гейта с удалённым файлом хэшей даёт ненулевой код возврата;

   - Acceptance: добавление `.docx` в произвольный путь роняет гейт; существующие

9. **Исключения только по путям**: борьба с ложными срабатываниями не ослабляет обнаружение.

     «разрешить строку» нет — токен, попавший в список хэшей, ловится везде, где не исключён путь

## Boundaries

**In scope:**
- Обезличивание 17 текстовых файлов HEAD по классам A/B/C (замена на плейсхолдеры, смысл сохраняется)
- Удаление `.planning/reference/act-word-source/` из индекса + `.gitignore`
- Удаление `.planning/PHASE-BRIEF-act-pdf-word-fidelity.md` (файл-носитель самой плотной утечки; его роль — вход для фазы 15, давно выполненной)
- Новый единый durable-гейт: allowlist реквизитов + хэши токенов + контроль бинарников + исключения по путям
- Поглощение и удаление `scripts/check-privacy-requisites.sh`, перевод шага `ci-fast.yml` на новый гейт
- `pre-commit`-хук в версионируемом каталоге хуков + документация по его включению
- Файл SHA-256 хэшей токенов, коммитится в репозиторий

**Out of scope:**
- **Переписывание истории git** (`filter-repo`, force-push) — решение пользователя от 2026-08-08, остаточный риск в старых коммитах принят осознанно; отслеживается как PRIV-03 в Backlog
- **Перевод репозитория в private** — то же решение
- **Распаковка и сканирование содержимого бинарных файлов** — заменено более дешёвым и более надёжным контролем по расширению+пути (R8)
- **Морфологическая нормализация русских окончаний в токенах** — отклонено в пользу токен-хэшей без стемминга: риск ложных срабатываний выше выигрыша
- **Секреты/пароли/API-ключи** — другой класс задачи, у него свои инструменты; эта фаза про персональные и организационные данные
- **Подключение гейта в `pnpm --dir ui lint`** — гейт repo-wide и написан не только про фронтенд; ROADMAP SC4 допускает «или эквивалентный CI-гейт», и `pre-commit` + `ci-fast.yml` этот критерий закрывают строже
- **Аудит `.planning/`-артефактов на утечки, не относящиеся к классам A–D** — за границей: классы зафиксированы разведкой, расширение списка — новая работа
- **Ротация пароля служебной учётной записи AD** — операционное действие пользователя (уже зафиксировано в Out of Scope вехи)

## Constraints

- **Порядок обязателен:** чистка (R1–R4) полностью предшествует включению гейта (R10).
  Гейт, включённый раньше, падает на собственном репозитории и блокирует работу над фазой.
- **Артефакты фазы сами не должны содержать маркеров.** PLAN/SUMMARY/REVIEW фазы 37 пишутся
  без цитирования утёкших значений; перед каждым коммитом фазы — прогон гейта по staged.
  Известный риск: агенты-исполнители и ревьюеры цитируют реальные значения из git-истории
  в свои отчёты (зафиксировано как повторяющаяся ловушка проекта).
- **CI не имеет доступа к секретам для этой проверки** — гейт обязан работать, имея только
  закоммиченный файл хэшей.
- **Git не включает хуки автоматически** — `core.hooksPath` требует одной локальной команды;
  поэтому CI-шаг обязателен как страховка, а не как дублирование.
- **Совместимость:** гейт запускается на macOS (dev) и Linux (CI runner). Windows-запуск
  не требуется.
- **`git grep -I`** (без бинарников) — канонический способ проверки критериев R1–R3, чтобы
  проверка не спотыкалась о бинарные файлы.
