## Phase Goal

**As a** сотрудник, выдающий устройство в работу, **I want to** создать акт приёма-передачи через UI с автоматическим следующим номером (или ручным override с фиксацией в журнале) и увидеть его в списке/детали, **so that** записи передачи устройств ведутся без Excel и без ручного присвоения номеров — это первое реальное окно ценности Phase 3 (закрывает ACT-01, ACT-02, ACT-03, ACT-05, ACT-13, ACT-14).

> **Vertical slice (MVP mode):** этот план даёт ДВЕ UI-возможности конечному пользователю — «Создать акт» (модал) и «Посмотреть акт в списке + детали» (master-detail). Возвраты, undo, PDF — следующие планы. После этого плана пользователь видит свой первый акт в Trackly.

<objective>
End-to-end вертикальный срез по созданию handover-акта: V014 indexes → core domain types (ActNew/ActRow/ActType) → core port (ActRepository) → infra repos (acts_sqlite + audit_log_sqlite + atomic counter) → app service (ActService::create под single-writer одной транзакцией) → DTO + Tauri commands + axum router → UI master-detail + wide create modal с ActNumberField (auto/override) + ActFormItemsTable.

Purpose: Закрыть «зелёным путём» 6 требований (ACT-01, ACT-02, ACT-03, ACT-05, ACT-13, ACT-14) и поставить шину, через которую планы 03/04 повесят возвраты и PDF.

Output: Запускаемое приложение `pnpm tauri dev`, в котором маршрут `#/acts` показывает master-detail layout, кнопка «+ Создать акт» открывает wide-модал, сохранение создаёт акт через единую транзакцию single-writer с инкрементом counter, switch-bar показывает счётчики, devices переключаются в «В работе» с новой Location.
</objective>
