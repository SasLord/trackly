## Phase Goal

**As a** сотрудник, **I want to** нажать кнопку «Печать» в детали акта и увидеть готовый PDF с реальными кириллическими ФИО, шапкой организации и таблицей позиций, который можно сохранить, открыть в системном просмотрщике или отправить на печать, **so that** учётный документ оформляется в один клик из приложения без выгрузки в Excel или Word — это центральная ценностная точка Phase 3 (закрывает ACT-11, ACT-12, DEV-15).

> **Vertical slice (MVP mode):** этот план соединяет PDF infrastructure (plan 01), acts CRUD (plan 02), returns (plan 03) с реальным потоком печати. После него «Печать» в ActDetail работает: появляется preview-модал с PDF, видны ФИО кириллицей, шапка организации, таблица устройств. Заодно семинаются дефолтные шаблоны в БД (ACT-12 шаблон акта приёма-передачи + DEV-15 шаблон документа приёма) и читается org.json для шапки.

<objective>
Templates seeding + Organization JSON I/O + полный PDF render pipeline endpoints: template_service (seed + get_active + render_preview) + organization_service (read + placeholder + logo path) + act_service.render_pdf + devices_render_acceptance_pdf + tauri commands + UI PdfPreviewModal с pdfjs-dist (через iframe blob: URL — без worker config per Pitfall 8).

Purpose: Закрыть требования ACT-11 (PDF Акта с шапкой+логотипом), ACT-12 (Редактируемый шаблон в БД — структурно через seed, UI редактор в Phase 7), DEV-15 (Редактируемый шаблон документа приёма — то же).

Output: «Печать» из ActDetail → PdfPreviewModal с реальным PDF; «Сохранить как PDF» → tauri-plugin-dialog save; «Открыть в системном просмотрщике» → tauri-plugin-shell open; «Печать» → window.print() на iframe. DEV-14 (документ приёма из страницы устройств) подготовлено backend-методом, UI button в plan 05.
</objective>
