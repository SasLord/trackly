<interfaces>
Текущая (баговая) реализация checkHunk() в verify-value-map.mjs:76-97 uses one anchored `^` plus a
lazy `.*?` pattern with the `m` flag, which under matchAll yields at most one match per line:
removedTokens comes from `/^-.*?(--(?:space|radius)-[a-z0-9]+)/gm` and addedTokens from
`/^\+.*?(--tr-(?:space|radius)-[a-z0-9]+)/gm`. Bug (CR-01, confirmed): a second or later token on
the same changed line (common pattern `padding: var(--x) var(--y);`) is never captured on either
side.

Текущий хвост файла verify-value-map.mjs (строка 175) — безусловный вызов `main();` на module
scope. main() вызывает process.exit() на каждой ветке (включая exit(1) при отсутствии
<base-ref>-аргумента). Это надо изменить на run-if-main guard, иначе named exports нельзя
безопасно импортировать (см. Task 1 action).

Rule 2 (hex-in-style) in check-tokens.mjs:113-136 is the template for the new Rule 4: it reuses
STYLE_BLOCK_RE = `/<style[^>]*>([\s\S]*?)<\/style>/g`, restricts to `.svelte` files only, and for
each style block runs the detection regex (currently HEX_RE) via `block.matchAll(...)`, pushing a
violation per match with file/line/matched-text. Rule 4 copies this exact structure, swapping only
the detection regex to `/\b(?:rgba?|hsla?)\(/g`. Script philosophy is "grep, not parser" (see file
header) — matching inside a `var(--tr-x, rgba(...))` fallback default is intentional: the closed-world
token layer (D-01, no bridge aliases) makes such fallbacks dead code that should be removed, not
preserved.

Current --tr-danger* tokens in _tokens.scss (light block, lines 49-51): --tr-danger: #cf3b3b;
--tr-danger-soft: rgba(207, 59, 59, 0.12); --tr-danger-text: #b02f2f; (dark block, lines 121-123):
--tr-danger: #f26565; --tr-danger-soft: rgba(242, 101, 101, 0.16); --tr-danger-text: #ff8080; The
new --tr-danger-ring follows the same rgb-component decomposition of each theme's --tr-danger at
alpha 0.2 (matching the majority of the 9 existing sites — Button.svelte today uses 0.3, which Plan
23-08 intentionally converges to the single canonical value): light `rgba(207, 59, 59, 0.2)`, dark
`rgba(242, 101, 101, 0.2)`.
