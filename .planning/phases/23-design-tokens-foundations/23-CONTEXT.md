# Phase 23: Токены и основы дизайн-системы (design-tokens-foundations) - Context

**Gathered:** 2026-07-16
**Status:** Ready for planning

<domain>
## Phase Boundary

Фаза 23 доставляет **слой токенов** и ничего больше. Конкретно: `ui/src/styles/_tokens.scss`
переписывается с нуля в единый слой `--tr-*` (поверхности, 5 уровней текста, акцент с
hover/active/soft, семантика с парами `-soft`/`-text`, нейтральная шкала `n-0…n-950`, 5 уровней
теней, 9 типографических ролей, 11 шагов space, 5 радиусов), а все call-sites в `ui/src`
(118 svelte-файлов **+ `global.scss`**) механически переводятся на новые имена по картам из
`23-UI-SPEC.md`. Попутно закрываются баги неопределённых токенов (QA-01 + 3 находки сверх него).

Требования: **DS-01, DS-02, DS-03, DS-04, QA-01**.

**В границах фазы:**
- Новый `_tokens.scss` — только `--tr-*`, старые имена удалены полностью.
- Механическая миграция всех call-sites по трём разным правилам (цвет — по роли, значения меняются;
  space/radius — по значению, значения НЕ меняются; типографика — по роли, размер может лечь на
  ближайший из 9 уровней).
- `global.scss` (body, focus-ring, скроллбар, skip-link) — мигрируется так же, как компоненты.
- Глобальный класс `.tr-mono` + его применение к идентификаторам (DS-03).
- Греп-гейт в lint/CI против возврата старых токенов и захардкоженных hex.
- Скрипт-верификатор карты space/radius (доказательство DS-04).

**Вне границ:**
- Визуальный редизайн компонентов (Button, Input, Badge, Tabs, Modal) — фаза 24.
- Таблицы и Dropdown — фаза 25. Окна — фазы 26–29.
- Layout-константы (`--sidebar-width`, `--header-height`, `--modal-max-width`, `--touch-target-min`,
  `--row-height*`) — не переименовываются в этой фазе (см. UI-SPEC §Layout constants).
- AA-контраст, форма focus-ring, паритет Tauri vs LAN-браузер — фаза 30 (QA-02/QA-03).
- Печатные HTML-шаблоны актов (`crates/trackly-app/templates/*.html`) — дизайн-система на них
  не распространяется (REQUIREMENTS.md → Out of Scope).
- Любые изменения поведения/логики/API.

</domain>

## Значения и карты миграции заблокированы UI-SPEC

`23-UI-SPEC.md` (статус `approved`, закоммичен) — **источник истины по значениям**.
Downstream-агенты ОБЯЗАНЫ прочитать его до планирования. Не дублируем сюда и не переоткрываем:

- Все hex-значения `--tr-*` для light + dark (brand/accent, surfaces, text, border, semantic,
  row states, neutral ramp, elevation).
- Карта цвета «старая роль → новая роль» + список ~48 захардкоженных hex с целевыми токенами.
- Шкала типографики (9 ролей: display/h2/h3/subtitle/body/body-strong/label/caption/micro + mono).
- Карта space **по значению** (7 старых имён → value-matched `--tr-space-*`).
- Карта radius по значению + split `--radius-sm`.
- Решение по motion (`transition: none` в `Button.svelte:46` — только про переключение темы;
  micro-transitions разрешены и относятся к фазе 24).

Единственное, что фаза 23 добавляет поверх UI-SPEC — решения ниже: **как** провести миграцию.

<decisions>
## Implementation Decisions

### Снос старого слоя

- **D-01:** **Старые токены сносятся целиком, без bridge-алиасов.** `_tokens.scss` переписывается
  с нуля — в нём остаются ТОЛЬКО `--tr-*` (+ неизменные layout-константы, см. D-02). Имена
  `--color-*`, `--space-*`, `--radius-*`, `--font-size-*`, `--font-weight-*`, `--line-height-*`,
  `--font-family-base`, `--shadow-elev-*` не существуют после фазы.
  **Обоснование:** CSS custom properties резолвятся в пустоту молча — сборка пропуск НЕ поймает.
  Временный алиас-слой означал бы, что пропущенный call-site выглядит корректно и доезжает до
  фазы 24 незамеченным. Без алиасов любой пропуск сразу виден как дефект (чёрный текст,
  нулевой паддинг) на UAT — то есть отсутствие подстраховки здесь и есть подстраховка.
- **D-02:** Layout-константы (`--sidebar-width`, `--header-height`, `--modal-max-width`,
  `--modal-max-width-wide`, `--touch-target-min`, `--row-height`, `--row-height-dense`) остаются в
  `_tokens.scss` под старыми именами и со старыми значениями — они не входят в семейства DS-01..04
  (см. UI-SPEC §Layout constants). Греп-гейт (D-04) их не трогает.
- **D-03:** `--shadow-elev-2-dark` удаляется как мёртвый код (0 call-sites; elevation теперь
  theme-scoped внутри самого `--tr-elev-*`) — подтверждено UI-SPEC §Elevation.
- **D-04:** **Греп-гейт в `pnpm lint` и CI.** Небольшой скрипт (node/sh, без новых dev-зависимостей),
  падающий при обнаружении в `ui/src`:
  1. `var(--color-*|--space-*|--radius-*|--font-size-*|--font-weight-*|--line-height-*|--shadow-*)`
     (кроме layout-констант из D-02);
  2. hex-литерала внутри `<style>`-блока svelte-файла.
  Гейт живёт до конца v1.2 и защищает фазы 24–30 от регресса. Точная реализация (отдельный скрипт
  vs расширение `lint`-скрипта, механика вырезания `<style>`-блока) — на усмотрение планировщика.
  Решение против stylelint: он мощнее и понимает CSS, но это новая dev-зависимость + настройка под
  Svelte ради двух правил.
- **D-05:** `global.scss` мигрируется **механически по карте**, наравне с компонентами:
  `--color-bg` → `--tr-bg`, `--color-text-primary` → `--tr-text-primary`,
  `--font-family-base` → `--tr-font-family`, `--space-md` → `--tr-space-md`,
  `--color-accent-focus` → `--tr-focus-ring`, `--color-border-strong`/`--color-text-muted`
  (скроллбар) → `--tr-border-strong`/`--tr-text-tertiary`.
  **Форма** focus-ring (`box-shadow: 0 0 0 3px`) и его охват (`*:focus-visible`) **не меняются** —
  это QA-02, фаза 30. Меняется только имя токена внутри.
  `@use './tokens'` в `global.scss` — единственная точка подключения, менять её не нужно (в файле
  есть комментарий, почему это не `prependData`: svelte хэширует `:root` в scoped-блоках).

### Дробление на планы

- **D-06:** **Дробить по семействам токенов, а не по каталогам/экранам.** Причина: три семейства
  мигрируют по трём РАЗНЫМ правилам, и их смешение в одном плане — это ровно тот футган, от которого
  предостерегают REQUIREMENTS.md и UI-SPEC. Один план = одно правило = один способ проверки.
  Предлагаемая (не жёсткая) раскладка:
  - План 1: новый `_tokens.scss` (весь `--tr-*` слой) + `global.scss`. Все остальные планы зависят от него.
  - План: **цвет** — по роли, значения меняются намеренно (+ ~48 hardcoded hex, + 7 сайтов
    `--color-surface-hover`/`-muted` из bug sweep UI-SPEC).
  - План: **space + radius** — по значению, значения не меняются (642 + 132 call-site).
  - План: **типографика** — по роли (~344 call-site) + `.tr-mono` (D-11/D-12).
  - План: **греп-гейт (D-04) + скрипт-верификатор карты (D-08)**.
  Точное число планов и волн — на усмотрение планировщика.
- **D-07:** **Split `--radius-sm`: безопасный дефолт — `--tr-radius-xs` (4px).** Из 103 call-site
  `var(--radius-sm)` значение 6px (`--tr-radius-sm`) получают ТОЛЬКО файлы из явного списка,
  зафиксированного в плане: `Button.svelte` и chrome полей ввода (Input/Select/Textarea/Checkbox).
  Всё остальное — включая спорные и кнопкоподобные элементы вне этого списка — уходит в
  `--tr-radius-xs` (4px, сохранение значения).
  **Обоснование:** дефолт должен падать в сторону DS-04 («не сдвигать»), а не в сторону
  субъективного «это похоже на кнопку». Пропущенный 4→6 — косметика, которую подберёт фаза 24;
  ошибочный 6px на чипе — незамеченный сдвиг.

### Проверка DS-04 («вёрстка не сдвигается»)

- **D-08:** **Скрипт-верификатор карты + ручной обход.** Автоматическая часть: скрипт разбирает
  git-дифф миграции space/radius и проверяет, что каждая замена соответствует value-map из UI-SPEC
  (старый токен → токен с тем же px), с одним разрешённым исключением — split `--radius-sm` (D-07).
  Это проверяет ровно ту ошибку, о которой предупреждает REQUIREMENTS.md («642 использования тихо
  поедут без единой ошибки сборки»), и делает это без запуска браузера.
  **Решение против playwright screenshot-diff:** цвета в этой фазе меняются НАМЕРЕННО
  (`--tr-bg` #fff→#eef1f6, инверсия поверхностей — D-10), поэтому pixel-diff был бы красным на
  каждом экране и не отличал бы «сдвинулась геометрия» от «поменялся цвет». Он проверял бы не то.
  Форма реализации скрипта (одноразовый vs постоянный в CI) — на усмотрение планировщика; ценность
  прежде всего одноразовая, во время миграции.
- **D-09:** **Визуальную проверку делает пользователь на UAT** (`/gsd-verify-work`) — обе темы,
  3–4 плотных экрана (Устройства, форма акта, Настройки) минимум. Исполнитель отвечает за
  скрипт-гейт, греп-гейт и `pnpm lint` / `svelte-check`, но НЕ поднимает браузер сам: бо́льшая часть
  UI за логином и требует бэкенда с данными. Паритет Tauri WebView vs LAN-браузер в этой фазе не
  проверяется — это QA-03, фаза 30.
  **Гоча для UAT (из памяти проекта):** серверный режим отдаёт `ui/dist`, поэтому перед проверкой
  через LAN-браузер нужен `pnpm --dir ui build`; `cargo tauri dev` хотрелоадит только
  desktop-webview.

### Промежуточный вид после фазы

- **D-10:** **Новые значения включаются сразу; «полуготовый» вид на несколько фаз принимается.**
  После фазы 23 приложение заметно изменится (в первую очередь потому, что **поверхности
  инвертируются**: `--color-bg` #ffffff → `--tr-bg` #eef1f6 и `--color-surface` #f5f6f8 →
  `--tr-surface` #ffffff — раньше белый холст с серыми панелями, теперь серый холст с белыми
  панелями), но компоненты останутся старыми до фаз 24–26. Это принято осознанно: каждая следующая
  фаза строит компоненты на реальных цветах, а не вслепую. Релиз в середине v1.2 не планируется.
  Вариант «имена мигрируем, значения включим флагом позже» отклонён — тогда DS-01/DS-02 в фазе 23
  нечем проверить.
- **D-11:** **Инверсию поверхностей мигрировать строго по карте UI-SPEC, не импровизируя:**
  `--color-surface` → `--tr-surface` везде, `--color-surface-muted` → `--tr-surface-sunken`,
  `--color-surface-hover` → `--tr-row-hover`. Места, где после инверсии пропал контраст
  (белое-на-белом), выявляются на UAT (D-09) и чинятся точечно — через `--tr-border`, `--tr-elev-1`
  или `--tr-surface-sunken`. Исполнитель НЕ триажит каждый surface-call-site «по смыслу»: это уже
  дизайн-решения по экранам, то есть территория фаз 24–28.

### Типографика и моношрифт (DS-03)

- **D-12:** **Глобальный класс `.tr-mono`** в `global.scss`
  (`font: var(--tr-text-mono); font-variant-numeric: tabular-nums;`), в компонентах —
  `class="tr-mono"`. Это новый паттерн для проекта (сейчас глобальный класс только `.skip-link`),
  принят ради грепаемости: охват DS-03 проверяется одним грепом по `tr-mono`, а не чтением 118
  файлов. Компонент-обёртка `<Mono>` отклонён — новый примитив, это территория фазы 24.
- **D-13:** **Охват моношрифта: списки + карточки/детали.** Везде, где идентификатор
  (инвентарный №, серийный №, № акта) отображается **как данные**: строки таблиц, детали
  акта/устройства, выпадайки автокомплитов. **НЕ** в полях ввода (ввод остаётся обычным шрифтом) и
  **НЕ** в печатных HTML-шаблонах (явно вне scope по REQUIREMENTS.md). Точки применения ищутся
  грепом по биндингам `inventory_number`, `serial_number`, номера актов (см. UI-SPEC §Verification
  Checklist п.3).
- **D-14:** **Типографика мигрируется на декомпозированные оси, 1:1, без переписывания блоков:**
  `--font-size-body` → `--tr-font-size-body`, `--font-weight-semibold` → `--tr-font-weight-semibold`,
  `--line-height-body` → `--tr-line-height-body` и т.д. В `_tokens.scss` определяются **обе** формы
  (composite shorthand `--tr-text-{role}` + три оси — как рекомендует UI-SPEC §Typography), но
  shorthand в фазе 23 обязателен только для `.tr-mono`; для нового кода в фазах 24+ он доступен.
  **Обоснование:** `font:` — сокращённое свойство, сбрасывающее `font-family` и `font-variant`;
  массовый перевод 344 call-site на него — это 344 шанса на тихую побочку в фазе, где
  единственный автоматический гейт — грепы. Отложенный риск лучше немедленного.
  Исключение (из UI-SPEC): `--font-size-sm` в `PersonAutocomplete.svelte:312` не имеет старого
  значения (баг QA-01) → `--tr-text-caption` / его оси.

### Claude's Discretion

- Точная структура `_tokens.scss`: один файл vs разбиение на партиалы (`_colors.scss`,
  `_typography.scss`, …). Учесть, что `global.scss` подключает его одним `@use './tokens'`.
- Точное число планов и раскладка по волнам в рамках D-06.
- Форма греп-гейта (D-04) и скрипта-верификатора (D-08): отдельные файлы vs расширение
  существующего `lint`-скрипта; где именно они живут в дереве.
- Порядок семейств между собой (цвет раньше space или наоборот) — важна только зависимость всех от
  плана с `_tokens.scss`.
- Обновление шапки-комментария `_tokens.scss` (сейчас «Design tokens — Phase 2») и комментария про
  `prependData` в `global.scss` под новую реальность.

## Existing Code Insights

### Reusable Assets
- `_tokens.scss` + `global.scss` — токенный слой уже централизован в одном месте и подключается
  один раз. Инфраструктуры менять не нужно, только содержимое.
- Тема уже переключается через `[data-theme='dark']` на корне + `color-scheme` per theme — новый
  слой ложится в ту же механику (включая theme-scoped `--tr-elev-*`).
- `@media (prefers-reduced-motion: reduce)` блок в `global.scss` уже глушит transitions — учитывать
  при обсуждении motion в фазе 24, здесь не трогать.

### Established Patterns
- Стили — scoped `<style lang="scss">` в каждом компоненте; глобальных классов почти нет
  (`.skip-link` — единственный). `.tr-mono` (D-12) — сознательное отступление ради грепаемости.
- **105 из 118 svelte-файлов уже ходят через токены** — смена значений разойдётся по UI сама.
  Работа фазы — это ~13 файлов с hardcoded-значениями + механический sweep имён в остальных.
- Проверки в проекте — `pnpm lint` (eslint+prettier), `pnpm svelte-check`, cargo-тесты на бэке.
  Всё, что фаза добавит для проверки себя, должно встроиться в эти же команды (D-04).

### Integration Points
- `ui/src/main.ts` импортирует `global.scss` до `mount()` — порядок подключения не меняется.
- Печатные HTML-шаблоны (`crates/trackly-app/templates/*.html`) имеют собственную вёрстку под печать
  и НЕ подключают `_tokens.scss` — они полностью вне досягаемости этой фазы.

## Specific Ideas

- **Инверсия поверхностей — главная визуальная неожиданность фазы.** Пользователь предупреждён и
  принял: `--tr-bg` #eef1f6 (был белый) / `--tr-surface` #ffffff (был серый #f5f6f8). Downstream не
  должен трактовать это как ошибку миграции и «чинить» обратно.
- **Безопасный дефолт побеждает точность** — в обоих спорных местах (split `--radius-sm` → D-07,
  типографика shorthand vs оси → D-14) решение падает в сторону «не менять значение», а точечная
  доводка отдаётся фазе 24 и UAT.
- Приложение не релизится в середине v1.2 — временный «полуготовый» вид ничего не стоит.
