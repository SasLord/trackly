## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| LAN browser → axum `/api/v1/chat_*`, `/api/v1/attachments_*` | Untrusted session-authenticated clients call chat and draft-upload routes | request ids, message text (≤4000 chars), draft attachment ids, file bytes |
| Desktop webview → Tauri commands (`chat_*`, `notify_desktop`) | Webview invokes the same `ChatService` via `resolve_tauri_identity`; `notify_desktop` has no data access | same as above; notification title/body (≤256 chars) |
| Server → WS clients (`http/ws.rs`) and desktop bridge (`main.rs` `trackly-event`) | Fan-out of `ChatMessage` / `ChatReadChanged` | ids, author name, user id of the read-mark owner (never message text) |
| Stored message text → Svelte render | Text written by one user is rendered for others | untrusted text, URLs |
| Webview → OS (`plugin-shell open`, Windows toast) | Click on a link / toast reaches the OS shell | http(s) URLs; anonymised notification text |
| Application → Windows (portable constraint) | Toast AUMID selection must not write registry / shortcuts / APPDATA | none written (read-only probe) |
| Supply chain | `tauri-plugin-notification` 2.4.0 (+ notify-rust, mac-notification-sys, tauri-winrt-notification), `windows` 0.62.2 edge | crate code |
