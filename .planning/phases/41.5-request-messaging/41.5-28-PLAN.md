<objective>
Десктопная половина gap R2-1: клик по системному уведомлению Windows доставляется в приложение.

Итог расследования (планировщик, 2026-11-19, по исходникам в ~/.cargo/registry):
- tauri-plugin-notification 2.4.0, desktop.rs `show()`: строит `notify_rust::Notification`, на Windows ставит `app_id(identifier)` только если каталог exe НЕ оканчивается на `target\debug`/`target\release` (иначе notify-rust берёт `Toast::POWERSHELL_APP_ID`), и вызывает `notification.show()` в `async_runtime::spawn`, выбрасывая `NotificationHandle` — поэтому клик теряется. JS-API плагина на десктопе клика не отдаёт (onAction — только мобильные).
- notify-rust 4.18.2 (windows.rs) сам вешает `on_activated` на тост tauri-winrt-notification и шлёт ответ в канал хендла; хендл плагин не хранит. Значит, механизм активации в процессе есть, нужен свой вызов.
- tauri-winrt-notification 0.8.1: `Toast::new(app_id).title(..).text1(..).on_activated(F)` где `F: Fn(Option<String>) -> Result<()> + Send + 'static`; `show(&self)` регистрирует обработчик `Activated` на ToastNotification и показывает через `CreateToastNotifierWithId(app_id)`. Пример crate'а `simple.rs` получает клик после `show()` без удержания объекта (ждёт в sleep). Реестр в крейте используется только в dev-dependency/примере `unpackaged_app.rs` (регистрация AUMID в HKCU) — нам это запрещено.
- Ограничения, которые проверяет только живая UAT на Windows (план 32): (1) клик по баннеру пока он на экране — событие Activated приходит в работающий процесс; (2) клик из Центра уведомлений после исчезновения баннера у не-упакованного приложения без COM-активатора может не доставляться — допустимое ограничение, фиксируется в UAT; (3) установленная NSIS-сборка создаёт ярлык в меню «Пуск» с AUMID = identifier, portable-ZIP — нет: показ уведомления под незарегистрированным AUMID в portable-режиме надо проверить вживую (регистрировать AUMID нельзя); (4) SetForegroundWindow может быть заблокирован Windows — тогда окно мигает в панели задач.
- macOS: notify-rust по умолчанию на NSUserNotification; ожидание клика (`wait_for_response`) — синхронная отправка со своим run loop, ненадёжно рядом с главным циклом Tauri; в dev уведомление идёт от «Терминала». Поэтому macOS/Linux — без своей команды: фронтенд использует запасной путь (план 29). Это best-effort, основная платформа — Windows.

Purpose: специалист/администратор в десктопе кликом по уведомлению попадает в заявку.
Output: команда notify_desktop, bindings, вердикт реестра паритета, юнит-тесты выбора AUMID.
</objective>
