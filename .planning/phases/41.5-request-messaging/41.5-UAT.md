### Gaps раунда 3

- **R3-1 (blocker): системные уведомления в десктопе Windows не показываются.**
  Регрессия планов 28/29: в раунде 2 уведомления плагина появлялись. Теперь при `target` фронт вызывает `notify_desktop` (`crates/trackly-app/src/tauri_cmds/system_notify.rs`); если команда вернула `true`, путь плагина (`sendNotification`) не выполняется (`ui/src/lib/platform/systemNotify.ts`). Код тоста почти совпадает с notify-rust 4.18.2, которым пользуется плагин: тот же `tauri-winrt-notification 0.8.1`, тот же AUMID (`identifier`, кроме target/debug|release), тот же `on_activated`. Отличия: у нас `text1 = body` (у плагина `text1 = ""`, `text2 = body`), нет `.sound(None)` / `.duration(Short)`, вызов в `spawn_blocking`, а не в `async_runtime::spawn`. Гипотезы: (а) `show()` возвращает Ok, а Windows молча отбрасывает тост — тогда фолбэк не срабатывает и уведомления нет совсем; (б) в portable-сборке AUMID `identifier` не зарегистрирован (ярлык с AUMID создаёт только NSIS), и в раунде 2 проверялась другая сборка. Раунд 3 проверялся на portable ZIP — гипотеза (б) остаётся главной, если раунд 2 был на NSIS. Причина на macOS не воспроизводится — нужна диагностика на Windows: лог результата `show()` и выбранного пути (без текста уведомления), проверка Центра уведомлений, запись варианта сборки.
- **R3-2: после отправки файла/картинки лента не докручивается до низа.**
  `RequestChat.svelte` `onSent` прокручивает после `tick()`, когда превью ещё не загружено (`loadFiles` асинхронный, высота картинки неизвестна); после загрузки картинки высота растёт, прокрутки нет.
- **R3-3: линия под вкладками «Информация / Чат».** Вернуть разделитель цвета `--tr-border` (как под шапкой, `DetailPanel.svelte`). Правило C12 сейчас этой линии не требует.
- **R3-4: поле ввода.** Убрать подсказку `ChatComposer.svelte:336` «Enter — отправить, Shift+Enter — новая строка»; выровнять вертикальные отступы композера сверху и снизу.
- **R3-5 (пожелание, низкий приоритет): тост о сообщении остаётся после перехода по системному уведомлению.** Пользователь согласен оставить как есть, если изменение рискованно. Безопасный вариант: при открытии чата заявки (клик по уведомлению или иначе) снимать тост этой заявки (`toastByRequest` в `chatNotifications.svelte.ts`), а не отказываться от тоста при показе уведомления — иначе вернувшийся без клика пользователь его не увидит.
- Наблюдение (не gap): клик по ссылке тоста при открытом модальном окне переходит на фоне, модальное окно не закрывается — поведение обычной ссылки; правило «модалка → тост-предложение» действует только для клика по системному уведомлению.

### Решения пользователя по раунду 3 (2026-11-19, до исполнения планов 33–35)

- **D-R3-1:** в portable-сборке системные уведомления показываются от имени Windows PowerShell (`POWERSHELL_APP_ID`), клик открывает заявку. Без записи в реестр и ярлыков. Установленная версия (NSIS) — под identifier («Trackly»).
- **Сборка раунда 2:** системные уведомления, которые «появлялись» в раунде 2, проверялись на dev-сборке на macOS, а не на Windows. Значит, на Windows системные уведомления десктопа не проверялись ни разу до раунда 3; гипотеза (б) (незарегистрированный AUMID в portable) раундом 2 не опровергается.
