# Phase 41.5 Plan 29: Notification click opens request and tab (R2-1)

A click on an OS notification or toast opens the request: message goes to the "Chat" tab, status change to "Information". Runtime behaviour is NOT VERIFIED live (plan 32).

## Decisions (as planned)

- Target link is unique per creation (`&n=<Date.now base36><seq>`), so hashchange always fires.
- systemNotify stays in lib/platform, takes `NotifyTarget {activate, href, label}`, imports nothing from features/.
- Click goes through `runOrOffer`: an open modal gives a toast offer instead of navigation.
- Focus fallback only on non-Windows desktop, never navigates, only offers a toast. Windows: notify_desktop, on false/error only the plugin path.
- EmployeeLayout: toast with link always plus OS notification when unfocused (D-G1), no else.
