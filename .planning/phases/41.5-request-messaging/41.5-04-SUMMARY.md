# Phase 41.5 Plan 04: Message draft attachments Summary

The attachment service now accepts files as message drafts (`parent_kind='message_draft'`, `parent_id` = request id) through the existing upload pipeline, and marks chat files with `from_message` in the DTO.

- Upload allowed for the request author, participants, Admin and Manager; a stranger gets Forbidden on both the service and HTTP transports.
- Upload into completed/rejected/cancelled requests and `ad_register` requests is Forbidden (checked in `authorize`, before the body is read).
- Drafts are invisible to list, history, open_for_read (file and thumb), delete, restore and purge for every caller. They write no audit_log row and send no `AttachmentsChanged`.
- `AttachmentDto.from_message` is `message_id IS NOT NULL`. The UI `bindings.ts` is gitignored and was updated locally.
