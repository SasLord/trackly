# Phase 41.5 Plan 06: Write side of request chat Summary

Atomic send of text plus files in one writer transaction, draft cleanup, and WS notification strictly after commit.

- `send`: load_access, no_chat, user id, normalize/too_long/empty checks, then one transaction that re-reads status and deleted flag, inserts the message, promotes drafts (forged id gives Forbidden and rollback), and writes `custom:attachment_added` audit with `message_id` per file. After the await: `ChatMessage` (ids and author name only, no text) and `AttachmentsChanged` when files exist. Rejected sends emit nothing; closed rejects also discard the caller's drafts.
- `discard_drafts` and `purge_stale_drafts` write no audit and no events; blob goes away only when no row references the hash. Startup spawns `purge_stale_drafts(24h)`.
- The service has no edit or delete of messages (D-22).

## Tasks
Both tasks live in one commit because they share `chat_service.rs` (the closed-reject path of `send` calls the draft cleanup): d0b9f205.

## Deviations from Plan
None of substance. Plan wording about a "fast pre-check" before the writer was intentionally omitted (see decisions) so the status check only exists inside the writer closure.
