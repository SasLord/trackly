## Pattern Assignments

### `migrations/V054__request_chat.sql` (migration, CRUD)

**Analog:** `migrations/V050__attachments.sql`

Правила из аналога (строки 1-35): только `CREATE TABLE` / `CREATE INDEX` / `ALTER TABLE ... ADD COLUMN`; никаких перестроек родителей (урок V042); последняя строка — `PRAGMA user_version`. Пользователи БЕЗ внешних ключей.

```sql
CREATE TABLE attachments (
  id                   INTEGER PRIMARY KEY AUTOINCREMENT,
  parent_kind          TEXT    NOT NULL,
  parent_id            INTEGER NOT NULL,
  ...
  uploaded_by_user_id  INTEGER NULL,
  created_at_utc       INTEGER NOT NULL,
  deleted_at_utc       INTEGER NULL,
  deleted_by_user_id   INTEGER NULL
);
CREATE INDEX idx_attachments_parent ON attachments (parent_kind, parent_id, created_at_utc, id);
PRAGMA user_version = 50;
```

**Водяной знак (RESEARCH A2 закрыт чтением DDL):** `app_settings` из `V016__cartridges_kind_color_settings.sql` стр. 37-44 имеет колонки `key, value, created_at_utc, updated_at_utc` (все NOT NULL), поэтому INSERT из RESEARCH Pattern 1 в таком виде не соберётся. Копировать форму сида из V016:

```sql
INSERT INTO app_settings (key, value, created_at_utc, updated_at_utc)
  SELECT 'chat_unread_baseline_audit_id', CAST(COALESCE(MAX(id), 0) AS TEXT), unixepoch(), unixepoch()
    FROM audit_log;
```

Следующий номер — V054 (последний V053). `build.rs` пересобирает крейт при новом `.sql` (память embed_migrations_stale_build), всё равно проверить, что `user_version` в тесте = 54.

```rust
pub fn request_visibility_clause(user_param: &str) -> String {
    format!(
        "(r.requested_by_user_id = {p} OR EXISTS (SELECT 1 FROM request_participants rp \
         WHERE rp.request_id = r.id AND rp.user_id = {p}))",
        p = user_param
    )
}
```

Участники: `SqliteRepairRepository.participant_user_ids(conn, request_id)` (стр. 442-458).

**События для ленты** — SQL-образец `requests_sqlite.rs::get_history` (стр. 481-515):

Для ленты: `ASC`, плюс исключение `custom:attachment_*` (их отдаёт история вложений), плюс для сводки `a.user_id IS NOT ?caller`.

### `crates/trackly-app/src/services/chat_service.rs` (service, CRUD + event-driven)

**Analog:** `services/attachment_service.rs` (1000 строк; читать targeted).

**Импорты / зависимости** (стр. 8-30):

```rust
use rusqlite::OptionalExtension;
use trackly_core::auth::{Identity, Role};
use trackly_core::error::AppError;
use trackly_core::primitives::clock::Clock;
use trackly_infra::db::{pools::ReaderPool, writer_worker::WriterHandle};

```

**Поля и WS-инъекция** (стр. 189-226): `pub(crate) ws_tx: Option<Arc<tokio::sync::broadcast::Sender<WsEvent>>>`, билдер `with_ws_tx(mut self, ws_tx)`. Подключение в `context.rs` — как у `attachments` (стр. 310-326, поле стр. 140, возврат стр. 550); `ws_tx` тот же `Arc`, что `ctx.ws_broadcast`.

**Авторизация — единая точка.** Образец `decide` (стр. 954-993), правило «автор / участник / Admin / Manager»:

```rust
let staff = matches!(caller.role, Role::Admin | Role::Manager);
let readable = staff || match parent.kind {
    ParentKind::Request => {
        (request_author.is_some() && caller.user_id == request_author)
            || caller.user_id.is_some_and(|u| participants.contains(&u))
    }
    ...
};
if !readable { return Err(AppError::Forbidden); }
```

Загрузка родителя — `load_parent` (стр. 918-951): запрос с `deleted_at_utc IS NULL` (иначе `NotFound { entity, id }`) + `participant_user_ids`. Для чата добавить: `request_type != 'ad_register'` -> код `no_chat`, `user_id = None` -> `Forbidden` (RESEARCH Pitfall 7). `chat_service::authorize` вызывается в КАЖДОМ публичном методе (`feed`, `send`, `mark_read`, `discard_drafts`, `unread_summary`).

**Запись + рассылка ПОСЛЕ коммита** — стр. 479-545 (`ingest`):

```rust
let row = self.writer.execute(move |conn| {
    let tx = conn.transaction().map_err(map_rusqlite)?;
    let id = repo.insert_on(&tx, &AttachmentNew { .. })?;
    audit_repo.insert(&tx, AuditEntry { entity_type: entity, entity_id: parent_id,
        action: "custom:attachment_added", user_id, before_json: None, after_json: None,
        payload_json: Some(serde_json::json!({ "attachment_id": id, "name": name }).to_string()),
        created_at_utc: now })?;
    ...
    tx.commit().map_err(map_rusqlite)?;
    Ok(row)
}).await?;

// D-15/D-25: only after the writer returned Ok.
self.notify_changed(parent).await;
```

`notify_changed` (стр. 544-554) и чтение автора/участников ПОСЛЕ коммита `parent_for_event` (стр. 807-818) через `spawn_blocking` + `readers.acquire()`. Статус заявки (`open|in_progress|in_repair`) проверять ВНУТРИ closure writer (TOCTOU, RESEARCH Pitfall).

**Audit-вставка для файла сообщения:** payload обязан нести `"message_id"` (маркер для исключения из ленты и счётчика, RESEARCH Pitfall 5). Образец payload — `insert_audit` (стр. 820-846).

**Вложения сообщения:** `AttachmentService::ingest` не вызывать из `chat_service` повторно — клиент грузит черновики существующим upload-маршрутом с `parent_kind=message_draft`; `chat_send` в одной транзакции повышает их (`UPDATE attachments SET parent_kind='request', message_id=?`) после проверки `parent_kind='message_draft' AND parent_id=? AND uploaded_by_user_id=? AND message_id IS NULL AND deleted_at_utc IS NULL`. Это решение A1 из RESEARCH, планировщик подтверждает.

**Ветка `MessageDraft` в `attachment_service.rs`:** в `load_parent` добавить плечо `ParentKind::MessageDraft` (проверять родительскую заявку), в `decide` — доступ только участникам, `Intent::Read/Delete*/ManageDeleted -> Forbidden`; в `ingest` — пропустить `audit_repo.insert` и `notify_changed` для черновика (`kind == MessageDraft`). `audit_entity(kind)` (стр. 162) тоже получает плечо.

## Shared Patterns

### Единая серверная проверка доступа (BOLA)
**Source:** `services/attachment_service.rs::decide` (стр. 954-993) и `request_service.rs::get` (стр. 95-122: `Employee` + `requested_by_user_id` + `participants.contains`).
**Apply to:** все публичные методы `ChatService`; `attachment_service` для ветки `MessageDraft`. Адаптеры (Tauri/HTTP) логики не содержат.

### WS рассылка только после коммита
**Source:** `attachment_service.rs` стр. 541-554 + гейт `tests/attachments_changed_gate.rs`.
**Apply to:** `chat_service::send`, `mark_read`. Не использовать `EntitiesChanged`/`broadcast_entities`.

### Один код на два транспорта
**Source:** `build_*` в `tauri_cmds/*.rs` + `handler_*` в `http/*.rs` (шапка `http/attachments.rs` стр. 1-10).
**Apply to:** `tauri_cmds/chat.rs`, `http/chat.rs`; паритет проверяет `http_route_parity`.

### Результат «отклонение не равно Err»
**Source:** `AttachmentUploadDto` + `ingest` (стр. 437-468).
**Apply to:** `chat_send` (`reject_code`: `too_long | closed | empty | no_chat`); `Forbidden`/`NotFound` остаются `AppError`.

### Миграции
**Source:** `V050__attachments.sql`.
**Apply to:** V054 — только CREATE/ADD COLUMN, `PRAGMA user_version = 54;` последней строкой.

### Сброс кэшей по пользователю (UI)
**Source:** `userScoped.svelte.ts` (`registerUserScopedReset`), пример `placeContentEvents.svelte.ts` стр. 55-60.
**Apply to:** `unreadStore.svelte.ts` и любой новый модульный стор.

### UI-токены и модалки
**Apply to:** все новые `.svelte`: только `var(--tr-*)`, ни hex, ни `rgba()` в `<style>` (`check-tokens.mjs`); `AttachmentViewer` в единственном экземпляре соседним элементом (`check-modal-isolation.mjs`); явные `white-space`/`text-align` на пузыре (память modal_inherits_table_cell_styles); `Dropdown`, не нативный `<select>`; текст сообщения только как `{text}`, без `{@html}`.
