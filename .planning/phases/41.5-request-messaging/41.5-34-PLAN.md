Событие `Failed` у ToastNotification крейт НЕ выставляет (есть только `on_activated` и `on_dismissed`), поэтому молчаливый отказ Windows через API крейта не виден.
- Документация крейта: «`Toast::POWERSHELL_APP_ID` — if you do not have an AppUserModelID / if the program was not installed»; пример `unpackaged_app.rs` показывает, что для собственного AUMID у не-упакованного приложения нужна регистрация в HKCU (нам запрещено), иначе «the notification won't appear». У классических Win32-приложений Windows показывает тост только для AUMID, известного оболочке (ярлык в «Пуске» с этим AUMID или регистрация); для неизвестного `Show()` проходит без ошибки, а тост не появляется.
- NSIS-шаблон Tauri (строки в cli.darwin-arm64.node): `WriteUninstaller "$INSTDIR\uninstall.exe"` и `!insertmacro SetLnkAppUserModelId "$SMPROGRAMS\…\${PRODUCTNAME}.lnk"` — установленная сборка регистрирует AUMID = identifier ярлыком; portable ZIP (release.yml: trackly.exe + portable.txt + README + пример конфига) — нет. Значит, в portable identifier не зарегистрирован, и тост молча отбрасывается — и у нашей команды, и у плагина (плагин тоже берёт identifier вне target/debug|release). Отсюда: «запасной путь через плагин» в portable НЕ помог бы — он отбрасывается так же. Раунд 2, где уведомления плагина были видны, вероятно, проверялся на NSIS (вариант сборки не записан).
- Совместимый с portable путь, сохраняющий клик: `POWERSHELL_APP_ID` (известен оболочке на любой Windows 10/11; пример крейта `simple.rs` получает on_activated с этим AUMID без регистрации). Цена: уведомление подписано «Windows PowerShell» и с её значком; клик из Центра уведомлений после исчезновения баннера может не дойти до приложения (или запустить PowerShell) — проверяется в UAT.
