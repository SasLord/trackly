# Phase 41.5 Plan 05: Read side of request chat Summary

ChatService with a single access check, a server-merged feed (messages, request events, attachment events), read marks and the unread summary; wired into AppCtx; new suite `app_chat` (17 tests).

- Feed order is (time, event before message at equal time, id). Message files appear only in the bubble (`from_message`); their audit rows carry a message_id marker and are dropped from attachment events.
- The resolution block reads `requests.resolution_notes`; `show_notes` is set on the last complete/reject/repair_complete event; nothing is copied into `chat_messages`, and the feed writes nothing.
- `first_unread_id` is computed from the effective read mark; attachment events are matched to audit ids through the new `list_attachment_audit_on`.
- `mark_read` stores maxima and sends `ChatReadChanged` after the writer await. The service has no edit/delete-message methods (D-22).
