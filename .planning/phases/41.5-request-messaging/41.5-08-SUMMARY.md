# Phase 41.5 Plan 08: Chat write-site gates Summary

Positional broadcast gate for the chat service and a repository-wide inventory
of request audit entries versus WS signals, both proven by mutations.

## What was built

- `chat_changed_gate.rs`: Gate A (every `.send(` after the `writer.execute(...).await`,
  and only in `send` / `mark_read`), Gate B (verdict per writer owner: `send`,
  `mark_read`, `delete_drafts`; silent functions stay silent), Gate C (no
  `EntitiesChanged`/`broadcast_entities(`), Gate D (TOCTOU: `can_post_status(`
  between `.transaction()` and `.commit()` inside the writer closure of `send`).
- `chat_audit_signal_inventory.rs`: scans all of `src/` for `entity_type: "request"`,
  finds 17 writer functions, requires a signal, a DELEGATED row (`try_create` -> `create`)
  or an EXEMPT row with a reason of 40+ characters; floor of 10 functions.
- Both wired into `suites/gates.rs`; registry reasons for `chat_service.rs` and
  `merge_into_open` (message transfer, D-09) updated.

## Mutation proofs

- 11 in-memory mutations on the real sources (send moved inside closure; pure
  reorder with the same `.send(` count; unlisted writer call; removed send;
  send in a silent function; EntitiesChanged; status check moved out of the
  closure; removed signal in `complete`; rogue audit writer; broken delegation),
  each turns the matching gate red; every anchor asserted unique.
- Manual mutation of the real `chat_service.rs`: a genuine send moved into the
  writer closure of `send` made `gate_a` fail with "`send` sends before/inside
  the writer call"; file restored, gate green again.

## Deviations from Plan

**1. [Rule 1 - plan inaccuracy] Verdict owner for drafts.** The plan listed
`discard_drafts` and `purge_stale_drafts` as writer owners; they reach the writer
only through `delete_drafts`. Verdict is on `delete_drafts`; the three callers
are in a SILENT list.

**2. Single commit for both tasks.** `suites/gates.rs` references both new files,
so they were committed together (349446d1).

**3. `scripts/check-privacy.mjs` needs `--hashes`;** the pre-commit hook ran it and passed.

## Deferred Issues

- `RequestService::delete` (admin soft delete) writes an audit entry with no WS
  signal. Recorded as EXEMPT with a reason; the unread summary already filters
  deleted requests, so other clients correct themselves on next load. Adding a
  signal needs requester/participants read before the delete and a decision on
  how the UI treats a "deleted" status; not done here.
