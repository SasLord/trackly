## Deviations from Plan

**1. [Rule 1 - Test fixture] One item per device in acts_groups**
- `device_ids.len()` must equal `quantity`, so a single item with three ids is rejected. The helper builds one item per device with `device_ids = [id]` (still the canonical path with the status gate). No production change.

**2. [Rule 1 - Test fixture] Column name**
- `devices` has `complectation`, not `kit`, in SQL (the DTO maps it). Seeds use the SQL name.

**3. [Rule 1 - Test expectation] Escaping of the slash**
- MiniJinja autoescape prints `/` as `&#x2f;`, so the print assertions use `с&#x2f;н` and `&lt;&#x2f;b&gt;`. Stored text stays unescaped, as required.

**4. [Control block] groups_anchor contrast**
- After inversion the outsider was already transferred, so the "ordinary device still transfers" control uses a fresh device instead of re-transferring the same one.

**5. [Scope] `#[allow(dead_code)]` attributes untouched**
- This plan wires `plan_in_tx` and `apply_plan_in_tx` but none of the `ReleaseEffect::Record` / restore primitives, so no attribute was removable; `group_act_plan.rs` keeps its module-level allow because the revert functions still have no caller.
