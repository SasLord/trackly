## Пикер акта

### Как пользователь выбирает группу в форме акта?

| Option | Description | Selected |
|--------|-------------|----------|
| Секция «Группы» в том же Dropdown строки | Одно поле поиска находит и устройства, и группы; механика секций уже сделана (план 41-21) | ✓ |
| Отдельная кнопка «Добавить группу…» | Модальный выбор с фильтрами; второй путь ввода и модалка над модалкой | |
| Оба пути | Секция + модалка, как в составе группы (D-01 фазы 41) | |

**Notes:** модалка над модалкой запрещена D-09 фазы 41.

### Что делаем с фильтром статуса «На складе»?

| Option | Description | Selected |
|--------|-------------|----------|
| Группы и их устройства — без фильтра по статусу | Остальные устройства как сейчас; иначе GAM-02 недостижим | ✓ |
| Только группы без фильтра, устройства по-старому | Подтверждение GAM-02 работает только для группы, собранной на складе | |
| Снять фильтр совсем, статус бейджем | Шире всего, но меняет поведение актов вне объёма фазы и трогает подбор количества | |

**Notes:** `ActFormItemsTable.svelte:150-166` жёстко фильтрует по `statusIdByCode('на_складе')`;
устройство работающего АРМ имеет статус «В работе» и в пикер не попадает вовсе.

### Что происходит в таблице позиций при выборе контейнерной группы?

| Option | Description | Selected |
|--------|-------------|----------|
| Сразу N обычных строк, строки группы нет | act_items остаются устройственными; возврат, печать, отчёты не трогаются | ✓ |
| Строка группы с раскрытием, разворот на сохранении | Компактнее, но удалить одно устройство нельзя без правки группы | |
| N строк с пометкой группы в строке | Сохраняет след «из АРМ», но требует новой колонки в act_items | |

**Notes:** принятая цена — в акте не остаётся следа «позиции пришли из АРМ #3».

### Что стало с группой после проведения акта на все её устройства?

| Option | Description | Selected |
|--------|-------------|----------|
| Все члены в акте → группа переезжает, состав цел | groups.place_id меняется, выноса и подтверждения нет; GAM-02 только на части состава | ✓ |
| Всегда выносить из состава, группа пустеет | Поведение D-22 без изменений; выбор группы в акте теряет смысл | |
| Спрашивать всегда | Попап на любой передаче члена группы, даже когда взяли всю группу | |

## Подтверждение выноса (GAM-02)

### Когда спрашиваем подтверждение выноса?

| Option | Description | Selected |
|--------|-------------|----------|
| При сохранении акта — один попап на всех | Список выносимых с именем группы; не мешает по ходу набора | ✓ |
| При добавлении каждой строки | Понятно к какой строке, но верёвка попапов на большом акте | |
| Предупреждение в строке + попап при сохранении | Бейдж «из АРМ #3» сразу, подтверждение одно; больше кода в таблице позиций | |

### Восстанавливается ли членство при откате акта?

| Option | Description | Selected |
|--------|-------------|----------|
| Да, возвращается в ту же группу | «Как будто акта не было», ровно как GAM-03 требует от журнала | ✓ |
| Нет, вынос необратим | Проще, но откат не полный и место больше не держится группой | |
| Возвращается с подтверждением при откате | Максимум контроля, ещё один вопрос в пути удаления акта | |

**Notes:** цена выбора — акт обязан помнить, из какой группы вынес (сейчас это только запись
`audit_log`).

### Откат, а группы уже нет или устройство вошло в другую группу?

| Option | Description | Selected |
|--------|-------------|----------|
| Откат проходит, членство не восстанавливается, Toast объясняет | Удаление акта не заложник сторонних действий с группами | ✓ |
| Откат блокируется с объяснением | Строго, но удаление акта становится недоступно из-за чужих правок | |
| Перевести обратно силой из новой группы | Полный откат, но ломает свежее решение человека без его ведома | |

### Нужна ли в попапе кнопка «перенести всю группу вместо этого»?

| Option | Description | Selected |
|--------|-------------|----------|
| Нет: «Вывести и передать» / «Отмена» | Отмена возвращает в форму без сохранения; рисунок NumberTakenPopup | ✓ |
| Да, третья кнопка «Добавить всю группу» | Ловит частую описку, но модалка правит состав акта за спиной формы | |

## Якорная группа в акте

### Что уходит в акт при передаче якорной группы?

| Option | Description | Selected |
|--------|-------------|----------|
| Одна строка-якорь, группа и детали едут за ним | D-13 фазы 41.1: место якоря и группы разойтись не могут | ✓ |
| Якорь + строки деталей в act_items | В базе 4 позиции, на бумаге 1 — расхождение надо держать в возврате и отчётах | |
| Якорь передаётся, детали остаются на месте | Физически неверно: диск внутри системника едет вместе с ним | |

### Что попадает в текст комплектации?

| Option | Description | Selected |
|--------|-------------|----------|
| Имя + инвентарный/серийный каждой детали | Для архива важен каждый номер; снимок пишет сервер на момент акта | ✓ |
| Только имена деталей | Короче в печати, но акт не идентифицирует детали | |
| Существующая комплектация устройства + состав группы | Ничего не теряется, но правило склейки надо задать и проверить на живом PDF | |

**Notes:** используется существующее поле `act_items.complectation_at_time` → `item.kit`; новой
переменной шаблона не вводится (ломает редактор шаблонов, strict-undefined).

### Какое основание (`source`) у строк журнала, вызванных актом на группу?

| Option | Description | Selected |
|--------|-------------|----------|
| Все строки пакета — source='act' + act_id | Основание всего пакета — номер акта; откат снимает всё по act_id (GAM-03 дословно) | ✓ |
| Строка группы 'act', устройства 'group' | Точнее по механике, но в таймлайне устройства не видно акта, а HST-03 требует ссылки | |
| Новый токен source='act_group' | Точная аналитика, но плодит токены (в V040 уже висит мёртвый 'workstation') | |

**Notes:** `group_place.rs:251 propagate_group_place_in_tx` и
`place_movements_sqlite.rs:175 record_batch_movement_if_applicable` уже умеют всё нужное —
правка в параметризации `source`/`act_id`.

## Строка группы в «Местах» (GAM-04)

### Что стоит в столбцах у строки группы?

| Option | Description | Selected |
|--------|-------------|----------|
| Тип = тип группы, Название = имя + счётчик, номер и статус пусты | У группы нет инвентарного (гейт 40.2/40.5) и сводного статуса | ✓ |
| Статус — сводный по составу («Смешанный») | Информативнее, но вводит седьмое значение, которого нет в device_statuses | |
| У якорной группы — номер и статус якоря | У якоря есть реальное устройство-источник правды, но это два рисунка строки вместо одного | |

### Строка группы — раскрывается или ведёт в раздел «Группы»?

| Option | Description | Selected |
|--------|-------------|----------|
| Шеврон inline — распахивает состав в той же таблице | Рисунок DeviceGroupRow / вложенной группы / пакета отчёта | |
| Переход-фокус в раздел «Группы» | Проще, но уводит с экрана ради одного взгляда на состав | |
| И то, и другое | Шеврон раскрывает состав, двойной клик уводит в «Группы» | ✓ |

**Notes:** в «Местах» двойной клик сейчас открывает `PlaceEntityViewModal` — для строк
устройств и картриджей это поведение сохраняется.

### Прячет ли строка группы USB-принтер, входящий в АРМ?

| Option | Description | Selected |
|--------|-------------|----------|
| Скрытие действует на всех членов, включая принтеры | Один типонезависимый предикат на все виды содержимого (D-38 фазы 41.1) | ✓ |
| Принтеры всегда видны своей строкой | Принтер — обслуживаемое оборудование; но на вкладке «Все» он виден дважды | |

### На каких вкладках содержимого видна строка группы?

| Option | Description | Selected |
|--------|-------------|----------|
| «Все» и «Устройства» | Группа стоит там, где стояли бы её устройства; требование «вместо» выполняется дословно | ✓ |
| Только «Все» | Вкладка «Устройства» выглядела бы пустой при ненулевом счётчике | |
| Новая вкладка «Группы» | Явно, но противоречит «вместо» и требует пятого значения ContentTab в localStorage | |
