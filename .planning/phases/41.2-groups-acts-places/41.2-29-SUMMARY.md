# Фаза 41.2 План 29: забывание переноса группы при удалении акта (UD-4)

Удаление акта, переносившего группу, после последующих перемещений группы оставляет группу и её членов на месте; перенос забывается из журнала мест и из эффекта следующего акта.

## Что сделано

- `revert_move_effect_in_tx`: если живая корневая группа стоит на месте X != `to_place_id` эффекта (X задано), перенос «забывается»: `forget_group_move_rows_in_tx` (строки акта по `group_id` пакета удаляются, «откуда» ближайшей более поздней строки той же сущности другого акта/без акта получает «откуда» удаляемой, вместе с путём), `rebase_later_move_effects_in_tx` (ближайший более поздний эффект Move группы с `from == to` забываемого получает `from` забываемого). Уведомления нет.
- `undo_device_mutations_for_act`: `kept_in_place_group_ids` из итога отката передаются в цикл снимков, `snapshot_keeping_group_place_in_tx` подменяет `place_id` снимка членом группы текущим местом корня (только в ветке применения снимка; якорный конфликт D-09 не затронут).
- Тесты: `acts_groups` 62 (контроль «удалить А2», удаление А1 при живом А2 с последующим удалением А2, ручной перенос, акт возврата, страж ложного срабатывания, дополненный d9; старый d4 переписан); юнит-тесты в `group_act_plan` (перепись, rebase ровно одного эффекта, строки без преемника) — 46 в `group_act_plan`.
- Способ построения цепочки А1→А2: сервис допускает вторую передачу тех же устройств, когда группа целиком стоит на новом месте; А1 и А2 — настоящие акты передачи через `create` (два живых акта, эффекты Move по одной группе).

## Мутации реального исходника (восстановлено, дерево чистое)

1. Ветка «забыт» всегда `Ok(None)` (уведомление, без kept): краснят 4 (ручной перенос, А1/А2, d9, возврат).
2. Подмена места в снимке отключена (`&[]`): краснят 3 (ручной перенос, А1/А2, возврат); d9 зелёный (якорный путь).
3. Перепись преемника отключена: краснят те же 4.
4. Rebase эффекта отключён: краснит `undo_earlier_of_two...` (удаление А2 после А1).
5. Условие ветки «забыт» заменено на `true`: краснят 17, включая страж `undo_act_when_group_came_back...`.

## Отклонения

**1. [Rule 1 - дефект] Подмена места и для обычного возврата.** План требовал подмену только для «забытых» групп, но после забытого А1 удаление А2 возвращает группу на Склад А, а снимок члена А2 хранит Склад Б, поэтому член выводился из группы (тест «затем удалить А2»). `kept_in_place_group_ids` теперь содержит и группы, обращённые обычным путём: место группы после отката авторитетно для членов. Для неизменной цепочки это эквивалентно прежнему поведению (место снимка = месту группы). Поле названо по плану, документировано.

**2. Вызовы `revert_move_effect_in_tx` из update/update_return** (act_service ~1351, ~2922) теперь тоже получают поведение «забыть» вместо уведомления; существующие тесты update/return зелёные. Полная семантика правки акта — план 41.2-30.
