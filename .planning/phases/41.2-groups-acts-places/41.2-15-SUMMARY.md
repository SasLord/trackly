# Phase 41.2 Plan 15: Client side of the act rollback Summary

Deleting an act now tells the user what the rollback could not give back: sticky warning toasts after the success toast, each with a link to the group when the server names one; and the movement timeline no longer loses the group context for rows written by an act.

GAM-01..GAM-04 stay `Pending` on purpose; `requirements-completed` is empty and nothing was marked in REQUIREMENTS.md (plan 41.2-16 owns that). The plan frontmatter lists GAM-03 and it was deliberately NOT marked.

## What changed

- **Confirm text** (`window.confirm`, no new component): ordinary act gets "Устройства, выведенные этим актом из состава групп, вернутся в свои группы." before the backup sentence; return act gets "Устройства, выведенные этим возвратом из состава групп, вернутся в свои группы." at the end.
- **Toasts**: `showRollbackNotices(result.notices)` runs after `notifyPlaceContentChanged(result.changed_place_ids)` and after the existing success toast. Each of the first five unique notices is `pushToast('warning', message, { sticky: true, link })`; `link = { label: 'Открыть группу', href: '#/groups?id=' + group_id }` only when `group_id !== null`. More than five: a sixth sticky summary toast "И ещё K позиций не вернулись в свои группы.". Deletion stays a success path in every case.
- **Timeline**: after the act-number link, `actTail(entry)` picks `'group'` (entity_type = 'group' -> "· перенос группы", no link), `'member'` (group_id set, handler present, non-empty name snapshot -> "· в составе группы «<link>»"), or nothing. No act number -> the old "актом". `source='group'` branch, place formulas and the rest are unchanged.

## How the notices carry-forward was discharged

- **Real notices, not an empty vector.** The UI renders `result.notices` as delivered; the texts below come from the backend tests plan 13 pinned (d3 i-iii, d4, d9) and are not duplicated in the UI file:
  - `«Монитор #2» не вернулся в «АРМ #3»: группа удалена.` (group_id null, no link)
  - `«Монитор #2» не вернулся в «АРМ #3»: устройство уже входит в «АРМ #7».` (link to the OTHER group)
  - `«Монитор #2» не вернулся в «АРМ #3»: группа теперь в другом месте.` (link to the group)
  - `Группа «Сборка #4» не возвращена на прежнее место: после акта её переместили.` plus one per anchor/part device mentioning "после акта её переместили" (all with the group's id)
  - also reachable: `Группа «…» не возвращена в прежнюю группу: после акта изменились её место или состав.` and `«…» не вернулся в «…»: не удалось восстановить состав.`
- **Fold decision**: no fold by `group_id` (reasons in key-decisions). Exact duplicates are collapsed before counting. Trade-off: a moved anchor group with five parts shows 5 toasts + a summary of 1; that is noisy but each toast names its device, and it is a rare path.
- **Pre-V049 acts** (no effect rows): the server returns no notices, so no warning toast appears and the success toast reads normally. Caveat found while doing this: the confirm sentence "Устройства, выведенные этим актом из состава групп, вернутся в свои группы." over-promises for an act created BEFORE V049 that already took devices out of groups (phase 41 let acts release members without recording an effect); those devices will not come back and nothing says so. The client cannot tell such an act apart (no flag on `ActDto`). Not fixed here; it is on plan 16's list below.
- **Bound by a gate, not only by a test**: check-act-delete-notices.mjs.

## Deviations from Plan

**1. [Addition, Rule 2] New gate `ui/scripts/check-act-delete-notices.mjs` + `ui/package.json`** - the plan lists three files; the order of toasts, dedupe-before-cap and the group-before-member check are invisible to compile gates and a counting grep would not see order. **2. [Wording] Summary toast verb agrees with the count** - plan text "не вернулись" for every K; 1 and 21 now read "позиция не вернулась в свою группу". The allowlist therefore carries five markers ('не вернулась в свою группу' in addition to the four in the plan).

**3. [Behaviour] Exact-duplicate notices collapsed before counting** - not in the plan; needed so "И ещё K" cannot count what the sticky dedupe in the toast store would hide.

**4. [Cosmetic] A pre-existing comment in MovementTimeline mentioning "{@html}" was reworded** - the plan's acceptance criterion greps for `@html` and expects nothing; the match was only a comment ("без {@html}"), not a usage.

**5. [Scope] Vocabulary selftest** - three fixtures added for ActsPage (one positive, one narrow-marker negative, one deny-list negative).
