# Phase 41.2 Plan 03: Contract wave for places, device filter and journal cause Summary

**GroupMoveCause and a required expand_groups flag threaded through every layer, plus the group_members_only device filter, with behaviour unchanged for all existing callers.**

## Performance

- 3 tasks, 3 per-task commits (core+infra, app, client)
- Files: 20 source/test files modified, `ui/src/bindings.ts` regenerated (gitignored, not in commits)

## Accomplishments

- Core and infra carry the new row fields, the required `expand_groups` parameter (infra reads it as `_expand_groups` - behaviour is plan 41.2-05), and the three `NULL AS ...` UNION columns.
- `group_members_only` is a parameterised predicate (`?13`) shared by COUNT and SELECT, filtering on live (not soft-deleted) groups only. A new infra test mixes statuses and includes a soft-deleted-group member and an out-of-group device.
- `GroupMoveCause` replaces the three hardcoded `MovementSource::Group` and the hardcoded `None` act id in `group_place.rs`; existing callers pass `GroupMoveCause::GROUP`. Printer-member cartridges now receive `act_id` from the cause.
- Bulk move requests `list_subtree_contents(&tx, root_id, true, true)` (exactly one occurrence) so groups are still found when members get collapsed later.
- `expand_groups` has no serde default on the HTTP payload and no default on any layer.
- Client calls `places_contents` with `expandGroups: true` in both places (rows and bulk-move counter).
