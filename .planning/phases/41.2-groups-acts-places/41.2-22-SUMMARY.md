# Фаза 41.2 План 22: попап выбора при удалении акта (UD-1)

Если сервер ответил `needs_group_restore`, `ActsPage` закрывает `ActDeleteModal` и показывает один `GroupRestoreChoicePopup`; подтверждение повторяет удаление с выбором по всем группам.

## Что сделано

- **7cb1e26e (RED).** Гейт `check-act-delete-choice.mjs` на неисправленных исходниках дал exit 1, 7 нарушений: нет попапа, ветки `needs_group_restore`, третьего аргумента `acts.delete` и параметра в `api/acts.ts`.
- **ec120c36 (GREEN).**
  - Попап презентационный. У каждой группы своё радио (`restore` по умолчанию, `keep`), начальный фокус на «Отмена», список устройств прокручивается.
  - `handleDelete(act, choices?)` проверяет `needs_group_restore` сразу после `await`, до тостов, `notifyPlaceContentChanged` и `refresh`. Ветка не удаляет и не показывает тосты.
  - Подтверждение попапа вызывает `handleDelete(prompt.act, choices)`. Повторный `needs_group_restore` открывает попап заново.
  - `api/acts.ts`: `groupChoices` уходит, только когда массив непуст (ключ camelCase, как у `actId`/`deviceId`).
  - Гейт подключён в `pnpm lint`.
- **eb35dde1.** UI-SPEC §10.5 с описанием попапа и пометкой в §10.4: на пути удаления жёлтого тоста «группа теперь в другом месте» нет.

## Гейт

`--selftest` ловит 8 мутантов реальных исходников, у каждого якорь встречается ровно один раз:
- удалена ветка `needs_group_restore`;
- проверка переставлена ниже success-тоста (мутант-перестановка);
- убран `initialFocus`;
- `acts.delete(` внутри попапа;
- вызов без `groupChoices`;
- подмена фразы варианта;
- попап под чужим `{#if}`;
- `api.delete` без третьего параметра.

Пустой набор файлов даёт нарушение (M).

## Отклонения

**1. [Rule 3 - блокировка] Якоря соседних гейтов.** Из-за новой сигнатуры `handleDelete` и вызова `acts.delete(…, choices)` обновлены якоря в `check-act-delete-confirm.mjs` (мутант 1) и `check-place-tree-invalidation.mjs` (мутант 3g). Сами проверки и мутанты те же, ослаблений нет.

**2. [Rule 3 - блокировка] Allowlist словаря групп.** `check-group-vocabulary` (GRD-06) покраснел на фразах попапа. Добавлена запись с четырьмя узкими маркерами реальных литералов по образцу `GroupReleaseConfirmPopup`.

**3. План требовал «ровно два вызова acts.delete(».** Реализация использует один вызов с необязательным `choices`. Гейт требует, чтобы у каждого вызова был третий аргумент, и чтобы такой вызов был. Сила проверки не изменилась.

## Известные ограничения / для плана 41.2-28 (живая проверка пользователем)

Гейт структурный и этого не доказывает. Проверить в запущенном приложении:
1. Сценарий: акт выводит устройства из группы, затем группа переносится на другое место, затем удаляется акт. После «Удалить» в окне подтверждения оно закрывается, открывается попап «Вернуть устройства в группы?» без смещения, без двух окон одновременно.
2. Начальный фокус стоит на «Отмена»; Enter не удаляет; Esc, крестик и подложка закрывают попап, акт остаётся.
3. По каждой группе названы группа, её новое место и устройства с прежним местом; длинные названия переносятся, список прокручивается.
4. «Вернуть в группу» (по умолчанию): после «Удалить акт» устройства в группе на её новом месте. «Оставить вне группы»: устройства на прежнем месте вне группы.
5. Вид попапа в WebView2/WKWebView и в браузере по LAN.

`entities_changed_gate` красный по `device_service.rs::create` (quick 261105-s6s), вне области.
