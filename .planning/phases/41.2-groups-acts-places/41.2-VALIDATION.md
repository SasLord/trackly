### Ограничения запуска (уроки проекта — обязательны к соблюдению)

- Одновременно **ровно один** `cargo test`. Полный прогон — один раз на границе волны, в фоне (`run_in_background`), `timeout` до 2 ч, сырой вывод в файл (`grep` съедает буфер при убийстве). Остальное скоупится по `-p` / `--test`.
- `cargo test … -- <фильтр>` выходит с **0, если фильтр ничего не нашёл** → каждую проверку по фильтру дополнять `| grep -E 'test result: ok\. [1-9][0-9]* passed'`.
- `pnpm lint` **НЕ** включает `svelte-check`; `clippy` и `fmt` — отдельные команды. Исполнители сдают зелёным тот гейт, что не гоняли → в плане перечислять все команды явно.
- Компилирующие гейты (`svelte-check`, `eslint`, `pnpm build`) **не видят** рантайм-ошибок рун Svelte (`effect_update_depth_exceeded`, потеря состояния при `{#key}`) → такие свойства закрывает только живой прогон.
- Структурные правила над `.svelte` доказываются прогоном `--src=<копия>` с мутированным **реальным** файлом (чистая копия зелёная, мутированная красная), а не только фикстурами в памяти.
- `trackly-app` тесты требуют собранный `ui/dist` (`pnpm --dir ui build`) и `TRACKLY_AD_MOCK` / `TRACKLY_SNMP_MOCK`.
- После обновления Xcode линковка `exit 69` → префикс `DEVELOPER_DIR=/Library/Developer/CommandLineTools`.

## Sampling Rate

- **После каждого коммита задачи:** таргетный `cargo test -p <crate> --test <файл>` слоя задачи (+ `grep` на ненулевое число прошедших) и нужный `node ui/scripts/check-*.mjs`; для UI-задач ещё `pnpm --dir ui svelte-check`.
- **После каждой волны:** все таргетные прогоны волны → `cargo test -p trackly-app --test export_bindings` → `pnpm --dir ui svelte-check` → `pnpm --dir ui lint` → `cargo fmt --all -- --check` → `cargo clippy --workspace --all-targets -- -D warnings`.
- **Полный `cargo test --workspace`:** один раз на границе волны, в которой менялись схема или сервисы (V049, `act_service`), в фоне.
- **Перед `/gsd-verify-work`:** весь набор CI в порядке `ci-fast.yml` зелёный + человеческий чек-лист H1–H9 в Tauri **и** в LAN-браузере.
- **Max feedback latency:** 60 секунд на задачу.

## Расходящиеся фикстуры

> Иначе тест вакуумен — урок «до-фикс и после-фикс дают одну строку».

- **План групп:** одно множество устройств акта, два состава группы (полный / минус одно) → разный результат (перенос vs вынос). Плюс: вложенная покрытая группа в непокрытом корне; пустой контейнер; «спящая» группа; якорь с деталями, часть которых тоже перечислена в акте.
- **Журнал:** группа с принтером-членом и **прикреплённым картриджем** + одиночное устройство вне группы в том же акте (чтобы `batch_id` был у одних строк и `NULL` у других). Без принтера с картриджем баг каскада картриджей (`act_id = None`) не виден.
- **Откат D-09:** четыре фикстуры (группа жива / удалена / устройство в другой группе / группа перенесена). Для третьей причины группа должна оказаться в месте ≠ месту восстановления.
- **Комплектация:** якорь со своим `devices.kit` и тремя деталями (с инвентарным номером, с серийным, без номера; в названии одной — символ `&` для проверки autoescape); ожидаемая строка — золотое значение. Фикстура расходится: тот же якорь без группы → только `devices.kit`, с группой → `devices.kit; состав`.
- **Места:** группа из 3 устройств (одно — принтер с картриджем) + «спящая» группа из 2 + одиночное устройство + вложенное место; в обоих режимах считать **и строки, и `device_count`** (числа должны различаться).
- **Закрытие вакуумности перед выпуском:** прогон теста на **прежнем** коде (`git stash` фикса → тест красный) для каждого критерия SC1–SC4.

## Проверка печатной формы

Пайплайн актов с фазы 16 — **HTML**, а не PDF: `ActService::render_pdf` возвращает `String` (HTML-документ), печать браузерная (`srcdoc` iframe + `print()`), krilla заморожен. Приём «реальный PDF + `qlmanage`» буквально неприменим; его суть — «текстовые тесты не видят переполнения и наложений» — сохраняется:

1. **Автоматически** (необходимо, не достаточно): `html_act_render.rs` — подстрока «Комплектация: …» в ветках N=1 и N>1, экранирование `&` / `<` в названиях деталей.
2. **Одноразовый `#[ignore]`-стенд** `zz_uat_server.rs`: поднимает `build_router` на свежей БД с `ui/dist`, сеет вымышленные данные (якорь + ≥ 8 деталей с длинными кириллическими названиями) → печатный просмотр в Chrome/Safari по LAN. Файл **не коммитится**. Грабли: `into_make_service_with_connect_info::<SocketAddr>()`, обёрнутое тело логина `{"req":{…}}`, куки `Secure`, `NumberFieldInput` в camelCase, колонки `inventory_number` / `serial_number`.
3. **Человек, десктоп** (WKWebView / WebView2): печать акта с длинной комплектацией. Граница гарантии стенда: webview Chromium по HTTP ≠ WKWebView по Tauri invoke.

Планируемых JS-зеркал нет: «единицы акта» и вывод «целиком / часть» — на сервере; текст комплектации собирается на сервере; число «N устройств» — готовое `member_count` + существующий `pluralizeRu`.
