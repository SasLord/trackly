# Phase 39.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Derived from `39.1-RESEARCH.md` § Validation Architecture.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `cargo test` (Rust unit + integration, workspace-standard) + `svelte-check` / `eslint` / `pnpm --dir ui build` (фронт, статические гейты) |
| **Config file** | none — конвенция workspace (`Cargo.toml` + `#[cfg(test)]` модули, `crates/*/tests/*.rs`) |
| **Quick run command** | `cargo test -p trackly-core shorten_place_path -- --test-threads=1` |
| **Full suite command** | `cargo test -p trackly-app -- --skip login_remember_persistent_cookie --test-threads=1` |
| **Estimated runtime** | quick ~15s · full ~4–6 min |

**Environment requirements (обязательно, иначе `trackly-app` тесты падают):**
- `TRACKLY_AD_MOCK=1`, `TRACKLY_SNMP_MOCK=1`
- реальный собранный `ui/dist` (`pnpm --dir ui build`) — сервер-мод тесты читают его с диска

**Конкурентность:** ровно ОДИН `cargo test` за раз. Два процесса конкурируют за
lock в `target/` и выглядят как многоминутное зависание.

**Известный зависающий тест:** `login_remember_persistent_cookie` — pre-existing,
всегда прогонять с `--skip`, включая `-p trackly-app`.

## Sampling Rate

- **After every task commit:** узкий `cargo test -p <crate> <module>::` на затронутый модуль
- **After every plan wave:** `cargo test -p trackly-app -- --skip login_remember_persistent_cookie --test-threads=1` (полный пакет, один процесс)
- **Before `/gsd-verify-work`:** полный набор зелёный + `svelte-check` + `eslint` + `pnpm --dir ui build`
- **Max feedback latency:** ~15s (quick) / ~360s (full wave gate)

**Печатные формы:** статические гейты и text-extraction тесты НЕ видят перекрытий и
переполнений в PDF. Изменение шаблона акта (D-20) проверяется живым рендером —
throwaway `#[ignore]`-тест + визуальный осмотр PNG, по прецеденту `act_pdf_word_fidelity`.
