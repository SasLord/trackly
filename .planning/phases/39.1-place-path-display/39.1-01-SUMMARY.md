# Phase 39.1 Plan 01: Схема хранения и формула сокращения пути Summary

**V039 migration adds `places.path_variant_override` + 3 org-default `app_settings` keys + an upward-walking recursive-CTE view `place_effective_variant`, plus a new pure `shorten_place_path()` formula in `trackly-core` covering the full D-13..D-16 input/output table.**

## Performance

- **Duration:** ~10 min
- **Completed:** 2026-08-28
- **Tasks:** 3
- **Files modified:** 3 (2 created, 1 modified)

## Accomplishments
- `migrations/V039__place_path_display.sql`: adds the override column, seeds three organization-default `app_settings` rows (`place_path_variant='ends'`, `place_path_sep_ends=' // '`, `place_path_sep_last_two=' / '`), and defines `place_effective_variant` — a recursive CTE that walks UP `parent_id` to resolve the effective variant per place, with early exit on the first non-NULL override and a SQL-level `COALESCE` fallback to the organization default.
- 6 new integration tests in `crates/trackly-infra/tests/place_effective_variant.rs` prove: fresh-DB org-default fallback, explicit-override precedence over org default, 3-level ancestor-chain inheritance, dynamic re-parenting to top level switching a `NULL`-override place to the org default on the very next `SELECT`, override survival across a move (including move-to-top-level), and immediate visibility of an org-default change for every non-overridden place.
- `PathDisplayVariant` enum + `shorten_place_path()` added to `crates/trackly-core/src/domain/places.rs`, mirroring the existing `PlaceKind`/`natural_name_cmp` conventions in the same file. 16 new unit tests cover the entire D-13..D-16 table (1/2/3/4+ segments × Ends/LastTwo/Last) plus the D-09/D-10 "separator whitespace is not trimmed" contract and explicit rejection of the retired `"full"` token.

## Issues Encountered
- `embed_migrations!` (refinery) resolves the `migrations/` directory at compile time but has no `build.rs` watching that directory for changes — adding `V039__place_path_display.sql` did not trigger a recompile of `trackly-infra` on its own the first time the new integration test file was run (`no such column: path_variant_override` / `no such table: place_effective_variant`). Touching `crates/trackly-infra/src/db/migrations.rs` forced the recompile and all 6 tests then passed. This is a known pre-existing quirk of the `embed_migrations!` macro, not a bug introduced by this plan — noted here in case future plans in this phase hit the same stale-cache symptom after adding a new migration file without touching any `.rs` file.
