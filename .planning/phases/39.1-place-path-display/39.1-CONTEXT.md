# Phase 39.1: Формат пути Места в UI - Context

**Gathered:** 2026-08-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Выбор сокращения пути места переезжает из `trackly.config.toml` в приложение: умолчание задаётся
для всей организации в «Настройки → Организация» (вариант + разделители), а любое место может его
переопределить, наследуя выбор родителя по умолчанию. Требования PLC-07 и PLC-08.

Фаза НЕ добавляет новых способов отображения места, не трогает дерево мест как таковое и не
меняет формат `place_full_paths` (` / ` остаётся канонической формой полного пути в БД).

</domain>

<decisions>
## Implementation Decisions

### Где разрешается наследование

- **D-01:** Наследование разрешает **бэкенд**, и отдаёт клиенту **готовую короткую строку**
  (`place_path_short`) рядом с полным путём — не «эффективный вариант», не карту дерева на фронте.
  Причина: строки отчётов несут путь строкой без `place_id`
  ([report_service.rs:1160](crates/trackly-app/src/services/report_service.rs:1160)), а CSV/PDF/печать
  генерируются на бэкенде — единая точка сокращения покрывает все транспорты сразу.
- **D-02:** Сокращение считается **на каждом запросе** (как `place_full_paths`, который никогда не
  бывает устаревшим). Новый WS-броадкаст не заводим: смена умолчания или варианта видна при
  следующей загрузке списка.
- **D-03:** Наследование **динамическое**: место со значением «Как у родителя» при перемещении
  подхватывает вариант нового родителя. Ничего не снапшотится, инвалидировать нечего.
- **D-04:** Переопределение места **не сбрасывается** при перемещении, в том числе при переносе
  на верхний уровень — там дропдаун тоже доступен (см. D-06), скрытого состояния не возникает.
- **D-05:** В форме Места **не показываем**, во что разрешается «Как у родителя» — ни подписи,
  ни примера, ни названия унаследованного варианта в пункте.

### Настройки организации и форма Места

- **D-06:** Дропдаун «Вариант сокращения» есть у **всех** мест, включая места верхнего уровня;
  у них «Как у родителя» ссылается на умолчание организации. Отдельного корневого элемента с
  именем организации в разделе «Места» нет и не появляется — корень это Организация,
  и настраивается он в Настройках.
- **D-07:** Умолчание организации живёт **новым подразделом внизу «Настройки → Организация»**
  (`ui/src/features/settings/OrgSettings.svelte`): выбор варианта + предпросмотр.
- **D-08:** Разделитель — **отдельное поле на каждый вариант**: одно для «Крайние», одно для
  «Два последних». Не одно общее поле, как предполагал SC#2 роадмапа.
- **D-09:** Умолчания разделителей: «Крайние» = ` // `, «Два последних» = ` / `. Пробелы значимы,
  значение `, ` даёт перечисление через запятую.
- **D-10:** Пустой разделитель **запрещён** — поле обязательное, сохранение отклоняется с
  сообщением об ошибке.
- **D-11:** Предпросмотр показывает **все три варианта разом на двух образцах** (сетка 3×2):
  «Здание А / 1 этаж / 1-05» и «Территория А / Объект Х / помещение 3». Оба поля разделителей
  видны в действии сразу, без переключения радио-кнопок.
- **D-12:** Права на изменение варианта у места — **те же, что и на редактирование Места**
  (не отдельный ManageSettings). Поле сохраняется тем же вызовом, что название и тип.

### Формула сокращения

- **D-13:** Разделитель варианта **соединяет показанные сегменты**, а не отмечает пропуск как
  особый символ. Но ставится он **только когда что-то реально выброшено** — правило из
  quick 260827-ui3 сохраняется.
- **D-14:** Следствие D-13: путь из 2 сегментов при варианте «Крайние» отдаётся как
  «Здание А / 1 этаж» со штатным ` / ` — выбрасывать нечего, разделитель варианта не появляется.
- **D-15:** «Последнее» для пути из одного сегмента показывает его же («Склад»), без маркера
  сокращения.
- **D-16:** «Два последних» на пути из 3+ сегментов даёт «1 этаж / 1-05» (свой разделитель из D-09);
  «Крайние» на том же пути — «Здание А // 1-05».

### Охват — где путь сокращается

- **D-17:** Сокращается: экранные списки (Отчёты, Содержимое места, Устройства, Картриджи) —
  как сейчас, плюс **печать и PDF отчётов** (`reports_export_pdf`, HTML-рендер на бэкенде),
  плюс **печатные формы актов**.
- **D-18:** **CSV-экспорт отчётов отдаёт полный путь** — файл уходит третьим лицам, подсказки при
  наведении в нём нет, сокращение теряло бы информацию безвозвратно.
- **D-19:** Остаются **полными**: детальные экраны (ActDetail, CartridgeDetail, PrinterDetail),
  выбор места в PlacePicker/ReturnModal, результаты поиска в дереве мест. Граница из
  quick 260827-ui3 не двигается.
- **D-20:** В акте сокращается **снимок пути** (`place_path_snapshot`, заморожен по D-16 фазы 39),
  а вариант берётся по **текущему** состоянию `acts.place_id`; если `place_id` пуст или место
  исчезло — умолчание организации. Задевает minijinja-шаблоны актов, а они лежат **в БД** —
  сид шаблонов придётся трогать (см. Integration Points).
- **D-21:** Полный путь остаётся в `title` во всех экранных местах — без изменений (SC#5).

### Переезд с конфига

- **D-22:** Ключ `[organization] place_path_display` **просто удаляется** — ни разового импорта в
  БД, ни warn-хука на старте. Приложение не в проде, ключу один день.
- **D-23:** После миграции: организация = «Крайние», **все существующие места = «Как у родителя»**
  (ноль переопределений). Система ведёт себя ровно как сегодня при дефолтном конфиге.

### Охват — уточнение после исследования

- **D-24:** **Экспорт устройств в CSV** (`DeviceService::export_csv`, `device_service.rs:838`) —
  третий CSV-экспорт, не покрытый D-17/D-18 на момент discuss-фазы. Решение владельца (2026-08-28):
  **остаётся полный путь**. Довод D-18 применим буквально — файл уходит третьим лицам, подсказки
  при наведении в нём нет. Правило становится простым: **любой CSV — полный путь**. Код не меняется;
  фаза добавляет только тест-замок, фиксирующий отсутствие сокращения.

### Claude's Discretion

- Форма хранения переопределения места (колонка в `places` через миграцию V039 против отдельной
  таблицы) и хранения умолчаний организации (`app_settings` key/value против колонок
  org-settings) — на усмотрение планировщика; `app_settings` уже имеет готовый прецедент
  `low_stock_basis` с парой `settings_get_/set_` на обоих транспортах.
- Форма вычисления эффективного варианта на бэкенде (рекурсивный SQL-CTE рядом с
  `place_full_paths` против обхода в Rust) — на усмотрение исследователя/планировщика,
  при условии D-02 (пересчёт на каждом чтении, ничего не кэшируем).
- Имя и точная форма нового поля в DTO (`place_path_short` — рабочее название).

</decisions>

### Reusable Assets
- `ui/src/lib/utils/placePath.ts` — формула уже выделена в один чистый модуль. По D-01 логика
  переезжает на бэкенд; модуль либо удаляется, либо остаётся только для предпросмотра в

- `app_settings` (key/value, миграция V016) + `settings_get_/set_low_stock_basis` — готовый

- `ui/src/features/settings/OrgSettings.svelte` — секция с `.form-label`/`.form-grid` и
  логотипом внизу; новый подраздел (D-07) встаёт под `.logo-section`.
- `ui/src/features/places/PlaceFormModal.svelte` — уже использует `Dropdown` (не нативный
  `<select>`) для «Тип»; новый дропдаун «Вариант сокращения» копирует этот же паттерн.
- `crates/trackly-app/src/services/report_service.rs::combine_printer_and_place` — композитная
  ячейка «Место» отчёта «Заявки» (quick 260827-gim). Сокращение должно применяться только к
  путевой части, имя принтера сохраняется — регресс формата недопустим.

### Established Patterns
- Тонкие адаптеры: Tauri-команда и HTTP-хендлер оба зовут общий `build_*`; логика не дублируется.
- `place_full_paths` — вью с рекурсивным CTE, пересчитывается на каждом чтении, никогда не
  устаревает. D-02 повторяет ровно эту дисциплину для эффективного варианта.
- Портируемость: значения настроек живут в БД рядом с данными, не в `%APPDATA%` и не в конфиге —
  это и есть содержательный смысл SC#6.
- Шаблоны печатных форм хранятся **в БД**, а не в файле в репозитории: правка бандл-шаблона
  НЕ доходит до существующих БД без апгрейда сида (урок quick 260704-uw3).

### Integration Points
- Read-пути, которым нужна короткая строка: `device_service`/`devices_sqlite`,
  `cartridge_service`/`cartridges_sqlite`, `PlaceService` (содержимое места),
  `report_service` (4 домена + `combine_printer_and_place`), рендер `reports_export_pdf`.
- `reports_export_csv` — единственный экспорт, который по D-18 остаётся на полном пути.
  Разные значения в CSV и PDF одного отчёта — намеренная асимметрия, зафиксировать в тестах.
- `act_service` + `act_handover.minijinja` + сид шаблонов в БД — путь D-20.
- `crates/trackly-app/src/dto/auth.rs` / `http/auth.rs` / `tauri_cmds/auth.rs` —
  `AuthStatusDto.place_path_display` больше не нужен, если фронт перестаёт сокращать сам;

- `ui/src/lib/stores/auth.svelte.ts::placePathDisplay` — то же самое.
- Миграция V039 (места + умолчания организации) и `role_endpoint_matrix.rs` — новые эндпойнты
  настроек требуют покрытия ролевой матрицей, как `settings_set_low_stock_basis`.

<specifics>
## Specific Ideas

- Образцы для предпросмотра заданы явно и должны использоваться дословно:
  «Здание А / 1 этаж / 1-05» и «Территория А / Объект Х / помещение 3».
- Формулировка запроса владельца — «перечисление получится через запятую»: значение разделителя
  `, ` должно давать именно перечисление, то есть пробелы в поле значимы и не тримятся.
- Владелец дважды подчеркнул, что корень — это Организация, а не узел дерева: в разделе «Места»
  корневого элемента с именем организации быть не должно.

</specifics>
