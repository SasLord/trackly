## Summary

предков), таблица кейсов D-13..D-16 покрыта юнит-тестами, разделители нигде не тримятся
(проверено сквозным round-trip-тестом), пустой разделитель отбивается на сервере

`MutatePlaces` на per-place override, обе точки закрыты в `role_endpoint_matrix`), асимметрия
CSV(полный)/PDF(сокращённый) закреплена явным `shorten: bool` и регрессионным тестом.
Снимок `_legacy_defaults/v27/act_handover.html` побайтово совпадает с pre-39.1 HEAD — механизм
апгрейда шаблона не сломан. Приватность: реальных данных организации/людей в новых тестах,
шаблонах и фикстурах нет (только «Иванов И.И.»-класс и generic-placeholder'ы).

Но переезд «сокращение считает бэкенд» проведён не до конца, и на двух путях данные
пропадают с экрана:

1. **Поиск картриджей** (`cartridges_search`) не джойнит `place_effective_variant` →
   `place_path_short: null` → колонка «Место» показывает «—» у КАЖДОЙ найденной строки, хотя
   место у картриджа есть. Регресс относительно поведения до фазы (тогда фронт сокращал
   `full_path` сам).
2. **Форма места** после создания/переименования всегда шлёт второй RPC; при его падении
   пользователь видит ошибку на уже выполненной операции, `onSaved` не вызывается, а повтор
   «Создать» плодит дубль места.

Плюс к этому — общий класс дефекта: везде, где `place_path_short` пустой, UI списков показывает
«—» вместо деградации к полному пути (в `PlaceContents` и в отчётах деградация есть, в списках
устройств/картриджей — нет).

### CR-02: PlaceFormModal делает второй RPC всегда — падение приводит к «фантомной ошибке» и дублю места

**File:** `ui/src/features/places/PlaceFormModal.svelte:213-239`

**Issue:** `handleSubmit` после `places_create`/`places_rename` **безусловно** вызывает
`places_set_path_variant`, даже когда вариант не менялся (в режиме создания он всегда `null`,
то есть запись «как было»). Последствия:

- Если второй вызов падает (CAS-конфликт, обрыв сети, 403 при истёкшей сессии) — первый уже
  закоммичен. Пользователь получает `mapServerError(e)` и НЕ получает `onSaved(saved)`: список
  не обновляется, место выглядит несозданным. Естественная реакция — нажать «Создать» ещё раз,
  и появляется дубль (создание места по имени в рамках родителя не является идемпотентным).
  В режиме переименования картина зеркальная: переименование прошло, а тост говорит об ошибке.
- Даже на happy-path каждое создание/переименование пишет лишнюю запись в `audit_log`
  (`action: "set_path_variant"`, before == after) и лишний раз инкрементит `version`, из-за чего
  любая другая открытая форма с этим местом сразу получает CAS-конфликт.

**Fix:**
```ts
// вызывать вторую мутацию только при реальном изменении
const initialVariant = mode === 'rename' && place ? (place.path_variant_override ?? null) : null;
...
if (pathVariant !== initialVariant) {
  try {
    saved = await apiCall<PlaceDto>('places_set_path_variant', {
      id: saved.id,
      pathVariantOverride: pathVariant,
      version: saved.version,
    });
  } catch (e) {
    // первичная мутация уже прошла — закрываем форму и сообщаем ЧАСТИЧНЫЙ провал,
    // иначе пользователь повторит create и получит дубль
    pushToast('error', 'Место сохранено, но вариант сокращения не применён');
    onSaved(saved);
    return;
  }
}
pushToast('success', isRename ? 'Место переименовано' : 'Место создано');
onSaved(saved);
```

### WR-02: `place_effective_variant` выкидывает ВСЕХ потомков soft-deleted места и всю таблицу при отсутствии ключа в `app_settings`

**File:** `migrations/V039__place_path_display.sql:66-82`

**Issue:** проверено репродукцией на SQLite (дерево 1←2←3, org-дефолт `ends`):

| состояние | строки во view |
|---|---|
| всё живо | `(1,ends) (2,ends) (3,ends)` |
| место 2 soft-deleted | `(1,ends)` — живое место **3 тоже исчезло** |
| нет строки `place_path_variant` в `app_settings` | `(1,NULL) (2,NULL) (3,NULL)` |

Рекурсивный член фильтрует `p.deleted_at_utc IS NULL`, поэтому у потомка удалённого предка
рекурсия обрывается на строке с `variant IS NULL AND parent_id IS NOT NULL` — а терминальный
предикат такие строки как раз исключает, и `place_id` вообще не попадает во view. Второй кейс:
`COALESCE(variant, (SELECT ... ))` даёт NULL, если подзапрос пуст, — тогда `effective_variant`
NULL у ВСЕХ мест, и вместе с WR-01 весь столбец «Место» в списках устройств/картриджей
превращается в «—». Сегодня оба состояния недостижимы штатным кодом (места удаляются только
hard-delete и только пустые; ключ пишется через upsert), поэтому это WARNING, а не BLOCKER, —
но ни один из двух кейсов не покрыт тестом (`crates/trackly-infra/tests/place_effective_variant.rs`
проверяет только живые деревья), а хелпер `effective_variant()` в этом файле упадёт паникой,
если строки нет.

**Fix:** добавить в `place_effective_variant.rs` два теста (soft-deleted предок; удалённый ключ
`place_path_variant`) и зафиксировать желаемое поведение. Наиболее дешёвая правка самого view —
оставить дефолт даже при обрыве цепочки:
```sql
SELECT id AS place_id,
       COALESCE(variant, (SELECT value FROM app_settings WHERE key = 'place_path_variant'), 'ends')
FROM walk
WHERE variant IS NOT NULL OR parent_id IS NULL
   OR NOT EXISTS (SELECT 1 FROM places p WHERE p.id = walk.parent_id AND p.deleted_at_utc IS NULL);
```

### WR-03: JS-зеркало формулы расходится с Rust на 2-сегментном пути + вариант «Последнее»

if (segments.length === 2) {

### WR-05: три записи org-дефолтов пишутся без транзакции — возможен частично применённый набор

**File:** `crates/trackly-app/src/tauri_cmds/settings_org.rs:385-407`

**Issue:** `build_settings_set_place_path_defaults` внутри одного `writer.execute` делает три
независимых `conn.execute` (variant, sep_ends, sep_last_two) в autocommit-режиме. Ошибка на
втором/третьем операторе оставит БД в состоянии «вариант новый, разделители старые» и вернёт
`Err` — пользователь увидит «не удалось сохранить», а часть настроек уже изменилась. Соседний
код в этом же файле (`org_db_service`, `templates_*`) для многострочных записей транзакцию
использует.

**Fix:**
```rust
.execute(move |conn| {
    let tx = conn.transaction().map_err(map_rusqlite)?;
    for (key, value) in [
        ("place_path_variant", patch.variant.as_str()),
        ("place_path_sep_ends", patch.sep_ends.as_str()),
        ("place_path_sep_last_two", patch.sep_last_two.as_str()),
    ] {
        tx.execute(
            "INSERT INTO app_settings (key, value, created_at_utc, updated_at_utc) \
             VALUES (?1, ?2, ?3, ?3) \
             ON CONFLICT(key) DO UPDATE SET value = ?2, updated_at_utc = ?3",
            rusqlite::params![key, value, now],
        ).map_err(map_rusqlite)?;
    }
    tx.commit().map_err(map_rusqlite)
})
```
