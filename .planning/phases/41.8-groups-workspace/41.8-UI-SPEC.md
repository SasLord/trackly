# Phase 41.8 — UI Design Contract

> Визуальный и интеракционный контракт фазы «Группы» как рабочее место: меню строки устройства
> в составе группы, явные операции «Вывести из группы» / «Переместить в группу», попап «уже в
> группе» вместо тоста-отказа, «Списать» для устройств и групп, «призраки» разбора, общий
> модификатор неактивной строки и вложенная группа в узле своего типа.
> Составлен gsd-ui-researcher, проверяется gsd-ui-checker.
>
> **Макета нет.** Дизайн-система — Фаза 23 (`ui/src/styles/_tokens.scss`, гейт
> `check-tokens.mjs`), примитивы — Фазы 24–25, раздел «Группы» — Фаза 41 (`41-UI-SPEC.md`),
> меню строки, попап «Добавить в группу», тона статусов — Фаза 41.1 (`41.1-UI-SPEC.md` §7, §10,
> §11, §16). Этот документ **не переоткрывает** ни решения `41.8-CONTEXT.md` (D-00…D-25), ни
> контракт 41.1: он его **дополняет**. Всё, что здесь не названо, остаётся по 41.1.
> Новых npm-зависимостей — **ноль**. Новый токен — **один** (`--tr-row-inactive-opacity`, §5.2).
>
> **Приватность (жёсткое условие, репозиторий публичный):** все примеры вымышлены: «АРМ #3»,
> «АРМ #5», «Системный блок #4», «Разбор #7», «Монитор #2», «SSD 256 ГБ», «Память 8 ГБ»,
> «Склад А», «Здание А / 2 этаж / 214», «Иванов И.И.»; номера — плейсхолдерами («инв. № …»).

## 2. Границы: что контракт НЕ покрывает

- **История событий** (ввод, вывод, перенос, списание в ленте устройства) — Фаза 41.10. Здесь
  только требование: каждая операция — одна серверная транзакция с одной записью аудита.
- **Модификатор неактивной строки в «Устройствах», «Местах», отчётах** — отложено (CONTEXT,
  Deferred). В этой фазе `inactive` ставят **только** строки состава группы: призраки и
  списанные участники (D-24).
- **`GroupMoveModal` («Перенести…»)** — перенос группы на другое МЕСТО — не меняется (D-07):
  ни подпись, ни поведение, ни место в меню относительно прежних пунктов.
- **Попап выноса из состава в акте** (`GroupReleaseConfirmPopup`, титул «Вывести из состава и
  передать?») — поверхность Фазы 41.2, в перечень D-02 не входит и не переименовывается.
- **Снимок происхождения как сущность (F14)** — не делается; призраки вычисляются по
  `devices.origin_group_id`.
- **Форма серверных команд, DTO, имена кодов ошибок, разбивка на планы** — Claude's Discretion
  планировщика. Контракт задаёт только видимое пользователю и **требования к данным** (§12.6,
  §10.3), без которых экран нельзя собрать без N+1.
- **Роли как граница безопасности** — серверные (MutateGroups: admin, manager). Скрытие пунктов
  — UX-слой.

## 5. Color

### 5.1 60/30/10

Токены и роли Фазы 23 не меняются. Светлая тема — дефолт, тёмная — `[data-theme='dark']`.

| Роль | Токен | Использование в Фазе 41.8 |
|------|-------|----------------------------|
| Доминанта (60%) | `--tr-surface` / `--tr-surface-raised` | таблица состава; тело модалок, панель `ActionMenu`, панель `Dropdown` |
| Вторичная (30%) | `--tr-bg`, `--tr-group` | фон страницы, `thead`; строки вложенных групп в составе (`TableRow group`, унаследовано) |
| Границы | `--tr-border` / `--tr-border-strong` | разделители меню; **верхняя граница строки-разделителя блока призраков — `--tr-border-strong`** |
| Текст | `--tr-text-primary` / `-secondary` / `-tertiary` | ячейки и пункты / тела попапов, пометки призраков, подсказки `Radio` / подпись «в {родитель}» в дереве |
| Акцент (10%) | `--tr-accent`, `-soft`, `-text`, `--tr-focus-ring` | **строго список ниже** |
| Деструктив | `--tr-danger`, `-soft`, `-text` | кнопка `variant="destructive"` в попапах «уже в группе» («Переместить») и «Списать»; пункт «Удалить» (`.menu-danger`, унаследовано); бейдж «Списано» |
| Предупреждение | `--tr-warning-soft` / `--tr-warning-text` | callout последствий в §9, §10, §11 (унаследованная форма из `AddToGroupModal`) |
| Состояния строк | `--tr-row-hover`, `--tr-row-selected` | унаследовано; у неактивной строки hover **сохраняется** |

**Акцент зарезервирован строго за:**
1. primary-кнопкой «Переместить в группу» одноимённого попапа (§9) — единственная primary
   новой поверхности; в попапах «уже в группе» и «Списать» primary нет, там действие
   деструктивное;
2. выбранным узлом дерева (`--tr-row-selected` + inset 2px `--tr-accent`, унаследовано) —
   **только у активированного узла**, у его двойника по D-25 — нет (§13.3);
3. подсветкой найденного фрагмента имени в поиске дерева (`--tr-accent-text`, унаследовано) —
   в том числе в узлах-двойниках;
4. отмеченным `Radio` в §11.2 (унаследовано от примитива);
5. focus-ring — глобальный `*:focus-visible` и inset-кольцо первой ячейки / узла (унаследовано).

Акцент **не** используется: для подписи «в {родитель}», для пометок призраков, для строки-
разделителя блока призраков, для пунктов меню, для бейджей состава.

### 5.2 Новый токен неактивной строки (D-23)

| Токен | Значение | Где объявлен | Обоснование |
|-------|----------|--------------|-------------|
| `--tr-row-inactive-opacity` | **0.65** | `:root` (вне тем — значение одно на обе темы) в `_tokens.scss`, рядом с layout-константами | Минимальная непрозрачность, при которой `--tr-text-primary` поверх **всех шести** фонов гейта держит композит ≥ 4.6:1 в обеих темах (расчёт §5.3). 0.6 уже проваливает светлую тему (3.99:1 на `--tr-surface-sunken`) |

Механика модификатора (`TableRow`, проп `inactive?: boolean`, по умолчанию `false` — для
существующих вызовов визуально инертен):

| Правило | Значение |
|---------|----------|
| Что гаснет | все `<td>` строки, **кроме** помеченных классом `tr-cell-solid` |
| Чем гаснет | `opacity: var(--tr-row-inactive-opacity)` на `<td>` (не на `<tr>`: иначе погаснет и кебаб, и бейдж) |
| Цвет текста в погашенных ячейках | принудительно `--tr-text-primary` (в т.ч. колонка «Тип», где сейчас `--tr-text-secondary`): `--tr-text-secondary` при 0.65 даёт 2.72:1 — ниже порога |
| Что **обязано** быть `tr-cell-solid` | (1) ячейка статуса — бейджи никогда не гаснут: их контраст гейт меряет на композите `*-soft` без учёта opacity; (2) ячейка-причина — место призрака с пометкой (§12.2); (3) колонка действий — интерактивный элемент не гаснет |
| Hover / selected | работают как у обычной строки (фон строки не гаснет) |
| Курсор, клики, фокус | без изменений: неактивная строка — **не** disabled-элемент, она открывает просмотр |
| Селектор | в форме `.tr-row.inactive :global(> td:not(.tr-cell-solid))` — `.tr-row` в своей области видимости (урок 41.1 о специфичности `:global`). **Не** через `:has()` |

Неактивность читается **не только цветом/прозрачностью** (WCAG 1.4.1): у призрака — текстовая
пометка в ячейке места (§12.2), у списанного участника — бейдж «Списано» в ячейке статуса.

### 5.3 Новое правило гейта контраста R4

`check-contrast.mjs` получает правило R4: композит `--tr-text-primary` с альфой
`--tr-row-inactive-opacity` поверх каждого из шести фонов (`--tr-bg`, `--tr-surface`,
`--tr-surface-raised`, `--tr-surface-sunken`, `--tr-row-hover`, `--tr-group`) × 2 темы = 12
ячеек, порог `COMPOSITE_MIN = 4.6`. Отсутствие токена — нарушение, не пропуск. Расчёт
исследователя (sRGB source-over, та же формула, что R1):

| Тема | bg | surface | raised | sunken | row-hover | group |
|------|----|---------|--------|--------|-----------|-------|
| светлая, 0.65 | 4.79 | 5.04 | 5.04 | **4.63** | 4.79 | 4.70 |
| тёмная, 0.65 | 7.07 | 6.75 | 6.45 | 7.17 | 5.89 | 6.46 |

Self-test R4: мутант со значением 0.6 обязан покраснеть (светлая/sunken 3.99). Проверка гейта
по реальному исходнику: прогнать R4 до добавления токена — красный («токен отсутствует»).
`--tr-row-selected` (rgba) остаётся вне периметра (D-33 гейта) — проверяется вручную (§14.4).

## 6. Меню строки устройства (D-01…D-03, D-19)

Одна чистая функция `buildMenuSections` (`deviceRowMenu.ts`) для всех потребителей:
«Устройства», «Принтеры», таблица состава группы. Golden-фикстура `check-device-row-menu`
обновляется вместе с порядком.

### 6.1 Порядок секций (D-03)

```
Опросить сейчас                ← только принтеры (унаследовано)
──────────────────────────
Просмотр
Редактировать
Печать документа приёма        ← только при переданном обработчике
──────────────────────────
Вывести из группы              ← участник, не якорь (D-01)
Переместить в группу           ← участник, не якорь, статус не «Списано»/«На списание»
──────────────────────────
Добавить в группу              ← свободное устройство (41.1 §7.3, без изменений)
{быстрые действия типов}
──────────────────────────
Списать                        ← статус «На списание» (D-19, D-21)
Удалить                        ← .menu-danger
```

- Секция «Вывести / Переместить» стоит **сразу после** «Печать документа приёма» (или после
  «Редактировать», если печати нет) — граница секции даёт это автоматически.
- Секции «Вывести / Переместить» и «Добавить в группу» **взаимоисключающие** на практике
  (участник не видит «Добавить», свободный не видит «Вывести»), но порядок фиксирован для обеих.
- **«Списать»** стоит в последней секции **над** «Удалить», обычным цветом
  (`--tr-text-primary`), **не** `.menu-danger`: красный в меню остаётся только у «Удалить»;
  деструктивность «Списать» несёт кнопка подтверждения (§11).
- Правило разделителей 41.1 §7.2 (пустая секция — без разделителя, двух подряд нет, меню не
  начинается и не заканчивается разделителем) сохраняется.
- Прежняя подпись «Вывести из состава» исчезает из меню всех поверхностей (D-02).

(правило 41.1). UI прячет то, что сервер отклонит.
² У якоря пункт «Списать» в меню устройства открывает **то же** подтверждение группы (§11.3),
что пункт «Списать» группы: у якоря списание всегда меняет группу, двух разных смыслов у одной
подписи быть не должно (R-03).
³ «Списать» требует прав на правку устройства и, для участников/якорей, MutateGroups; точный
набор ролей — серверный, UI зеркалит.

Решения — по `status_code`, не по подписи и не по id (D-02 фазы 41.1).

### 6.3 Клавиатура и ARIA

Без изменений по 41.1 §7.4. `aria-label` триггера: «Действия с устройством: {имя}».

## 7. Таблица состава группы как рабочее место (D-05)

### 7.1 Строка устройства

| Жест | Поведение |
|------|-----------|
| Кебаб в колонке действий | `DeviceRowMenu` (меню §6), **не** локальный `ActionMenu` с одним пунктом |
| Правый клик по строке | `preventDefault()` + то же меню у курсора (`openAt`) — одинаково в Tauri и LAN-браузере |
| Двойной клик по строке | `PlaceEntityViewModal` устройства; правка — оттуда. Перед открытием снять выделение текста (41.1 §8.2) |
| `Enter` на первой ячейке | то же, что двойной клик (паритет с `DeviceListRow`) |
| `ContextMenu` / `Shift+F10` на первой ячейке | меню у левого-нижнего угла ячейки |
| Одиночный клик по первой ячейке | только фокус строки. **Переход в раздел «Устройства» с этого жеста снимается** (R-01) |

Колонка действий рендерит кебаб для **всех** строк устройств при любой роли, у которой меню
не пусто («Просмотр» есть всегда) — в отличие от прежнего «только canEdit».

Требование к меню в этой таблице: набор пунктов считается по **загруженному** `DeviceDto`
(статус, членство, якорь). Кебаб строки состава обязан пройти через тот же `prepare()`, что
правый клик, — меню не открывается с пунктами, посчитанными по пустому устройству.

### 7.2 После любого действия

Правка, вывод, перенос, списание, удаление, «Вернуть в разбор» → в той же функции, что вызов
API: перечитать состав (`loadComposition`), сообщить странице (`onChanged` → дерево и
карточка), `notifyPlaceContentChanged(changed_place_ids)` при смене места (реестр INV-7).
Раскрытые вложенные группы остаются раскрытыми (унаследованное поведение `loadComposition`).

### 7.3 Модалки внутри ячейки

`DeviceRowMenu` рендерит модалки внутри `<td>` (Modal не портальный). Тела всех новых модалок
(§9–§11) **явно** задают `white-space: normal` и `text-align: left`; иначе наследуют
`nowrap` / `text-align: right` колонки `.col-menu` (урок `modal_inherits_table_cell_styles`).
Охрана событий строки (`isRowOverlayEvent` / `isOwnKeyEvent` первым оператором обработчика)
распространяется на новые строки состава.

## 8. Меню группы: строка вложенной группы и узел дерева (D-06, D-07, D-21)

### 8.1 Узел группы в дереве

```
Переименовать
Перенести…                     ← только корневая группа (GroupMoveModal, место) — без изменений
──────────────────────────
Вывести из группы              ← только вложенная группа
Переместить в группу           ← только вложенная группа
──────────────────────────
Списать                        ← якорь группы в статусе «На списание» (D-21)
Удалить                        ← .menu-danger
```

- Разделитель ставится **элементом** `<hr role="separator">` (механика 41.1 §6.3), а не
  `border-top` у `.menu-danger`, как сейчас: прежний бордюр снимается, чтобы над «Списать» и
  «Удалить» не стояло две линии.
- У АРМ (container) якоря нет — пункта «Списать» нет никогда.
- «Перенести…» и «Переместить в группу» стоят в **разных** секциях: у корневой группы есть
  только первое, у вложенной — только второе (у вложенной место задаёт корень), поэтому в
  одном меню они не встречаются никогда.

### 8.2 Узел типа в дереве

Без изменений по составу («Создать группу этого типа», «Переименовать», «Удалить» для
не встроенного типа без групп). Правый клик открывает то же меню, что кебаб.

### 8.3 Правый клик и клавиатура в дереве (GRW-03)

| Жест | Поведение |
|------|-----------|
| Правый клик по узлу группы / типа с непустым меню | `preventDefault()` + меню узла у курсора; узел **не** становится выбранным (выбор — левым кликом) |
| Правый клик по узлу без меню (нет прав) | родное меню браузера не подавляется (R-02 фазы 41.1) |
| `ContextMenu` / `Shift+F10` на сфокусированном `treeitem` | меню у левого-нижнего угла имени узла |
| Двойник узла по D-25 (§13) | то же меню, что у основного узла, в том же составе |

### 8.4 Строка вложенной группы в таблице состава

Кебаб и правый клик по строке группы (`TableRow group`, `oncontextmenu` уже форвардится):

```
Открыть группу
──────────────────────────
Вывести из группы              ← canEdit
Переместить в группу           ← canEdit
──────────────────────────
Переименовать                  ← canEdit
──────────────────────────
Списать                        ← canEdit, якорь «На списание»
```

«Удалить» в этой строке не появляется (как и сейчас): удаление группы — из дерева и панели.
Клик по кебабу не сворачивает и не разворачивает строку (`menu-stop`, унаследовано).

**Двойной клик по строке вложенной группы ничего не добавляет к одиночному:** строка
раскрывается (или сворачивается) **один раз** и остаётся в этом состоянии — не «раскрыть и
тут же свернуть». Охрана:

- обработчик `click` строки группы переключает раскрытие **только при `event.detail <= 1`**
  (1 — первый клик мышью, 0 — активация с клавиатуры); второй клик серии (`detail === 2`) и
  последующие игнорируются;
- обработчик `dblclick` на строке группы **не назначается**: просмотр (`PlaceEntityViewModal`)
  открывается двойным кликом только у строк устройств (§7.1), у групп — нет;
- выделение текста после двойного клика снимается так же, как у строк устройств (41.1 §8.2).

Проверка — в живом приложении (§14.4, п. 9).

## 10. Попап «уже в группе» (D-15, D-16, D-18)

Открывается вместо тоста-отказа, когда сервер отвечает **машинно различимым** отказом «уже в
группе» (не по разбору текста). Пути: строка добавления состава (устройство и группа),
`AddToGroupModal` в режиме «Добавить» (гонка: устройство заняли в другой сессии), строка
возврата детали разбора (§12.5), массовое добавление (§10.2).

### 10.1 Одиночный

Отдельная `Modal size="md"` поверх страницы. Если исходный путь сам модалка
(`AddToGroupModal`), попап **заменяет её содержимое** шагом «подтверждение» в той же `Modal`
(модалка над модалкой запрещена, D-09 фазы 41); «Отменить» возвращает к выбору группы.

| Случай | Титул | Тело |
|--------|-------|------|
| Устройство | Устройство уже в группе | Устройство «Монитор #2» сейчас входит в группу «АРМ #3». Переместить его в «АРМ #5»? |
| Группа | Группа уже вложена | Группа «Системный блок #4» сейчас вложена в «АРМ #3». Переместить её в «АРМ #5»? |
| Возврат детали (D-15) | Деталь уже в группе | Деталь «SSD 256 ГБ» сейчас входит в группу «АРМ #3». Переместить её обратно в «Разбор #7»? |

- Под телом — callout `--tr-warning-soft` / `--tr-warning-text`, если у цели есть место и оно
  отличается от текущего: «Устройство переедет в «Здание А / 2 этаж / 214».» (для группы —
  «Группа и её состав переедут в «…».»). Без места или то же место — callout не рендерится.
- Футер: `Button variant="secondary"` **«Отменить»** + `Button variant="destructive"`
  **«Переместить»** (D-16: «danger» = `destructive`, варианта `danger` в проекте нет).
  Подпись «Переместить» остаётся и в случае возврата детали — одна подпись на одну операцию.
- Фокус при открытии — на «Отменить» (деструктивное действие не подтверждается случайным
  `Enter`).
- «Переместить» → та же единая операция переноса, что §9 (с флагом переноса). Кнопка
  `loading` на время запроса; отказ — инлайн-текст сервера под телом.
- Успех: Toast «Устройство перемещено в группу «АРМ #5»» / «Группа «Системный блок #4»
  перемещена в «АРМ #5»» / «Деталь возвращена в «Разбор #7»».
- «Отменить» / `Esc` / крестик: ничего не меняется, строка поиска сохраняет текст запроса.

### 10.2 Массовый (`GroupAddDevicesModal`, D-18)

Шаг подтверждения **в той же** `Modal size="wide"` (не вторая модалка). Выбор сохраняется.

| Элемент | Контракт |
|---------|----------|
| Титул | «{N} {устройство / устройства / устройств} уже в других группах» через `pluralizeRu`; при N = 1 — «1 устройство уже в другой группе» |
| Тело | «Переместить {их / его} в «АРМ #5»? Остальные выбранные устройства будут добавлены как обычно.» (вторая фраза — только если выбраны и свободные) |
| Список | строки «Монитор #2 — в группе «АРМ #3»»: имя `--tr-text-body`, инв. № `.tr-mono` если есть, хвост `--tr-text-secondary`; `max-height: 240px`, прокрутка внутри; порядок — как в таблице выбора |
| Футер | secondary «Отменить» (назад к выбору, отметки сохранены) + destructive «Переместить» |
| Операция | одна серверная: все добавления и переносы — всё или ничего |
| Успех | модалка закрывается; Toast «Добавлено {N} {устр.}, из них перемещено {M}» через `pluralizeRu` — например «Добавлено 5 устройств, из них перемещено 2» |
| Отказ | инлайн-текст сервера в шаге подтверждения; ничего не применено |

Существующая пометка занятости в таблице выбора («уже в группе «…»») остаётся подсказкой и
выбор **не блокирует**.

### 10.3 Требование к данным

Отказ «уже в группе» несёт, на каждое занятое устройство/группу, `id` и **имя** текущей
группы — клиент не делает дополнительных запросов, чтобы нарисовать попап.

## 11. «Списать» (D-19…D-22)

Общее для всех трёх вариантов: `Modal size="md"`, футер — `Button variant="secondary"`
**«Отменить»** + `Button variant="destructive"` **«Списать»** (`loading` на время запроса),
подтверждение показывается **всегда** (D-19), фокус при открытии — на «Отменить». Одна
серверная операция (D-22); после успеха — §7.2 + WS-событие до «Устройств», «Групп», «Мест».

### 11.1 Свободное устройство

- Титул: **«Списать устройство?»**
- Тело: «Устройство «Монитор #2» (инв. № …) получит статус «Списано». Вернуть прежний статус
  можно вручную в форме устройства.» (без инв. № — фраза без скобок)
- Toast: «Устройство списано»

### 11.2 Участник группы, не якорь (D-20)

- Титул: **«Списать устройство?»**
- Тело: «Устройство «Память 8 ГБ» (инв. № …) получит статус «Списано».»
- `fieldset` с легендой «Устройство входит в группу «Системный блок #4»:» (`--tr-text-label`) и
  двумя `Radio`, вертикально, gap `--tr-space-xs` (8px):

| Вариант | Подпись (`--tr-text-body`) | Подсказка (`--tr-text-caption`, `--tr-text-secondary`) |
|---------|----------------------------|--------------------------------------------------------|
| **по умолчанию** | Оставить в группе списанным | В составе группы оно будет показано неактивной строкой. |
| второй | Вывести из группы | обычная группа: «Место устройства не изменится.» · деталь разбора: «Деталь останется в составе разбора выведенной.» |

- Вариант по умолчанию — «Оставить» (пожелание пользователя: списанное «ещё может как-то
  помогать»; меньше изменений одним кликом).
- Toast: «Устройство списано» / «Устройство списано и выведено из группы «Системный блок #4»»

### 11.3 Группа с якорем «На списание» (D-21)

Открывается из меню узла дерева, строки вложенной группы и из меню устройства-якоря (§6.2 ²).

| | `substitute` («Системный блок») | `teardown` («Разбор») |
|-|---------------------------------|-----------------------|
| Титул | **«Списать «Монитор #2»?»** (имя якоря) | **«Списать «Монитор #2»?»** |
| Тело | Устройство «Монитор #2» — якорь группы «Системный блок #4» — получит статус «Списано». Группа будет расформирована, её состав освободится; статус и место этих устройств не изменятся: | Донор «Монитор #2» получит статус «Списано». Запись разбора «Разбор #7» сохранится вместе с деталями: |
| Список | участники группы | живые детали, затем выведенные с хвостом «— выведена» (`--tr-text-secondary`) |
| Пустой состав | вместо списка и двоеточия: «Состав группы пуст.» | «Деталей в разборе нет.» |
| Toast | «Устройство «Монитор #2» списано, группа «Системный блок #4» расформирована» | «Донор «Монитор #2» списан, запись разбора «Разбор #7» сохранена» |

Список: строки «имя · инв. №» (`.tr-mono`), `max-height: 240px`, прокрутка внутри.

**Загрузка и ошибка состава (R-12).** Подтверждение без списка состава — не подтверждение
(D-21 требует показать, что освободится). Поэтому:

| Состояние | Место списка | «Списать» |
|-----------|--------------|-----------|
| Загрузка | `Spinner size="sm"` + «Загрузка…» | `disabled` |
| Ошибка | инлайн `--tr-danger-text`: «Не удалось загрузить состав группы. Нажмите «Повторить».» + `Button variant="secondary" size="sm"` **«Повторить»** справа от текста | `disabled` |
| Повтор | «Повторить» `loading`, текст ошибки остаётся до ответа | `disabled` |
| Загружено (в т.ч. пусто) | список / пустой текст | доступна |

Фокус при ошибке остаётся на «Отменить»; «Повторить» достижима `Tab`.

После расформирования `substitute` дерево снимает выбор с удалённого узла (поведение удаления группы,
унаследовано), фокус — на узел типа.

## 12. Призраки разбора и неактивные строки (D-10…D-15, D-23, D-24)

### 12.1 Кто неактивен

| Строка | `inactive` | Причина текстом |
|--------|:-:|-----------------|
| Призрак разбора (живое устройство) | ✓ | пометка в ячейке места (§12.2) |
| Призрак разбора, удалённое устройство | ✓ | «удалено» в ячейке места |
| Призрак разбора, списанное устройство | ✓ | пометка места + бейдж «Списано» |
| Участник любой группы со статусом «Списано» (D-24) | ✓ | бейдж «Списано» в ячейке статуса |
| Участник «На списание» | — | (ещё не списан) |
| Якорь, живые детали, прочие участники | — | — |

### 12.2 Строка призрака

Те же шесть колонок, что у участника:

| Колонка | Содержимое | `tr-cell-solid` |
|---------|------------|:-:|
| Тип | тип устройства | — |
| Название | имя | — |
| Инв. № / Серийный № | `.tr-mono`, как у участника | — |
| Место | **пометка**: в другой группе — «выведено → АРМ #3»; не в группе — «выведено · Склад А» (короткий путь места); удалено — «удалено». `--tr-text-caption`, `--tr-text-secondary`; `title` — полный путь места | ✓ |
| Статус | бейдж статуса по стору (тон по `code`); у удалённого — «—» | ✓ |
| Действия | кебаб с единственным пунктом «Вернуть в разбор» (§12.4) | ✓ |

### 12.3 Положение и счётчики (D-11)

- Призраки идут **в конце** состава разбора, после живых деталей, порядок — по дате вывода
  (свежие выше); если даты нет — по имени.
- Перед ними — **строка-разделитель** на всю ширину (`colspan` = 6): текст «Выведенные детали
  · 2» (`--tr-text-caption`, `--tr-text-secondary`), padding `--tr-space-xs` / `--tr-space-md`,
  верхняя граница `--tr-border-strong`, без фона, не фокусируется, без меню. Это и есть
  подпись «+ N выведено» рядом со счётчиком (D-11): число стоит сразу под последним членом.
- Счётчики вкладки «Состав», узла дерева и «Мест» считают **только членов** — призраки не
  входят.
- Призраков нет — разделитель не рендерится.
- Пустое состояние таблицы (`Table empty`) — только если нет ни членов, ни призраков; при
  одних призраках показываются разделитель и призраки, без пустого состояния.

### 12.4 Жесты призрака (D-12, D-15)

| Жест | Призрак (живое устройство) | Призрак удалённый |
|------|---------------------------|-------------------|
| Двойной клик / `Enter` на первой ячейке | `PlaceEntityViewModal` (просмотр) | ничего |
| Кебаб / правый клик / `Shift+F10` | меню из одного пункта **«Вернуть в разбор»** — только canEdit | кебаба нет; правый клик — родное меню |
| `title` строки | — | «Устройство удалено — вернуть нельзя» |

«Вернуть в разбор»: если деталь сейчас ни в какой группе — сразу одна серверная операция
ввода (разрешённое исключение D-08), Toast «Деталь возвращена в «Разбор #7»». Если она в
другой группе — попап §10.1 (случай «Возврат детали»). Списанную деталь вернуть **нельзя**
(правило «Списано в группу не вводится»): у списанного призрака пункт скрыт, кебаб не
рендерится.

### 12.5 Строка добавления в составе разбора (D-08, D-15)

| Элемент | Разбор (`teardown`) | Прочие типы |
|---------|---------------------|-------------|
| Поиск (`Dropdown combobox`) | **только** призраки этого разбора, не удалённые и не списанные; групп нет; одна секция без заголовка | устройства + группы (без групп `teardown`, D-17) |
| Placeholder | «Вернуть выведенную деталь — название, инвентарный или серийный номер» | «Добавить устройство или группу — название, инвентарный или серийный номер» (без изменений) |
| Мета строки результата | «сейчас в группе «АРМ #3»» или короткий путь места | без изменений |
| «Добавить несколько…» | **не рендерится** (массовое добавление нарушило бы D-08) | без изменений |
| «Создать деталь» | без изменений | — |
| Пустой поиск | «Выведенных деталей нет» / «Новые детали добавляются кнопкой «Создать деталь».» | унаследовано |

Выбор результата: деталь не в группе → ввод сразу; в группе → попап §10.1 «Возврат детали».

Пустое состояние таблицы разбора (нет ни деталей, ни призраков): «Деталей пока нет» /
«Создайте первую деталь кнопкой «Создать деталь» ниже.»

### 12.6 Требования к данным призрака

Одним ответом состава (без N+1, с учётом удалённых, D-14): `device_id`, имя, тип,
инв./серийный №, `status_code` + подпись, признак удаления, id и имя текущей группы (или
null), короткий и полный путь места, дата вывода (если есть). Членские строки списанных
участников уже несут `status_code` — этого достаточно для `inactive`.

## 13. Вложенная группа в узле своего типа (D-25)

### 13.1 Где видна

Вложенная группа показывается **дважды**: по месту вложения (как сейчас) и **корневым узлом
своего типа** — «двойником». Двойник — полноценный узел: выбирается, открывает панель группы,
раскрывается со своими вложениями, имеет меню (§8.1) и правый клик.

### 13.2 Вид двойника

```
[›] Системный блок #4   в АРМ #3        [Без места] [3]  [⋯]
```

- Подпись «в {имя родителя}» — сразу после имени: `--tr-text-caption`, `--tr-text-tertiary`,
  gap `--tr-space-2xs`, `flex: none`, `max-width: 40%`, `text-overflow: ellipsis`. Имя
  группы сжимается **после** подписи (у имени `flex: 1; min-width: 0`).
- `title` узла: «Вложена в «АРМ #3» · {место}».
- У узла по месту вложения подписи нет.
- Подпись участвует в доступном имени `treeitem`: «Системный блок #4, в АРМ #3».
- Двойник считается в счётчике узла типа (`group_count` типа включает вложенные группы этого
  типа, каждую один раз).
- Порядок среди корней типа — общий (`seq`, затем `id`), двойники не выносятся в конец.

### 13.3 Ключи, выбор, фокус

| Свойство | Контракт |
|----------|----------|
| Ключ основного узла | `group-{id}` (как сейчас) |
| Ключ двойника | `in-type-{id}`; его потомков — `in-type-{aliasRootId}-group-{childId}` |
| DOM id | `rowDomId(key)` — уникален для обоих узлов |
| Выбран | только **активированный** узел (`aria-selected="true"` у одного `treeitem`); панель группы одна и та же |
| Глубокая ссылка `#/groups?id=` и «Открыть группу» | выбирают **основной** узел (по месту вложения), как сейчас |
| Клавиатура | стрелки ходят по видимым узлам, оба узла — разные остановки; раскрытие двойника не раскрывает основной и наоборот |
| Поиск по дереву | двойник ищется как обычный узел; счётчик результатов в live-регионе считает **группы**, а не узлы |

## 14. Состояния и доступность

### 14.1 Состояния

| Поверхность | Loading | Empty | Error |
|-------------|---------|-------|-------|
| Меню строки в составе | меню открывается после `prepare()` (устройство, статусы, типы); с пустой панелью — никогда | — | Toast «Не удалось загрузить устройство. Проверьте подключение и повторите.», меню не открывается |
| «Переместить в группу» | `Dropdown loading` | «Подходящих групп нет» (§9) | «Не удалось загрузить список групп. Закройте окно и откройте его снова.» внутри поля (`--tr-danger-text`); primary `disabled` |
| Попапы «уже в группе» / «Списать» | кнопка действия `loading`, вторая `disabled` | — | инлайн-текст сервера под телом (форма `server-error` из `GroupDeleteModal`) |
| Подтверждение группы (§11.3) | список состава грузится с `Spinner size="sm"` «Загрузка…»; «Списать» `disabled` до загрузки | «Состав группы пуст.» / «Деталей в разборе нет.» | «Не удалось загрузить состав группы. Нажмите «Повторить».» инлайн + кнопка «Повторить»; «Списать» `disabled` до успешной загрузки (R-12, §11.3) |
| Призраки | приходят вместе с составом (своего loading нет) | разделитель не рендерится | как ошибка состава |
| Строка возврата детали | `Dropdown loading` | §12.5 | унаследовано |

### 14.2 Клавиатура

| Поверхность | Требование |
|-------------|------------|
| Строка состава | `Enter` = просмотр; `ContextMenu` / `Shift+F10` = меню; кебаб `Tab`-достижим |
| Узел дерева | `ContextMenu` / `Shift+F10` = меню узла (новое); прочее унаследовано |
| `Radio` в §11.2 | группа стрелками, `Tab` входит на отмеченный вариант |
| Попапы | фокус-ловушка, возврат фокуса на триггер (`Modal`); начальный фокус на «Отменить» в деструктивных попапах |
| Строка-разделитель призраков | не фокусируется |

### 14.3 Экранный диктор

- Неактивная строка объявляется **текстом** (пометка места, бейдж «Списано»), не прозрачностью.
- Строка-разделитель — обычная ячейка таблицы с текстом «Выведенные детали · 2».
- `fieldset`/`legend` у выбора в §11.2.
- Пункты меню — `role="menuitem"`, разделители — `role="separator"` (унаследовано).

### 14.4 Только в живом приложении (Tauri и LAN-браузер)

Компиляционные гейты этого не видят (уроки `compile_gates_miss_svelte_runtime`,
`synthetic_harness_not_verification`):

1. Правый клик по строке состава и по узлу дерева подавляет родное меню одинаково в Tauri и в
   LAN-браузере; у узла без прав — родное меню.
2. Двойной клик по строке состава открывает просмотр, не оставляет выделенного слова; правка
   из просмотра обновляет состав и счётчики «Мест».
3. Тексты модалок, открытых из кебаба строки состава, переносятся и выровнены влево (не
   `nowrap`, не по правому краю).
4. Неактивная строка различима и читаема в обеих темах, в том числе на hover и на
   **выбранной** строке (`--tr-row-selected` вне периметра гейта); бейдж и кебаб не погашены.
5. Подпись «в АРМ #3» у двойника не выталкивает счётчик и кебаб в узком дереве.
6. Выбор двойника не подсвечивает основной узел; клавиатура не «прыгает» между двойниками.
7. Меню узла дерева: один разделитель над «Списать»/«Удалить», не два.
8. Попап «уже в группе» открывается из всех трёх путей; тоста-отказа нет ни на одном.
9. Двойной клик по строке вложенной группы в составе раскрывает (или сворачивает) её один
   раз — строка не «мигает» раскрытием и обратным сворачиванием; просмотр не открывается.

| Ситуация | Копирайт |
|----------|----------|
| Ввод существующего устройства в разбор (D-08) | В разбор нельзя добавить существующее устройство: детали появляются только через «Создать деталь». |

| Вложение разбора в группу (D-09) | Группу типа «Разбор» нельзя вложить в другую группу. |
| Цикл вложения | Нельзя вложить группу в саму себя или в одну из её вложенных групп. |
| Перенос в текущую группу | Устройство уже входит в эту группу. |
| Перенос / ввод «Списано» | Устройство со статусом «Списано» в группу не добавляется. *(унаследовано)* |
| Перенос / ввод «На списание» | Устройство со статусом «На списание» в группу не добавляется. *(унаследовано)* |

| Сетевая ошибка вывода | Не удалось вывести из группы. Проверьте подключение и повторите. |
| Сетевая ошибка переноса | Не удалось переместить. Проверьте подключение и повторите. |
| Сетевая ошибка списания | Не удалось списать. Проверьте подключение и повторите. |
| Сетевая ошибка возврата | Не удалось вернуть деталь в разбор. Проверьте подключение и повторите. |
| Устройство для меню строки состава не загрузилось (Toast) | Не удалось загрузить устройство. Проверьте подключение и повторите. |
| Список групп в попапе «Переместить в группу» не загрузился (инлайн) | Не удалось загрузить список групп. Закройте окно и откройте его снова. |
| Состав для подтверждения «Списать» группы не загрузился (инлайн + кнопка «Повторить», R-12) | Не удалось загрузить состав группы. Нажмите «Повторить». |

## 18. Решения researcher'а (Claude's Discretion)

| # | Решение | Обоснование | Отвергнуто |
|---|---------|-------------|------------|
| R-01 | Одиночный клик по первой ячейке строки состава больше не уводит в «Устройства»; `Enter` открывает просмотр | Паритет с `DeviceListRow` (D-05) и цель фазы «переход в «Устройства» не нужен»; уход со страницы от одиночного клика ломает правый клик/двойной клик рядом | Оставить навигацию по клику (двойной клик тогда сначала уводил бы со страницы) |
| R-02 | Неактивная строка гасит ячейки, а не `<tr>`; статус, ячейка-причина и действия — `tr-cell-solid`; текст погашенных ячеек — `--tr-text-primary` | Только так проходит порог 4.5/4.6: `--tr-text-secondary` и бейджи под opacity 0.65 дают 2.7–3.1:1. Пометка-причина и кебаб читаются полностью | `opacity` на всю строку (бейджи и вторичный текст ниже порога); сплошной «бледный» цвет текста вместо прозрачности (противоречит D-23 «полупрозрачная») |
| R-03 | «Списать» у устройства-якоря открывает подтверждение группы (§11.3) | Списание якоря всегда меняет группу (расформирование или донор); одна подпись — один смысл | Отдельная «просто смена статуса» у якоря (оставила бы `substitute` с якорем «Списано») |
| R-04 | «Списать» — обычным цветом над «Удалить» | Красный в меню закреплён за «Удалить» (41.1); деструктивность несёт кнопка подтверждения | `.menu-danger` у двух соседних пунктов |
| R-05 | По умолчанию в §11.2 — «Оставить в группе списанным» | Пожелание пользователя; минимум изменений одним `Enter` | «Вывести» по умолчанию |
| R-06 | Подпись D-11 «+ N выведено» реализована строкой-разделителем «Выведенные детали · N» перед призраками | `Tabs` рисует счётчик числом; текст внутри вкладки ломал бы её ширину. Разделитель стоит прямо под последним членом и отделяет призраков от членов | Текст в вкладке «Состав»; подпись в узле дерева (32px, тесно) |
| R-07 | Список массового попапа — «Монитор #2 — в группе «АРМ #3»» | Нотация D-18 «устройство → группа» в интерфейсе читается как «будет перемещено в АРМ #3» — обратный смысл. Стрелка оставлена только в пометке призрака, где она и значит «ушло туда» | Буквальная стрелка в списке |
| R-08 | Шаги «уже в группе» внутри уже открытой модалки — заменой содержимого той же `Modal` | Запрет модалки над модалкой (D-09 фазы 41); выбор пользователя сохраняется | Вторая модалка поверх |
| R-09 | Ключ двойника `in-type-{id}`; глубокие ссылки выбирают основной узел | Не ломает существующие ссылки и `expandPathTo`; ключи уникальны для DOM и фокуса | Выбор двойника по ссылке (раскрывал бы тип вместо родителя) |
| R-10 | Удалённый призрак без просмотра и без меню | Просмотр удалённого устройства не гарантирован API; пустой жест честнее ошибки | Просмотр с тостом-ошибкой |
| R-11 | «Добавить несколько…» скрыт в разборе | Массовое добавление существующих устройств противоречит D-08 | Модалка с фильтром «только призраки» (дублирует строку возврата) |
| R-12 | В подтверждении «Списать» группы (§11.3) кнопка «Списать» `disabled`, пока состав не загружен; при ошибке — инлайн «Не удалось загрузить состав группы. Нажмите «Повторить».» и кнопка «Повторить» | D-21: подтверждение перечисляет состав — без списка человек подтверждает вслепую; повтор на месте не теряет контекст | Оставить «Списать» доступной при ошибке (подтверждение без содержания); закрывать модалку с тостом (лишний путь назад) |
