# Phase 41.8 Plan 15: CR-01, списанный участник группы в актах

Серверный отказ акту для статуса «Списано» (D-27) и исключение списанных из снимка планировщика групп; возвраты списанного отказывают Conflict с понятной причиной.

## Что сделано

- `is_act_assignable` отказывает по `device.status_code == "списано"` до всех веток, включая членов групп.
- `ActGroupSnapshot::with_written_off` убирает списанных из состава (`direct_of`), `collect_units` не эмитит списанный якорь, `plan` не выносит списанного. `load_snapshot` читает их одним запросом по коду статуса. `act_expansion` менять не пришлось.
- `not_in_work_return_conflict`: для списанного в `do_return` и ветке added `update_return` текст «Устройство «X» имеет статус «Списано» и не может быть возвращено актом: уберите его из возврата.»; прочие статусы сохраняют прежний текст; откат всей операции прежний.

## Ветка retained: доказательство недостижимости (вместо status_after_return)

`update_return` перед обработкой `retained_with_change` сверяет `status_id` текущего устройства с `after_json` журнала возврата (act_service.rs, блок «изменилось после этого возврата»). Устройство возвращено актом, значит ожидаемый статус «На складе»; списание после этого даёт расхождение и Conflict до `update_full_in_tx`. Поэтому статус «На складе» списанному не записывается. `status_after_return` не добавлялся (было бы мёртвым кодом; пункт acceptance `grep -c status_after_return >= 2` сознательно не выполнен). Тест 8 закрепляет охрану: Conflict, статус «Списано» и место не тронуты.
