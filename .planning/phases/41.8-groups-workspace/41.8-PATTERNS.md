## Pattern Assignments

### `crates/trackly-core/src/error.rs` — новый вариант `AlreadyInGroup` (model, request-response)

**Analog:** вариант `AccessBlocked` в том же файле (структурные поля уходят в `details`).

**Объявление варианта** (образец — стр. 123-146, `#[error(..)]` + поля):
```rust
#[error("account blocked (pending={pending}, rejection_reason={rejection_reason:?})")]
AccessBlocked { pending: bool, rejection_reason: Option<String> },
```
Новый вариант: `AlreadyInGroup { items: Vec<OccupiedItem> }`, `OccupiedItem { kind: &'static str, id: i64, name: String, group_id: i64, group_name: String }` (`Serialize`).

**Три места, где `match` исчерпывающий** (добавлять строго во все):
- `code()` (стр. 150-165): `Self::AccessBlocked { .. } => "ACCESS_BLOCKED",` -> добавить `Self::AlreadyInGroup { .. } => "ALREADY_IN_GROUP",`
- `details_value()` (стр. 168-196): `Self::AccessBlocked{..} => json!({ "pending": pending, "rejection_reason": rejection_reason })` -> `json!({ "items": items })`
- `crates/trackly-app/src/error_axum.rs` стр. 33-46: добавить `AppError::AlreadyInGroup { .. } => StatusCode::CONFLICT,` (рядом с `Conflict`), обновить шапку-комментарий «Conflict / OptimisticLockMismatch → 409».

**Клиентский разбор** (`ui/src/lib/api/errors.ts` 1-15): `AppError.details?: Record<string, unknown>` уже есть; по образцу `AccessBlockedDetails` добавить `AlreadyInGroupDetails { items: { kind, id, name, group_id, group_name }[] }` и читать по `parseAppError(e).code === 'ALREADY_IN_GROUP'` — НЕ разбирать `message`.

**Тест формы** (образец стр. 337-346):
```rust
let v = ser(&AppError::NotFound { entity: "device", id: 42 });
assert_eq!(v["code"], "NOT_FOUND");
assert_eq!(v["details"]["id"], 42);
```
+ добавить строку в `code_for_all_variants` (стр. ~200-330).

### `crates/trackly-infra/src/repos/groups_sqlite.rs` — призраки и счётчик D-13 (repository, чтение)

**Analog:** `member_devices` (стр. 807-841) для призраков; `count_live_parts_in_tx` (стр. 317-330) для счётчика.

**Core read pattern** (копировать каркас `prepare` + `query_map` + `MemberDeviceRow`):
```rust
let mut stmt = conn.prepare(
    "SELECT d.id, COALESCE(dt.name, ''), d.name, d.inventory_number,
            d.serial_number, d.place_id, pfp.full_path, ds.name, ds.code
     FROM group_devices gd
     JOIN devices d ON d.id = gd.device_id AND d.deleted_at_utc IS NULL
     LEFT JOIN device_types dt ON dt.id = d.type_id
     LEFT JOIN device_statuses ds ON ds.id = d.status_id
     LEFT JOIN place_full_paths pfp ON pfp.place_id = d.place_id
     WHERE gd.group_id = ?1
     ORDER BY d.name, d.id",
).map_err(map_rusqlite)?;
```
Призраки: тот же SELECT, но `FROM devices d` с `WHERE d.origin_group_id = ?1 AND NOT EXISTS (SELECT 1 FROM group_devices m WHERE m.device_id = d.id AND m.group_id = ?1)`, **БЕЗ** `deleted_at_utc IS NULL` (D-14), плюс `LEFT JOIN group_devices gd ... LEFT JOIN groups cg` ради текущей группы (полный запрос — RESEARCH Pattern 3). Новый тип `GhostDeviceRow` рядом с `MemberDeviceRow`.

**Счётчик D-13** (образец `count_live_parts_in_tx`, стр. 317-330):
```rust
tx.query_row(
    "SELECT COUNT(*) FROM group_devices gd
     JOIN devices d ON d.id = gd.device_id AND d.deleted_at_utc IS NULL
     WHERE gd.group_id = ?1
       AND d.id IS NOT (SELECT anchor_device_id FROM groups WHERE id = ?1)",
    rusqlite::params![group_id], |r| r.get(0),
)
```
Новый `count_origin_ghosts_in_tx`: `SELECT COUNT(*) FROM devices WHERE origin_group_id = ?1 AND id NOT IN (SELECT device_id FROM group_devices WHERE group_id = ?1)` — без фильтра удалённых.

**Не трогать:** `set_parent_in_tx` (стр. ~407) — им пользуется `group_act_plan.rs` (994, 1008, 1234, 1505); D-09 и D-16 класть в сервис. `add_device_in_tx` (199-225) бросает `Conflict` на занятое устройство — оставить как нижний предохранитель.

### `crates/trackly-app/src/services/group_service.rs` (service, CRUD в транзакции)

**Analog:** `add_devices` (стр. 943-1081), `remove_devices` (1086-1157), `set_parent` (1168-1255), `delete_group` (772-837) — тот же файл.

**Скелет мутации** (copy: `authorize` -> `writer.execute` -> `tx` -> `deps` -> аудит -> `commit` -> `broadcast_entities` ПОСЛЕ коммита), стр. 943-961 и 1075-1080:
```rust
authorize(caller, &Action::MutateGroups)?;
let device_ids = normalize_device_ids(device_ids)?;
let now = self.clock.unix_seconds();
let user_id = caller.user_id;
let (result, added) = self.writer.execute(move |conn| {
    let tx = conn.transaction().map_err(map_rusqlite)?;
    let deps = GroupMoveDeps::new();
    let group = deps.groups.get_group_in_tx(&tx, group_id)?;
    let target_behavior = GroupBehavior::from_str_lenient(
        &type_repo.get_type(&tx, group.type_id)?.behavior);
    ...
    tx.commit().map_err(map_rusqlite)?;
    Ok((result, added))
}).await?;
self.broadcast_entities("add_devices", place_ids, device_ids, group_ids);
```

**Тело цикла `add_devices`, которое выносится в приватный `add_one_in_tx`** (стр. 969-1046): проверки «не найдено / удалено / уже в группе / `STATUS_CODE_WRITTEN_OFF` / `STATUS_CODE_TO_WRITE_OFF` (только для teardown)», `add_device_in_tx`, ветка `set_device_origin_if_null_in_tx` (стр. 1016-1019 — **удалить**: D-08), затем `apply_group_place_to_device_in_tx` с `is_repair_exempt_status_code`-охраной (1024-1046).

**D-08 (замена ветки teardown)**: вместо записи происхождения — проверка (RESEARCH «Проверка teardown-цели»): `SELECT origin_group_id FROM devices WHERE id = ?1`; если `origin != Some(group_id)` -> `device_ids_error("В разбор нельзя добавить существующее устройство: детали появляются только через «Создать деталь».")`. Хелпер `device_ids_error` — стр. 918-923.

**D-16 (отказ «уже в группе»)**: заменить `return Err(device_ids_error(format!("Устройство «{}» уже входит в группу «{}». Сначала выведите его из состава.", ...)))` (стр. 983-992) на сбор ВСЕХ занятых в `Vec<OccupiedItem>` и один `AppError::AlreadyInGroup { items }` после цикла (D-18). Флаг переноса — не в `add_devices`, а отдельный `move_devices`.

**Якорь при переносе** (копировать охрану из `remove_devices`, стр. 1110-1130):
```rust
if let Some(anchor_group) = deps.groups.anchor_group_of_device_in_tx(&tx, *device_id)? {
    if anchor_group.id == group_id { /* Validation { field:"device_ids", message: «…якорь группы…» } */ }
}
```
Перенос снимает членство через `deps.groups.remove_device_in_tx(&tx, id)` (НЕ `release_device_in_tx`: он пишет свой аудит `custom:group_member_released` и держится стражами `s11_*`), далее `add_one_in_tx` с `MoveOccupied`, ровно ОДНА запись `audit_log` (`entity_type: "group"`, `action: "move_devices"`), одно `broadcast_entities("move_devices", ...)` с id цели и всех исходных групп.

**Аудит-запись** (стр. 1050-1064, копировать форму):
```rust
deps.audit.insert(&tx, AuditEntry {
    entity_type: "group", entity_id: group_id, action: "add_devices", user_id,
    before_json: None, after_json: None,
    payload_json: Some(to_json(&serde_json::json!({ "device_ids": added }))?),
    created_at_utc: now,
})?;
```

**`set_parent` (D-09, D-16 для групп)** — стр. 1168-1255. Проверки вставлять ПЕРЕД `deps.groups.set_parent_in_tx(...)` (стр. 1186-1187), после `let before = deps.groups.get_group_in_tx(&tx, id)?;`:
- `type_repo.get_type(&tx, before.type_id)?.behavior == "teardown"` и `parent_group_id.is_some()` -> `Validation` «Группу типа «Разбор» нельзя вложить в другую группу.»;
- `before.parent_group_id.is_some() && before.parent_group_id != parent_group_id && !replace_parent` -> `AlreadyInGroup` с `kind: "group"`.
Сигнатура получает `replace_parent: bool`.

**`delete_group` (D-13)** — расширить блок `before.type_behavior == "teardown"` (стр. 794-807). Сейчас:
```rust
let parts = repo.count_live_parts_in_tx(&tx, id)?;
if parts > 0 { return Err(AppError::Validation { field: "id".to_string(),
    message: format!("Группу «{}» нельзя удалить: в ней {} {}. Сначала выведите детали из состава.",
        before.name, parts, ru_plural(parts, "деталь", "детали", "деталей")) }); }
```
Добавить `count_origin_ghosts_in_tx`; текст — UI-SPEC §15.3 (вторая часть «из них N выведены» только при N > 0, склонения через `ru_plural` из `services/plural.rs`).

**Вынос расформирования** — `delete_group` содержит `repo.delete_group_in_tx(&tx, id)?;` + аудит `delete` (стр. 808-824); для `write_off(substitute)` вынести в общую `delete_group_in_tx`+аудит, не копировать.

**Статус «Списано»:** образец подстановки статуса по `code` — `create_group` (стр. ~650-665: `SELECT id FROM device_statuses WHERE code = ?1` с `STATUS_CODE_TO_WRITE_OFF`); константы `STATUS_CODE_WRITTEN_OFF`/`STATUS_CODE_TO_WRITE_OFF` — стр. 62-63. Решения по `code`, не по подписи.

**`composition` (призраки)** — стр. 309-363: после `devices = repo.member_devices(...)...map(|d| GroupMemberDeviceDto { place_path_short: compute_place_path_short_with_conn(&conn, d.place_id, d.place_path.clone()), ... })` добавить аналогичный `ghosts` (только если `behavior == teardown`), вернуть в `GroupCompositionDto { devices, child_groups, ghosts }`.

## Shared Patterns

### Пара «серверный отказ + скрытие в UI»
**Источник:** `deviceRowMenu.ts` (шапка 1-17) + `group_service.rs`. Каждый новый запрет (D-08, D-09, D-13, D-16, D-17) делается парой: сервер отказывает (граница безопасности), UI заранее прячет. Тесты вызывают сервис напрямую, не через UI.

### Транзакционная мутация + аудит + WS после коммита
**Источник:** `group_service.rs::add_devices` (943-1081), `delete_group` (772-837).
**Применять к:** `move_devices`, `write_off`, изменённый `set_parent`.
`authorize(caller, &Action::MutateGroups)?` первой строкой -> `self.writer.execute(move |conn| { let tx = conn.transaction()...; ...; tx.commit() })` -> `self.broadcast_entities(op, place_ids, device_ids, group_ids)` ТОЛЬКО после успешного коммита (`entities_broadcast::send_entities_changed`). Одна транзакция на перенос, одна запись `audit_log` (опора фазы 41.10).

### Единый `build_*` для двух транспортов
**Источник:** `tauri_cmds/groups.rs` (стр. 155-165, 335-343) + `http/groups.rs` (291-304, 365).
**Применять к:** каждой новой команде. Тонкие адаптеры; логика только в `GroupService`. Дублирующий `authorize` в `build_*` — осознанная защита в глубину.

### Инвалидация счётчиков «Мест» в той же функции, что вызов API
**Источник:** `AddToGroupModal.svelte` стр. 90-91; `GroupContentsTable.svelte` стр. 384-385.
`notifyPlaceContentChanged(result.changed_place_ids)` сразу после `await groups.*(...)`, в той же функции; не выносить в обёртку/родителя (гейт INV-7 ищет в окружающей именованной функции).
