# Phase 41.8 Plan 21: списание участника группы через форму (сервер) Summary

Обычное обновление устройства (HTTP и Tauri) больше не переводит участника группы на «Списано» без явного выбора «оставить / вывести»; якорь через форму не списывается; выбор исполняется в одной транзакции.

## Что сделано

- `DevicePatch.group_write_off: Option<GroupWriteOffChoice>` (`keep` / `release`, serde snake_case, specta Type); в доменный патч не переносится, читается в `update` до `patch.into()`.
- `DeviceService::update`: переход на «Списано» определяется по коду статуса (эффективный == «списано», прежний != «списано»). Охрана якоря `anchor_group_of_device_in_tx(` стоит выше `repo.update_in_tx(`; участник без выбора даёт Validation с `field = group_write_off`; выбор при не-члене игнорируется.
- «Вывести»: `release_device_in_tx` после `update_in_tx` и блока D-17 (запись `custom:group_member_released`, D-29), затем перечитывается строка для снимка. Правка остаётся одной записью audit `update`.
- D-24: блок D-17 («был исключённым -> стал обычным») не срабатывает при переходе на «Списано» (`&& !to_written_off`): оставленный участник не стягивается на место группы.
- D-22: событие `update` несёт id группы (выведенной и оставленной).
- `anchor_write_off_error` в group_membership.rs; `write_off_device` переключён на него (текст прежний).

## Красные до правки (зафиксировано)

Красные: `u11_member_without_choice_is_rejected`, `u11_anchor_rejected`, `u11_release_in_one_transaction`, `u11_keep_keeps_membership_and_place` (место стянуто на место группы), `u11_http_cannot_bypass` (200 вместо 400), `u11_event_carries_group` (group_ids пуст). Зелёные и до правки (контроль): `u11_non_member_unchanged`, `u11_edit_other_field_of_written_off_member_ok`.
