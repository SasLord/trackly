# Phase 41.8 Plan 33: подменю «Статус» в DeviceRowMenu (D-35) Summary

Общее меню строки получило пункт «Статус ▸» (ActionSubmenu): выбор варианта сразу меняет статус через сервер по правилам формы, структуру обработчика держит гейт.

- cab08ac0 test: правила S1-S6 гейта и порядок пунктов в UI-SPEC

## Реализация

- Варианты строит `statusMenuOptions` (план 29): текущий отмечен (`aria-checked`), неактивные получают `aria-disabled` и `title` с причиной. Литералов подписей статусов нет.
- Номер открытой ремонтной заявки грузит `loadOpenRepairs([id])` в `prepare()`, при монтировании кебаба и при каждом открытии (`onOpenChange`); запись только из async-продолжения, устаревший ответ отбрасывается. При заявке все варианты неактивны с подписью.
- `changeStatus`: устройство захватывается до await; вердикт `writeOffChoiceNeeded` до `devices.update`; `anchor_refuse` даёт тост без запроса; `choose` открывает `WriteOffChoiceModal` (отмена выходит без запроса); `group_write_off` только из выбора; один повтор при `VALIDATION` с `details.field === 'group_write_off'`; прочие ошибки тостом с текстом сервера; флаг `changing` гасит двойной запуск.
- Успех: `notifyPlaceContentChanged` по месту до и после (возврат из исключённого статуса может перенести на место группы, D-17), тост «Статус изменён: …», `onChanged()`. Другого списка затронутых мест в `DeviceSaveOutcome` нет, берётся `place_id` из ответа.
- Пункт виден при `canChangeStatus(role)` и непустом справочнике; у принтеров по `deviceId` используется свежее `fetched` из `prepare()`.
