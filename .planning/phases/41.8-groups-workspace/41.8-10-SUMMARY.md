# Phase 41.8 Plan 10: Таблица состава как рабочее место Summary

Состав группы повторяет «Устройства»: меню и жесты DeviceRowMenu, меню вложенной группы, призраки разбора с возвратом, неактивные строки и попап «уже в группе» вместо тоста.

## Задачи
1. Строки устройств и вложенных групп: коммит 8acb15ac. DeviceRowMenu (trigger=none) + свой кебаб через openFromElement, правый клик, Enter, двойной клик; неактивность по коду «списано», tr-cell-solid на статусе и действиях; меню группы (Открыть / Вывести из группы / Переместить / Переименовать / Списать при якоре «на_списание»); «Вывести из состава» в файле больше нет; onOpenDevice убран из GroupContentsTable, GroupPanel и GroupsPage (вместе с openDevice).
2. Призраки, возврат, строка добавления разбора, origin: коммит ab8ac6b0. Разделитель «Выведенные детали · N», неактивные строки призраков (удалённый без просмотра и кебаба), меню «Вернуть в разбор», клиентский поиск по призракам без запросов к серверу, «Добавить несколько…» не рендерится в разборе, origin_group_id в обоих путях создания DeviceFormBody (правка не затронута).
3. Попап «уже в группе»: коммит f5c53617. addDevice/attachGroup различают ALREADY_IN_GROUP по коду, «Переместить» — moveDevices / setParent с replace_parent: true; группы teardown отфильтрованы из подсказок по type_behavior.

## Отклонения
- **[Rule 3] TableRow.svelte:** onToggleGroup передаёт событие (в т.ч. из шеврона), иначе охрана `detail <= 1` невозможна. Прочие потребители не затронуты.
- **[Rule 3] check-printer-identity.mjs:** GroupsPage перестал импортировать `$lib/deviceTypeIds` (вместе с openDevice), антивакуум J5 краснел; MIN_IMPORTERS 7 -> 6 (реальных импортёров 6).
- Пустой результат поиска возврата: Dropdown имеет фиксированный текст «Ничего не найдено», поэтому «Выведенных деталей нет. Новые детали добавляются кнопкой «Создать деталь».» показан подсказкой под полем.
- Призраки выводятся только для самой открытой группы разбора (разбор не вкладывается).
