## Невакуумность (мутации реального исходника, якоря уникальны, файлы восстановлены из копий)

Про `spa_fallback`: «200» ничего не доказывает, поэтому тест роли проверяет `body.as_array()`, длину 2 и подписи из ответа. В текущем дереве неизвестный `/api/` путь отдаёт JSON 404 (покрыто `unknown_api_path_answers_json_404_not_spa`), но тест от этого не зависит: любая подмена не-массивом краснит его.

- **Мутация A**, из `build_device_types_list` снят `authorize(caller, &Action::ReadData)?;` (якорь из двух строк, 1 вхождение): `device_types_role_matrix` красный, `employee → device_types_list → ожидался 403, получен 200 OK`.
- **Мутация B**, из `http/devices.rs` снята строка маршрута (1 вхождение): `device_types_role_matrix` красный, `ожидался 403, получен 404 Not Found`. В `http_route_parity` красными стали два теста: `every_tauri_command_is_reachable_over_http` («команды Tauri без HTTP-маршрута … device_types_list») и `live_router_answers_every_tauri_command_path` («живой build_router() отвечает так же, как на несуществующий путь … device_types_list»). То есть паритет покрывает новую команду без правок самого теста.
- После отката обоих: `git diff -- crates/trackly-app/src` пуст, `device_types_role_matrix` и `http_route_parity` зелёные.

Ограничение: красный-первым в классическом смысле (тест до кода) тут невозможен для маршрута, которого нет, поэтому невакуумность доказана двумя мутациями выше. Мутация «манипулировать порядком/формой ответа» не делалась: ответ строится прямо из `list_types` (план 01), его содержимое закреплено `device_types_dictionary` (6/6).

Роли: employee явно проверен на отказ (403), manager и admin на успех и содержимое. Роли без доступа сверх этих трёх в матрице стенда не заведены (в `gt_env` три cookie).
