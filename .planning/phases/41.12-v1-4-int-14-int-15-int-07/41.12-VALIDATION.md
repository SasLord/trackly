## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Rust: `cargo test` (интеграционные `crates/trackly-app/tests/*.rs`, tokio multi_thread). Структурные гейты: `ui/scripts/check-*.mjs` (zero-dependency Node, у каждого `--selftest` с мутантами по реальным файлам). Нового фреймворка не вводим. |
| **Config file** | `Cargo.toml` (workspace); `ui/package.json` (скрипт `lint`) |
| **Quick run command** | `DEVELOPER_DIR=/Library/Developer/CommandLineTools TRACKLY_AD_MOCK=1 TRACKLY_SNMP_MOCK=1 cargo test -p trackly-app --test device_types_dictionary -- --test-threads=1` · гейты: `cd ui && node scripts/check-device-type-labels.mjs --selftest && node scripts/check-device-type-labels.mjs && node scripts/check-place-tree-invalidation.mjs --selftest && node scripts/check-place-tree-invalidation.mjs && node scripts/check-place-path-short.mjs --selftest && node scripts/check-place-path-short.mjs` |
| **Full suite command** | `pnpm --dir ui lint` · `pnpm --dir ui exec svelte-check --threshold error` · `cargo fmt --all -- --check` · `cargo clippy --workspace --all-targets -- -D warnings` · затем ОДИН `cargo test --workspace --no-fail-fast -- --test-threads=1` |
| **Estimated runtime** | гейты ~20 с; `cargo test -p trackly-app` минуты; полный workspace ~80 мин (в фоне, вывод сырым в файл) |

**Общий принцип невакуумности — красный-первым.** Каждый новый тест и гейт сначала прогоняется на
ТЕКУЩЕМ (дефектном) коде и обязан быть КРАСНЫМ, затем на исправленном — зелёным. Якоря мутаций
проверены на уникальность (вхождений ровно 1); якоря новых строк проверяет `mutate()` в selftest
(`count == 1`).

## Sampling Rate

- **After every task commit:** быстрый запуск нужного Rust-теста или пары `--selftest` + основной прогон правленого гейта.
- **After every plan wave:** `pnpm --dir ui lint`, `svelte-check`, `cargo fmt --check`, `cargo clippy`, затем ПО ОДНОМУ (не параллельно): `cargo test -p trackly-app --test device_types_dictionary`, `--test devices_csv_import`, `--test devices_csv_export`, `--test device_status_vocabulary_gate`, `--test http_route_parity`, `--test devices_filter_registry`.
- **Before `/gsd-verify-work`:** один полный `cargo test --workspace --no-fail-fast -- --test-threads=1` в фоне, зелёный.
- **Max feedback latency:** ~60 с на задачу (быстрый запуск), граница волны — минуты.

## Manual-Only Verifications

Режим `human_verify_mode: end-of-phase`. Каждый пункт называет существующий компонент UI и готовит
условие, при котором дефект воспроизводим. **Внимание:** при `auto_advance` исполнители закрывают
такие чекпоинты без запуска приложения — пункты собрать и отдать пользователю ДО верификации.

| Behavior | Критерий | Why Manual | Test Instructions |
|----------|----------|------------|-------------------|
| Фильтр «Тип устройства» на странице «Отчёты», вкладка «Перемещения» | 1c | список строится в webview из команды справочника | БД с принтером: в списке «Устройство» и «Принтер», слова «Расходник» нет |
| Удаление устройства из меню строки (`DeviceRowMenu`, пункт «Удалить») на страницах «Устройства» и «Принтеры» | 3a, 3c | регрессия «счётчик места уменьшился при обычной работе» видна только в живом дереве «Места» | устройство привязано к месту с видимым счётчиком; удалить; счётчик уменьшился без обновления страницы. Обрыв сокета руками НЕ проверяется: в десктопе Tauri моста не оборвать, а «отключить сеть» в LAN-браузере рвёт и HTTP-запрос удаления. Локальный путь (живой HTTP, мёртвый WS) доказывается мутациями гейта 3a–3c в `check-place-tree-invalidation --selftest`. Необязательно: LAN-браузер, DevTools -> Network -> Request blocking, заблокировать `/api/v1/ws`, перезагрузить, удалить (если браузер WebSocket не блокирует — не дефект) |
| Удаление картриджа с местом на странице «Картриджи» | 3a, 3c | то же | то же условие и оговорка |
| Импорт CSV через `DeviceImportCsvModal` | 2 | требует файла и просмотра раздела | файл с колонкой «Тип» и одной строкой «Принтер»: запись видна в разделе «Принтеры» |
| Импорт старой выгрузки приложения (принтеры подписаны «Расходник») | D-01 | проверяет сохранённую совместимость | строка «Расходник» по-прежнему создаёт принтер, а не «Устройство» |
