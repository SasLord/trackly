## Фикстуры: как проверена кодировка

- `utf8.csv`, `utf8_bom.csv`, `malformed_mixed_rows.csv`: заменена ровно одна строка (python, `bytes.replace` с проверкой ровно одного вхождения), остальные байты не тронуты. BOM цел: `head -c 3 utf8_bom.csv | xxd -p` -> `efbbbf`; `utf8_bom.csv == EF BB BF + utf8.csv` (проверено побайтово, True).
- `cp1251_comma.csv`, `cp1251_semicolon.csv` регенерированы по рецепту из `fixtures/devices/README.md` из исправленного `utf8.csv` (`str.encode('cp1251')`, `;` подставляется до кодирования), руками не правились.
- Проверка кодировки (команда `file` бесполезна: для обоих файлов говорит «CSV text» / «ISO-8859 text»): (1) `.decode('utf-8')` обоих файлов бросает `UnicodeDecodeError`, т.е. это не UTF-8; (2) `.decode('cp1251') == utf8.csv.decode()` -> True; (3) `iconv -f CP1251 -t UTF-8 | grep -c "Расходник"` -> `0` для обоих, `grep -c "Принтер,МФУ Пример"` для comma-файла -> `1`, последняя строка semicolon-файла: `Принтер;МФУ Пример;;;;Кладовая;На складе`.
- `git diff --stat -- fixtures`: по 1 вставке / 1 удалению в каждом из пяти файлов.
- `devices_filter_registry.rs`: «Расходник Дельта» -> «Принтер Дельта» (строка Seed и комментарий у `D`); имя не использовалось как ключ фильтра (grep).
