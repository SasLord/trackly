# Phase 40.5 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Источник: `40.5-RESEARCH.md § Validation Architecture`. Решения: `40.5-CONTEXT.md` (D-01..D-16).

**Главный риск этой фазы — не «код не работает», а «тесты починены так, что перестали что-либо
доказывать».** ~38 утверждений в 7 файлах закреплены за отменяемым правилом; механическая замена
«Nв» → «Nв1» проходит зелёным, ничего не проверяя. Всё ниже устроено вокруг этого риска.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `cargo test` (встроенный Rust harness); `nextest` в проекте не используется |
| **Config file** | нет отдельного — workspace `Cargo.toml` + `crates/trackly-app/tests/*.rs` + inline `#[cfg(test)]` |
| **Quick run command** | `cargo test -p trackly-app --test <затронутый_файл>` |
| **Full suite command** | `cargo test --workspace --no-fail-fast -- --test-threads=1` |
| **Estimated runtime** | быстрый — секунды/десятки секунд; полный — **~80 минут** |

**Требования окружения** (память `ci_test_requirements`): пакет `trackly-app` требует
`TRACKLY_AD_MOCK` / `TRACKLY_SNMP_MOCK` и собранный `ui/dist` (`pnpm --dir ui build`). Фаза UI
не меняет, но полный прогон на границе всё равно требует свежего `ui/dist`.

**Новых test target'ов не создаётся** — все затронутые тесты уже существуют как integration-тесты
в `crates/trackly-app/tests/`; новые тест-функции добавляются в ТЕ ЖЕ файлы.

**Известная помеха** (память `workspace_test_hangs_auth_remember_cookie`): пред-существующее
зависание `login_remember_persistent_cookie`. Полный прогон запускать с `--skip` для него, иначе
80 минут превратятся в бесконечность.

## Sampling Rate

- **После каждого коммита задачи:** `cargo test -p trackly-app --test <затронутый_файл>` (секунды).
- **После каждой волны:** `cargo test -p trackly-app` (весь пакет — ловит межтестовые эффекты).
- **Граница фазы:** ОДИН `cargo test --workspace --no-fail-fast -- --test-threads=1`, в фоне,
  запускается в начале волны-границы (D-13).
- **Никогда:** два `cargo test` одновременно (память `cargo_no_concurrent_test`).
- **Печать и визуал:** вне cargo test — только Human-UAT (см. ниже).
- **Max feedback latency:** внутри волны — секунды; на границе — один фоновый прогон.

## Per-Task Verification Map

*Заполняется планировщиком: одна строка на задачу каждого PLAN.md. Ниже — контракт уровня фазы,
к которому задачи обязаны привязаться.*

| Success Criterion (ROADMAP) | Доказывается | Тип | Автоматическая команда | Инфраструктура |
|---|---|---|---|---|
| **1.** Суффикс стабилен; безцифровой «Nв» исчез со ВСЕХ поверхностей | `format_act_number` даёт «в{sub}» независимо от числа соседей; ни одна read-поверхность не производит «Nв» | unit + integration | `cargo test -p trackly-app --lib dto::act::tests` + `--test acts_display_rule --test acts_numbering --test place_movements_timeline --test report_movements --test html_act_render --test acts_returns --test acts_clone_handover` | ✅ есть (инвертировать) |
| **2.** Плотная нумерация, несколько дырок, порядок заполнения | {в1,в2,в3} → удалить в1 и в3 → следующий получает 1, за ним 3 | unit (алгоритм) + integration (через `do_return` + `delete_soft`) | `cargo test -p trackly-infra` + `cargo test -p trackly-app --test acts_returns` | ❌ **Wave 0** — сценарий с двумя дырками не покрыт |
| **3.** Существующие акты не перенумеровываются | после `delete_soft` соседа номер оставшегося возврата не изменился | integration | `cargo test -p trackly-app --test acts_returns` | ❌ **Wave 0** |
| **4.** `sibling_return_count` удалён структурно | сборка без поля/параметра; грепа нет | grep-гейт (не cargo test) | `grep -rn sibling_return_count crates --include=*.rs \| grep -v target` → **пусто** (либо ровно одно явно задокументированное исключение с названной причиной, D-03) | N/A |
| **5.** F7 снят с причины | нет `display.find('в')`; литеральная «в» в маске номера до цифр не ломает суффикс | unit + grep-гейт | `grep -n "find('в')" crates/trackly-app/src/services/act_service.rs` → **пусто** + новый unit-тест на номер вида `АКТв-2026/09-1` | ❌ **Wave 0** |
| **6.** Уникальность пересмотрена по смыслу | handover «42в1» конфликтует с живым возвратом «42в1»; «42в» больше не конфликтует, потому что такого отображения не существует | integration | `cargo test -p trackly-app --test acts_numbering` | ✅ есть, требует пересмотра ассертов ПО СМЫСЛУ (D-09) |

**Дополнительный гейт, не привязанный к критерию:** после удаления коррелированного подзапроса из
`SELECT_ACTS` позиционные `row.get(N)` в `from_row` сдвигаются (D-16). Это молчаливая ошибка:
компилируется, типы совпадают, значения разъезжаются. Требуется явная проверка соответствия
колонок — как минимум тест, читающий акт с непустыми `handover_date_utc` и `place_path_snapshot`
и сверяющий их значения.

## Anti-Vacuous Anchor (обязательное условие приёмки)

Фаза НЕ может быть закрыта, пока не предъявлен тест, который:

1. **Падает на СТАРОЙ формуле** и проходит на новой — расхождение до/после фикса должно быть
   продемонстрировано, а не заявлено (память `vacuous_test_fixture_must_diverge`).
2. **Имеет уникальный якорь мутации** — если проверка снимается заменой в одном месте, эта замена
   не должна попадать в соседнюю функцию (память `mutation_test_anchor_must_be_unique`).

Готовые кандидаты уже есть в коде и документируют ровно тот дефект, который убирается:
- `format_retroactive_promotion` — в ДВУХ файлах (`dto/act.rs`, `acts_display_rule.rs`);
- `second_partial_return_assigns_sub_number_2_and_promotes_suffix` (`acts_returns.rs`);
- блок `ends_with('в') && !ends_with("в1")` в `acts_clone_handover.rs` (~590-598).

Их следует **инвертировать с сохранением намерения и переименовать**, а не удалить: удалённый
тест — это снятый гейт, и «зелено» после него ничего не значит.

## Wave 0 Requirements

- [ ] `crates/trackly-app/tests/acts_returns.rs` — «две дырки, порядок заполнения»: создать 3
      возврата (sub 1,2,3) → `delete_soft` 1 и 3 → новый возврат получает **1**, следующий — **3**.

      путается с суффиксом возврата. Сегодня не покрыт ничем.
- [ ] Правка-инверсия существующих якорей (см. «Anti-Vacuous Anchor») — 4 места.
- [ ] `acts_numbering.rs` — пересборка сценариев конфликта на «42в1» с живым возвратом; замена

## Manual-Only Verifications

| Behavior | Критерий | Почему вручную | Инструкция |
|---|---|---|---|
| Печать акта с одним возвратом «…в1» | 1 | Тесты извлечения текста не видят перенос/наложение | Предпросмотр печати на десктопе (`cargo tauri dev`) **и** в LAN-браузере после `pnpm --dir ui build` (память `dev_browser_testing_needs_ui_build`, `lan_print_dom_leakage`) |
| Печать с длинным суффиксом («в12» при двузначном родителе) | 1 | То же; проверяется визуальное переполнение | Два места в `act_handover.html`, где печатается `act.number_display`: `.subtitle` и `.appendix-mark` |
| Пользовательский сценарий приёмки | 2, 3 | Сквозной путь через UI, а не через сервис | Создать 2 возврата (в1, в2) → удалить в1 → создать новый → он получил **в1**, а не в3; исходный в2 в списке не изменился |
| Попап «Номер занят» | 6 | Текст попапа и то, какую запись он называет | Попытаться создать/переименовать акт в «42в1», когда у акта «42» есть живой возврат с таким отображением; попап должен называть именно эту запись (не «42в» — такого отображения больше нет) |
| Превью шаблона номера | 1 | Отдельная поверхность чтения номера | Настройки → шаблоны номеров → тип «Акты»: занятые номера показываются как «…в1»/«…в2», а не «…в» |

**Замечание о процессе** (память `auto_advance_auto_approves_human_verify`): `auto_advance` в
конфиге включён, и исполнители имеют привычку закрывать human-verify чекпоинты, не запуская
приложение. Пункты этой таблицы должны дойти до пользователя как чеклист ДО объявления фазы
проверенной, а не быть отмечены агентом.

## Security Domain

`security_enforcement: true`, ASVS L1. Фаза меняет внутреннюю формулу форматирования и SQL
выделения номера — новых точек входа, аутентификации и авторизации не добавляет.

| ASVS | Применимо | Контроль |
|---|---|---|
| V2 Authentication | нет | `do_return`/`create`/`update` уже за существующей `Identity`-проверкой; фаза её не трогает |
| V3 Session | нет | — |
| V4 Access Control | нет | Ролевая матрица `Action::*` не меняется |
| V5 Input Validation | частично | Проверка занятости номера — единственный затронутый пользовательский input-путь; D-09 меняет смысл конфликта, не снимает проверку. Остаётся через `validate_number_value` + trim/case-insensitive |
| V6 Cryptography | нет | — |

| Угроза | STRIDE | Митигация |
|---|---|---|
| Гонка двух `do_return` одного родителя выдаёт одинаковый `sub_number` | Tampering (целостность) | Существующие single-writer + `BEGIN IMMEDIATE` + уникальный индекс `idx_acts_number_sub_unique` (`migrations/V042__acts_number_text.sql`) — структурный backstop уже есть, нового не требуется (D-07) |
| Переиспользованный номер: печатный «в1» и будущий «в1» — разные документы | Repudiation (продуктовый риск, не уязвимость) | Принято пользователем осознанно (D-06). В UAT — как подтверждение понимания, НЕ как дефект |
