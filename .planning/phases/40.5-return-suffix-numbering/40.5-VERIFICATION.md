# Phase 40.5: Return Suffix Numbering — Verification Report

Отображаемый номер не зависит от изменчивого состояния соседей.

### Gap 1 — акт становится невозвратимым навсегда (WR-02)

Проверено по коду:
- `next_sub_number_for_parent` (`acts_sqlite.rs`) запрашивает `sub_number` только у `acts WHERE parent_act_id = ?1 AND deleted_at_utc IS NULL`. О чужих актах с номером «{parent}в{k}» он не знает.
- `do_return` (`act_service.rs:~1513`) берёт этот `sub_number`, вставляет строку и тут же вызывает `ensure_act_family_display_free_in_tx(&tx, act_id)` (`:~1571`). При коллизии возвращается `AppError::Conflict`, транзакция откатывается, повторной попытки со следующим sub нет.
- Так как аллокатор детерминирован и состояние возвратов не меняется (откат), следующий вызов даст тот же `sub=1` и тот же `Conflict`. Блокировка постоянна.
- Предпосылка достижима: handover «42в1» создаётся молча, пока у #42 нет возвратов (часть A теста `display_number_space_covers_returns_in_both_directions`, `acts_numbering.rs:~466-494`, именно это и делает и подтверждает `Conflict` на первом возврате).
- Регрессия относительно базы: при `MAX+1` первый возврат показывался как «42в» и не конфликтовал.
- Сообщение об ошибке называет только собственный номер («Акт №42в1 уже существует»), не блокирующий акт; в UI признака состояния «невозвратим» нет. Фикс пользователю недоступен из сценария возврата.
- Тест фиксирует отказ первого возврата, но не проверяет ни постоянство, ни выход.
- Не совпадает с бэклогом 999.2 (превентивное предупреждение на маске): даже при предупреждении выхода со стороны возврата нет.

Предлагаемое исправление: пропускать позиции k, у которых «{parent}в{k}» занято чужим живым актом (D-05/D-06 не нарушаются — пропуск только при реальной занятости), плюс тест «после конфликта возврат возможен»; минимум — назвать блокирующий акт в сообщении.

### Gap 2 — невыполненный пункт CONTEXT (WR-05)

Проверено по коду:
- `report_service.rs:1302-1305` — SQL отчёта «Акты»: `CAST(a.number AS TEXT) as number`, `CAST(a.sub_number AS TEXT) as sub_number`; `format_act_number` в отчёте не вызывается. Возврат: «Номер = 42», «Суб-номер = 1».
- UI: `ReportsPage.svelte:172` выводит `{ key: 'sub_number', label: 'Суб-номер' }`; `ReportTable.svelte:18` — тип. Другой логики суффикса в `ui/src` нет.
- `git diff --stat c7f5726e..HEAD -- ui` пуст: `ui/` не менялся, ни в одном SUMMARY проверка не упомянута.
- После D-01 это единственная поверхность, где акт возврата отображается как «42» (таймлайн и «Перемещения» закрыты ранее).

Предлагаемое исправление: считать display в Rust через `format_act_number` и отдавать его в колонке «Номер» (данные `a.act_type`, `a.sub_number`, `parent.number` доступны self-join'ом), либо письменно зафиксировать «сырые» колонки и переименовать колонку в UI; добавить тест.
