**Gathered:** 2026-10-18
**Status:** Ready for planning

## Phase Boundary

Фаза закрывает технический долг, принятый при закрытии Фазы 41.1: приводит три сторожевых
гейта к тому, что они заявляют, расширяет охват ещё четырёх, починивает обновление строки
ребёнка в раскрытой свёртке и закрывает один процессный пункт (сплошной прогон) и один
пункт человеческого чек-листа.

Пользовательских симптомов у большинства пунктов нет — закрывается **охват стражей**, чтобы
будущие правки токенов, инвалидации, фильтров и состава не проходили зелёными.

**Новых продуктовых возможностей фаза не вводит.** Единственное видимое пользователю
изменение, кроме свежести строки ребёнка — обводка у приглушённых чипов статуса (следствие
решения по CR-01, не самостоятельная фича).

### В объёме

- **CR-02** — устаревшая строка ребёнка раскрытой свёртки после правки поля вне ключа
  группировки.
- **CR-01 / AR-26** — `check-contrast.mjs` R1 меряет контраст не на том фоне.
- **AR-24** — `check-place-tree-invalidation.mjs` слеп к мутанту `notifyPlaceContentChanged([])`.
- **AR-23** — пункт человеческого чек-листа на неатомарность D-35 + живое прохождение.
- **AR-25** — один сплошной прогон `fmt → clippy → test --workspace` с сохранением сырого вывода.
- **WR-02** — `list`/`list_all` молча игнорируют `place_id`, `state`, `name_prefix`.
- **WR-05** — у правила [H] нет замороженной до-фиксовой фикстуры.
- **WR-06** — [D1] не проверяет полярность условия.
- **WR-07** — инвентарь [F5] пропускает `<Badge>` без слова `tone` в теге.
- **WR-08** — [G] не связывает подлежащее `{#each}` с результатом `visibleChildren`.
- **WR-09** — `EXPORT_MAX_ROWS` без сервисного теста + окно молчаливого усечения между
  COUNT и SELECT.

### Вне объёма

- **WR-01** — **уже закрыт** коммитом `4d2cb91f` (проверено по коду до начала фазы, см.

## Implementation Decisions

### WR-02 — фильтры `place_id` / `state` / `name_prefix`

- **D-01:** Реализовать **все три** предиката в `list` и `list_all` (вариант «явно отвергать»
  отклонён). `name_prefix` в `list`/`list_all` закрывает заодно pre-existing gap Фазы 18,
  задокументированный в `dto/device.rs:312-315`.
- **D-02:** Семантика `place_id` — **поддерево**, по уже зафиксированному проектом решению
  **D-28** (`report_service.rs:1286`: «choosing a place captures it and every place nested
  under it»). `WITH RECURSIVE subtree(id)` с отсечением `deleted_at_utc IS NULL`, как в
  отчётах. Ре-решать эту семантику планировщику не нужно — расхождение `list` с отчётами
  недопустимо.
- **D-03:** Семантика `name_prefix` — **тот же FTS5-поиск по четырём полям**
  (наименование / инвентарный № / серийный № / модель), что в `list_grouped`. Одно поле —
  одно поведение во всех трёх путях; выгрузка CSV совпадает с тем, что видно на экране.
  Поле **не переименовывается** (вариант с `search` отклонён как слишком широкий диф).
- **D-04:** Семантика `state` (= `d.condition`, свободный текст) — **нормализованное
  равенство** (TRIM + без учёта регистра), а не точное. Прощает «Б/У» против «б/у» как во
  вводе пользователя, так и в самой БД.
- **D-05:** Нормализация `state` живёт в **своей скалярной функции SQLite** (рабочее имя
  `tr_norm`), регистрируемой на каждом соединении **в той же точке, где ставятся PRAGMA** —
  иначе чтения из reader-пула упадут на незнакомой функции. Предикат вида
  `tr_norm(d.condition) = tr_norm(?)`. Варианты «нормализованная колонка» (миграция с
  перестройкой таблицы) и «нормализация только в Rust» отклонены. Индекс по `condition` при
  этом не используется — на наших объёмах приемлемо, отметить в комментарии.
- **D-06:** Предикат **общий для `count_list_rows` и `select_list_rows`** — как уже сделано
  для флагов якорей (`LIST_FLAG_PREDICATES`), иначе `total` разойдётся с числом строк.
- **D-07:** Текст ошибки переполнения экспорта — **убрать пример**: «Сузьте выборку
  фильтрами.» вместо «Сузьте выборку (например, выберите статус).» Текст перестаёт стареть
  при каждом изменении набора сужающих полей и согласуется с баннером отчётов.
- **D-08:** Страж на корень WR-02 — **сервисный тест-реестр**: тест перечисляет ВСЕ поля
  `DeviceFilter` и для каждого даёт вердикт «сужает» (с позитивным И негативным кейсом по
  реальным данным) либо «осознанно игнорируется» (с обоснованием). **Новое поле без вердикта
  даёт красный.** Покрывает `list`, `list_all` и `list_grouped`. Варианты «только тесты на три
  поля» и «гейт-скрипт по исходнику» отклонены: счётный гейт по исходнику не видит, работает
  ли предикат на данных.

### CR-02 — свежесть строки ребёнка в свёртке

- **D-09:** Номер поколения растёт на **любом успешном** `refresh()` — правка, удаление,
  действие из меню, смена фильтра, WS-инвалидация. Ровно то, что уже делает
  `reloadExpandedAnchors()`: одно правило на два кеша, нечего рассинхронизировать. Вариант
  «только после мутаций» отклонён (второй вид refresh + вопрос «а WS — это мутация?»).
- **D-10:** Во время перечитывания на экране остаются **старые строки** до прихода новых;
  ушедший ребёнок отсекается `visibleChildren` сразу. Без мигания «Загрузка…» — как у якорей
  сейчас. Правленое поле обновляется с задержкой одного запроса.
- **D-11:** `loadedKey = null` из `handleEdit` и `handleDelete` **убрать**. Номер поколения
  становится единственным владельцем инвалидации: двух механизмов нет, гонки с сохранением
  нет. Комментарий над `handleEdit` переписать под новую правду (сейчас он утверждает
  обратное — это зафиксированный Warning в `41.1-VERIFICATION.md`).
- **D-12:** Правило **[G] объединяется с WR-08** в одно правило с тремя утверждениями:
  (а) ключ кеша детей содержит номер поколения; (б) в `handleEdit`/`handleDelete` нет второго
  пути инвалидации; (в) подлежащее `{#each}` — именно результат `visibleChildren(...)`, а не
  `children`. Три мутанта в selftest. Один файл, один парсер — дешевле, чем два правила.
- **D-13:** Кеш якоря (`anchorMembers` в `DevicesPage`) **трогать не нужно** — `refresh()`
  безусловно зовёт `reloadExpandedAnchors()`, дефекта CR-02 у якорей нет (проверено, см.
  `<code_context>`).

### CR-01 / AR-26 — контраст на композите

- **D-14:** Альфа-бленд **написать** — существующего в проекте нет (см. `<code_context>`).
  Композитить `*-muted-soft` / `*-soft` поверх каждого из четырёх фонов `BG_4`, в обеих темах.
- **D-15:** R1 **сводится к «не ниже 4.5 на композите»**; требование порядка
  (muted тише active) снимается. Причина: на композите порядок, по данным CR-01,
  инвертируется, а окно светлой warning-пары шириной ≈0.21 (`check-contrast.mjs:40-44`) не
  даёт поднять `MIN_CONTRAST_GAP`, не трогая токены.
- **D-16:** Различие внутри пары несёт **нецветовой признак** — **обводка (1px) у
  приглушённых** soft-чипов. Токены `*-muted-text` / `*-muted-soft` из Фазы 41.1 остаются на
  месте, подложка остаётся, добавляется класс в `Badge` и токен цвета рамки в обеих темах.
  Вариант «точка вместо подложки» (`appearance: 'dot'`) отклонён: он осиротил бы токены 41.1 и
  потребовал переписать R1/R2 с нуля.
- **D-17:** R2 (потолок альфы `MAX_ALPHA_RATIO = 0.65`) **остаётся** — это второй, уже
  работающий носитель различия.
- **D-18:** Независимая мотивация D-16 — WCAG 1.4.1: сегодня «на ремонте» и «в ремонте»
  (как и «на списание» / «списано») различаются **только оттенком**.

### Охват гейтов — WR-05…WR-09, AR-24

- **D-19:** В фазу входят **все четыре** оставшихся WR. Порядок по реальному риску, от
  худшего:
  1. **WR-09** — единственный дефект данных, а не слепота стража.
  2. **WR-06** — полярность [D1]: снятие охраны автостатуса склада при создании проходит зелёным.
  3. **WR-07** — занижение инвентаря [F5] (знакомый проекту класс).
  4. **WR-05** — вакуумность [H]: мутанты бьют по синтетической `CLEAN_PAGE`, боевая форма не доказана.
- **D-20:** WR-09 закрывается **одним снимком** для COUNT и SELECT
  (`unchecked_transaction`), **плюс** «пояс и подтяжки» — `LIMIT max_rows + 1` с проверкой
  `rows.len() > max_rows`, **плюс** сервисный тест на `AppError::Validation { field: "export" }`
  без 50 000 вставок (параметризовать потолок, а не константу жёстко).
- **D-21:** WR-06 — проверять **подвыражение целиком**, не присутствие имён; два мутанта на
  полярность (`(isEdit || storageIntent)` и `!membershipLoaded`) в фикстуры.
- **D-22:** WR-07 — «Badge статуса» определяется **от файла-импортёра** и от переменной,
  объявленной как `$derived(statusTone(...))` с произвольным именем; [F5] краснеет на любом
  `<Badge>` в файле-импортёре, не попавшем ни в одну категорию. Порог `MIN_STATUS_BADGES`
  перестаёт быть единственным носителем охвата.
- **D-23:** WR-05 — заморозить `DevicesPage.pre-fix.svelte.txt` (версия до плана 29) по
  образцу `DeviceGroupRow.pre-fix.svelte.txt`: до-фиксовая копия обязана дать H1/H2/H5,
  боевой файл — быть чистым, плюс защита от подмены («в замороженной копии не должно быть
  `refreshSeq`»).
- **D-24:** AR-24 — гейт проверяет, что аргумент `notifyPlaceContentChanged(...)` — **параметр
  обработчика, а не литерал `[]`**; мутант «аргумент заменён на `[]`» в selftest (сегодня это
  blind spot №4, признанный самим файлом гейта).

### Правило всей фазы — доказать непустоту

- **D-25:** **Любая** правка гейта в этой фазе сдаётся с доказательством непустоты:
  (а) мутант по **реальному** исходнику (не по синтетической фикстуре) краснеет;
  (б) **прежняя** версия гейта на том же мутанте зелёная — иначе правка ничего не добавила.
  Это та самая ошибка, которая и породила весь долг фазы 41.1; правило распространяется и на
  те гейты, где находка его явно не называет.
- **D-26:** Якорь мутационной проверки обязан быть **уникальным** в файле — `replace(…, 1)`
  по неуникальному паттерну снимает гейт у соседней функции и даёт ложно-зелёный результат.

### Процессные пункты

- **D-27:** **AR-23** — живая проверка в **режиме сервера по LAN**: включить встроенный
  сервер, открыть в браузере, остановить сервер между созданием детали и добавлением в
  состав. Код не трогаем (вариант «dev-инъекция сбоя» отклонён — новый код в продукте ради
  проверки; «сервисный тест вместо живой» отклонён — критерий успеха №4 требует живого
  прохождения). **Перед проверкой обязательна сборка `pnpm --dir ui build`** — LAN-браузеру
  отдаётся `ui/dist`, а не HMR-бандл.
  Пункт чек-листа: «остановить сервер между созданием детали и добавлением в состав → тост
  называет устройство, устройство осталось в месте, счётчик верен».
- **D-28:** **AR-25** — один прогон, **повторяющий `ci-full` командой в команду**:
  `cargo fmt --check` → `cargo clippy -D warnings` → `cargo test --workspace --no-fail-fast
  -- --test-threads=1` ([ci-full.yml:116](.github/workflows/ci-full.yml:116)), одной
  непрерывной командой **в фоне**, timeout до 2 ч, **сырой вывод целиком в файл вне
  репозитория** (scratchpad), выжимка в SUMMARY. Базовый прогон до правок не делаем. Повтор
  команды CI исключает расхождение «локально зелено, в CI красно».

### Established Patterns

- **Один источник правды, не «пояс и подтяжки» в состоянии UI** — D-11 убирает второй путь
  инвалидации вместо того, чтобы его сохранить.
- **Пояс и подтяжки допустимы на границе данных** — D-20 намеренно держит и снимок, и
  `max_rows + 1`: цена ошибки здесь — молчаливо усечённая выгрузка.
- **Гейт обязан быть не вакуумным** — доказывается мутантом по реальному исходнику, а не
  зелёным HEAD (D-25). Якорь мутации обязан быть уникальным (D-26).
- **Счётный гейт по именам занижает инвентарь** — охват строится **от репозитория**, а не
  порогом; освобождения кодируются вердиктом (D-08, D-22).
- **Гейт по исходнику слеп к порядку и к данным** — реальная проверка идёт тестом (D-08).
- **`svelte-check` / `pnpm build` не видят рантайм-ошибок рун** — CR-02 проверяется в
  работающем приложении, а не компиляцией.
- **`pnpm lint` НЕ включает `svelte-check`**; `clippy` и `fmt` — тоже отдельные команды.
  Исполнитель обязан прогнать каждую, а не одну за все.
- **Миграций фаза не вводит** (D-05 отказался от колонки) — ловушка «FK OFF не работает в
  refinery-транзакции» в этой фазе не возникает.
