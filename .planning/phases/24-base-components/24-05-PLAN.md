<objective>
Extend `Badge.svelte`'s API backward-compatibly per D-08, corrected per checker feedback (see revision note
below): add an OPT-IN `appearance: 'soft' | 'solid' | 'dot' | 'count'` prop. When a call-site does not pass
`appearance` (true for all 21 current call-sites), Badge renders through the exact CURRENT per-tone CSS of
`Badge.svelte`, verbatim — including `variant="accent"` as SOLID (`background: var(--tr-accent); color:
var(--tr-on-accent)`), `variant="default"` text as `var(--tr-text-primary)`, and `variant="success"` /
`"warning"` / `"destructive"` keeping their existing `color-mix(...)` soft look. Only when `appearance` is
explicitly passed (by the new showcase section) does Badge render the full 5-tone x 4-appearance matrix from
`Badges.dc.html`. Keep the existing `variant` prop name and its 5 values (`default`/`accent`/`success`/
`warning`/`destructive`) completely untouched, so none of the 21 real `<Badge>` render call-sites in `ui/src`
need to change. Internally map `variant` to the reference's 5 tone names (`default -> neutral`, `destructive
-> danger`, others pass through) for the opt-in matrix path only. Then build the "Бейджи" showcase section.

**Revision note (why the default path changed from the original plan):** D-08's context text describes the
default as "soft = current visual." Direct inspection of `Badge.svelte` proves that is factually false for two
tones: `variant="accent"` is currently SOLID, not soft, and is resolved dynamically to `'accent'` on 6 live
screens (CartridgeListRow, CartridgeDetail, RequestListRow, RequestDetail, DeviceGroupRow, DeviceListRow) — a
uniform soft formula would visibly regress all six. `variant="default"` currently uses
`var(--tr-text-primary)`; the soft formula would use `var(--tr-text-secondary)`, drifting the most
call-site-dense tone. Per D-08's actual priority ("безопасность обратной совместимости важнее чистоты API"),
this plan makes the default/no-`appearance` render path reproduce the current file's per-tone CSS verbatim
instead of forcing every tone through the uniform soft formula. The 5-tone x 4-appearance soft/solid/dot/count
matrix from `Badges.dc.html` remains fully available — it is simply opt-in via an explicit `appearance` prop,
which only the showcase (Task 2) passes.

Purpose: Badge is the single most call-site-dense primitive in this phase (21 usages across acts, requests,
printers, cartridges, devices, reports) — the backward-compat contract is the hard constraint that makes this
plan riskier than a pure new-component build.
Output: Extended `Badge.svelte`; new `BadgeSection.svelte`.
</objective>
