<objective>
Close 24-REVIEW.md's two BLOCKER findings (CR-01, CR-02) plus WR-02, all three living in `Modal.svelte`'s
focus-management code added by plan 24-10:

- **CR-01** — `handleKeydown` (Escape) is wired to both `<svelte:window>` and the `.modal-backdrop` div. Since
  24-10 made initial focus land *inside* the dialog on every open, keydown bubbling now deterministically
  reaches both listeners on every Escape press, so `onClose()` fires twice for all ~25 Modal consumers.
  Non-idempotent consumers (`DeviceImportCsvModal.svelte:201`'s `handleClose`) double-execute their close logic.
- **CR-02** — `TRAP_FOCUSABLE_SELECTOR` omits `iframe`, so `PdfPreviewModal.svelte`'s `<iframe>` (act/document
  print preview — a core app workflow) is excluded from the Tab-cycle: `last` becomes the footer's last button,
  and Tab from there wraps back to `first` instead of ever reaching the iframe. Related root cause: dropdowns
  moved by `use:portal` into `document.body` (LocationAutocomplete, PersonAutocomplete — used inside
  OperationModal/ReturnModal/DocumentAcceptanceModal/PrinterCreateModal and others) are physical siblings of
  the modal backdrop, not descendants of `dialogEl`, so they are invisible to both `trapTab`'s node query AND
  its `onkeydown` listener (which was attached to `.modal-container`, a DOM subtree the portaled node no
  longer belongs to).
- **WR-02** — the initial-focus selector (`FOCUSABLE_SELECTOR`) has no `:not([disabled])` exclusion and no
  visibility filter, unlike the trap's separate `TRAP_FOCUSABLE_SELECTOR`. When the first DOM match is disabled
  or hidden, `first.focus()` silently no-ops but the `else { dialogEl?.focus() }` branch never runs (because
  `first` was truthy), so focus stays on the page behind the backdrop — exactly the bug 24-10 was meant to fix.

Note on 24-REVIEW.md's CR-02 text: it also names
`ui/src/features/settings/TemplateEditor.svelte:267`'s iframe as affected. That iframe is NOT inside this
file's `<Modal>` (the only `<Modal>` in `TemplateEditor.svelte` is the "Сбросить шаблон?" confirmation dialog,
which contains no iframe) — it renders directly on the settings page. This plan does not target it; the real,
verifiable production consequence of CR-02 is `PdfPreviewModal.svelte`'s iframe.

Purpose: Restore the CMP-05 Modal contract (single onClose per close, complete Tab-trap, reliable initial
focus) that 24-10 partially delivered but also partially broke/left incomplete.
Output: `Modal.svelte` with one keydown source of truth and a portal-aware, iframe-inclusive focus trap;
`portal.ts` tagging every teleported node so any current or future `use:portal` consumer is automatically
visible to whichever Modal happens to be open around it.
</objective>
