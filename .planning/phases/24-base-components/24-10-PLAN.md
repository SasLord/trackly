here right after the three BLOCKER gaps per gap-closure scope guidance): `Modal.svelte` declares
`role="dialog" aria-modal="true"` but implements none of the three WAI-ARIA Dialog Pattern behaviors — no
initial focus on open, no focus trap (Tab/Shift+Tab freely escape into the backdrop-covered page content), and
no focus restoration to the triggering element on close. Modal is reused across every form in the app, so this
gap compounds through phases 25-30 as more forms adopt it.

Purpose: Prevent keyboard/screen-reader users from "falling through" the modal into inert background content,
and from losing their place in the page after closing a modal.
Output: `Modal.svelte` with initial focus, a Tab-cycle trap scoped to its own focusable descendants, and
focus restoration on close.
</objective>

    Add an `$effect` block (placed after the existing state declarations, before `handleKeydown`) that: returns

    Add a `trapTab(e: KeyboardEvent)` function: returns immediately if `e.key !== 'Tab'` or `!dialogEl`;
    otherwise collects all elements inside `dialogEl` matching
    `'button:not([disabled]), [href], input:not([disabled]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])'`

    empty; otherwise, if `e.shiftKey` and `document.activeElement === nodes[0]`, calls `e.preventDefault()` and
    focuses the last node; if not `e.shiftKey` and `document.activeElement === nodes[nodes.length - 1]`, calls
    `e.preventDefault()` and focuses the first node.

    On the `.modal-container` div (currently just `<div class="modal-container modal-{size}">`, line 52), add
    `bind:this={dialogEl}`, `tabindex="-1"`, and `onkeydown={trapTab}` — this scopes the trap to the container
