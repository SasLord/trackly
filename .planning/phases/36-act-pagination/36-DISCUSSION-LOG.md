## Форма «Приложения №1»

### Структура таблицы при семи полях описания

| Option | Description | Selected |
|--------|-------------|----------|
| Двухуровневая строка | Основная строка с узкими колонками + подстрока во всю ширину с Комплектация/Тех. характеристики; лист портретный, `@page` не трогается | ✓ |

### Пустые значения

| Option | Description | Selected |
|--------|-------------|----------|

### Оформление таблицы

| Option | Description | Selected |
|--------|-------------|----------|
| Полная сетка, 10pt | Рамки у всех ячеек, шапка жирным по центру | |

### Страховка на случай, если фон не напечатается

| Option | Description | Selected |
|--------|-------------|----------|
| Зебра + волосяная линия | Зебра (~#f2f2f2, `print-color-adjust: exact`) плюс тонкая светло-серая линия между устройствами и под шапкой | ✓ |

## Порог и запасные пути

### Порог включения приложения

| Option | Description | Selected |
|--------|-------------|----------|
| Строго N > 1 | Два устройства — уже приложение; дословно соответствует DOC-10/DOC-11 | ✓ |
| Порог выше (например, от 3) | Экономит бумагу; цена — три формы акта вместо двух и расхождение с текстом требования | |
| По фактической высоте | Ветвление по тому, влезло ли на лист; требует измерения в рантайме и повторного прогона Paged.js | |

**User's choice:** Строго N > 1 → D-13

### Одно устройство не влезло в лист

| Option | Description | Selected |
|--------|-------------|----------|
| Перетекает на второй лист как есть | Paged.js разбивает поток сам; подписи уезжают целиком | ✓ |
| При переливе — тоже в приложение | Требует измерения высоты в рантайме | |
| Обрезать длинные поля | Юридический документ с умышленно неполными данными | |

**User's choice:** Перетекает как есть → D-14

### Таблица приложения длиннее листа

| Option | Description | Selected |
|--------|-------------|----------|
| Шапка повторяется, устройство не рвётся | `<thead>` на каждом листе, две строки устройства держатся вместе через `break-inside: avoid` | ✓ |
| Шапка не повторяется | Меньше работы, третий лист читается плохо | |
| Шапка повторяется + «продолжение» | Требует `@page`-колонтитула — тот же конфликт с гейтом Фазы 33 | |

**User's choice:** Шапка повторяется, устройство не рвётся → D-15

### Разрыв перед приложением

| Option | Description | Selected |
|--------|-------------|----------|
| Всегда принудительный | `break-before: page`; два устройства дают два листа даже при свободном месте — этого требует DOC-11 | ✓ |
| По месту на листе | Экономит бумагу, но нарушает DOC-11 и критерий #3 фазы | |

**User's choice:** Всегда принудительный → D-16

## Claude's Discretion

- Оттенок зебры, толщина и цвет волосяной линии, кегль таблицы и отметки, проценты ширины колонок.
- Точная формулировка центрального заголовка описи и строки-отсылки на первом листе.
- Способ удержания двух строк одного устройства вместе (`<tbody>` на устройство против `break-inside: avoid` на строках).

## Deferred Ideas

- Итоговая строка «Всего устройств: N» как защита от утери листа приложения — отклонена в этой фазе (D-09).
- Нумерация страниц «Лист N из M» во всех печатных формах — требует переписывания гейта `html_page_parity.rs` (D-12).
- Альбомная ориентация для широких печатных форм — отклонена как рискованная в связке «второй `@page` + Paged.js + гейт паритета» (D-01).
