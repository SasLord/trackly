# Phase 41.4 Plan 17: попапы завершения/указания устройства и секция заходов Summary

Три компонента на Svelte 5 с рунами по UI-SPEC §7.1, §7.3, §8, §9; пока нигде не подключены (подключение в плане 18). Визуально и в рантайме НЕ проверено — это UAT плана 21.

## Сделано

- **RepairCompleteModal**: при `repairState.moved` — PlacePicker «Куда вернуть устройство» с предзаполнением `suggestedReturnPlaceId` и живое превью «Статус устройства: «…» на складе / на рабочем месте» (подписи из deviceStatuses; признак склада — серверный список `cartridge_storage_place_ids`, т.е. место или любой предок с is_storage, клиент дерево не обходит); без перемещений — подтверждение без поля места. Комментарий уходит в `notes`. Ошибка VALIDATION/CONFLICT (в т.ч. D-10) показывается в попапе текстом сервера, прочее — тост.
- **RepairAssignDeviceModal**: Dropdown (variant select, flat, поиск) со всеми устройствами, пометка «уже в ремонте»; `conflictRequestId` — role=alert + Button link «Открыть заявку №N» (проп `onOpenRequest`), без тоста; успех — тост «Устройство указано».
- **RepairVisitsSection**: карточки новые сверху, бейдж, мета, поля, `costDisplay` с сервера, «Скан результатов» (есть (N) — link на прокрутку к вложениям / нет); для canManage «Печать акта» (кнопка + пункт ActionMenu) и «Приложить скан» у закрытых заходов (`uploadAttachment` + `repairs.linkScans`, ошибки файла inline без тоста); автору-сотруднику кнопок нет, при нуле заходов секция не рисуется.

## Отклонения

- **[Rule 3] PdfPreviewModal** (вне списка files_modified): добавлен `mode='repair'` + `repairVisitId` (рендер через `repairs.renderAct`), чтобы печать акта шла тем же предпросмотром и печатью (Tauri и LAN), а не копией логики. Добавлены необязательные `onLoaded`/`onLoadError`: секция показывает `loading` на кнопке пока акт готовится и тост «Не удалось подготовить акт…» вместо встроенного сообщения об ошибке. Существующие вызовы не затронуты (колбэки опциональны).
- Подтверждение завершения без перемещений использует то же поле «Комментарий».
