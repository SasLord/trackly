Данные только вымышленные. Учётные записи: администратор; сотрудник «Иванов И.И.» (группа АРМ А с принтером и системным блоком); сотрудник «Петров П.П.» (другая группа АРМ Б). В браузере открыть F12 -> Network (фильтр «Fetch/XHR») для проверки запросов.

Р1. Создание, LAN-браузер под сотрудником «Иванов И.И.» (RequestFormModal). Создать подряд: «Свободная форма»; «Замена картриджа» с принтером; «Ремонт» с устройством группы А; «Ремонт» → «Другое» без устройства. После каждого «Отправить» — выбрана новая заявка. Ожидается: нет красных тостов «Недостаточно прав для этого действия» и «Не удалось загрузить справочник статусов…»; в Network нет запросов device_statuses_list, repairs_last_places и нет ответов 403.
Р2. Просмотр. Сотрудник открывает ремонтные заявки разных статусов (новая; принятая в работу и перемещённая; уехавшая в сервис; завершённая; отменённая; без устройства). Условие готовит администратор на десктопе: принять, отправить в ремонт, забрать, завершить по заявкам сотрудника. Ожидается: без тостов; в карточке «Статус устройства» — подпись («На складе», «В ремонте» и т.п.), не код с подчёркиванием; в Network нет 403.
Р3. Отмена автором. Сотрудник отменяет свою новую ремонтную заявку и свою заявку в работе до перемещения (кнопка отмены в RequestDetail). Открывает вкладку «Отменённые» и каждую отменённую заявку. Ожидается: «Заявка отменена», открытие без тостов, история на месте, в том числе «request N not found» не появляется.
Р4. Поглощённая заявка. Условие: у устройства из группы А открыта ремонтная заявка от «Петров П.П.»; заявка «Другое» «Иванов И.И.» в работе. Администратор в «Указать устройство» выбирает это устройство → «Объединить». Сотрудник «Иванов И.И.» открывает свою поглощённую заявку (отменена): без тостов, запись «Объединена с заявкой №N» — ссылка, клик открывает целевую (сотрудник теперь участник).
Р5. Удалённая заявка. Сотрудник «Иванов И.И.» держит список открытым на вкладке «Отменённые». Администратор в своей вкладке удаляет одну из отменённых заявок «Иванов И.И.». Сотрудник кликает по этой строке в устаревшем списке. Ожидается: русский тост «Заявка не найдена: возможно, её удалили», без текста «request N not found», карточка пуста, строка пропала после обновления списка, остальные строки открываются.
Р6. Смена пользователя в одной вкладке (дефект 4). Одна вкладка LAN-браузера, без F5 между шагами. (а) Администратор: «Устройства» (статусы в фильтре и строках — подписи), «Заявки» → любая ремонтная заявка, выполнить сценарий объединения (адрес станет #/requests?id=N). Выйти. (б) Войти «Иванов И.И.»: адрес не содержит id чужой заявки, карточка пуста; повторить Р1 и Р2 — тостов нет. Выйти. (в) Войти «Петров П.П.» (группа Б): список содержит только его заявки; создать ремонтную заявку и открыть её — тостов нет. Выйти. (г) Войти администратором: «Устройства» — подписи статусов и фильтр по статусу работают, «Добавить устройства в группу» показывает типы и статусы подписями; в карточке ремонтной заявки подпись статуса. Ожидается: никаких следов предыдущего пользователя, справочники загружены заново, ошибок нет.
Р7. Сервер всё ещё закрывает справочник. В F12 -> Console под сотрудником выполнить запрос POST /api/v1/device_statuses_list — ответ 403 (справочник для сотрудника не открыт; подпись приходит в карточке).
Регресс (десктоп Windows, администратор). Карточка ремонтной заявки показывает подпись статуса устройства; «Принять» с попапом перемещения, «Отправить в ремонт», «Забрать из ремонта», «Завершить», «Отменить ремонт» — попапы открываются, места предлагаются, действия проходят; «Указать устройство» и «Объединить» работают; страница «Устройства» и фильтр по статусу, «Добавить устройства в группу», пикер акта — подписи статусов на месте; тосты администратору не показываются без причины.
