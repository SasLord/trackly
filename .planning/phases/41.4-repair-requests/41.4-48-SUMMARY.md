# Phase 41.4 Plan 48: DatePicker в macOS WKWebView Summary

Значение даты прижато влево (`::-webkit-date-and-time-value`), а там, где у `input type=date` нет нативного индикатора (WebKit без Chromium/Firefox-признаков), справа рисуется своя кнопка «Выбрать дату» с `showPicker()` и фоллбэком `focus()`.

## Что сделано

- `calendarIcon.js` (+ `.d.ts`): `needsOwnCalendarIcon(userAgent)` — true только при `AppleWebKit` и без `Chrome|Chromium|CriOS|Edg|EdgA|EdgiOS|OPR|Firefox|FxiOS|Android|iPhone|iPad|iPod`; пустой/undefined UA — false.
- `DatePicker.svelte`: обёртка `span.date-picker-field` (block, relative, 100%), прежний input (колоночный flex плана 38 не тронут), `.has-own-icon { padding-right: 36px }`, кнопка `button.date-picker-btn` (type=button, aria-label, tabindex=-1) под `{#if ownIcon && !disabled}`, цвет `var(--tr-text-secondary)` (hover/focus `--tr-text-primary`, кольцо `--tr-focus-ring`). Обработчик: `typeof input.showPicker === 'function'` -> `showPicker()` в try; при отсутствии метода или исключении — `input.focus()`.
- `PeriodSelector.svelte`: `:global(.date-picker-field) { width: auto; min-width: 130px }` в `.range-label` (обёртка по умолчанию 100%).
- Гейт `check-date-picker-layout.mjs`: `checkIcon` (вложенность, а не счёт), `checkDetector` + `UA_TABLE` (12 строк), selftest: 17 плохих фикстур (каждая проверена на правильную причину) + чистая + заглушки детектора true/false.
- Проба `probe-date-picker-chromium.mjs` переписана: собирает НАСТОЯЩИЙ `DatePicker.svelte` (vite lib-сборка в каталог вне репо), монтирует его; прогоны chrome-ua и webkit-ua (подставленный UA Tauri WKWebView), обе темы.

## Deviations from Plan
