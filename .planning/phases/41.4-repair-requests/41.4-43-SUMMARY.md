## Расследование «request N not found» у сотрудника

Статус: ПРИЧИНА НЕ ПОДТВЕРЖДЕНА (гипотеза). Реальный путь на отменённой автором ремонтной заявке не найден.

Сервер. `AppError::NotFound{entity:"request"}` возвращают только:
- `requests_sqlite.rs`: `get` (217-, 264-), `fetch_in_tx` (241-), ветка `affected == 0` в `update` (217); все фильтруют `deleted_at_utc IS NULL`;
- `repairs_sqlite.rs`: 140-146 (`get_repair_fields`), 163 (`set_repair_fields_in_tx`), 181-184 (`lock_mismatch`); тот же фильтр;
- `attachment_service.rs` 940 (`entity` берётся из вида родителя, для request фильтр `deleted_at_utc IS NULL`), 350-369 для вложений (`attachment`);
- `repair_service.rs` 565/686/1593/1707/2149 — `entity:"device"`, 1916 — `repair_visit`; в `repair_act.rs` — не заявка.

Единственная запись `deleted_at_utc` для `requests` — `request_service::delete` (686), а он для ремонтных заявок в статусах open/in_progress/in_repair возвращает Validation (см. SUMMARY 41). Фильтров по статусу/устройству/видимости, дающих NotFound вместо Forbidden, нет: `get` у сотрудника-чужака даёт Forbidden. Слияние (`merge`) и отмена (`cancel_by_author`: `request_repo.get` -> `set_request_status_in_tx` с `lock_mismatch`) заявку не удаляют, статус `cancelled`/`merged` читается автором (тесты плана 41 зелёные без правок). Вывод: NotFound на отменённой ремонтной заявке у автора с сервера возникнуть не может, пока строка не удалена мягко.

UI. Сырой текст серверной ошибки показывают: эффект загрузки выбранной заявки в `RequestsPage` (`pushToast('error', e.message)`) и `catch` в `RequestDetail.handleCancelConfirm` (до отправки заявка существует, NotFound только при её исчезновении). После отмены `applyRepairResult` -> `onTransition` -> `handleTransition` читал заявку молча, а запросы `repairs.getState`, `getHistory`, `attachments.history` в `RequestDetail` глушат ошибки. Эффект загрузки зависит только от `selectedId`, отмена его не меняет и повторно `get` не вызывает.

Наиболее вероятный реальный путь (гипотеза, не доказана): устаревший `selectedId` из хеша `#/requests?id=N` (в том числе оставшийся от предыдущего пользователя/сессии — закрыто планом 42, D-39) либо заявка, удалённая персоналом (обычная, не ремонтная) во время просмотра: `requests.get` -> NotFound -> сырой тост. Этот путь теперь даёт русский тост и сброс выбора (D-40). Серверный путь не найден; Rust не правился. Живая проверка в плане 46 должна зафиксировать, при каком действии появляется тост (если появится после смены выбора, а не после отмены — подтверждение гипотезы про устаревший id).
