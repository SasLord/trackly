# Phase 41.4 Plan 15: вкладка «В ремонте» и форма заявки Summary

Вкладка «В ремонте» со счётчиком и раздел «Ремонт» в форме с присоединением к уже открытой заявке (кастомный Dropdown, без нативного select).

## Сделано

- Вкладка `in_repair` стоит после «В работе»; счётчик берётся из `requests.statusCounts()` (`inRepair`), null до первой загрузки (не 0). Загрузка при монтировании, после каждого `refresh()` и в `handleWsEvent` (new_request, request_status_changed). Пустое состояние вкладки по UI-SPEC §11.
- Строка списка: статус «В ремонте» (warning), тип «Ремонт». Тост о новой заявке знает тип repair.
- Форма: три кнопки типа (Замена картриджа, Ремонт, Свободная форма); Dropdown устройств (flat, секции по типу, «Другое» последней строкой), Textarea 4 строки; ошибки «Выберите устройство.» / «Опишите неисправность.» с role=alert; при выборе устройства с inRepair подсказка D-20, кнопка «Присоединиться к заявке», тост «Вы присоединились к заявке на ремонт» (по `joined`).
- EmployeeLayout: статус in_repair в тексте уведомления.

## Отклонения

- [Rule 3] Dropdown показывает справа в строке текст «уже в ремонте» (getGroupMeta принимает только строку), а не Badge: расширять общий компонент в этом плане не стали. Badge «уже в ремонте» выведен в подсказке под полем.
- Поиск устройств идёт по названию, инв. номеру и типу: в `RepairDeviceOptionDto` нет серийного номера (серверный DTO не менялся).
- Карт статусов заявок общей нет: статусы продублированы локально в RequestListRow/EmployeeLayout (как и было); новые копии не создавались, только добавлены ветки.
- Заглушка плана 07 (RequestsPage не открывает карточку по `?id=`) не входила в этот план и остаётся.
