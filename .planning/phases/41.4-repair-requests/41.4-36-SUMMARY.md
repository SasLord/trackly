# Phase 41.4 Plan 36: слияние заявок — описание, вложения, ссылка; «Кому выдал» Summary

Слияние заявок (D-33) теперь дописывает описание поглощаемой в описание цели и копирует живые вложения строками с тем же хешем; история отдаёт id связанной заявки; «Кому выдал» запоминается в app_settings.

## Что сделано

- `merge_into_open` (одна транзакция writer): UPDATE описания цели (версия +1, updated_at_utc = now, только при непустом описании источника), копия живых строк `attachments` через `SqliteAttachmentRepository::list_by_parent_on/insert_on`, `custom:attachment_added` на цели (attachment_id, name, merged_from_request_id, source_attachment_id); после коммита `WsEvent::AttachmentsChanged` по цели, только если скопирована хотя бы одна строка.
- `RequestHistoryEntryDto.related_request_id` из payload (`into_request_id`, иначе `merged_request_id`).
- `SETTING_LAST_RECEIVER = "repair_last_receiver_name"` — upsert в транзакции `send` рядом с `SETTING_LAST_GIVER`; `last_places` отдаёт `last_receiver_name`.
- registry.rs: причина исключения `merge_into_open` дополнена сигналом AttachmentsChanged.
- Bindings перегенерированы (`export_bindings`), `lastReceiverName` и `relatedRequestId` присутствуют в `ui/src/bindings.ts` (файл в .gitignore, не коммитится).
