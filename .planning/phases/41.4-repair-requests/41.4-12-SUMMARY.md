# Phase 41.4 Plan 12: заходы в сервис Summary

Отправка в ремонт с номером акта из отдельного счётчика, два пути возврата (в том числе забор с завершением заявки одной транзакцией) и явная связь сканов с заходом.

## Задачи
1. `send`, `receive`, `link_scans`, DTO, `status_code_for_place` (D-09, отложенная в плане 10), `check_date`, `required_text` - 457b44d4
2. `repair_send_receive.rs`, 9 тестов - 711a56d4
3. Реестр гейта (`b` для send/receive, `ex` для link_scans), сценарии `scenario_send`/`scenario_receive` (оба варианта), кейс `RepairService::send` в `number_space_broadcast_gate.rs` - b2f14252

## Решения
- Запись устройства идёт через единственный `apply_device_state_in_tx` (счёт вызовов `update_status_and_place_in_tx(` по-прежнему 1).
- `receive` сначала закрывает заход, потом перемещает устройство: сбой перемещения откатывает закрытие (тест D-08 проверяет заход открыт, устройство в сервисе, заявка in_repair).
- Складское место для D-09 определяется само или любым предком с `is_storage` (как `list_storage_place_ids`).
- Без отметки место возврата запоминается под `repair_last_move_place_id`; с отметкой не запоминается; сервис под `repair_last_service_place_id`.
- `NumberSpaceChanged{repair_act_create}` рассылается только из `send`.
- Дата возврата не раньше даты отправки (сверх плана, Validation).
