# Phase 41.4 Plan 16: три попапа цикла ремонта Summary

Три попапа на Svelte 5 с рунами, по UI-SPEC §4-§6; компоненты пока нигде не подключены (подключение в планах 17-18). Визуально и в рантайме НЕ проверено — это UAT плана 21.

## Сделано

- **RepairMoveModal** (props: open, mode, request, repairState, onClose, onSuccess): быстрый выбор склада (до 4, `cartridge_storage_place_ids` + `places_get`, aria-pressed), PlacePicker, Badge статуса «Ожидает ремонта» из справочника, D-18 (подпись якоря, отключённое поле для вложенной группы), D-23 (role=status), предзаполнение `lastPlaces().movePlaceId`, «Без перемещения» только в mode accept, тосты по спецификации, один тост на событие.
- **RepairSendModal**: поля по §5, описание предзаполнено текстом заявки, сервис предзаполнен `servicePlaceId`, фото только кнопкой с списком и ×. После успешной отправки (один тост) файлы грузятся `uploadAttachment('request', id, file)` последовательно; ошибки по файлам списком role=alert, без тостов, попап переходит в режим итога («Закрыть»), повторная отправка невозможна.
- **RepairReturnModal**: поля по §6, отметка «Сразу вернуть на рабочее место» (подпись «Рабочее место», `suggestedReturnPlaceId`, скрытие быстрого выбора, кнопка «Забрать и завершить заявку»), «необязательно» + подсказка D-29, стоимость строкой без клиентского разбора; ошибка `VALIDATION` с `details.field === 'cost'` показывается под полем текстом сервера. После забора файлы грузятся и связываются `repairs.linkScans(visitId, ids)` (заход с наибольшим seq из ответа).

## Отклонения

- **[Rule 3] Button.ariaPressed** — у общей Button не было `aria-pressed`, а §4 требует его на кнопках быстрого выбора. Добавлен необязательный проп, остальные вызовы не затронуты.
- **[Rule 3] Input.inputmode** — для `inputmode="decimal"` у стоимости; необязательный проп.
- **[Rule 3] Гейты lint**: `check-place-path-short` (вердикты FULL_BY_DESIGN для RepairMoveModal и RepairReturnModal — подписи самих складских мест, как у acts/ReturnModal) и `check-group-vocabulary` (два литерала RepairMoveModal про группу, D-18).
- Для вложенной группы (groupNested) в Move текст пояснения написан исполнителем: «Устройство входит в группу, место задаётся группой и здесь не меняется.» — в UI-SPEC точной формулировки нет; уточнить при UAT.
- Пустые «Кто принял» и «Выберите место» получили тексты ошибок, которых в UI-SPEC нет («Укажите, кто принял устройство.», «Выберите место.»; в Send — «Укажите, кто выдал устройство.»).
- Тост ошибки при неверной версии заявки — общий «Не удалось …», специальной обработки конфликта версий нет.
