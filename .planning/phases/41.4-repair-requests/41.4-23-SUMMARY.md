# Phase 41.4 Plan 23: акт передачи в ремонт без «Тип», исходное место Summary

Строка «Тип» убрана из шаблона акта; «Расположение до отправки» для первого захода с перемещением по заявке берётся из `repair_origin_place_id`, иначе из `from_place_id` захода; прежнее тело заморожено как `_legacy_defaults/v30`.

## Что сделано

- `repair_act.rs`: через `get_repair_fields` читаются (origin, moved); при `seq == 1 && moved && origin.is_some()` место = origin, в остальных случаях `from_place_id` захода.
- `repair_transfer_act.html`: удалена строка «Тип:», обновлён комментарий контекста.
- `_legacy_defaults/v30/repair_transfer_act.html`: побайтно равен HEAD-версии прежнего шаблона; внесён в `KNOWN_LEGACY_DEFAULTS` (`html_templates.rs`), так что неизменённые копии на диске обновятся при запуске, изменённые остаются нетронутыми.
- Ключ `device.type` в контексте рендера и в демо `template_service` сохранён (предпросмотр strict-undefined не ломается).
- 7 новых тестов в `repair_act_render.rs` (без «Тип», исходное место, без перемещения, moved без origin, seq 2, апгрейд v30 + изменённая копия, пользовательская копия с `device.type`).

## Отклонения от плана

Нет. Одна техническая деталь: в тесте seq 2 первый заход закрывается возвратом (на заявку допускается один открытый заход, UNIQUE).
