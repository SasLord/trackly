# Phase 41.4 Plan 47: область принтеров сотрудника (D-41), сервер

`RequestService::printer_options` для сотрудника отдаёт только принтеры из `SqliteRepairRepository::employee_device_ids` (та же область, что у формы «Ремонт»); `create` отклоняет принтер вне области ошибкой `Forbidden` до записи. Персонал (Admin, Manager) видит и выбирает все принтеры.

## Коммиты

- `ddd88fc6` test(41.4-47): тесты области, красные до правки (RED)
- `db40db9a` feat(41.4-47): область в `printer_options` и проверка в `create`, правка прежнего теста

## Что сделано

- `printer_options`: после `authorize` считается `staff`; сотрудник без `user_id` получает `Forbidden`; для сотрудника результат запроса фильтруется `retain` по области (SQL запроса, сортировка и поля `id/name/place` не менялись).
- `create`: не-персонал без `user_id` получает `Forbidden` явно (подстановка `unwrap_or(1)` осталась только для доверенного администратора); если задан `printer_device_id`, а его нет в области, то `Forbidden` до `BEGIN` записи, для любого типа заявки.
- Предикат персонала не продублирован: `repair_service::is_staff` стал `pub(crate)` и используется из `request_service.rs`. Новой SQL-области в `request_service.rs` нет, команд Tauri/HTTP не добавлялось, DTO не менялся.

## Тесты

Новый файл `request_printer_scope.rs` (9 тестов), фикстура расходится по месту и составу: группа А (системный блок, сетевой принтер в составе, USB-принтер хоста А, вложенная группа с принтером, ссылка `device_refs`), группа Б, свободный принтер, сотрудник без групп. Ожидания заданы списками id.

Характеризация неоднозначностей D-41 (замечание 1): (а) сетевой принтер на месте группы, но вне состава, не виден и не создаётся; (б) принтер по `device_refs` вложенной группы не виден сотруднику родительской; (в) USB-принтер, хост которого лишь ссылка, не виден. Эти три принтера проверяются и в `printer_options`, и в `create` (Forbidden).

Прочее: создание без `user_id` у не-персонала (Forbidden, замечание 2); отказ не пишет строк в `requests` и `audit_log` (счёт до и после); `free_form` с чужим принтером отклоняется, без принтера и со своим проходит; персонал создаёт на любой принтер.

RED (прогон до правки): 6 из 9 красные (`employee_sees_only_printers_of_own_scope`: получено {2,3,4,5,6,8,9,11,12,13}, ожидалось {2,3,4,6}; остальные: без групп, без user_id, исключённые принтеры, отказ create, free_form), зелёные только тесты персонала и создание на свой принтер.
