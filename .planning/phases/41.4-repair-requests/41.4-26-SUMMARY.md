# Phase 41.4 Plan 26: принтеры в пикере устройств акта Summary

Корень: складской запрос пикера возвращает свёртки по убыванию количества с лимитом 20 (`ORDER BY cnt DESC, d.name ASC LIMIT ?2`, `crates/trackly-infra/src/repos/devices_sqlite.rs`, три SQL-ветки `list_grouped`), а текстовый поиск FTS не индексирует название типа. Единичный принтер (количество 1) вытесняется при пустом запросе, а слово «принтер» его не находит. Поэтому принтеры в пикере не видны.

## Вердикты по гипотезам

| Гипотеза | Вердикт | Тест и вывод |
|----------|---------|--------------|
| H1: принтер «В работе» вне групп не виден (D-02) | Поведение подтверждено, но это не причина для принтеров со склада | `working_printer_outside_groups_not_in_picker_and_act_rejected`: `склад видит=false, члены групп видят=false`; акт на такой принтер отклонён `Conflict "Устройство id=1 больше не на складе…"` |
| H2: единичные устройства вытесняются при пустом запросе | Подтверждена, корень дефекта | `printer_among_many_collapsed_groups`: `пустой запрос: принтер виден = false (из 20 свёрток)`; `поиск LaserJet: виден = true` |
| H3: принтеры, привязанные к АРМ | Опровергнута | `group_member_printer_visible_in_members_section`: член группы виден в «составе групп» при любом статусе |
| H4: свёртка теряет ids | Опровергнута | `discovered_printer_visible_in_storage_section`: принтер из обнаружения (type_id 2, статус «На складе», без места) найден в `ids` и пустым запросом, и по «HP», «M404n», «LaserJet Pro» |

Принтер из обнаружения сам по себе в пикере виден; пропадает он только при наличии более 20 других свёрток и при поиске по слову «принтер».

## Исправление

1. `list_grouped` теперь применяет `filter.type_id` (параметр `?7`, `AND (?7 IS NULL OR d.type_id = ?7)` в трёх ветках). Все существующие вызовы передают `type_id: null`, поведение страницы «Устройства» и поиска по группам не меняется (`devices_grouping`: 29 из 29).
2. `ActFormItemsTable.svelte`: `fetchStorage` дополнительно ищет типы, в названии которых есть введённый текст (от 2 символов, не более 3 типов, справочник типов с сервера, без хардкода id), и подмешивает их складские свёртки перед обычными результатами с дедупликацией по `repr.id`. Единственный вызов `devices.listGrouped(` сохранён внутри `storageGroups`, D-22 (`loadOpenRepairs`, `REPAIR_ACT_NOTE`) не тронут.
3. `check-act-group-picker.mjs`: якорь мутанта «storage-no-status» поправлен на новый отступ.

Мутационная проверка: в `devices_sqlite.rs` предикат `(?7 IS NULL OR d.type_id = ?7)` заменён на `(?7 IS NULL OR 1 = 1)` (3 вхождения, найдены все): `printer_among_many_collapsed_groups` красный. Исходник восстановлен, остаётся только намеренная правка (3 вхождения предиката).

## Что осталось открытым

- Пустой запрос по-прежнему показывает 20 свёрток с наибольшим остатком: принтер там не появится, пока пользователь не введёт «принтер» (или имя модели). Это сознательно, чтобы не менять порядок для других потребителей.
- Принтер «В работе» вне групп по правилу D-02 41.2 недоступен в пикере (H1); правило не менялось. Если принтеры пользователя именно такие, это продуктовое решение (вернуть на склад / включить в группу либо ослабить правило), его принимает пользователь.
- Замечание, не исправлялось: в `act_service.rs` проверка `is_act_assignable` выполняется только на пути `device_ids` (около строки 616); путь с пустым `device_ids` и `quantity 1` (legacy) её не вызывает. Пикер всегда передаёт `device_ids`, так что для UI это не достижимо, но прямой вызов сервиса может передать устройство «В работе».
- Визуально в приложении не проверено; живая проверка пункта 14 остаётся планам 33 и 34.

## Deviations from Plan

**1. [Rule 1 - Bug] `list_grouped` игнорировал `type_id`.** Найдено при реализации поиска по типу. Исправлено предикатом `?7` (см. выше); добавлен в файл `devices_sqlite.rs`, которого план касался как кандидата.

**2. Тест 2 фиксирует фактическое поведение.** Утверждение «принтер не виден при пустом запросе и 25 свёртках» оставлено в тесте намеренно (документирует H2); если пустой запрос когда-нибудь начнёт показывать принтер, тест напомнит обновить его.
