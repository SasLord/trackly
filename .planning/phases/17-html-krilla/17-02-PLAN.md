<objective>
Retarget TemplateService's editor-facing methods (list_all_for_editor, update_body,
reset_to_default, validate_preview) from the DB-backed document_templates table
(DocSpec-MiniJinja) onto the same templates/*.html files that the acts (and, after
Plan 17-01, the report) render pipeline reads — using the unmodified Phase-16
html_templates primitives (resolve_templates_dir, load_template,
DEFAULT_HTML_TEMPLATES). The frozen DB path (DEFAULT_TEMPLATES,
seed_defaults_on_startup, get_active) is left completely untouched per D-13 — it
keeps running, just no longer backs the editor UI.

Purpose: The editor currently edits a dead DocSpec-MiniJinja path that no longer
prints anything (acts render from HTML files since Phase 16) — this plan makes the
editor edit what actually gets printed, and removes the last render_docspec call
from the settings/templates surface (Req 6).

Output: TemplateService with an organization: Option<Arc<OrganizationService>>
field + with_organization builder (mirrors Plan 17-01's ReportService change and
ActService's existing pattern), file-backed editor methods, validate_preview
taking a kind param and returning Result<String, AppError> (HTML), and the
Tauri/HTTP templates_validate_preview adapters no longer discarding kind.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Editor "Сохранить"/"Сбросить" -> filesystem write | update_body/reset_to_default write directly to templates/*.html on disk (portable-mode path via Paths::templates_dir()) |
| kind parameter -> filename construction | kind (client-supplied string, e.g. "act_handover") is used to build a file path (templates_dir joined with "{kind}.html") — this is the plan's primary new attack surface |
| Editor "Проверить" body -> MiniJinja render | Arbitrary MiniJinja source text (the textarea body) is compiled and rendered server-side for preview |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-02-01 | Tampering (path traversal) | update_body/reset_to_default kind-to-filename mapping | mitigate | kind is checked against DEFAULT_HTML_TEMPLATES's fixed 3-entry allowlist (act_handover/act_acceptance/report) BEFORE any path join — an unrecognized kind returns AppError::NotFound, never reaches the templates_dir join; no ".." or absolute-path values can escape the allowlist since the join operand is always one of the 3 literal ".html"-suffixed strings looked up from the const, not the raw client string |
| T-17-02-02 | Tampering | validate_preview body -> MiniJinja render | mitigate (unchanged from Phase 7 T-07-04-02) | build_safe_html_env autoescape ON + render_with_timeout's fuel cap (100,000 units) + 5s wall-clock timeout — body is compiled/executed server-side only, template output is never eval'd as script in the browser (preview renders into an iframe srcdoc, Plan 17-03) |
| T-17-02-03 | Denial of Service | update_body syntax validation | accept (unchanged) | Pre-existing add_template_owned syntax check runs before any write — malformed MiniJinja is rejected with AppError::Validation before touching disk, same as the current DB-backed behavior |
| T-17-02-SC | Tampering | No new package-manager installs in this plan | accept | Plan adds zero new Cargo/npm dependencies |
</threat_model>
