<objective>
Migrate ReportService::export_pdf off krilla/DocSpec onto the Phase-16 HTML-print
pattern: a new editable templates/report.html (embedded default + file-first +
materialize-on-startup, reusing the untouched html_templates.rs mechanism),
Rust-side month-grouping into a generic groups/columns/row context, and
build_safe_html_env MiniJinja rendering. The Tauri command and HTTP handler both
switch their return type from Vec<u8> (PDF bytes) to String (HTML), with the
HTTP handler's Content-Type becoming text/html; charset=utf-8.

Purpose: Closes deferred item 16-HUMAN-UAT 2a (Reports migration) and the live bug
2b (reports_export_pdf "Ошибка при создании PDF") by removing krilla from the
Reports export path entirely, mirroring the already-shipped act HTML-print pipeline.

Output: templates/report.html, updated html_templates.rs, report_service.rs
with HTML-returning export_pdf, reports.rs (Tauri) and http/reports.rs (HTTP)
returning String/text-html, context.rs wiring ReportService to
OrganizationService for templates-dir resolution.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Report filter/period values -> HTML | User-supplied filter values (location name, search string, status/type IDs resolved to labels) flow into report_service.rs's groups/row_field cell values, then into report.html template interpolation |
| Template file on disk -> render | templates/report.html is a portable-mode file editable outside the app (VSCode, network share) — its content is trusted input to MiniJinja (same trust model as the two existing act templates) |
| HTTP client -> reports_export_pdf | LAN browser session posts report_type/filter/period to /api/v1/reports_export_pdf, authenticated via session_identity + Action::ReadData |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01-01 | Tampering | report_service.rs::export_pdf ctx interpolation | mitigate | build_safe_html_env autoescape ON for every variable interpolation in report.html except the single hardcoded org.logo_data_uri "| safe" exception (server-constructed base64 + mime whitelist, never user input) — mirrors T-07-04-02/T-16-02 |
| T-17-01-02 | Information Disclosure | report.html filesystem read | accept | Same trust model as act_handover.html/act_acceptance.html (Phase 16) — file lives in portable templates/ dir next to the executable, editable only by whoever has filesystem access to the machine, not remotely writable via this plan's endpoints |
| T-17-01-03 | Denial of Service | render_with_timeout fuel/timeout | mitigate | Reused unchanged from Phase 16 — build_safe_html_env sets a 100,000-unit fuel cap + render_with_timeout enforces a 5s wall-clock cap via spawn_blocking, same protection already proven for acts |
| T-17-01-04 | Tampering | ReaderPool/query params in report_service list_* methods | accept | Unchanged from Phase 7 (T-07-03-01) — all filter values already flow through parameterised placeholders; this plan does not touch the query layer, only export_pdf's rendering tail |
| T-17-01-SC | Tampering | No new package-manager installs in this plan | accept | Plan adds zero new Cargo/npm dependencies — html_templates.rs/minijinja_env.rs/base64 crate are all pre-existing Phase 16 dependencies reused as-is |
</threat_model>
