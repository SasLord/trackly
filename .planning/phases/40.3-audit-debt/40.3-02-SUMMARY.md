# Phase 40.3 Plan 02: Персистентная FK-проверка при миграциях Summary

**`run_to` теперь безусловно проверяет `PRAGMA foreign_key_check` на КАЖДОМ старте (не только когда были pending-миграции) и персистит бейзлайн в `app_settings.migration_fk_baseline` — новое FK-нарушение блокирует все последующие запуски, а не только первый, при этом self-heal восстанавливает чистый старт после ручного исправления данных.**

## Decisions Made

- Формат сериализации бейзлайна — простой TSV-подобный текст (`table\trowid\tparent\tfkid` построчно), не JSON: избегает лишней зависимости в инфра-слое ради структуры из ≤10 строк на практике (see threat register T-40.3-05 — accept, DoS через размер неактуален на масштабе приложения).
- Таймстемпы `created_at_utc`/`updated_at_utc` для строки бейзлайна берутся напрямую через `std::time::SystemTime` (не через `Clock`-абстракцию core), т.к. `migrations.rs` — инфра-модуль ниже гексагональной границы и не знает о `Clock`; сами значения не несут пользовательской ценности, только факт наличия строки.
