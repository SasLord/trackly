# Phase 40.3 Plan 08: Структурное закрытие BLOCKER-3 (предпросмотр возврата + расширенный гейт) Summary

**ReturnModal.svelte больше не предсказывает номер акта возврата в предпросмотре (WR-08); check-act-number-no-regex-split.mjs теперь ловит все 5 известных форм регресса через два независимых правила, доказано встроенным --selftest на 7 фикстурах (WR-07); живая проверка тоста и предпросмотра ПОДТВЕРЖДЕНА человеком в реально запущенном cargo tauri dev.**

- **Duration:** ~20 мин (оценка, включая живую проверку человеком)
- **Tasks:** 3 из 3 выполнены (2 auto + 1 checkpoint, чекпоинт закрыт реальным human-verify)

## Accomplishments
- `ReturnModal.svelte`: удалены `predictedSubNumber`/`parentNumber` (клиентская реконструкция номера из `act.number_raw` + предположение о формате суффикса); подсказка предпросмотра создания возврата — простой текст «Создаст акт возврата» без интерполированного номера. Тост (исправлен в 40.3-03) не тронут.
- `check-act-number-no-regex-split.mjs`: узкая проверка `.replace(/^\d.../)`заменена на два независимых правила — (A) `DIGIT_PREFIX_REGEX_LITERAL_RE` ловит anchored digit-prefix regex-литерал где угодно в файле (inline и вынесенный в `const`), (B) `NUMBER_RAW_RE` + `ALLOWED_NUMBER_RAW_FILES` ловит любое употребление `number_raw` вне whitelist. `checkFile` рефакторен на чистую `scanSource(relPath, src, violations)` + тонкую fs-обёртку. Новый `--selftest` прогоняет 7 in-memory фикстур (4 варианта WR-07 + WR-08-конкатенация + чистый код + legit whitelist) и завершается `exit(1)` при любом расхождении.
- Мутационная проверка на уникальном якоре (`if (!ALLOWED_NUMBER_RAW_FILES.has(relPath))`) подтвердила, что whitelist реально работает: временное снятие условия перевело реальное сканирование репозитория из PASS в FAIL (легитимный `ActFormBody.svelte:178` начал репортиться) — восстановлено перед коммитом.
- `pnpm --dir ui lint` (полная цепочка, 15 гейтов включая этот) — PASS. `svelte-check` — 0 новых ошибок/предупреждений в затронутых файлах.
- `pnpm --dir ui build` выполнен после фронтенд-правки — `ui/dist` актуален для LAN/browser-проверки (project memory `dev_browser_testing_needs_ui_build`).
- **Живая UAT-проверка чекпоинта ВЫПОЛНЕНА** пользователем в реально запущенном `cargo tauri dev` (в контраст с 40.3-03, где чекпоинт был закрыт auto-approve БЕЗ наблюдения и зафиксирован как UNVERIFIED — именно это и породило BLOCKER-3). Подтверждено: предпросмотр создания возврата показывает ровно «Создаст акт возврата» без интерполированного номера; тост после сохранения показывает корректный шаблонный номер без дублирования и без клиентски предсказанного под-номера.
