## Decisions Made

- `bulk_create_with_printer` отклоняет printer-блок БЕЗУСЛОВНО (не «только для не-принтеров», как в create-пути) — bulk-путь не имеет атомарного single-device IP/SNMP концепта в принципе; сообщение прямо советует «создайте принтер отдельно».
- Вариант (b) для `quantityDisabled` (блокировать Количество), а не вариант (a) (прятать IP-блок) — из `40.3-REVIEW.md` CR-01, сохраняет уже установленный UX-паттерн для `inventoryNo`/`serialNo`.
- UAT-дефект исправлен расширением области `NumberTemplateField` на edit-режим, а НЕ написанием отдельного edit-специфичного компонента-кнопки — переиспользует всю существующую логику подстановки/D-14/живого «занят»-чека, добавляя только один узкий проп.
- `templateActionsDisabled` — предикат «неактивна, пока живое значение совпадает (trim) с исходно сохранённым; активна с первого рендера, если исходное значение было пустым» — снимок `savedInventoryNo` берётся ОДИН раз из `target` при монтировании (обычный `const`, не `$state`/`$derived`), что подтверждено достаточным, т.к. компонент полностью перемонтируется через `{#key openInstanceCounter}` при каждом открытии модала.
- IP/SNMP в edit-режиме — сознательно вне объёма (см. `## Deviations` ниже и pending-todo) — backend не умеет обновлять сетевые параметры принтера вообще; «просто показать блок» создало бы форму с молчаливой потерей данных, ровно тот класс дефекта, который закрывал этот же раунд аудита (BLOCKER-2/CR-02).

## Deviations from Plan

### Auto-fixed / UAT-driven Issues

**1. [Rule 2 — missing critical functionality, обнаружено на живом чекпоинте] Edit-mode «Вставка» для Инвентарный № отсутствовала**
- **Found during:** живой чекпоинт этого плана (не автоматическая задача) — человек открыл `cargo tauri dev`, попытался проверить перенесённый 40.3-05 сценарий и обнаружил, что в режиме правки поле Инвентарный № — обычный `<Input>` без кнопки «Вставка», хотя UI-требование («если со временем решили указать инвентарный номер, должна быть возможность подставить шаблон») предполагает такую возможность.
- **Issue:** `DeviceFormBody.svelte` рендерила `NumberTemplateField` ТОЛЬКО в create-режиме; edit-режим не имел доступа к шаблонам вообще — ни для изначально пустых записей, ни (что не требовалось) для уже пронумерованных.
- **Fix:** `NumberTemplateField` получил `templateActionsDisabled` (узкая версия `disabled`, гасит только кнопку+стрелку, Input остаётся редактируемым); edit-режим рендерит `NumberTemplateField` с этим пропом, вычисляемым по сравнению живого значения с исходно сохранённым снимком; плюс `autofillOnMount={false}` (не перетереть сохранённый номер при открытии) и `excludeId={target.id}` (живая подсказка «занят» не находит саму запись).
- **Files modified:** `ui/src/features/devices/DeviceFormBody.svelte`, `ui/src/lib/components/NumberTemplateField.svelte`
- **Verification:** `pnpm --dir ui exec svelte-check` — 0 ошибок; `pnpm --dir ui lint` — полный проход (eslint, prettier, все кастомные гейты); `pnpm --dir ui build` — успешно; ПОВТОРНОЕ живое наблюдение человеком в `cargo tauri dev` подтвердило все ветки: кнопка неактивна при неизменённом сохранённом номере (само поле редактируемо), активна сразу для записи без номера, активна после очистки/правки, сохранённый номер не перетирается при открытии карточки, нет ложного «занят» на собственной записи.
- **Committed in:** `1bd215d6` (fix)

**2. [Не дефект — сознательно отложенный долг, зафиксирован по требованию пользователя] IP/SNMP редактирование в edit-режиме — НЕ реализовано в этом плане**
- **Context:** во время того же живого чекпоинта пользователь также запросил видимость/редактируемость блока IP/SNMP в edit-режиме («Может у него сменится IP, его надо будет поправить»).
- **Почему не сделано здесь:** это НЕ косметическое расширение видимости — backend вообще не имеет пути обновления сетевых параметров принтера (`PrinterRepo` без update-метода; единственный `UPDATE printers` во всей инфре пишет только `last_seen_utc` из поллера; `PrinterService` не имеет `update`). «Просто снять `!isEdit`» создало бы форму, молча теряющую введённые данные — тот же класс дефекта (BLOCKER-2/CR-02), который этот план и закрывал.
- **Решение пользователя:** отдельная фаза после 40.3 (полная сквозная фича на 6 слоёв — порт, репозиторий, сервис, DTO, оба транспорта, UI), а не заплатка в рамках этого плана.
- **Committed in:** `c33a4f8c` (docs) — `.planning/todos/pending/2026-09-23-printer-network-params-editable.md`
- **Важно для верификатора фазы:** IP/SNMP блок в `DeviceFormBody.svelte` по-прежнему рендерится ТОЛЬКО при `{#if typeId === PRINTER_TYPE_ID && !isEdit}` — это НЕ регрессия и НЕ незакрытое требование ЭТОГО плана, условие оставлено намеренно неизменным (см. `<threat_model>` плана — T-40.3-16..18 уже фиксировали эту границу как accept).
