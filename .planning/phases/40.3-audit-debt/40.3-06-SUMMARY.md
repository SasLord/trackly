# Phase 40.3 Plan 06: DevicePatch.place_id + UserPatch.email double-Option serde fix Summary

**Added the missing `serde(default, with = "serde_with::rust::double_option")` attribute to `DevicePatch.place_id` and `UserPatch.email` — the last two fields of a 7-field double-Option class where JSON `null` was silently collapsing into "field not sent", making "clear Место"/"clear email" a silent no-op — plus two mutation-validated JSON-boundary regression test pairs.**

## Accomplishments
- `DevicePatch.place_id` now carries the serde double_option attribute (6th of 6 double-Option fields in `dto/device.rs`, matching serial_no/model/specs/kit/state fixed in Plan 40.3-01)
- `UserPatch.email` now carries the same attribute (1st and only such field in `dto/auth.rs`) — closes the independently-found CR-01 bug from code review
- Two new JSON-boundary regression pairs added, each with a pure-serde test (`serde_json::from_str`, not a Rust literal — the only way to actually cross the same boundary as the HTTP/Tauri transport) and an e2e test through the service layer proving the untouched sibling field (`name`/`full_name`) is preserved
- Both fixes mutation-validated by hand: temporarily removing the attribute reliably reds the new tests, then the attribute was restored
