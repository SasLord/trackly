<objective>
`ReturnModal.svelte` после успешного оформления возврата показывает тост, СКЛЕИВАЯ
`ret.number_raw` (сырое значение до форматирования) с суффиксом, вычисленным по regex
`ret.number.replace(/^\d+/, '')` — код предполагает, что номер акта ВСЕГДА начинается с
цифр. С Фазы 40.2 (NUM-14) номер акта — свободный текст по шаблону («2026/09-1»), поэтому
для такого номера тост показывает искажённое «№2026/09-1/09-1в» вместо правильного
«№2026/09-1в». Сервер уже отдаёт готовое `ActDto.number` — искажение чисто на клиенте
(находка N-1, `.planning/v1.4-MILESTONE-AUDIT.md`). Forward risk F7 аудита предупреждает,
что это класс бага, не единичный инцидент — любой будущий клиентский код, собирающий номер
из `number_raw` + суффикс, повторит его (актуально для Фазы 41 WKS-05/06 актов АРМ).

Purpose: тост возврата показывает корректный номер акта; постоянный структурный гейт ловит
регресс этого класса бага в будущих фазах.
Output: однострочный фикс + новый `check-*.mjs` гейт, подключённый в `pnpm lint`.
