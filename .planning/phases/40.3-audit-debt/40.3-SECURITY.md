## Границы доверия

| Граница | Описание | Данные |
|---------|----------|--------|
| Браузер (LAN) / Tauri WebView → `devices_update` (Tauri invoke и HTTP `/api/v1/*`) | Непроверенный JSON `DevicePatch` пересекает границу процесса | инвентарные атрибуты устройства, `place_id` |
| Браузер / Tauri WebView → `users_update` | Непроверенный JSON `UserPatch` | ФИО (внутренний сотрудник), e-mail, роль, пароль |
| Браузер / Tauri WebView → `devices_create_single_with_number_check` | Непроверенный JSON, включая опциональный printer-блок (IP + SNMP community) | IP-адрес, community-строка |
| Браузер / Tauri WebView → `devices_bulk_create` | Непроверенный JSON, `count` | атрибуты устройства |
| Файл БД (portable-режим) → приложение на старте | Состояние БД, которое могли изменить сторонним инструментом; не сетевой ввод | схема, FK-целостность, `app_settings` |
| Сервер → UI (тост/предпросмотр после мутации акта) | Целостность отображения серверного значения (Repudiation-класс) | номер акта |
| Клиентский guard `quantityDisabled` (`DeviceFormBody.svelte`) | **НЕ граница доверия** — обходится любым не-UI клиентом; реальная граница — серверная валидация в `bulk_create_with_printer` | количество, printer-блок |

## Примечания аудитора (информационно, не блокеры)

- **N-1 (WR-13, перенесено из `40.3-VERIFICATION.md:105`).** В `pnpm lint` вызывается
  только реальное сканирование гейта, режим `--selftest` в lint/CI не подключён.
  Сам гейт работает (проверено запуском), но доказательство его полноты (7 фикстур)
  не защищено от будущего незаметного ослабления регулярок. На закрытие T-40.3-07 /
  T-40.3-20 не влияет — обе меры физически присутствуют и выполняются в CI.
- **N-2 (WR-14).** Правило (A) `DIGIT_PREFIX_REGEX_LITERAL_RE` — широкий текстовый
  матч, не привязанный к контексту regex-литерала; теоретически возможен будущий
  false-positive. Сегодня — 0 нарушений на реальном репозитории.
- **N-3.** `PrinterService::poll_single` (`services/printer_service.rs:404`) передаёт
  в SNMP литерал `"public"`, а не сохранённую в `printers.community` строку. Это
  поведение существовало до фазы 40.3 и вне её реестра; отмечается лишь потому, что
  план 04/05 добавил пользовательский ввод community — фактически введённое значение
  сегодня в опросе не используется (экспозиция секрета меньше ожидаемой, не больше).
- **N-4.** Асимметрия веток `run_to`: в ветке «есть pending-миграции» FK отключаются
  на время прогона и восстанавливаются, в ветке «нет pending» — нет. Это отмечено и
  в `40.3-REVIEW.md` (IN-раздел) как информационное; на T-40.3-04 не влияет, так как
  `fk_violations` в обеих ветках вычисляется одинаково.
