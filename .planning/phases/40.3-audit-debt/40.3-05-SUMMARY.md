# Phase 40.3 Plan 05: DeviceFormModal вместо PrinterCreateModal Summary

**«Завести принтер» переключён с двухшагового обходного модала на единый `DeviceFormModal(initialTypeId=2)` — шаблоны номеров, D-01 попап-цепочка и IP/SNMP теперь идут через тот же путь, что и «Устройства»; старый модал физически удалён.**

## Accomplishments

- `DeviceFormBody.svelte`: опциональный блок «IP-адрес»/«SNMP community» (по образцу удалённого `PrinterCreateModal`), рендерится ТОЛЬКО при `typeId === PRINTER_TYPE_ID && !isEdit` (D-03); `submitSingleCreate()` строит `printerBlock` и передаёт 4-м аргументом в `createSingleWithNumberCheck`.
- `devices.ts`: `createSingleWithNumberCheck` расширен опциональным 4-м параметром `printer: PrinterCreateBlockDto | null = null`, зеркалящим backend-контракт 40.3-04; мёртвый/некорректно типизированный `create()` удалён вместе со своим единственным вызывающим (D-04).
- `DeviceFormModal.svelte`: новый опциональный проп `initialTypeId` — предзаданный тип для create-режима (игнорируется при правке, `target.type_id` всегда приоритетнее).
- `PrintersPage.svelte`: `PrinterCreateModal` заменён на `DeviceFormModal(target=null, initialTypeId=2)`; `onSaved` теперь вызывает `notifyPlaceContentChanged` для затронутого места (PLC-06) — `pnpm lint`'s `check-place-tree-invalidation.mjs` (реестр INV-7) подтвердил регистрацию `DeviceFormModal` автоматически, без ручных правок реестра.
- `PrinterCreateModal.svelte` удалён целиком — обходного пути мимо шаблонов номеров и INV-7 больше не существует (D-02).

## Decisions Made

- Блок IP/community — DOM-отсутствие, а не CSS-скрытие, вне create+Принтер (D-03) — исключает случайную отправку `printerBlock` для устройств/edit-режима даже при программной ошибке видимости.
- `PrintersPage.onSaved`: `oldPlaceId` всегда `null` (create-режим, нет `editTarget`) — минимальная адаптация эталонного паттерна `DevicesPage.svelte::onSaved` под контекст без предыдущего значения места.
- `devices.create()` удалён, а не расширен до `DeviceSaveOutcome` — единственный вызывающий (старый `PrinterCreateModal`) исчез вместе с самим файлом, расширение стало бы мёртвым кодом (D-04).

## Требует ручной проверки

**Task 3 (чекпоинт «живая проверка «Завести принтер» через DeviceFormModal») закрыт статусом
UNVERIFIED (deferred to human UAT).** Координатор подтвердил чекпоинт через авто-approve
(`AUTO_MODE=true`) — это решение по процессу продолжения плана, а НЕ результат наблюдения
поведения в запущенном приложении. Ни агент, ни человек не открывали `cargo tauri dev` и не
проверяли форму визуально в рамках этого плана. Все автоматические проверки (`cargo test
--test export_bindings`, `svelte-check`, `pnpm lint`, `pnpm build`) прошли зелёным — это
подтверждает типы, сборку и статические инварианты (включая INV-7 реестр), но НЕ подтверждает
рантайм-поведение форм (see project memory: `compile_gates_miss_svelte_runtime` — компайл-гейты
не видят рантайм-ошибок рун).

Живая проверка нужна отдельно, до закрытия фазы 40.3-audit-debt, по следующим шагам:

1. `pnpm --dir ui build` (уже выполнено в рамках этого плана — `ui/dist` свежий), затем
   `cargo tauri dev`.
2. Настройки → Организация → Шаблоны номеров: убедиться, что для типа «Устройства и
   принтеры» есть контекст «Новый принтер» с активным шаблоном (или создать временный).
3. Экран «Принтеры» → «Завести принтер». Проверить: поле номера показывает автоподстановку
   «первый свободный» по шаблону; кнопка «Вставка» открывает меню шаблонов; ниже поля
   «Место» появляется блок «IP-адрес»/«SNMP community» (community — только при непустом IP).
4. Ввести номер, ЗАНЯТЫЙ другим устройством, сохранить — должен появиться попап «Номер занят».
5. Ввести свободный номер + IP + место, сохранить. Проверить: принтер появился в списке;
   счётчик занятости выбранного места в дереве «Места» обновился БЕЗ перезагрузки страницы;
   в карточке принтера IP-адрес сохранён.
6. Открыть созданный принтер на правку (DeviceFormModal в edit-режиме) — блок IP/community
   НЕ должен отображаться (правка IP остаётся через карточку принтера/PrinterDetail).

Аналогично, живой UAT плана 40.3-03 (регулярка act-number) тоже остаётся открытым — фаза
40.3-audit-debt в целом НЕ подтверждена живьём ни по одному из своих UI-планов; это должно
попасть в фазовую верификацию как human_verification item, а не считаться закрытым по факту
прохождения статических гейтов.
