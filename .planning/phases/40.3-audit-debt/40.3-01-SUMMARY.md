# Phase 40.3 Plan 01: Double-Option для полей устройства (WR-03) Summary

**Serial_no/model/specs/kit/state устройства теперь корректно очищаются через форму правки — domain, DTO и оба SQL write-пути используют один и тот же double-Option паттерн, что уже работал для inventory_no/place_id.**

## Performance

- **Duration:** ~31 мин (16:52–17:23 UTC)
- **Started:** 2026-09-22T16:52:00Z
- **Completed:** 2026-09-22T17:23:00Z
- **Tasks:** 3/3
- **Files modified:** 5 (+ Cargo.lock)

## Accomplishments
- `domain::DevicePatch`: 5 полей (`serial_no`, `model`, `specs`, `kit`, `state`) переведены с `Option<String>` на `Option<Option<String>>`, с doc-комментариями по образцу `inventory_no`
- `dto::DevicePatch`: добавлен `#[serde(default, with = "serde_with::rust::double_option")]` на все 5 полей — без него double-Option молча коллапсирует на serde JSON-границе (Pitfall 1); исправлена конверсия `impl From<DevicePatch>` (`p.field = Some(inner)` вместо `p.field = inner`), которая ранее стирала внешний `Option` даже после исправления атрибута
- `devices_sqlite.rs`: обе функции записи (`update_in_tx`, `update` trait impl) переведены с `COALESCE(?, column)` на `CASE WHEN ?flag = 1 THEN ?value ELSE column END` для всех 5 полей, позиционные параметры `?1..?15` пересчитаны на `?1..?20` в обеих
- Два новых интеграционных теста в `devices_crud.rs`, оба идут через `serde_json::from_str::<DevicePatch>(...)` (не Rust-литерал) — единственный способ поймать Pitfall 1 и Pitfall 3 одновременно
