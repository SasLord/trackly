## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Integration-тест перестройки таблицы переписан без буквального `CREATE TABLE ... AS SELECT *`**
- **Found during:** Task 2 (integration-тест `table_rebuild_reassigning_rowid_does_not_falsely_block_grandfathered_violation`)
- **Issue:** Буквальная реализация из текста плана (`CREATE TABLE devices_rebuilt AS SELECT * FROM devices; DROP TABLE devices; ALTER TABLE devices_rebuilt RENAME TO devices;`) не копирует `INTEGER PRIMARY KEY`-ограничение — рабочая перестроенная `devices` осталась без PK/уникального индекса на `id`, из-за чего `PRAGMA foreign_key_check` стал падать с `"foreign key mismatch - \"cartridges\" referencing \"devices\""` ДЛЯ ЛЮБОЙ другой таблицы, ссылающейся на `devices(id)` — это баг тестовой инфраструктуры (порча схемы), а не целевой rowid-reassignment сценарий, который тест должен проверять.
- **Fix:** Тест теперь копирует DDL таблицы `devices` через `SELECT sql FROM sqlite_master WHERE name = 'devices'` (сохраняет `PRIMARY KEY`/все ограничения), затем делает `INSERT INTO devices_rebuilt (<колонки без id>) SELECT <те же колонки> FROM devices` — явное исключение `id` из списка колонок заставляет собственный `AUTOINCREMENT`-счётчик новой таблицы назначить свежий физический rowid (с 1), моделируя худший случай WR-01 без порчи схемы.
- **Files modified:** `crates/trackly-infra/src/db/migrations.rs` (только тестовый код)
- **Verification:** Тест зелёный; sanity-assert `assert_ne!(after_rebuild, before_rebuild)` подтверждает, что rowid реально изменился; мутационная проверка (временный откат `violations_with_grown_signature` на `after.difference(&baseline)`) красит именно этот тест.
- **Committed in:** `cc340890` (Task 2 commit)
