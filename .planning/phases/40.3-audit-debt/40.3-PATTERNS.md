```rust
if let Some(inner) = dto.place_id {
```

#### `crates/trackly-infra/src/repos/devices_sqlite.rs` — SQL, ДВЕ копии

**Analog:** тот же файл, `inventory_number`/`place_id` CASE-паттерн — уже реализован ДВАЖДЫ
(в `update_in_tx`, строки 280/285, и в `update`, строки 701/706) — WR-03 распространяет тот же
приём на serial_number/model/condition/complectation/notes В ОБЕИХ копиях.

**Текущий SQL в `update_in_tx` (строки 277-290):**
```sql
"UPDATE devices SET
   name             = COALESCE(?1, name),
   type_id          = COALESCE(?2, type_id),
   inventory_number = CASE WHEN ?3 = 1 THEN ?4 ELSE inventory_number END,
   serial_number    = COALESCE(?5, serial_number),
   model            = COALESCE(?6, model),
   condition        = COALESCE(?7, condition),
   complectation    = COALESCE(?8, complectation),
   place_id         = CASE WHEN ?9 = 1 THEN ?10 ELSE place_id END,
   status_id        = COALESCE(?11, status_id),
   notes            = COALESCE(?12, notes),
   version          = version + 1,
   updated_at_utc   = ?13
 WHERE id = ?14 AND version = ?15 AND deleted_at_utc IS NULL",
rusqlite::params![
    patch.name.as_deref(),
    patch.type_id,
    patch.inventory_no.is_some() as i64,
    patch.inventory_no.as_ref().and_then(|v| v.as_deref()),
    patch.serial_no.as_deref(),
    patch.model.as_deref(),
    patch.state.as_deref(),
    patch.kit.as_deref(),
    patch.place_id.is_some() as i64,
    patch.place_id.flatten(),
    patch.status_id,
    patch.specs.as_deref(),
    now_utc,
    id,
    version,
],
```

**Целевой SQL (по образцу `inventory_number`/`place_id` — CASE + is_some() as i64 флаг + значение
для каждого из 5 полей).** Позиционные `?N` после вставки 5 новых флагов ПОЛНОСТЬЮ пересчитать —
не полагаться на текущую нумерацию:
```sql
UPDATE devices SET
   name             = COALESCE(?1, name),
   type_id          = COALESCE(?2, type_id),
   inventory_number = CASE WHEN ?3  = 1 THEN ?4  ELSE inventory_number END,
   serial_number    = CASE WHEN ?5  = 1 THEN ?6  ELSE serial_number END,
   model            = CASE WHEN ?7  = 1 THEN ?8  ELSE model END,
   condition        = CASE WHEN ?9  = 1 THEN ?10 ELSE condition END,
   complectation    = CASE WHEN ?11 = 1 THEN ?12 ELSE complectation END,
   notes            = CASE WHEN ?13 = 1 THEN ?14 ELSE notes END,
   place_id         = CASE WHEN ?15 = 1 THEN ?16 ELSE place_id END,
   status_id        = COALESCE(?17, status_id),
   version          = version + 1,
   updated_at_utc   = ?18
 WHERE id = ?19 AND version = ?20 AND deleted_at_utc IS NULL
```
с параметрами `patch.serial_no.is_some() as i64, patch.serial_no.as_ref().and_then(|v| v.as_deref())`
и аналогично для model/state(condition)/kit(complectation)/specs(notes) — точно как
`patch.inventory_no.is_some() as i64, patch.inventory_no.as_ref().and_then(|v| v.as_deref())` уже
делает.

**КРИТИЧНО (Pitfall 3, подтверждено этим сеансом):** идентичный блок SQL присутствует ВТОРОЙ раз
в функции `update` (строки 698-711, вызывается напрямую, не через транзакцию — НЕ snapshot-
restore, обычный non-tx update-путь трейта). Обе копии требуют идентичной правки, иначе баг
останется в одном из двух write-путей.

```rust
    tx: &rusqlite::Transaction<'_>,
    device_id: i64,
    type_id: i64,
    now_utc: i64,

    match type_id {

            if !printer_repo.exists_for_device_in_tx(tx, device_id)? {
                printer_repo.create_in_tx(
                    tx,
```

**Analog:** тот же файл `crates/trackly-infra/src/db/migrations.rs` — `fk_violations` (строки

```rust
    let goal = i64::from(target.unwrap_or_else(max_known_version));
    let pending = match last_applied_version(conn)? { None => true, Some(v) => v < goal };

    // NEW: читается БЕЗУСЛОВНО, не только внутри `if pending`.
    let baseline = read_persisted_baseline(conn)?.unwrap_or(fk_violations(conn)?);

    let report = if pending {
        /* как сейчас: FK off, run, FK restore */
    } else {
        build_runner(target)?.run(conn).map_err(/* ... */)?
    };

    // NEW: считается БЕЗУСЛОВНО на каждом старте, не только при pending.
    let after = fk_violations(conn)?;
    let new_violations: Vec<_> = after.difference(&baseline).collect();
    if !new_violations.is_empty() {
        return Err(/* как сейчас, текст ошибки не менять */);
        // baseline НЕ обновляется — следующий старт снова заблокирован.
    }
    persist_baseline(conn, &after)?; // NEW: self-heal только когда чисто

    /* ... schema_version читается как сейчас ... */
}
```

**Хранение бейзлайна — guarded single-key read, аналог `place_path_settings.rs`:**
`crates/trackly-infra/src/repos/place_path_settings.rs:66-80` — guarded-read одного ключа
`app_settings`, отсутствие строки — не ошибка:
```rust

```
И запись — аналог `cartridges_sqlite.rs:2754`:
```rust
"INSERT INTO app_settings (key, value, created_at_utc, updated_at_utc) \

```
**Пограничный случай (WR-08/place_path_settings-подобный):** на БД, которая сама проходит
миграцию, создающую `app_settings` (V016), в ЭТОМ ЖЕ запуске — трактовать отсутствие таблицы как

состояние раннера миграций в самой БД» ни для того, ни для другого варианта.

## Shared Patterns

### Double-Option "не передано / очищено / новое значение"
**Source:** `crates/trackly-core/src/domain/devices.rs` (`inventory_no`, `place_id`) +
`crates/trackly-app/src/dto/device.rs` (`place_id`, после WR-03 — все 6 nullable полей)
**Apply to:** WR-03 (все три слоя) — единственный устоявшийся в проекте способ различить три
состояния partial-update поля; НЕ изобретать вариант с sentinel-значениями или отдельным булевым
флагом рядом с полем.

### `serde_with::rust::double_option` для JSON-границы
**Source:** внешняя библиотека, уже в workspace-зависимостях (`Cargo.toml:23`, `version = "3"`)
**Apply to:** ЛЮБОЕ DTO-поле `Option<Option<T>>`, которое реально десериализуется из
пользовательского JSON (не только внутренних Rust-вызовов) — без этого атрибута double-Option
молча не работает через транспорт (Pitfall 1). `place_id` сегодня НЕ имеет этого атрибута и
работает только по случайности пути данных (Assumption A1, RESEARCH) — не копировать это как
образец для новых полей, красным флагом должен быть любой DTO double-Option БЕЗ этого атрибута.

### `notifyPlaceContentChanged` после мутации с местом
**Source:** `ui/src/features/devices/DevicesPage.svelte:168-186` (`onSaved`)
**Apply to:** N-2 (`PrintersPage.svelte`'s новый `onSaved`) — тот же расчёт
`oldPlaceId`/`newPlaceId` → `Set` → `notifyPlaceContentChanged`.

### INV-7 `MUTATING_COMPONENTS` реестр
**Source:** `ui/scripts/check-place-tree-invalidation.mjs:706-711`
