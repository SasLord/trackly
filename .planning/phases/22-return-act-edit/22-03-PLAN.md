<objective>
Expose `ActService::update_return()` (built in Plan 22-02) through both transports Trackly
supports — Tauri `invoke` for the desktop webview and `/api/v1` HTTP for LAN browser clients
— using the exact thin-adapter pattern every other act mutation already follows. Gate the new
command with the same `Action::MutateActs` RBAC check as `acts_update`/`acts_return`/
`acts_delete` (no new `Action` enum variant). Regenerate `bindings.ts` so the frontend (Plan
22-04) can compile against real generated TypeScript types.

Purpose: Close the wire-level gap between the working service method and the UI; this plan is
pure plumbing — no new business logic, only routing + RBAC gate + type export.
Output: `acts_update_return` reachable via Tauri invoke and HTTP POST; RBAC test proving
Employee rejection; frontend client method; regenerated bindings.ts.
</objective>
