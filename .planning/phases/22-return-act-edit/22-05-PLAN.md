<objective>
Fix the two BLOCKER-severity defects found by the Phase 22 code review
(`.planning/phases/22-return-act-edit/22-REVIEW.md`, CR-01 and CR-02) in
`ActService::update_return()`'s delta engine, and add the regression tests
that would have caught them (none of the 11 existing `acts_update_return.rs`
tests exercise an empty-bulk-location edit or a chained
edit-then-un-return sequence).

Purpose: `update_return` currently (a) silently NULLs a retained device's
warehouse location whenever a condition-only edit is submitted with no bulk
location (data loss, reachable through the shipped `ReturnModal`), and (b)
restores an un-returned device from the WRONG audit snapshot when that
device was previously condition/location-edited within the same return,
leaving it stuck `на_складе` while the parent handover counts it as
outstanding (corrupt, unrecoverable-without-audit state).

Output: `update_return`'s added/retained device-mutation loops preserve a
device's current location when no new location is supplied; un-return
restore is scoped to exclude retained-edit audit rows via a distinct audit
`action` tag; both fixes are covered by new integration tests in
`acts_update_return.rs` plus one new repo-level unit test in
`audit_log_sqlite.rs`.
</objective>
