   `location_name_override`) required (field
   `"items[{idx}].location_id_override"`, message "Расположение обязательно
   (apply_to_all = false)").

`do_return`'s over-return guard (lines 1314-1347, the SOURCE pattern for
WR-03) computes, per device: `handover_qty` = `SELECT COALESCE(SUM(quantity),
0) FROM act_items WHERE act_id = ?1 AND device_id = ?2`; `already_returned` =
`SELECT COALESCE(SUM(rai.quantity), 0) FROM act_items rai JOIN acts ra ON
ra.id = rai.act_id WHERE ra.parent_act_id = ?1 AND rai.device_id = ?2 AND
ra.deleted_at_utc IS NULL`; then rejects with `AppError::Validation` when
`per_device_qty + already_returned > handover_qty`.
`update_return`'s step 8a "added" validation loop (lines 1654-1681) has the
existence check and the `in_work_status_id` status guard but NOT this bound.
`parent_act_id` (the SUBSTITUTE for `do_return`'s `act_id` parameter in both
queries above — same semantic value, the parent handover's id) is already
resolved at line 1541-1543.

`act_service.rs` line 1541-1543 (WR-02 target): `let parent_act_id = act
.parent_act_id.expect("return act always has parent_act_id");` — this runs
inside `self.writer.execute(move |conn| { ... })`, the single-writer closure
(CLAUDE.md: "NEVER panic inside the writer task").

`None` effective value as "no change" (`unwrap_or(false)`).
