<objective>
Wire the working backend (Plans 22-01..22-03) into the UI: make «Редактировать» functional
on return-act cards by reusing `ReturnModal.svelte` in a new edit mode — visually identical
to the create-mode dialog, per the Phase 19 precedent (D-10) of reusing the create form for
edit — prefilled from BOTH the return's own saved items and the parent's still-outstanding
items, with the ФИО swap logic skipped (prefill directly from the return's own values, D-12)
and a new «Дата возврата» date-picker (D-03/D-04) reusing `ActFormBody`'s exact date-picker
pattern. **Also fix the create-mode submission path** so that RESEARCH.md's Pitfall 1
(silent-drop of giver_name/receiver_name/handover_date_utc) is closed end-to-end: the
backend's `do_return` fix (Plan 22-02 Task 1) and the new «Дата возврата» field (D-04, present
in BOTH modes) are unreachable unless the create-mode payload literal actually sends these
three fields — this plan is the ONLY place that wiring happens.

Purpose: This is the user-facing delivery of ACT-03 — the only plan a human will actually
interact with to confirm the feature works end-to-end, and the only plan that makes the
create-mode half of Pitfall 1's fix (backend already accepts the fields since Plan 22-02)
actually reachable from the UI.
Output: Working «Редактировать» on return-act cards; edit dialog prefilled and functional;
create dialog now persists user-entered ФИО and «Дата возврата» instead of silently dropping
them; reactive detail-view refresh on save.
</objective>
