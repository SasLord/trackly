# Phase 22 Plan 03: Return-Act Edit — Transports Summary

**`acts_update_return` wired through both Tauri `invoke` and `/api/v1` HTTP as thin `authorize(&Action::MutateActs)` adapters over `ActService::update_return()` (Plan 22-02), with an RBAC regression test, a typed frontend client method, and bindings.ts regenerated to expose the real generated types for Plan 22-04's UI work.**

## Performance

- **Duration:** ~25 min (pure plumbing plan, no new business logic — smallest plan in the phase so far)
- **Completed:** 2026-07-13
- **Tasks:** 2/2 completed
- **Files modified:** 6

## Accomplishments

- **Task 1 — Tauri + HTTP transport wiring:** `build_acts_update_return(ctx, caller, payload: ActUpdateReturnDto) -> Result<ActDto, AppError>` added to `tauri_cmds/acts.rs`, calling `authorize(caller, &Action::MutateActs)?` then `ctx.acts.update_return(payload).await` — byte-identical shape to `build_acts_update`. `#[tauri::command] #[specta::specta] acts_update_return` wraps it and is registered in `specta_export.rs`'s `collect_commands!` list. `http/acts.rs` gained `UpdateReturnPayload { payload: ActUpdateReturnDto }` (`rename_all = "camelCase"` on the wrapper struct only, per the module's existing convention — the nested DTO keeps its own snake_case per S-2), `handler_update_return`, and `.route("/api/v1/acts_update_return", post(handler_update_return))` registered next to the existing `acts_update`/`acts_return` routes.
- **Task 2 — RBAC test, frontend client, bindings regeneration:** Added Case 43 to `role_endpoint_matrix.rs` — Employee session POSTing to `/api/v1/acts_update_return` gets `403 Forbidden`, proving the same `Action::MutateActs` gate rejects before any act lookup (mirrors Case 42's `acts_update` precedent exactly). Extended `export_bindings.rs` with assertions for `ActUpdateReturnDto`, the `acts_update_return` command, and the extended `ActReturnDto` (`giver_name`/`receiver_name`/`handover_date_utc`) and `ActItemDto` (`device_location_id`/`device_location`) fields — all confirmed snake_case on the TS side, consistent with every other act DTO in the module. `ui/src/lib/api/acts.ts` gained `acts.updateReturn: (payload: ActUpdateReturnDto) => apiCall<ActDto>('acts_update_return', { payload })`, typed against the real regenerated `bindings.ts` (not hand-typed guesses).
