<objective>
Lay the interface groundwork for return-act editing (ACT-03): extend the DTOs that the
backend service, transports, and frontend will all consume; add the audit-log repo helper
that Plan 22-02's D-11 safety check depends on; add per-item device-location data so the
edit form can prefill "Расположение"; and backfill existing return rows' `handover_date_utc`
so it stops meaning "copied from parent" and starts meaning "Дата возврата" (D-03/D-05/D-08).

This is the "Wave 0" interface-contracts step for the whole phase — Plan 22-02
(`ActService::update_return`), 22-03 (transports), and 22-04 (UI) all build directly against
the structs and helper created here. No business logic runs yet; this plan only shapes the
wire contract and one pure-data migration.

Purpose: Give every downstream plan in this phase a stable, already-compiling contract to
implement against, avoiding scavenger-hunt exploration mid-implementation.
Output: `ActUpdateReturnDto` struct, extended `ActReturnDto`/`ActItemDto`, new
`select_latest_device_mutation_pair` repo fn, `V034` migration, extended `load_items_for_act`
SQL.
</objective>
