<objective>
Удаление акта должно освобождать его номер. Сейчас после soft-delete акта №20 создать новый акт
с номером 20 нельзя ни вручную (`number_override`), ни через кнопку «Следующий»: уникальность в
`ActService::create`/`update` проверяется по ВСЕМ строкам `acts` (включая soft-deleted, комментарий
ссылается на `D-Soft-vs-Hard-Acts-01`), а автономер берётся из монотонного `counters.act_number`,
который никогда не откатывается назад.

Решение (зафиксировано в CONTEXT.md, отменяет часть `D-Soft-vs-Hard-Acts-01` про блокировку номера
удалённого акта, остальная часть — soft-delete акта + hard-delete `act_items` — не трогается):
- Обе проверки уникальности (`create` и `update`) фильтруются по `deleted_at_utc IS NULL` — это
  ровно то, что уже покрывает существующий частичный уникальный индекс
  `idx_acts_number_sub_unique` (`WHERE deleted_at_utc IS NULL`, `V004__acts.sql`) — схему менять не
  нужно.
- Автономер и подсказка «Следующий» перестают использовать `counters.act_number` и берут
  `MAX(number) + 1` среди живых актов, с fallback на 1 для пустой таблицы.
- Гонок нет: единственный писатель (`WriterHandle`) + `BEGIN IMMEDIATE`, `MAX` вычисляется внутри
  той же write-транзакции, что и `INSERT`.
- Оба транспорта (Tauri command `acts_peek_next_number` и HTTP `/api/v1/acts_peek_next_number`,
  оба — `create`/`update`) идут через один и тот же `ActService`, так что правка сервисного слоя
  автоматически покрывает оба.
- Фронтенд не трогаем: `ActNumberField.svelte` только сравнивает введённое значение с результатом
  `acts.peekNextNumber()` для показа бейджа «override» — своей копии формулы номера у него нет
  (проверено grep по `ui/src`), значит после бэкенд-фикса бейдж естественным образом перестанет
  появляться, когда пользователь ничего не вводит вручную.

Purpose: убрать искусственную блокировку номеров удалённых актов — акты нумеруются «одной кнопкой»
без ручного управления счётчиком, даже после удаления/отмены создания.

Output: `next_act_number_from_max` — единственная функция источника истины для авто-номера
(заменяет чтение/запись `counters.act_number` на пути актов); обновлённые уникальность-проверки в
`create`/`update`; 2 новых unit-теста на саму функцию + 3 новых интеграционных теста через
`ActService` (create-путь, update-путь, `peek_next_number` после удаления последнего акта).
</objective>
