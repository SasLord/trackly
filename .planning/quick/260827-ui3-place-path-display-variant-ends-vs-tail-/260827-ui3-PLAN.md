<objective>
Сегодня формат сокращения пути места («последние два сегмента») зашит буквально в двух местах
фронтенда (`ReportTable.svelte::shortPlacePath`, `PlaceContents.svelte::shortPath`) — независимые
копии одной и той же логики, без единой точки правды и без возможности переключить формат. Владелец
продукта просит второй вариант отображения — «начало // конец» (например «Здание А // Кабинет
214»), который должен стать вариантом ПО УМОЛЧАНИЮ, с переключением через `trackly.config.toml`.

**Дизайн-решение 1 — модель конфига.** Новый `enum PlacePathDisplay { Ends (#[default]), LastTwo,
Full }` в `crates/trackly-infra/src/config.rs`, ровно по образцу уже существующего в этом же файле
`LdapTlsMode` (unit-enum, `#[serde(rename_all = "snake_case")]`, `#[derive(..., Default)]` с
`#[default]`-вариантом). Новое поле `OrganizationConfig.place_path_display` — `#[serde(default)]`
(опционально, в отличие от соседнего обязательного `timezone`): старые/частично заполненные секции
`[organization]` без этого ключа не ломаются, получают дефолт `Ends`. Нераспознанное строковое
значение (например `place_path_display = "brief"`) НЕ обрабатывается через `#[serde(other)]`
fallback — это НЕ новый прецедент, а то же самое поведение, что уже принято для `ldap_tls_mode`:
`toml::from_str::<AppConfig>` возвращает `Err` на весь файл, `AppConfig::load_or_default` пробрасывает
`AppError::Validation`, а `trackly_app::config_recovery::load_or_recover` (существующий, не
трогаем) откатывается на `AppConfig::default()` целиком (т.е. и на `PlacePathDisplay::Ends`) и
пишет причину в `config-error.txt`/диалог. Один согласованный failure-механизм на весь конфиг, а
не отдельная ветка обработки для одного поля.

**Дизайн-решение 2 — плумбинг до фронтенда.** НЕ заводим новый Tauri-command/HTTP-route. Значение
кладём третьим полем в уже существующий `AuthStatusDto` (`needs_bootstrap`, `desktop_lock_enabled`,
`user`), который отдают ОБА транспорта: `build_auth_status` (`http/auth.rs`, публичный роут без
session-гейта) и `build_auth_status_tauri` (`tauri_cmds/auth.rs`). Обоснование выбора именно этого
DTO, а не нового `settings_get_place_path_display`-роута по образцу `settings_org.rs`:
- `auth_status` и так вызывается ОДИН раз на каждом старте приложения (`App.svelte::loadAuthStatus`),
  ДО и НЕЗАВИСИМО от состояния логина — то есть значение гарантированно доступно к моменту рендера
  любого защищённого экрана, без дополнительного round-trip и без риска 401-редиректа на `#/login`
  (`apiCall` шлёт именно туда при 401), которым грозил бы session-гейтед `settings_get_*`-роут,
  вызванный до входа.
- В `AuthStatusDto` уже есть прецедент «bootstrap-конфиг рядом с live-данными» —
  `desktop_lock_enabled` ровно такой же read-only флаг из bootstrap-слоя, что и наш.
- Оба билдера уже принимают `&AppCtx` с `ctx.config: Arc<AppConfig>` — правка это одна новая
  строка в каждом из двух `Ok(AuthStatusDto { ... })`.

**Путь миграции на будущий admin-editable app_settings** (владелец продукта сказал «пока» через
config.toml): когда придёт время сделать значение редактируемым из UI, меняется ТОЛЬКО тело этих
двух `build_auth_status*`-функций — они начинают читать `app_settings` с фолбэком на
`ctx.config.organization.place_path_display`, зеркаля ровно то, как уже устроена пара
`low_stock_basis`/`LowStockBasis::DEFAULT` в `tauri_cmds/settings_org.rs`. Имя поля DTO, транспорт,
и весь фронтенд-код (Задача 2) не меняются вообще — это не переписывание, а замена источника внутри
уже существующей точки чтения.

**Дизайн-решение 3 — единая функция сокращения на фронтенде.** Новый чистый TS-модуль
`ui/src/lib/utils/placePath.ts` (по образцу соседних `pluralize.ts`/`date.ts` — без рун, plain
functions) с одной функцией `shortenPlacePath(fullPath, variant)`, которая заменяет ОБЕ существующие
дублирующие реализации (`ReportTable.svelte::shortPlacePath`, `PlaceContents.svelte::shortPath`).
Значение варианта живёт в `authStore` (`ui/src/lib/stores/auth.svelte.ts`, уже существующий `$state`
store), заполняется в уже существующем `App.svelte::loadAuthStatus()` — НЕ новый жизненный цикл, а
одна новая строка присваивания в уже вызываемой функции. Дефолт стора — `'ends'`, совпадает с
бэкенд-дефолтом: до завершения boot-фетча или при его ошибке рендер уже показывает правильный
дефолтный вариант, а не пустую ячейку.

**Область применения (подтверждена владельцем продукта) — везде, где путь места СЕГОДНЯ
сокращается, плюс два очевидных узкоколоночных списка, которые сокращения ещё не имеют, но живут в
той же природе (узкая колонка таблицы):**
- `ReportTable.svelte` (отчёты, включая композитную колонку «Заявки» — только путевая часть).
- `PlaceContents.svelte` («Содержимое места»).
- `DeviceListRow.svelte` (список устройств, колонка «Место») — новое применение.
- `CartridgeListRow.svelte` (список картриджей, колонка «Место») — новое применение.

**НЕ трогаем** (осознанно, детальные/дизамбигуационные/печатные контексты, где сегодня НЕТ
сокращения — полный путь там уместнее узкой таблицы): `ActDetail.svelte`, `CartridgeDetail.svelte`,
`PrinterDetail.svelte`, `ReturnModal.svelte` (список выбора места — полный путь снимает
неоднозначность), `PlaceTree.svelte` (результаты поиска — тоже дизамбигуация). Печатные шаблоны и
CSV/PDF-экспорт отчётов не меняются — экспорт и так отдаёт несокращённую строку (закреплено
quick-задачей 260827-gim), эта задача не переопределяет то поведение.

**Критично — не регрессировать 260827-gim.** `ReportTable.svelte::formatPlaceCell(row, col,
transformPath)` — единственная точка, куда подставляется функция сокращения; префикс
(`col.compositeWith`, имя принтера) читается как ОТДЕЛЬНОЕ поле строки и никогда не проходит через
`transformPath`. Эта задача меняет ТОЛЬКО то, какая функция передаётся как `transformPath`
(`shortPlacePath` → `(p) => shortenPlacePath(p, authStore.placePathDisplay)`), саму функцию
`formatPlaceCell` и её вызовы не трогает.

Purpose: убрать дублирование логики сокращения (два независимых бага вместо одного), дать владельцу
продукта предпочитаемый им формат по умолчанию, оставить путь к смене формата без правки кода.

Output: единая функция сокращения на фронтенде с двумя переключаемыми вариантами + вариантом «без
сокращения»; конфигурируемый дефолт «начало // конец»; значение долетает до обоих транспортов через
уже существующий boot-time DTO.

  export function normalizePlacePathDisplay(raw: string | null | undefined): PlacePathDisplay {
    return raw === 'ends' || raw === 'last_two' || raw === 'full' ? raw : 'ends';
  }

  export function shortenPlacePath(fullPath: string, variant: PlacePathDisplay): string {
    if (!fullPath) return fullPath;
    const segments = fullPath.split(' / ');
    if (variant === 'full' || segments.length <= 2) return fullPath;
    if (variant === 'last_two') return segments.slice(-2).join(' / ');
    return `${segments[0]} // ${segments[segments.length - 1]}`;
  }
