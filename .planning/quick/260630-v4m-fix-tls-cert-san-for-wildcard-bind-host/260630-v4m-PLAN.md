# Quick Task 260630-v4m: Fix TLS cert SAN for wildcard bind host

## Problem

`generate_self_signed(host)` in `crates/trackly-app/src/server/tls.rs` builds the
cert SAN as `[host, "localhost"]`. When the bind host is the wildcard `0.0.0.0`
(or `::`, or empty), the SAN contains the literal `"0.0.0.0"` + `"localhost"` —
neither matches the machine's real LAN IP that browsers connect to
(`https://<LAN-IP>:port`). After the bind fix (commit 4ec2a9b), LAN browsers
still get a **hostname-mismatch** cert error on top of the expected
self-signed-untrusted warning, worsening the fingerprint-trust UX.

This is a secondary/UX issue, not the connectivity blocker (that was the
bind-host fix).

## Approach

When `host` is unspecified/wildcard (`0.0.0.0`, `::`, or empty), enumerate the
machine's non-loopback IPv4/IPv6 addresses and add them to the cert's SANs.
rcgen 0.14's `generate_simple_self_signed` → `CertificateParams::new` already
auto-classifies each SAN string: `IpAddr::from_str` success → IP SAN, else
DnsName. So pushing IP strings is sufficient — no manual `SanType` construction.
Also add the OS hostname (validated as a DNS label) and always keep `"localhost"`.

New deps (pure-Rust, portable, no DLL shipping):
- `if-addrs` — cross-platform interface enumeration (Windows/macOS/Linux).
- `hostname` — cross-platform OS hostname.

## Tasks

1. **Add deps** — `if-addrs` + `hostname` to `[workspace.dependencies]` in root
   `Cargo.toml` and reference them from `crates/trackly-app/Cargo.toml`.
   - verify: `cargo metadata` resolves; build compiles.
   - done: both crates present in lockfile.

2. **Implement SAN detection** — add `is_wildcard_host` + `collect_subject_alt_names`
   helpers in `tls.rs`; `generate_self_signed` builds its SAN list via the helper.
   Non-wildcard host keeps the original `[host, "localhost"]` behaviour.
   - files: `crates/trackly-app/src/server/tls.rs`
   - verify: `cargo build -p trackly-app`
   - done: wildcard host produces SANs including detected LAN IPs + hostname + localhost.

3. **Unit test + regression check** — test that `collect_subject_alt_names("0.0.0.0")`
   includes at least one detected non-loopback IP (or documents none detected when
   the test host has no usable interfaces). Run tls test suites + clippy.
   - verify: `cargo test -p trackly-app --test tls_server_smoke` and tls unit tests pass;
     `cargo clippy -p trackly-app`.
   - done: new test passes, `tls_server_smoke` + `generate_self_signed_does_not_panic` green.
