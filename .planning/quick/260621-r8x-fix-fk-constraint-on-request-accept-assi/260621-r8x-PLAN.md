# Quick Task 260621-r8x: Fix FK constraint on request accept

## Problem

Admin "Принять в работу" (accept request) failed with
`conflict: FOREIGN KEY constraint failed`, while "Отклонить" (reject) worked.

**Root cause:** the UI (`RequestDetail.svelte` `handleAccept`) sent
`assignedToUserId: identity?.id`. In unlocked-desktop mode `authStore.user.id`
is the sentinel `0` ("Рабочий стол", set in `App.svelte`), which has no `users`
row → violates `requests.assigned_to_user_id → users(id)`. Reject sends no
assignee, so it worked.

## Tasks

1. **Backend (authoritative fix):** `RequestService::transition` Accept branch
   resolves the assignee from `caller.user_id` (the acceptor), ignoring the
   client-supplied `assigned_to_user_id`. `None` for trusted-desktop → COALESCE
   keeps the existing value → no invalid FK. Mirrors the D-REQ-01 server-side
   override pattern.
2. **Frontend cleanup:** `handleAccept` sends `assignedToUserId: null` (backend
   owns resolution). Payload field kept for type compatibility.
3. **Regression test:** `tests/request_accept_assignee.rs` — trusted-admin
   (`user_id: None`) accept with a forged `assigned_to_user_id: Some(0)`
   succeeds and moves to `in_progress` (pre-fix this FK-failed).
