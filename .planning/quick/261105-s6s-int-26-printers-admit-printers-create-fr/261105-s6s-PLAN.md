# Quick 261105-s6s: INT-26 — `printers_admit` пишет строку `printers` дважды

## Проблема

`build_printers_admit` (tauri_cmds/printers.rs) делает:
3. `ctx.devices.create(DeviceNew{type_id: 2, …})` — внутри транзакции устройства
   `sync_printer_row_in_tx` уже создаёт строку `printers` (без IP, community = public)
   и коммитит;
4. `ctx.printers.create_from_device(...)` — второй INSERT по тому же `device_id` →
   нарушение `printers.device_id UNIQUE`.

Итог: команда падает, в БД остаётся принтер без IP/community; страж дубликата по
`ip_address` его не видит, повтор плодит новое устройство.

## Решение

Не «второй шаг поверх», а одна транзакция: IP и community уходят в
`sync_printer_row_in_tx` как `printer_override` (тот же механизм, что у формы
«Новый принтер», Phase 40.3 Plan 04). Строка `printers` создаётся СРАЗУ с сетью;
шаг 4 удалён. Сбой валидации IP откатывает и устройство — сирот не остаётся.
