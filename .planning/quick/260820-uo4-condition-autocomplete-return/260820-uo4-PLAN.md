<objective>
В разделе «Акты» модал «Возврат» (`ReturnModal.svelte` + `ReturnItemsTable.svelte`) сейчас
рендерит поля «Состояние» (bulk и per-row) как обычные `<Input>` — без автокомплита и без
дропдауна вообще. Одновременно уже существующий переиспользуемый автокомплит
`DeviceAutocompleteField.svelte` (поле «Состояние» в попапах «Добавить устройство/принтер» и
«Редактирование устройства/принтера») показывает только ранее введённые значения — без шести
стандартных вариантов (Новое, Б/У, Хорошее, Среднее, Плохое, На списание), которые должны быть
видны всегда, даже если их никогда не вводили.

Ключевое проектное решение (зафиксировано после чтения кода): стандартные варианты добавляются
**только на фронтенде**, внутри `DeviceAutocompleteField.svelte`, мержем в существующий
реактивный список подсказок для `field === 'state'` — по тому же паттерну, что уже применён для
`field === 'location'` (`allLocationSuggestions` + `allItems`-derived). Это даёт три вещи разом:
(а) дефолты появляются одновременно и в Акты→Возврат, и в попапах устройства/принтера — БЕЗ
дублирования логики, т.к. все три места используют один и тот же компонент; (б) никаких записей
фейковых данных в БД; (в) де-дуп корректен «из коробки», т.к. фильтрация делается по уже
загруженному `suggestions` в момент рендера.

Backend НЕ трогаем: `devices_autocomplete`/`devices_state_hints` (crates/trackly-app/src/services/
device_service.rs) не меняются. Существующий `STATE_HINTS`/`stateHints()` (используется ТОЛЬКО для
чипов «Быстрый выбор» в `DeviceFormBody.svelte`, отдельный, более длинный список) тоже не
трогается — он вне скоупа этой задачи (пользователь просил дефолты именно в дропдауне
автокомплита, а не в чипах).

Purpose: пользователь заводящий возврат по акту получает подсказки состояния устройства (как уже
есть для расположения), не набирая типовые формулировки вручную и не рискуя опечаткой/разнобоем
формулировок («Хорошее» vs «хорошее» vs «хор.») — те же стандартные варианты видны и в формах
устройства/принтера.

Output: рабочий автокомплит-дропдаун со стандартными + ранее использованными значениями
«Состояние» в bulk- и per-row-полях модала «Возврат»; тот же дропдаун в попапах
устройства/принтера дополнительно всегда показывает шесть стандартных вариантов.
</objective>
