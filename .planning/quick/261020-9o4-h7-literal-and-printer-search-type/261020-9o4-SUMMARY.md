# Quick 261020-9o4: [H7] без литерала listGen, поиск принтеров через devices.list

Правило [H7] теперь принимает у `<DeviceList` и `<DeviceGroupRow` только идентификатор `listGen` (`{listGen}` или `listGen={listGen}`). Поиск принтеров для группы идёт одним `devices.list` с `type_id`, а не через `listGrouped`, и call-site закреплён новым гейтом в `pnpm lint`.

## Задача 1. TD-1: [H7] принимал литерал

Регулярка проводки в `checkListGen` содержала альтернативу `\blistGen\s*=`, она пропускала `listGen={0}`. Заменена на `(?<=\s)(?:\{\s*listGen\s*\}|listGen\s*=\s*\{\s*listGen\s*\})(?![\w$])`. Сообщение называет причину (литерал или чужое имя пропа замораживает ключ кеша `idsKey@listGen`). Шапка и докстринг правила обновлены.

**Попутная находка (Rule 1, в том же файле).** Проверка Props («необязателен или значение по умолчанию») грепала `\blistGen\s*=` по ВСЕМУ тексту `DeviceList.svelte`, поэтому законная запись `listGen={listGen}` у `<DeviceGroupRow` краснела по этому правилу (старый гейт: exit 1 на законной форме). Перед проверкой Props теперь вырезается ровно подстрока `listGen={listGen}`. Литерал `listGen={0}` и `listGen = 0` в деструктуризации остаются красными (мутант `h7-default-value`). Без этого критерий «`listGen={listGen}` зелёный» не выполнялся для `DeviceList`.

Мутанты самотеста (по РЕАЛЬНЫМ файлам через `mutate()`, якоря уникальны, иначе `exit 1`): `h7-page-literal`, `h7-list-literal`, `h7-page-wrong-name`, `h7-default-value`; зелёные формы `listGen={listGen}` в обоих местах.
