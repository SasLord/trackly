# Quick Task 260724-pxf — Summary

Fixed two confirmed pre-existing logic bugs surfaced by the phase-29 code review
(`.planning/phases/29-login-and-employee-shell/29-REVIEW.md`). Phase 29 was a
CSS/markup-only migration; neither bug was introduced by it.

## WR-01 — WS refcount leak on fast unmount
**File:** `ui/src/features/layout/EmployeeLayout.svelte` (onMount)

`connectWs()` (`ui/src/lib/api/ws.ts`) increments the shared `refCount`
synchronously but resolves its teardown function asynchronously via `.then()`.
If the component unmounted before the promise resolved, the returned cleanup ran
while `unlisten` was still `undefined`, so the later-arriving release never fired
and `refCount` never decremented — the WS singleton/reconnect machinery leaked
across fast mount/unmount cycles.

**Fix:** Added a `disposed` flag. The cleanup closure sets `disposed = true`; the
`.then()` handler calls the release fn immediately when `disposed` is already
true, otherwise stores it in `unlisten` as before. Verified against `ws.ts`: the
release fn is idempotent (`released` guard + `refCount = Math.max(0, …)`), so an
immediate call is safe and always decrements exactly once.

## WR-02 — empty-string rejection_reason misclassified
**File:** `ui/src/features/auth/BlockedScreen.svelte` (rejected-state branch)

The `{:else if}` selecting the "Запрос отклонён" state used a truthiness test on
`rejection_reason`. `LoginPage.svelte` normalization preserves `""` (any string,
including empty), and the backend (`crates/trackly-app/src/services/auth.rs`)
derives `rejection_reason` from free-form `resolution_notes`, which can be empty.
A rejected request with an empty reason therefore fell through to the first-time
"Доступ закрыт" screen instead of "Запрос отклонён".

**Fix:** Changed the condition to `blockedDetails.rejection_reason !== null`,
distinguishing `null` (no restore request yet) from `""` (rejected, empty reason).
