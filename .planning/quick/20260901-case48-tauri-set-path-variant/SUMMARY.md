# Quick: Case 48 — седьмая мутация на Tauri-транспорте (остаток IN-02)

## Задача

Фаза 39.2 закрыла IN-02 только на HTTP-транспорте: Case 45 расширен седьмой мутацией
и добавлен Case 51. Case 48 (Manager на Tauri-пути) остался на шести `build_places_*`
мутациях — `build_places_set_path_variant` не проверялся.

Верификатор фазы оценил это как WARNING, а не блокер, и был прав по существу:
`authorize(caller, &Action::MutatePlaces)` стоит первой строкой ВНУТРИ
`build_places_set_path_variant` (`tauri_cmds/places.rs`), а HTTP-хендлер и Tauri-команда
обе лишь делегируют — то есть Case 45 уже бил в ту же строку. Остаточная проблема
чисто структурная: если Tauri-команда однажды перестанет делегировать, дырка откроется
молча.

## Изменения

`crates/trackly-app/tests/role_endpoint_matrix.rs` — единственный тронутый файл:
- импорт `build_places_set_path_variant`;
- седьмая проверка в блоке Case 48 (Manager → `Err(AppError::Forbidden)`);
- шапка модуля и комментарий блока: «six» → «seven», с указанием, откуда взялась седьмая.

Продакшн-код не менялся.

## Мутационная проверка (и ошибка в ней, которую стоит记录)

Зелёный тест ничего не доказывает, пока не показал, что умеет краснеть. Проверка заняла
четыре захода, потому что первые три были **мис-таргетированы мной, а не дефектны**:

паттерн `) -> Result<PlaceDto, AppError> {\n        authorize(caller, &Action::MutatePlaces)?;`
в `place_service.rs` НЕ уникален — `.replace(old, new, 1)` бил в `rename` (стр. 206),
а не в `set_path_variant` (стр. 270). Три прогона подряд показывали «тест зелёный при
снятом гейте», и это выглядело как вакуумная проверка, хотя снимался не тот гейт.
Урок: в мутационном тесте якорь обязан быть доказанно уникальным (`s.count(old)==1`),
иначе мутация тихо уезжает в соседнюю функцию и оболгает результат.

Прицельные результаты:
1. Снят гейт ТОЛЬКО в обёртке (`tauri_cmds/places.rs`) → тест зелёный. Ожидаемо:
   сервисный слой гейтит независимо (`place_service::set_path_variant:270`).
2. Сняты ОБА гейта `set_path_variant` → тест КРАСНЫЙ. Падает на Case 50 (он раньше
   по файлу): `expected 403, got 404 Not Found` — без гейта вызов уходит в репозиторий
   и отказывает иначе. Гейт нагружен.
3. Изоляция самой новой строки: ожидание временно инвертировано на `Ok(_)` → падение
   ровно на `role_endpoint_matrix.rs:1861` со значением `Err(Forbidden)`. То есть строка
   исполняется, оценивается и умеет падать — не «молча пустая».

Все мутации вносились в копии/с немедленным восстановлением; `git diff` после проверок
пуст по обоим продакшн-файлам.
