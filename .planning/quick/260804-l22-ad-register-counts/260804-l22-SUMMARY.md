# Quick Task 260804-l22: AD register counts leak Summary

**Closed a REQ-06 visibility leak where `RequestService::counts()` inflated an Employee's own request-count badge with an invisible `ad_register` system row that `list()` already hid from them.**

## Performance

- **Duration:** 12 min
- **Tasks:** 2 completed
- **Files modified:** 4

## Accomplishments
- `RequestRepository::counts` trait, its sole impl (`SqliteRequestRepository`), and its sole caller (`RequestService::counts`) now agree on a 3-arg signature carrying `exclude_ad_register: bool`
- All 6 SQL `COUNT(*)` queries in `counts()` (all/open/in_progress/completed/rejected/cancelled) now filter `request_type != 'ad_register'` when the flag is set, matching `list()`'s existing per-bucket consistency
- New regression test proves an Employee's own pending `ad_register` request now yields `counts.all == 0` / `counts.open == 0` (previously `1`/`1`), while an Admin caller still sees `counts.all == 1` / `counts.open == 1`

## Task Commits

Each task was committed atomically:

1. **Task 1: Apply exclude_ad_register filter to counts() at port, repo, and service layers** - `bf9ca5c` (fix)
2. **Task 2: Regression test — employee counts exclude own ad_register request, admin counts include it** - `58a68c4` (test)

## Files Created/Modified
- `crates/trackly-core/src/ports/requests.rs` - Added `exclude_ad_register: bool` param to `RequestRepository::counts` trait signature + doc comment
- `crates/trackly-infra/src/repos/requests_sqlite.rs` - Added the param to the sqlite impl; added `AND (?2 = 0 OR request_type != 'ad_register')` to all 6 count queries, bound to `exclude_ad_register_i64`
- `crates/trackly-app/src/services/request_service.rs` - `RequestService::counts` now computes `exclude_ad_register` from `caller.role` (identical expression to `list()`) and passes it through
- `crates/trackly-app/tests/requests_ad_register.rs` - New test `ad_register_excluded_from_employee_counts` asserting employee vs admin count divergence

## Decisions Made

- `cargo fmt` scoped to only the 4 touched files, per project convention avoiding pre-existing workspace-wide drift noise
