# ADR 0002. Сеть Link, закрепление сертификата и секреты

## Статус
Accepted. Совместимость pin с reqwest/ring и tokio-tungstenite, а также keyring на трёх ОС проверяются в Фазе 44; кода в Фазе 42 нет.

## Контекст
Link ходит на сервер по HTTPS с самоподписанным сертификатом и хранит токен сеанса.

## Решение
- Вся сеть Link находится в Rust-части. Webview без доступа к сети: CSP `default-src 'self'`, `connect-src` только `ipc:` и `http://ipc.localhost`, capabilities без shell, fs и dialog.
- Закрепляется SPKI-отпечаток сертификата сервера. Его задаёт установщик или конфиг.
- Токен хранится в хранилище ОС через `keyring-core` 1.1.0 (MSRV 1.85) и store-крейты под `cfg(target_os)`: `windows-native-keyring-store`, `apple-native-keyring-store`, `zbus-secret-service-keyring-store` (Linux, без libdbus). Без Secret Service токен только в памяти.
- Крейт `keyring` 4.x отвергнут как тонкая обёртка над теми же компонентами (расхождение исследования закрыто).

## Последствия
Компрометация webview не даёт сетевого доступа. Смена сертификата сервера требует обновления закреплённого отпечатка.

## Отвергнутые варианты
- Сетевые запросы из webview: расширяет поверхность атаки.
- Токен в файле или localStorage.
- Доверие к системному хранилищу сертификатов для самоподписанного сертификата.
