# ADR 0003. Модель чата, полнотекстовый поиск и доставка

## Статус
Accepted

## Контекст
Чат заявок (`chat_*`) привязан к заявкам. Link нужен полноценный мессенджер с поиском.

## Решение
- Отдельная модель `im_*`; наращивание `chat_*` отвергнуто.
- Доставка «сигнал + догрузка по курсору»: события-сигналы только сообщают об изменениях, клиент догружает данные по курсору. Реализация в Фазе 43.
- FTS5: токенайзер `trigram` плюс нормализация `ё->е` и в индексируемом тексте, и в запросе.
- Запрос короче 3 символов идёт отдельным путём (LIKE или запрет), решение в Фазе 47.
- Запрос всегда соединяется с членством внутри SQL.
- Задел: тест миграции «FTS5+trigram доступен» в Фазе 47.

## Результаты эксперимента (rusqlite 0.41 bundled, SQLite 3.54.1, 2026-11-26)

| Проверка | Результат |
|----------|-----------|
| trigram, подстрока по-русски без учёта регистра | находит |
| unicode61, подстрока (`коллег`) | 0 строк, работают только префиксы |
| trigram, запрос из 2 символов | 0 строк |
| `ё` и `е` в любом токенайзере | не склеиваются |

## Последствия
Нормализация `ё->е` обязана выполняться в обоих местах, иначе поиск расходится. Короткие запросы требуют отдельного пути.

## Отвергнутые варианты
- unicode61: не ищет подстроки.
- Расширение `chat_*`: смешивает домены заявок и мессенджера.
