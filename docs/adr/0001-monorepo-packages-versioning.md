# ADR 0001. Монорепо, общие пакеты и версионирование Link

## Статус
Accepted

## Контекст
Веха v1.5 добавляет второй клиент, Trackly Link, рядом с серверным приложением Trackly. Им нужны общие дизайн-токены, UI-кит и транспорт, но сборки и выпуски у них разные.

## Решение
- pnpm workspace в корне (`pnpm-workspace.yaml`: `ui`, `link-ui`, `packages/*`), единый `pnpm-lock.yaml` в корне.
- Общие пакеты: `@trackly/design`, `@trackly/kit`, `@trackly/transport`, `@trackly/attachments`. Это source-packages без собственной сборки: потребитель компилирует их своим Vite (D-17).
- Правило «общее = не зависящее от домена Trackly»: пакеты не импортируют `bindings*`, `auth`, `features/*` из `ui/`.
- Trackly остаётся в `ui/` (D-18). Чат заявок остаётся в `ui/` до v1.6 (D-19).
- `trackly-proto` и `proto-ts` в фазу 42 не входят: новых DTO нет до фаз 43 и 47.
- Крейт Link называется `link-app`, исполняемый файл задан через `[[bin]] name = "trackly-link"`. Имя `trackly-client` отвергнуто.
- Нумерация Link независима и начинается с `0.1.0` (D-10). Версия пишется литералом; `version.workspace` в крейте Link запрещён. Версия 1.0.0 выпускается после закрытия v1.5.
- Выпуск Link идёт отдельным `release-link.yml` на тегах `link-v*.*.*` (D-11), независимо от `release.yml` (теги `v*.*.*`).
- Откат версии = выпуск с большим номером. `version_comparator` остаётся запасным вариантом.
- Ключи подписи в репозиторий не попадают.

## Последствия
Общий lock-файл упрощает согласование зависимостей. Разные теги исключают случайный выпуск одного клиента при выпуске другого. Дисциплина импортов проверяется гейтом.

## Отвергнутые варианты
- `version.workspace` для Link: связывает номера двух продуктов.
- Собираемые пакеты со своим Vite-конфигом: лишняя сборка без выгоды.
- Имя крейта `trackly-client`: не отражает продукт.
