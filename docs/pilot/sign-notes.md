# Подпись тестовой сборки Link для пилота (D-05)

Правило AppLocker по издателю (и для AD CS, и для самоподписанного сертификата) срабатывает только для подписанного исполняемого файла. Нужно проверить оба варианта подписи.

Важно: подпись установщика НЕ подписывает установленный `trackly-link.exe`. AppLocker проверяет именно установленный exe.

## Вариант 1. Сертификат AD CS

1. Выпустить сертификат по шаблону «Code Signing» в корпоративном центре сертификации.
2. Подписать: `signtool sign /fd SHA256 /tr <url-службы-времени> /td SHA256 /sha1 <thumbprint> trackly-link.exe`.
3. Создать правило AppLocker «Издатель» для этого сертификата и проверить запуск.

Доверие у AD CS есть из коробки: корневой сертификат ЦС уже в доверенных у доменных ПК.

## Вариант 2. Самоподписанный сертификат с раздачей доверия через GPO

1. `New-SelfSignedCertificate -Type CodeSigningCert -Subject 'CN=Link Pilot Test' -CertStoreLocation Cert:\CurrentUser\My -NotAfter (Get-Date).AddMonths(6)`.
2. Экспортировать ТОЛЬКО публичный `.cer`.
3. Раздать через GPO в «Доверенные корневые центры сертификации» и «Доверенные издатели». Без доверия в корневых правило по издателю не сработает.
4. Подписать: `Set-AuthenticodeSignature` или `signtool`.
5. Создать правило AppLocker по издателю и проверить запуск.

## Как подписывать на пилоте

- (a) Рекомендуемый путь: оператор подписывает уже установленный exe на тестовом ПК.
- (b) Подпись в CI - территория Фазы 45, в Фазе 42 не делается.

## Ключи и секреты

Закрытые ключи, PFX и сертификаты в репозиторий и в CI этой фазы не попадают. Отпечатки и Subject реальных сертификатов в документы не записывать; в примерах только «Link Pilot Test».
