# Фикстуры для `check-privacy.selftest.mjs`

Эта директория содержит фикстуры для self-test'а `scripts/check-privacy.mjs`
(гейт приватности, PRIV-02). Формат README следует конвенции
`crates/trackly-app/tests/fixtures/devices/README.md`.

**Каждый токен здесь полностью вымышлен (C-01).** Ни один файл в этой
директории не содержит реальных реквизитов организации, реальных ФИО
сотрудников или реальной инфраструктурной информации. Ничто отсюда никогда
не читается production-гейтом — только `check-privacy.selftest.mjs`.

**Начиная с плана 37-04:** `allowlist-regression.rs.txt` и
`binary-regression.docx` *намеренно* нарушают гейт (это их единственное
назначение — регрессия C-02/R8). После активации гейта в `--staged`/HEAD-режимах
(pre-commit хук, `ci-fast.yml`) эта директория исключена из авто-обнаружения
целей отдельной константой `AUTO_SCAN_EXCLUDED_PREFIXES` в `check-privacy.mjs`
(не той же, что `EXCLUDED_PATH_PREFIXES`/`EXCLUDED_PATH_EXACT`, которые
R9/D-13 фиксируют неизменными с плана 37-03) — иначе коммит самих этих
фикстур в HEAD навсегда бы ронял полный прогон гейта по репозиторию. Явные
позиционные вызовы (`check-privacy.selftest.mjs`) этот фильтр не проходят,
поэтому регрессионные проверки продолжают видеть нарушения как задумано.

## Файлы

| Файл | Назначение |
|------|------------|
| `tokens.fixture.sha256` | Тестовый файл хэшей режима 2 (n-грамм) — содержит SHA-256 нормализованной вымышленной фразы «Пчёлкин Артём» (класс B), с шапкой-инструкцией, зеркалирующей формат production-файла (D-07/D-08). НИКОГДА не указывается как `--hashes` вне self-test. |
| `with-marker.md` | Markdown-файл, где вымышленный маркер «Пчёлкин Артём» встречается рядом (в одной строке, смежными словами) — гейт должен упасть (exit 1), подтверждая, что 2-словная n-грамм-фраза ловится своим собственным хэшем (D-05). |
| `without-marker.md` | Тот же вымышленный маркер, но слова разнесены по разным строкам (не смежные) — ни одна n-грамма не совпадает с хэшем из `tokens.fixture.sha256`, гейт должен пройти (exit 0). |
| `empty.sha256` | Файл хэшей нулевого размера — проверяет fail-closed поведение (R7): пустой `--hashes` обязан приводить к exit 1, а не к молчаливому пропуску проверки. |
| `allowlist-regression.rs.txt` | `.rs`-по форме фрагмент (реальное расширение `.txt`, чтобы не попасть под `cargo build`) с `inn`/`ogrn`-литералами, отсутствующими в портированном списке `ALLOWED` — регрессионная проверка режима 1 (C-02): миграция из `check-privacy-requisites.sh` не должна ослабить исходную allowlist-логику. |
| `binary-regression.docx` | Файл нулевого размера с расширением `.docx` вне `BINARY_ALLOWLIST` — проверяет контроль бинарных расширений (R8): такой путь обязан быть нарушением (класс D). |

## Как self-test использует эти файлы

`check-privacy.selftest.mjs` вызывает `check-privacy.mjs` через `execFileSync`,
явно передавая конкретный fixture-файл как позиционный аргумент (а не через
`--staged`/HEAD-сканирование), и проверяет:

1. exit-код каждого вызова совпадает с ожидаемым;
2. вымышленное значение токена НИГДЕ не встречается в объединённом
   `stdout`+`stderr` дочернего процесса (D-16 — сообщение о срабатывании
   содержит только класс, никогда не значение).

## Регенерация `tokens.fixture.sha256`

Хэш в файле — это `sha256(normalize("пчёлкин артём"))`, где `normalize` —
та же функция, что в `check-privacy.mjs` (`lowercase` + `ё→е` + Unicode NFC).
Пересчитать вручную:

```bash
node -e "
const crypto = require('node:crypto');
const s = 'пчёлкин артём'.toLowerCase().replace(/ё/g, 'е').normalize('NFC');
console.log(crypto.createHash('sha256').update(s, 'utf8').digest('hex'));
"
```
